物流轨迹：多渠道展示

展示渠道是一条优先级链，不是二选一开关：C 端小程序 [wx-plugin, self-map]、 B 端 App 与运营端 [self-map]。链上谁先说「这一单我能呈现」谁上，备载荷失败自动落到下一个。 七屏：C 端两种渠道各两屏、B 端一屏、运营端一屏、失败兜底一屏。

01 — 03

C 端小程序 · 自建渠道（self-map）

没有微信支付交易单号的订单走这条（线下收款、历史单）。地图只能画到城市级 —— 快递100 给的是行政区中心点，不是快件 GPS。这是行业通行做法，但稿子里必须标出来， 否则落地后第一个问题一定是「为什么不显示快递车在哪」。

04 — 05

C 端小程序 · 微信渠道（wx-plugin）

这一单有微信支付交易单号时走它。我们只负责拿到 waybill_token， 点开之后是微信自己的全屏物流页，轨迹、地图、样式都由微信渲染 —— 我们一行都改不了，也不必维护。

06 — 07

B 端 App 与运营端

这两端用不了微信插件（插件只在小程序内），链上只有 self-map。 运营端本期不做地图：网页地图要高德 JS API key，线上只有服务端 Web 服务 key，得先申请。
