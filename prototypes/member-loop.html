会员标签与定向营销

把会员接到营销上：给人打标签、归成人群，再在活动、发券、发消息三处用同一块选人面板选人； 发出去之后看谁来了、谁下单，再把这批人打标或存成人群，回到起点。二十四屏。

写法全部沿用营销 v2 画布的七条约定（底部操作栏、三行卡、分组列表、≤3 用分段、状态才用标签、每屏最多一条提示）； 营销那边已画的屏只标差异，不重画。标「待拍板」的说明条对应需求文档 §十 待拍板的那几条。

闭环：会员名单 m01–m03 → 打标签 m04–m09 → 存成人群 m10–m11 → 选人面板 m12–m13 → 活动 · 发券 · 发消息 m14–m18 → 买家收到、进店、下单 c01 → 效果回看 m19–m20 ↺ 回到打标 / 人群 m20 → m06 · m11

底座是分层口径（m21）：「沉睡 24 人」每天凌晨重算，否则整条链从第一个数字就是错的。运营端只看、不改商家的标签（o01–o02）。

对账

m01 — m03

会员名单：筛出一批人

入口仍在「我的 › 会员」。筛选的结果不是终点：底部「对这批人」一次给出四个去处，闭环从这里出发。

m04 — m09

打标签：一个一个打，或者一批打

今天后端能打、页面没有入口。补两个入口（详情页一人、名单一批），再把标签管理页从「字典」升级成「这个标签被用在哪」。系统分层不在这里改。

m10 — m11

人群：存的是条件，不是名单

人群是「下次还要用」的筛选。名单每天在变，每次使用时当场重算；列表上的人数只是上次算的结果，带时间。

m12 — m13

选人面板：三处共用的那一块

活动、发券、发消息今天各有一份「选给谁」，选项还不一样（活动四项、发券四项加人群、发消息只有人群）。 合成一块：分层、标签、人群、来源四组多选，组内组间都取或；存下来的是这几项，不是人。活动多一个「非本店会员」，且与其余互斥。

m14 — m18

接到营销上：活动、发券、发消息

这五屏是营销 v2 已有屏的改版，只动「给谁」相关的行，其余照旧。发送结果页沿用 v2 s16，不重画。

c01

买家这一侧：「来了」从哪来

回看的三个数里，「来了」与「成单」都靠买家这一侧打点：点消息进店页记一次「来了」，7 天内在本店下单记「成单」，归到最近一次触达。

m19 — m20

效果回看：发出 → 来了 → 成单，再回到打标

入口两处：营销首页（v2 s01）加一行「发出去的」，人群详情（m11）的「用在哪」。口径只有一种：7 天窗口、归最近一次触达。

m21

分层口径：闭环的底座

今天分层只在下单时算，一个不再下单的人永远不会变成「沉睡」；60 天写死在代码里。改成每天凌晨重算、阈值进平台配置，商家这边只读。

o01 — o02

运营端：看得见谁在轰炸，改不了商家的标签

挂在「会员与人档」下，与现有「触达健康度」合并为一个 tab。标签是商家的资产，平台不解释含义、不列标签名；只看数量、频次与跳过率。
