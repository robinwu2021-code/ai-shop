# 线上验收 · B 端用例（商家 · `https://www.hxmall.top/b/`）

> 前置一律见[总纲](./线上验收-总纲.md)，本文不重复。功能编号对照 [B端功能清单](../requirements/B端功能清单.md)。
> 28 个页面 / 92 个契约方法，本文覆盖其中的**主路径与状态机边界**，不追求逐方法遍历。

**执行前必读**：线上没有可直接登录的演示商家（总纲 §③），B 端必须从入驻走。
TB-04 之后要切到平台端 [TP-10](./线上验收-用例-平台端.md) 审核，才能继续 TB-05。

## 一、登录与入驻（B-1）

| ID | 用例 | 步骤 | 期望 | 风险 |
|---|---|---|---|---|
| TB-01 | 发码限流生效 | 同一手机号连点两次「获取验证码」 | 第二次被拒（60s 间隔闸），提示可读 | 若不限流 = 线上发码端点裸奔 |
| TB-02 | 手机号登录即注册 | 新手机号 + 真实短信码登录 | 登录成功，**直接引导开店**而不是进空工作台（B-1.5 的反面就是这条） | 真短信通道未报备会发不出 |
| TB-03 | 微信一键登录在 H5 不出现 | 打开 `/b/#/pages/login/index` | H5 只渲染手机号登录；不该出现点了没反应的微信按钮 | `loginMethods()` 若写死会露出死按钮 |
| TB-04 | 入驻提交（个人主体） | 选行业 → 主体选「个人」→ 填店名/简介 → 勾选「本店同时作为自提点」→ 提交 | 提交成功，页面转「审核中」；**不跳工作台** | — |
| TB-05 | 行业限制主体类型（B-1.8） | 选一个线上业态的行业 | 不被允许的主体类型在表单上**禁用**，不是提交后才报错 | 主数据未灌 = 全放开 |
| TB-06 | 资质硬校验（B-1.4） | 主体选「个体工商户」，不传营业执照，提交 | **直接驳回**并给出原因 | — |
| TB-07 | 驳回不跳转（B-1.5） | 承 TB-06 | 留在原页、错误就地显示，不提示「已提交」 | 这是老 bug 的回归点 |
| TB-08 | 草稿续填（B-1.6） | 填一半退出，重进入驻页 | 已填内容回显 | — |
| TB-09 | 审核通过后作用域生效 | 平台端 TP-10 通过后，B 端重新进入 | 工作台可打开，`/biz/**` 不再 403 | **U-DEMO 那两家就是死在这里**（无 `mch_account` 就全 403 且只表现为「打不开」） |

## 二、工作台与店铺（B-2 / B-3）

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TB-10 | 六个待办数字 | 打开工作台 | 待发货/待自送/待核销/待分拣/待售后/待回评 六格；**新店应全为 0 而不是空白或报错** |
| TB-11 | 数字即入口 | 点任一非零格子 | 跳到对应列表且已按该状态筛过 |
| TB-12 | 履约台入口条件（B-2.4） | 入驻时勾了自提点 vs 没勾，两个账号对比 | 只有承接自提点的商家能看到履约台入口 |
| TB-13 | 自带客流占比卡（B-2.3） | 工作台下滑 | 单独一张卡，费率 0%；无数据时给「还没有」而不是 `NaN%` / `--` |
| TB-14 | 店铺资料与公告 | 「我的 → 店铺」改公告并保存 | 保存成功；**公告要过平台审核**（P-10.1），此时 C 端门店主页应仍显示旧值 |
| TB-15 | 店铺码 | 店铺页找店铺码 | 能生成/查看，扫出来落到 C 端门店主页且带 `merchantNo` 归因参数 |

## 三、商品（B-4）

| ID | 用例 | 步骤 | 期望 | 风险 |
|---|---|---|---|---|
| TB-16 | 建品（标品） | 商品 → 新建 → 选类目 `CAT210 纸品清洁`（无资质门槛）→ 填标题/规格/价格/库存 → 保存 | 建品成功，出现在列表 | 选了带 `required_code` 的类目会被准入卡住，那是 TB-18 |
| TB-17 | 规格模板带 code 落库（P-3.4 跨端） | 平台端先建规格模板（TP-06），B 端建品时选用它 | 商品身上**真的带着 `optionCode` 与 `templateNo`**——这正是曾经在存盘那一刻被静默丢掉的字段 | 页面显示正常也可能没落库，需 TP-06 侧回查 |
| TB-18 | 类目准入拦截 | 选 `CAT110/CAT120` 一类挂了 `required_code` 的类目建品 | 未获授权 → 拒绝并说明要什么资质 | 授权码表若为空会「全放行」 |
| TB-19 | 上下架 | 列表上切换上架状态 | 状态即时变；下架后 C 端社区流里消失 |
| TB-20 | 改库存（CLERK 也能做） | 改某 SKU 库存 | 成功，且 `biz:stock` 与 `biz:goods` 是**两个码**——只有改价才要后者（TB-31 验） |
| TB-21 | 铺社区 | 把商品投放到 `C0001` | C 端绑 C0001 的用户能看到；绑 C0002 的看不到 |

## 四、订单与履约（B-5 / B-6）

> 依赖：C 端已下单（TC-14）且**已执行付款桩**（总纲 §①）。

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TB-22 | 接单可见性 | 订单列表 | 只看得到本店的单；C 端那笔跨店订单**只有属于本店的那笔子订单**在列表里（ADR-002 拆单） |
| TB-23 | 状态筛选 | 切各状态 tab | 计数与列表一致；空 tab 给空态不是转圈 |
| TB-24 | 分拣（B-6.2） | 履约台 → 分拣 → 点数 | 数量对得上；**报短少**能提交并留痕 |
| TB-25 | 发货到自提点 | 分拣完 → 发货 | 订单 `PAID → PREPARING → ARRIVED`；C 端订单详情出现取货码 |
| TB-26 | 核销三校验（B-6.4） | 核销台输码 | ① 码存在 ② 属于本店/本自提点 ③ 未被核销过。**三条都要单独试一遍错码** |
| TB-27 | 重复核销 | 同一码核销两次 | 第二次拒绝，不重复推状态 |
| TB-28 | 非法状态迁移 | 对 `WAIT_PAY` 的单点发货 | 后端拒绝（状态机），前端不该先乐观改 UI |
| TB-29 | 逾期未取（B-6.7 / C-FF-07） | 用一笔已到货未取的单观察 | 顺延后作废的规则值来自平台端 P-5.1，**两边数字要一致**（不要在 B 端读到硬编码值） |

## 五、售后 · 评价 · 营销 · 客户（B-7 / B-9 / B-10 / B-11）

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TB-30 | 售后待办 | C 端发起售后（TC-22）后看工作台 | 待售后 +1，点进去是那笔单 |
| TB-31 | 同意退货 | 售后详情 → 同意 | 售后 `PENDING → AGREED`；C 端出现「填运单号」入口 |

| TB-34 | 差评申诉（B-9.4） | 对一条 ≤3 星评价发起申诉 | 可提交；4 星以上**不该有申诉入口** |
| TB-35 | 建活动的时间校验（B-10） | 建一个结束时间早于开始时间的活动 | 拒绝并说明；不要落库后再报错 |
| TB-36 | 客户列表（B-11） | 我的 → 客户 | 只有本店客户；**CLERK 角色进不来**（TB-40 对照） |

## 七、多门店 · 员工与授权（B-14 / B-11.12）

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TB-41 | 加员工并授角色 | 我的 → 员工 → 新增 → 选 `CLERK` | 该手机号登录后**只看得到收银台相关入口**，改价/活动/售后/客户全部不渲染（不是点了报错） |
| TB-42 | 六角色权限并集 | 给同一人加 `CLERK` + `COURIER` | 两套入口都在，权限取并集 |
| TB-43 | 只有老板能碰的三页 | 用 `MANAGER` 账号访问 `settle` / `staff` / `stores` | 入口不渲染；直接改 URL 深链也进不去（`biz:finance` / `biz:store:admin`） |
| TB-44 | 自定义角色（role-detail） | 建一个自定义角色勾几个码 | 保存后按码生效 |
| TB-45 | 新建第二家门店（B-11.12.2） | 门店管理 → 新建 | 第一个免费、第 2 个起要额度。**收费模型未拍板**，此处只验「有没有卡住」，卡法对不对不判 |
| TB-46 | 切门店穿透四个域 | 顶部切到第二家店 | 商品/订单/履约/数据**全部跟着切**，不能只切一半 |
| TB-47 | 跨店总览（cross-store） | 打开 cross-store | 两家店数据能对比；单店账号不该看到这页 |

## 九、本轮明确**不测**的（附理由）

| 不测 | 理由 |
|---|---|
| 真实支付、微信收款、零钱结算 | 无通道（总纲 §①） |
| 营业执照 OCR | 未接（B 端功能清单 §七） |
| 图片多实例读取 | 单机部署，本机磁盘就够；多实例才是问题 |
| 微信一键登录 | 小程序端能力，H5 验不了（TB-03 只验它不该出现） |
| 订阅消息推送真达 | `SHOP_WX_SUBSCRIBE_STUB` 为桩，两个模板号未报备 |
