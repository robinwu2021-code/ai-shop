## 一、登录与权限（P-1）

**这一组优先级最高**：平台端权力最大（改费率、批提现、封商家），权限没兜住比任何功能缺陷都严重。

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TP-01 | **岗位权限最小化** | 依次用 `bd` / `goods` / `support` / `finance` / `risk` 登录 | 每个账号**只渲染自己模块**的导航。`bd` 不该看到结算与资金，`support` 不该看到费率配置 |
| TP-02 | **深链绕不过权限** | 用 `support` 登录后手改 URL 到 `/finance` | 进不去（不是渲染出来再报错）。前端不渲染 + 后端 403，两层都要验 |
| TP-03 | 超管是上界 | `admin` 登录 | `perms: ["*"]`，18 个模块全可见——用它对照 TP-01 的差集 |
| TP-04 | 菜单来自库不是代码 | 对比 `ops-web/lib/nav.ts` 与实际渲染 | 接真后端时菜单由库里的数据决定，两边不一致要以库为准并记下来 |
| TP-05 | 操作审计留痕（P-1.1） | 做一次审核/改价/封禁，再看审计日志 | 有谁·何时·改了什么三要素；**代客操作也要留痕** |
| TP-06 | 员工与数据域 | 给一个客服账号设片区数据域 | 他只看得到该片区的单 |
| TP-07 | 改密与首登强改 | 新建员工 | 首次登录应强制改密（`mustChangePassword`）。⚠️ 线上 `admin` 现在是 `false`，见总纲 §五 |

## 八、跑之前要先定的一件事

**总纲 §五第 1 条**：`admin/admin123` 现在公网可登超管。
处理方式有两条路，各自会改变本文的前置：

| 方案 | 影响本文 |
|---|---|
| 保留种子、只给 `admin` 改密 + ops 加 IP 白名单 | 用例全部照跑，账号表里的密码换成新值 |
| 关掉 `SHOP_SEED_ENABLED` 重建库 | **11 个岗位账号、2 社区、2 商家、4 商品全没了**——TP-01/11/13/14/15/39/40 的前置要重写，B/C 两端也一起受影响 |

**建议第一条**：验收要的是有数据的环境，安全问题用改密 + 白名单单独解，不要用「清库」顺手解决。
