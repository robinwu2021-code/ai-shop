# 线上验收 · C 端用例（顾客 · `https://www.hxmall.top/`）

> 前置一律见[总纲](./线上验收-总纲.md)。功能编号对照 [C端功能清单](../requirements/C端功能清单.md)。
> 27 个页面 / 74 个契约方法。**C 端是三端里唯一能不登录就先跑一段的**——

## 零、未登录也能跑（先跑这一段，零成本）

线上种子数据已就位（C0001 阳光花园 / G0001 五常大米 …），下面这些不消耗短信。

| ID | 用例 | 步骤 | 期望 | 风险 |
|---|---|---|---|---|
| TC-01 | 首页可打开 | 访问 `/` | title「社区好物」，首屏不白 | 已在部署时验过，回归用 |
| TC-02 | 附近社区（C-CM-01） | 首次进入弹社区选择 | 列出 C0001 / C0002 及各自的自提点，带到货时间说明 | 定位权限被拒时要有兜底列表 |
| TC-03 | 绑社区 + 选自提点（C-CM-02） | 选 C0001 → PP0001 老张粮油店 | 归属条常驻首行，一行显示「自提点 · 到货时间」 | — |
| TC-04 | 社区决定可见性 | 切到 C0002 再看商品流 | 商品集合**跟着变**（G000x 都铺在两个社区，重点看请求参数真的带了 communityNo） | 若不变说明可见性没生效 |
| TC-05 | 社区在卖（C-GD-03） | 首页下滑 | 4 个种子商品都在，卡片四行齐（标题 / 时效 / 价格 / 商家·已售） |
| TC-06 | 价格永不截断（C-GD-07） | 找一个带划线价 + 折扣标的卡片，窄屏看 | 价格行最多三件，超出的截断，**价格本身不截** |
| TC-07 | 商品详情（C-GD-06） | 点 G0001 五常大米 | 两个 SKU（10 斤 / 20 斤）可选，库存与履约说明在 |
| TC-08 | 商家主页（C-ST-01） | 点进 M0001 老张粮油店 | 是交易页不是介绍页；未登录时第一屏退化成「店铺热销」 |
| TC-09 | 未认证商家标识 | 对比 M0001（已认证）与 M0002（未认证） | 认证标只在 M0001 上 |
| TC-10 | 搜索（C-GD-05） | 搜「米」 | 商品区 + 商家区两个分区 |
| TC-11 | 分类页（C-GD-04） | 分类 tab | 五类；**卡券类目线上是 ARCHIVED，不该出现** |
| TC-12 | 未登录不拉未读数（C-NT-03） | 打开「我的」，看网络面板 | **不发** `unreadMessages` 请求（老 bug：未登录也拉，然后显示「已全部阅读」） |
| TC-13 | 三语与 RTL（C-UI-03） | 切英文、切阿语 | 阿语整体镜像，归属条文案**重新拉取**而不是留着中文快照（C-CM-04） |
| TC-14 | 明暗与配色（C-UI-01/02） | 切深色、换几套皮肤 | 8 套配色可切；`fresh` 主色锁 `#00B578` |
| TC-15 | 宽度自适应（C-UI-05） | 桌面浏览器拉宽窗口 | >600px 固定 375 画布居中，不是拉伸变形 |

## 二、购物车与下单（C-CT / C-OD）

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TC-19 | 加购（C-CT-01） | 商品页加购 | 飞入动效落点是购物车图标真实坐标 |
| TC-20 | 按商家分组（C-CT-02） | 分别加 M0001 与 M0002 的商品 | 购物车按店分组 |
| TC-21 | **按商家拆单（C-CT-04）** | 全选结算 | 生成 **2 笔子订单**共享一个 `payGroupNo`，用户感知是「买了一次」 |
| TC-22 | 拆单披露（C-OD-06） | 订单详情 | 明示「本单由 XX 提供并收款」 |
| TC-23 | 确认订单（C-OD-01） | 选自提点 PP0001 | 自提点/地址/券/积分四项齐；配送费按规则算 |
| TC-24 | 优惠券（C-CT-05） | 领券再用券 | 能领能用；**跨商家摊分口径未定**，此处只验不报错、金额不为负 |
| TC-25 | 积分抵扣（C-CT-06） | 新账号积分为 0 | 抵扣入口给「无可用」，不是可点后报错 |
| TC-26 | **支付（C-OD-02）** | 点支付 | **预期唤不起收银台**——返回 `STUB` 通道。这是已知边界不是缺陷；记录页面此时的表现是否可解释（不能卡死在转圈） |
| TC-27 | 付款桩推进 | 运维执行付款桩（总纲 §①） | 两笔子订单**一起**转 `PAID`（同一 `payGroupNo` 整组支付） |
| TC-28 | 未支付自动关单 | 留一笔不付，等超时 | 自动 `CANCELLED` 并释放锁库；时长值以规则表为准 |
| TC-29 | 取消订单（C-OD-05） | 对 `WAIT_PAY` 和 `PAID` 各取消一笔 | 都允许；对 `PREPARING` 的单不该有取消入口 |
| TC-30 | 订单列表分 tab（C-OD-03） | 切 全部/待付/待提/待收/待评/售后 | 计数与内容一致 |
| TC-31 | 订单详情码在最上面（C-OD-04） | 打开一笔待取货的单 | 取货码在首屏第一位，不用滚 |

## 七、本轮明确**不测**的

| 不测 | 理由 |
|---|---|
| 真实支付、退款到账 | 无通道；TC-26/27 记录的是桩行为 |
| 微信静默登录 | 小程序侧能力，H5 不适用 |
| 订阅消息授权（C-NT-01） | 桩，且授权只在小程序有意义 |
| 推送 token（C-NT-02） | App 端能力，H5 无 |
| 三市场定价（C-UI-04 的 AE/US） | 线上只灌了 CN 的价，切市场只能验切换不报错 |
