# 二 · 行业定位与工作流声明（组合模型六件事）

```
电子元器件订单 = 基础订单流 + B2B 询报价工作流
```

| 声明 | 答案 |
|---|---|
| **W1 对象与状态机** | **RFQ**（DRAFT→SUBMITTED→QUOTING→QUOTED→ACCEPTED / EXPIRED / CANCELLED）· **Quote**（版本链，一条 RFQ 多版报价）· **BOM 匹配任务**（行级：UNMATCHED→MATCHED→CONFIRMED） |
| **W2 开单时机** | **延迟** —— 报价被接受才 `place`。询价不是交易意向；「询价即订单」会污染订单量与转化率（与美业电话预约同一判据） |
| **W3 付款时点** | 先付（散客）/ **账期赊销**（协议客户，`WAIT_OFFLINE_PAY` + AR 域） |
| **W4 同步点** | A1 转单 · A2 收款与核销 · A3 分批发货 · A4 退料 · A5 事件（onPaid → 释放信用额度、onCancelled → 回滚占用） |
| **W5 超时逆向** | 报价到期自动失效（Job）· 询价长期无响应归档 · 转单未支付按门店配置关单 |
| **W6 依赖与打印** | 依赖：阶梯价 · SPQ/倍数 · 批次库存 · AR；打印场景 **QUOTE · PACKING_LIST · STATEMENT** |

**RFQ/Quote 是前置单据，不是 `Engagement`** —— 判据同美业预约单：不聚合订单、不结清。
组合模型的判据在第四个行业复用成功，**零新同步点、零新订单状态（L6 复验通过）**。

# 三 · 场景与工作流（记法同[场景手册](../technical/design/三行业场景工作流手册.md)）

| # | 场景 | 轨道 | 开单 | 收款 |
|---|---|---|---|---|
| E1 | BOM 询价 → 报价 → 转单 | RFQ+订单 | 延迟 | 先付/账期 |
| E2 | 单料号快速询价 | RFQ+订单 | 延迟 | 同上 |
| E3 | 现货直接下单（有报价历史/协议价） | 订单 | 即时 | 同上 |
| E4 | 多轮议价 | RFQ | — | — |
| E5 | 分批交货 | 订单+履约 | — | — |
| E6 | 账期回款与对账 | 订单+AR | — | 账期 |
| E7 | 替代料推荐（原型号 EOL/无货） | RFQ | — | — |
| E8 | 批次退货 | 订单+库存 | — | — |

**E1 主流程**
```
客户传 BOM(Excel) → 解析成行 → ⟨三级匹配：精确 MPN / CPN 命中 / 模糊⟩
→ 未命中行进人工确认队列（**不许全自动直报**）→ RFQ SUBMITTED
→ 销售逐行报价（阶梯价 + 交期 + 可用量；EOL 行附替代料）→ QUOTED（valid_to 到期失效）
→ 客户接受（整单或勾选部分行）→ [A1] place（**价格锁定 priceHit=QUOTE:<no>**）
→ 先付：[A2] 支付 ｜ 账期：WAIT_OFFLINE_PAY + AR 生成应收
→ [A3] 分批发货（每次一张 shipment，行上累计已发）→ 收货
→ 账期到期 → 收款 [A2] markPaid → AR 核销
⊗ 报价过期 → EXPIRED，需重新询价（价格波动大，不许沿用旧价）
```

**E5 分批交货**
```
订单行 10000 只 → shipment#1 发 3000（行已发=3000）→ shipment#2 发 7000（=10000，行闭合）
子单在全部行闭合后才 COMPLETED；每次发货打 PACKING_LIST（客户料号 + 批次 + 卷盘号）
```

**E6 账期回款**
```
发货后 → AR 应收（起算日=发货日或对账日，门店配）→ 到期前提醒 → 收款
→ ord_payment 一笔（可能一次付多单）→ 逐单 markPaid → AR 核销
⊗ 逾期 → 冻结新单信用额度（下单前校验拦截）
```

# 四 · 数据库调整方案

**三层分开，改动量与风险差别很大：**

## 4.1 基座加列（三处，**三行业共享收益**，风险低）

```sql
-- ① 阶梯价：V2 价格条目的真缺口（有 store/channel/tier/valid，唯独没有数量档）
ALTER TABLE sell_price_entry ADD COLUMN min_qty INT NOT NULL DEFAULT 1
  COMMENT '起算数量档：1/100/1000。解析规则由「最具体者胜」扩为「最具体 × 满足数量的最高档」';
-- 索引随之调整：idx_price_lookup (sku_no, store_no, channel, tier, min_qty, valid_from)

-- ② 标准包装量与订购倍数（MOQ 既有）
ALTER TABLE prd_store_listing ADD COLUMN spq INT NULL
  COMMENT '标准包装量：一盘 5000 只';
ALTER TABLE prd_store_listing ADD COLUMN order_multiple INT NULL
  COMMENT '订购倍数：只能按 N 的倍数买。NULL=不限';

-- ③ 生命周期状态（元器件必需；零售可空）
ALTER TABLE prd_goods ADD COLUMN lifecycle VARCHAR(16) NULL
  COMMENT 'ACTIVE/NRND(不推荐新设计)/EOL(停产)/OBSOLETE；NULL=不适用';
```
**兼容**：三列全部 `NULL`/默认值 = 旧行为；`min_qty=1` 使既有条目语义不变。

## 4.3 V1 进销存：启用批次（**最大的一处改造**）

`inv_item.trackBatch` 的注释写着「一期恒 0，**开启后余额要从一个数变成一组批次**」——
留位不等于实现。启用需要：

```sql
-- 余额加批次维度（主键随之扩展）
ALTER TABLE inv_stock_balance ADD COLUMN batch_no VARCHAR(32) NOT NULL DEFAULT '';
-- 唯一键 (owner,item,location) → (owner,item,location,batch_no)；'' 表示不追批次的物料

CREATE TABLE inv_batch (
  batch_no   VARCHAR(32) NOT NULL,
  owner_id   VARCHAR(32) NOT NULL, item_id VARCHAR(32) NOT NULL,
  lot_code   VARCHAR(48) NULL COMMENT '厂商批号',
  date_code  VARCHAR(16) NULL COMMENT '2438 = 2024 年第 38 周',
  msl        VARCHAR(8)  NULL COMMENT '湿敏等级 MSL1–5',
  expire_at  DATE NULL COMMENT '由 date_code + shelf_life 推算',
  cost_minor BIGINT NULL COMMENT '本批次进价——批次成本的落点',
  received_at DATETIME NOT NULL COMMENT '入库日，账龄起算',
  UNIQUE KEY uk_batch (batch_no), KEY idx_batch_item (owner_id, item_id, expire_at)
);
-- 流水与出入库行加 batch_no（inv_ledger / inv_inbound_line / inv_outbound_line）
```
**风险**：一旦开启不可回退 —— 历史余额要么补批次、要么标记 `batch_no=''`（无批次）。
**建议**：按物料开关（`trackBatch` 本就是物料级），元器件类物料开、其余保持 0。

# 五 · 领域对象

```
elc/domain/（行业包，只依赖 shop-industry-spi）
├── Rfq（聚合根）           lines · status · 三级匹配 · submit()/quote()/accept()
│    └── RfqLine            rawPart 原文永不覆盖 · matchState · goodsNo/skuNo
├── Quote（聚合根）         version 链 · validTo · accept() → 转单命令
│    └── QuoteLine          unitPrice(锁价源) · priceSource · leadTime · orderedQty
├── PartRef / Alternate     匹配与替代（读模型）
├── BomDocument             解析 + 列映射记忆
└── ElectronicsPackage implements IndustryPackage
        capabilities: RFQ_QUOTE · PART_CROSS_REF · ALTERNATE_PART
        required: BUNDLE_SKU? 否 —— 依赖 TIERED_PRICE · SPQ_MULTIPLE · BATCH_STOCK · AR_CREDIT

ar/domain/（新域，基座侧）
├── CreditProfile           limit/used 条件扣 · freeze()
├── Receivable              due/settled · overdue 判定
└── Settlement              一笔收款核销多张应收
```

**不变量（新增）**
| # | 律 |
|---|---|
| X1 | RFQ 行的 `raw_part/raw_mfr/raw_desc` **永不被匹配结果覆盖**（匹配错了要能回看原文） |
| X2 | 只有**最新版且未过期**的 Quote 可被接受；过期 Quote 接受即拒 |
| X3 | 转单价 = `quote_line.unit_price`，**不重算**；订单行 `price_hit=QUOTE:<quoteNo>:v<n>` |
| X4 | 部分转单：`Σ ordered_qty ≤ qty`（条件 UPDATE） |
| X5 | 下单数量必须满足 `MOQ ≤ qty` 且 `qty % order_multiple == 0`（基座下单五步第②步扩展） |
| X6 | 匹配 `AUTO_MATCHED` **不可直接报价**，必须 `CONFIRMED`（人工闸，见 §八 风险） |
| X7 | AR：`used_minor + 新单额 ≤ credit_limit`（条件 UPDATE）；`FROZEN` 拒新赊销单 |
| X8 | `shipped_qty ≤ qty`；全部行闭合才允许子单 COMPLETED |

# 八 · 风险

1. **BOM 匹配准确率是产品成败点，不是技术问题** —— 匹配错一行，客户按错料号采购，损失由谁承担？
   X6 的人工确认闸是硬约束：**`AUTO_MATCHED` 不可直接报价**；
2. **批次一旦开启不可回退**（§4.3）—— 按物料开关，元器件开、其余保持 0；
3. **账期赊销是信用风险不是字段**：额度、逾期、坏账、追偿 —— 建议独立立项；
4. **报价过期后不许沿用旧价**（元器件价格波动大）—— X2 是硬闸；
5. B2B 销售端界面（客户管理、跟单）本册未覆盖，属独立议题。
