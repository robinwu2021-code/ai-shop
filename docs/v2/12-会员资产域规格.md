## 1. 一句话模型

**两种载体一张流水**：账户（储值，双池本金/赠金）+ 卡（次卡/期限卡实例）；
`mbr_asset_txn` 是余额与余次的**唯一变更入口** —— 绝不无流水 UPDATE。

## 2. 表清单

| 表 | 关键列 | 说明 |
|---|---|---|
| `prd_trait_redeemable`（商品侧） | card_kind(VALUE/TIMES/**PERIOD 记账**) · face/bonus_value · total_times · valid_days · scope_type/refs · store_scope | 卡定义=CARD 商品；卖卡是订单、发卡是履约 |
| `mbr_asset_account` | **principal/bonus 双池** · (member, entity) 唯一 | 扣减按比例；退卡只退本金 |
| `mbr_card` | card_kind · remain_times(条件扣) · expire_at · status(非 ACTIVE 不可耗) · **source_order_no 唯一=发卡幂等** | |
| `mbr_asset_txn` | subject(ACCOUNT/CARD) · biz_type(RECHARGE/ISSUE/CONSUME/REVERSE/REFUND/EXPIRE/NO_SHOW/ADJUST) · 三个 delta · order/payment_no · **reversal_of 唯一=只可冲一次** · idem_key | 唯一入口 |

## 3. 不变量 M1–M8

流水恒等（对账 Job 日切）｜条件扣｜冲正唯一｜比例扣退本金｜状态守卫不可耗｜
适用校验在下单｜发卡按订单幂等｜耗次 n≥1 条件更新。

## 4. 接缝与 API

行业入口只有 `CoreMemberApi` 四个方法（deduct/reverse/balance/applicable）；
耗用=支付：流水 → `markPaid(TIMES_CARD/STORED_VALUE)` + `asset_deduct_minor`；
退卡固定顺序：已耗核销（默认原价）→ payment 冲正 → 资产回补 → 退款登记。
HTTP：`GET /mp/assets` · `GET /mp/assets/cards/{no}` · `GET /biz/members/{m}/assets` · `POST /biz/assets/adjust`(审批)。
充值/办卡无专用端点 —— 就是 CARD 商品下单。
