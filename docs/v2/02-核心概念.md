# 02 · 核心概念

> 本层回答：**每个名词是什么**。一句话 + 一个例子；细节见括号里的链接层。

## 商品侧

| 概念 | 一句话 | 例子 |
|---|---|---|
| **Product（SPU）** | 商家的一件商品/菜品/项目的定义 | 「招牌牛肉面」 |
| **Variant（SKU）** | 可购买的最小单位，有价有码 | 小碗 ¥18 / 大碗 ¥22 |
| **Option（销售规格）** | 产生不同 Variant 的轴。**影响成本或库存身份** | 杯型：大杯/中杯 |
| **Modifier（选配）** | 不产生 Variant 的附加选择，可加价可免费 | 免辣（¥0）、加珍珠（+¥2）、指定总监（+¥50） |
| **ProductType（产品类型）** | 行为画像=Trait 组合，**是一行数据** | 「鲜活海产」={按重, 每日定价} |
| **Trait（行为）** | 系统消费的强类型行为，有限集合 | SCHEDULED_SERVICE（时长/缓冲/资源） |
| **Listing（门店报价）** | 这家店怎么卖它：上下架/工位/限量/渠道 | A 店在售、沽清 20 份 |
| **PriceEntry（价格条目）** | 上下文价：渠道×客群×有效期，运行时解析 | 外卖价 ¥20、会员价 ¥16、明日时价 |
| **AvailabilityWindow** | 这个时刻能不能点 | 午市 11:00–14:00 |
| **Collection（陈列）** | 前台分组，与类目无关 | 菜单分类「热菜」、项目分组「面部」 |
| **Station（出品工位）** | 产出路由单元（≠资源） | 热菜档、拣货 A 区 |
| **Bundle（组合）** | 固定/可选组/次数三形态 | 套餐 ≡ 疗程包 ≡ 礼盒 |
| **Taxonomy（后台类目）** | 平台治理：资质/税务 | 「预包装食品」 |

## 订单侧

| 概念 | 一句话 | 例子 |
|---|---|---|
| **主单** | 支付边界：一次付款一张 | 跨店购物车一单两店 |
| **子单** | 商家×履约边界：结算/售后宿主 | 张记粮油那半单 |
| **行（OrderLine）** | 商品快照 + 行类别（PRODUCT/FEE/GIFT） | 牛肉面×2；餐盒费（FEE） |
| **行选配明细** | Modifier 快照，厨房票/退款/提成都读它 | 免辣 Δ0；总监 Δ5000（ref=技师） |
| **markPaid** | 幂等的支付确认，**不关心钱从哪来** | 微信回调/线下确认/耗卡同一个方法 |
| **ord_payment（收款流水）** | 一笔收款一行，混合收款=多行 | 现金 30 + 微信 46 → settle |
| **计量调整** | 按实结算差额落行 | 称重 ±、将来按时/按里程 |

## 资源与工作流侧

| 概念 | 一句话 | 例子 |
|---|---|---|
| **Resource（资源）** | 可被时间占用的单元 | 桌台、技师、床位、包间 |
| **Hold（占位单）** | N 格×M 资源×n 份的原子占位，TTL+幂等释放 | 双人 90 分钟 = 8 单元 |
| **开放占用** | 占住直到释放，不知何时结束 | 开台、KTV 包厢 |
| **Engagement（经营单据/基础工作流）** | 聚合订单、占用资源、最终结清或作废 | 台账、工单、收银票 |
| **相位（Phase）** | Engagement 的骨架状态：OPEN↔SETTLING→CLOSED\|VOIDED | 行业状态映射进来 |
| **同步点 A1–A5** | 工作流与基础流唯一的接触面 | A1 开单 A2 钱 A3 履约 A4 逆向 A5 事件 |
| **预约单** | 前置单据：持有占位、可无订单，**不是 Engagement** | 电话约了还没来 |

## 术语层（模型统一给系统，叫法分行业给人）

| 模型 | 零售 | 餐饮 | 服务业 |
|---|---|---|---|
| Collection | 商品分组 | 菜单分类 | 项目分组 |
| Modifier | 选购选项 | 做法/加料 | 加项/指定技师 |
| Station | 拣货分区 | 出品部门 | 服务区 |
| daily_quota | 每日限量 | 沽清份数 | 每日可约 |
| Engagement | 收银票 | 台账 | 工单 |

词条是数据（i18n × 行业维度），由 form-schema 下发，**不是代码分支**。
