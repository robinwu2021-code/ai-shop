# 13 · 打印域规格

> 摘要层。完整方案与规格（合册）见 [TDD-打印域-方案与规格](../technical/design/TDD-打印域-方案与规格.md)。

**一句话**：打印是基座设备通道（与 notify 同构），行业只提供内容（`PrintPayloadProvider`），
差异全落 `prn_route` 数据行 —— 代码零行业分支。

| 表 | 职责 | 要点 |
|---|---|---|
| `prn_printer` | 设备 | vendor 适配器 SPI；secret 加密；心跳离线告警 |
| `prn_template` | 模板 | 存库不写代码；平台默认+门店覆盖；`{{}}`+管道，渲染失败落默认并告警 |
| `prn_route` | 路由 | `match_expr` 受限表达式（字段白名单，不 eval）；**零命中绝不静默丢** |
| `prn_job` | 任务 | outbox 语义：幂等键、退避重试、FAILED 可见可补打（补打引用原任务快照） |

场景取值域：基座 3 + 餐饮 5 + 美业 4（行业加场景=常量+默认模板行，不改基座）。
**真机验收不可替代**：中文/切纸/分单命中/断网恢复/重提交幂等 —— 假打印机的绿测不算数。

**运行逻辑**（同日扩版）：触发矩阵（13 行：行业×时刻×场景，触发端只判场景与能力不判行业）·
七步流水线（触发→幂等闸→渲染→路由→落库→单机 FIFO 投递→巡检收敛）· 容错矩阵九行 ·
**重复的三种语义**：系统重投=幂等闸吞掉零票、自动重试=同任务一张票、人工补打=新任务且
dedupCritical 场景票面自动加【补打】大标（厨房看见不重做）· 逆向联动：撤未打、冲已打（插队）。
