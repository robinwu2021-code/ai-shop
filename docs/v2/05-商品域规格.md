# 05 · 商品域规格

> 本层回答：**照着建**。表以"列清单"形式给全（完整带注释的 DDL 在
> [商品域V2-设计规格书](../technical/design/商品域V2-设计规格书.md)）。
> 通用约定：`id` 物理主键不对外、审计四列+乐观锁+软删+`tenant_no` 每表都有（下略）；金额一律分。

## 1. 表清单（19 张 + 沿用规格四层）

## 2. 领域对象

```
Product(抽象: Standard/Fresh/Service/Virtual/Card 五特化, STI)
 ├ SpecMatrix(轴+Variants)  Attributes  FulfillmentPolicy  AfterSalePolicy
 ├ traits(): ServiceTrait / MeteredTrait(settle()) / PreorderTrait / BundleDefinition
 └ modifierGroups: List<GroupRef>
ModifierGroup(聚合根, validatePick)   Listing(聚合根, Quota/availableAt)
PriceBook.resolve(sku, ctx) → Money   Collection(MANUAL items / SMART rule)
vo: Money(整数,币种) · Duration · Quota · 类型化业务键
不变量 14 条集中 ProductInvariants；domain 包禁 import 框架与 BaseEntity（ArchUnit）
```

## 3. Service

`MerchantGoodsService`(沿用+segments 段) · `ModifierCatalogService` · `ListingService`(含
tryConsumeQuota 条件扣) · `PricingService.resolve`(**全系统唯一价格判定处**) ·
`AvailabilityService` · `CollectionService` · `FormSchemaService`(建品表单唯一来源) ·
`CatalogQueryService`(storefront 合成视图：陈列×时段×沽清×价格服务端算完)

## 4. API（现有前缀，不开 /v2 命名空间）

```
POST /biz/goods/save            增 traits/modifierGroupNos/afterSalePolicy/caution（不传=不改）
GET  /biz/goods/form-schema     唯一新增读端点（b-app 弃 type 硬渲染，与后端同 PR）
GET/POST /biz/modifier-groups · /biz/stores/{s}/collections · /availability-rules
POST /biz/listings/{l}:sold-out|:delist · PUT /biz/listings/{l}
PUT  /biz/price-entries:batch · GET /biz/price:resolve
GET  /mp/storefront/{storeNo}?channel=&at=      合成视图，端上不拼
GET/PUT /ops/product-types                      改 traits 走审批
```

> 行业数据对标（三张建品单：三文鱼/牛肉面/深层护理）见[设计规格书 §六](../technical/design/商品域V2-设计规格书.md)。
