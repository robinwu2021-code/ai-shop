# 16 · V1 ↔ V2 数据表对齐报告

状态：**对账 · 2026-08-29 首次** · 数据源：生成物 `backend/shop-app/src/test/resources/schema-test.sql`（主库全量）
+ `backend/shop-inventory/src/main/resources/db/inventory/*.sql`（库存域）+ V2 十五册设计。
定位：设计文档写了十几册，**从没和真实数据库对过账**。本册就是那次对账，并**修正对不上的地方**。

**方法**：脚本提取 V1 实有表名 → 与 V2 设计表清单做五组集合运算（新表撞名 / 沿用假设 / 未点名 / 跨域 / 库存域），
每组给结论与处置。可复算：`grep -ioE 'CREATE TABLE (IF NOT EXISTS )?[a-z_]+' <schema> | awk '{print tolower($NF)}' | sort -u`。

# 二 · 五组结论

## A · V2 新表 vs V1 撞名 —— ✅ 零撞名

18 张商品域新表 + 2 张订单域新表（`cat_product_type` · `prd_trait_*` 6 · `prd_metered_rate` ·
`prd_bundle_component` · `prd_modifier*` 3 · `sell_*` 5 · `prd_sku_bundle` · `ord_item_modifier` · `ord_payment`）
**在 V1 中全部不存在** —— 建表不会撞既有对象。

## B · V2 声称「沿用」的表 vs V1 实有 —— ✅ 假设全部成立

`prd_category` · `prd_goods` · `prd_sku` · `prd_spu_std` · `prd_topic` · `prd_store_stock` ·
`prd_store_price` · `prd_store_goods`（待改名）· `ord_order` · `ord_sub_order` · `ord_item` ·
`ord_status_log` · `ord_after_sale` · `ord_invoice_request` —— **14 张全部真实存在**，
设计里"沿用 + 加列"的前提没有落空。

## C · ⚠️ V1 实有但 V2 文档未点名的 10 张（本次对账的主要发现）

设计册里把存量笼统写成「规格四层（4 张）」等，**与真实表数对不上**。逐表定性：

| V1 表 | 真实用途 | V2 处置 |
|---|---|---|
| `prd_spec_dim` · `prd_spec_value` · `prd_spec_template` | 规格项 / 规格值 / 商家常用模板 | **沿用**（Option 的物理承载） |
| `prd_category_spec` · `prd_category_spec_value` | 规格库**类目绑定层**（哪个类目该给哪些规格） | **沿用** |
| `prd_merchant_spec` · `prd_merchant_spec_override` · `prd_merchant_spec_value` | 规格库**商家覆盖层**（自建规格/改平台规格） | **沿用** |
| `prd_category_pay_mode` | 支付方式四层判定的**类目层**（平台×类目开关） | **沿用**（V2 能力开关的既有范式来源） |
| `prd_category_points` | 积分规则按二级类目配 | **沿用** |
| `prd_stock_lock` | 下单库存锁定（锁→转实扣→超时释放） | **沿用**（库存域边界内，V2 不碰） |
| `prd_topic_goods` | 平台专题内商品 | **沿用**（与门店 Collection 正交） |
| `prd_community_pool` | 社区商品池 | **待删** —— [全域命名基准](../technical/reference/全域命名基准.md) §2.3 已判「被选品×服务区域取代」，本次仅记录，不在 V2 批次内动 |

**结论**：规格库是**概念四层、物理 8 张表**。15 册写的「规格四层（4 张）」是把层数当成了表数 —— 已修正（§四）。

## E · 库存域（19 张，V2 不动边界）

`inv_item` · `inv_item_ref` · `inv_owner` · `inv_location` · `inv_stock_balance` · `inv_ledger` ·
出入库 4 张 · 盘点 2 张 · 预留 2 张 · 调拨 · `inv_uom` · `inv_daily_snapshot` · `inv_outbox` · `inv_open_credential`。

电子元器件方案依赖的三张**已确认存在**：`inv_item_ref`（多套料号骨架）· `inv_owner`（寄售所有权）·
`inv_stock_balance`（批次改造对象）。批次启用（`trackBatch`）仍是**未落地的留位**，与方案描述一致。
