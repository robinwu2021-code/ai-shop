# PRD-订单同步给收件人

状态：待确认
创建：2026-10-08
相关：[TDD-订单同步给收件人](../technical/TDD-订单同步给收件人.md) · [ADR-029 订单对收件人可见](../technical/ADR/ADR-029-订单对收件人可见.md) · [TDD-多地址下单](../technical/TDD-多地址下单.md)（已实现，本篇的前置）

---

## 1. 背景

下单人和收货人经常不是同一个人：给父母寄菜、给同事寄办公用品、团长替几户下单。

现在的订单**只认下单人**。`ord_sub_order` 上早就有 `receiver_name / receiver_phone / receiver_address`
三个快照字段（`V69`），也支持逐商家指定不同收货地址（`TDD-多地址下单`，已实现）——
但那个手机号**只是个联系方式**，收件人本人在平台上看不到任何东西：
货到哪了、什么时候到、是谁寄的，全得回头问下单人。

缺的不是地址能力，是**「收件人」这个参与方在订单上不存在**。
全仓 `receiverUserNo` 零命中，订单可见性只有 `user_no = 下单人` 一条判据。

## 2. 范围

### 做

- 下单人把某条子单**同步**给收件人（显式动作），收件人注册/登录后能看到
- 平台总闸开启时，收件人已是平台用户的情况下**自动同步**
- 同步时发通知：已注册走站内信，未注册走短信
- 收件人视角：看物流与状态、确认收货

### 不做（Out of Scope）

| 不做 | 原因 |
|---|---|
| **同一商家分送多个地址** | 拆单维度现在只有 `entity_no`，扩成「商家 × 地址」会牵动运费/履约/核销/售后/分账。本期多地址仍用多单解决 |
| **微信订阅消息** | 生产是桩、两个模板未报备、且要收件人为本场景单独授权。**连 `notify_scene_channel` 的 WXSUB 行都不落**——`V156` 的注释明确规定：没有对应模板调用的场景不落 WXSUB 行，「给它开关也发不出」 |
| **收件人发起售后/退款** | 钱原路退回付款人，责任与凭证归属归下单人 |
| **催单** | 核实后发现：**平台现在根本没有「催单」这个功能**（`trade` 域零实现；`remindBeforeMinutes` 是关单前提醒，另一回事）。它是一块独立新功能，不该夹带在本篇里做 |
| **号码级退订表** | 一期量小且必须下单人主动触发；真起量再补（见 §7 缺口） |
| **收件人改地址/改配送时间** | 下单人填的东西不该被第三方改 |

## 3. 角色与可见性

| | 下单人 | 收件人 |
|---|---|---|
| 这条子单的物流与状态 | ✅ | ✅ |
| 商品名称与数量 | ✅ | ✅ |
| **金额** | ✅ | **默认不可见**，手动同步时下单人可放开 |
| 同一主单的**其他子单** | ✅ | ❌ 永远看不到 |
| 下单人是谁 | — | ❌ 不下发身份，只在通知文案里出现称呼 |
| 确认收货 | ✅ | ✅ |
| 退款 / 售后 | ✅ | ❌ 入口不渲染，后端也拒 |
| 撤回同步 | ✅ | — |

> **默认不可见是本篇的基调**：没有同步记录的订单，收件人永远看不到。
> 这条和「号码对上就看」不冲突——同步是**授权**，号码匹配只是**认领**的手段。

## 4. 主流程

### 4.1 手动同步

```
下单人在订单详情点「同步给收件人」
  └→ 可选：是否让对方看到金额（默认否）
  └→ 建立同步记录（幂等：同一子单对同一号码只有一条）
  └→ 发通知
        ├ 收件人已注册 → 站内信
        └ 未注册       → 短信
```

### 4.2 自动同步

平台总闸**默认关闭**。开启后，在**支付成功**时（不是下单时——未支付的单同步出去没有意义）判定：

```
平台总闸开  ∧  下单人没在下单页取消本单  ∧
收件人手机号解析到另一个已注册账号  ∧  该账号 ≠ 下单人
  └→ 自动建立同步，金额一律不可见
```

只对已注册的人自动。未注册的判断不了「在不在别的账户」，仍走手动。

### 4.3 收件人侧

```
收件人用这个手机号注册 / 登录
  └→ 「寄给我的」里出现所有同步给他、且未撤回的订单
       （包含他注册之前就同步过来的——注册那一刻一次性全部生效）
```

收件人的单放在**单独的「寄给我的」页签**，不混进「我的订单」：
两边能做的事不一样（退款入口有无）、金额可见性也不一样，混在一起语义会乱。

> **前提：收件人账号得有手机号身份。** 匹配链是「账号 → 手机号 → hash」，
> 纯微信登录、从没绑过手机号的账号认领不了，「寄给我的」会是空。
> 这种情况端上要**明说「绑定手机号后可查看」**，不能只给一个空列表——
> 否则用户会以为功能坏了。（见 AC12）

## 5. 通知

| 收件人 | 渠道 | 一期 |
|---|---|---|
| 已注册 | 站内信 | ✅ 无桩、生产恒真、零成本 |
| **未注册** | **短信** | ✅ 需**新报备一个阿里云模板**（最长前置，按天算） |
| 已注册 | 微信订阅消息 | ⬜ **不落行**（见 §2 不做） |
| 已注册 | App 推送 | ⬜ 生产是桩 |

**二选一不叠加**：已注册只发站内信，未注册只发短信。两条都发是花钱买打扰。

短信拟文案（以报备定稿为准，通知类模板**不得带短链**）：

> 【签名】{name}给您寄了一件商品，可在小程序用本机号登录查看物流与签收。退订回N

**同一子单对同一号码只发一次**（由同步记录的唯一键天然保证）。

## 6. 验收标准

- **AC1** Given 一条配送类子单，When 下单人点「同步给收件人」，Then 建立一条同步记录；重复点不产生第二条
- **AC2** Given 同步时未勾选「让对方看到金额」，When 收件人查看该单，Then 返回体内不含任何金额字段
- **AC3** Given 已同步，When 下单人撤回，Then 收件人立即查不到该单
- **AC4** Given 某手机号在注册前已被同步过 N 单，When 该号完成注册并登录，Then「寄给我的」一次性出现这 N 单
- **AC5** Given 收件人查看某单，Then 返回体不含同一主单的其他子单、不含下单人身份、不含退款/售后入口
- **AC6** Given 收件人查看某单，When 点确认收货，Then 订单进入已完成；When 调退款接口，Then 被拒
- **AC7** Given 某单**从未**被同步，When 收件人（手机号完全匹配 `receiver_phone`）登录，Then 查不到该单
- **AC8** Given 平台总闸开、收件人手机号属于另一个已注册账号，When 支付成功，Then 自动建立同步且金额不可见
- **AC9** Given 平台总闸关，When 支付成功，Then 不产生任何自动同步
- **AC10** Given 同步成功，Then 已注册收件人收到站内信、未注册收件人收到短信，且同一子单对同一号码只发一次
- **AC11** Given 多地址下单且某商家段未指定地址，When 提交配送类订单，Then 被 `RECEIVER_REQUIRED` 拦住（补现有缺口）
- **AC12** Given 当前账号没有手机号身份（纯微信登录），When 打开「寄给我的」，Then 显示「绑定手机号后可查看」的引导，而不是空列表

## 7. 风险与已知缺口

| 项 | 说明 |
|---|---|
| **号码回收** | 同步记录长期有效，手机号换主后新机主注册即可看到旧单（收件人姓名、地址、品名）。**本期接受此风险**，不加有效期——理由与权衡见 ADR-029 |
| **突破「线索不发」政策** | 平台有一条有测试守着的政策：未注册手机号一律不发消息。本功能是显式例外，论证见 ADR-029 |
| **短信成本** | 每单每收件人一条；靠「必须下单人主动触发」+ 幂等唯一键 + 日上限控制 |
| **号码级退订未做** | 短信文案给退订指引，但平台侧没有 opt-out 表，短期靠人工处理 |
| **微信通道整体不可用** | 生产是桩 + 模板未报备 + 现存 c-app/后端模板号不一致的既有缺陷（另案） |
