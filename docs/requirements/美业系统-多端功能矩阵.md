## 一、范围与使用方式

美业业务覆盖项目选购、顾客识别、预约、到店、派工服务、交易/资产消费、完工、经营收尾和逆向。商品、订单、人员身份、会员和账务继续复用共用所有者；美业只维护预约业务单、服务工单、护理资料及行业规则。

**疗程权益共用Pay权益定义、发行和使用能力；美业负责疗程服务计划、预约与实际执行。** 售卡收款、权益发行、每次消费和每次服务是不同事实，不能用一张普通订单反复标付，也不能在美业再建余次账。

本矩阵包含20个模块、118项功能和六类端的完整目标，阶段只表示建议依赖顺序，不是上线承诺。现有页面、接口或基础内核存在不等于表内整个模块已交付；第七节单独说明复用现状。

### 1.1 六类终端与现有产品的关系

| 列名 | 面向人员和用途 | 产品落点与状态边界 |
|---|---|---|
| C 顾客 | 本人选项目、预约、付款/资产授权、服务进度、本人记录 | 复用现有c-app；美业专用流程是目标增量 |
| 前 前台/POS | 前台、接待、收银员；代约、签到、派单、收款和打印 | 建议作为B端/POS作业视图；尚不认定有独立生产应用 |
| 技 技师作业 | 技师、助理；本人排程、被分派任务、交接、完工 | 可由B端按岗位提供视图；不强制另建App |
| 管 商家Web | 商家运营、店长；项目、人员、资源、规则和报表管理 | 商家侧管理视图，区别于平台ops-web；建设形态待定 |
| B 老板App | 老板及受权店长；移动经营、审批、异常和管理 | 复用现有b-app；权限按角色/门店划定，不默认所有B用户都有老板权 |
| 平 平台运营 | 平台运营、客服、财务、技术运维 | 复用ops-web，按岗位诊断/治理，不默认代商家营业或操作资金 |

终端不是角色，也不是后端数据所有者。同一个人可兼任前台与技师，但按当前身份、门店及具体动作授权；一个界面不能因为放在老板App就跳过收款或顾客本人授权。

服务人员复用共用业务人员主档，独立关联可选登录账号。门店任职、业务岗位、项目技能、班表/人员资源和任务参与分别建模；餐饮服务员、厨师和美业技师使用同一体系。预约指定人、已确认安排人、实际执行参与人分别保存，换人不覆盖原预约或历史参与。详细对象见[人员模型补充](../technical/design/美业系统-领域对象与聚合边界.md)及[数据库设计](../technical/design/美业系统-数据库结构设计.md)。

### 1.2 矩阵符号、边界与阶段

**看**＝受权只读；**操**＝受权执行；**管**＝配置维护；**申**＝只能申请；**审**＝受权审批；**诊**＝留痕诊断及受控恢复；**—**＝默认无此功能。组合符号是目标职责，实施时必须拆成可检验的动作权限；不在本轮创建权限码或路由。

M＝零售基础主数据；K＝标准商业核心；S＝平台支撑；E＝可选共用扩展；I＝美业业务。下文模块是产品功能分组，不等于新服务或独立数据库。

| 阶段 | 建议交付范围 | 启用条件 |
|---|---|---|
| P1 | 单店、单客、联网、先付单次服务；预约/直客、工单、基础消息打印 | 预约启用前具备原子资源合同；完工接核心履约；打印需真机验收 |
| P2 | 既有储值/可用权益消费接入、本人确认、消费记录、门店账户 | 门店独立账户及资产范围/恢复验收；不等于售疗程能力已具备 |
| P3 | 客史、人员协作、运营营销、物料、班次、经营报表和提成 | 业务政策、资料权限、产出及分摊事实明确 |
| P4 | 付费疗程销售、复杂收银、后付、定金、团体、上门、外部/离线 | 每项共用合同及专项政策独立评审验收 |

支付未知或资产确认中时保持原来源恢复，不能换渠道再收一笔。P1中的“先付”包括到店合法收款后再服务，不包括服务完成后收款。

## 五、疗程权益共用能力与美业功能关系

| 环节 | 功能主责 | 消费者/前台/技师分别做什么 | 所有权及防错边界 |
|---|---|---|---|
| 定义 | BTY-K01 | 消费者读规则；运营维护；前台和技师查适用范围 | Pay定义权益版本，商品引用；美业不保存第二份余次规则 |
| 销售 | BTY-K02/K03 | 消费者购买或本人接管付款；前台受权代办；技师无收款权 | 商品/交易定价收款，一次售卡对应可追溯发行来源 |
| 发行 | BTY-K03 | 消费者看到账；前台查进度；技术按原号恢复 | Pay幂等发行，收款成功不等于发行已成功 |
| 计划 | BTY-K06及F模块 | 顾客预约；前台安排；技师查看分派 | 美业维护服务计划，共用资源仲裁，不提前扣满所有未来次数 |
| 使用 | BTY-K04/K05/J04 | 消费者确认具体本次；前台发起；技师查看是否具备开工条件 | Core可信来源和授权＋Pay使用；一次扫码识别不等于授权 |
| 执行 | H | 顾客看进度；前台协调；技师实际服务与完工 | 美业保存事实，完工再接核心履约，余次不由工单自行递减 |
| 历史与逆向 | BTY-K07/K08及N/O/Q模块 | 顾客查询/申诉；商家核验；平台受权恢复 | 次数变化、服务事实、提成调整分别留痕；退卡政策未定不开执行入口 |

例如十次护理疗程：一次销售、一次合法发行、最多十次有效权益使用，以及对应实际服务工单；不表示十次新现金收入，也不表示售卡订单必须伪装成十次重复付款。赠送次数和金额储值继续按各自资产合同。
