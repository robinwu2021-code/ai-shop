# PRD · 商品快速录入：压缩包导图与文字识别

> 状态：草稿（2026-10-05）
> 落点：B 端 App 建品页 [goods-edit](../../b-app/src/pages/goods-edit/index.vue) + [photos.ts](../../b-app/src/pages/goods-edit/photos.ts)
> 技术方案：TDD-商品快速录入（待建）
> 原型：待画

---

## 一、一句话

**让商家少一张张选图、少一个个填参数：图打包成压缩包一次导进来（主图、详情页按序号各就各位），
商品信息粘一段文字（或让压缩包带进来）自动识别成规格 / 价格 / 快递等草稿，
识别完弹框让商家逐项确认，确认了才落表单。**

两个入口彼此独立，各自能单独用。

## 二、为什么现在做

商家录一个商品今天要：逐张选主图、逐张选详情图、一个个填规格与参数。
图多的商品（详情页七八张长图是常态）光选图就要点十几次；参数则要在类目模板里一项项挑。
商家手里往往**已经有一个整理好的图片文件夹**和**一段供货商给的商品文案**——
把这两样直接喂进来，比在手机上重新操作一遍快得多。

现状（2026-10-05 对代码的盘点）：

| 能力 | 现状 | 本 PRD |
|---|---|---|
| 主图/轮播 | `cover` + `images[]`（上限 7），逐张 `pickImages`→`mUploadImage` | 加「压缩包批量导入」 |
| 详情长图 | `detailImages[]`（上限 10），与轮播分两列、顺序即展示序 | 同上，按序号 |
| 图片上传 | 后端 `/biz/upload/image` 统一走 `MediaUploadService`（含 magic-number 校验） | **复用，零后端改动** |
| 图识别 | `mRecognizeGoods(图)→GoodsGuess`（只有标题/类目）、`mDescribeGoods(图)→{detail,params}`（params 只能从类目模板里挑） | 不够：要的是**自由文字→多类结构化** |
| 文字识别 | **无** | 新端点 + LLM + 规则兜底 |
| App 解压 | **仓库从未用过** zip/chooseFile | 新建端能力 |

## 三、名词

| 词 | 定义 | 不是什么 |
|---|---|---|
| **主图** | 详情页顶部可滑的方图，存 `cover`+`images`，首张即封面 | 不是详情长图 |
| **详情页** | 图文正文区竖排的长图，存 `detailImages` | 不进轮播 |
| **识别草稿** | LLM/规则从文字里解析出的、**尚未落表单**的结构化结果，带来源与置信度 | 不是已保存的商品字段 |
| **规则兜底** | 价格/快递/区域等确定性字段由正则抽取，LLM 不可用或读错时以规则为准 | 不是「LLM 失败就整个放弃」 |

## 四、输入模型（L2 结构）

两个解耦入口。文字解析的**唯一输入是文字输入框的当前内容**（单一真源）——
压缩包里的 txt 只是「替商家把文字预填进输入框」，不单独触发解析。

```
┌ A 导入压缩包 ───────────────┐      ┌ B 商品信息文字（多行输入框）────┐
│ 解压 →                      │      │ 可粘贴 / 手输 / 被 A 回填        │
│   图：主图/ 详情/ 按序号     │      │                                 │
│   txt（可选）：回填到 B ─────┼─────▶│ [识别] → LLM+规则 → 弹框逐项确认 │
└─────────────────────────────┘      └─────────────────────────────────┘
```

| 情形 | 压缩包 | 输入框 |
|---|---|---|
| 全含 | 图 + txt | 自动回填 txt |
| 只有图 | 只图 | 商家自己粘文字 |
| 只有文字 | 不用 | 手动粘贴 |
| 各自来 | 图（或逐张选） | 手输 |

## 五、压缩包契约（给商家的约定）

```
商品.zip
├── 主图/   1.jpg 2.jpg …    → cover + images（首张=封面，上限 7）
├── 详情/   1.jpg 2.jpg …    → detailImages（上限 10）
└── 说明.txt  一段自由文字     → 回填到输入框 B（可选）
```

- 分类靠**目录名**（主图/详情，兼容 main/detail、大小写）；
- 顺序靠**文件名里的数字自然排序**（2 < 10，不是字符串序）；
- 文字文件：根目录任一 `.txt`（UTF-8）；
- 容错：无子目录→全部当主图；无 txt→只导图不碰输入框；超限→截断并提示。

## 六、文字识别：LLM 为主 + 规则兜底

| 类别 | 例子 | 谁解析 | 理由 |
|---|---|---|---|
| 价格 | `10元` | **规则为主** | `\d+(\.\d+)?元` 确定，价格=真金白银不交给概率 |
| 重量/净重 | `净重4.5斤`、`单果140g+` | 规则抽值 + LLM 定语义 | 正则拿数值，LLM 判断是规格还是参数 |
| 快递 | `圆通快递` | **规则为主** | 固定词表直接命中 |
| 不发货区域 | `新疆西藏海南不发货` | 规则抽地名 + 命中「不发货」 | 地名有限集 |
| 规格归类 | `单果140g+`→规格维度 | **LLM 为主** | 需要语义拆成 {维度, 值} |

**兜底的工程形态**：规则先跑抽确定字段（永不丢）→ LLM 做语义归类 →
冲突时**规则的确定字段压 LLM**（价格以正则为准，LLM 不得改写）→
LLM 不可用/超时/置信低则整条退回规则结果。

**规则层放后端**，与 LLM 同一次返回合并，端上不重复维护正则。
后端走现有 AI 通道（注意大 body 要锁 HTTP/1.1）。

## 七、识别后弹框确认（核心交互）

识别完**不自动填**，弹 `sh-sheet` 清单逐项确认：

```
识别结果（请确认）
  规格   ☑ 单果重量：140g+        [LLM]
  价格   ☑ 4.5斤装  ¥[10.00]      [规则]   ← 可就地改
  快递   ☑ 圆通快递               [规则]
  区域   ⚠ 新疆 西藏 海南  → 去运费模板确认   ← 不勾选、只跳转
  [全部采纳]  [取消]
```

三条边界：
1. 默认勾选规则命中 + 高置信 LLM 项；**低置信项默认不勾、标灰**（同 `applyGuess`「认不准不预填」）；
2. **价格必须商家过目**、可就地编辑（价格不静默落）；
3. **「不发货区域」不自动改运费模板**——它跨整店，一句话能误伤所有商品，只展示文本 + 跳转，绝不直接写。

确认后按勾选落到 `params` / `specGroups` / `skus` / `fulfillments`，复用现有 `applyParamPicks` 等填充函数。

## 八、验收标准（AC）

| 编号 | 验收 |
|---|---|
| AC1 | App 导入压缩包：主图进 `images`（首张=`cover`）、详情进 `detailImages`，各按文件名数字排序 |
| AC2 | 压缩包只有图、无 txt 时：只导图，输入框不动 |
| AC3 | 压缩包含 txt：内容回填输入框；输入框已有字时弹「覆盖/追加/取消」，不静默覆盖 |
| AC4 | 解压出的图逐张走现有上传，非图字节被 magic-number 挡下，超限（7/10）截断并提示 |
| AC5 | 输入框点识别：价格、快递、不发货区域由规则稳定抽出（不依赖 LLM） |
| AC6 | LLM 不可用/超时：识别仍返回规则结果，价格/快递/区域不丢 |
| AC7 | 识别结果弹框逐项确认，默认全不落表单；取消＝一项都不落 |
| AC8 | 价格项可就地编辑后再采纳；低置信项默认不勾 |
| AC9 | 「不发货区域」只展示文本 + 跳运费模板，**不写任何商品/模板字段** |
| AC10 | 文字输入框内容不入库——确认后落正式字段，输入框本身不持久化 |

## 九、分期

| 期 | 内容 |
|---|---|
| P1 | App 压缩包导图 + 规则-only 文字识别 + 确认弹框（AC1–5,7–10） |
| P2 | 接 LLM 语义归类，规则转兜底（AC6 完整） |
| P3 | 小程序/H5 解压；运费模板区域联动 |

## 十、不做的事

- **不自动改运费模板**（不发货区域只跳转）；
- **不新增商品字段**（输入框是临时录入区）；
- **图不走新批量端点**（复用 `/biz/upload/image`，后端零改动）；
- 图片审核、文字里的敏感词过滤——另档。
