## 一、一句话

**让商家答得出三个问题：我这批花了多少、还剩多少、卖一件赚多少。**
让平台答得出一个问题：**哪些商家的账正在出问题。**

---

## 二、给谁用

| 画像 | 现状 | 他要什么 | 不要什么 |
|---|---|---|---|
| **张姐 · 菜摊** | 单店、几十个 SKU、库存就是摊上摆着的 | 卖完了能一键改数；别让她每天录单 | 进货单、成本、报表 —— 一个都不要 |
| **老陈 · 粮油店** | 单店、两三百 SKU、有进货有压货 | **进了多少、剩多少、赚多少**；哪件压着该清 | 供应商档案、账期、批次 |
| **连锁 · 三家店 + 一个仓** | 多店、一处备货 | 仓发货、店际调拨、跨店库存一眼看全 | WMS 那套库位拣货 |

**产品判断**：三类人用**同一套页面**，差别只在
①「有没有货要管」（张姐永远只用库存总览的改数按钮）②档位解锁的功能。
不做三套界面 —— 判断错了的代价是多点一次，而配置错了要找人改。

## 三、B 端需求

### 3.1 库存（`FREE`，人人可用）

| # | 需求 | 验收标准 |
|---|---|---|
| B-1 | 看到本店每个 SKU 的**可用 / 实存 / 预留** | 三个数分开显示；`可用 = 实存 − 预留` 在界面上能被验证 |
| B-2 | 直接改某个 SKU 的库存（盘点） | 输入「实际有多少」，系统算差异；**原因必填**（盘点/损坏/过期/赠送/其他） |
| B-3 | 看到每一次变动**是谁、什么时候、因为什么** | 变动明细按时间倒序；每行显示操作人、单据号、变动前后结存 |
| B-4 | 改不成负数 | 实盘填负数、或出库超过实存 → 拒绝并提示还剩多少 |
| B-5 | 缺货与滞销一眼看见 | 低于安全库存标红；90 天未动标灰。**列表默认把这两类排在前面** |
| B-6 | 多店商家能切店看 | 顶部切换库位；未选品的店不出现在列表里 |
| **B-0** | **每一屏都要有一处跳得过去** | 逐屏 `grep navigateTo`；H5 改 hash 能进**不算**通过 —— 这个仓库已栽过三次（`my-specs` / `sku-identity` / `income`） |

> **B-3 是这一期真正的交付物。** 今天商家问「昨天还有 20 袋今天剩 3 袋」，
> 平台连「谁改的」都答不上来 —— 而改库存是店员和理货员每天的活。

### 3.2 进货与成本（`PRO`）

| # | 需求 | 验收标准 |
|---|---|---|
| B-7 | 记一笔进货：日期、供应商（**随手填**）、逐行 SKU + 数量 + 单价 | 保存为草稿；**过账后库存才增加**，草稿不影响可售 |
| B-8 | 进货把成本价带进来 | 过账后 SKU 的成本价更新为**最新进价**；商家可改成手工价 |
| B-9 | 看到每件货的**毛利估算** | `(售价 − 成本) × 销量`；**界面必须标「估算」并给出算式** |
| B-10 | 补录昨天的进货 | 单据上的「发生日期」可回填，报表按它归期，不按录入时间 |
| B-11 | 录错了能改 | 草稿可改；**已过账的只能整单作废重录**，作废留痕 |

### 3.3 单据（`FREE` 看 / `PRO` 建）

| # | 需求 | 验收标准 |
|---|---|---|
| B-12 | 一个地方看全部出入库 | 入库/出库/盘点/调拨四类，可按日期与类型筛 |
| B-13 | **销售出库自动成单** | 顾客付款后自动生成出库单，操作人显示「系统」，能点进订单 |
| B-14 | 报损出库 | 选货、填数量与原因；过账后库存减少并留一行流水 |

### 3.4 仓与调拨（`CHAIN`）

| # | 需求 | 验收标准 |
|---|---|---|
| B-15 | 建一个「仓」 | 仓不对买家展示、不出现在附近商家里 |
| B-16 | 门店从仓发货 | 门店设置发货源为仓后，下单扣的是仓的库存 |
| B-17 | 店际调拨 | 发出 → 收到两步；**发出后收到前，两边合计不变**（货在「在途」上） |
| B-18 | 跨店库存总览 | 一个 SKU 在各库位的余额一屏看全 |

### 3.5 报表（`PRO`）

| # | 需求 | 验收标准 |
|---|---|---|
| B-19 | 进销存月报：期初 / 进 / 销 / 损 / 期末 | 五个数满足 `期初 + 进 − 销 − 损 ± 调 = 期末`，界面上能对上 |
| B-20 | 动销榜 / 滞销榜 | 动销按销量降序；滞销 = 90 天零动销且仍有库存 |
| B-21 | 导出 CSV | UTF-8 带 BOM（Excel 打开不乱码）；导出留审计 |

## 四、运营端需求

运营端**不替商家管库存**，只做治理与支撑。

| # | 需求 | 验收标准 |
|---|---|---|
| O-1 | **库存健康度**：负库存、零库存仍在架、90 天未动销 | 三类各出一张可下钻的清单，能定位到商家与门店 |
| O-2 | 商家的库存台账可查（只读） | 按商家 → SKU → 流水三级下钻；**不提供修改入口** |
| O-3 | 预留积压监控 | `HELD` 超过 TTL 仍未回收的预留列出来 —— 它意味着回收任务出了问题 |
| O-4 | 对差看板：平台侧库存 vs 进销存 | D1 双写期用；**连续 N 天为零才允许切真相源** |
| O-5 | 档位与能力位配置 | `inv_purchase` / `inv_warehouse` 两个能力位可按主体授予 |
| O-6 | 单位字典维护 | 增删计量单位（全局，不按商家） |

> **O-2 明确只读**：运营能改商家库存的那一刻，「这个数是谁改的」就多了一个答案，
> 而商家不会知道。要改只能让商家自己改，或走工单留痕。

## 五、不在范围

| 不做 | 为什么 |
|---|---|
| 供应商档案 / 账期 / 应付 | 小店的供应商是微信里那个人 |
| 批次 / 效期 / 序列号 | 让余额从一个数变成一组，模型级分叉，单独立项（字段已留位） |
| 移动加权 / FIFO 成本 | 漏录一次之后所有历史毛利全错**且不报警** |
| WMS（库位、拣货路径、波次） | 储藏间没有库位 |
| 运营端修改商家库存 | 见 O-2 |
| 总账 / 凭证 / 科目 | 那是会计系统，我们出业务口径报表 |

## 六、档位对应

| 档 | 解锁 |
|---|---|
| `FREE` | 库存总览、**变动明细**、盘点、单据只读 |
| `PRO` | 进货单与成本毛利、动销/滞销、进销存月报、导出 |
| `CHAIN` | 仓与调拨、跨店库存、Open API |

**变动明细与盘点不收费**：流水是平台自己的欠债（超卖追责、对账证据），
藏在付费墙后面等于平台自己也没有证据。

---

## 七、怎么知道它有用

上线后看四个数，而不是看「有没有人点」：

| 指标 | 说明它有用 |
|---|---|
| 有变动明细的 SKU 占比 | 流水真的在长，不是空表 |
| 盘点后差异的绝对值趋势 | **下降 = 账实在收敛**。这是这套东西唯一的终局指标 |
| 录过进货单的商家数（PRO） | 「进」这一半有没有被接受 |
| 因缺货导致的下单失败数 | 应当下降 —— 有了预警才谈得上补货 |
