## 零、这次重整改了什么

草稿写于**动工之前**，今天它有六处与线上不一致。**不是待办，是需求本身要改**——
照草稿排期的人会去做一件已经被明确判掉的事，或漏掉一件已经上线的事。

| # | 草稿说 | 今天的实际 | 处置 |
|---|---|---|---|
| ① | B-9「毛利估算 `(售价 − 成本) × 销量`，界面标『估算』」 | **刻意不给毛利**，给的是**销货成本**。收入不在本域（出库单只带成本不带售价），凑出来的毛利在促销 / 多渠道 / 改价后统统对不上，而毛利正是商家拿去报税的那个数 | **改判**：需求改成「销货成本 + 损失成本」，毛利留给知道收入的那一侧 |
| ② | §六 三档 `FREE` / `PRO` / `CHAIN` 解锁 | **一行代码都没有**。32 个商家端点只判权限码（`biz:stock` / `biz:customer` / `biz:store:admin`），进货、报表、调拨、建仓**今天对所有商家免费开着** | **降为未做**，单列 §八。这是本域最大的一处需求与实现的差 |
| ③ | §五「不做供应商档案 —— 小店的供应商是微信里那个人」 | **已上线**：`inv_supplier` 表、4 个端点、独立的「供应商」页，2026-08-30 真机验通 | **移出「不在范围」**，进 §三「记」组。改判的理由见[供应商与发货要素 §二](../technical/design/进销存-供应商与发货要素.md) |
| ④ | 决策 E「底部 tab 换成『库存』，商品移二级」 | **未执行**。底部仍是 工作台 / 订单 / 商品 / 我的，进销存的门是**工作台上那张卡** | **撤回决策 E**。卡这个形态更好：它同时给出四个数，而 tab 只给一个入口 |
| ⑤ | 决策「运营端挂 `/products`，不新建 L1」 | 已是**独立顶级模块** `/inventory`，四个 tab | **决策记录那一行作废**（`V261` 已落库） |
| ⑥ | O-3 预留积压 / O-5 能力位 / O-6 单位字典 | **三条都没有落点**（`inv_uom` 表建了，无端点无界面） | 保留为需求，标「未做」，见 §四 |

**另外两处是文档自己的账**（本轮已修）：

- [界面清单](../technical/design/进销存-界面清单.md)自称「生成的，判据是跑一遍输出没变」，
  但生成器的页面列表写死为九屏，**漏掉第十屏「供应商」** —— 少一页的症状是清单少一节，
  而「输出没变」照样成立。重跑之后发现漂的**远不止那一页**：「货品」全域改称「商品」、
  调拨发货三项、进货的供应商选择器，都是 08-28 之后改的而清单一直在说旧话。
- 本域**没有任何闸门**盯这份清单（`pre-push` 只跑 `gen-ui-catalog.py`）。
  今天靠的是有人想起来重跑。

## 一、一句话（不变）

**让商家答得出三个问题：我这批花了多少、还剩多少、卖一件赚多少。**
让平台答得出一个问题：**哪些商家的账正在出问题。**

> ①改判之后，第三个问题今天的答案是「你这批货的**成本**是多少」——
> 赚多少要拿订单金额去减。这不是缩水，是把一个会算错的数换成一个算得准的数。

## 二、给谁用（不变）

| 画像 | 他要什么 | 不要什么 |
|---|---|---|
| **张姐 · 菜摊**：单店、几十个 SKU | 卖完了能一键改数；别让她每天录单 | 进货单、成本、报表 |
| **老陈 · 粮油店**：单店、两三百 SKU | 进了多少、剩多少、成本多少；哪件压着该清 | 账期、批次 |
| **连锁 · 三店一仓** | 仓发货、店际调拨、一件货在各处的分布 | WMS 那套库位拣货 |

三类人用**同一套页面**，差别只在「有没有货要管」。不做三套界面 ——
判断错了的代价是多点一次，而配置错了要找人改。

## 三、B 端需求 · 按商家做的四件事重排

草稿按「库存 / 进货 / 单据 / 仓 / 报表」排，那是**功能的分法**；
商家脑子里是「今天要做什么」。四组的频率差两个数量级，排布也按这个来
（工作台一张卡 → 库存页当枢纽 → 写动作在贴底条、查与配收在细线之下）。

图例：✅ 已交付 · ⚠️ 交付了但没在生产验过 · ❗改判 · ❌ 未做

## 四、平台端需求

平台端**不替商家管库存**，只做治理与支撑。**一个写端点都没有，这是有意的**：
运营能改商家库存的那一刻，「这个数是谁改的」就多了一个答案，而商家不会知道。

| 新号 | 需求 | 验收标准 | 状态 | 落点 | 旧号 |
|---|---|---|---|---|---|
| INV-P1 | **库存健康度** | 负库存 / 零库存仍在架 / 长期未动销，三类可下钻到商家 → 门店 → SKU | ✅ | `/inventory` · `GET /ops/inventory/health` | O-1 |
| INV-P2 | 某商家的**库存台账只读** | 商家 → SKU → 流水，游标翻页，**没有任何修改入口** | ✅ | `/inventory?tab=ledger` · `ledger` `balances` | O-2 |
| INV-P3 | **库存对差** | 平台侧 `prd_sku.stock` vs 进销存余额逐条比；**「有差异」与「还没跑」必须长得不一样** | ✅ | `/inventory?tab=recon` · `recon` | O-4 |
| INV-P4 | **开放对接凭据**发放 / 吊销 | 签发按钮按 `inventory:credential:grant` 藏掉（与页面可见性的持有人不重合） | ✅ 2026-08-29 生产走通一次 | `/inventory?tab=credentials` · `credentials` ×3 | 草稿没有，从缺口反推 |

| INV-P6 | 档位与能力位配置 | `inv_purchase` / `inv_warehouse` 两个能力位可按主体授予 | ❌ 未做，**且它依赖 §八 那件还没做的事** | — | O-5 |

| 进货 | `pages/purchase-edit` | `biz:stock` | INV-W4…W7 W9 W10 · W12 | 挑货弹层里有扫码；无拍送货单 |

| 供应商 | `pages/suppliers` | `biz:stock` | INV-W10 | 平台级供应商档案未建（列已留） |
| 库位 | `pages/locations` | **`biz:store:admin`** | INV-C1 C2 | 无安全库存设置（INV-C4） |

**三个权限码是有意分开的**，不是随手选的：

- **报表判 `biz:customer`** —— 店员有 `biz:stock`（改库存是他每天的活）但不该看到成本与销量
- **库位判 `biz:store:admin`** —— 建仓是门店级配置，与改库存是两拨人
- 其余八屏判 `biz:stock`（它的注释原文：「改库存（含门店库存）。高频日常动作，且不出钱」）

**入口结构**（④ 撤回底部 tab 之后的定案）：

```
工作台 · 进销存卡（有 biz:stock 才出）
├─ 四个数：在售 / 缺货 / 滞销 / 在途   → 都点到「库存」
└─ 三个快捷（随状态变，不写死）        → 直达，跳过枢纽

库存（枢纽）
├─ 贴底写动作条：进货 · 盘点 · 报损 · 调拨      ← biz:stock
└─ 细线之下的查与配：单据 · 报表 · 库位 · 供应商 ← 各判各的码
```

**两条落地规矩**（各栽过一次）：

1. **菜单以库为准**。只改 `nav.ts`、接上真后端就是看不到 —— 运营端菜单在
   `sys_function_point` 里，要一条迁移（开放对接那一屏就是这么漏的，`V271` 补的）。
2. `nav.ts` 的 `module` 字段是**权限码前缀**，不是模块名。填一个没有对应
   `xxx:` 码的值，`canModule` 会走「这个模块不受权限约束」的分支，**整段对所有人可见**。

**平台端还缺三块**（INV-P5 P6 P7）：预留积压、能力位配置、单位字典。
前两块各是一个筛选项与一组表单字段，第三块是一条迁移加一个 tab —— 都不大，
但**都不在今天的四个 tab 里**，说「运营端做完了」是不对的。

## 八、档位：需求写了三档，实现一档都没有

草稿 §六 把功能分给 `FREE` / `PRO` / `CHAIN` 三档，[三端落点](../technical/design/进销存-三端落点与功能矩阵.md)
的每一屏也标了档位。**今天这套分档在代码里不存在**：

```
32 个商家端点  →  只判 biz:stock / biz:customer / biz:store:admin
grep PlanPort|planCode|MerchantPlan  在 shop-inventory 下  →  0 命中
grep inv_purchase|inv_warehouse      全仓代码               →  0 命中
                                     （只出现在三份设计文档里）
```

也就是说**进货、成本、报表、导出、建仓、调拨今天对每一个商家免费开着**。
`mch_plan` 那张表里今天只有一个能力位（`cross_store_stats`），也没接到库存上。

这**不是一个可以顺手补的开关**，要先答三个问题（§十 ①）：

- 已经在用这些功能的商家，加档之后是**关掉**还是**继承**？关掉等于线上功能倒退。
- 判在哪一层：端点（漏一个就绕过去）还是 Port（要每个 Service 都认识档位）？
- `FREE` 那一档里**变动明细与盘点不收费**这条要保住 ——
  流水是平台自己的欠债（超卖追责、对账证据），藏在付费墙后面等于平台自己也没有证据。

## 九、不在范围

| 不做 | 为什么 |
|---|---|
| ~~供应商档案~~ | **已改判并上线**，见 §零③ |
| 供应商账期 / 应付 / 授信 / 资质附件 | 那是应付账款，本轮只解决「进货单能指向一个稳定的对象」 |
| 批次 / 效期 / 序列号 | 让余额从一个数变成一组，模型级分叉，单独立项（字段已留位） |
| 移动加权 / FIFO 成本 | 漏录一次之后所有历史毛利全错**且不报警** |
| WMS（库位、拣货路径、波次） | 储藏间没有库位 |
| 运营端修改商家库存 | 见 §四 抬头 |
| 总账 / 凭证 / 科目 | 那是会计系统，我们出业务口径报表 |
| 条码批量导入 | 没人会为一个还没上线的功能录 396 个条码。**数据要被用出来**（INV-W12） |
| 拍送货单出货品与数量 | 值，但那是另一个模型任务（多行表格 OCR + 与商家货品对齐），单独提 |
| 扫码直接过账 | 扫错一件和数错一件的代价不一样，**前者商家不会发现**。数量仍要人确认 |

## 十一、怎么知道它有用

上线后看五个数，而不是看「有没有人点」：

| 指标 | 说明它有用 |
|---|---|
| 有变动明细的 SKU 占比 | 流水真的在长，不是空表 |
| **盘点后差异的绝对值趋势** | 下降 = 账实在收敛。**这是这套东西唯一的终局指标** |
| 录过进货单的商家数 | 「进」这一半有没有被接受 |
| 因缺货导致的下单失败数 | 应当下降 |
| 条码**绑定数**的增长（INV-W12 上线后） | **不要看扫码成功率** —— 第一天必然接近 0，而那不代表功能坏了 |
