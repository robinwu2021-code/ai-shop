## 一、范围与边界

用户已确认：商家收款，平台负责活动、账户和账单管理；活动先制定，充值按活动买赠；初期面向美业；支付模块包含现金支付、积分和储值。

以下为待评审推荐：pay 内独立储值模块；本金与赠金按批次管理；合格批次按充值时间先后使用、批次内按比例扣减；首期不设置本金和赠金的自动到期；储值余额不足时支持现金补款；服务部分退款回原批次，退余额只退剩余本金并处理对应赠金。活动先支持固定档位赠金，普通充值使用赠金为零的常设活动。

首期不做跨主体通兑、转赠转让、赠项目和赠次卡、自动营销广播、历史账户批量导入、积分与储值同时抵扣。退款金额基于历史实际扣款，不自动将已消费项目按原价重算。上述推荐不覆盖既有业务的已确认合同。

## 二、验收标准

| AC | Given / When / Then |
|---|---|
| SV01 | Given 商家未发布活动；When 发起充值；Then 拒绝入账。活动发布后修改金额或范围产生新版本，历史充值继续使用原版本 |
| SV02 | Given 消费者选择有效档位；When 创建充值单；Then 保存活动、主体、门店范围、币种、本金、赠金和支付期限快照，原子占用名额/赠金预算 |
| SV03 | Given 商家侧充值收款成功；When 账务入账；Then 本金、赠金、充值批次、流水及出站事件同事务提交，重复事件不重复发放 |
| SV04 | Given 同一消费者在多家商家有余额；When 查询或支付；Then 按商家主体与币种隔离，展示总余额及当前项目可用余额 |
| SV05 | Given 多次充值来自不同活动；When 消费；Then 可追溯各批次本金与赠金扣减，合格批次先进先出、批次内按比例拆分，冻结额不可重复使用 |
| SV06 | Given 员工创建服务消费单；When 消费者确认；Then 能看到项目、服务人员、优惠、支付拆分和预计余额，手机号查询不等于扣款授权 |
| SV07 | Given 储值加现金支付；When 现金成功、失败或结果未知；Then 分别确认扣款、明确失败后释放、未知时持续查询并保留占用；关单后晚到款按交易作废路径退款 |
| SV08 | Given 全额或部分服务退款；When 回补确认；Then 按原项目支付分摊回原批次，累计不超过原扣款；现金退款状态与余额回补状态分别可查 |
| SV09 | Given 消费者申请退余额；When 审批和退款；Then 先预留本金和关联赠金，按充值来源逐笔退剩余本金，明确到账后终结本金与赠金，失败不显示到账 |
| SV10 | Given 充值、消费或退款已记账；When 查看详情；Then 展示发生时间、门店、项目、经办人、原活动、本金/赠金变化、该笔发生后余额及当前余额入口；原记录不可覆盖 |
| SV11 | Given 储值业务状态变化；When 触发通知；Then 按设计矩阵区分交易结果、待办、账户提醒、营销四类，事件重投不重复创建站内信，失败通知不回滚交易 |
| SV12 | Given 收款已成功但未入账、退款未知或账务差异；When 达到处理阈值；Then 生成带业务单号和下一步动作的商家/运营待办，消费者看到真实处理中状态 |
| SV13 | Given 运营检查日账；When 汇总；Then 账户余额=批次余额=流水净额，充值实收、服务消费额、未消费余额分别统计，储值消费不触发第二次现金结算 |
| SV14 | Given 三端评审；When 打开原型；Then 可浏览活动到充值、消费者授权消费、账单、退款和通知监控，并区分成功、处理中、失败及空态 |
| SV15 | Given 商家线下收款；When 员工登记并由有权人员确认凭据；Then 显示人工确认收款来源、经办人和消费者确认过程，不伪造通道交易号 |

## 三、消费者与商家操作

消费者：进入商家储值 → 选活动 → 查规则并支付 → 查到账 → 确认服务消费 → 查消费明细 → 必要时申请服务退款或退余额。

商家：创建活动 → 发布版本 → 查客户储值 → 发起充值或服务开单 → 查消费者确认结果 → 处理售后与退余额 → 日结对账。

运营：配置通知路由 → 处理收款与发放差异 → 查看账务与通知失败 → 在有权限且留痕的动作中恢复，不直接修改账户数字。

## 四、评审边界

固定活动发布审批角色、单人/单次额度、储值风险额度、低余额提醒阈值及对外通知模板属于实施前配置决策；本稿不宣称已获得微信模板或外发授权。原型使用同一组示例金额与虚构商家、客户资料，供流程评审。


## C 端优先级调整（2026-10-16 用户补充）

C 端首要需求为消费记录、消费明细和展示核销二维码。账户首页主操作为“消费记录”和“展示核销码”；消费记录展示项目、门店、时间、本金与赠金扣减、消费后余额，并可追溯原活动。线上购买储值为低等级需求，保留于次要入口与原型末尾，不作为首期核心验收前提。

核销码绑定本人账户及商家，短时有效并防重放；扫码仅识别账户并发起消费单，不直接授权扣款。消费者核对项目与金额后确认；二维码原型为不可实际扫码的视觉占位。新增 s24 核销码页。调整后共 24 屏：商家端 7 屏、C 端 16 屏、运营端 1 屏；先前 23 屏验证记录为调整前版本。


## 最新范围修订（2026-10-16，以本节为准）

用户明确收简页面：本金、赠金、充值批次及拆分不在页面展示，仅作为内部设计与账务规则保留。C 端核心仅为核销记录列表及简明详情（项目、金额、门店、时间、状态、单号），不展示内部资金分配。核销统一使用会员码，不新增独立储值核销码或页面。线上购买储值为低优先级，本期 C 端原型移除。

不支持线上退款：移除 C 端退款申请、进度及操作入口；原文关于线上退款的需求、流程及验收不属于本期范围。历史退款设计仅作为边界参考，不代表允许在线执行；如后续确需商家线下纠错或退费，另行确定审核、凭据及账务处理。原型中的商家退款审核仅为历史设计参考，非本期承诺功能。

本次原型 C 端仅保留 s14 核销记录、s13 核销详情、s23 空态；早期屏数及交互验证记录为历史版本，不适用于当前交付。


## C 端入口补充（2026-10-16）

主要路径：我的 → 核销记录，默认汇总本人全部商家、门店记录，按时间倒序；支持商家/门店筛选，无需先选门店。辅助路径：门店主页 → 我的核销记录，自动筛选当前门店，可切回全部。每条展示项目、金额、商家及实际核销门店、时间、状态；详情随所选记录展示。统一查询不合并各商家账户。会员码继续使用“我的”统一入口，无储值专用码。

新增 s25 我的入口、s26 门店入口、s27 统一会员码衔接示意；当前共 13 屏，C 端 6 屏。原型支持门店筛选、带筛选进入、各记录详情切换。会员码只是占位示意，不生成凭证。


## 默认储值门店目录及排序（2026-10-16，以本节覆盖此前默认流水列表规则）

统一入口先展示本人有成功储值记录的门店，点击门店后查看该店核销记录。余额已耗尽仍保留门店；只有核销而无储值记录的门店不进入默认储值目录。每个门店按 max(最近成功储值时间, 最近成功核销时间) 倒序，时间相同按门店号稳定排序。未付款、失败和处理中记录不更新排序；使用业务发生时间而非消息到达时间。没有核销时按最后储值时间排序。储值记录归属实际充值门店，同主体其他店发生核销只更新对应核销店的时间；主体通用余额不为所有门店虚构储值记录。

门店卡展示门店名、最近活动类型及时间，不展示本金赠金。主入口路径：我的 → 储值门店 → 门店核销记录 → 详情；门店主页入口直接进入本店核销记录。新增 s28 二级核销记录页，s14 改为储值门店目录。当前 14 屏，C 端 7 屏。
