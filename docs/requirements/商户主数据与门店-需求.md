## 一、需求来源：不是"字段不够"，是商家会撞墙

商家入驻时要填的东西，最终要能**变成一个通道能受理的进件请求**。
现在填的和通道要的对不上，而对不上的代价由商家承担：

| 现象 | 商家看到的 | 真实原因 |
|---|---|---|
| 入驻通过了，进件被拒 | 「资料都通过了为什么收不了款」 | 微信小微按**行业**给白名单，线上业态不收；而入驻时根本没问行业 |
| 门店主页少一段介绍 | 「我明明写了店铺简介」 | 简介只存在申请单上，通过审核后没写进商家主体 |
| 「按行业强制开积分」这条规则无法执行 | —— | `usr_merchant.points_forced` 的注释写着按行业，而行业字段不存在 |

所以本需求的目标不是"加两个字段"，是**让入驻时收集的信息足以判断这家店能不能做生意**。

## 二、功能点

### 2.1 商户基础属性（P0，已落地）

| ID | 功能 | 说明 | 端 |
|---|---|---|---|
| B-1.3.1 | **行业** | 入驻必选。取值来自平台维护的行业注册表，**决定可选的主体类型** | B / C 入驻表单 |
| B-1.3.2 | **店铺简介** | 入驻填写，通过审核后落到商家主体，C 端门店主页展示 | B / C |
| B-1.3.3 | 主体类型按行业过滤 | 选完行业后，不被该行业允许的主体在表单上**直接禁用**并说明原因 | B / C |
| P-11.1.7 | 行业主数据维护 | 平台维护行业的启停、小微准入、是否强制积分 | 平台端 |

**验收要点**

- 选「线上/虚拟」+「小微」提交 → 当场被拒，错误码 `70001`，文案给出「换个主体」这条出路
- 审核通过后，B 端「我的」能看到行业与简介；C 端门店主页能看到简介
- 行业停用后，**新入驻选不到，存量商家不受影响**——停用不是撤销资质

### 2.2 预定义主数据统一（P0，已落地）

平台维护、三端共用一份取值域：

| 主数据 | 表 | 管什么 |
|---|---|---|
| 支付渠道 | `sys_pay_channel` | 能否分账/补差/打款、支持的支付方式、限额 |
| 行业 | `sys_industry` | 能否小微进件、是否强制积分 |
| **商家主体类型** | `sys_merchant_subject` | 通道码映射、要不要执照、结算账户形态、是否受行业白名单限制 |

对外一个只读出口 `GET /common/master-data`，游客可读。

**为什么要统一**：这三样东西的规则**来自通道**，会随对方调整而变。
端上各写一份的直接后果是——微信放开了某个行业的小微，我们要发三个端的版本才能让商家选得到。

### 2.3 多门店（**已决策：不做**）

现状是「一个商家 = 一个店」。三个决定性问题的结论见
[ADR-011 §6](../technical/ADR/ADR-011-经营主体与门店边界.md)：

| # | 问题 | 结论 |
|---|---|---|
| 1 | 需要多门店，还是"一个老板开两家店"用两个主体就够？ | **两个主体就够，不做多门店** |
| 2 | 库存按门店独立还是主体共享？ | 独立（若将来做） |
| 3 | 评价归门店还是主体？ | 门店（若将来做） |

**结论（2026-08-07）：不做多门店。** 一个老板开两家店，就开两个主体——
进件、分账、结算、评价全部天然隔离，代价只是切换账号，
远小于让订单/结算/积分/履约四个域各长出一层。真出现连锁客户时再回到 ADR-011。

**P0 已执行（V42）**：`address` 与 `open_hours` 此前在 `usr_merchant` 与
`usr_merchant_store` **两张表都有**，靠一段双写代码维持一致。现在门面表是唯一权威。
这一步与多门店做不做无关。

## 三、不在本需求内

| 不做 | 为什么 |
|---|---|
| 营业执照上的「经营范围」文本 | 与库里现有的 `service_scope`（服务覆盖范围，ADR-009）是两件事。进件要的资质在 `qualifications`，够用 |
| 门店级独立进件 | 通道按主体发号，做不到；真需要就是两个主体 |
| 存量商家的行业自动映射 | 商品类目到行业**不是函数关系**（卖生鲜的可能是超市也可能是餐饮），推错直接影响他能不能开小微。由运营逐个划 |
| 支付宝小微准入 | 尚未确认，全部保守置 0。确认前小微只走微信 |

## 四、词典补充

| 词 | 含义 | 不要混淆 |
|---|---|---|
| **行业** | 商家的经营业态（餐饮/线下零售/…）。挂**商家**，决定通道准入 | ≠ 商品类目（挂**商品**，决定授权范围）。一家便利店横跨多个商品类目，行业只有一个 |
| **主体类型** | 小微 / 个体工商户 / 企业。决定要不要执照、钱打到哪儿 | ≠ 商家分层（`tier`，为引入大商家预留） |
| **经营范围** | 本仓库指 `service_scope`：这家店的货能被谁看到（ADR-009） | ≠ 营业执照上的经营范围 |
| **主体 / 门店** | 主体是通道与税务认的那个；门店是顾客感知的那个 | 一期两者**一一对应**且已决策不拆（ADR-011）。地址与营业时间归门面表 `usr_merchant_store`，主体表上没有这两列（V42） |
