## 1. 必须遵守的已确认规则

1. 门店创建时选择经营类型；每个行业展示 FREE／PRO／CHAIN 三档，FREE 最低且可继续使用。
2. 商业权益 code 只控制整个业务端的访问，不控制菜单、按钮或某个功能；进入端后继续执行现有角色权限。
3. 购买归属当前门店，不归付款账号；同一账号不同门店分别计算，不能跨店通用。
4. 同门店、同 code 的所有有限时长累计，包括 Plan、单端包、组合套餐和有限赠送。POS 到 12 月 1 日再买 30 天，合计到 12 月 31 日。
5. 后续 Plan 续费／升级保留独立端包未用时长。已用 10 天、剩余 20 天的端包遇到新 30 天 Plan，未来仍有 50 天。
6. 升级关闭旧 Plan 未用部分并按剩余实付价值抵扣；独立端包不转换、不重复抵扣，其余量保留顺延。
7. Plan、商品、期限、价格、可售端和权益组合由平台发布，App 不自行硬编码商业承诺。

默认设计：验证码登录即注册；先建门店并授予 FREE，再确认付费订单。周期为明确天数，Plan 组合固定周期、单端包保留余量排队；商业价格、退款政策、宽限及具体端组合仍以评审和平台发布为准。

### 2.1 全 App 的连接关系

保留底部“工作台／订单／商品／我的”。平台商城首期作为经营工具入口放在“我的”，工作台只增加当前门店方案／端状态的轻量入口，不新增第五个底部 Tab。

存量商品、销售订单、营销会员、库存、收入结算、员工权限继续使用现有入口。本次“商城订单”专指商家向平台购买服务或硬件，必须与“顾客销售订单”区分；门店软件访问权益也必须与给消费者发放的券、卡、储值区分。

业务端入口只展示已经验收且适配门店经营类型的端。餐饮／美业在本原型中只体现经营类型、Plan 和端资格，不推断本 App 已具有相应行业作业页面。某端未实现时只展示不可购买的规划状态，不制作可用假入口。

## 3. 用户、权限与信息边界

| 用户 | 可以查看 | 可以操作 | 不能据此获得的能力 |
|---|---|---|---|
| 已登录无店账号 | 经营类型、三档公开信息、建店草稿 | 创建自己的首店，创建后购买 | 未创建门店不能生成门店付费权益 |
| 老板／明确授权的采购人员 | 门店订阅、端权益、订单、抵扣余额 | 报价、购买、续费、升级、申请退款 | 不能跨店消费权益、不能访问平台运营端 |
| 仅有商城订单查看权的人员 | 授权范围内订单及其成交金额、交付与退款进度 | 查看订单、物流和原单进度 | 不因能看订单就获得付款、取消、退款申请或余额访问权 |
| 普通店员 | 当前店可进入端、到期时间、必要联系入口 | 进入已有资格且岗位允许的业务端 | 默认不展示采购金额、余额账本和付款按钮 |
| 平台内部人员 | 本原型不包含平台管理页 | Plan／商品发布在平台运营端维护 | B 端不出现修改价格、人工赠送、审核退款等管理入口 |

端权益与岗位权限分别判断。已购买端但店员岗位无权进入时写“暂无访问权限”，不能再次诱导购买。采购能力以后端 `canPurchase` 等权限结果为准，不仅按前端角色名称判断。

原型必须分别演示三个权限结果：`canPurchase` 控制报价、下单、付款、取消和退款申请；`canViewEntitlementSources` 对应采购／订阅管理授权，控制 P11→P12；`canViewCommerceOrders` 对应采购或商城订单查看授权，控制 P19/P20 和 P12→原单。三者不能互相推断。无来源查看权时 P11 仅显示摘要，不给无权跳转；有来源管理权但无订单查看权时 P12 的来源编号只读、不跳原单。P24/P25 按当前 API 仅供采购权限查看，不给只读订单人员开放抵扣账本。后端仍逐 API 校验，原型条件不是安全边界。

## 4. 主要流程

### FL01 首次登录与免费开店

登录并同意协议 → 身份认证 → 无门店 → 选择经营类型 → 填门店资料 → 展示该类型三档并选 FREE → 确认开店 → 服务端建店和 FREE 授予成功 → 基础经营台。

只有服务端明确返回门店为空才显示无店态。加载失败显示重试，不显示“你还没有门店”。返回上一步保留草稿；重复点击创建只产生同一门店。

### FL02 选择付费方案开店

经营类型／资料／方案与 FL01 相同 → 选付费期限 → 确认开店 → 先创建门店及 FREE → 为真实 storeNo 报价 → 展示订单确认 → 用户确认付款 → 支付处理中 → 数字权益交付完成 → 当前门店权益／进入目标端。

离开支付、取消支付、报价失败都保留已创建的 FREE 门店，返回页面提示“门店已创建，当前使用免费版”；不能让用户再次填写开店资料或重复建店。

### FL03 已有账号登录和切店

认证 → 获取可访问门店 → 一店默认进入／多店选择 → 显示切店过程 → 加载门店经营类型、Plan、端权益和角色 → 工作台。后续切店统一通过现有入口。

切换门店时清空旧店商城筛选、购物意向、报价和端上下文；旧店未付款订单仍属于旧店，不能改绑到新店。订单详情始终明确归属门店。

### FL04 从 Plan 进入商城购买

我的→订阅方案→三档比较／进入平台商城→选 Plan／端包／开店组合／硬件→商品详情→服务端报价→订单确认→创建订单→渠道支付→服务端确认支付→数字整组交付／硬件发货。

首期不新增跨店购物车；一个订单对应一个门店。组合套餐以平台 SKU 交付清单为准，不允许在 App 自拼未定价组合。

### FL05 同端续费与累计

门店权益→POS 来源和合计到期→续费／商城加购→展示“增加 30 天，预计到 12 月 31 日”→确认付款→查看来源时间片和新的合计到期。

之后购买包含 POS 的 Plan 时，报价展示“保留端包剩余 20 天”，提交后 Plan 结束再接续端包；不能仅显示 Plan 到期而误称 POS 同时到期。

### FL06 Plan 升级抵扣

当前订阅→升级→选同经营类型高档与期限→服务端报价→列旧 Plan 未用价值、已有余额、本次抵扣、新价和现金应付→确认订单→支付／零元结算→旧 Plan 转换＋新 Plan 生效＋端包余量保留→结果页。

报价过期或版本变化，展示新报价并再次确认，不自动按增加后的金额扣款。零元单也要明确“确认升级”，不能伪造支付渠道成功。低档购买不能绕过升级直接覆盖当前高档；主动周期内降档首期不开放。

### FL07 某业务端到期

点击业务端／恢复该端会话→服务端检查→该端到期→显示到期时间与下一步。采购人员“去续费”；店员“联系老板”；另给“返回经营台”。账号会话保留，商城和必要历史处理入口可用。

主体资质不足、门店治理停用、岗位无权限与商业到期分别提示；付费购买不能解决前三类问题，不应一律显示购买按钮。

### FL08 商城订单、硬件与退款

商城订单→订单详情→数字交付和硬件包裹分开查看。需要退款→选原组件／数量与原因→展示适用政策及预计处理方式→申请提交→查看审核／退款／权益调整状态。

部分数字来源已用或已升级转换时，显示需审核或联系平台，不提供任填金额的直接退款入口。现金原路退款和订阅抵扣余额恢复分别列示，不能把后者写成现金到账。

## 8. 页面与 API 对照

| 页面组 | API 合同组 | 要点 |
|---|---|---|
| P01–P03 | auth/login、auth/context、store/list、门店 context | 只有空结果才是无门店；登录不需要先有付费权益 |
| P04–P07 | business-types、行业 plans、quick-start／store/create | 行业Plan在未建店前可读；付费必须用新建真实门店报价 |
| P08–P13 | subscription、entitlements、sources、end-access／end-sessions | 合计到期读 code 连续覆盖，不用 Plan 单一到期日替代 |
| P14–P17 | mall categories／products、quotes、orders | 升级／续费走同一订单合同，以 intent 区分 |
| P18–P21 | payment-attempts、payment-refresh、order、shipments | App只触发支付／查单，服务端事实推进交付 |
| P22–P23 | refunds、refund detail | 金额与可退来源由服务端决定 |
| P24–P25 | subscription-credits、ledger | 门店专属的订阅抵扣，与现金／消费者储值分离 |

后端建议合同尚未实现时，原型可用明确标注的 fixture 演示，不能将 mock 成功说成真实支付或真实权益已发放。

## 9. 状态、金额与关键文案

| 场景 | 建议用户文案／呈现 | 操作 |
|---|---|---|
| 开店成功尚未付款 | 门店已创建 · 当前使用免费版 | 继续购买／进入经营台 |
| Plan与端包累计 | 本次增加30天 · 预计可用至12月31日 | 确认订单 |
| Plan续费保留端包 | 已保留端包剩余20天 | 查看权益明细 |
| 某端到期 | POS使用资格已到期 | 去续费／联系老板 |
| 付款已确认但交付未完成 | 已付款 · 权益开通中 | 查看订单，不显示再次支付 |
| 支付未知 | 支付结果待确认 | 查询结果，不先建另一单 |
| 数字完成、硬件未发 | 权益已开通 · 硬件待发货 | 查看权益／订单 |
| 抵扣结余 | 剩余抵扣101元，留在本店订阅余额 | 查看余额，不显示提现 |
| 报价改变 | 报价已更新，请确认金额 | 确认新报价 |
| 端内岗位无权 | 暂无访问权限，请联系老板 | 返回经营台，不显示购买诱导 |

金额显示必须附币种语义，原价、优惠、Plan抵扣、现金应付分行列示；不把抵扣当本单已付款现金。新购混合套餐只让 Plan 组件使用订阅余额，硬件不能抵扣。

## 10. 原型情景与验收清单

原型至少提供以下可切换情景。所有店名、金额、订单和日期为虚构测试数据，价格不作为正式报价。

| 情景 | 数据条件 | 必须走通 |
|---|---|---|
| S01 | 新账号，无店 | P01→P03→P04→P05→P06 FREE→P07→P08 |
| S02 | 无店选PRO，支付取消 | 门店保留FREE，回工作台不再要求建店 |
| S03 | 同账号零售／餐饮／美业三店 | 切店后经营类型、三档、商城和端权益全部切换；不出现新行业作业页 |
| S04 | 普通店员；另一个仅有订单查看权的人员 | 店员只看端摘要且无来源跳转；订单只读人员可看成交金额与进度，但没有付款／取消／退款申请／余额入口 |
| S05 | Plan POS到12月1日，加购30天 | 报价与交付结果均为12月31日，来源各自可查 |
| S06 | 上例再续Plan30天 | 原端包30天保留，合计到次年1月30日 |
| S07 | 端包已用10／余20天，再购30天Plan | 新Plan后仍留20天，当前起合计50天；来源出现拆片 |
| S08 | 365元/365天Plan已用165天，升级699元 | 旧值抵200元、现金499元，独立端包余量不参与抵扣 |
| S09 | 可抵价值800元，目标699元 | 0元确认升级，101元余额留本店 |
| S10 | Plan＋硬件组合 | 分项展示数字开通与硬件物流；抵扣不买硬件 |
| S11 | 支付回调重复／查单重复 | 原订单状态更新，来源只出现一份时长 |
| S12 | 数字单正在支付，试图另一笔数字购买 | 引导查看原单；纯硬件仍可购买 |
| S13 | 某端到期／岗位无权／治理停用 | 三种提示与CTA不同，账号有效时不清登录 |
| S14 | 报价过期或SKU停售 | 刷新价格／重新选购，不能自动多扣金额 |

| S16 | 旧主体合同有宽限／额度保护 | 清楚标“原合同”，不与本店新Plan端期限合并承诺 |
