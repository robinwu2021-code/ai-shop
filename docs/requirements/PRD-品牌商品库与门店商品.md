# PRD 品牌商品库与门店商品（连锁选品）

状态：待确认
创建：2026-10-08
决策依据：[ADR-030 商品归属改为门店 Offer 与品牌库](../technical/adr/ADR-030-商品归属改为门店Offer与品牌库.md)
设计：[TDD-商品归属重构-品牌库与门店Offer](../technical/design/TDD-商品归属重构-品牌库与门店Offer.md)

---

## 1. 为什么要做

### 1.1 触发问题（线上实例）

商家反馈「虹选粮油的经营范围是嘉逸花园，小程序选嘉逸花园看不到商品」。查下来是**两个独立缺陷**：

1. **重复聚落**（与商品模型无关，可独立先修）：「嘉逸花园」在聚落表里有两条，
   坐标完全相同，一条是系统批量导入的（区级区划码），一条是商家当天配经营范围时**自建**的（街道级）。
   门店经营范围指向自建那条，而买家在选社区列表里可能选到另一条 —— 那条没有任何商家服务，于是 0 商品。
   同类重复在龙华区有 21 个以上（「和成天下」8 条、「中建三局生活区」3 条）。
2. **连锁门店的商品归属别扭**：「虹选粮油」其实不是一个商家，是「虹选科技有限公司」名下的**一家门店**。
   该主体 4 家门店共享一份主体商品池，靠「店级上架行」区分谁卖什么。
   店主的心智是「我这家店的商品」，系统的模型是「主体的商品投影到我店」，两者不一致。

### 1.2 现状的三个硬伤

| 硬伤 | 现状 | 后果 |
|---|---|---|
| 连锁没有自己的商品库 | 只有平台级标准品库（运营维护、复制式取用） | 连锁总部无法维护一份自家商品给旗下门店选品 |
| 加盟跨不过主体 | 库若按主体，同品牌不同法人各一份 | 改一次要改 N 份 |
| 门店差异化靠覆盖表 | 门店价 1 条、门店库存 2 条（近乎空置） | 机制太绕，商家不用；等于没有门店差异化 |

---

## 2. 目标与非目标

**目标**
- 连锁总部能维护**一份品牌商品库**，旗下门店（含跨法人的加盟店）从库里选品上架。
- 门店也能**不经库、直接自建商品**。
- 「这家店卖什么、什么价、多少货、上没上架」**一处可答**，不再是四张表拼。
- 总部改库条目（标题/图/规格），旗下门店**自动跟变**；价和库存永远是门店自己的。

**非目标**（本期不做）
- 门店级独立进件/分账/费率 —— 通道按营业执照发号，保持按主体（ADR-011）。
- 品牌库带价带库存 —— 库是模子。
- 跨品牌共享库条目 —— 要共享用平台标准品库。
- 废弃平台标准品库 `prd_spu_std` —— 它是另一层，保留。

---

## 3. 角色

| 角色 | 新增能力 |
|---|---|
| **品牌/连锁总部** | 维护品牌商品库；看旗下门店选品与铺货率 |
| **门店店长** | 从品牌库选品上架；自建本店商品；定本店价/库存/上下架 |
| **运营** | 维护品牌与门店的归属；平台级强制下架（保持现有能力） |
| **买家** | 不感知库与品牌：看到的是「这家店在卖的东西」 |

## 4. 验收标准（AC）

### 4.1 品牌与库

| AC | 标准 |
|---|---|
| AC1 | 存在「品牌/连锁」这一级，**在经营主体之上**，一个品牌可挂多个主体（支持加盟跨法人） |
| AC2 | 品牌商品库条目含：类目、标题、副标题、主图、详情图、规格组（规格选项带 `optionCode` 以便跨店可比）；**不含价、库存、上下架** |
| AC3 | 库条目只有品牌总部可写；旗下门店只读 |
| AC4 | 未归属任何品牌的独立单店，不受影响：照常自建商品（无库可选不报错，入口不出现） |

### 4.2 门店选品与自建

| AC | 标准 |
|---|---|
| AC5 | 门店可从**本品牌库**选一条或多条，一键生成本店商品；生成后价/库存由门店填 |
| AC6 | 门店可**直接自建**商品，不经过任何库 |
| AC7 | 同一库条目在同一门店**只能有一条**在用的商品（不允许重复选同一条） |
| AC8 | 商品列表能分辨来源：「品牌库」还是「本店自建」 |
| AC9 | 门店**取消上架/删除**自己的商品，不影响库条目，也不影响其他门店 |

### 4.3 引用关系（库→门店）

| AC | 标准 |
|---|---|
| AC10 | 总部改库条目的标题/图/规格 → 引用它的所有门店商品**自动跟变**（无需门店操作） |
| AC11 | 总部改库条目**永不**改动门店的价、库存、上下架状态 |
| AC12 | 库条目被总部归档 → 已引用它的门店商品**照常在售**（不被动下架），但不能再被新门店选中 |
| AC13 | 门店可对引用来的商品做**局部改写**（如本店副标题）；被改写的字段不再跟随库 |

### 4.4 门店独立经营

| AC | 标准 |
|---|---|
| AC14 | 价、库存、上下架**都在门店这一层**，同品牌两家店可完全不同 |
| AC15 | 一家店卖掉的库存**不影响**另一家店（ADR-011 §6.2 #2 的「库存按门店独立」真正落地） |
| AC16 | 运营的平台级强制下架**仍然有效**，且作用在门店商品这一层 |

### 4.5 买家可见性

| AC | 标准 |
|---|---|
| AC17 | 买家选一个社区，看到的是「送得到这个社区的门店，在架的商品」—— 判据仍是 `ReachRule`（ADR-009/013），不另写一遍 |
| AC18 | 同一品牌多家店都送得到同一社区时，同一件商品**不重复展示**；落到唯一一家提供门店（现有「默认店优先、否则店号最小」口径不变） |
| AC19 | 买家不感知品牌库：详情页不出现「库」字样 |

### 4.6 重复聚落（独立于本次重构，可先发）

| AC | 标准 |
|---|---|
| AC20 | 同名且同位置的聚落**不再新增重复**：商家配经营范围/开通时命中已存在的，复用其聚落号，不插新行 |
| AC21 | 买家选社区列表里**不出现同名同址的两条** |
| AC22 | 嘉逸花园这一例修好：买家选「嘉逸花园」能看到虹选科技旗下服务该聚落门店的在架商品 |
| AC23 | 存量重复（龙华区 21+ 组）有一份可重复执行的合并处置，且合并**不丢**任何已有经营范围引用 |

## 5. 关键交互

### 5.1 门店建品（B 端）

```
[商品] → 新建
          ├─ 从品牌库选品      ← 仅当本店所属主体归属某品牌时出现
          │     └─ 库列表(按类目/关键词/条码搜) → 勾选多条 → 填价/库存 → 上架
          └─ 自己建一件新的    ← 始终可用（现有录入链路，含压缩包导入与文字识别）
```

### 5.2 总部维护库（运营端或品牌端）

库条目列表 → 新建/编辑（类目、标题、图、规格组）→ 保存即对旗下门店生效（AC10）。
列表上显示**被几家门店引用**（铺货率），归档时提示「N 家门店在用，归档后它们照常在售」（AC12）。

---

## 6. 迁移对商家的可见影响

| 场景 | 迁移后 |
|---|---|
| 单店主体（绝大多数） | **无感**。原商品变成默认店的门店商品，货号不变 |
| 多门店主体（如虹选科技 4 店） | 原「主体商品 + 店级上架行」按店拆成各店自己的商品；原货号留给默认店那条，其余店新发号 |
| 已有门店价/库存覆盖行 | 并入对应门店商品的价/库存 |
| 历史订单 | 不受影响（订单自带快照，且已双写 `store_no`） |

---

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 一件商品裂成多条，商家觉得「变多了」 | 单店无感；多门店在列表按门店分组展示，并在迁移说明里讲清 |
| 总部改库误伤门店（改了不该改的） | AC11 硬约束：价/存/上下架永不跟随；AC13 允许门店改写后脱钩 |
| 历史货号引用断裂 | 原货号保留给默认店；订单链路本就带快照与 `store_no` |
| 合并重复聚落丢引用 | AC23：合并前把指向被并聚落的经营范围行全部改指，带校验 |
