状态：需求草案，待后端评估。取代先前请求的「新增 `PAY_ORDER`／`OFFLINE_RECORD` 两种发票来源」。

## 一、背景与原则

- **现况**：`POST /biz/invoices` 只接受 `SUB_ORDER`，因为发票来源插件（`InvoiceSourcePort`，ADR-063）目前只有 `SubOrderInvoiceSourcePortImpl` 一个，它读 `ord_sub_order + ord_item` 的冻结资料。
- **手持机的问题**：POS 收银只产生收款订单（`PYO…`）或现金记录（`OFR…`），没有商品明细与课税别，开不了票；订单列表、退款折让、云端打印、库存扣减也都缺订单（缺口 D1）。
- **原则**：
  1. **开票资料只来自订单**，开票时不由 App 提供明细。
  2. 订单按**统一格式**提交（各渠道共用），必须带齐开票所需资料。
  3. 缺资料的订单（例如直接输入金额）可在**结账时**或**开票时**补齐，补的内容写回订单并冻结。
  4. 发票模块只认「资料齐全」的订单；沿用 `SUB_ORDER` 插件，不再为每种单据写来源插件。

## 二、开一张台湾电子发票必须有的资料

| 类别 | 字段 | 说明 |
|---|---|---|
| 卖方 | 门店、营业人统编与名称 | 后端按门店带出，订单不用传 |
| 交易 | 订单号、币别、付清时间 | 付清时间决定期别 |
| 明细 | 每行：品名、数量、单位、单价、金额、**课税别** | 至少一行；折扣、优惠用负数行 |
| 总额 | 应税／零税率／免税三类销售额、税额、总计 | 由明细算出，必须等于实收 |
| 买受人 | 一般消费者／统编＋抬头／载具类型＋号码／捐赠码 | 四选一，规则同 `TwBuyerRules` |
| 状态 | 已付清、无退款 | 部分退款要开折让，不是开新票 |

## 三、各种情况与缺什么

| 情况 | 明细从哪来 | 缺的资料 | 补的时机 |
|---|---|---|---|
| 商品下单（扫码或点选 SKU） | 后端按 SKU 冻结品名、课税别 | 无 | — |
| **直接输入金额** | 只有金额 | **品名、课税别** | 结账时或开票时 |
| 商品＋输入金额混合 | 部分来自 SKU | 输入金额行的品名、课税别 | 同上 |
| 单品改价、整单优惠、点数折抵 | 改价写在行上；优惠是负数行 | 混合税别时优惠要分摊到税别 | 后端按比例自动分摊；分不了回待补 |
| 会员结账 | 会员资料 | 会员载具（会员有设就自动带入） | 结账时 |
| 买统编、载具、捐赠 | 顾客当场提供 | 买受人 | 结账时或开票时 |
| 分次付款（现金＋刷卡） | 一张订单多笔收款 | 无（收款加总＝总额） | — |
| 预订订金、尾款 | 订金单、尾款单 | 发票开在哪一阶段 | 门店设定（全额一次开或分次开） |
| 离线现金单 | 本机先存，连线后补传 | 同上各种 | 补传后照常判断 |
| 开票前部分退款 | — | 不能开原额 | 开实收净额，或先开再折让（门店设定） |

## 四、统一格式

### 1. 建立订单（结账时，各渠道共用）

```json
POST /biz/store/{storeNo}/orders                     // 名称待定；头带 Idempotency-Key
{
  "clientOrderNo": "POS-…",                          // 端上单号：离线补传与幂等
  "channel": "POS",                                  // POS / ONLINE / FOOD / BEAUTY …
  "currency": "TWD",
  "lines": [
    { "kind": "SKU",    "skuNo": "S…", "quantity": 1, "unitPriceMinor": 2500 },
    { "kind": "CUSTOM", "quantity": 1, "unitPriceMinor": 1000,
      "name": "清潔用品",                              // 可不填：缺了就是「待补」
      "taxType": "TAXABLE",                          // 可不填：缺了用门店默认税别，或标为待补
      "invoiceCategory": "C-CLEAN" }                 // 可选：门店常用品项（带出品名与课税别）
  ],
  "adjustments": [ { "kind": "DISCOUNT", "name": "整單 9 折", "amountMinor": -350, "allocate": "AUTO" } ],
  "member":  { "memberNo": "…" },
  "invoice": { "buyer": { "type": "CARRIER", "carrierType": "3J0002", "carrierId": "…" },
               "timing": "ON_PAID" },                // ON_PAID 付清自动开 / MANUAL 手动 / LATER 稍后再补
  "operator": { "staffNo": "…" }
}
```

- 有 SKU 的行：**品名、课税别以后端商品资料冻结为准**；App 送的成交价与商品价不同时按改价权限判断。
- 自订行（直接输入金额）：品名、课税别可空；空着就进「待补」。

### 2. 返回：订单＋开票准备度

```json
{
  "orderNo": "SO…", "status": "AWAITING_PAYMENT", "totalMinor": 3150,
  "lines": [
    { "lineNo": 1, "name": "Test Tissue", "taxType": "TAXABLE", "amountMinor": 2500, "frozen": true },
    { "lineNo": 2, "name": null, "taxType": null, "amountMinor": 1000, "frozen": false }
  ],
  "invoiceReadiness": {
    "state": "NEEDS_INFO",                            // READY / NEEDS_INFO / NOT_PAID / REFUNDED / ISSUED
    "missing": [ { "lineNo": 2, "fields": ["name", "taxType"] } ],
    "buyerSet": true
  }
}
```

订单详情（`GET`）也带 `invoiceReadiness`，结账页、订单详情、发票列表都能显示「可开票／待补资料／未付清」。

### 3. 收款挂订单

- 现金：`POST /biz/payment/offline-records` 带 `orderNo`（字段已存在）。
- 收款码、付款链接：`POST /biz/payment/collection` 带订单号（现有 `bizRef`）。
- 刷卡等其他方式同样带订单号。
- 收款加总等于订单总额时，订单转「已付款」；若 `invoice.timing = ON_PAID` 且准备度为 READY，自动开票。

### 4. 补充开票资料（结账时或开票时都走这一支）

```json
PUT /biz/orders/{orderNo}/invoice-data               // 头带 Idempotency-Key；需权限
{
  "lines":  [ { "lineNo": 2, "name": "清潔用品", "taxType": "TAXABLE" } ],   // 只能补空着的字段
  "buyer":  { "type": "COMPANY", "taxId": "50766768", "name": "創科系統有限公司" },
  "reason": "輸入金額補品名"
}
→ 返回同第 2 点格式，invoiceReadiness 更新
```

### 5. 开票：只送订单号

```json
POST /biz/invoices { "sourceType": "SUB_ORDER", "sourceNo": "SO…" }   // 头带 Idempotency-Key
→ 准备度不是 READY 时回 26002（INVOICE_SOURCE_NOT_READY），并附 missing 清单
```

## 五、规则（后端执行）

1. **资料来源只有订单**：开票接口不收明细；要改明细只能透过「补充开票资料」写回订单。
2. **只能补空的，不能改已冻结的**：SKU 行、已补过的行不能改；补的人、时间、原因留稽核纪录。
3. **开票后订单的开票资料锁死**：要改就作废后重开，或开折让。
4. **课税别有边界**：自订行默认用门店默认税别；选零税率或免税需权限，或只能从门店「常用品项」里选。
5. **一致性**：明细加总＝总额＝收款加总；混合税别的整单优惠按金额比例自动分摊，分不了回待补。
6. **幂等**：建立订单以 `clientOrderNo`＋Idempotency-Key；开票以订单号（同单再开回原发票）。
7. **退款**：退款挂订单；已开票的部分退款开折让，全额退款按规则作废或折让。

## 六、手持机对应画面

| 时机 | 画面 | 做法 |
|---|---|---|
| 输入金额时 | H05b | 键盘下方加「品項」快选（门店常用品项）；选了带出品名与课税别，不选就是待补 |
| 收款后 | H10／P03 | 准备度不是 READY 时先补品名、课税别，再选载具开立 |
| 事后开票 | H12 → I03 | 显示「待補資料」，补完再开 |
| 门店设定 | I01 | 默认课税别、常用品项清单、开票时机（付清自动开／手动／稍后） |

## 七、对后端的请求

1. 新增「建立订单」接口（统一格式），POS 订单落成 `ord_sub_order + ord_item`，状态待付款。
2. 订单行支持「待补」字段（自订行的品名、课税别），并提供「补充开票资料」接口与开票准备度。
3. 收款（offline-records、collection、刷卡）挂订单号；收款加总等于总额时订单转已付款。
4. 门店设定：默认课税别、常用品项（品名＋课税别）、开票时机。
5. 发票模块沿用 `SUB_ORDER` 插件，准备度不是 READY 时回 26002 并附 missing。

## 八、一并解决的缺口

- D1 零售下单（订单没有商品行）
- X11 发票只接受子订单；X12 云端打印要子订单
- X15／X16 库存只能用 `store-stock` 设值（可改为下单时扣）
- 订单列表看不到商品、退款没有原因与经手人、报表要从明细算（N8–N10）
