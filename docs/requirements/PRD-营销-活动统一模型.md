## 一、一句话

**用一个活动模型覆盖所有玩法；拼团与社区集单都要，各管一件事。**

- 拼团（凑够人数成团）是**拉新工具**：买家转发，替商家带人。
- 社区集单（到截单时间成交）是**日常经营**：商家以销定采，按量进货、统一送到自提点。

---

## 二、谁、在什么场景下用

| 角色 | 场景 | 要的是 |
|---|---|---|
| 店主（B 端） | 每天发一期鲜果集单，晚上看订了多少、第二天按量进货 | 不压货、不白跑一趟采购 |
| 店主 | 节日前做一个拼团，让老客帮忙转发 | 用低价换新客 |
| 店主 | 周末做满减、给沉睡老客发券 | 配一次就不用管 |
| 买家（C 端） | 在商品页看到拼团价 / 集单价 / 可领的券 | 看得懂、不白等 |
| 平台运营 | 发起中秋大促，商家报名、平台出一半让利 | 预算可控、商家可审 |

## 三、范围

### 3.1 要做

| 块 | 内容 | 原型 |
|---|---|---|
| 活动 | 一个模型：头 + 条件 + 利益 + 约束（+ 实例）；新建两步（填写 → 确认），玩法是表单字段 | s02–s08 · s35 |
| 玩法 | 满减、折扣、特价、第二件、买赠、**拼团**、**社区集单**、秒杀、新客立减 | s03 |
| 拼团 | 团的开、凑、成、散；商家开团与买家开团 | s09–s10 · s21–s22 · s34 |
| 社区集单 | 按期收单、截单、起订量兜底、按商品与自提点汇总、去采购 | s19–s20 · s26 · s31–s33 · s37 |
| 券 | 列表、新建（类型是字段）、详情、发放（选人群）、发放结果、核销、C 端领券与出示 | s12–s18 · s24–s25 · s36 |
| C 端露出 | 商品页价格与优惠、确认订单的优惠明细（先活动后券） | s21 · s23 · s26 |
| 平台活动 | 运营发起、商家报名、运营审核；出资与预算 | s27–s30 |

### 3.2 不做（这一期）

- 条件之间的「或」：用两个活动表达。
- 分组叠加：同一单里活动**互斥取最优**，再叠券；叠加组字段预留、界面不给。
- 砍价、助力、签到、抽奖、预售定金：模型能表达，界面不画、不开放。
- 储值卡：那是预收资金，不是券。
- 集单跨商家：**集单只在一个商家内**，不做多家拼一车（2026-09-18 定）。配送沿用现有自提点履约。
- 「自己组合」（s11，一条活动多条件、多利益）：随平台活动在 P3 做；P1 玩法面板里不放这一项。

## 四、业务规则

### 4.1 活动

1. **玩法是模板，不是类型。** 每个玩法 = 预填好的条件类型 + 利益类型；加玩法不改算价。
2. **长期活动必须设份数或预算其中一个**，否则不能发布。
3. **同一单里多个活动同时命中时，只给对买家最优惠的一个**；券在活动之后的金额上再算。
4. **进行中只能改结束时间与上限**；改规则须结束后另建（已有订单按旧规则算过价）。
5. **结束活动不影响已开出去的实例**（已开的团、已下单的集单期）：它们照常走完。
6. 发布前若与其他进行中活动商品重叠，确认页提示「同一单只享更优惠的一个」。

### 4.2 拼团

1. 成团条件是**不同买家数** ≥ N；同一人买多件只算一人。
2. 团有截止时限（默认开团后 24 小时）；到时未凑齐，**自动退款**。
3. 商家与买家都能开团；团限定一个自提点。
4. 活动停了，已开的团照常到期；团可单独「散团退款」。

### 4.3 社区集单

1. **一期 = 一个集单活动在一个截单日的全部订单。** 每天一期（或按活动的周期）。
2. 截单前买家可取消；截单后不能取消，商家开始采购。
3. **起订量可选。** 截单时未达起订量：商家选「取消本期（全额退款）」或「照常发货」；
   超过**处理时限**商家未处理，**自动取消并退款**。处理时限**每个活动单独配置**（默认截单后 14 小时）。
4. 截单后生成本期汇总：按商品、按自提点的份数；「去采购」把按商品的汇总带进进销存进货单。
5. 提货日按活动规则算（如「次日 09:00 起」），订单与履约批次都用这个日期，**不再用下单日**。
6. 同一 SKU 不能同时在「集单」与「SKU 预售」（`presale_quota > 0`）中；发布时拦。
7. **截单后下的单进入下一期**；商品页的截单时间随之显示下一期的。

### 4.4 券

1. 券类型（现金 / 折扣 / 兑换 / 次卡 / 免运费）是表单字段；折扣券必须填封顶。
2. 保存前算出「最多支出」= 数量 × 面额（折扣按封顶）。
3. 停发不影响已领的券。
4. 定向发放按人群；7 天内收过消息、未绑手机号、关闭本店消息的人**跳过并逐项说明**。

### 4.5 平台活动

1. 平台定：时间、玩法、规则、出资方式、平台预算、报名截止、报名门槛、类目与城市。
2. 商家填：商品、份数；界面显示平台补贴与商家承担的每单金额及「最多承担」总额，不显示比例。
3. 运营审核时看得见平台预算已占用多少；超预算的报名不能通过。
4. 审核通过后按平台时间自动开始。
5. **平台出资按统一结算周期结给商家**：随订单进入商家的常规结算单，作为平台补贴项，不单独打款、不月末另补。

## 五、验收标准

| # | 验收标准 | 原型 |
|---|---|---|
| AC-1 | 新建活动为两步；玩法是表单第二行，选定后才出现「规则」一组；满减与拼团同一张表，只有规则组不同 | s03–s06 |
| AC-2 | 长期活动未设份数也未设预算时，不能发布 | s04 |
| AC-3 | 同一单命中两个满减，只减更多的那个；券在活动之后的金额上计算 | s23 |
| AC-4 | 进行中的活动只能改结束时间与份数，改规则被拒 | s35 |
| AC-5 | 结束一个拼团活动后，已开的团仍可成团或到期退款 | s08 |
| AC-6 | 拼团按不同买家计数；成团时限取活动配置；到截止未凑齐自动退款 | s10 · s22 |
| AC-7 | 集单：截单前买家可取消，截单后不可 | s37 |
| AC-8 | 集单：订单与履约批次的提货日取活动规则算出的日期，不取下单日 | s20 · s37 |
| AC-9 | 集单：截单后按商品、按自提点汇总份数，与订单明细一致 | s20 |
| AC-10 | 集单：未达起订量时商家可取消本期（全额退款）或照常发货；超过该活动配置的处理时限未处理，自动取消 | s19 · s33 |
| AC-11 | 集单：同一 SKU 在预售中时，不能加进集单活动 | s19 |
| AC-12 | 新建券保存前显示最多支出；折扣券不填封顶不能保存 | s13–s14 |
| AC-13 | 定向发券时，被跳过的人按原因分项计数 | s16 |
| AC-14 | 平台活动报名超出平台预算时，审核不能通过 | s30 |
| AC-15 | 商家首页入口：集单排在团前；差人的团与未达起订量的期用黄色标出 | s01 · s31 |
| AC-16 | 平台活动的平台出资进入商家常规结算单（平台补贴项），与订单同一结算周期 | s28 |
