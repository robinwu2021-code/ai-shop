## 二、按角色 × 权限码

| 角色 | 能做 | 权限码 |
|---|---|---|
| **商家 · 店主** | 进件、看账、申请开票、看欠款 | `biz:finance` |
| **商家 · 员工** | 按授权，默认**看不到钱** | 无 |
| **运营 · 财务** | 应付对账与付款、发票、放款复核 | `finance:*` |
| **运营 · 风控** | 挂起处置、名单、追偿 | `risk:*` |
| **运营 · 超管** | 通道设置、费率版本 | `finance:rate:update` |

> **两条边界写在这里，因为它们最容易被顺手打破**：
> ① 商家员工默认看不到钱 —— 「看账」不是基础能力，是要单独授权的；
> ② 运营端**不下发分账、不解冻**：那些动作有自己的触发路径（结算生成、售后裁决），
> 在运营台放一个「立即分账」按钮等于给人一个绕过状态机的口子，而这条链路动的是真钱。

## 三、按状态：钱的每一个位置

| 状态 | 钱在哪 | 谁能改 | 出口 |
|---|---|---|---|
| `PENDING` | 商家二级户 · 冻结 | 系统（批次放行） | `SPLITTING` |
| `SPLITTING` | 通道处理中 | 通道回执 | `SPLIT` / `RETRYING` |
| `SPLIT` | 已发出，未确认 | **只有通道回执** | `SPLIT_CONFIRMED` / `REVERSED` |
| `SPLIT_CONFIRMED` | 商家可用余额 | — | `REVERSED` |
| `RETRYING` | 同 `PENDING` | 系统 | `SPLITTING` / `MANUAL` |
| `MANUAL` | 同 `PENDING` | 人工 | 终态 |
| `REVERSED` | 已回退 | — | 终态 |
| `FROZEN_BACK` 🆕 | **已自动解冻，佣金收不到** | — | 终态 + 告警 |
| `OFFLINE_SETTLED` | 商家口袋（从没进平台） | — | 终态 |
| `PENDING_RECON` | 平台户 | 运营确认 | `CONFIRMED` |
| `CONFIRMED` | 平台户 | 运营付款 | `PAID` |
| `PAID` | 已打给供应商 | — | 终态 |

> `SPLIT → SPLIT_CONFIRMED` **只能由通道回执推进**，不给运营端按钮。
> 与 `APPROVED → PAID` 同一条规矩：让人手动把单子做平，
> 之后对账差额永远说不清是「通道慢了」还是「有人点早了」。
