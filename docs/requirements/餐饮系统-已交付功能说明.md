## 二 营业配置与访问范围

**用途：** 决定哪家门店、哪些员工及终端可以在什么时间办理餐饮业务。

- 复用现有账号、主体、商户、门店和权限体系；餐饮请求受当前身份及业务范围约束。
- 餐饮营业策略与原门店营业时间、接单日历衔接，支持餐段、日期例外、暂停及接单产能约束。
- 采用门店时区与营业日切点，保留订单所属营业日及规则来源，用于跨午夜经营与责任移交。
- 区分员工、已注册顾客、匿名顾客和设备身份，记录业务来源；匿名点餐不创建虚假注册账号，也不自动授予会员资产或付款权限。
- 平台提供授权诊断与基础支持；商家维护自身经营配置。税率配置不走平台审核。

**操作流程：** 商家完成门店及餐饮策略配置，分配员工权限；顾客或设备建立有效会话；服务端在查询、报价及下单时校验身份、门店与可售范围。

**当前边界：** 服务员、收银、顾客和设备的真实界面接入需要联验；平台支持接口不具备代商家收退款的权限。门店策略当前不接受非空capabilities/approvalRef，不能据此认定能力模板管理已经开放。

## 三 桌台与就餐管理

**用途：** 管理物理桌位和本次用餐关系，支持多人、多桌及多轮点餐。

| 已交付功能 | 功能说明 |
|---|---|
| 桌区与桌台配置 | 管理桌区、桌台、座位及桌码，作为开台和就餐会话的基础 |
| 开台与占用 | 建立就餐台账，记录人数、座位和桌位占用；并发操作校验资源及版本 |
| 转台与加桌 | 将当前用餐关系转到目标桌，或为同一台账增加桌位，保留原批次和订单来源 |
| 带单拼桌与拆桌 | 调整跨台账的业务关系及批次、座位、原行责任归属，保留原核心订单和已付事实 |
| AA业务份额 | 按人、菜或金额建立业务份额；相关改单或桌台变化时校验、失效或重新确认份额 |
| 清台与跨日处理 | 根据未完成事项及清台条件处理占用，保留跨日业务与后续责任关联 |

**示例：** A桌需要转到B桌时，系统校验目标占用和当前冻结状态，迁移就餐关系；已下单菜品继续引用原批次，不再生成一份交易订单。合桌后仍能追溯各菜品来源。

**当前边界：** AA业务份额和带单合并不等于AA收款、跨支付根合并付款或已经结清；资金分配另属支付阶段。

## 四 菜品与餐牌管理

**用途：** 在基础商品之上组织适合餐饮展示和销售的菜品配置。

| 已交付功能 | 功能说明 |
|---|---|
| 商品关联与餐饮属性 | 菜品引用原商品/SKU，扩展餐饮展示、制作及可售配置；商品与库存身份继续复用底座 |
| 餐牌与分类 | 通过餐牌和餐牌内分类组织展示，不以基础商品分类代替所有餐牌规则 |
| 时段与日期例外 | 支持早餐、午餐、晚餐等配置时段及自定义餐牌，结合门店营业时间和日期例外判定 |
| 渠道差异 | 将适用的时段/渠道价格及配料覆盖带入真实报价与成交，并冻结来源版本 |
| 配置维护与发布 | 管理餐牌、口味、配料、套餐及配方的配置和发布版本，历史成交继续引用原快照 |
| 可售控制 | 结合上下架、销售限制、沽清、配额和库存合同校验；提交时重新确认可售及价格 |

**操作流程：** 关联基础商品 → 配置菜品属性 → 加入餐牌分类 → 设置时段和适用渠道 → 发布 → 顾客浏览有效餐牌 → 下单时重新报价确认。

**当前边界：** 当前餐牌为门店范围配置；总部连锁批量下发、多门店差异覆盖以及菜品批量导入导出尚不纳入已完成范围。本地渠道餐牌价格与第三方渠道映射分别管理，本地生效不代表已同步外送平台；Keeta尚未真实接入。

## 五 口味 配料 套餐与精确数量

**用途：** 支持奶茶、饮料、套餐和称重菜等复杂选择，并确保价格、制作和库存使用同一份成交内容。

- 口味和选项按组管理，支持有效选择及数量约束；收费小料、配料组合和套餐组件进入报价及订单来源。
- 固定及自选套餐支持候选选择、替换、加价或补差；保留组件树及原行分配。
- 同一SKU采用不同做法时，保留各自选择和数量，避免合并后丢失制作信息。
- 小数和称重场景保存精确物理数量与单位，不把整数计价行数当成真实库存量。
- 库存需求在成品SKU和配方物料之间选择排他计划，避免套餐父子或成品与原料同时重复扣减。
- 价格、配方、税和数量来源随成交冻结；变化后重新确认，历史单据不随配置修改而改变。

**示例：** 一杯饮料选择杯型、糖冰和收费小料后，报价包含有效选配；制作读取冻结口味，小料按其实际库存或配方需求执行，不以商品当前配置重新展开历史订单。

**当前边界：** 单位精度及换算必须有明确依据，不自动推断重量换算。复杂组件本批按非支付后付受理交付，完整预付资金链路仍待支付阶段完成。

## 六 点餐与订单

**用途：** 将不同终端的点餐行为转为可追踪批次，并绑定共享核心订单。

| 已交付功能 | 功能说明 |
|---|---|
| 多身份下单 | 支持员工代客、注册顾客、真实匿名及设备来源；员工POS/WAITER和匿名/设备下单仅POSTPAY，注册顾客既有受控PREPAY保留；分别保留操作人和就餐来源 |
| 协作购物车 | 以就餐会话组织草稿，支持同桌选择及并发版本校验 |
| 报价与确认 | 使用共享定价能力处理有效选择、数量及费用，冻结报价来源，变化时要求重新确认 |
| 正式批次与加菜 | 提交生成批次并绑定原订单；同桌加菜创建后续批次，原批次不被覆盖 |
| 多履约场景 | 支持堂食、自提、自营外送及预约批次；保留地址、服务范围、费用和时间来源 |
| 后付受理 | 在门店许可、库存承诺和业务受理条件成立后进入制作，保持真实未付状态 |
| 重试与恢复 | 使用原请求标识查询或恢复提交结果，避免重复订单、重复库存及重复派工 |

**后付典型流程：** 建立会话或开台 → 加入菜品及选配 → 后端报价 → 确认提交 → 校验并承诺库存 → 绑定核心订单 → 受理并派工 → 多轮加菜 → 交付及后续结账。

**当前边界：** 既有基础先付路径保留，未获得可信支付成功前不派工。本次没有交付新增复杂预付、券/储值/积分扣减或现金收款闭环。

## 七 厨房制作与交付

**用途：** 将已受理批次拆成工位任务，区分制作、出品、上菜及实物交接。

- 按原菜品、组件和工位路由派工；重复事件不应创建重复任务。
- 支持等叫、叫起、催菜、道次及座位信息，保留中餐共享和西餐分道组织方式。
- 支持部分数量制作、出品及交付，校验累计数量不超过原可执行数量。
- 支持套餐及小料跨工位制作、父级装配、齐套及包装核对。
- 自提通过核销记录领取；外送通过骑手领取和交接记录实物移交，并与原履约合同衔接。
- 撤菜和重做关联原任务，保留制作事实，不通过删除任务掩盖耗用。

**示例：** 三份菜先完成两份时，仅确认两份出品和相应交付；剩余一份继续待做。厨房出品不会直接把整单标为全部送达。

**当前边界：** 厨房屏和服务员界面仍需接入及实操联验；制作完成、出纸、上菜、骑手交接和顾客签收各自独立。当前厨房列表实际只取活动任务。本轮本地修复后仅接受HELD/QUEUED/MAKING/READY，SERVED/VOIDED筛选明确拒绝；已通过4项HTTP回归，并于2026-10-25随`fef7f0098`发布，历史回看另列能力。

## 八 实际耗用与独立库存

**用途：** 将制作领耗、补料和报损记录为真实库存事实，并保留与菜品的关联。

- 根据冻结需求计划调用独立库存能力，处理预占、释放及部分履约关联。
- 支持制作领耗、补料、重做、报损及必要冲销，记录数量、单位、批次和可取得的历史估值回执。补料/报损接口输入制作任务的菜品或组件数量，再按冻结配方展开材料量，不接受任意原料SKU的独立实耗列表。
- 理论配方数量与实际发生数量分开，原键重放或结果未知时查询恢复原动作。
- 已制作退餐不自动恢复库存；可退料或报损需要相应业务处置和原事实关联。

**当前边界：** 已交付制作实际耗用，不表示销售历史成本及完整毛利报表已具备。成本不可取得时保留未知；不以当前采购价或领耗金额直接冒充销售成本。

## 九 改单 退餐与应收调整

**用途：** 在保留原单和制作事实的前提下，处理加减菜、替换及非资金退餐。

| 已交付功能 | 功能说明 |
|---|---|
| 草稿及处理中取消 | 草稿删除走购物车archive；员工取消限POS/WAITER、POSTPAY且未绑定原单的PREPARED/PLACING/UNKNOWN批次；已受理批次走退餐，C端没有对应任意批次取消接口 |
| 正式单业务变更 | 按已绑定原行/组件处理退量及有效应收；换菜通过原退量、新购物车报价下单、关联替换实现，保留原新行关系；没有原正式行任意改价或增量接口 |
| 申请与审核 | 校验原数量、已履约量、其他活动申请及权限，记录原因和审核结果 |
| 制作处置 | 根据制作状态决定撤回、重做、报损等处理，不重复派工 |
| 应收变更 | 经核心能力确认金额及应收变化，保留税和原分配依据 |
| 并发与恢复 | 与桌台冻结、AA计划及其他变更互锁，重复请求回放原结果 |

**操作流程：** 选择原批次和原行 → 输入数量及原因 → 校验/审核 → 确认厨房处置 → 更新有效应收及业务状态 → 留存审计。

**当前边界：** 本批非资金退餐由B端business-return、审批及厨房处置接口办理。C端既有returns接口走原核心售后，仅接受注册buyer并拒绝session/token，不是匿名/设备的非资金退餐入口。应收减少不等于款项已退回；新增资金退款、混合资金原路退回及完整已付部分退款仍需支付专项完成。

## 十 预约 专项费用与营业责任

**用途：** 支持预约资源、提前点单和营业异常的非资金处理。

- 桌位预约记录人数、时段及桌位资源，校验桌位容量、当前占用和预约重叠，支持取消释放和到店开台。预点保存、到店准备购物车及转单另有生命周期；定时点餐通过餐段、截止及接单产能链路约束。纯桌位预约成功不代表已经占用接单产能，也不保证该预约时段符合营业日历。
- 排队与通知提供业务状态及发送衔接，排队号与自提取餐号分别管理。
- 茶位、锅底、包材、服务费、低消，以及自助、宴会、企业订单的本批非资金规则，由共享收费及税能力确认金额和来源。
- 营业异常支持分类、处置、结转、源事实复核和历史更正；未完成事项可进行非资金责任交接。
- 跨日保留原营业日及后续处理关联，恢复查询和审计支持追踪具体责任。

**当前边界：** 订金收退、企业信用授信和挂账收款未纳入本批；自助、宴会等非资金规则不表示专项完整营业流程已交付。外部短信或推送送达需供应商联验。非资金交接不等于现金盘点、完整资金对账或全部日结结清。

## 十一 打印 KDS与平台支持

**用途：** 基于原业务事件生成票据和屏幕任务，提供授权诊断能力。

- 厨房、加撤菜、标签及预结等场景使用票面模板和设备路由；内容保留原业务版本。
- 转台和改单通过业务事件传递；打印复用共享任务及桥接能力。
- 支持设备绑定、撤权，打印状态查询、补打原因和结果未知的恢复；补打不新建制作事实。
- KDS支持授权订阅和断线回放，订阅范围与门店、工位权限一致。
- 平台支持接口提供宿主schema、依赖装配、异常及原来源的只读诊断，不执行商家营业恢复写操作；就绪诊断不代表门店页面、设备和完整营业流程已验收。

**当前边界：** 厂家SDK、双语票面、标签尺寸、切纸和真实出纸待实机验收；已创建或投递任务不等于纸张已打印。厨房屏终端体验另行验收。

## 十二 共享试算与税费基础

餐饮复用共享定点报价、规则校验、税计算、人工调整及应收能力，不维护第二份成交金额。共享基础已交付配置、计算和报价快照等阶段能力；本批真实套餐、配料、小数数量、费用及应收变更接入对应原能力。

商家可自行配置税率及价外加税或价内倒推，商品税分类和优惠参与范围分别处理。成交保留适用版本，不能将不参与优惠推断为免税。人工调价通过原授权及审批来源办理，保留原因和并发校验。

**当前边界：** 规则模型可表达券、储值、积分及互斥，并不等于餐饮已完成真实资产授权、扣减和资金提交；不能把报价能力作为付款成功依据。发票及税务申报不属于当前完整交付。

| 每日任务与重算 | 一个每日任务处理日报构建、补漏、失败查回、已标记更正及导出维护，不另建周/月定时任务 |
| 授权导出 | 按需生成固定查询快照的私有CSV，查询状态、下载、撤权复核和到期清理；首发限集成writer宿主 |

货币金额及数量按币种、单位分列；历史查询只读已发布统计结果，不遇到缺值就回业务库静默补齐。订单、履约及售后来源事件已接更正标记；其他来源的追溯更正覆盖仍需补齐。

**业务前置：** 独立库与最小权限账号、迁移、门店历史起点和指标版本、每日任务调度及角色权限投放。PAY只读来源提供方另需发布与配置；本次未部署该支付进程。销售历史成本、费用、部分优惠税额分配、遗留支付门店归属、历史库存结存等来源仍未完整验收。
