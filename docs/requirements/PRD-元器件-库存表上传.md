## 一、一句话（L1）

供应商从微信里转一张 ERP 导出的 Excel，平台**认出哪列是料号、厂牌、数量、价格**，
先给他看「会新增 / 更新 / 下架多少」，他点确认才上架。本篇要让这条路**传错了能看清、改完能补传、
传了半张表不会把库存清空、传过的每一次都查得到**。

## 三、一期验收标准（L3）

「警告」的四种（一期）：

| 码 | 什么时候 | 为什么只警告不拦 |
|---|---|---|
| `MFR_MISSING` | 没写厂牌 | 很多现货商只报料号，拦了就传不上来；但买家看不到厂牌会犹豫 |
| `MFR_UNKNOWN` | 写了厂牌，别名表里认不出 | 厂牌库是运营在补的，认不出不代表写错 |
| `QTY_ZERO` | 数量为 0 | 可能是故意清零，也可能是公式没算出来 |
| `DC_UNPARSED` | 写了批号，读不出年份 | 买家只看得到年份，读不出就等于没写 |

- **AC1** Given 表里有 3 行错误、2 行警告 When 上传 Then 预览回 `rowInvalid=3`、`rowWarn=2`，
  问题列表里每一行带 `level`（ERROR / WARN）；确认后警告的 2 行**在售**，错误的 3 行**不在**
- **AC2** Given 一个有问题行的批次 When 导出问题行 Then 得到一个 `.xlsx`：第一行是原表头 + 「问题」，
  其后**只有**出问题的行，单元格与原表一致，「问题」列是人话（「没有料号」「厂牌认不出：TIX」）
- **AC3** Given AC2 导出的文件改好后 When 按「合并」上传 Then 修好的行上架，**之前已上架的行一行不变**
- **AC4** Given 在售 100 行、全量替换将下架 40 行（过 30% 线）When 确认但没带下架数
  Then 拒绝（`ELEC_DELIST_CONFIRM`，文案带「40」）；带 `expectDelist=40` 再确认 Then 成功
- **AC5** Given AC4 的预览之后，又有一张表先上架、使下架数变成 55 When 带 `expectDelist=40` 确认
  Then 拒绝并告知新的数字 —— **确认的必须是此刻的后果，不是预览那一刻的**
- **AC6** Given 同一家两张预览 When 两个请求同时确认 Then 两个都成功或一个被拒，
  但最终库存**等于依次执行两次**的结果（不会出现两个批次交错写行）
- **AC7** Given 今天已上传 20 次 When 第 21 次上传 Then 拒绝（`ELEC_UPLOAD_DAILY_LIMIT`，文案带上限）；
  换列映射、确认**不计次**
- **AC8** Given 传过 3 次（1 次已上架、1 次预览未确认、1 次预览已过 24 小时）When 打开上传记录
  Then 按时间倒序 3 条，状态分别为「已上架」「待确认」「已过期」，每条显示**端上选的文件名**与各项计数
- **AC9** Given 一条已上架的记录 When 打开详情 Then 看到当时的四个数与问题行，并能再次导出问题行
- **AC10** Given 运营有「供应商查看」权限 When 查某家的上传记录 Then 回与 AC8 同样的列表；没有权限 Then 403
- **AC11** 别人的批次号：查详情 / 导出 → 404（不是 403，不泄露批次存在）

## 四、不做（Out of Scope）与待拍板（L4）

**本期不做**：表中二期各行；ops-web 的页面（只出接口，页面与菜单随元器件运营端前端一批做）；
价格异常警告（见下）。

**为什么不做「价格偏离同料号行情」的警告**：`elc_part_market.price_from_e6` 是**加过价、换算成含税人民币、
按数量档**的参考价，供应商表里的是原价、可能未税、可能美元、按阶梯 —— 两者相减前要先换到同一口径，
口径换错了警告就是噪声，而警告一旦噪声化，真正的警告也没人看了。放到二期与 1.7 一起做。

**待拍板**：

| # | 问题 | 建议 |
|---|---|---|
| 1 | 下架护栏的线：30%？ | 30%，可配。小供应商在售 5 行删 2 行也会触发 —— 这时多点一下是合理的 |
