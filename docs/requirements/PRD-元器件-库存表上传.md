## 一、一句话（L1）

供应商从微信里转一张 ERP 导出的 Excel，平台**认出哪列是料号、厂牌、数量、价格**
（先查表头别名表，认不出再请大模型帮忙），把**解析后的数据**给他逐行过目，他点确认才上架。
没确认之前数据只在服务器内存里，最多留 1 小时；原文件以**原名**存到磁盘，按「已入库 / 未入库」分两个目录，
未入库的每周清一次，已入库的长期保留。

本篇要让这条路做到：**认得准、错在哪一格说得清、改完能补传、传了半张表不会把库存清空、每一次上传都查得到。**

## 三、一期验收标准（L3）

### 识别

- **AC1** Given 表头写「制造商」「库存数量」（在别名表里）When 上传 Then 这两列直接认出，**不调大模型**，映射来源标「别名」
- **AC2** Given 表头是 `Item / Maker / Stk`，别名表认不出料号与数量 When 上传 Then 调大模型，
  认出的列来源标「AI」，端上高亮提示核对
- **AC3** Given 大模型回的「料号列」样本里大多不像料号 When 校验 Then 这个字段被丢掉，不进映射
- **AC4** Given 大模型不可用、超时或关着 When 上传 Then **不报错**，预览状态为「待指定列」，他手工选完照常往下走
- **AC5** Given AC2 或 AC4 的映射被他确认上架 When 他下次上传同样写法的表头 Then 别名直接命中，不再调大模型；
  **别家供应商不受影响**（学到的别名只属于他）

### 报错

「警告」四种（一期）：`MFR_MISSING` 没写厂牌 · `MFR_UNKNOWN` 厂牌认不出 · `QTY_ZERO` 数量为 0 · `DC_UNPARSED` 批号读不出年份。

- **AC6** Given 第 12 行数量写「约2千」、料号为空 When 上传 Then 问题列表里这一行有**两条**：
  `A12（型号）没有料号`、`D12（数量）读不出：约2千`，都带行号、列字母、表头名、原值
- **AC7** Given 3 行错误、2 行警告 When 确认 Then 警告的 2 行在售，错误的 3 行不在；预览里 `rowInvalid=3`、`rowWarn=2`
- **AC8** Given 有问题行的批次 When 导出 Then 得到 `.xlsx`：原表头 + 「原行号」「问题」两列，**只有**问题行，
  出错的格底色标红，所有格都是文本（`0805` 不会变成 `805`）
- **AC9** Given AC8 的文件改好后按「合并」上传 When 确认 Then 修好的行上架，**之前已上架的行一行不变**

### 预览与暂存

- **AC10** Given 一次上传 When 看预览 Then 能按「新增 / 更新 / 下架 / 未变 / 有问题」分页看到**解析后的**料号、厂牌、数量、批号、价……；
  「更新」的行带旧值
- **AC11** Given 预览未确认 When 查库 Then `elc_stock_batch` 只有一行元数据，**没有任何数据行**
- **AC12** Given 预览 When 点「放弃」Then 内存里的数据清掉，记录状态为「已放弃」；**原件不删**，仍在未入库目录，等每周清理
- **AC13** Given 上传已满 1 小时 When 确认 / 翻页 / 改映射 Then 回「预览已失效，请重新上传」
- **AC14** Given 上传后 10 分钟 elec-svc 重启 When 他点确认 Then 照常成功（从磁盘原件重建，**不重新调大模型**，映射保持他改过的样子），
  且失效时刻仍是上传起 1 小时，不因重建而延后
- **AC15** Given 他有一张待确认 When 又上传一张 Then 前一张状态为「已作废」，内存数据清掉，原件同 AC12

### 覆盖与并发

- **AC16** Given 在售 100 行、全量替换将下架 40 行（过 30% 线）When 确认但没带下架数 Then 拒绝，文案带「40」；带 `expectDelist=40` Then 成功
- **AC17** Given AC16 的预览之后库存变了、下架数变成 55 When 带 40 确认 Then 拒绝并告知 55
- **AC18** Given 同一家两个确认请求同时到 When 执行 Then 最终库存等于依次执行的结果

### 文件、记录与限制

- **AC19** Given 供应商 S001 在 2026-10-08 上传「9月库存（华强）.xlsx」When 看磁盘 Then 原件在
  `<上传目录>/failed/2026-10-08/S001/9月库存（华强）_<批次号>.xlsx`；**确认上架后**移到 `applied/` 下同样的相对路径；
  批次记录里能查到原文件名、相对路径、所在目录、大小、sha256
- **AC19a** Given 上传一个 `.xls` 文件（解析失败）When 看记录 Then 有一条「解析失败」的批次，原因是「格式不支持」，原件在 `failed/` 下；
  供应商端仍收到原来的报错
- **AC19b** Given `failed/` 下有 8 天前、今天两个日期目录，`applied/` 下有 400 天前的目录 When 每周清理跑过
  Then 只删 `failed/` 下 8 天前那个；`applied/` 一个都不动；被删的批次记下「原件已清理」的时刻
- **AC19c** Given 某批次已上架、但当时移动原件失败，文件还留在 `failed/` When 每周清理 Then 先把它补移到 `applied/`，**不删**
- **AC19d** Given 运营有「供应商查看」权限 When 下载某批次原件 Then 拿到原文件、原文件名；原件已清理 Then 回「原件已清理」
- **AC20** Given 今天已上传 20 次 When 第 21 次 Then 拒绝，文案带上限；改映射、确认、放弃不计次
- **AC21** Given 传过 5 次（已上架 / 待确认 / 已过期 / 已放弃 / 解析失败）When 打开上传记录 Then 倒序 5 条、状态各自正确、显示端上选的文件名；
  已上架的那条能看问题行并再次导出（**原件已被清理也能导出** —— 问题行在确认时入库）
- **AC22** Given 运营有「供应商查看」权限 When 查某家上传记录 Then 回同样的列表；没权限 403
- **AC23** Given 运营有「基础数据管理」权限 When 把某个学到的别名提升为全局 Then 所有供应商都命中它
- **AC24** 别人的批次号：详情 / 翻页 / 导出 / 放弃 → 404

## 四、不做与待拍板（L4）

**本期不做**：§二 里二期各行；ops-web 的页面（只出接口）；价格异常警告 ——
`elc_part_market` 的参考价是加过价、换算成含税人民币、按数量档的，供应商表里是原价、可能未税、可能美元，
口径没对齐就比，警告会变成噪声，而噪声化的警告会让真警告也没人看。

**待拍板**：

| # | 问题 | 建议 |
|---|---|---|
| 1 | 下架护栏的线 | 30%，可配 |
| 2 | 过线后只要二次确认，还是更高的线直接拒 | 只二次确认；真的清仓换货是正当操作 |
| 3 | 每天上传上限 | 20 次，可配 |
| 4 | **cdw 的 8003 是公网明文 HTTP、不校验身份**（从生产机实测直连 200）；表头与前 5 行样本（含价格）会经公网发过去 | 一期接受，只发 5 行；二期给 8003 加 API key 或走内网隧道。另：8003 同时是 soukmind 的生产端点，我们的量（每次上传最多一次、约 1 秒）可以忽略 |
| 5 | 每家只留一张待确认 | 是。两张并存时确认顺序不同结果就不同，他自己也说不清哪张是准的 |

| 7 | 缺厂牌列也调大模型？ | 是。厂牌缺了整张表的厂牌全空，代价比一次 1 秒的调用大得多 |
