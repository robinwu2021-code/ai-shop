## 一、先说现状：活动这块比想象中完整

| 已有 | 位置 |
|---|---|
| 四类活动：店铺券 `COUPON` / 满减 `FULL_CUT` / 限时特价 `FLASH` / 买赠 `BUY_GIFT` | `mkt_campaign` |
| **门店维度**：全部门店 or 指定一家（`store_no`） | 表 + B 端表单 |
| 真的在下单时生效（满减、特价、买赠三条链路） | `CampaignPort` → `OrderServiceImpl` |
| 叠加规则：活动 → 券 → 积分；同类取最优 | 下单算价 |
| 领取数 / 核销数 | 活动列表 |
| 券的预算前置（建券时保证敞口可算，折扣券强制封顶） | 已实现 |
| 到期自动转 `ENDED`、已结束不可复活 | 服务层 |

**所以本次不是从零做活动，是补四个洞。**

## 二、四个洞

### 洞 1：商家不知道该选哪一类

界面按**活动类型**组织（满减/特价/买赠），而店主脑子里是**目的**：
「我要拉新客」「老客好久没来了」「这批菜今天必须清掉」「想让他们多买一点」。
让他自己把目的翻译成类型，翻译错了活动就白做。

**改法**：新建活动第一步选目的，第二步才是参数。四个目的各自预置一套参数：

| 目的 | 预置 | 受众（依赖会员） |
|---|---|---|
| **拉新客** | 店铺券 · 新人专享 · 门槛低面额小 | 非本店会员 |
| **唤回老客** | 店铺券 · 面额大一点 · 有效期 7 天 | 沉睡会员 |
| **清库存** | 限时特价 · 限量 · 当天有效 | 全部 |
| **提客单** | 满减（满 X 减 Y） | 全部 |

目的只是**入口和默认值**，落库仍是现有四类 —— 不新增类型、不动算价分支。

### 洞 2：活动对所有人一视同仁

「熟客专享价」「新客首单立减」是小店最常见的两种玩法，现在做不出来。

**改法**：活动增加**受众**（全部 / 会员标签 / 会员层 / 会员来源 / 非会员）。
**不选 = 全部**，与今天行为完全一致；老活动零影响。

### 洞 3：限时特价与买赠**没有上限**

券有预算前置，活动没有：一场限时特价可以卖到亏穿，商家只能盯着手动关。
`total_count` 目前只在券那一类有意义。

**改法**：`FLASH` / `BUY_GIFT` 必须填**限量**（件数），到量自动结束并通知商家。
理由与券的预算前置同一个：**敞口要在按下保存的那一刻就是确定的**，
而不是运行到一半才去追。

### 洞 4：效果只有「领了多少」

现在能看到领取数与核销数，看不到**带来了什么**：多少单、多少新客、多少沉睡被唤回、
毛估营业额增量。没有这个数字，商家下次只能凭感觉决定加不加码。

**改法**：每场活动一张效果卡 —— 触达/曝光、参与人数、订单数、成交额、
其中新客与唤回各多少。数据来源是订单上已有的活动标记，不新增埋点。

## 三、还要补的两件小事

1. **一键再来一次**：把上一场活动复制成草稿（时间改成今天起）。
   小店的活动是重复的（每周三特价），每次重填十个字段没人愿意。
2. **冲突提示**：同一批商品同时在两个活动里时，建的时候就说清「同类取最优，实际生效的是哪个」。
   现在这个规则只写在文档里，商家看不到。

## 四、明确不做（沿用既有判断）

| 不做 | 理由 |
|---|---|
| 百分比折扣、N 件优惠 | B-10.2 已记：模型里没有，扩它要动枚举 + 算价分支 + 三端展示，一期没有明确场景 |
| 限时特价按 SKU 分价 | 模型是「商品 + 一个活动价」，多规格会被拉平。**一期不改模型**，但界面必须写明「对该商品所有规格生效」，否则商家按 10 斤装的价填，5 斤装也照这个价卖 |
| 赠品跨商品 | `buyN/giftM` 只表达同款，跨款要新模型 |
| 平台补贴活动 | 出资方是平台，涉及预算审批与结算拆分，属运营端 |

## 五、与会员的联动点（三处）

1. **受众**：活动圈定会员（洞 2）。
2. **入口互通**：会员筛完人可以「给这批人建一场活动 / 发一张券」；活动详情能看到覆盖多少会员。
3. **回流打标**：因某场活动首次下单的人，自动打 `来自「活动名」`，让洞 4 的数字能拆开看。

## 六、验收标准

- AC-1 新建活动可先选目的，选完参数已按目的预填，落库 `type` 仍是四类之一。
- AC-2 不选受众的活动，对所有买家的算价结果与本次改动前**逐分相同**。
- AC-3 受众为「沉睡会员」的活动，非沉睡会员下单时不享受，且商品页不展示活动标。
- AC-4 `FLASH`/`BUY_GIFT` 未填限量时保存被拒；达到限量后活动自动结束并推送商家。
- AC-5 活动效果卡的订单数与成交额，与订单库按活动标记聚合的结果一致。

## 七、分批（与会员批次对齐）

| 批次 | 活动侧内容 | 依赖 |
|---|---|---|
| 四-A | 目的引导 + 限量 + 冲突提示 + 一键再来一次 | 无（可先于会员上线） |
| 四-B | 受众（会员定向）+ 回流打标 | 会员批次一、三 |
| 四-C | 效果卡 | 四-B |

## 八、待定

1. 限量到量后是「自动结束」还是「自动暂停可续量」？（我倾向自动结束，续量等于新建一场，账更清楚）
2. 「非本店会员」这个受众是否允许 —— 它意味着活动只给陌生人，老客会问「为什么我没有」。
