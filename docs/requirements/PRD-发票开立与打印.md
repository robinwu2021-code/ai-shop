## 0. 一句话

门店结账后要能**当场开出一张合法的发票并打印出来**；零售、餐饮、美业用同一个发票模块，
税制（台湾电子发票、以后的其他地区）作为可替换的一层，首期只落台湾。

## 1. 为什么现在做

| 现状 | 问题 |
|---|---|
| CKO-24 明确写着「税票能力未具备，不把普通客单标成税发票」 | 台湾门店结账只能出收银小票，**不能当发票用**；顾客要发票只能手写或另用开票机 |
| `ord_invoice_request`（V94）是**线上订单事后申请、平台人工开票**的流程 | 不覆盖门店当场开立，也不认识字轨、随机码、载具 |
| 餐饮结账接口已经留了 `invoice` 字段（14-05） | 只透传，没有任何地方真正开票 |
| 共享打印中心已能出收银/退款/充值凭证 | 没有发票证明联场景，也画不了条码和 QR |

台湾的营业人（统一发票使用者）**交易当下必须开立统一发票**，这不是「可选增值」，
是门店能不能合法收钱的前提。

## 2. 用户与场景

| 谁 | 场景 |
|---|---|
| 收银员（零售 / 餐饮 / 美业） | 结账时选「会员载具 / 手机条码 / 自然人凭证 / 捐赠 / 打统编」，结账完成后证明联自动出纸 |
| 店长 | 证明联卡纸、缺纸 → 补印（会标「补印」）；开错 → 当期作废后重开；部分退货 → 开折让 |
| 店主 / 财务 | 每期（两个月）登记财政部配发的字轨号段；查本期开了多少、上传是否成功 |
| 运营 | 看各商家上传失败、即将超过 48 小时未上传的发票 |

## 3. 台湾电子发票要点（本需求依据的外部规则）

- **期别**：两个月一期（1-2、3-4 …… 11-12 月），用「民国年 + 双月」表示，如 `11512` = 115 年 11-12 月。
- **字轨号码**：2 个英文字母 + 8 位数字（如 `AB12345678`），号段由国税局按期配给营业人，**依序使用，不得重号**。
- **随机码**：每张 4 位数字，用于兑奖与查询。
- **买受人**：一般消费者（B2C）或打统编（B2B，8 位数字带检查码）。
- **载具 / 捐赠**：手机条码（`/` + 7 码）、自然人凭证（2 英 + 14 数）、商家会员载具；或捐赠给社福团体（爱心码 3–7 位）。
  **存了载具或捐赠，就不印证明联**（只印交易明细）；打统编可同时印证明联。
- **证明联版式**：5.7 cm 热感纸，含期别、号码、开立时间、随机码、总计、卖方统编、（买方统编）、
  一维条码（Code39）、两个 QR 码（左码含加密验证与明细，右码续明细）。证明联正本只印一次，再印要标「补印」。
- **上传**：B2C 开立后 **48 小时内**上传财政部大平台（经加值中心或 Turnkey）；作废、折让同样要上传。
- **作废**：同期内可作废；跨期只能开折让。

## 4. 验收标准

| AC | Given / When / Then |
|---|---|
| AC1 号段 | Given 主体已登记本期字轨 `AB` 号段 00000001–00000050 When 连续开立 3 张 Then 号码依次为 AB00000001、AB00000002、AB00000003；并发开立不重号 |
| AC2 号段用尽 | Given 号段已用到最后一号 When 再开立 Then 拒绝并返回「本期发票号码已用完」，不生成发票 |
| AC3 开立幂等 | Given 某来源单（行业 + 来源类型 + 来源单号）已有一张有效发票 When 结账回调重复触发开立 Then 返回原发票，不再取号 |
| AC4 买受人校验 | When 统编检查码不对 / 手机条码格式不对 / 同时给载具和捐赠 / 同时给统编和捐赠 Then 拒绝开立，错误码分别可辨 |
| AC5 金额 | Given 来源单的冻结税结果 When 开立 Then 销售额 + 税额 = 总计，等于来源单的含税应收；明细行合计等于总计 |
| AC6 证明联 | Given B2C 未存载具未捐赠 When 开立成功 Then 生成一份证明联打印事实，含期别、号码、随机码、一维条码内容（19 码）、左右 QR 内容 |
| AC7 不印证明联 | Given 存了手机条码载具或捐赠 When 开立成功 Then 不生成证明联打印事实，发票标记 `printMark=N` |
| AC8 补印 | Given 证明联已印 When 有 `biz:print:reprint` 的人补印并填原因 Then 打印中心出一张标「补印」的证明联，记录原因与操作人；发票号码不变 |
| AC9 作废 | Given 本期发票 When 作废 Then 状态 VOIDED，生成作废上传任务；同来源可重新开立一张新号码 |
| AC10 跨期不能作废 | Given 上一期发票 When 作废 Then 拒绝，提示改开折让 |
| AC11 折让 | Given 总计 1050 的发票 When 开折让 300 再开 800 Then 第一次成功、第二次拒绝（超过剩余可折让 750） |
| AC12 上传 | Given 新开发票 When 上传任务执行 Then 状态 PENDING → UPLOADED；通道失败则 FAILED 并按退避重试，不重复取号 |
| AC13 多行业 | 零售订单、餐饮结账、美业服务单用同一个开立入口；发票模块不读任何行业表 |
| AC14 税制可替换 | Given 主体未开通任何税制 When 开立 Then 拒绝「该主体未开通发票」；新增税制只加一个实现类，不改开立主流程 |
| AC15 查询 | B 端按门店、期别、状态分页查发票，看详情与上传状态 |
| AC16 自动开立 | Given 主体打开「付款后自动开立」且收银员付款前预存了手机条码载具 When 付款成功 Then 自动开出一张存载具、不印证明联的发票；未打开时不开；开不了（金额组成不支持）时跳过留给手动 |
| AC17 课税别 | Given 一单含应税、零税率、免税商品 When 开立 Then 应税 / 零税率 / 免税销售额分列，只有应税部分计 5% 税，上传报文课税别为混合（9）；混合税别且有整单优惠时拒绝 |
| AC18 积分与秤重 | Given 子单有积分折抵或秤重调整 When 开立 Then 各成一行（折抵为负），明细合计等于实付 |
| AC20 常用载具 | Given 顾客在 C 端添加手机条码 /ABC+123 When 再加一个自然人凭证并设为默认 Then 列表里默认只有一个；格式不对的拒绝；别人看不到、删不了他的载具 |
| AC21 会员载具 | Given 商家申请了会员载具类别号 When 顾客为订单选「会员载具」 Then 发票存入以他登录账号为号码的会员载具，不印证明联；顾客无法指定别的号码 |
| AC22 默认走载具 | Given 商家开了自动开立且有会员载具 When 有账号的顾客付款、事先没选开法 Then 自动存会员载具；门店现场无账号的单照常开一般发票并印证明联 |
| AC23 我的发票 | When 顾客打开「我的发票」 Then 看到跨商家、开给自己的全部发票及明细；看不到别人的 |
| AC24 订单选开法 | Given 一张订单拆给两家商家 When 顾客选开法 Then 每家各自回结果（已记下 / 已开立 / 已开过 / 未开通 / 无会员载具）；已付款且商家开了自动开立的当场开出 |
| AC25 交易明细 | When 任一发票开立 Then 有一张冻结的交易明细（品名、数量、单价、金额、总计）；存载具 / 捐赠时写明发票去向，一般发票写「本明细非发票」 |
| AC26 折让证明单 | When 开折让 Then 出一张折让证明单（原发票号码与日期、未税 / 税额 / 合计、买受人签收栏） |
| AC27 证明联正本唯一 | Given 证明联已出 When 再出 Then 只能走补印，版面醒目标「補印」；不允许「加印」第二张正本 |
| AC28 鲸跃加值中心 | Given 主体通道为 CETUSTEK 且保存了鲸跃商家代号、账号、密码 When 核验账号 Then 统编与本主体一致才通过，服务商回的 QR 金钥自动存起来；When 取号段 Then 服务商配给的号段入库并可直接开立；When 上传任务执行 Then 开立 / 作废 / 折让按鲸跃报文送出，重复上传视为送达；账号密码不落业务表、不回显 |
| AC35 上传失败分级止损 | Given 主体通道为鲸跃 When 上传回「认证错误」 Then 该主体的上传全部暂停、不再打到服务商，B 端设置页显示暂停原因；商家核验账号通过后自动补传。When 上传被拒（格式 / 业务规则 / 未登记的码） Then 该票标为「待人工处理」、不自动重发，可手动重新上传；When 服务商系统错误或网络不通 Then 退避重试 |
| AC36 折让作废 | Given 本期一张已开的折让 When 有 `biz:invoice:void` 的人作废它并填原因 Then 折让标为已作废、累计折让退回（全部折让作废后发票本身可作废）、折让证明单不再出纸、生成作废折让上传（鲸跃 UploadCancelAllowance / Turnkey G0501）；跨期折让拒绝，已作废的不能再作废 |
| AC37 上报期限告警 | Given 一张台湾 B2C 发票（或其作废 / 折让）尚未上传 When 距开立过去 24 小时 Then 预警一次；When 超过 48 小时 Then 告警一次（B2B 为 3.5 日 / 7 日）；B 端发票列表顶部显示本门店逾期、即将到期、暂停、待人工的张数，详情显示上传期限 |
| AC38 号段水位 | Given 主体本期剩余号码低于提醒值（默认 50）或用尽 When 巡检 Then 各提醒一次（补足后再跌破重新提醒）；期末前 5 天下期还没号段则提醒一次。Given 通道为鲸跃且开了自动领号 When 余量不足或期末前 Then 先向鲸跃领号，领到不提醒、失败转提醒；账号暂停中不领号。B 端设置页显示本期剩余与下期已备张数 |
| AC39 向服务商查单 | Given 主体通道为鲸跃 When 在发票详情点「向服务商查询状态」 Then 显示鲸跃侧状态（已开立 / 已作废 / 部分折让 / 完全折让 / 查无此票）与本地是否一致；鲸跃已收到而本地上传未标送达（如超时、回「上传失败」）的补记为已送达；不一致且没有待补传的告警 |
| AC40 运营端跨商家处置 | Given 运营持 `finance:invoice:read` When 打开「结算与资金 › 电子发票」 Then 看到所有开通电子发票的营业人（通道、本期余量与水位、待上传 / 暂停 / 待人工 / 将到期 / 逾期件数、暂停原因），可按问题、通道、关键字筛；上传任务与发票可跨商家查；持 `finance:invoice:verify` 时可代商家核验账号、领号段、重传待人工的上传、向服务商查单，规则与商家端一致 |
| AC41 多地区多供应商接入 | Given 台湾与阿联酋各有若干开票供应商，主体用哪家由系统统一决定（商家选择或系统指定） When 上传任务把报文交给该供应商 Then 对外接口与行为不变；各家供应商的失败按同一规则分类（不可达重试、账号问题暂停、被拒待人工）；接一家同形态的新供应商只需写报文映射与结果码表 |
| AC42 默认市场与供应商、商家可选 | Given 平台配置了默认市场与各市场的默认供应商 When 商家开通电子发票不选供应商 Then 跟随市场默认，平台改默认即一起切换；When 从其它系统迁来的商家在本市场支持的供应商里选了一家 Then 按商家所选开票，选了不支持的拒绝；已开出的票始终由当时那家上报与查单 |
| AC29 多地区（草稿） | Given 同一主体在台湾与阿联酋各有门店 When 两地门店各自开票 Then 各按所在地区的税制开立，地区在开立时冻结；未开通该地区的主体拒绝开立 |
| AC30 多供应商与门店路由（草稿） | Given 营业人在鲸跃与绿界各有一个启用账户，A 店绑鲸跃、其余默认绿界 When 两店开票 Then A 店走鲸跃、其余走绿界 |
| AC31 开立时冻结账户（草稿） | Given 一张经鲸跃开出的发票 When 门店改绑到绿界后作废或折让这张票 Then 仍经鲸跃原账户送出；新开的票走绿界 |
| AC32 在线配号与未知态（草稿） | Given 绿界开立请求超时 When 恢复任务按原 RelateNumber 查单 Then 有则补记号码并出证明联，没有则标失败；未知期间同一来源单不能换供应商重开 |
| AC33 双形态部署（草稿） | Given `shop.invoice.deployment=standalone` When 核心开票 Then 经内部接口到独立的发票服务完成，结果与内嵌形态一致 |
| AC34 往来留痕与回放（草稿） | 每一次对供应商的调用与每一份回执都留脱敏记录与加密原文；处理失败的回执可由运营回放，回放生成新记录指向原记录 |
| AC19 Turnkey | Given 主体通道为 TURNKEY When 上传任务执行 Then 在 Turnkey 上传目录生成合法的 MIG 4.0 XML（F0401 / F0501 / G0401），重发覆盖同名文件 |

### 4.1 载具优先（2026-11-21 起的开票主线）

载具发票不出纸，顾客在财政部大平台与「我的发票」里查；所以先做顾客自己选载具（AC20–AC24），
纸本证明联只服务于不要载具的顾客。手机条码的真伪验证需财政部验证接口的 AppID，拿到后接入。

## 5. 不做（首期 Out of Scope）

- 商业加值中心（ezPay / 绿界等）对接：通道接口已就绪，签约后各加一个实现；首期正式通道为财政部 Turnkey（不需签约）。Turnkey 回执目录的处理结果回写下一步做。
- B2B 交换（存证以外的 A0401 交换流程）、跨境电商、特种税额（娱乐业等）。
- 发票兑奖、中奖通知、载具归户。
- 运营端界面（上传失败清单）：下一批。
- 线上订单事后申请开票（`ord_invoice_request`）的迁移：继续原流程，不并入。
- 中国大陆、阿联酋等其他税制：只留 SPI 和税制编码，不实现。
