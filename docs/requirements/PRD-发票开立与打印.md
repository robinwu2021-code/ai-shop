## 0. 一句话

门店结账后要能**当场开出一张合法的发票并打印出来**；零售、餐饮、美业用同一个发票模块，
税制（台湾电子发票、以后的其他地区）作为可替换的一层，首期只落台湾。

## 1. 为什么现在做

| 现状 | 问题 |
|---|---|
| CKO-24 明确写着「税票能力未具备，不把普通客单标成税发票」 | 台湾门店结账只能出收银小票，**不能当发票用**；顾客要发票只能手写或另用开票机 |
| `ord_invoice_request`（V94）是**线上订单事后申请、平台人工开票**的流程 | 不覆盖门店当场开立，也不认识字轨、随机码、载具 |
| 餐饮结账接口已经留了 `invoice` 字段（14-05） | 只透传，没有任何地方真正开票 |
| 共享打印中心已能出收银/退款/充值凭证 | 没有发票证明联场景，也画不了条码和 QR |

台湾的营业人（统一发票使用者）**交易当下必须开立统一发票**，这不是「可选增值」，
是门店能不能合法收钱的前提。

## 2. 用户与场景

| 谁 | 场景 |
|---|---|
| 收银员（零售 / 餐饮 / 美业） | 结账时选「会员载具 / 手机条码 / 自然人凭证 / 捐赠 / 打统编」，结账完成后证明联自动出纸 |
| 店长 | 证明联卡纸、缺纸 → 补印（会标「补印」）；开错 → 当期作废后重开；部分退货 → 开折让 |
| 店主 / 财务 | 每期（两个月）登记财政部配发的字轨号段；查本期开了多少、上传是否成功 |
| 运营 | 看各商家上传失败、即将超过 48 小时未上传的发票 |

## 3. 台湾电子发票要点（本需求依据的外部规则）

- **期别**：两个月一期（1-2、3-4 …… 11-12 月），用「民国年 + 双月」表示，如 `11512` = 115 年 11-12 月。
- **字轨号码**：2 个英文字母 + 8 位数字（如 `AB12345678`），号段由国税局按期配给营业人，**依序使用，不得重号**。
- **随机码**：每张 4 位数字，用于兑奖与查询。
- **买受人**：一般消费者（B2C）或打统编（B2B，8 位数字带检查码）。
- **载具 / 捐赠**：手机条码（`/` + 7 码）、自然人凭证（2 英 + 14 数）、商家会员载具；或捐赠给社福团体（爱心码 3–7 位）。
  **存了载具或捐赠，就不印证明联**（只印交易明细）；打统编可同时印证明联。
- **证明联版式**：5.7 cm 热感纸，含期别、号码、开立时间、随机码、总计、卖方统编、（买方统编）、
  一维条码（Code39）、两个 QR 码（左码含加密验证与明细，右码续明细）。证明联正本只印一次，再印要标「补印」。
- **上传**：B2C 开立后 **48 小时内**上传财政部大平台（经加值中心或 Turnkey）；作废、折让同样要上传。
- **作废**：同期内可作废；跨期只能开折让。

## 4. 验收标准

| AC | Given / When / Then |
|---|---|
| AC1 号段 | Given 主体已登记本期字轨 `AB` 号段 00000001–00000050 When 连续开立 3 张 Then 号码依次为 AB00000001、AB00000002、AB00000003；并发开立不重号 |
| AC2 号段用尽 | Given 号段已用到最后一号 When 再开立 Then 拒绝并返回「本期发票号码已用完」，不生成发票 |
| AC3 开立幂等 | Given 某来源单（行业 + 来源类型 + 来源单号）已有一张有效发票 When 结账回调重复触发开立 Then 返回原发票，不再取号 |
| AC4 买受人校验 | When 统编检查码不对 / 手机条码格式不对 / 同时给载具和捐赠 / 同时给统编和捐赠 Then 拒绝开立，错误码分别可辨 |
| AC5 金额 | Given 来源单的冻结税结果 When 开立 Then 销售额 + 税额 = 总计，等于来源单的含税应收；明细行合计等于总计 |
| AC6 证明联 | Given B2C 未存载具未捐赠 When 开立成功 Then 生成一份证明联打印事实，含期别、号码、随机码、一维条码内容（19 码）、左右 QR 内容 |
| AC7 不印证明联 | Given 存了手机条码载具或捐赠 When 开立成功 Then 不生成证明联打印事实，发票标记 `printMark=N` |
| AC8 补印 | Given 证明联已印 When 有 `biz:print:reprint` 的人补印并填原因 Then 打印中心出一张标「补印」的证明联，记录原因与操作人；发票号码不变 |
| AC9 作废 | Given 本期发票 When 作废 Then 状态 VOIDED，生成作废上传任务；同来源可重新开立一张新号码 |
| AC10 跨期不能作废 | Given 上一期发票 When 作废 Then 拒绝，提示改开折让 |
| AC11 折让 | Given 总计 1050 的发票 When 开折让 300 再开 800 Then 第一次成功、第二次拒绝（超过剩余可折让 750） |
| AC12 上传 | Given 新开发票 When 上传任务执行 Then 状态 PENDING → UPLOADED；通道失败则 FAILED 并按退避重试，不重复取号 |
| AC13 多行业 | 零售订单、餐饮结账、美业服务单用同一个开立入口；发票模块不读任何行业表 |
| AC14 税制可替换 | Given 主体未开通任何税制 When 开立 Then 拒绝「该主体未开通发票」；新增税制只加一个实现类，不改开立主流程 |
| AC15 查询 | B 端按门店、期别、状态分页查发票，看详情与上传状态 |

## 5. 不做（首期 Out of Scope）

- 真实加值中心（ezPay / 绿界等）对接：首期只做通道接口与本地桩通道；正式通道等商户签约后单独接。
- B2B 交换（存证以外的 A0401 交换流程）、跨境电商、特种税额（娱乐业等）。
- 发票兑奖、中奖通知、载具归户。
- 运营端界面与 B 端 App 页面：首期只出 B 端 API 与打印，页面下一批。
- 线上订单事后申请开票（`ord_invoice_request`）的迁移：继续原流程，不并入。
- 中国大陆、阿联酋等其他税制：只留 SPI 和税制编码，不实现。
