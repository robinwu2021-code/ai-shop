## 零、一句话现状（2026-08-05 更新）

**买卖闭环已经通了。** 买家：逛 → 加购 → 结算 → 支付 → 订单 → 取货码；
供给侧（现在在 **b-app**）：登录注册 → 入驻 → 上架（多规格）→ 接单 → 分拣 → 核销 → 订单完成；
买家再回来发表评价 → 计入商家评分。

上一版这里写的是「能逛、能加购，但买不了」—— 那条链现在打通了。

> 归属键 `leaderNo` → `merchantNo`（常去的店）；`Pickup.leader*` → `host*`（承接方是入驻商家）。

> **同时新增一期最高优先级功能：门店主页（可分享）** —— 商家把店铺码发给自己的老客，
> 老客扫码进店、点「我买过的」一键再来一单。**这是一期的主获客路径**，见 §二 P0-D。

### ~~P0-D 门店主页~~ ✅ 已完成（2026-08-05）

> [ADR-004](../technical/ADR/ADR-004-增长模型从孵化团长转向商家自带客流.md) 决策：**主获客路径是商家自带客流**，不是裂变玩法。
> 一个粮油店有 200 个稳定老客，店主把店铺码印在包装袋上发进客户群，这 200 人带着复购习惯进来，获客成本 ≈ 0。
> ⚠️ **粮油副食不是「逛」出来的**：路径必须压到三步 —— 打开 → 常买 → 下单。第一屏是「我买过的」，不是店招 Banner。

## 五、建议的下一步

买卖闭环通了之后，优先级变成三件事：

**0. 做门店主页（P0-D，25–30）** —— 这是 ADR-004 之后的最高优先级。

理由：闭环通了，但**没有真实用户和真实订单去验证它**。门店主页是唯一能立刻带来真实订单的功能——
一个店主就能启动，不需要等社区里凑够人、不需要裂变冷启动。做完它，才有真实数据去验证核销台和评价。
建议与 E10（去团长化改造）一起做，因为两者都动商家身份模型。

**1. 把「假」的地方补真** —— 现在闭环是通的，但有几处仍是占位或未验证：
   - 送货上门 / 快递的结算只写了没实测（地址簿选址回填链路）
   - 领券中心、卡包没有页面（券能用但领不到，卡能买但看不见）
   - 求团发起仍是占位弹窗

**2. 接真后端** —— 这是从「能演示」到「能上线」的分水岭。
   建议顺序：`/mp/**` 对齐 → 微信支付真付 → 按商家拆单 + 分账 → 上架。
   越早接，`E3 按商家拆单` / `E4 退款回退分账` 的改动面越小 —— 这两项拖到后期会很痛。

**3. 补齐履约方式（P0-E，33–37）** —— 尤其**邻里自提**：求团买床垫、校服这类东西本来就没有门店可提，
不做这一条，求团这条线落不了地。建议与 E14（`PickupPoint` 实体）一起做，两者是同一个模型改动。

**必须先定的三条**：**B10 费率档位**（决定商家愿不愿意把老客带进来）、**B9 履约服务费口径**
（决定小店愿不愿意接分拣核销）、**B13 邻里自提地址脱敏**（决定发起人敢不敢把家当自提点）。
这三条不定，P0-D 和 P0-E 做出来也推不动。
