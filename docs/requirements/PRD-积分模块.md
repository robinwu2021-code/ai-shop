# PRD 积分独立业务模块

状态：草稿，待评审 · 档位：2 · 创建与更新：2026-10-14

积分是平台出资的购物权益。平台先备款、按预算返分，商家签约受理并获得全额兑付；退款和资金追回分开处理，用户权益始终有实际资金支撑。

阅读入口：[技术设计与开发计划](../technical/TDD-积分域重整.md) · [资金方案](../technical/design/积分资金方案-平台预存池.md) · [ADR-036](../technical/ADR/ADR-036-积分改为平台出资预存池.md)。本 PRD 接管原 [支付 PRD S8](./PRD-支付域.md#s8--积分) 的新积分规划，旧实现不据此认定完成。

实施前提：用户确认积分尚未上线。本期直接采用最新逻辑并移除旧方案，不做旧积分业务数据迁移、双引擎或旧客户端兼容。

## 1 目标与范围

服务对象是运营/财务、受理商家及购物用户。成功标准是：不超发、已承诺可履行、部分退款可恢复、每笔积分和资金可追溯，积分业务包可独立理解和单测，账务及结算协作在现有pay模块内完成。

本期：CN/CNY；购物返分；平台统一积分；线上购物；随单兑付及归集商家定期兑付；三端运营；退款、到期、统计、对账与首次上线。协议按主体签署、按门店记受理账户，积分不追溯发放商家出资。

独立定义：积分是现有`backend/pay/pay-domain`中的独立业务模块，根包`ai.neargo.shop.pay.points`，具有自己的业务对象、表族、应用服务和统一写账入口；不新增Maven模块、JAR、数据源、事务管理器或部署服务。复用`payTxManager`和`paySqlSessionFactory`；Mapper归`ai.neargo.shop.pay.mapper.points`。订单/售后经SPI与可靠事件调用，结算在pay域内经PointsSettlementHook协作，必要账务变更可同事务提交。

不做：线下返分/抵扣、用户间转赠、提现、积分形式售后退款、商家会员积分、签到等新营销场景、跨币种兑换、无通道支撑的直连定期付款。本期保留场景扩展接口，但不实现虚拟功能。

## 2 角色与完整用户流程

| 角色 | 可操作内容 | 可见结果 |
|---|---|---|
| 运营 | 种类/规则、计划、暂停、用户冻结、差异处理 | 少发量、余额、资金预留、在途异常 |
| 财务 | 备款/提取/调账审批、资金证据核验、付款/应收处理 | U/C/D/B、独立 R、外部资金覆盖 |
| 商家主账号 | 签署受理协议、方式选择、账单确认/异议 | 受理分、兑付额、现金/抵销、未付金额 |
| 商家财务员工 | 授权门店内查询及账单处理 | 不取得主体代签权，不越门店查询 |
| 用户 | 查看余额/原因/流水、下单选择积分 | 待生效/可用/占用、实际应付额、退款扣减明示 |
| 系统 | 持久化事件、付款查询、补偿、到期、对账 | 幂等结果、任务水位及告警 |

运营建种类 → 两人复核 U/B 备款 → 生效；商家签受理协议 → 下单试算并预留积分/B → 支付后兑付并返待生效积分 → 结算终局转正；随单随货款兑付，定期经账单确认后兑付。售后先准备积分处理、再执行资金、以明确结果确认；资金未追回使用 B，R 保留追款事实。

## 3 验收需求

每条 AC 的前置为“种类与相关业务有效、主体合法”，具体拒绝条件见对应条目；测试必须同时覆盖成功和拒绝分支。

| AC | 功能 | Given / When / Then 验收 |
|---|---|---|
| AC-PTS-01 | 模块边界 | 积分独立为pay.points业务包及pts表族，复用pay事务与Mapper工厂；订单/售后经SPI，结算经域内Hook；禁止绕过统一写账入口，不新增物理模块。 |
| AC-PTS-02 | 种类 | 同一区域同时只有一种可新增发放/核销的积分；币种取区域主数据，兑换比例生效后不可改，存量履约不受停用影响。 |
| AC-PTS-03 | 运营备款 | U/B 补充、提取和用户调账必须由两名不同人员提交/审批；过账需唯一且已核验的资金证据，重复证据不重复入账。 |
| AC-PTS-04 | 备付隔离 | U 对应发放户，C 对应用户及门店积分，D 对应未付兑付；B 为退款备付，R 独立应收，不充当现金。 |
| AC-PTS-05 | 备款流转 | 补 B 不发行积分；U 转 B 必须同步把发放户积分转入可回流接收户；提取不超过未占用余额。 |
| AC-PTS-06 | 返分规则 | 规则优先级为商品例外、类目、平台兜底，明确 0 不下落；FIXED 按件数、RATIO 按商品现金实付，赠品为 0；返分金额不超过商品现金实付。 |
| AC-PTS-07 | 发放预算 | 支付成功形成待生效积分；U/发放户不足时整张子单不发，记录 SKIPPED 原因和本应发放量，不阻断支付。 |
| AC-PTS-08 | 发放闸门 | 线下支付不发积分；暂停、冻结、规则 0 均记录原因；商家未签受理协议不影响平台返分。 |
| AC-PTS-09 | 转正 | 只在子单结算终局转正未收回部分；退款/终局先到时，后到的发放不恢复已取消权益。 |
| AC-PTS-10 | 受理协议 | 商家主体签协议后门店才可接受积分；主账号授权签署，留文本摘要、版本和签署人，运营不可代签。 |
| AC-PTS-11 | 在途承诺 | hold 成功时固定协议、兑换比例、结算方式、资金路径；后续解约、暂停或修改协议不破坏该订单履约。 |
| AC-PTS-12 | 核销计算 | 只在可受理门店分摊，券后商品金额为基数、运费不抵；每子单对齐兑换单位，合计等于总占用；quote 与 hold 同规则。 |
| AC-PTS-13 | 退款额度 | 新 hold 同时锁定用户积分及 B 退款额度；B 可用额度不足时返回明确原因、无任何部分占用；现有预留不被提取或复用。 |
| AC-PTS-14 | 下单降级 | 抵扣失败返回无抵扣及原因，下单响应/支付金额必须展示实际金额；独立提交的占用与订单创建失败之间有幂等释放和事实补偿。 |
| AC-PTS-15 | 取消与关单 | 未支付取消释放用户占用和 B 预留；支付与释放并发只允许一个合法结果，以订单事实补偿，不能凭超时释放已支付占用。 |
| AC-PTS-16 | 随单兑付 | 支付事实到达后积分转接收户退款预留、C 转 D；实际付款按锁定的当前应付额，不按历史结算快照。 |
| AC-PTS-17 | 付款结果 | 付款意图先提交再调通道；固定幂等号和金额，超时保留 UNKNOWN/PAYING，查询结果后确认或终止，外部成功本地失败可补记但不重复付款。 |
| AC-PTS-18 | 路径能力 | 随单直连需补差能力，归集需可追溯专项回补；定期归集复用付款单，直连无转账能力时拒签定期；远程支付形态未经契约验证不开放积分。 |
| AC-PTS-19 | 结算基数 | 随单货款基数包含积分，定期货款基数不含积分；佣金两者均含积分，付款来源互斥，归集专项回补不构成第二笔商家应付。 |
| AC-PTS-20 | 定期出单 | 固定同店同种类账期的候选头寸集合、截止时刻和金额，集合绑定及金额快照同事务提交；新增头寸不混入。 |
| AC-PTS-21 | 草稿修订 | 同账期沿用逻辑结算单，修订号递增并保存旧明细；按修订号确认，退款后重算无需违反账期唯一键，异议单停止自动确认。 |
| AC-PTS-22 | 定期退款 | 出单、确认未付款、付款中和已付均有退款路径；确认未付款可撤销确认回到草稿，PAYING 必须查清结果，已付走备付退款。 |
| AC-PTS-23 | 应收抵销 | 账单抵销须锁定具体应收记录；付款成功或零现金抵销确认时才核减 R、回补 B；失败释放锁，未知保留锁，抵销不得伪记现金入账。 |
| AC-PTS-24 | 退款比例 | 抵扣积分按累计商品业务退款比例退，返分按退款行对应规则/发放快照收回；商品与运费分开，最后一次商品全退补齐尾差。 |
| AC-PTS-25 | 退款准备 | 以售后单号准备退款，固定输入摘要、应退分、应收回、扣现金、承担差额及资金证据引用；相同请求重放返回原结果，改金额须拒绝或新建修订。 |
| AC-PTS-26 | 现金扣减 | 现金扣减不超本次业务现金退款额；仅支持补收回平台的路径可扣；现金未到账不得增 U 或发行积分，不支持路径的不足部分平台承担。 |
| AC-PTS-27 | 退款恢复 | 准备阶段只锁定，不把退回积分提前变可用；现金成功/合法零现金完成后确认，失败可重试，未知不撤销；撤销须资金动作未发生或补偿完成。 |
| AC-PTS-28 | 备付退款 | 已付商家补差未追回，仍从退款预留退分，以 B 转 C 保证实款支撑，同时登记 R；后续实际追回回补 B、核减 R。 |
| AC-PTS-29 | 积分回流 | 接收户退款预留仅在窗口结束、无进行中售后、资金结果明确且权威退款责任解除后转可回流；TOPUP 不能消费预留。 |
| AC-PTS-30 | 到期 | 账户滚动到期只清可用格，待生效/占用/退款准备不清；GRANT/HOLD 续期，REVOKE/EXPIRE 不续；提醒按周期幂等，过期转收入需划拨证据。 |
| AC-PTS-31 | 暂停 | 发放/核销分别支持全局、区域、种类、场景、端、商家、门店、用户；必填原因审计，恢复不阻断资金收尾；不可核销期间到期按受影响区间并集顺延。 |
| AC-PTS-32 | 明细统计 | 平台/门店/用户明细可追溯到凭证、订单、资金证据；停发来自发放头寸，累计统计可重算，回流不重复算业务发放或兑付。 |
| AC-PTS-33 | 可靠事件 | 订单/售后与pay各自事务写Outbox；跨域消费Inbox与积分过账同pay事务。pay内结算事实同步调用Hook并同事务写账，重复/乱序/崩溃可恢复，不依赖内存AfterCommit保证投递。 |
| AC-PTS-34 | 对账 | 内部账、头寸/准备单/预留、外部资金及源订单事实分别核对；缺失发放、已付仍 HELD、无单占用等均可定位补偿，不只核余额恒等式。 |
| AC-PTS-35 | 权限 | C 端仅本人，B 端主体/门店来自 BizContext，运营受角色及数据范围限制；平台总户不可被商家权限过滤，放开范围只在可信内部服务。 |
| AC-PTS-36 | 旧方案移除 | 最新实现完成后删除旧积分服务/SPI/Mapper/任务、收费口径、配置与接口；运行构建不得引用旧积分表或装配旧实现，三端使用最新契约。 |
| AC-PTS-37 | 首次上线 | 仅最新实现运行；按最新模型初始化种类/真实预算/规则/协议，全链路验收后启用；停止新增仍可完成已有付款/退款/恢复，不以关开关撤销承诺。 |
| AC-PTS-38 | 审计并发 | 凭证和两类流水只增不改，条件写失败整体回滚；锁按全局稳定键排序，幂等键含动作/对象/修订，payload 冲突拒绝，禁止余额负数。 |
| AC-PTS-39 | 整数与时区 | 积分、金额用整数和既约比例，BigInteger 中间运算并显式溢出拒绝；日期按区域时区，跨币种/种类混入同一凭证拒绝。 |
| AC-PTS-40 | 运营任务 | 补充计划只生成待审批单；调度器调用积分任务，不引业务模块；低水位、预留不足、未知资金、应收逾期和差异均有告警及处理入口。 |

## 4 非功能与上线约束

- 所有金额为币种最小单位；例子按 100 积分=1元，不代表默认参数已经批准。
- 正确性优先于放行：quote 可降级，hold 必须原子；新业务被暂停时，旧业务资金收尾仍执行。
- 本期容量验收基线：同种类 50 次过账/秒持续 10 分钟，hold P95≤500ms、错误率≤0.1%，无余额/预留/头寸差异。正式流量超过基线时必须重定目标并复压，不能宣称此基线覆盖任意负载。
- 事件正常投递延迟≤10秒，积压超过60秒告警；未知付款超过30分钟升级；账务一致性每小时、外部证据每日，源事实补偿每5分钟；所有修复可审计。
- 发放、核销、退款和付款须先完成并发、崩溃恢复、越权、数据源归属和首次上线验收再开闸；不能分批向生产开放一个缺退款/对账的积分系统。
