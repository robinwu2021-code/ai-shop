# 门店注册 · 进件 · 运营端管理 —— 对齐结论与开发计划

> 2026-09-02 · 承接[门店注册到进件-流程节点与代码对齐](./门店注册到进件-流程节点与代码对齐.md)。
> **本轮范围**：门店注册（入驻）链路 + 进件的**运营端管理与查询** + 门店治理，逐条核到端点级。
> **边界**：真实支付通道 / 结算分账 / 出款 / 对账**在另一会话（支付方案）进行中**，本计划不碰，
> 只到「读 `mch_payment_merchant` 状态 + 触发回查」为止（详见 §一）。

## 一、范围与边界（先划清，免得和支付会话打架）

| | 本会话（门店注册 + 进件运营管理） | 支付会话（另一会话） |
|---|---|---|
| 入驻/注册链路 | ✅ 全部 | —— |
| 进件 | **运营端可见性、看板、查询、人工回查**（读 `mch_payment_merchant`，调已有 `MerchantPaymentService.refresh`） | 真实进件通道 `PayApplymentGateway` 实现、`sub_mchid` 回执、通道回调入口 |
| 门店治理 | ✅ 店招审核 / 门店档案 / 店铺码 / 获客 / 模板 | —— |
| 结算/分账/出款/对账 | ❌ 不碰 | ✅ `/ops/settle*`、`/ops/finance/*`、`/ops/payments/recon*`、资金路径直连 |
| 搜索/查询 | ✅ 入驻/商家/门店/进件 列表的筛选与分页 | 结算类列表的筛选 |

> **关键判断**：`MchPaymentMerchant` 表与 `MerchantPaymentServiceImpl` 都在 `shop-merchant`（商户域），
> `MerchantGovernServiceImpl` 已注入 `MchPaymentMapper`。所以**进件的运营端看板/查询是商户域内的活，
> 不需要动 `pay/pay-*` 模块**，与支付会话天然隔离 —— 看板即便在 stub 通道下也能用（展示 APPLYING/REJECTED/ACTIVE）。

## 三、发现的契约缺陷与风险（先修，成本低）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| R1 | `GET /ops/merchants` 的 `status` 用 **单值 `eq`**，前端可能传 CSV（如 `SUBMITTED,REVIEWING`） | `MerchantGovernServiceImpl.list` line 118-119 `w.eq(getStatus, status)`；前端 `listMerchants` 的 `status` 会拼逗号 | CSV 到后端 **静默匹配零行**，运营看到「空列表」以为没商家 |

### WS-C · 进件运营端管理（商户域内，不碰通道，M 量级）

目标：给运营一个**跨商家的进件视图 + 人工回查**，卡在 APPLYING/REJECTED 的商家一眼可见。
全部读 `mch_payment_merchant` / 调已有 `MerchantPaymentService.refresh`，**不实现通道**。

| 序 | 事项 | 层次 | 端点 | 说明 | 验收 |
|---|---|---|---|---|---|
| C1 | 进件看板（读） | 后端+ops-web | `GET /ops/onboarding`（建议名） | 列出各主体各通道的 `applyStatus`、`rejectReason`、缺项、提交时间、**停留时长**；筛选 `status`/`payChannel`/`keyword`/分页。落 `MerchantGovernServiceImpl`（已有 `MchPaymentMapper`） | 能筛出全部 REJECTED；每行显示拒因与缺什么 |
| C2 | 人工回查/推进 | 后端+ops-web | `POST /ops/onboarding/{payNo}/refresh` | 转调 `MerchantPaymentService.refresh`（已存在），运营点一下主动回查通道；留痕 | 点击后状态按通道回执刷新；stub 下也不报错 |
| C3 | 导航叶子 | ops-web | `nav.ts` 商家治理下加「进件看板」 | 权限码复用 `merchant:read`（读）/ 新增 `merchant:onboarding:push`（回查） | 菜单可见、按权限门禁 |

> **与支付会话的接缝**：C1/C2 只消费 `MchPaymentMerchant` 的现有字段和 `refresh`。
> 通道真正接通后（支付会话），看板**自动**显示真实回执，无需改看板代码。上线前对齐字段口径即可。

## 十、ops-web 最后 13 个 mock 端点：四条各卡在哪（2026-09-02 查证）
