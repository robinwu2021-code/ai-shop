# B 端注册开店、订阅与商城：原型需求总结

日期：2026-11-03。状态：原型评审稿；目标需求与当前演示覆盖分别说明，不代表正式 App、API 或商业配置已上线。

[打开交互原型](../../prototypes/b-store-plan-mall.html) · [详细需求包](./B端App-注册开店Plan商城-原型需求包.md) · [逐页与情景覆盖](./B端App-注册开店Plan商城-原型覆盖.md)

## 一、目标与边界

让商家按当前门店完成注册开店、选择行业方案、购买经营服务或硬件，并能理解业务端资格、续费升级、商城订单及退款进度。保留现有“工作台／订单／商品／我的”四项底栏，平台商城从“我的”、订阅和到期引导进入，不增加第五个 Tab。

本轮目标为 **34 项功能（F01–F34）、25 个画面（P01–P25）、8 条流程（FL01–FL08）、16 组演示情景（S01–S16）**。画面编号不等于新增路由：4项改造画面覆盖6条既有路由、3项为状态或弹层、18项为建议新增页面。

不重画现有销售订单、商品库存、营销会员、结算、进件资质或行业作业页。商城订单是商家向平台采购，与顾客销售订单分开；软件访问权益与消费者卡券、储值分开。

## 二、核心规则

1. 每店一个经营类型，展示该类型的 FREE／PRO／CHAIN 恰三档；名称、期限、价格、整端组合读取平台发布数据。产品经营类型不覆盖主体进件行业。
2. 先创建真实门店并授予 FREE，再创建付费订单。取消或未支付仍保留门店，不重复开店。
3. 采购和权益归属门店，不归付款账号。切店清旧报价、选购和端上下文，历史订单不改绑；余额不能跨店使用。
4. 商业 code 只控制整个业务端。进入端后继续校验岗位 RBAC；未验收端不可购买，平台 SYSTEM 端不可售。
5. 同店同 code 的有限来源时长累计：POS 原到12月1日，加购30天到12月31日；再续Plan30天到次年1月30日。
6. Plan续费或升级保留独立端包未用量。端包已用10天、未用20天，再加30天Plan，未来仍有50天；历史不回填、来源不重叠消耗。
7. 升级仅转换旧Plan未用实付价值，端包余量独立保留，赠送不折成现金。365元/365天已用165天，示例旧值200元，新价699元，现金499元。
8. 可抵800元而新价699元时，须明确确认零元升级，101元留本店抵扣；不能提现、不能买硬件。首期升级只一个新Plan周期。
9. 报价和折价以服务端为准，版本或金额变化后重新确认。混合商品分别展示数字与硬件，硬件不参与订阅抵扣。
10. 支付与交付分开。未知结果查原单，不重复付款；支付成功不冒充权益已开通。全部数字组件按原组完成，不能靠补赠绕过失败。
11. 某端到期不清账号会话，FREE经营台与商城保留。未购、未来开始、岗位无权、治理停用和请求失败分别引导，不一律要求购买。
12. 退款按原组件、数量、原因和政策申请；已用或已转换来源需审核。现金原路退款、门店抵扣恢复与权益调整分别显示。旧主体额度和宽限承诺单独兼容，不与新门店Plan混写。

## 三、角色与信息范围

三项权限独立演示，不互相推断：

| 权限 | 可查看／操作 | 不能据此获得 |
|---|---|---|
| 采购 `canPurchase` | 报价、下单、付款、取消、申请退款；本店抵扣余额和流水 | 跨店使用、平台发布、退款审核 |
| 来源查看 `canViewEntitlementSources` | 某端的来源、已用/未用和排期 | 自动查看原商城订单 |
| 商城订单查看 `canViewCommerceOrders` | 授权订单、交付和物流 | 付款、取消、退款申请、抵扣余额 |

普通店员只看岗位允许的端资格与必要到期信息，不能默认看到采购金额。无来源权不展示来源入口；有来源权但无订单权时，原单编号只读、不跳转。正式授权仍由服务端逐接口校验。

## 四、8条主流程

| 流程 | 用户路径 | 关键结果 |
|---|---|---|
| FL01 免费开店 | 登录→无店→经营类型→资料→FREE→创建结果→工作台 | 免费门店先成立，返回保留草稿 |
| FL02 付费开店 | 选择付费意向→创建门店/FREE→报价→订单→支付与交付 | 取消支付仍保留免费店 |
| FL03 登录与切店 | 登录→可访问门店→选择/管理→工作台 | 清旧报价，原订单不改店 |
| FL04 商城购买 | 我的/订阅→方案比较/商城→商品→报价→确认→支付/交付 | 一单一店，无跨店购物车 |
| FL05 同端续购 | 权益→来源→续购→累计预览→支付/交付→权益 | 所购时长实增，端包余量保留 |
| FL06 升级抵扣 | 当前订阅→升级报价→旧值/余额/现金→确认→结果 | 零元也确认，结余留本店 |
| FL07 端到期处理 | 访问某端→判定原因→续费/联系老板/返回经营台 | 商业到期、岗位和治理分别处理 |
| FL08 订单与售后 | 商城订单→详情→硬件物流/退款申请→进度 | 现金、抵扣与权益调整分开 |

## 五、25个画面分组

| 分组 | 画面 |
|---|---|
| 登录与开店 P01–P07 | 登录注册、门店选择/管理、无店、经营类型、资料、开店方案、创建结果 |
| 工作台与订阅 P08–P13 | 工作台/我的、订阅总览、方案比较、权益总览、来源详情、端准入结果 |
| 商城与成交 P14–P18 | 商城、商品、确认订单、升级确认、支付与交付结果 |
| 订单与售后 P19–P23 | 商城订单、订单详情、硬件物流、退款申请、退款进度 |
| 抵扣 P24–P25 | 本店抵扣余额、抵扣流水 |

S01–S16覆盖免费/付费开店、多行业切店、独立权限、同code累计、端包保留、升级现金/零元结余、软硬组合、未知支付、数字占用、准入异常、报价过期/停售、退款与旧合同。逐项预期和当前边界见覆盖记录。

## 六、当前原型与未覆盖项

原型由HTML、独立脚本和共享proto.css构成，25画面并列展示；支持情景、权限、中文/英文/阿语、RTL和明暗主题。全部报价、金额、日期、订单和付款均为本地演示，无真实API或持久化。现有测试与覆盖记录验证的是原型交互，不是生产支付、服务端事务或鉴权。

仍需补齐：完整失败/提交中状态、真实发布目录和期限SKU、商城搜索及订单分页、多包裹物流、组件数量/政策化退款与最终权益协调、完整来源片段、真机软键盘和安全区、跨客户端防重及生产接口。当前累计和升级为固定示例，不能用于实际结算。

后续认证与提醒增强另属后续设计：P08/P11/P13及消息将增加临期、到期和深链校验，提醒以同code连续期限为准，不能只看单一Plan期限；这些增强未计入本次25画面的原型验收。

商业待定参数包括各行业实际组合/价格、正式期限、退款与宽限、可售端验收名单、旧合同分摊。采用明确演示值，不把参数当成已发布承诺。
