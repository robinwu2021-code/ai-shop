# 会员联想与储值原单隔离修复

沿用writing-plans/executing-plans/TDD；用户要求仅基本编译及本次定向测试，不重复全量回归。

## 已定位根因

StoredValueRechargeSheet.load在识别当前会员之前读取sv.offline:{商家}:{门店}，任何会员都会恢复同一原单；resumed对应词条为“存在待确认操作”。confirm-offline后端已在一个Pay事务完成创建/提交/收款确认，无额外审批节点。旧前端异常一律保留命令，没有先查询原单状态。查询仅支持完整号码，按钮为sh-link。

## 任务

- [x] A. 按当前会员隔离原单；服务端返回pendingScope（租户/商家/店/操作员/顾客的稳定摘要，非资金授权）；新本地map保留多笔，老格式仅匹配当前会员时恢复；恢复先resolve查询，不自动重复确认收款。确定业务失败且服务端封闭原命令成功后可清除失败草稿，网络未知保留原键。正常用户与其他会员不互相阻断。
- [x] B. 联想查询：仅授权商家会员，姓名/备注及手机号前缀/尾号；3位数字或2字起，防抖350ms、最多20条；完整号码保留原查询契约。人档域批量匹配只返回脱敏资料，不在会员域储存明文或解密。不在资金事务内调用远端。
- [ ] C. 搜索使用统一有背景按钮；原型与文档同步；定向测试、类型/构建、一次整体审查；推送、部署与真机更新。不得执行真实收款或自动确认历史资金。

## 裁定

- “不需要确认”指不增加审批/再次确认；仍保留一次显式储值提交，禁止点开弹框就入账。
- 身份不明、断网或原单结果未知时不伪造成功、不丢原幂等键；只影响该会员。旧原单保持可恢复。

## 接口与恢复约定

- GET /biz/stored-value/customer-candidates 新增keyword（会员姓名/备注、手机号前缀/尾号），兼容phone完整号码查询；授权商家范围、最多20条、资料脱敏，不提前开户。
- Selection新增pendingScope，为租户/商家/门店/操作员/顾客的稳定摘要，仅作缓存命名空间，不能替代权限。无需数据库迁移。
- 打开弹框只查方案，一次显式储值提交执行confirm-offline，无审批。未知网络结果保留原body/key；恢复先resolve，无原单时cancel-create封闭原命令，拒绝取消则回查。业务拒绝也必须封闭后才能换key。
- 历史缺少号码密文的人档无法恢复前缀，完整号码哈希与已有尾号匹配保留。姓名联想使用商家会员备注。
