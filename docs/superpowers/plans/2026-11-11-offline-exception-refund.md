# Offline Exception Refund Implementation Plan

Goal: 两套套餐异常真实款项完成可恢复线下退款、核验与占用释放。
Architecture: 原资金账本 + 共用退款协调记录；原生业务授权/证据与占用释放，不另建资金账本。
Tech Stack: Java21, MySQL9, Flutter, Next.js。
Spec: docs/superpowers/specs/2026-11-11-offline-exception-refund-design.md

## Global Constraints
- 先本地，两个购买场景及退款闭环修复验收后按用户最新指令直接部署166；真实收款配置后补，不写入测试资金。
- 保留原工作区未提交改动；在既有隔离工作树续接。
- 原实收金额/币种/引用必须从资金权威读取。实际银行退款不由代码发起。
- 只有可信退款完成后，经银行对账关闭，才释放占用。未知/部分退款不释放。
- 原始请求及退款核验动作冻结，外部IO不进入业务事务。

## Tasks
- [ ] 资金端：权威列举实际收款/退款容量；对账关闭验证真实全额退款，拒绝备注伪装；相关MySQL9回归。
- [ ] 共享协调：退款申请、实际退款核验、原动作恢复与后台扫描，原款/退款事实严格匹配，私有证据与状态投影。
- [ ] 两域接线：商城及主体包API/权限/私有凭证、退款及占用解除，保留已购权益和后续新单。
- [ ] App/OPS闭环：异常实收、退款申请/核验/恢复/对账释放及安全买家进度回显。
- [ ] 回归定位修复、真实账本与HTTP本地联调、复查与文档更新。
