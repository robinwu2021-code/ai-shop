# 会员底部弹框储值执行计划

> **For agentic workers:** 使用superpowers:executing-plans在当前隔离工作树内执行，逐项记录RED/GREEN与编译结果。

**Goal:** 当前门店查询会员，点击会员选方案，弹框确认线下储值，原单恢复与到账反馈。
**Architecture:** Core拥有会员与身份，shop-app聚合和鉴权，Pay拥有方案、收款与资金；B端复用统一组件。未注册会员身份改造须保持已有账户与原单兼容。
**Tech Stack:** Java21/Spring/MyBatis/Flyway、Vue3/uni-app/TypeScript。
**Spec:** docs/technical/TDD-会员办理储值-UI与接口补充.md。

## 全局约束

- 门店沿用外层，弹框只选方案；无新增会员确认、填写收款方式或凭据页面。
- 原单幂等、权限先检查、同客同店复用、跨店隔离；金额取冻结方案。
- 不伪造userNo，不冒充现金／银行流水。新增会员不自动开户。
- 每轮编译与基本定向单测，不重跑已回归全量套件。不执行实际资金入账测试。

## 审查重点

- 未注册身份与已注册既有账户的映射、认领冲突。
- customerRef到期后的原单恢复，不重新生成命令。
- 创建与确认权限同时验证，越店和越商家拒绝。
- 弹框关闭／切店／重复点击的异步响应隔离。
- 请求结果不明时保留原键，未CREDITED不显示成功。
