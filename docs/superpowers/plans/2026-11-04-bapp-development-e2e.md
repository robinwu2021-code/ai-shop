# B 端开发环境端到端联调执行计划

用户明确要求实际开发环境的注册、登录、建店、进件资料提交及短信对接，发现问题直接修。本轮沿用已批准的门店商业/认证/进件设计及标准29操作，不新增付费Plan购买。已有隔离工作树 commerce-foundation，Flutter继续由现有 ai-shop-bapp 会话负责，避免并行覆盖。

## 目标与边界

- 启动当前真实后端及数据库，通过实际HTTP从Flutter访问；不再以WireAdapter替代端到端证据。
- 实际短信仅发送用户指定收件号码；号码不落版本库，配置密钥不输出/不提交。真实短信必须关闭全局固定码，核对短信测试号白名单不截获收件号。
- 独立开发数据库/媒体目录，不附着或修改生产数据。可以配置明确开发目录（实际发布三档和FREE）及开发主数据，不伪造已购/审核/收款成功。
- 收款进件可在明确开发provider下验证资料及状态合同；不进行真实扣款或真实银行开户，未接真实通道则如实报告边界。
- 默认不开启任何生产fixture后门。不推送或发布；保留前端现有未提交工作。

## 步骤

1. 核实配置及工具链：当前jar、JDK21、独立MySQL、迁移、DB会话、commerce开关/密钥、媒体、短信签名/模板/凭据。缺少手机号和凭据位置通过异步问题收集，继续其他工作。
2. 启动隔离的真实后端；校验完整迁移及应用装配，修复可复现的启动/API问题。通过实际发布服务配置可建店三档，验证FREE同事务。
3. 通过用户手机号实际发码与收码登录，覆盖首次注册和已有账号再次登录。留短信受理/到达验证与脱敏证据，不记录验证码/密钥。
4. Flutter新标准流程实际HTTP/可交互集成：精确选店、multipart资质上传、主数据、申请、协议、收款资料及回查，验证默认/独立行及超时/拒绝恢复；问题先复现再修。
5. 定向回归、独立审查与真实HTTP/数据库证据汇总；区分真实短信、真实HTTP、开发provider与实际收单边界。记录运行地址、配置方式及清理/保留的进程。
