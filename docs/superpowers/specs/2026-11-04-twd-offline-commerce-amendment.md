# 台湾平台收款与线下购买补充设计

用户于 2026-11-04 明确：主市场为台湾 TWD；NewebPay、LINE Pay、JKOPay 均纳入平台商户通道，完成串接验收后启用。同时支持商家提交线下付款资料、运营审核及运营直接代录。

本补充沿用独立 commerce 模块和宿主支付、库存、身份、媒体的边界，不把平台收款混为门店消费者收款。当前三家尚无真实适配与验收，配置和通道状态不能冒充已接通。

## 交付边界

- 本轮新增线下购买闭环及三家线上通道的统一契约、配置归属、可用性边界；真实线上协议与商户串接验收完成后才能启用。
- 商家创建 OFFLINE 订单并提交声明金额、声明时间、流水和私有凭证。提交不产生支付事实或权益。
- 运营核对实际收款主体、币种、实际到账金额和时间、唯一资金参考及证据。只有可信核款记录进入宿主既有支付账本后，才推进已付款和权益交付。
- 运营可以录入已有线下订单，也可以为指定门店选择已发布 SKU 代客报价、建单并录款。价格和分摊由同一内核计算；不得把付费购买写成零价值赠送，不任意改客户端总价。
- 金额不符记录为待核对，不伪造全款事实或静默吞掉差额；首期不自动实现多笔补差和溢付分配。

## 所有权、授权与审计

- 保留 ACCOUNT 订单原有归属规则；新增明确 STORE 买家模式用于运营代客订单，实际操作者仍为 OPERATOR。
- STORE 所有权键使用有域隔离的稳定摘要，绑定租户、当时买方主体及门店；买方主体来自可信目录，不取请求体。不得伪造 ACCOUNT 或 SYSTEM。
- B 端仅本店、同买方主体且有采购/财务能力的实时成员可读取或恢复 STORE 订单。证据读权限更窄：本人提交凭证与平台内部对账证据分别控制，平台内部对账单不下发给商家。
- 核款、平台收款配置、退款审批、线下退款确认使用明确的运营权限；使用实时 DB 会话与权限，不回落缓存。
- 接受已授权核款意图后，后续恢复不依赖运营或商家持续在线；保存真实操作者及审批证据，不伪造后台身份重新审批。

## 资金与资料归属

- commerce 拥有申报、审查、代客订单等商业工作流资料；这些声明和状态不是第二套现金账本。
- 宿主 pay 域拥有平台商户收款档案、收款指引版本、实际 PAY/REFUND 记录、人工记账与唯一流水约束。继续复用现有 stl_payment 等资金真源。
- 平台商户、收款主体、银行资料和正式售价由运营实际配置；不编造默认银行账户。线上密钥由受控部署配置提供，不放商业快照或 API 响应。
- 收款指引发出后版本不可被配置修改追改；停用只影响新指引，历史原样保留。
- 媒体使用既有私有资料服务，绑定租户、门店、订单和提交人，拒绝任意外部 URL。文件与资金端口 I/O 不放在商业或资金数据库锁内。

## 时间、占用与关单

- 报价有效期仍为 15 分钟。线下付款窗口是单独配置、带版本的规则；开发示例为 PT24H，启用时必须显式配置，创建订单后冻结 paymentDueAt，不静默续期。
- 运营确认时间与实际到账时间分开。商家声明时间不作为到账事实，不为赶截止时间回填虚假时间。
- 事后代录历史收款必须走明确的人工补录模式；不全局放松线上付款时间校验，权益仍按实际交付生效。
- 拒绝凭证不代表未收款、不能释放占用。指引已发出后，关单须有运营对账/作废决定、参考、原因和证据，并建立不可绕过的正常认款禁入栅栏。
- 该栅栏证明业务已作废及截至对账时未发现匹配款，不声称银行永远不会再收到钱。关单后发现入款，即使声明原在截止前，也记录真实资金并走异常退款；不重新覆盖已释放占用后的新订单。
- UNKNOWN 保留可恢复状态，不猜测成功或无款。核款与关单并发必须保留首笔真实付款证据，旧单不得清除新单占用。

## 线下退款

- 仍先审核报价并冻结受影响来源/任务，再创建原收款关联的退款意图。
- 线下退款不自动转账；在运营填写实际出款时间、金额、币种、原付款关联、接收方参考及证据前保持待处理。
- 确认实际线下退款后才完成来源和抵扣调整，保留原现金和抵扣谱系，不把人工拒绝伪装为渠道最终失败。

## TWD 金额策略

- 保持 Money.minor 的明确精度：TWD 69900 表示 NT$699.00。新主机策略为 scale=2、现金/分摊量子=100；原 CNY 和历史量子 1 订单行为保持兼容。
- 新 TWD 商品价格和组件/周期现金分摊按整元网格计算，尾差仍按稳定序分配，金额逐级守恒。策略由可信端口提供并冻结进新报价/订单，不取 HTTP 参数。
- 估值和抵扣批次仍保留分级整数精度。先合计旧 Plan 转换价值及历史余额，再把本次抵扣降至可结算网格；余数保留余额，不丢弃。
- 例：转换价值 19950、新价 69900 时，抵扣 19900、现金 50000、剩余余额 50。不是把 19950 四舍五入或抹掉 50。
- 退款上限可保留分级精度，实际批准现金须符合原订单现金量子且不超过上限；拒绝非网格值，不静默改金额。抵扣恢复仍精确到内部最小单位。

## 验证重点

单一真实现金账本、声明不发权益、实时权限/私有附件隔离、流水跨订单防重复、核款/关单并发、原订单时限与迟到款补偿、代客 STORE 所有权、零元内部结算、差额不发权益、线下退款未知与重放、跨库阶段故障恢复，以及 TWD 多行/多周期/赠送/混合硬件金额与价值谱系守恒。
