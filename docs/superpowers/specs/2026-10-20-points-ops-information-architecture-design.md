# 积分运营端菜单与信息架构设计

**状态：** 对话方案已确认；请审阅本正式规格。规格确认后再制定开发计划，当前未开始实现。

## 目标

- 积分运营成为独立一级菜单，和“结算与资金”分开。
- 菜单按运营办理顺序排列：先配置，再接入和准备资金，随后开启业务、处理日常事项，最后结算与核对。
- 多记录业务以清单为主视图；创建、编辑、审批、执行和详情进入抽屉或确认弹框。
- 一个页面聚焦一个运营对象或一种办理任务，避免在同一页堆叠不相关的表单、查询和列表。
- 保留现有 API 和权限码；旧 `/points?tab=...` 地址提供兼容跳转，避免已有链接失效。

## 推荐菜单顺序

一级菜单：**积分运营**。菜单首页为积分总览，侧栏子项按“配置接入 → 资金准备 → 开启与日常处理 → 结算核对”的运营顺序排列。

### 1. 配置与接入

1. **积分类型与规则**：积分类型、兑换比例、抵扣上限、闲置规则和兜底规则。
2. **门店协议与接入**：协议签署、门店接入模式、线上/线下积分能力及存量义务检查。
### 2. 资金准备

3. **积分资金账户**：按积分类型查看平台资金池及各资金分格余额。
4. **资金申请与划拨**：充值、平台/商家池间划拨、提现、审批、执行和原始资金指令回查。
5. **资金计划**：查看周期计划、计划执行批次、收款声明与计划调整。

### 3. 开启与日常处理

6. **业务范围开关**：资金与接入就绪后，按全局、类型、场景、客户端、商家、门店或用户开启/关闭发放与核销。
7. **用户调账**：调增/调减申请、双人复核和状态追踪。
8. **退款待处理**：积分退款异常及需要运营介入的售后处理。
9. **订单积分核验**：按订单/子单号核验积分占用、发放、退款阶段及差异。

### 4. 结算与核对

10. **门店账单**：账单生成、修订确认、争议、应收补收和付款准备。
11. **积分账户查询**：按用户、门店或账户类型定位账户及余额分格。
12. **积分流水**：检索用户/门店积分账本记录。
13. **资金凭证与流水**：检索资金凭证及资金流水。
14. **业务头寸查询**：按业务类型和原编号查询待处理头寸。
15. **积分统计**：查看指定日期与范围的统计快照；重建统计作为受权限控制的确认操作。
16. **资金对账**：按记账日查看对账快照、扫描状态和差异。
17. **异常事件**：查看待处理/失败事件并保留原事件号重试。

## 总览页边界

总览页只负责快速判断“当前积分资金和运营是否正常”，展示积分类型摘要、关键资金分格、待复核申请、退款待处理、待结算账单和对账异常数量，并提供进入对应清单的链接。总览不承载审批、资金变更或多业务表单。

## 页面交互统一约束

- 主区域优先显示单一清单，筛选项放在列表上方；加载、错误、空结果均用运营端现有状态组件表达。
- 点击行打开详情抽屉；新增和编辑使用表单抽屉；审批、划拨、执行、冻结、重试等有资金或状态影响的动作使用确认弹框，并显示对象、金额/积分数、当前状态、操作原因和影响说明。
- 单项查询可以使用列表上方的紧凑查询表单，但查询结果仍以表格/结果清单展示，详情再进抽屉。
- 没有多条记录的单一概览（如资金分格快照）可用概览卡片；这不扩展成混合工作台。
- 复用运营端现有 `DataTable`、`Drawer`、`FormDrawer`、`Dialog`、表单控件、全局语言设置与视觉令牌，不另造组件体系。

## 表单输入与校验规范

- **可枚举数据优先选择控件**：积分类型、市场/币种、业务动作、范围、方向、场景、状态等使用 `Select`、单选或开关；门店、用户、账户、渠道等来自已有数据源时使用可搜索选择器，不让运营手输系统已有的编号。
- **文本与数字分开**：编号、原因、外部凭证和说明使用文本输入；积分数、金额最小单位、兑换比例、比例上限、天数和时间使用专用数字/日期输入。数字字段明确单位、`min`、`max`、`step` 和精度，禁止把数字当自由文本，也不把编号当数字处理。
- **选项切换时处理条件字段**：切换资金动作、范围、场景等选项后，只显示该选项需要的字段；被隐藏的条件字段清空或显式保留为草稿但不得提交。切换后重新校验依赖字段，避免将上一个选项的值带到新操作。
- **提交校验分层**：输入离开时校验单项；提交时校验整张抽屉表单；对上下限、日期先后、门店/类型关联、金额可用余额等组合规则在提交前校验，服务端仍做最终校验并把业务错误定位回字段或记录。
- **动作确认信息完整**：划拨、提现、审批、冻结、退款、重试和状态切换，在确认弹框中复述对象、动作、积分/金额、当前与目标状态、不可逆影响及必填原因；提交后回到原列表并刷新对应行。

## 页面职责与输入方式（设计第 2 部分）

| 菜单 | 主页面只展示 | 新建/修改/处理方式 | 主要输入与联动 |
|---|---|---|---|
| 积分类型与规则 | 类型清单 | 新建/编辑/启停抽屉；点击行查看详情 | 市场、币种等用下拉；积分单位、金额单位、上限、闲置天数用数字；类型码/原因用文本；状态动作确认 |
| 门店协议与接入 | 门店接入及协议清单 | 点击行打开门店详情抽屉；签署/发布/接入变更用表单抽屉 | 积分类型、门店、场景、协议版本和接入模式用选择；理由用文本；线上/线下能力选项变化时只保留对应设置 |
| 业务范围开关 | 开关规则清单 | 新建/变更用抽屉；确认后刷新该行 | 范围、方向、积分类型、客户端用选择；仅范围需要时才选门店/用户；切换范围清空不再适用的对象字段 |
| 积分资金账户 | 各类型账户分格清单 | 点行开账户明细抽屉；资金变化跳转资金申请 | 积分类型用选择；余额为只读金额，不在本页编辑 |
| 资金申请与划拨 | 申请/执行状态清单，待审批优先 | 新增申请、审批、执行/回查用抽屉或确认弹框 | 资金动作、来源/目标池和通道尽量选择；金额数字化；仅提现显示收款路由字段，仅充值显示核验证据；动作切换清理相关字段 |
| 资金计划 | 周期计划清单 | 新建/编辑、生成批次、声明到账、取消放抽屉或弹框 | 周期、动作、类型用选择；金额和日期使用数值/日期控件；动作变化校验所需的证据或路由字段 |
| 用户调账 | 调账申请清单，待复核优先 | 新建调账用抽屉；批准/驳回用确认弹框 | 用户、类型、方向用选择；积分数量用整数输入；原因用文本；禁止申请人自审 |
| 退款待处理 | 需人工处理的退款清单 | 点击行看完整退款事实；关闭/重试需二次确认 | 门店、售后/订单号优先搜索选择；原因文本；重试清楚说明将新建退款尝试 |
| 订单积分核验 | 按订单/子单查询得到的核验结果清单 | 查询后点击结果打开绑定、占用、支付、退款事件详情 | 单号作为文本检索；单号类型用选择；查询结果展示差异和各阶段状态 |
| 门店账单 | 账单组清单 | 生成账单用独立抽屉；修订、争议、确认、付款准备在详情抽屉执行 | 类型、门店用选择；账期用日期范围；金额只读；每个行操作说明当前修订号与影响 |
| 积分账户查询 | 查询结果清单 | 结果行打开账户分格详情抽屉；冻结在确认弹框处理 | 账户类型、积分类型、用户/门店用选择或搜索；账户编号按文本检索 |
| 积分流水 | 积分账户流水清单 | 点击行查看关联账户和订单详情 | 账户类型、流水方向、时间范围用选择/日期；用户/门店/凭证号按文本检索 |
| 资金凭证与流水 | 资金凭证清单，可切换资金流水列表 | 点击行打开资金指令与关联头寸详情 | 流水类型、状态、时间范围用选择/日期；资金指令号按文本检索 |
| 业务头寸查询 | 头寸查询结果清单 | 点击行打开原始业务事实和处理状态 | 头寸类别用选择；原编号文本检索；只读展示处理进度 |
| 积分统计 | 日统计快照清单 | 重建单日统计需确认弹框并保留操作号 | 日期、统计范围、对象类型用选择/日期；门店/用户使用搜索选择 |
| 资金对账 | 对账批次与差异清单 | 启动扫描用确认弹框；差异行打开详情抽屉 | 积分类型和日期用选择；扫描范围固定展示；未完成扫描明确标注，不能显示为平账 |
| 异常事件 | 事件与恢复状态清单，待人工处理优先 | 查看事件抽屉；重试必须二次确认并沿用原事件号 | 事件类型、状态用选择；编号只读/文本检索；重试原因用文本 |

页面拆分的原则是**一个主列表只对应一个业务对象**。积分流水、资金凭证、资金流水、头寸和统计快照各自有不同的字段与查询目的，因此分别成页；资金申请、计划和用户调账不得并置，账单、退款回查和异常恢复不得并置。

## 路由、权限与接口边界（设计第 3 部分）

### 路由组织

积分运营菜单入口使用独立页面路由，避免仍把所有领域挂在 `/points?tab=...` 的单页组件中。建议路由与菜单项一一对应：

| 路由 | 页面 |
|---|---|
| `/points` | 总览 |
| `/points/types` | 积分类型与规则 |
| `/points/store-access` | 门店协议与接入 |
| `/points/switches` | 业务范围开关 |
| `/points/accounts` | 积分资金账户 |
| `/points/funding` | 资金申请与划拨 |
| `/points/plans` | 资金计划 |
| `/points/adjustments` | 用户调账 |
| `/points/refunds` | 退款待处理 |
| `/points/order-inspection` | 订单积分核验 |
| `/points/statements` | 门店账单 |
| `/points/account-lookup` | 积分账户查询 |
| `/points/ledger` | 积分流水 |
| `/points/funds-ledger` | 资金凭证与流水 |
| `/points/positions` | 业务头寸查询 |
| `/points/stats` | 积分统计 |
| `/points/reconciliation` | 资金对账 |
| `/points/events` | 异常事件 |

旧地址在迁移期保留映射：`overview → /points`、`configuration → /points/types`、`switches → /points/switches`、`treasury → /points/funding`、`settlements → /points/statements`、`queries → /points/ledger`。旧查询页中的账户、资金凭证/流水、头寸、统计、对账和事件均有独立的新菜单入口，不会因主链接映射而丢失；保留来源筛选参数的兼容规则在实施时逐项核验。

### 菜单权限与动作授权

- 一级菜单及页面可见性仍走现有菜单权限过滤机制；只读入口使用读取权限。
- 创建、编辑、审批、执行、冻结、重试、重建统计和对账扫描等动作仍由现有服务端权限码分别控制，页面按钮按权限隐藏/禁用，接口权限继续作为最终边界。
- 本次不改业务权限语义或服务端鉴权。若菜单矩阵审查发现“读菜单权限与具体业务读取接口不匹配”，先单独列为权限对齐任务，避免信息架构调整扩大权限范围。

### 已发现的接口能力边界

- 人工积分退款查询接口当前强制要求 `storeNo`，因此退款页应先选择/搜索门店，再展示该门店的待处理清单。若业务要求跨门店统一待办队列，需新增并评审后端分页查询契约与权限范围，不能由前端拼全量门店请求模拟。
- 运营端已有门店清单查询能力，可为退款页、协议页、账单页提供门店搜索选择器；仍以积分接口的 `storeNo` 为请求边界。
- 门店协议及门店积分接线也需要 `typeCode`、`storeNo` 或场景参数，页面先通过选择/搜索确定对象，再请求列表或详情。
- 原订单积分核验是按子单号单笔查询，放在独立的“订单积分核验”页面；不混入类型配置、流水或资金异常页。
- 当前统计重建属于写操作，应该从只读统计检索中移到受权限保护的单独动作/详情确认流程；结果和操作记录要能回到对应统计清单。

### 页面数据流和状态反馈

每页保持“筛选条件 → 单一列表 → 行详情/行操作”的数据流。抽屉打开时按行 ID/业务编号取最新详情；成功操作后关闭表单抽屉、刷新对应列表行与相关总览计数；失败时保留输入并显示字段级或业务级错误。列表空状态给出本页相关的创建/清筛选入口，错误态保留筛选并提供重试。

待复核、失败、未知结果和待人工介入记录按业务紧迫性优先显示。资金状态为 `UNKNOWN` 时仅提供原指令回查路径，不允许 UI 暗示可创建新资金申请替代原指令。

## 迁移顺序与验收标准（设计第 4 部分）

### 实施顺序

1. **菜单与路由骨架**：新增“积分运营”一级菜单及四组菜单项；建立独立页面路由；旧 `?tab=` 地址按映射兼容；先验证菜单判权、当前选中态、浏览器前进/后退和深链。
2. **配置与接入**：拆分类型/规则和门店协议/接入；先将当前页面的能力移动到单一清单和抽屉，不改变后端业务语义。
3. **资金准备与业务启用**：拆分账户、申请/划拨、计划、业务开关；资金与接入就绪后再开启发放/核销范围。把高风险操作改为有上下文的确认弹框，保证未知资金状态只允许原号回查。
4. **日常处理与结算核对**：拆分用户调账、退款待处理、订单积分核验、门店账单、账户查询、流水/凭证、头寸、统计、资金对账和异常事件。确保原页面每个查询和处理能力都能从新菜单或对应记录详情到达。
5. **全局验收**：逐页检查列表字段、筛选、分页、空/错/加载态，检查双语、响应式、键盘操作和权限；通过针对性测试和运营端生产构建后再部署。

每阶段完成后该阶段菜单与已有操作均可用，不要求先做完全部新页面才可验证；阶段之间不改积分接口契约，除非后续明确批准跨门店退款队列。

### 验收标准

- 左侧出现独立一级“积分运营”，菜单按已确认的四组和业务先后顺序展示；当前页面选中态、权限过滤和全局语言一致。
- 总览以概况和待办入口为主；其余每页只围绕一个对象/任务，页面主内容是清单或单一查询结果，不再出现资金申请与调账、账单与退款回查、流水与对账等跨域并排区块。
- 所有现有积分运营能力在新结构中有且只有一个主要入口，旧链接不会 404 或悄悄落到无关页面；被拆出的能力有明确新菜单或详情链接。
- 每个列表具备清楚的筛选条件、加载/错误/空状态和分页；点击行可以查看详情，新增/编辑/审批等操作不要求在列表页内展开第二块复杂工作区。
- 可枚举项使用选择控件；文本和数字字段正确分类；数字有单位及边界；选项切换时条件字段及时变化、旧值不误提交；客户端与服务端校验错误均能让运营定位问题。
- 有资金或状态影响的动作显示对象、金额/积分、状态变化和原因；提交期间防止重复操作；成功后刷新相关列表/计数；错误保留用户输入且不误报成功。
- 页面可见性与服务端权限一致：无操作权限时不展示可执行入口，直接访问和 API 仍受后端权限保护；用户调账双人复核约束、资金 UNKNOWN 原号回查规则继续成立。
- 验证范围包含菜单/路由映射、表单字段联动与校验、列表关键状态/空错误态、权限展示和 `ops-web` 生产构建；不做无关的全仓并发测试。

### 不纳入首版

- 不改积分账务、资金状态机、审批语义及服务端鉴权规则。
- 不新增跨门店全局退款队列接口；首版按门店筛选查询。
- 不在此轮重做 C 端或 B 端积分页面，也不重设计运营端全局组件与语言系统。

## 当前页面与建议拆分映射

| 当前内容 | 建议入口 | 主要整理方向 |
|---|---|---|
| 类型、兜底规则、协议、接入、订单核验、人工退款混在类型配置 | 积分类型与规则；门店协议与接入；订单积分核验；退款待处理 | 按运营对象拆开，不让配置页面承担售后和订单诊断 |
| 资金申请、资金计划、计划批次和用户调账同页 | 资金申请与划拨；资金计划；用户调账 | 每类记录各自成为列表页，操作进入抽屉 |
| 账单、应收、退款准备、资金回查混在结算页 | 门店账单；退款待处理；异常事件 | 主页面保留账单清单，跨业务回查有独立入口 |
| 账户、流水、凭证、头寸、统计、对账、事件混在查询页 | 积分账户查询；积分流水；资金凭证与流水；业务头寸查询；积分统计；资金对账；异常事件 | 让每个入口围绕一种查询任务与结果清单组织 |

## 实施前核对

实施每个页面前，逐项对照既有 API 契约核验清单字段、筛选条件、详情数据、游标分页和权限码；这属于实现核对，不改变本规格确定的信息架构。若核验发现某项能力没有现成接口，先记录为接口缺口并在实现该页面前单独评估，不用前端重复请求或拼接数据掩盖。
