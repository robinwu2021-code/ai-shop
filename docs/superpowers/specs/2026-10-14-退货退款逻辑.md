# 退货退款逻辑（售后 2.0 · 整合稿）

状态：草稿 v2（2026-10-14 用户定调：**退款永远不自动；以商家运营为主，商家与消费者协商，平台介入兜底**）
创建：2026-10-14
整合自：《订单与售后-三端状态关联》《售后2.0-方案》、`TDD-售后规则-审核与部分退款`（现行）、`TDD-订单售后三端断点修复`（已修）

## 0. 原则

1. **退款永远不自动。** 每一笔售后退款都由一个人的明确动作触发：**商家同意 / 商家主动退 / 平台裁决**。
   系统超时只做两件事：**提醒**（商家），**开门**（买家获得「申请平台介入」）。不替任何人决定退钱。
2. **商家与消费者协商为主，平台兜底。** 平台不主动接管；只有买家（或商家）申请介入时才进场。
3. **备货是信息，不是开关。** 「开始备货」告诉买家「商家已在做这单」、允许商家协商扣损耗；它不改变「谁来决定」（反正都是商家）。
4. **阶段以申请时刻为准**（快照），之后的进展只影响处理建议，不改规则。
5. **按商品行 × 件数退**；部分退款不改订单状态，只记退款进度。
6. **先问渠道能不能退**，不能就给替代方案，不硬退。
7. **承诺与行为同源**：端上不再出现「秒退」「自动退款」字样；说的每一句（需商家确认 / 售后期剩 N 天 / 商家还有 N 小时处理）都来自后端同一判据。

## 1. 两类退款，别混

| 类 | 是什么 | 谁决定 | 自动？ |
|---|---|---|---|
| **售后退款** | 交易成立后，买家申请或商家主动发起的退款 | 商家（平台介入时由平台裁决） | **永不** |
| **交易不成立的原路退回** | 拼团未成团、集单截单前撤单、关单后才到账的支付回调（钱进来了但订单已关） | 规则本身（交易没成立，钱不属于任何商家） | 现在是自动，**待拍板 §12-1** |

> 第二类不是「退款决定」，是「这笔钱本就不该收」——不退会变成平台无主资金。本文其余部分只讲第一类。

## 2. 履约阶段

| 阶段 | 判据 | 对买家怎么说 |
|---|---|---|
| `NOT_PREPARED` 未备货 | 已付款，商家未点「开始备货」，无运单 | 待发货 |
| `PREPARING` 备货中 | 商家已点「开始备货」 | 商家已于 HH:mm 开始备货 |
| `LABELED` 已出单未揽收 | 有运单号、轨迹停在 CREATED，6h 宽限内 | 已出单 |
| `SHIPPED` 运输中 | 已揽收及以后；或出单超 6h 未揽收（从严） | 已发货 |
| `AT_PICKUP` 已到自提点 🆕 | 自提类子单已到货 | 已到自提点 |
| `RECEIVED` 已签收 | 子单 COMPLETED | 已完成 |

---

## 3. 「开始备货」

| 项 | 规则 |
|---|---|
| 谁、何时 | 商家；子单已付款待发货；**全部履约方式、全部品类**（现状只对快递/自送显示）；B 端列表可批量 |
| 次数 | 一次，不可撤销；记 `prepared_at` / `prepared_by`，写时间线 |
| 前置 | 该子单没有进行中的售后（见 §12-4） |
| 买家可见 | 订单详情「商家已于 10-14 09:30 开始备货」；申请页「商家已开始备货，退款需与商家协商，可能扣除已产生的损耗」 |
| 商家可做 | 对这单的退款申请**协商扣损耗**（买家接受才生效） |
| 备货超时未发出（默认 48h，可配） | **不自动退，不改规则**。只做：① 提醒商家发货 ② 买家端出现「催发货 / 申请平台介入」③ 运营看板记一次「备货超时」（滥用指标） |

---

## 4. 决策矩阵

所有格子「商家超时」的结果都一样：**提醒商家（到时 + 再过 24h 各一次）；买家获得「申请平台介入」**。所以表里只列差异项。

### 4.1 仅退款

| 阶段 | 可申请 | 商家处理时限 | 处理建议（B 端） |
|---|---|---|---|
| NOT_PREPARED | ✅ | 24h | 同意（库存回补） |
| PREPARING | ✅ | 24h | 普通品：同意；食品/定制：协商扣损耗 或 驳回（模板「已备货/定制」） |
| LABELED | ✅ | 24h | 先取消取件单，再同意（按钮直达） |
| SHIPPED | ✅ 生鲜仅质量类 | 48h | 同意并「签收后退」，或建议买家拒收 |
| AT_PICKUP | ✅ 生鲜仅质量类 | 24h | 协商（货已到店，食品有损耗） |
| RECEIVED · 售后期内 | ✅ 生鲜仅质量类 | 48h | 质量+有图：同意；无图：请补图；高额：协商 |
| RECEIVED · 售后期外 | ❌ 入口消失，后端拒 | — | — |

**「签收后退」（WAIT_RECEIPT）**：商家在货在途时同意了，钱等签收。签收那一刻**不自动打款**，而是提醒商家「已签收，确认退款」一键完成；15 天未签收 → 买家可申请介入。（现状是签收即自动退，待拍板 §12-2）

### 4.2 退货退款

| 阶段 | 可申请 | 流程 |
|---|---|---|
| 发货前 | ❌（货没出门，走仅退款） | — |
| SHIPPED / AT_PICKUP / RECEIVED（售后期内） | ✅ 生鲜仅质量类 | 商家同意退货（48h）→ 买家 7 天内填退货运单（超时关闭申请）→ 商家确认收货并退款（48h，超时提醒 + 买家可申请介入） |

### 4.3 服务类（到店核销 / 上门）

| 阶段 | 规则 |
|---|---|
| 未使用 | 仅退款，商家同意 |
| 已使用 | 协商或平台介入 |

## 5. 部分退款

### 5.1 三个来源

| 来源 | 流程 |
|---|---|
| 买家申请部分（选件数 / 金额） | 商家同意 / 协商 / 驳回 |
| 商家协商 | 商家对买家的申请提出较少金额（扣损耗、按件折算）→ 买家接受才执行；48h 未答视为拒绝，回到待商家处理 |
| **商家主动退款** 🆕 | 不需买家申请：商家在订单上选原因（缺货少发 / 称重差价 / 补偿 / 价格调整 / 其他）+ 行与金额 → 执行，买家收到通知 |

商家主动退款也生成售后单（`initiator = MERCHANT`），走同一资金链路与可退额校验。

### 5.2 渠道能力与兜底

| 渠道 | 原路部分退 | 说明（限制做成配置） |
|---|---|---|
| 微信支付（直连 / 收付通） | ✅ | 可多次部分退，有次数上限与可退期限；收付通须先按比例回退分账 |
| 支付宝直付通 | ✅ | 可多次部分退，有可退期限；分账后须先退分账 |
| 0 元单 | — | 只退积分 / 券 |
| 线下当面付 | ❌ 平台不经手 | 商家线下退款 → B 端登记（金额 + 方式 + 凭证）→ 买家确认收到 |

渠道不支持 / 超次数 / 超期限 / 分账已结算退不回时，商家确认那一步就给替代方案（不等点下去才报错）：
**积分补偿**（买家同意）→ **商家线下退款并登记** → **整单退后重拍**（仅未发货、买家同意）。

### 5.3 系统内部先改

- 退款请求号 `AS-<子单号>` → **按售后单号**（否则一张子单只能退一次钱，第二次被幂等吞掉、账实不符）。
- 分账按退款金额比例回退。
- 渠道能力表 `pay_channel_refund_capability`，运营端可改。

## 6. 金额

| 项 | 规则 |
|---|---|
| 单位 | 商品行 × 件数 |
| 行可退额 | 下单时快照的行实付 `paid_share_minor` × 退件数 / 购件数；上限 = 行实付 − 已退 |
| 再次申请 | 允许；上限按剩余可退额 |
| 运费 | 发货前退完全部行 → 连运费退；已发货 → 仅商家责任原因退运费 |
| 损耗扣减 | 只能经协商（买家接受），商家不能单方面少退 |
| 券 | 整单全部退完才退回 |
| 抵扣积分 / 赠送积分 | 按退款比例退回 / 扣回 |

---

## 7. 时效（全部可配；超时都不退钱）

| 时效 | 默认 | 超时 |
|---|---|---|
| 售后期（完成后） | 7 天；质量类 15 天 | 入口关闭 |
| 商家处理申请 | 24h（发货前 / 到店）· 48h（在途 / 已签收） | 提醒商家 ×2；买家可申请介入 |
| 备货后未发出 | 48h | 提醒商家；买家可催发货 / 申请介入；运营看板计数 |
| 协商待买家回应 | 48h | 视为拒绝，回到待商家处理 |
| 买家寄回 | 7 天 | 关闭申请（不是退款） |
| 商家确认退货收货 | 48h | 提醒商家；买家可申请介入 |
| 签收后待商家确认退款（WAIT_RECEIPT） | 签收即提醒 | 24h 后再提醒；买家可申请介入 |
| 驳回后买家申请介入 | 7 天 | 关闭 |
| 平台介入处理承诺 | `interveneWorkDays` | 告警运营 |

## 8. 售后单状态机

```text
APPLIED ─┬→ REFUNDING ─→ REFUNDED        商家同意（仅退款即退 / 退货等寄回、商家确认收货后退）
         ├→ WAIT_RECEIPT ─→ REFUNDED     商家同意、货在途；签收后商家一键确认退款
         ├→ NEGOTIATING 🆕 ─┬→ REFUNDING  买家接受协商额
         │                  └→ APPLIED    买家拒绝 / 48h 未答
         ├→ REJECTED ─→ ARBITRATING / CLOSED
         ├→ ARBITRATING                  买家申请介入（入口：被驳回 / 商家超时 / 协商僵持）
         │      └→ REFUNDING（平台裁决，可部分）/ CLOSED
         └→ CLOSED                       买家撤销 / 寄回超时
```

- `ARBITRATING` **只有买家（或商家）申请才进**，不再有系统自动转入。
- 子单：部分退 → 状态不变，`refund_progress = PARTIAL`；全部退完 → `REFUNDED`。

## 9. 商家操作推荐（效率靠建议，不靠自动）

每张售后单下发 `advice = { action, reasonKey, suggestedRefundMinor?, deadlineAt }`：
- `action` 按 §4 矩阵「处理建议」列；附理由。
- `deadlineAt` 只说「几点前处理，否则买家可申请平台介入」—— 这是商家真正在乎的后果。
- 买家近 30 天售后异常高时附「谨慎」标记。
- 驳回给模板：已备货/定制、生鲜签收非质量、超出售后期、已协商一致、商品无质量问题。
- **一键按建议处理**；售后列表支持**勾选多条 → 批量同意**（商家逐条看过、自己点，不是规则代办）。

> 删掉原方案的「自动化策略」与买家端「秒退」：与「退款永远不自动」冲突。

## 10. 物流信息不一致

| 场景 | 处置 |
|---|---|
| 已发货但没录单号 / 轨迹未同步 | 商家补录运单 → 阶段重算为 SHIPPED → 建议「签收后退 / 拒收」 |
| 单号录错 | 商家改单号：原发货单作废、新建发货单，留痕 |
| 出单后迟迟不揽收 | 建议先取消取件单再同意 |
| 轨迹签收但买家说没收到 | 建议「核实」：商家上传签收凭证 / 联系快递；僵持则买家申请介入 |
| 自提到店买家没来取 | 食品类建议协商（扣损耗） |

## 11. 现网要关掉的自动退款（一期必须做）

| 现有逻辑 | 位置 | 改为 |
|---|---|---|
| 商家 48h 未处理 → 自动同意（仅退款立即打款） | `AfterSaleTimeoutJob` → `AfterSaleServiceImpl.autoApprove` | 提醒商家 + 买家可申请介入 |
| 退货寄回后商家 48h 未确认 → 系统退款 | `AfterSaleServiceImpl`（confirmHours 超时） | 提醒商家 + 买家可申请介入 |
| 在途仅退款签收 → 自动退款 | `settleOnReceipt`（确认收货 / 自动收货触发） | 提醒商家一键确认（待 §12-2） |
| 生鲜灰色地带超时「只再提醒」、无出口 | `autoApprove` | 并入统一规则（提醒 + 买家可申请介入） |
| 售后规则页的「商家响应时限 → 超时自动同意」文案 | ops-web 售后规则页、`AfterSaleRuleService` | 改为「超时提醒 / 开放介入」 |
| 已付款退款执行失败的重试 | `RefundRetryJob` | **保留**：它执行的是已经有人同意的退款，不是做决定 |

## 12. 待拍板

1. **交易不成立的原路退回**（拼团未成团、集单撤单、关单后迟到的回调）保持自动？推荐保持——钱不属于任何商家，不退就是平台挂账。
2. **签收后待退（WAIT_RECEIPT）**：签收后提醒商家一键确认（推荐，严格按「永不自动」），还是商家同意时就算已决定、签收即执行？
3. **售后期**：7 天（与结算一致，推荐）/ 15 天？
4. **有进行中售后时禁止点备货**？（推荐）
5. **积分按比例退、已发货运费仅商家责任退**？（推荐）
6. **商家主动退款**：原因清单够不够？是否设单笔上限 / 运营抽查（防拿退款当返现刷单）？
7. **渠道兜底顺序**：积分补偿 → 线下退款登记 → 整单退后重拍？
8. **线下退款登记**：必须买家确认收到才算结（推荐，与「不自动」一致）？买家不确认时可申请介入。
9. **分期**：一期 = §11 关掉自动退 + 退款请求号 + 写入门条件更新 + 「开始备货」全开放 + 行级退款与可退额 + 售后期；二期 = 处理建议 / 批量 / 商家主动退 / 协商 / 渠道兜底 / 线下登记。
