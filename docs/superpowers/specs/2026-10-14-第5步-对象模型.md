# 第 5 步 · 对象模型（编码前的抽象）

状态：草稿（待确认）
创建：2026-10-14
依据：《第5步-售后写路径与行级退款-方案》（已拍板）、结算口径 **A**（2026-10-14 确认）

## 0. 总览

```text
            ┌──────────── 售后·退款领域（trade/order/refund，shop-core）────────────┐
 申请 ───►  RefundableQuery ──► RefundableView（能退什么、退多少、截止何时）
            RefundPlanner  ──► RefundPlan（这次退哪几行、各几件、货款多少、运费多少）
               ├─ AfterSaleWindowPolicy   售后期
               ├─ FreightRefundPolicy     运费退不退
               ├─ LineAmountPolicy        一行退 n 件多少钱
               └─ ChannelRefundCapability 渠道能不能部分退
 商家核定 ─► ApprovedAmountAllocator ──► RefundPlan（核定额按行分回）
 执行退款 ─► AfterSaleRefundExecutor（编排）
               ├─ SettlePort.reverseSplit / refund ───────────┐
               ├─ PointsRefundPolicy        抵扣积分按比例退     │
               ├─ RefundLedger              行 / 子单已退额 + 进度 │
               ├─ CouponReturnPolicy        整单退完才退券        │
               └─ TradeStatusWriter         售后 / 订单状态经门   │
            └────────────────────────────────────────────────────┘
            ┌──────────── 结算领域（pay/pay-domain/.../settle/refund）──────────┐
            SettlementRefundPolicy（口径 A）──► BillRefundShare（商家回退额 / 补贴收回 / 运费回退）
               ├─ PreSplitAdjuster   分账前：结算单各金额按比例扣减
               └─ PostSplitReverser  分账后：按额发「部分分账回退」
            └──────────────────────────────────────────────────────────────┘
```

## 1. 值对象（不可变，record）

| 对象 | 字段 | 职责 / 方法 |
|---|---|---|
| `RefundableLine` | itemId, title, orderedQty, refundedQty, paidShareMinor, refundedMinor | `remainingQty()`、`remainingMinor()` —— 一行还能退多少 |
| `RefundableView` | subOrderNo, lines, freightRefundableMinor, deadlineAt, partialSupported | `remainingMinor()`；`GET /mp/order/{no}/refundable` 的返回 |
| `RefundLine` | itemId, qty, amountMinor | 这次退的一行 |
| `RefundPlan` | subOrderNo, lines, freightMinor | `goodsMinor()`、`totalMinor()`、`isWholeRemaining(view)` |
| `BillRefundShare` | merchantReverseMinor, subsidyReturnMinor, freightReverseMinor, finalRefund | 结算口径 A 算出来的一次退款在结算单上的份额 |
| `LedgerResult` | progress（`RefundProgress`）, subRefundedMinor | 账本记完之后的结果 |
| `RefundProgress`（enum） | NONE / PARTIAL / FULL | `of(refundedMinor, payAmount)` |

## 2. 规则 / 策略（每个一个接口 + 默认实现，可单测、可替换）

| 对象 | 方法签名 | 规则（已拍板） |
|---|---|---|
| `AfterSaleWindowPolicy` | `Long deadlineAt(OrdSubOrder sub, String reasonCode)`；`boolean isOpen(…, long now)` | 未完成：不限；完成后 7 天，质量类（DAMAGED / QUALITY / EXPIRED）15 天。天数取配置 |
| `FreightRefundPolicy` | `long freightFor(OrdSubOrder sub, FulfillStage stage, boolean coversAllRemaining, String reasonCode, long freightRefundedMinor)` | 未发货且退完全部剩余 → 退运费；已发货 → 仅 DAMAGED / QUALITY / WRONG_ITEM / MISSING 退；只退一次 |
| `LineAmountPolicy` | `long amountFor(RefundableLine line, int qty)` | `paidShare × qty / orderedQty` 向下取整；退到本行最后一件时 = 本行剩余可退额（吃尾差） |
| `ApprovedAmountAllocator` | `RefundPlan allocate(RefundPlan requested, long approvedMinor)` | 核定 / 协商额 ≤ 申请额；按各行申请额比例分回（复用 `LineShares.allocate`），运费最后扣 |
| `ChannelRefundCapability` | `boolean supportsPartial(String payChannel)` | 微信 / 支付宝：是；线下：否（走线下退款登记）；0 元：无现金 |
| `PointsRefundPolicy` | `long pointsBackMinor(OrdSubOrder sub, long refundMinor)` | 抵扣积分 × 退款额 / 子单实付，四舍五入；赠送积分同比例扣回 |
| `CouponReturnPolicy` | `boolean shouldReturn(List<OrdSubOrder> siblings)` | 支付单下全部子单 REFUNDED / CANCELLED 才退券（沿用现状） |
| `FreshQualityRule`（包装现有 `AfterSaleRules.applyGate`） | `Optional<ErrorCode> check(FulfillStage, boolean fresh, String reasonCode)` | 生鲜已揽收 / 已签收仅质量类 |
| `SettlementRefundPolicy`（结算口径 **A**） | `BillRefundShare share(StlBill bill, long refundGoodsMinor, long refundFreightMinor, long goodsPaidRemainingMinor)` | r = 本次货款 ÷ 剩余货款实付；商家回退 = (基数 − 佣金 − 服务费) 剩余 × r；补贴收回 = 补贴剩余 × r；运费：商家自寄从商家回退，平台代寄平台承担；退到最后一笔时取剩余全额（吃尾差） |

## 3. 领域服务（编排规则对象，自身不写规则）

| 对象 | 方法 | 协作 |
|---|---|---|
| `RefundableQuery` | `RefundableView view(String subOrderNo)` | 读子单 + 行 → `LineShares.of`（存量现算）→ `AfterSaleWindowPolicy` → `FreightRefundPolicy` → `ChannelRefundCapability` |
| `RefundPlanner` | `RefundPlan plan(RefundableView view, List<RefundLine> requested, FulfillStage stage, String reasonCode)` | 不传行 = 整单剩余；逐行校验件数 ≤ 剩余；`LineAmountPolicy` 算额；`FreightRefundPolicy` 算运费 |
| `RefundLedger` | `LedgerResult record(String afterSaleNo, RefundPlan plan)` | 行 `refunded_qty / refunded_minor` 累加、子单 `refunded_minor` 累加、算 `RefundProgress`；经 `RefundLedgerStore` 落库 |
| `AfterSaleRefundExecutor`（实现已有的 `RefundExecutor` 接口） | `void execute(OrdAfterSale as, RefundPlan plan)` | 顺序：`SettlePort.reverseSplit(按额)` → `SettlePort.refund(售后单号)` → `PointsRefundPolicy` → 退货回补库存（按行件数）→ `RefundLedger` → 售后经门 REFUNDED →（FULL）订单经门 `FULLY_REFUNDED` → `CouponReturnPolicy` |
| `PreSplitAdjuster`（结算域） | `void adjust(StlBill bill, BillRefundShare share)` | 分账前：基数 / 佣金 / 服务费 / 商家实得 / 补贴按比例扣减，状态不变；最后一笔才标 REVERSED |
| `PostSplitReverser`（结算域） | `boolean reverse(StlBill bill, BillRefundShare share, String afterSaleNo)` | 分账后：`gateway.splitReverse(金额, "REV-"+售后单号)`；补贴 `SUBR-`+售后单号；累计 `reversed_minor`；最后一笔标 REVERSED |

## 6. 调用时序（买家退 3 件中的 1 件，已分账）

```text
POST /mp/order/{sub}/after-sale {items:[{itemId:9, qty:1}]}
  AfterSaleServiceImpl.apply
    view = RefundableQuery.view(sub)                     // 行 9 剩 3 件、剩 9000 分；运费不可退（已发货、原因 NOT_WANTED）
    plan = RefundPlanner.plan(view, [9×1], stage, code)  // 行 9：1 件 = 3000
    AfterSaleLineStore.saveLines(as, sub, plan.lines)
    TradeStatusWriter.afterSale(… APPLY …)
商家同意
  AfterSaleRefundExecutor.execute(as, plan)
    SettlePort.reverseSplit(sub, as, 3000, 0)
      SettlementRefundPolicy(A).share(bill, 3000, 0, 9000)  // 商家回退 = 商家所得 × 1/3
      PostSplitReverser.reverse(bill, share, as)            // splitReverse(金额, REV-as)，结算单仍 SPLIT
    SettlePort.refund(sub, as, 3000, …)                     // 幂等键 = 售后单号
    PointsRefundPolicy … ；回补库存 1 件
    RefundLedger.record(as, plan)                            // 行 9 refunded 1 件 / 3000；子单 PARTIAL
    TradeStatusWriter.afterSale(… REFUND_SUCCEEDED …)        // 子单状态不变
```

## 7. 测试（对象级为主，场景兜底）

| 层 | 对象 | 关键用例 |
|---|---|---|
| 单测 | 每个 policy | 售后期边界（第 7 天最后一秒 / 质量 15 天）；运费四种组合；行最后一件吃尾差；核定额分回 Σ 相等；口径 A 三笔分次退完 Σ 回退 = 商家所得 |
| 单测 | `RefundPlanner` / `RefundLedger` | 超剩余件数拒；不传行 = 整单剩余；PARTIAL → FULL |
| 单测 | `PreSplitAdjuster` / `PostSplitReverser` | 分账前部分退后剩余照常分账（不再标 REVERSED）；分账后部分回退保持 SPLIT |
| 场景 | 全链路 | 3 件分三次退完：三笔支付流水、三笔分账回退、订单最终 REFUNDED、券退回 |
| 消融 | — | 换回整笔回退 / 键改回子单号 / 恢复落定即 REFUNDED，各自对应用例红 |
