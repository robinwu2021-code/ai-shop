约定：规则、策略、批准方案、执行记录分别是对象；服务只编排。下列接口与字段是后续代码修复的设计输入，不表示现有类或数据库已有这些能力。

## 0. 总览（本轮拟定）

```text
申请/预览 → RefundableQuery → RefundPlanner → RefundProposal
商家同意/买家接受协商/平台裁决
  → ApprovalEvidence + 不可变 RefundPlan
  → RefundExecution(PREPARED) + RefundReservation + outbox（同一本地事务）
发送/恢复 → 回退阶段 → SettlePort.requestRefund
  → ACCEPTED: PROCESSING / UNKNOWN: 回查 / FAILED: 重试或人工
  → SUCCEEDED: 同一成功归并入口 → 预占转实退 → 权益意图与真实结果
零现金 → 权益意图与真实结果 → BENEFITS_SETTLED
现金/权益结清 → 售后 REFUNDED → OrderClosurePolicy
  → goodsClosed + rightsSettled: 订单 REFUNDED
  → 全部交付/取消义务闭合 + rightsSettled: 订单 COMPLETED
库存 → 按取消履约或实收/验货事实单独幂等，不由现金受理推导
结算 → SettlementRefundBasis（不可变）+ SettlementRefundBalances + FinancialClosure + RecoveryClaim
```

## 1. 值对象与持久化事实（本轮拟定）

| 对象 | 字段/事实 | 定义 |
|---|---|---|
| RefundPurpose | CANCEL_ITEMS / RETURN_ITEMS / REFUND_WITHOUT_RETURN / MONEY_ADJUSTMENT | 取消未交付；退回；不退货终止交易；金额调整。用户流程 type 与账务 purpose 分开 |
| RefundableLine | itemId, orderedQty, closedQty, returnedQty, cancelledQty, paidShareMinor, cashRefundedMinor, agreedRetainedMinor, reservedCashMinor, reservedClosedQty | 件数终止余量与现金余量分别计算；历史 refunded_qty 不自动等同 returnedQty |
| RefundableView / RefundPreview | lines, normalDeadlineAt, qualityDeadlineAt, freightRemainingMinor, routeCapabilities, sourceVersion；预览另带 effectiveDeadlineAt / selectedReasonCode / plan / freightReason | GET返可退事实，POST after-sale-preview输入{type,reasonCode,items[{itemId,qty}],refundMinor?}并只读计算选定方案；提交同算法重验 |
| RefundPlanLine | itemId, coveredQty, closedQty, returnedQty, cancelledQty, cashMinor, agreedRetainedMinor | coveredQty 仅表达范围；金额调整后三种事实数量均为 0，closedQty 也为 0 |
| RefundProposal | afterSaleNo, type, purpose, lines, freightMinor, evidence, version | 可协商的提议；旧提议不能被接受请求误认成新提议 |
| RefundPlan | planId/version, purpose, lines, freightMinor, retainedFreightMinor, benefitIntents, route, ApprovalEvidence | 批准后不可变；方案现金额与合法留存分列；修改须新提议/重新批准 |
| ApprovalEvidence | actor, operatorNo, proposalVersion, acceptedAt/verdict, reason | 普通批准、买家接受少退协议或平台裁决；价差调整保存自身依据 |
| RefundExecution | executionNo, afterSaleNo, planHash, planSnapshot, phase, status, requestNo, resultEvidence, leaseUntil | PREPARED / PROCESSING / UNKNOWN / FAILED / SUCCEEDED；可内部用 DISPATCHING 租约；外部效果不随本地事务回滚 |
| RefundReservation | executionNo, item/sub cashMinor, closedQty, status | 预占不等于实退；批准事务占用，可信成功转实退；只有确定未发送/确定不可再成功才可取消预占 |
| RefundDispatchResult | outcome, providerNo, retryable, failureCode, evidence | ACCEPTED / SUCCEEDED / FAILED / UNKNOWN；非空流水号不是成功 |
| RefundLedgerResult | cashProgress, goodsClosed, cashSettled, benefitsSettled, closureReady | cashProgress = NONE / PARTIAL / FULL（0 元现金进度为 NONE），只投影旧JSON refundProgress、不新增重复cashProgress JSON；goodsClosed另下发，商品与权益闭合独立 |
| SettlementRefundBasis | 原始商品现金实付、商家所得、佣金、服务费、积分费用/补贴、运费归属、资金路径、收款/付款账户快照、version | 原始基数不可变；存量恢复不确定的单转人工核对，不能编造金额 |
| FinancialClosure | remainingPayable / paidUnreversed / legalRetained / recoveryOutstanding / pendingInstructions | 结算财务结束独立判定，不因 goodsClosed 或订单 REFUNDED 自动标 REVERSED；合法商家应付仍可结算 |
| SettlementRefundBalances | remainingPayableMinor, paidMinor, reversedMinor, recoveryOutstandingMinor, allocatedRefundMinor | 剩余应付、实际已付、已回退、待追回、已分配退款份额独立守恒 |
| RecoveryClaim | claimNo, supplier/责任方, originalPayment, executionNo, amountMinor, recoveredMinor, offsetEvidence, status | 归集供应商已付款后的追偿，不把减少账单当作已追回 |
| BenefitIntent/BenefitResult | executionNo, kind, entitlementSource, requested, succeeded, pending/failed, evidence | 本轮只定订单边界；具体积分域模型另评审；无权益可显式 NONE，有权益不得空成功 |

兼容类型：当前 `RefundLine(itemId, qty, amountMinor)` 仅保留为旧入口适配合同；本轮明确数量事实的新类型名为 `RefundPlanLine`。`OrderClosurePolicy` 是唯一纯闭合政策，现金比例、商品与权益结清输出到 `RefundClosure`，不再另建同职责的 RefundClosurePolicy。

数量约束：0 ≤ closedQty ≤ coveredQty；returnedQty/cancelledQty 只描述真实退回/未交付取消，不能同时终止同一份商品交易；不退货终止用途的二者为 0。累计终止量 ≤ orderedQty；同一行金额调整可覆盖相同商品，不重复终止件数。允许退回事实先登记，现金成功后再结清批准方案，二者时间不强绑。

## 2. 规则 / 策略（本轮拟定）

| 对象 | 方法/输入 | 规则 |
|---|---|---|
| AfterSaleWindowPolicy | deadline(sub, reasonCode)、dualDeadlines(sub) | 普通 7 天、质量类 15 天；申请资格取申请快照，提交时同算法重验 |
| RefundPurposePolicy | mapAndValidate(type, reason, proposal, currentFacts) | 不把只给金额推导为全退件数；老客户端金额申请映射 MONEY_ADJUSTMENT；完整取消/退回必须有明确范围 |
| FreightRefundPolicy | freightFor(currentFacts, purpose, coversAllRemaining, reasonCode, refunded/reservedFreight) | 发货前取消全部余项才退；发货后仅商家责任；实退/预占/合法留存分别记，只退一次 |
| LineAmountPolicy | amountFor(remainingRefundableCashMinor, remainingClosableQty, closedQty, purpose) | 按件终止以剩余可退现金/剩余可终止件数切分，下取整，最后一次取余款全额；现金余量扣实退/生效留存/其他执行预占；MONEY_ADJUSTMENT不耗件；批准plan冻结后不重算 |
| ApprovedAmountAllocator | allocate(proposal, approval) | Σ cash 与留存分别精确；减少终止交易应退额必须买家接受或平台裁决并记 agreedRetainedMinor；金额调整无损耗协议义务 |
| ChannelRefundCapability | capabilities(route, facts) | 线上退款/回退能力与线下登记能力分开；确定失败才可评审换路；未知不能切路径 |
| OrderClosurePolicy | evaluate(OrderClosureFacts) | facts封装当前状态、行数量、现金负债/实退、权益结果和预占；goodsClosed 且现金/权益结清 → REFUNDED；交付+终止混合闭合 → COMPLETED；仍有履约义务则保留履约状态；既有CANCELLED不被迟到资金回执复活 |
| CouponReturnPolicy | shouldReturn(siblings, entitlementFacts) | 全主单商品交易终止触发返券意图，真实结果计入权益结清后再结束订单；不能等待REFUNDED再返券造成循环；部分退款/混合交付不自动退券 |
| InventoryDispositionPolicy | cancellation/receipt/inspection facts | 未付款取消释放占用；已付款未发商品取消按精确数量回补已扣库存；真实退货验收可回售才入库；MONEY_ADJUSTMENT 和无需退货退款不入库 |
| SettlementRefundPolicy | share(basis, refundedGoodsBefore, refundGoodsMinor, refundFreightMinor) | 每项 cut = floor(original × after / goodsPaidOriginal) − floor(original × before / goodsPaidOriginal)；分账前后用同一原始基数；FinancialClosure另外判断，合法留存不随订单全终止回退 |
| BenefitsSettlementPolicy | intentions + results + closureFacts | 0 元不使用 0/0 现金比例；以真实权益结果推进 BENEFITS_SETTLED；补偿不等于原现金到账 |

结算分母为 0 不可直接套比例公式；非现金权益成本如何归属依赖待确认积分方案，现金结算本轮只明确必须显式 NONE 或人工核对。退货损耗、运费合法留存的结算分配需要在批准方案中明确责任，不把它们当欠退额。

本轮拟定按件终止交易的 LineAmountPolicy：remainingRefundableCashMinor = paidShareMinor − 已成功现金实退 − 已接受/裁决生效的合法留存 − 其他执行现金预占；remainingClosableQty = orderedQty − 已终止closedQty − 其他执行终止件数预占。当前执行批准前算本次 closedQty 的现金：floor(remainingRefundableCashMinor × 本次closedQty / remainingClosableQty)，本次终止全部剩余件数时取剩余现金全额。当前槽位串行；批准时余额/数量与预占同事务冻结，已生成不可变plan后发送、回执、重试不得重算金额或把本执行预占再扣一遍。

反例：3件原现金3000，先MONEY_ADJUSTMENT退1000，剩余可终止件数仍3、剩余现金2000；随后依次终止1件，现金为666 / 667 / 667，总现金含调整恰为3000。CANCEL_ITEMS / RETURN_ITEMS / REFUND_WITHOUT_RETURN消费closedQty，MONEY_ADJUSTMENT只降现金不耗件；不能继续按原paidShare × 本次qty / orderedQty算1000一件。原始快照仍用于总额上限与可追溯；初版原份额按件公式作为历史记录保留，已被本轮剩余额/剩余件数推荐公式替代，尚未实现。

## 3. 领域服务与恢复阶段（本轮拟定）

| 对象 | 方法 | 协作与事务边界 |
|---|---|---|
| RefundableQuery | facts(sub)；preview(sub, type, reasonCode, items/qty, refundMinor?) | GET仅取事实+normalDeadlineAt/qualityDeadlineAt；只读POST预览调用同一planner计算方案，不占槽不写账；提交事务重读重验 |
| RefundPlanner | propose(view, requested, purpose, evidence) | 生成提议；不在申请时预占资金；预览与提交复用算法 |
| RefundApprovalService | approve(proposal, ApprovalEvidence) | CAS 校提议/槽位/数量与金额；进入WAIT_RETURN时仅冻结提议/协议，不创建现金执行、不伪造实收；实际进入REFUNDING才同本地事务持久化不可变执行计划、execution、reservation、outbox |
| RefundExecutionDispatcher | dispatch(executionNo) | 租约保护阶段；同一 requestNo 与方案重放；外部调用不宣称与本地事务原子 |
| SettlementRefundCoordinator | allocateAndReverse(executionNo, basis) | 分配份额与回退结果独立持久化；分账前扣未付应付，分账后逆实际支付；归集已付款建追偿；FinancialClosure不因商品全终止标结算REVERSED |
| RefundResultConverger | onReceipt/onQuery/result(executionNo, result) | 验真与方向/金额/账户认领；回执/回查/同步可信成功统一 CAS 幂等入口；未知不落成功 |
| RefundLedger | reserve / settle / cancelReservation | success 同本地事务预占转实退、现金进度/终止事实、状态与事件；不同外部域用可靠消息与独立结果 |
| CouponReturnCoordinator | evaluateAfterCommit(paymentNo) | 子单提交后可靠事件驱动独立支付级事务，先锁Payment后汇总主单事实；幂等返券/可恢复结果，不在持Order锁的子单退款事务再取Payment锁 |
| BenefitSettlementCoordinator | request/restore/intents(executionNo) | 持久化权益意图、结果和重试；现金已成功不重新退钱；确定权益结清才推进相应完成条件 |
| RefundRecoveryService | recover(executionNo) | 先回查 UNKNOWN；可重试同执行续跑；确定永久失败转人工；人工换路有原路径关闭证明/买家同意 |
| InventoryDispositionService | apply(fulfillmentFactId) | 按真实取消或实收验货幂等；与现金执行号关联用于追溯，不能对发送受理回补 |

禁止回执已成功后因重放、超时或迟到失败把执行退回 FAILED。现金 SUCCEEDED 是资金事实；权益未结清时可继续恢复权益，但不得重复原路现金退款。执行 FAILED 保留批准方案、回退事实及预占处理依据，不删除决定来“回滚”外部效果。

非零现金的权益成功事件依据已保存的现金成功凭据重新评估A13；线下则依据已保存的买家确认评估A21。现金到账先落实退与权益意图，权益未结清时售后仍REFUNDING且分别展示两种结果；权益完成后无需第二次渠道回执即可结束售后。A22仅处理零现金，不把它用作伪造非零现金到账的出口。

返券评价通过子单事实提交后的可靠事件/outbox触发，由独立支付级事务锁定Payment后汇总主单商品终止与应返券事实、幂等生成/执行返券意图。子单退款事务只更新自身事实并提交事件，不能已经持有Order锁再同步获取Payment锁；支付级评价失败可恢复、真实券结果参与权益结清。该锁顺序和异步边界为本轮待评审建议，不改变历史验收记录。

## 4. 端口（本轮拟定）

| 端口 | 契约 |
|---|---|
| SettlePort | requestRefund(RefundRequest) → RefundDispatchResult；queryRefundExecution(executionNo) → 可信结果；内部回退阶段持久化请求/结果，同样区分受理/成功/失败/未知；旧 String refund 是历史接口，不适用于新成功判定 |
| RefundExecutionStore | createImmutable / claimLease / compareAndSetPhase / recordEvidence；同执行号相同方案允许重放，不同方案拒 |
| RefundLedgerStore | reserve(executionNo, plan, versions) / settle(executionNo) / releaseWithProof(executionNo)；实退与预占分离 |
| RefundResultInbox | 验证与持久化回执；executionNo/requestNo + provider evidence 唯一；先收据后确认本地事实 |
| AfterSaleLineStore | 提议版本与批准快照分离；保留五类数量/现金/留存，不覆盖已发送方案 |
| BenefitPort | 请求权益返还/扣回意图、查询结果；真实存在权益时须返回可恢复的结果；具体积分命令待评审 |
| InventoryPort | cancelUnfulfilled / receiveInspectableReturn；按事实幂等，处理不可回售与人工验货 |
| SettlementRefundBasisStore | 新单不可变快照；存量依据可追溯账务还原/人工冻结核对；不读取当前应付充当原始基数 |
| RecoveryClaimPort | create/query/recover/offset；归集已付供应商退款债权与买家退款分开 |
| TradeStatusWriter | 只在业务守卫及真实资金/权益事实满足后 CAS 迁移；订单终态按 OrderClosurePolicy，不直接以 cashProgress=FULL 驱动；FinancialClosure独立，goodsClosed不自动使结算REVERSED |

动作输出拟采用 ActionDescriptor(actionContractVersion=1)，版本缺失为旧合同，空集合为真无动作；不得把这两种输出混为一谈。

归集买家退款不等供应商追偿；垫付来源、限额与权限尚待评审，未知资金结果不能靠绕过权限“解决”。退款执行可先形成应退负债/待授权状态，不能假记 SUCCEEDED。

## 6. 调用时序（拟定：3 件退回 1 件）

```text
预览(reasonCode,type,items[9×1]) → 实时方案/双窗口/预占/版本
买家提交 → 创建提议与申请槽位
商家同意退货 → WAIT_RETURN → 寄回 → RETURNING → 实收/验货事实
批准退款 → 同事务：不可变plan + execution PREPARED + reservation + outbox
dispatcher → 分配结算份额/按额回退 → requestRefund
ACCEPTED → PROCESSING（不写实退、不退券、不把售后标成功）
UNKNOWN → 回查；FAILED → 可重试同号/确定永久失败人工
可信SUCCEEDED → CAS归并 → reservation转实退 + 现金3000/终止1件 + 权益意图
权益恢复结清 → 本售后REFUNDED；订单还有2件待履约，保持履约状态
其他2件正常交付 → 订单COMPLETED，cashProgress=PARTIAL
三件全终止 → 主单全终止触发返券意图 → 权益真实结果结清 → 订单REFUNDED
现金0 → 跳过现金发送，权益真结果 → BENEFITS_SETTLED → 同一闭合判断
```

## 9. 补充（待确认）：积分按退款比例退回 / 扣回（5.5b）

**初版形成时的现状记录（保留，不表示本轮验收）**：抵扣积分是一行 `USE` 流水（PENDING → CONFIRMED → REVERSED，**整笔进退**），赠送积分是一行 `EARN` 流水；
两者都只在「整单退完」时由 `returnBenefitsIfWholeOrderRefunded` 整笔退回 / 扣回。部分退款今天**一分积分都不退**，
与《行级退款方案》§3「抵扣积分按退款额 / 实付比例退回、赠送积分同比例扣回」不一致。要补的是积分域的新语义，所以先出对象模型。

| `PointsProrationPolicy` + `Default`（规则） | 同上 | `share(usePoints, earnPoints, refundedBeforeMinor, refundMinor, payAmountMinor)`：与结算口径 A 同法 —— **按累计切分**，Σ 恰等于总分，最后一笔吃尾差 |
| `PartialPointsReturner`（领域服务） | 同上 | `returnFor(PartialReturn cmd)`：按售后单号幂等（R3）；USE 行累计 `returned_points`（条件增量 R2），退满才转 REVERSED；已 CONFIRMED 的部分同比例冲积分池（复用 `refundConfirmed` 的入池口径）；赠送分：待生效扣 pending，已生效扣余额（是否允许扣成负数沿用现有 `points.config` 开关） |
