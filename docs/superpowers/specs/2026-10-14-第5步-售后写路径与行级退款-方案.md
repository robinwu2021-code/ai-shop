## 0. 要解决什么（现状 → 目标）

| # | 现状（已核对代码） | 后果 | 目标 |
|---|---|---|---|
| 1 | 售后按**整张子单**，任何一笔退款落定子单就 REFUNDED | 退一件，买家看到「已退款」；还能再申请，上限仍是全额实付 | 按**行 × 件数**退；部分退不改订单状态，记退款进度 |
| 2 | 支付侧退款幂等键 `AS-<子单号>`（`SettleServiceImpl.afterSaleNoOf`） | 一张子单只能退一次钱，第二笔被吞掉，售后单却记 REFUNDED | 键改为**售后单号**，一张售后单一笔 |
| 3 | 🆕 **分账回退是整单的**：`reverseSplit(subOrderNo)` 整笔回退并把结算单标 REVERSED | 10-11 上线的「部分退款」退一件也把商家整单分账退回 —— **商家少收** | 按**退款金额**回退分账（§4） |
| 4 | 申请没有时间窗口 | 结算期过后还能申请，分账已划出，回退大概率失败 | 售后期：完成后 7 天（质量类 15 天） |
| 5 | 售后状态写入仍是 `setStatus + updateById` | 并发下会互相覆盖（如商家同意与买家撤销同时到达） | 经转换门 CAS（与步 4 同一套） |
| 6 | 极速退已废，但 `instantRefundEligible` 与商品「极速退款」标签仍按规则算 | 对外承诺秒退，实际要审核 | 下掉 |
| 7 | 「开始备货」只对快递 / 自送显示 | 自提、到店核销的食品商家没有入口 | 全部履约方式开放（B 端） |

## 2. 数据（V404）

```text
ord_item
  + paid_share_minor  BIGINT  NOT NULL DEFAULT 0  本行分摊后的实付（含优惠、积分抵扣分摊；不含运费）—— 下单时落快照
  + refunded_qty      INT     NOT NULL DEFAULT 0  已退件数
  + refunded_minor    BIGINT  NOT NULL DEFAULT 0  已退金额
ord_sub_order
  + completed_at      BIGINT  NULL                完成时刻（售后期起算点）
  + refunded_minor    BIGINT  NOT NULL DEFAULT 0  已退总额（含运费）
  + refund_progress   VARCHAR(8) NOT NULL DEFAULT 'NONE'   NONE / PARTIAL / FULL
ord_after_sale_item（新表）
  after_sale_no · sub_order_no · item_id · qty · refund_minor · 通用审计列
  唯一键 (after_sale_no, item_id)
```

**回填**（迁移内一次做完，可重复执行）：
- `paid_share_minor`：按 `amount / goods_amount × (pay_amount − freight_amount)` 分摊，**尾差进本子单金额最大的那一行**（SQL 两段：先按比例取整，再把差额补到最大行）。赠品行（amount = 0）为 0。
- `completed_at`：取状态流水里该子单最后一条 COMPLETED 的 `at`。
- 已 REFUNDED 的子单：`refunded_minor` = 其售后单实退额之和，`refund_progress = FULL`，各行 `refunded_qty = qty`、`refunded_minor = paid_share_minor`（存量只有整单退，按整单处理）。
- 其余：默认值。

> 线上 `ord_after_sale` 行数很少（结算侧注释记过「一行都没有」，上线前查一次实数写进上线记录）。

## 3. 金额算法

| 项 | 规则 |
|---|---|
| 行实付快照 | 下单时：子单 `pay_amount − freight_amount` 按各行 `amount` 比例分摊，最大余数法，保证 Σ = 子单商品实付 |
| 申请一行 n 件 | `paid_share × n / qty`，向下取整；**本行最后一件**吃尾差（= 本行剩余可退额） |
| 可退额上限 | 行：`paid_share − refunded_minor`；子单：`pay_amount − refunded_minor` |
| 运费 | 未发货且本次退完全部剩余行 → 连运费退；已发货 → 仅商家责任原因（DAMAGED / QUALITY / WRONG_ITEM / MISSING）退运费，且只退一次 |
| 不传行（老客户端） | 视为「整单剩余全退」：所有行剩余件数 + 符合条件的运费 |
| 商家核定 / 协商额 | ≤ 申请额；按行比例分回各行（同最大余数法），账本按分回的额记 |
| 抵扣积分 | 按退款额 / 子单实付 比例退回（四舍五入到整分） |
| 赠送积分 | 同比例扣回，不足扣到 0 不追 |
| 券 | 全部子单都 REFUNDED / CANCELLED 才退回（现状保留） |

## 4. 分账按退款金额回退（5.3，本步最大的风险点）

现状 `reverseSplit(subOrderNo)` 是整笔回退。改为：

```text
SettlePort.reverseSplit(subOrderNo, afterSaleNo, amountMinor)
  → 回退金额 = 本次退款中「商家应收」部分（按结算单的商家应收 / 实付 比例折算）
  → 结算单记 reversed_minor 累加；全部退完才标 REVERSED，否则保持 SPLIT（部分回退）
  → 通道调用带金额与回退单号（REV-<售后单号>）
```

| 通道 | 按额回退 | 处理 |
|---|---|---|
| 微信收付通 | 支持（分账回退按金额、多次） | 直接接 |
| 微信直连 | 无二级商户分账 | 不涉及 |
| 支付宝直付通 | 需核对「分账退回」是否支持按额多次 | **上线前查文档**；不支持则该通道部分退款走 §10-3 的兜底 |
| 线下 / 0 元 | 无分账 | 不涉及 |
| 尚未分账（结算前） | 不需回退，冲减待结算额 | 结算单 `pending_refund_minor` 累加，结算时扣 |

> 结算单（`stl_bill`）加列 `reversed_minor`，属支付域迁移（与 V404 同批，单独文件）。

## 5. 退款执行与账本（5.5）

```text
商家同意 / 确认收货 / 确认退款 / 平台裁决 / 买家接受协商
  → 售后单经门进 REFUNDING
  → doRefund：回退分账（按额）→ 原路退（键 = 售后单号）→ 积分按比例 → 退货回补库存（按行件数）
  → 售后单经门进 REFUNDED
  → RefundLedger.apply(售后行)：行 refunded_qty / refunded_minor 累加；子单 refunded_minor 累加；重算 refund_progress
  → FULL → 订单经门 FULLY_REFUNDED（O10）→ 全部子单终态则退券
```

- 账本与状态同事务。账本只在 REFUNDED 落定时记，**不在申请时预占**（防止申请后撤销要回滚）；申请时的可退额校验 = 剩余可退额 − 其他进行中售后的申请额（同一子单同时只允许一张进行中售后，现状保留，所以实际只需减 0）。
- 复用订单服务 2.0 已写好的 `RefundCalc`（行可退数量 / 金额）与 `RefundHandler` 的结构，接线即用；超出单类 200 行 / 方法 50 行的现有代码（`AfterSaleServiceImpl` 1300 行）**不往里加逻辑**，新逻辑落在 `trade/order/service/refund/` 新包。

## 6. 售后写路径经门（5.6）

`TradeStatusWriter` 加 `afterSale(...)`，替换 `AfterSaleServiceImpl` 里约 15 处 `setStatus + update`：申请（创建）、同意、协商、驳回、撤销、寄回、确认收货、确认退款、退款落定、申请介入、裁决、超时关闭。
行为不变（规则已在步 3 由新状态机判），只把写法换成 CAS + 一行流水；手写的 `appendLog` 随之去掉，避免时间线重复。

## 8. 测试与消融

| 关注点 | 测试 | 消融 |
|---|---|---|
| 快照分摊 Σ 相等 | 单测：多行 + 优惠 + 积分 + 运费，Σ paid_share = 实付 − 运费 | 去掉尾差处理 → 红 |
| 部分退不改订单状态 | 场景：3 件退 1 件 → 子单仍 FULFILLING、进度 PARTIAL、可再申请剩 2 件的额 | 恢复「落定即 REFUNDED」→ 红 |
| 第二笔退款真的出钱 | 场景：同子单两张售后 → 支付流水两行、退款单号不同 | 键改回子单号 → 第二笔被吞 → 红 |
| 分账按额回退 | 场景：退 1/3 → 结算单 reversed_minor = 商家应收 × 1/3、状态仍 SPLIT | 换回整笔回退 → 红 |
| 全部退完 | 场景：分两次退完 → 订单 REFUNDED、券退回 | — |
| 售后期 | 场景：完成 8 天后申请非质量 → 20012；质量类 15 天内可 | 去掉守卫 → 红 |
| 回填 | 迁移测试：构造存量行跑 V404，校验 Σ 与 FULL 标记 | — |
| CAS | 售后同意与撤销并发：只一方成功 | — |
