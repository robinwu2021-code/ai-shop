## L1 定位

元器件是一个将来要整个剥离出去的业务。第一步要跑通的闭环：

```
供应商：点「成为供应商」→ 从微信聊天里选库存表 → 预览 → 确认上架 → 定期重传或一键续期
买家：  查料号（库存档位 + 参考价）→ 询价 → 平台报价 → 微信通知 → 接受 → 平台线下成交
平台：  企业微信群收到询价（连同库里谁有货）→ 运营端录入报价 → 买家收到通知
```

**独立到什么程度**：进程、库、部署、企业微信通知都是自己的；**借主系统的只有三样** ——
认令牌、取手机号、发微信订阅消息，全部经主系统的 `/internal/elec/**` 走 HTTP，
元器件服务**一行主系统的表都不读**。将来换成自己的账号体系，只换这三个调用的实现。

## L2 结构

### 2.1 部署形态

```
 小程序 c-app（pkg-elec 分包）──── /elec/c/**  /elec/b/** ──┐
 运营端 ops-web（元器件询价页）── /elec/ops/** ──────────────┤  nginx（www.hxmall.top，同域）
                                                             ▼
                                              ┌──────── elec-svc :8085 ────────┐
                                              │ 库：ai_shop_elec（独占，自带迁移）│
                                              │ 企业微信群机器人：自己发          │
                                              └──────────┬──────────────────────┘
                                                         │ /internal/elec/**（X-Internal-Token，不经 nginx）
                                                         ▼
                                              shop-app :8081（主系统）
                                              ├ 认令牌（会话库）
                                              ├ 取手机号（usr_identity）
                                              └ 发订阅消息 + 站内信
```

| 路径前缀 | 谁调 | 令牌 | 说明 |
|---|---|---|---|
| `/elec/c/**` | 小程序买家 | C 端令牌（`ctk_`），查料号可匿名 | 查料号、批量查、询价 |
| `/elec/b/**` | 小程序供应商 | **同一个 C 端令牌** + 必须是供应商 | 成为供应商、上传、库存、续期 |
| `/elec/ops/**` | 运营端 | 运营令牌（`otk_`）+ 权限码 | 询价列表、录入报价、关单 |
| `/internal/elec/**` | elec-svc → shop-app | 共享密钥 | 不经 nginx，走 127.0.0.1 |

**为什么 B 端也用 C 端令牌**：决定 3（同一个账号）。「是不是供应商」由 elec-svc 自己查 `elc_supplier_member`，
不进令牌 —— 供应商是元器件的概念，主系统不该知道。

### 2.2 代码结构

```
backend/elec/                 聚合 pom（目录分组，照 pay/ 与 job/）
  elec-core/                  领域：实体、Mapper、服务、控制器、迁移 db/elec/V*
  elec-svc/                   可执行：启动类、安全链、主系统客户端、企业微信发送
backend/shop-app/.../portal/internal/InternalElecEndpoint.java   主系统给元器件的三个内部接口
```

**主应用不再引用元器件**：shop-app 的 pom 里没有 elec-core。依赖只有一个方向：elec-svc → 主系统的 HTTP 接口。

### 2.3 三个借用的能力

| 能力 | 主系统接口 | elec-svc 侧 | 失败时 |
|---|---|---|---|
| 认令牌 | `POST /internal/elec/session` `{token}` → `{realm, userNo, nickname, perms}` | 过滤器调它，**结果缓存 60 秒** | 主系统不可用 → 登录态接口 503，查料号照常（匿名可用） |
| 取手机号 | `GET /internal/elec/user/{userNo}` → `{phone}` | 询价、成为供应商时调 | 取不到按「没绑手机号」处理，端上弹手机号闸 |
| 通知买家 | `POST /internal/elec/notify/quoted` | 录入报价后调 | 送不到记 `elc_rfq.buyer_notified_at` 为空，不回滚报价 |

**缓存 60 秒的代价**：用户退出登录后，旧令牌在元器件这边最多还能用 60 秒。
主系统自己的撤销轮询是 5 秒；元器件这边第一步接受 60 秒，因为这里没有资金类动作。

## L3 详情

### 3.1 查询（重点）

采购在搜索框里敲的东西五花八门，查询要对这些输入都给出有用的结果：

| 采购实际输入 | 期望 | 做法 |
|---|---|---|
| `stm32f103-c8 t6` | 找到 STM32F103C8T6 | **规范化**：大写、去空格横杠下划线；保留 `/ . # + ,` |
| `F103C8`、`C8T6` | 只记得中间一截也能找到 | **分段键** `elc_part_key`（见下） |
| `TI TPS5433` | 只要 TI 的 | **拆词**：没有数字、且在别名表里的词当厂牌 |
| `STM32F103C8T6TR` 库里没有 | 别给一片空白 | **近似**：逐字符往回退，最多 4 位，标「相近料号」 |
| 敲到一半 | 下拉提示 | `suggest=true`：只回 8 条、不记需求 |
| 整张 BOM 贴进来 | 逐行告诉库里有没有 | **批量查** `/elec/c/part/lookup`，一行一个，≤ 50 行 |

**分段键**：把规范化料号在「字母 ↔ 数字」交界处切开，每个切点起的后缀存一行：

```
STM32F103C8T6 → STM32F103C8T6 · 32F103C8T6 · F103C8T6 · 103C8T6 · C8T6 · 8T6 · T6
```

中段匹配于是变成对键的**前缀**匹配，走 B-tree。只在交界处切（每个料号 6～10 个键，不是逐字符的 60 个），
百万料号是千万行级，MySQL 单表够用。代价：从一段的中间开始搜（`TM32F`）搜不到 —— 采购记料号是按段记的，
这个取舍可接受；真要任意子串再上 ngram / ES。

**排序**（同一次搜索里）：

1. 命中档：完全一致 → 开头一致 → 中段一致（→ 近似）
2. 有没有货：有货在前
3. 库存档位：1M+ → 100k+ → … → 1+
4. 料号短的在前（`LM358` 在 `LM358DR2G` 前）
5. 字典序

**买家看得到什么**：只读 `elc_part_market` 投影 —— 数量只给档（1k+、10k+），家数只给「1 家 / 多家」，
批号只给年份，价格是加价后的含税参考起价。**查询服务里没有 StockMapper**，在结构上读不到供应商与精确数量。

**过期**：投影行记着「最早一行库存到期的时刻」，读路径先把过期的重算掉（每次最多 200 个），不需要定时任务。

**搜索需求**：每次搜索按「天 × 规范化检索词」计数（`elc_search_daily`），另计没结果、首条有货的次数，
**不记是谁搜的**。「搜了没结果」就是平台该去找的货，也是拉新供应商最有说服力的话术。

**防爬**：游客按 IP 每分钟 60 次、登录用户按人 120 次（`shop.elec.search-per-minute-*`），
超了回 10429。档位化挡住「看到什么」，限流挡住「看多少」。

**接口**

| 方法 | 路径 | 登录 | 返回 |
|---|---|---|---|
| GET | `/elec/c/part?keyword=&suggest=` | 否 | `{keyword, mfrFilter, nearFrom, hits[]}`，hit 带 `match`（EXACT/PREFIX/CONTAINS/NEAR） |
| GET | `/elec/c/part/lookup?text=` | 否 | 每行 `{input, mpn, qty, match(EXACT/AMBIGUOUS/PREFIX/NONE), hit, others}` |
| GET | `/elec/c/part/{partNo}` | 否 | 料号 + 行情 |

**第一步不做**（有意）：参数筛选（参数来源只有上传，质量撑不起）· 国产替代展示（错一条就是质量事故）·
拼写纠错 · 描述全文检索。

### 3.2 供应商（B 端）

| 动作 | 接口 | 规则 |
|---|---|---|
| 我是不是供应商 | `GET /elec/b/supplier` | 不是 → data 为 null（端上显示「成为供应商」） |
| **成为供应商** | `POST /elec/b/supplier`（body 可空） | **一点就成**。唯一前提：绑过手机号（平台要联系他）。公司名等可空，之后在资料里补。企业微信群收到一条 |
| 补资料 | `PUT /elec/b/supplier` | 公司名、类型、城市、联系人、联系电话 |
| 上传库存表 | `POST /elec/b/stock/upload`（multipart） | xlsx / csv（UTF-8 或 GBK）；**认不了 .xls，明说另存为**。只预览，一行库存都不动 |
| 换列映射 | `POST /elec/b/stock/batch/{no}/remap` | 不用再传一次文件 |
| 确认上架 | `POST /elec/b/stock/batch/{no}/apply` | 按**此刻**的库存重算再写；预览 24 小时过期 |
| 我的库存 | `GET /elec/b/stock?filter=ALL/EXPIRING/EXPIRED` | 精确数量与批号只在这里出现 |
| 仍有货 | `POST /elec/b/stock/renew` | 在售的全部续期 30 天 |

上传的细则（已实现、已测）：表头不在第一行也认；型号 / P/N / 料号 / Part No 都认；
**空格子 = 不改**（连同原价的含税口径）；**全量替换**时表里没有的下架，预览先把要下架的列出来；
一行有效的都没有时拒绝确认（否则全量替换会把他的库存全部下架）；超过 2 万行直接拒，不静默截断。

**「定期上传」怎么落地**：库存 30 天不更新就不再给买家看。工作台显示「N 行 7 天内到期」，
一键续期或重传。第一步不主动推提醒（订阅消息一次授权只够一条，续期提醒放 P3 之后）。

### 3.3 询价与结果通知

**状态机**

```
SUBMITTED ──平台录入报价──► QUOTED ──买家接受──► ACCEPTED ──平台线下成交──► CLOSED
    │                         │
    └──平台关单（无货等）──► CLOSED ◄──报价过期── EXPIRED
```

| 动作 | 接口 | 规则 |
|---|---|---|
| 提交询价 | `POST /elec/c/rfq` | **要登录、要绑手机号**。1～50 行，每行料号 + 数量。提交时端上弹订阅授权（报价结果通知） |
| 我的询价 | `GET /elec/c/rfq` · `GET /elec/c/rfq/{no}` | 别人的单是 404 |
| 接受报价 | `POST /elec/c/rfq/{no}/accept` | 只在 QUOTED 且未过期；企业微信群收到「买家接受了」 |
| 运营：列表 | `GET /elec/ops/rfq?status=` | |
| 运营：录入报价 | `POST /elec/ops/rfq/{no}/quote` | 每行：含税单价、可供数量、批次年份、交期、备注；整单有效期。写完**通知买家** |
| 运营：关单 | `POST /elec/ops/rfq/{no}/close` | 原因：无货 / 买家不要了 / 已成交。无货也通知买家 |

**企业微信群消息**（新询价，已实现）：买家联系人与**完整手机号**、每行料号 × 数量、目标价、
**库里谁有货**（公司、电话、数量、批号、价，最多 3 家）、库里没货的标「要找货」。
群就是运营第一步的工作台，所以号码不掩码；超过 12 行只列前 12 行（企微 4096 字节上限）。

**微信通知买家**（P3）：场景 `ELEC_QUOTED`，模板字段：询价单号 · 料号（多行写「STM32F103C8T6 等 3 项」）·
结果（已报价 / 暂无货源）· 提示语。点开落到 `pkg-elec/rfq/index?rfqNo=`。
**一次授权只够一条** —— 提交询价时弹一次授权，正好覆盖这张单的结果通知。
同时写一条站内信：订阅消息是加速通道，站内信是必达的记录。

### 3.4 小程序（P2）

**首页入口**：c-app 首页团购入口行下面加一行（与团购那一行同一个件）：

```
[元器件]  查料号 · 询价 · 成为供应商                                ›
```

由后端开关控制显示（`bootstrapConfig.elecEnabled`）：元器件服务没开的环境不出现这一行。

**分包 `pkg-elec/`**（主包 2MB 限制，元器件整块放分包；独立那天整个搬成另一个小程序）

| 路由 | 页 | 要点 |
|---|---|---|
| `pkg-elec/home/index` | 元器件首页 = 搜索 | 搜索框（300ms 防抖提示）· 最近搜过 · 入口：批量查 / 我的询价 / **成为供应商**（已是供应商显示「供应商工作台」）· 结果列表就在本页 |
| `pkg-elec/part/index` | 料号详情 | 行情三格 · 参考价 · 底栏「询价」 |
| `pkg-elec/lookup/index` | 批量查 | 粘贴框 → 逐行结果 → 勾选有的行 → 一键询价 |
| `pkg-elec/rfq-create/index` | 填询价 | 行可增删改数量 · 发票 · 批次 · 城市 · 备注；提交前手机号闸 + 订阅授权 |
| `pkg-elec/rfqs/index` | 我的询价 | 状态三色 · 报价中写预计时间 |
| `pkg-elec/rfq/index` | 询价详情 | 状态轴 · 平台报价 · 「接受报价」 |
| `pkg-elec/supplier/index` | 供应商工作台 | 在售 / 7 天内到期 / 上次上传 · 上传入口 · 一键续期 · 库存列表三个页签 · 补资料 |
| `pkg-elec/stock-upload/index` | 上传库存 | 从微信聊天选文件 → 预览（新增/更新/下架/未变 + 认不了的行）→ 改列映射 → 确认 |

「成为供应商」在首页点下去：没绑手机号先弹手机号闸（复用 `phone-gate`），绑了就直接调接口，
成功后落到工作台，第一屏就是「上传库存表」。

**接口的端上登记**：c-app 的 `endpoints.ts` / `contract.ts` / `http.ts` / `mocks/elec.ts`、
`packages/shared/src/types/elec.ts`、`gen-openapi.mjs` 两张表。开发代理加 `/elec → localhost:8085`。

### 3.5 运营端（P3）

ops-web 加「元器件询价」一页：列表（状态筛选）+ 详情抽屉（买家、每行料号数量、库里谁有货、录入报价表单、关单）。
权限码两个：`elec:rfq:read`、`elec:rfq:quote`，按运营端的五处登记（权限种子、菜单迁移、perm-map、端点矩阵、生成物）。

### 3.6 库表变化（相对[数据库设计](./design/TDD-元器件-数据库设计.md)）

| 变化 | 原因 |
|---|---|
| 第一步只建 13 张（不建派单、供应商报价、加价规则、成交跟进） | 询价以平台为准，平台直接报价 |
| 加 `elc_part_key` | 中段搜索 |
| 加 `elc_search_daily` | 搜索需求（设计稿里叫 `elc_demand_daily`，这里只记搜索，询价次数从 `elc_rfq_line` 直接数） |
| `elc_supplier.company_name` 可空 | 决定 3：点一下就成为供应商 |
| 手机号明文存 | 与进销存一致，库里没有字段加密工具；独立库只有服务账号能读 |
| `elc_rfq_line` 加报价列、`elc_rfq` 加报价有效期与通知时间（P3，V2 迁移） | 平台报价是询价的一部分，一单一个报价方，不另建 offer 表 |

## L4 边界

### 4.1 需求 → 设计 → 测试

| # | 验收标准 | 落点 | 测试 |
|---|---|---|---|
| AC1 | 游客能按料号查到库存档位与参考价，看不到任何供应商信息 | `ElecPartServiceImpl` · `elc_part_market` | `uploadPreviewApplyThenBuyerSeesBandsOnly` |
| AC2 | 中段、带厂牌、多敲后缀都能查到 | 分段键 · `Query` · 近似 | `containsSearch` · `brandInQueryFilters` · `nearFallback` |
| AC3 | 粘贴多行逐行给出有没有 | `lookup` | `batchLookup` |
