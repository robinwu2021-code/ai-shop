## 业务边界

- 积分是 pay 内的独立业务模块，以门店为业务维度。
- 订单接线默认脱离；停新增保留原占用、返分、退款与资金义务的收尾能力。
- 生产不迁移旧积分余额；旧引擎已退出生产源码，仅在历史测试夹具中保留。
- 补收成功、现金退款明确失败且补收回退成功后，原售后保留待人工处理；运营可重试或关闭。
- 用户已授权完成后部署现有生产环境；代码发布不自动为门店签约或启用接线。

## 源流程与接脱

```mermaid
flowchart TD
  A[门店默认 DETACHED] -->|运营版本化接入| B[ACTIVE]
  B --> C[源事务冻结门店与规则]
  C --> D[pay 预占并确认金额]
  D --> E[原现金支付证据]
  E --> F[源 PAID 与返分事实]
  F --> G[核销或完成事实]
  G --> H[售后窗口及所有资金义务关闭]
  B -->|停新增| I[DRAINING]
  I --> H
  H -->|源与 pay 均证明清偿| A
  E --> J[原号退款准备及净现金意图]
  J -->|未知| J
  J -->|成功并核验| K[积分确认及源提交]
  J -->|明确失败| L[必要补收回退]
  L --> M[原售后 REFUNDING 待人工]
  M -->|关闭| N[源 CLOSED 与绑定 ABORTED]
  M -->|重试| O[关闭原尝试并创建新尝试]
  O --> J
  N --> H
  K --> H
```

恢复队列分别持久保存下单、退款、事件扫描位置，到末尾绕回。业务动作在选取游标事务之外执行；失败保留原号和重试资格。进程在游标提交后崩溃时，该记录在后续绕回再次入选。
