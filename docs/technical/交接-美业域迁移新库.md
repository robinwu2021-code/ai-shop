**代码现状（第 4–6 项）**
- 修订 `ord_appointment_revision`：一次变更一行（草稿 → 在途 → 生效 / 资源拒绝 / 待释放；草稿另有过期、放弃，旧生效版被取代）。生成列 `applying_key` + 唯一键 = 「同一预约只有一个变更在途」。变更号 `change_no` = 预约操作号。修订号按已有最大号 + 1（被拒的保留自己的号）。
- 资源命令 `ord_appointment_command`：一条命令一行（新约的占位、确认各一条），许可只写一次、重放原样答；答宿主的闸门号 = 预约单号、闸门版本 = 这次变更的修订号（宿主只要求非负，已核对）。
- **代码已不读写**：预约准备、当前行、资源围栏、资源意向、资源决策 5 张表（实体、Mapper、数据范围登记、结构校验与部分旧测试还在，待 4-10 删）。

- **与设计的出入**：确认失败后本该进「待释放」并一直占着闸门；现保持原行为（放开闸门），因为待释放要靠用户发起取消来释放，闸门占着会挡住取消。随 4-7 定。
