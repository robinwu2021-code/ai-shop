# 零售域：旧表 → 新表 → 子模块 → 状态

状态：勘查稿（2026-11-26）。上一层：[TDD-零售域对齐门店交易库](TDD-零售域对齐门店交易库.md)。

依据：设计方案 `库/05-门店交易库.md`、`库/06-行业库.md` 的「原表 / 并入了哪些旧表」两列；代码引用按表名在 `backend/`、`backend-plugins/` 的 `src/main` 里匹配（文件数，取前三个模块）；状态由五份分区勘查给出（会话笔记 `retail-survey-A…E`）。动态拼表名、纯 JDBC 无表名常量的地方匹配不到。

状态的含义：

- **切（先修 DDL）**：新库有同一张表（原表），列基本对得上；切之前必须先补回被降级的唯一约束、编号长度、状态长度（见 TDD §2.6）。
- **先并再切**：并进别的新表；要先在现有库里把代码改成新表的形状（多张合一、行转列），再切。
- **先留原表**：新库没有对应，或并入后缺列太多、要设计先定；切库后仍在主库，和交易库之间各自提交。
- **不再需要**：主代码零引用；迁数据时把取值写进并入的目标表。
- **留行业库 / 待定**：属于 `n_industry`，不在交易模块；待定的要设计方定。
