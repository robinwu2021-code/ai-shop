## §1 指标口径及可复算样本

以下样本选门店 S1、时区 Asia/Taipei、本地午夜日切、2026-11-21 至 27 日（含），查询截止为 28 日 00:00。交易按支付完成时间归日，统计截至查询截止时成功的退款。跨日退回原成交日重算。交易粒度取同一商家、门店内的子订单，活动版本可追溯；同一活动在同一子订单命中多行只计一单。金额按币种独立，以最小货币单位计算；收款基数取优惠后商品实收，剔除运费、服务费与已退商品实收。样本无运费、服务费和税额另计的情况。零售成交行按原成交含税价格计算；不另加税额。

## §2 实施与来源

| 接入点 | 成交依据 |
|---|---|
| 建单 | Android 在线现金、门店收款码和付款链接传入 `activityFactsVersion=1`，每项活动单独传 `adjustments[{kind:ACTIVITY,activityNo,amountMinor}]`。其余整单折扣、券与积分保留为 DISCOUNT。优惠和建单在同一事务提交，服务端拒绝的活动报价不进入在线收款。 |
| 旧模型活动 | 锁定本主体、该门店适用的活动，按实际行、商品范围、受众、排期及剩余额度核算金额。特价及买赠按命中行，满减及组合按符合条件的商品行分配。保存用量与预算、核销号、规则参数快照和 SHA-256 版本标识。 |
| 发布版本活动 | 固定金额 CUT 复用发布版本、受众、总额及个人限额检查，以 POS 实际币种核算。此类活动有个人限额，匿名客不能占用。建单后规则换版仍按建单锁定的版本追溯。 |
| 原行与实付 | V715 的 `ord_pos_activity_line` 用租户、核销号与原行保存折抵，另有同一活动、子单和原行的唯一约束。同单按活动号顺序锁定，再先处理单品优惠，后对剩余可参与行处理至多一项整单优惠。先分配活动折抵，再以余下行金额分配商品实收；商品范围外的其他行对参加单的整单实收仍有贡献。 |
| 会员 | 从当前主体、授权门店有来源或往来的 ACTIVE 会员解析账号。待付订单保存会员号，在线收款达到应收时再次确认并写入 `ord_order.pos_member_at_payment`；此后会员变更不影响既有成交。 |
| 退款 | 截至窗口结束前，按原行关联成功的现金类售后和行核定退款金额。活动原分摊依累计退件数按比例冲回，最后一件收齐尾差。现有单笔现金整退只读同一门店子单的 REFUND 审计事件。售后号与行的唯一键、整退幂等回执防止重投放大。 |
| 范围与时区 | `GET /biz/activities/{activityNo}/effect?storeNo=…&from=YYYY-MM-DD&through=YYYY-MM-DD&zone=…`。仅商家 CAMPAIGN 权限且限所选授权门店，越权返回 NOT_FOUND。手持取门店市场时区，区间按开始日至截止日的下一天本地零点。金额为该币种最小单位，百分比为 0–100 数值。 |
| 来源覆盖 | 各币种从首次具备新协议付清事实的营业日起展示。出现未留存支付时会员标识的旧 POS 成交，则当日和包含它的汇总显示资料不足。旧版与离线补传只含总优惠时不能归因，尚无数据的门店不宣称具备生产覆盖起点。 |

本接口的交易范围是门店零售 POS。既有订单与 Pay 事件仍走 `/biz/marketing-summary`。现金全退沿用已实现的原收款资格与权限。五指标可读取已成功、逐行的售后，退款操作仍受原支付渠道能力限制。
