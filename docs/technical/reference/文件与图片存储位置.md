# 文件与图片存储位置

核对日期：2026-11-13。实现方案见 [本地存储根路径与多云切换](../TDD-本地存储根路径与多云切换.md)。

## 1. 根路径

推荐宿主机：`/data0/app/ai-shop/storage`。容器挂载：`/data/storage`。设置`SHOP_STORAGE_ROOT=/data/storage`；默认`./data`保留现有开发目录。已有`SHOP_UPLOAD_DIR`或打印单独root覆盖时继续优先，不自动改到新目录。

```text
/data0/app/ai-shop/storage/                 # 宿主机
├── uploads/                              # 媒体桶根，下面是原object key
│   └── {entityNo}/
│       ├── {storeNo}/goods/{yyyyMM}/{uuid}.{ext}
│       ├── _ENTITY/{privateType}/{yyyyMM}/{uuid}.{ext}
│       ├── {storeNo}/{privateType}/{yyyyMM}/{uuid}.{ext}
│       └── _REPORT/reports/{exportNo}/{file}.csv
└── print-private/                        # 与打印COS的print-private前缀一致
    └── {existingPrintObjectKey}.pdf
```

`_ENTITY`表示主体级，不猜测默认门店。保留旧`{merchantNo}/{uuid}.{ext}`文件，不因调整根路径改key。业务用途段以生产者实际生成值为准，例如`goods`、`qual`、`aftersale`、付款凭证、`reports`。

## 2. 文件分类和权威位置

| 文件类型 | 本地/云落点与入口 | 读取规则 |
|---|---|---|
| 商品图、展示图 | MediaStore；本地`<root>/uploads/<key>`；COS`<media-bucket>/<key>` | goods公开，公共URL不包含物理路径 |
| 主体证件、资质及售后图 | 相同MediaStore，按entity/store/private用途分目录 | 稳定引用入库，读取时短时签名 |
| 线下付款、套餐证据 | 现有媒体owner及对应bizType；不另建重复文件库 | 原归属和签名规则；留存/回收按原业务规则 |
| 报表导出CSV | MediaReportArtifactStore→MediaStore；`entity/_REPORT/reports/exportNo/file.csv` | 私有服务端流或短时签名，不走公共商品图 |
| 打印PDF | PrintArtifactStorePort；本地`<root>/print-private/<key>`；COS打印桶`print-private/<key>` | 独立私有签名下载，原哈希与不可变语义 |
| near-pay进件附件 | `pay_onboarding_file.encrypted_content`＋Vault文件密钥 | AES-GCM，商户/申请归属、有效期和pin校验 |
| near-pay认领凭证 | `pay_channel_account_claim_file.encrypted_content`＋Vault密钥 | 私有加密读取，不公开原件 |
| 会话、服务配置和日志 | 原会话/配置/日志目录 | 不是业务对象文件，不纳入媒体根或云桶 |

主要源码：`shop-channel/channel/media/LocalDiskMediaStore`、`CosMediaStore`、`api/MediaReadController`；`shop-app/config/UploadResourceConfig`；`shop-store-mybatis/media/MediaBackfillService`；`print-channel/port/storage/PrivateLocalArtifactStore`；`shop-app/reportbridge/service/impl/MediaReportArtifactStore`。独立near-pay位于其自身仓库的OnboardingFileStore、ChannelAccountClaimFiles。

## 3. 配置和优先级

| 配置 | 作用 | 缺省 |
|---|---|---|
| `SHOP_STORAGE_ROOT` / `shop.storage.root` | 本地统一存储根 | `./data` |
| `SHOP_MEDIA_PROVIDER` / `shop.media.provider` | 普通媒体实现 | `local`；已实现`local / cos` |
| `SHOP_UPLOAD_DIR` / `shop.upload.dir` | 媒体单独根覆盖 | `<storage-root>/uploads` |
| `SHOP_MEDIA_SIGN_SECRET` | 本地私有签名密钥 | 生产需持久私有配置，API与OPS一致 |
| `shop.print.artifacts.provider` | 打印存储实现 | `local`，也支持`cos` |
| `shop.print.artifacts.root` | 打印单独根覆盖 | `<storage-root>/print-private` |
| `shop.print.artifacts.signing-key` | 打印签名密钥 | 沿现有私有配置 |
| `COS_BUCKET`、`COS_REGION`、`COS_SECRET_ID`、`COS_SECRET_KEY` | 媒体COS桶与认证 | provider=cos时沿原必填规则 |
| `COS_DOMAIN`、`COS_PRIVATE_BASE_URL` | COS公共出口及私有签名出口 | 沿原配置 |
| `shop.print.artifacts.cos.bucket` | 私有打印COS桶 | 打印cos模式必填 |

只选provider，不在云故障时自动改写本地。所有服务实例需挂载同一持久目录并使用一致签名配置；不能把文件写进容器可写层后当成持久存储。

## 4. 多云对齐

| 项目 | 本地 | 腾讯COS | Google Cloud Storage |
|---|---|---|---|
| 状态 | 已有实现，本批完善 | 已有实现 | 下一适配器，尚未实现 |
| 普通媒体key | `<uploads-root>/<key>` | `<bucket>/<key>` | 规划`<bucket>/<key>`，同一key |
| 公共图 | 应用公共读取，限定goods | 现有公共出口/ACL | 规划独立公共桶与独立私有桶 |
| 私有图/文件 | 应用HMAC短时签名 | COS短时签名/私有ACL | 规划GCS V4签名；私有桶不公开 |
| 凭据 | 本地目录权限及签名密钥 | 原私有凭据 | 规划ADC/服务账号或Workload Identity |
| 切换 | 配置并重启 | 配置并重启 | 实现并验收后开放，当前不可选 |

Google实施时复用MediaStore的put/exists/delete/openPrivate/URL方法；先保证私有材料不会因公共图IAM而被公开，再处理缩略图、CDN和原域名兼容。只保留接入规划，不提供会悄悄落回local的假GCS配置。

## 5. 切换步骤

1. 确认当前provider、媒体与打印的实际根、桶和挂载；不要仅根据YAML默认值推断线上配置。
2. 创建新持久根并配置服务账户权限；复制原文件，保留相对key，不改业务表和asset_key。
3. 核对对象数量、字节/哈希及抽样公开图、证件、付款凭证、CSV和打印PDF。
4. 设置provider及root/凭据；若要用统一根，明确处理原单独覆盖项，随后重启相关服务。
5. 验证上传、回读、过期/篡改签名拒绝、原链接及扫描回收识别，再逐步完成历史URL/域名迁移。

配置切换不等于自动迁移。私有稳定路径不等于公开URL，不把带有效期的签名地址存进业务表。旧根与旧云桶在验收前保留；本批不执行删桶、搬迁、历史URL改写或生产配置切换。

Google接入依据：[签名URL](https://docs.cloud.google.com/storage/docs/access-control/signed-urls)、[统一桶级访问](https://docs.cloud.google.com/storage/docs/uniform-bucket-level-access)。启用统一桶级访问后使用IAM而非对象ACL，不能直接照搬COS的逐对象PublicRead实现。

### 6.1 Google下一阶段拟定配置（尚不生效）

- `shop.media.provider=gcs`：仅在适配器交付后允许选择。
- `shop.gcs.project-id`、`shop.gcs.public-bucket`、`shop.gcs.private-bucket`、`shop.gcs.public-base-url`：拟定配置名，本批没有绑定或启用这些配置。
- 优先ADC/Workload Identity；本地开发可通过仓库外的`GOOGLE_APPLICATION_CREDENTIALS`提供服务账号凭据；生成V4签名还需要明确的签名能力与对象读取授权。
- 必须验证GCS默认URL中的bucket路径/公共域名可以反解回原key；扩展MediaKeyRoundTripTest和可信来源解析，不能把桶名误算入key导致误回收。
- `MediaReferenceQueryPortImpl`现有历史域名别名来自COS配置；GCS接线时需补齐提供方无关的可信出口及历史别名，不能接受任意来源URL。
- 本地路径、云key和历史业务URL分别验收；云桶公私隔离、过期/篡改签名、复制后的字节校验均通过后才开放切换。
