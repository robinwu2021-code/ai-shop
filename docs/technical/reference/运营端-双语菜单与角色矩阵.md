## 1. 命名和目录原则

中文菜单不超过四字；英文优先一至两词。菜单只表示功能，状态用页内筛选，新增、修改、提交等动作放在按钮中。按2026-11-13用户最新要求，目标目录改为一级模块、二级业务分组、三级功能入口；现有侧栏实现尚未随本次文档调整。完整树见[完整三级菜单](./运营端-完整三级菜单-2026-11-13.md)。

“商户商城”统一改为**经营服务 / Business Services**，包括平台向经营方销售的套餐、软件、硬件与服务。服务业经营使用**服务管理 / Services**，包含经营方向消费者提供的项目、预约和履约。两者的商品、订单和权益分别管理。

“基础资料”的商品分类用于经营商品；“经营服务”的商品分类用于平台服务商品。经营主体、门店、品牌连锁各自维护经营主档；商户专指独立支付域的平台商户，不再使用“商户中心”容纳全部经营对象。

### 1.1 八项核心对象补充规范（2026-11-13）

最新源码review、差距和优先级见[八项核心菜单规范review](./运营端-八项核心菜单规范-review-2026-11-13.md)。该review是后续调整建议，不表示已更改菜单、授权或部署。

- 账号：注册账号、运营员工、会员、人档、支付成员分别命名和鉴权；全量注册账号不从已有经营主体/门店反推。
- 经营与商户：经营主体、经营门店、品牌连锁属于经营域；平台商户属于支付域，各对象按真实关联展示；店招审核不是门店总览，链条画像不是连锁管理。
- 渠道与进件：支付渠道/渠道进件归near-pay；履约方式、消息通道各归原业务；平台入驻与支付进件分别审核。ai-shop现有支付进件页已接独立near-pay摘要，保留来源跳转，不重复维护私有材料与渠道审核状态。
- 订单与支付：经营订单、平台服务购买订单、支付订单分别命名和归属；套餐核款不等于门店向顾客收款，旧嵌入支付入口明确兼容身份。
- 商品：门店经营商品、平台服务商品、支付产品三类分开；餐饮/零售/服务业按真实能力与数据范围组织，不复制无权威数据的菜单。
- 每个标准入口有唯一href/point_code及权威系统；关联入口用详情链接。一级默认进入有权访问的核心列表，审核专岗可落到对应队列。
- 菜单读权限与办理/审核/配置动作权限分别核对；建议角色矩阵不自动授权。目录归组不能替代后端权限和数据范围。

## 6. 授权及业务边界

- 角色与数据范围分开；行业、市场、区域、主体、门店限制必须由后端落实。
- 同一人发起的入驻、核款、退款和敏感变更不能自行审核。
- 系统配置角色不默认获得业务和资金权限；需要兼任时正式授权。
- 两端分别授权；ai-shop授权不自动赋予支付私有材料、资金或结算权限。
- 导出、敏感原件及批量操作单独授权，不随查看权限开放。
- 菜单、API和数据范围一致校验；隐藏菜单不能代替后端鉴权。
- 全部注册账号、经营主体/门店、品牌连锁、行业业务订单、套餐软件权益归ai-shop。
- 渠道进件、私有材料、收款绑定、支付订单、资金流水和渠道清结算事实归near-pay。
- 经营财务归ai-shop，渠道资金事实归near-pay；台湾资金直达商户时不得凭菜单虚构平台余额。
