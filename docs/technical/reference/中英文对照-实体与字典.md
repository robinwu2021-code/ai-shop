## 二、字典 / 取值域

同一件事在这个仓库里有三种写法，三处都要在清单里，否则「这一列能存什么」永远只答对三分之一：

| 来源 | 写法 | 数量 |
|---|---|---|
| 后端字符串常量组 | `public static final String X = "X"` | 145 组 / 814 个取值 |
| 后端 Java enum | `enum X { A, B }` | 15 个 |
| 端上类型 | `type X = "A" \| "B"` 与 `as const` | 179 个 |

**这一节只看得见具名声明。** 裸字面量的取值域（散在 `case` / `Set.of` 里的大写串）
一个都不在上面的数里 —— 它们没有声明处，也就没有名字可登记。
这不是疏漏而是判据的边界：扩到「同一文件里几个大写字面量」会把噪声一起收进来，
而一份混着噪声的清单没人敢信。**这一类只能靠各自的守卫盯**，
例如触达场景码由 `NotifyScene` 收编后，`SceneChannelSeedTest` 两向守着它与种子行。

后端以字符串常量为主是有意的（见 `InvEnums` 的类注释）：库里存的就是这些串，
中间隔一层 enum 的话，反序列化失败报的是「没有这个枚举常量」，
而真正的问题是**库里出现了没人认识的值**。

### 2.3 端上取值域（179）

`登记` 一列取自 `packages/shared/src/contract/enum-registry.ts` ——
端上每个**具名枚举**都必须在那张表里有一条（G1 守卫）。三种取值：

- 登记表里的 `verdict`（`OK` / `MERGE` / `PLANNED` …）
- **未登记** —— 够 G1 判据却不在表里，这一档应当恒为 0
- `不适用` —— 够不上「具名枚举」：单取值，或取值不是大写 token
