## 2. 【L1】`backend/shop-kernel/` — 库项目

一个聚合 pom + 9 个模块，**产出 9 个独立 jar**。
L2 依赖的是**其中具体模块**，不是整个 kernel——否则 `portal-c` 会把六个域全背上，
那正是今天 `shop-core` 的病。

| 模块 | 文件 | 职责 | 拥有的表 |
|---|---|---|---|
| `shop-base` | 78 | 横切地基：`Realm`/`TokenStore`/`LoginUser`/`Perms`/`PasswordHasher`、幂等、Outbox 写入侧、异常与错误码。**零业务依赖，谁都能依赖** | 2 |
| `shop-spi` | — | 跨域契约：Port 接口。域↔域只经它，单体内本地调用、拆服务后换 RPC，**调用方一行不改** | 0 |
| `shop-channel` | 10 | 外部通道适配器（支付/短信/存储）。**只装适配器，不装业务判断** | 0 |
| `shop-domain-trade` | 35 | 购物车、下单拆单、订单、售后、状态机 | 6 |
| `shop-domain-product` | 38 | 商品、SKU、类目、库存与锁定、门店商品、**评价** | 11 |

## 4. 依赖规则（六条，ArchUnit 落地）

1. `portal-*` → 域模块，只经 Service 接口；**portal 之间互不依赖**
2. 域 ↔ 域只经 `shop-spi` 的 Port
3. `shop-jobs` → 域模块；**不依赖任何 portal**
4. 启动模块只有 pom 与装配；**域模块反向不得依赖 portal / jobs / 启动**
5. `@RestController` 只在 `shop-portal-*`；`@Scheduled` 只在 `shop-jobs`
6. `SecurityFilterChain` 只在 `shop-portal-*`，且**一个 portal 一条链**
   ——三端认证独立的守卫：装配了谁才有谁的链

> 第 4 条在项目层还有一道更硬的保险：kernel 与 service 是**两个项目**，
> L1 反向依赖 L2 编译期就过不去，不依赖有人记得写守卫。

**两处归属看着别扭但符合代码现状，记下来免得被"纠正"**：

- `rvw_*`（评价）在 **product** 而非 mkt：评价挂在商品上，实体也住在 `product` 包
- `mch_entity_apply`（入驻申请）在 **platform** 而非 merchant：申请发生在**成为商家之前**，
  与审核/权限同侧；`mch_entity`（已成为商家）才在 merchant

**跨模块读怎么办**：45% 的表被两端以上使用（见方案 §2.3），但**跨的是端不是模块**——
三个 portal 依赖同一个域模块即可。域↔域的跨模块读走 `shop-spi` 的 Port，不直连别人的表。

## 6. 迁移时要顺手清掉的

**`shop-svc-fulfillment/`（仓库根目录）**——6 个文件，**与 `backend/shop-core/fulfillment/`
逐个同名重复**，没有 pom、不属任何模块、不参与构建，是首次提交留下的孤儿目录。

留着的害处不是占空间，是**误导**：迁移时看到它会以为履约已经拆成服务了。
`ful_*` 三张表的 owner 是 `shop-merchant`（§5），这个目录**直接删**。

## 7. 现况对照（避免把目标态当成现况）

| | 现况 | 目标态 |
|---|---|---|
| 后端项目数 | **1**（`backend/` = `shop-parent`） | 2（一期）→ 5（二期） |
| 后端模块数 | **6**：`base` `core`(250 文件/9 域) `merchant` `settle` `channel` `app` | 16 |
| 部署单元 | **3 个进程**（同一 jar 的 `api`/`ops`/`worker` profile） | 一期 2 产物 → 二期 5 |
| 认证 realm | **2**（`ctk_` 被 C/B 共用） | 3（`ctk_`/`btk_`/`otk_`） |
| Outbox 投递 | ❌ **无人调用**（只有测试调） | `shop-jobs` 里的定时任务 |
| Controller 位置 | 各域 `api/{mp,biz,ops}` 子包内 | `shop-portal-*` |
| 数据库 | 一个 `ai_shop` | 一个（S4 前不拆） |

现况里唯一已经对齐目标的是**三进程部署**与**Controller 已按端分子包**——
后者正是这次迁移能以 `git mv` 为主的原因。
