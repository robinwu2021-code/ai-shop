# 运行时环境变量与地区配置清单

日期：2026-11-13。依据：用户要求同一制品复制到多个国家/地区；技术开关放运行时环境变量；地区业务参数只保留默认地区在环境变量，其余由系统配置决定，启动后按当前地区选择默认语言、币种、最小货币单位和支付小数规则。

状态：配置归属与实施清单；已生效项和待实现项分开标注。本批已实现统一本地存储根，现有local/COS开关继续有效；完整地区启动配置尚未全部实现。

## 1. 唯一配置归属

| 类别 | 保存位置 | 内容 | 生效时机 |
|---|---|---|---|
| 技术部署 | 环境变量/私有密钥配置 | 服务端口、数据库、内部地址、存储provider/root、密钥、技术模块装配开关 | 实例启动；改后重启，不重新打包 |
| 默认地区 | 环境变量`SHOP_DEFAULT_MARKET` | 当前实例默认market；地区业务信息仅这一项放环境变量 | 启动选择系统配置记录 |
| 地区业务资料 | 系统配置/主数据 | 默认语言、支持语言、币种、小数位、时区、展示格式、现金步长 | 发布配置后，新上下文采用新版本 |
| 支付产品能力 | 独立near-pay系统配置 | 渠道/产品/币种金额精度、限额、可用地区和启停 | 选择支付产品时校验 |
| 历史业务事实 | 单据及交易快照 | 实际market、currency、scale、支付产品与规则版本 | 创建/确认时冻结，不随当前配置变化 |

“环境变量只放默认地区”指地区业务参数，不是删除数据库、存储和安全密钥等必需部署参数。存储选择等技术开关在环境变量；经营品类、渠道启停、业务灰度等原运营配置仍由其现有系统配置管理，不因为统一本地存储而全部搬进环境变量。

不新增`DEFAULT_LANGUAGE`、`DEFAULT_CURRENCY`、`CURRENCY_SCALE`、`ALLOW_DECIMAL_PAYMENT`等地区环境变量。也不把运行时地区、语言和币种放进`NEXT_PUBLIC_*`构建变量。

## 2. 环境变量清单

| 变量 | 作用 | 当前实现 |
|---|---|---|
| `SHOP_DEFAULT_MARKET` | ai-shop/near-pay共用的默认地区码，例如CN/TW/AE | ai-shop已有；near-pay本批增加同名入口 |
| `SHOP_MEDIA_PROVIDER` | 普通媒体`local / cos`显式切换 | 已实现；GCS尚未开放 |
| `SHOP_STORAGE_ROOT` | 统一本地根，推荐容器`/data/storage` | 本批实现；缺省`./data`兼容旧目录 |
| `SHOP_UPLOAD_DIR` | 已有媒体单独目录覆盖 | 兼容原部署；不推荐新部署重复设置 |
| `SHOP_MEDIA_SIGN_SECRET` | 本地私有文件签名 | 已有；API/OPS应一致，私有保存 |
| `SHOP_PRINT_ARTIFACTS_PROVIDER` | 打印制品`local / cos` | 已有，与普通媒体分别配置 |
| `SHOP_PRINT_ARTIFACTS_ROOT` | 打印目录单独覆盖 | 已有；不设置时继承统一root下print-private |
| `SHOP_PRINT_ARTIFACTS_SIGNING_KEY` | 打印私有下载签名密钥 | 已有，私有保存 |
| `COS_*` | 腾讯云认证、桶、出口 | 已有；不是地区语言/货币配置 |
| 数据库/端口/服务地址/认证密钥等 | 基础设施连接及运行身份 | 保留现有变量，不重复列密钥值 |

技术开关不是所有币种的小数规则：不得配置一个全局布尔开关后假设全部渠道均相同。

### 2.1 默认地区兼容

- ai-shop仍绑定`shop.merchant.default-market`，由`SHOP_DEFAULT_MARKET`注入，不另建同义默认地区变量。
- near-pay仍绑定`near-pay.instance.region`；YAML缺省链为`SHOP_DEFAULT_MARKET` → `NEARPAY_INSTANCE_REGION` → `NEAR_PAY_INSTANCE_REGION` → TW。Spring直接属性覆盖仍遵循原优先级；例如旧`NEAR_PAY_INSTANCE_REGION`可直接映射该属性而盖过YAML。
- 已在near-pay现有启动检查中增加一致性校验：配置了`SHOP_DEFAULT_MARKET`但最终解析地区不一致时拒绝启动，要求清理旧覆盖。该保护沿用`near-pay.instance.startup-check`（默认true）；正式部署须保持启用，关闭检查的受控测试不具备此保护。
- 新部署只设置`SHOP_DEFAULT_MARKET`；旧别名只为已有环境兼容，迁移后从环境移除。
- 现有代码未配时，ai-shop保持CN、near-pay保持TW，避免改变已有部署。正式的新部署应明确提供同一个默认地区，不能依赖两端不同的历史缺省值。
- `SHOP_REGISTRATION_MARKETS`、`NEARPAY_TEST_MARKETS`等现有特殊测试范围不是生产地区参数的新入口；后续对齐系统配置时需要单独迁移，不能未经审核扩大经营地区。

### 2.2 现有地区变量的迁移清单

| 现有配置 | 目标归属 | 本批状态 |
|---|---|---|
| `SHOP_REGISTRATION_MARKETS` | 系统中开放注册地区清单，受sys_market启用状态约束 | 已识别，待迁移；不直接删除旧变量改变注册范围 |
| `SHOP_GEO_PROVIDER_BY_MARKET` | 地区对应地图提供方的系统配置 | 已识别，待迁移；地图服务密钥仍私有环境配置 |
| `NEARPAY_INSTANCE_REGION`、`NEAR_PAY_INSTANCE_REGION` | 统一为`SHOP_DEFAULT_MARKET` | 本批保留旧别名兼容，新部署只使用统一项 |
| `NEARPAY_TEST_MARKETS`及旧别名 | 受控共享测试实例配置，生产不扩大范围 | 已识别，待正式配置迁移；不自动修改现有授权 |
| `NEXT_PUBLIC_OPERATING_REGION` | 生产通过settings/运行快照取地区 | HTTP模式已读settings；仅保留原型用途，不作为生产真源 |
| `NEXT_PUBLIC_OPENED_STAGES` | 系统实例开放阶段配置 | HTTP已有settings来源；后续核对全端使用点 |

`COS_REGION`是云资源机房区域，既不是经营market，也不决定语言或币种，继续作为基础设施环境参数。

## 3. 系统地区配置清单

下面DTO名称为目标字段；表中标出已存在的权威来源。不得为了启动下发再复制一份币种账本。

| 字段 | 含义 | 权威来源/现状 |
|---|---|---|
| `market` | 当前地区码 | `sys_market.market`；默认选择来自环境变量 |
| `enabled` | 当前地区是否开放 | `sys_market.enabled` |
| `defaultLocale` | 地区默认语言，BCP47标签 | 待补按地区语言配置；现有appearance.fallbackLang只有全局值，不等价 |
| `supportedLocales` | 已发布可用语言及用户可选范围 | 待补系统配置及端上语言包校验 |
| `currency` | 记账币种 | `sys_market.currency` |
| `currencyScale` | 主币单位到记账最小单位的小数位 | `sys_market.currency_scale` |
| `minorUnitFactor` | 一主币单位对应多少最小单位 | 根据scale计算`10^scale`，不重复存字段 |
| `currencySymbol`/`displayDigits` | 显示符号和展示小数策略 | 系统展示配置；不能改记账换算 |
| `timeZone` | 账期/业务日期的IANA时区 | `sys_market.time_zone` |
| `cashStepMinor` | 现金收款最小步长，以minor计 | 待系统配置化；现有CashStepPolicy仍含TWD规则，不宣称已完成 |
| `configVersion` | 配置发布版本 | 复用/补齐原配置版本，供客户端与单据追溯 |

语言优先级：用户明确选择且仍被支持的语言 → 地区默认语言 → 系统配置的支持语言回退。不能把第一次初始化时自动保存的中文，当成用户明确选择而永远盖过地区默认值。

已有单据不可因修改地区配置被重新解释；产生交易后的币种和scale不得当普通运营字段随意修改，沿现有MarketService限制及正式账本迁移方案处理。

## 4. 支付小数规则

**记账精度、展示精度、现金步长、支付产品精度是四个不同事实。**

| 字段 | 现有来源 | 用途 |
|---|---|---|
| `currencyScale` | sys_market | 金额minor整数与主币单位转换 |
| `amountScale` | pay_product_currency_limit.amount_scale | 某渠道产品/币种接受到几位小数 |
| `singleMinMinor`/`singleMaxMinor` | 支付产品币种限额 | 单笔最小/最大金额 |
| `paymentStepMinor` | 由currencyScale和amountScale计算 | 若产品精度更粗，则`10^(currencyScale-amountScale)`，否则1 |
| `supportsFractionalPayment` | 由币种与所选产品精度计算 | 展示能力摘要，不作为独立可写布尔配置 |

金额内部及接口仍使用精确minor整数；主币文本转换需要十进制定点规则，不能依靠float或静默四舍五入。

当前代码的TW示例：市场记账scale=2，某产品amountScale=0，则paymentStepMinor=100。`100` minor可付，`150` minor不满足整元步长，必须明确拒绝或由既有业务报价规则重新确定金额，不能悄悄截成100。不能因此把TWD账本scale改为0。这里是现有数据/代码口径示例，不是对所有台湾渠道的统一断言。

支付规则按市场＋币种＋渠道＋产品＋支付方式/场景选择；不能只按国家返回一个“支持小数”后套到所有产品。退款、订单重试和补单使用原交易已冻结的币种/产品规则，不套新默认地区。

## 5. 启动和客户端流程（目标）

1. 同一后端JAR、同一前端静态制品复制到不同实例；运行时读取`SHOP_DEFAULT_MARKET`及基础设施变量。
2. 连接系统配置，校验默认地区存在、启用，读出币种、scale、时区及地区语言配置；缺失不能悄悄回退为CN/CNY/2位。
3. 在地区业务开放前检查语言包、支付产品精度、限额、存储和当前实例范围；生成统一运行配置快照及版本，不写死地区map。
4. 登录前页面通过同源运行配置接口取得地区默认语言；登录后按账号/门店上下文显示其实际地区与币种。默认地区不能改写已有账号、门店或交易的地区。
5. 前端拿到scale和产品能力后展示金额、控制输入；后端始终复核相同事实。浏览器Intl可以格式化，但不能代替账本scale或渠道精度来源。
6. 用户主动切语言不改变支付币种、账号所属地区、资金隔离或已创建交易。

运行配置下发接口尚待设计/实现，应与现有common/master-data、store-setup、near-pay settings分工：只返回必要公开配置，不返回存储根、云凭据、密钥、私有桶地址或内部服务地址。未完成该接口前，不能声称所有客户端都已支持一个包按地区自动初始化。
