# ADR-040 共用业务人员与账号权限分离

- 状态：沿既有多行业方案实施，SHR-01a基础数据/事实查询；其余切片待实施
- 日期：2026-10-21
- 需求：[美业功能矩阵 C](../../requirements/美业系统-多端功能矩阵.md#c-人员与权限)
- 设计与执行：[美业后端计划 §11](../TDD-美业系统-后端开发计划.md#11-shr-01a共用人员基础数据与批量事实查询)

既有mch_account是主体登录成员，mch_store_role是操作授权；它们不能表达没有登录账号的服务人员、有效任职和项目资格。
按已确定的多行业架构，人员主档、任职/岗位/技能归shop-merchant，由零售、餐饮、美业共用；账号可选关联，不按手机号自动合并人员。
不把岗位当权限，不将旧门店总名额slot作为STAFF资源占用，也不复制身份/交易/资产到行业包。

先交付5表及明确人员名单的批量事实查询；排班引用resourceNo，必须等待规范资源身份后落地，随后实施组合占用仲裁。
对重叠任职和过大事实集拒绝读取；代价是脏数据会明确失败，需要后续维护业务修复，不静默任选或丢失事实。
只读事实查询不构成资格许可、排班承诺或资源预留；账号绑定和任职写入仍须后续业务层锁/审计/权限与冲突处理。
