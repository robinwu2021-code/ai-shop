# ADR-057 补货来源统一认领与零售库存写入互斥

> 状态：实施决策（2026-11-11）；依据用户批准的I04-D2-01/02及统一幂等规范。

## 一、决策

补货来源身份由ai-shop主库商品库存域统一持有，FOOD和零售共用源系统/业主/单号/行号唯一约束。沿现有系统签名传输认领声明，实际数量仍归原执行器。零售与旧商城库存回写通过同主体数据库行锁互斥，不增加第三套余额。

## 二、理由与替代方案

FOOD独立部署的本地唯一键不能阻止主库零售再次认领。把三行业各自建相同唯一表不能解决跨库重复；本批也不将商城业务交接语义下沉到独立进销存服务。因此在已有ai-shop商家业务入口持久认领，由可信宿主签名向FOOD证明准入。

主库认领与FOOD执行是可恢复的两阶段业务事实，不承诺分布式原子提交。失败保留原绑定，不自动释放给另一行业。复用FOOD旧原件查询和现有请求恢复，不增加通用Outbox或重试平台。

## 三、约束

旧FOOD原件先核对；组件不可用不等于无历史。旧内部HTTP注册不能继续创建陌生原件；部署须先收口该路径再升级宿主，不允许混合未接主库的旧写入方启用零售；旧嵌入式FOOD宿主及未接实体围栏的StockSync节点也须升级/停止并排空在途写入。内部声明依赖现有可信宿主凭据，只能由已持久认领的宿主路径产生。

零售接管后关闭连接不恢复旧writer；未经原件/未知请求/余额处理不得切回。实体锁先于原件及余额锁，商品内继续商品→SKU→门店库存。实际收货、App和营业准出不在本决策实施批范围。
