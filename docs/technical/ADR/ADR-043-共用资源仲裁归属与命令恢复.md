# ADR-043 共用资源仲裁归属与命令恢复

- 状态：**共用资源仲裁与BM03预约来源已实施；模块部署准出待独立审查**
- 日期：2026-10-21
- 需求与设计：[SHR-02b详细需求](../TDD-共用资源容量与组合占用-SHR02b.md)
- 现状：人员/排班及容量仲裁、冻结许可、原命令恢复已实现并接入BM03；分阶段历史记录保留，当前部署边界见末节。

## 决策提案

1. 同一来源的稳定仲裁归属头与每次不可变命令分离；请求幂等阻止同键重复，归属头阻止不同键同来源重复占用。
2. 固定UTC桶、规范资源根锁及本地原子事务承接完整集合；人员跨店不复制容量。5分钟与请求规模已在1a冻结；TTL和后续容量保护参数仍待对应阶段验收。
3. 复用平台身份/IdempotencyScope/审计/Outbox/JobHandler；sys_idempotent不代替本域冻结载荷与恢复阶段。
4. 预约交接必须关联原单位，不再扣第二份容量；历史单位不复用，活动调整用新分配修订留证据。
5. 正常开放占用与超时保护分开：前者P1仅capacity1并拒绝未来预留，后者保留既有未来预约冲突，多原因阻断并进入协调。
6. 来源未知必须经冻结决策恢复；副作用前先保护hold。当前来源合同不齐的路径不开放收费/权益接入，不在本地事务中等待远程服务。

## 代价与范围

建议在原4张候选容量表之外增加归属头、命令日志、occupation-unit关系和block共4张支撑表；其中owner/command已在1b合并，真源现为41项，交接关系/block仍待后续。
根锁使同资源写串行，桶取整保守占用，P1整单位交接且不支持业务门店迁移；这些边界换取可证明的原子性与恢复语义。
公开接口、P3例外审批、P4并行/多阶段及旧单格切换独立验收。后续评审若调整模型，先同步详细TDD及JSON再编写新迁移，旧迁移保持冻结。

### 2026-10-21 独立行业冻结计划证据的归属

完整计划V1合同及编解码由shop-base/spi/resource/ResourcePlanContract唯一维护，避免美业依赖merchant内部准入类型或复制摘要算法。
merchant原ResourcePlanCodec保留为内部类型适配器；原序列化字节、摘要、资格豁免和原始区间保持兼容。
纯IdempotencyScope原包名/实现不变，下沉base；无MyBatis反向依赖。详见SHR02b §2.8/§5.9。
该决定仅解决合同复用，真实来源权限、意图生成、持久fence和终态恢复仍由行业权威负责；不等于提供了生产来源适配器。

BM03-a1沿原决策追加美业私有V2：独立预约资源意图/栅栏两表，原V1冻结；原预约改期/状态/签到写者在同根下检查活动fence。冻结计划保存原UTF8 LONGTEXT字节，数量guard及工单提交不是来源许可。Mapper仅为持久化原语，不注册来源授权提供者；真实权限/业务计划核对及可信终态解除属于a2。具体字段/验证见主TDD§2.15。

BM03-a2-1补充：当前经营成员/当店权限及原资源命令事实只读Port由shop-base定义、merchant所有者实现，PLATFORM机器协议供独立行业使用。MCH/USR显式隔离，业务服务员/技师资格不推导账号权限；完整Binding核验后查原命令，不查移动的当前头。ACCEPTED无终态证据，通信失败不伪装缺失，摘要不是不可信调用方可提交的权威回执。这些事实只说明读取时状态，不替代来源持久许可或终态协调；美业a2-2继续承担该职责。

## BM03模块部署接线（2026-10-22）

BM03预约以真实业务来源接入完整资源集合预留/确认/重叠替换/释放与原命令恢复。HOST无beauty-core的standalone部署通过反向HTTP取得SERVER来源许可，源服务关闭不能绕过冻结；SERVER私有库不复制平台容量或商业账。源准备、操作、安排、冻结决策是V3/V4共5表显式增量，原V1/V2冻结不变，当前美业私表23。

共用JobTargetEndpoint提供唯一token/JSON/ShedLock实现，平台及beauty-server各一薄入口；registry在shop-base、JDBC锁配置在shop-store-mybatis，独立服务不依赖shop-app。恢复声明api-only，默认每分钟，timeout60秒/lock120秒；既有job-worker发现/调度/运行记录及重启协调，不另设美业timer。扫描只核验已绑定原终态，不能把持久actor当认证信息。业务回执未知且未绑定时需当前合法操作人显式恢复原号。
