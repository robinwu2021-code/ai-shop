# ADR 040 餐饮销售配置与耗用权威边界

> 状态：边界已确认，按P0→P6实施中 · 2026-10-21。不是已实施的核心改造或生产迁移。
> 关联：[需求补充](../../requirements/餐饮系统-完整需求文档.md#十二餐牌配料套餐与消耗统计补充)、[增强方案及计划](../TDD-餐饮系统-餐牌选配套餐与耗用增强方案.md)。

## 1 背景

餐饮需要早餐/午餐/晚餐及自定义餐牌，同一商品在不同外送渠道可有不同价格和配料；奶茶小料、套餐和原料消耗必须同时可追溯。现有设计已保留餐牌、选配、套餐关系，但渠道范围仅有来源/履约、选配绑定在商品级、配方耗用只有报表目标，不能完整支撑需求。

## 2 已确认的边界

1. **一套商品与库存身份，多份销售配置。** 商品/SKU不因渠道差价复制；餐牌和渠道绑定决定可见项、选配及价格策略引用。基础分类不承担餐牌，免费糖冰复用规格字典。
2. **价格只有核心权威。** 餐饮不建价格余额账；渠道价、小料价格、套餐补差及退款分摊经核心报价核定。缺有效报价不能在端上兜底计算后下单。
3. **餐牌条目允许显式替换选配。** 默认INHERIT商品级组；REPLACE使用菜项全部显式组，空组即禁选，不回退。需要渠道差异的组发布独立修订，不用多层补丁合成隐藏规则。
4. **配方属于餐饮配置，库存事实属于进销存。** 配方引用权威物料/单位及发布修订；餐饮保存制作耗用意图、理论量与库存回执引用，不维护另一份实存或历史成本。
5. **计价树和库存树分别冻结。** 一个制作节点明确选SELLABLE_SKU、RECIPE_LEAVES或NONE，避免容器/组件/原料双扣。赠品和已含小料也有耗用；免费不代表无库存影响。
6. **退款和返料分开。** 未制作释放原预占，已制作退款不回原料，重做产生独立制作耗用；实际退料必须有进销存反向单据。
7. **同步确认和本地发布分开。** 外送同步采用原Outbox及稳定请求号，逐项保存远端状态；不承诺外部平台不存在的原子性和幂等接口。

## 3 未采用方案

| 方案 | 不采用原因 |
|---|---|
| 每渠道复制商品或SKU承载差价 | 价格变化导致商品与库存身份分裂，销量和物料难以汇总 |
| 所有渠道复用同一组，前端隐藏部分小料 | 服务端提交、第三方目录和报价可以绕过隐藏规则 |
| 餐饮直接在订单金额上加配料费 | 绕过核心价格、优惠及退款分摊，形成两套金额权威 |
| 销售SKU与配方原料都自动扣库存 | 同一物理需求重复过账 |
| 用销售数乘当前BOM即实际消耗 | 忽略历史配方、选配、部分制作、重做、报废和在制品 |
| 将整数库存一律换成毫克并把成本四舍五入 | 未证明库存单位与估值可无损表示，会产生精度或成本丢失 |

## 4 代价与实施门槛

需要评审餐牌/渠道增量字段、9张餐饮候选表、权威渠道报价及物料单位/估值/制作耗用合同。现有交易接口不能仅通过增加餐饮配置表就被宣布支持；需要独立PAY/进销存及内嵌兼容回归。原商品、订单、库存迁移冻结，不通过修改旧迁移完成升级。

本提议接受后按TDD的P0～P6逐项交付，先收口合同再提交运行时代码。用户已经提出的功能作为目标需求保留，具体表字段与权威接口仍是本轮待评审设计。
