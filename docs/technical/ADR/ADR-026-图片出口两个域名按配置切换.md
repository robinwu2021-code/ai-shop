# ADR-026 · 图片出口用两个自有域名，按配置切换

**日期**：2026-09-25 　**状态**：提议 　**相关**：[TDD-图片走服务器与流量切换](../design/TDD-图片走服务器与流量切换.md) ·
[TDD-图片存储与空间回收](../design/TDD-图片存储与门店空间清理.md) §9

## 背景

COS 上线以来，库里存的公开图地址是桶的公网域名
`https://hxmall-merchant-1301656997.cos.ap-guangzhou.myqcloud.com/<key>`，客户端直连 COS 下载。
2026-09-25 账户欠费，COS 返回 451，全站图片同时失效。

这暴露了一个结构问题：**图片从哪里出流量，被写死在了数据里**。
想换出口（走服务器、上 CDN、换云厂商），就得先迁一次库里 25 个字段的数据；
而老版本的 App 和小程序手里还攥着旧地址，迁完数据也收不回来。

## 决定

1. **两个对外域名，始终都在线**：
   - `img.hxmall.top`：经应用服务器（nginx 走内网从 COS 取图）；
   - `cdn.hxmall.top`：经图片服务器（CDN 或 COS 自定义域名），要切换时再建。
2. **库里只存规范地址** `https://img.hxmall.top/<key>`。
3. **接口返回时按配置 `shop.media.delivery=server|direct` 决定出口**：
   `direct` 模式下，由一个 HTTP 过滤器把响应里的规范前缀换成 `cdn.hxmall.top`；
   请求里提交回来的 `cdn` 前缀在入口换回规范地址。
4. **缩略图写法固定为 `<地址>!w<宽度>`**，宽度只允许 200 / 375 / 750，两个出口都认。
5. **私有图（签名地址）永远走应用服务器**：`https://www.hxmall.top/cos-private/<key>?<签名>`，不参与切换。
6. 测试阶段用 `server`：服务器与桶同地域，内网流量免费；轻量服务器月流量包 500 GB。

## 为什么

- **切换 = 改一个配置并重启**：不迁数据、不发版、不改 DNS，回滚同样是改回配置。
- **改写只在 HTTP 边界**：不碰全局 JSON 序列化。代码里有 66 处自行序列化，图片数组就是序列化后写进库里的，
  全局改写会把 `cdn` 地址写进数据库。
- **规范地址本身能打开**：推送、订阅消息、导出这类不经过过滤器的出口，拿到的是经应用服务器的地址，
  切到 `direct` 之后也不会变成裂图，只是那一小部分流量仍走服务器。
- **缩略图写法两边统一**：否则切换时客户端拼出来的地址要跟着变，还得发版。
- **私有图不上 CDN**：CDN 透传签名要单独配鉴权，配错就是把证件照缓存成公开可访问；而它的量很小。

## 代价

- 服务器多了一个对外职责（图片转发、缓存、缩图），`server` 模式下受 5 Mbps 带宽限制，
  所以上传压缩和列表缩略图必须同时上线。
- `direct` 模式下每个 JSON 响应多一次按字节替换（要先缓冲响应体）；`server` 模式零开销。
- 缩略图写法在数据万象那边要建同名样式，分隔符是否支持 `!` 待确认（TDD §六 Q1）。
  **写法要在第一次产出缩略图地址之前定死。**
- 老客户端里残留的 COS 公网地址，要等桶改成私有读之后才会彻底失效（TDD §4.3 第 14 步）。

## 不适用

- 商家端 APK 的下载（`/dl/`）：本来就走服务器，不在这里。
- 第三方平台上的图（微信头像等外链）：不是我们的对象存储，不改写。
