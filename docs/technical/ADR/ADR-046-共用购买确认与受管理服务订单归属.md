# ADR-046 共用购买确认与受管理服务订单归属

日期：2026-10-23。状态：已确认实施决策，精确设计已通过技术核对；不表示Task56或BM04已交付。

## 背景

美业接待范围需要转换为消费者明确确认的普通服务销售订单。商家识别顾客、登记预约或创建工单，均不能代替当前消费者的购买授权。零售与餐饮已有普通订单写入及优惠分摊逻辑，行业另建订单或价格账会使退款、资金与履约事实出现多个来源。

## 决策

报价、本人确认、普通建单、长期原号映射和稳定来源行由trade原所有者提供，共用合同放shop-base/spi/trade，美业只保存来源引用。继续使用ord_order、ord_sub_order、ord_item及OrderServiceImpl唯一普通writer，不新建美业订单、价格引擎或应收支付账。

prepare由当前有权操作员发起，严格共享身份引用仅用于冻结规范buyer。confirm/place只接受真实HOST当前C有效会话，不接受商家委托、请求自报买家或临客认领作为购买授权。原始身份引用、认领凭证、联系方式与session/token不进入交易持久命令、日志或公开回显。权限和当店数据域在每次请求包括原号重放时重新验证。

持久报价与本人确认绑定同一规范买家、范围及完整经济结果。最终普通writer在任何创建恢复意图、库存或订单副作用之前，以同次实际价格和行分摊校验封版摘要；总额相同但商品、活动选择或出资分摊改变也不能成交。操作、确认消费、订单、managed归属及来源行在同平台事务提交。首次成功确认请求键与首次合法建单元数据claim请求键长期绑定；下游失败保留原claim；异键冲突可通过原操作查询原单，不靠短期缓存重新建单。

受管理服务子单原子写入SERVICE_EXECUTION归属，通用状态写门和底层CAS共同禁止旧核销、收货及自动完成提前写COMPLETED。付款不代表完成服务，不发可用旧核销码。BM05执行证明尚未开放。未管理的历史零售及餐饮订单保留既有语义。

最终锁内仅使用已核实的本地owner实现；目录展示窗口与商品售价保持各自归属，不把锁外报价当作锁内授权。可能涉及远程身份、权限、物流或资金查询的调用在锁外完成，最终本地事实再核对；不能满足本地事务能力的部署明确拒绝该能力。

来源行号与真实订单行在同次插入时绑定，不按SKU或顺序事后猜测。来源数量和金额每次读取真实订单、取消及退款事实；观察指纹和版本仅标识已验证的一致快照，不成为新的账本。未知资金保持未知并阻断消费，不用零代替未知，不以订单投影伪造资金receipt。

## 取舍与实施边界

增加共用checkout过程表与受管理归属列，换取丢响应、重启和缓存清理后的长期可恢复性；代价是更严格的本人会话、请求键和事务边界。首期单operation仅一个quote版本；报价失效或范围变化使用新的明确operation，不自动改写原购买确认。

仅支持MAIN/CNY、单主体单店、SERVICE/STORE_VERIFY/COUNT普通销售，已支持的普通金额活动和本地金额券复用原算法。复杂权益、积分、赠品回退及PAY券明确关闭；真实资金原号与现金receipt归Task57，美业绑定/账单归58，行业协议归59，BM04构件部署与模块准出归60。新迁移追加当前最新号，已执行SQL冻结；美业V1–V7不改。
