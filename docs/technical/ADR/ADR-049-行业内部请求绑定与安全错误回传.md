# ADR-049 行业内部请求绑定与安全错误回传

日期：2026-10-24。状态：Task59 设计已技术核对并放行实施；运行时验证尚未执行。

已有机器协议采用 X-Internal-Token 和 DelegatedIdentityContext，部分旧预约接口返回裸 VO。美业独立部署需要把当前 HOST 已认证身份交给私有 SERVER，并反向读取共用商品、身份、订单及资金事实。仅按 HTTP 状态或部分对象编号验证，无法证明结果对应完整原请求，也无法区分原操作不存在与错误路由。行业层不能复制共用业务账或借机器身份获得 C 购买、支付和 B 实收权限。

在共用中立包增加 InternalRequestBinding、InternalCall、InternalReply、InternalBindings，绑定固定入口/动作、完整身份、主体、门店、目标及全部类型化请求。使用现有机器令牌对规范 JSON 计算 HMAC-SHA-256；摘要只在内部请求关联中短暂使用，不持久化、公开或写日志，不声称具备 nonce 或独立会话验证。公开凭据签发沿已有明确合同，输入凭据不回显。

专用内部序列化器递归输出字段及显式 null，不修改零售全局 ObjectMapper。上下文解码器验证实际记录结构，避免缺失数字变成 0、未知金额消失。完整回显并不代替 owner 的当前权限、顾客、来源及资金一致性验证。

新增可选错误码/请求摘要头及 ServiceCallException 可选元数据，旧构造器、状态和调用方式不变，不读取或记录错误 body。绑定调用方仅在摘要及业务码/状态白名单匹配时接收明确业务失败；未绑定 404、错误回显及通信失败保持协议/依赖未知。令牌先于委派、owner 和写入副作用，纯 Spring JSON 解码可能先发生。空令牌允许默认零售构造，调用仍 401 且不计算摘要。

中立 BoundDelegatedCalls 位于 base-auth，复用原上下文 finally 恢复，不引用美业类型。美业只增加已实现服务的公开入口及 4 个反向 B checkout 方法；confirm/place/pay/cash 继续要求 HOST 实际当前会话。052/054 的最小别名规范化属于本次入口一致性修正，旧 schema1、原请求摘要与派生资源键保持可恢复；新增可选断言不能被忽略。

代价是更严格的内部类型合同、少量公共库可选元数据及配置/类路径验证。旧裸 VO 合同保持兼容；新绑定调用不将旧混合版本响应误当成功。令牌轮换可能令在途摘要验证失败，调用方按原号恢复。历史报价及到店码的合法原键回放不增加客户端未来有效期门槛。

设计 AC 覆盖真实 TCP/全局 Advice、身份与作用域、缺字段/错误 200、默认零售空令牌、历史恢复、schema1/2 别名竞争、真实 owner 桥接及双子进程类路径。此时这些是计划验收，尚非已通过测试。当前 JAR 部署和全 BM04 审查归 Task60。
