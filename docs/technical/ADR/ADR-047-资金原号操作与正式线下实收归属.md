# ADR-047 资金原号操作与正式线下实收归属

日期：2026-10-23。状态：已确认实施决策，Task57精确设计已通过技术核对；尚未实施或验收资金行为，不表示BM04部署完成。

## 背景

共用交易已有消费者确认的普通服务订单及稳定来源行。原资金账能够按原支付号查成功，但旧init会直接重新调prepay、非确定失败关闭原attempt，且长期请求映射和发送前持久意图尚不完整。线下商户确认、附件归属、实际经办账号和资金回执必须分清；订单PAID投影或截图本身不是银行核验。

## 决策

资金仍由pay owner的stl_payment拥有，trade只保存永久原请求映射。P0在平台短事务冻结原key摘要与原订单金额/买家/主体/店/路由命令，提交后才调用资金；P1冻结指令，P2在同pay事务中序列化原订单、ledger.open与paymentNo/outTradeNo/canonical绑定，不能出现账已提交而映射为空的窗口。不建美业支付账或第二余额账。

每笔实际payment只有一个canonical operation承担发送，多个合法请求可映射同一原payment；别名不独立SENDING、不重复prepay。发送前先提交SENDING，再锁外调用gateway。UNKNOWN、超时、暂未找到、参数过期、进程丢失或订单关闭均不授权换号；query/callback继续原号。现有QueryResult不能证明最终未支付，首期仅确证从未发送的NOT_SENT终态允许真实当前C用明确新key尝试，其余保持UNKNOWN，不虚构渠道关闭证明。

当前资金owner沿用全局orderNo/outTradeNo身份；tenant目前是默认MAIN审计字段，并非已启用的行级隔离。新guard按全局orderNo唯一，operationNo按真实全局查询键唯一，不以客户端tenant分裂同一资金锁。CHECKOUT首期仍限MAIN，LEGACY保留原owner范围，不将此决策宣传成完整多租户资金隔离。

C付款、参数重放只真实HOST当前消费者有效会话；B正式实收只真实当前当店操作账号及pay:cash:receive，OWNER沿已有*，其它默认角色不增权。旧MerchantOperatorAccessPort合同兼容，新增真实account解析复用原namespace/权限SQL；主体号不冒充经办账号。原key不进入URL、持久明文或日志，支付参数和凭证正文不向B/internal回显。

CASH与BANK_TRANSFER按既有OFFLINE纯记账语义，由有权商户确认外部已经实收，receipt不表示平台过账或银行独立核验。BANK_TRANSFER核真实私有附件owner事实、字节存在、同实体/店/实际上传账号；专用OFFLINE_RECEIPT类型禁止通用上传绕过及正常回收/删除，不保存任意URL作证明。pay P1冻结完整离线命令但不提前占证据唯一键；P2只canonical领取唯一证据引用、绑定原订单/方法/经办/时间并同事务open+settle生成真实receiptNo，别名保留原命令并复用回执。

原quote/place已验证正式四层支付准入，后续实收读取已消费确认、原报价与原订单的一致原应收，不重新销售、定价或因当前商品下架/开关关闭而抹掉已收。首次申报前已关单或关单并发胜出，仍保留真实资金receipt并走既有LATE_PAYMENT resolution，原订单终态不改。金额或币种异常的可信渠道实收保留原资金，进入异常处理，不伪造成未收或再开attempt。既有线下零佣金、影子记账、无分账和排除通道对账不变。

receipt读取、媒体与gateway I/O均锁外；pay guard→operation→payment以及平台op→order按精确设计执行。原markPaid的SettlePort读取搬锁外，锁内只核不可变receipt与当前owner事实；当前HOST其余实际投影provider已审计为本地SQL/outbox，库存既有独立TX边界如实保留。managed仍SERVICE_EXECUTION，正式收款也不出旧核销码、不提前完工。旧unmanaged线下确认保留原业务语义，不伪称已升级成新资金receipt；真实线上/线下owner状态不互转的边界以实际调用图及反例验证。

## 取舍与实施边界

增加三个过程/仲裁表及stl_payment原号/receipt引用列，保留资金事实单一来源。专用凭证即使尚未被收款使用也保留，付出存储成本换取锁外真实字节检查与后续绑定之间不被正常清理删除。未来独立银行证明、合并转账拆分、全部通道确定未付终态和真正多租户隔离均需明确新合同，不能偷换当前人工实收或UNKNOWN语义。

候选V540首次执行前由根独立审阅并固定SQL/hash；V539及beauty V1–V7冻结，支付当前仍同平台schema/独立pool与payTx，不虚构独立pay迁移目录。测试必须先真实行为RED、原生资金并发/原子映射/独立进程重启/真实权限凭证及最小消融；仅第三方用隔离TEST/STUB，不操作外部真实资金。Task58绑定、59消费端协议、60大模块真实JAR部署尚未交付。
