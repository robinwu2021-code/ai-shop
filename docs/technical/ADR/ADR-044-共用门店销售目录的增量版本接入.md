# ADR-044 共用门店销售目录的增量版本接入

> 状态：已实施，BM-01隔离部署验收通过 · 2026-10-21 · 档位2。
> 需求：美业功能矩阵BTY-B03、BAPI-006；商品V2概念参考Collection/Availability，非整体物理模型落地。

## 1 背景

BM-01已有商品事实和服务定义，缺真实销售分组/时段提供方。现有平台专题不具门店所有权，不复用为门店私有分组；餐饮私有餐牌不作为反向依赖。
商品V2整体规格/listing/价格重构仍为草稿，直接改名既有商品/货架会扩大本模块迁移和所有行业影响。

## 2 决策

product拥有prd_store_catalog头及不可变prd_store_catalog_version，完整版本仅冻结分组/顺序、规范SKU引用/显隐、显式时区及销售周窗口。
共用Service提供受权维护，Port只提供有效版本读取，真实商品、SKU、门店价格、货架、库存继续归既有所有者。美业不建目录账或价格表。
同一门店完整目录原子发布，范围/版本/规范引用/幂等/审计事件一起校验；旧版本不覆盖或删除。
无有效目录是明确的旧口径“无额外陈列/时段限制”；有目录则完整应用其配置。所有展示仍校验实际在售服务事实，目录放行不等于可约或收费许可。
时段只是售卖展示规则，不复用员工班表/资源容量；跨夜显式拆分，按Instant和ZoneId判断。
版本事件仅在显式、无实际消费者的归档合同下保存证据；不得通过切全局投递模式或删除消费者来让模块部署通过。

## 3 代价和边界

整店版本方案不提供本批SMART自动圈品、多渠道价/渠道差异时段、配额/沽清、复杂V2 listing迁移，未实现能力明确拒绝。
未来完整V2接管时须迁移目录稳定标识/版本，不能同时启用两套陈列写权威。该代价小于本模块提前更名旧商品/货架或复制行业价格。
逐步执行及实际验收见美业主TDD §2.10/§2.11和BM-01部署关口；本模块结果与范围见主TDD§22；不代表完整商品V2或生产发布完成。

## 4 本次物理与入口合同

| 表/接口 | 实际合同 |
|---|---|
| prd_store_catalog | BaseEntity审计；entity_no/store_no、catalog_no、current_version_no；scope唯一头；version为头修订 |
| prd_store_catalog_version | BaseEntity审计；entity_no/store_no、catalog_no、catalog_version_no、revision_index、effective_at（UTC）、frozen_payload、snapshot_hash；业务号及目录修订唯一 |
| frozen_payload | Definition(timezone,groups,entries)；Group(key,title,position,visible)；Entry(skuNo,groupKey,position,visible,salesMode,windows)；Window(daysMask,startMin,endMin) |
| GET /biz/store-sales-catalog | at可选，默认服务端当前时刻；实体/门店取BizContext；biz:goods；返回头修订及实际生效版本，支持历史回查 |
| POST /biz/store-sales-catalog/versions | PublishReq(expectedRevision,validFrom,timezone,groups,entries)；强制Idempotency-Key；actor取会话，门店必须当前授权门店 |
| StoreSalesCatalogPort.read | 实际目录拥有方只读投影，美业通过ServiceCatalogFactsPort及受内部凭据保护的typed HTTP获得；无客户端entity/actor扩权 |

[实际V536迁移](../../../backend/shop-app/src/main/resources/db/migration/V536__shared_store_sales_catalog.sql)是DDL真源。
这些共用表不加入美业私有V1或美业Mapper清单，平台H2投影从迁移生成。
归档需显式shop.catalog.publication.archive-only=true，默认不降级正式投递；有实际消费者或已登记交付路由时拒绝归档并回滚。
本文只描述BM-01提供方，不把尚未实施的预约/下单适配声明为已接入该时段守卫。
