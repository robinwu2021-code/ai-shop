# ADR-035 订单号序列化：短期号段方案（头 + 日期时 + 序列）

状态：**已实施**（2026-10-11；实施见 [TDD-订单号序列化](../TDD-订单号序列化.md) §5/§6。决策 2026-10-10 用户确认）
关联：[ADR-033 业务编码统一生成](ADR-033-业务编码统一生成.md)（本 ADR **特意偏离**它，仅针对订单号）
背景来源：用户 2026-10-10「订单号不要展示字母、结尾是数字，容易记忆与识别；头 + 日期 + 序列号，
序列四位满了从一开始，先从 DB 拿 10 个到内存、不每笔查库；将来可重新设计，如 A0610100001」

## 决策

**订单号**（主单）与子单号改为可读的序列格式，其余业务码不变：

```
主单：O + yyMMddHH + NNNN        例 O261010140001   （O + 26101014 + 0001）
子单：<主单号> + "-" + 序号        例 O261010140001-1 / -2
```

- 头 `O` 标识「订单」，**其余全是数字**；子单号 = 主单号 + 后缀，一眼看出属于哪一单。
- `yyMMddHH`：下单时刻到**小时**。日期便于运营/客服识别，小时让同一天的号更分散。
- `NNNN`：序列的 4 位展示，`0001`~`9999` 循环，满了回绕。将来扩 5 位只改展示宽度。

**序列用号段发（DB 游标 + 内存分发）**，不是每笔 +1：

- DB 新建 `sys_sequence(seq_name 主键, next_value BIGINT)`，订单序列一行（`ord_main`）。
- 要号时在一个小事务里 `next_value += 段长(10)`，把这 10 个序列值缓存进内存，之后 10 笔从
  内存游标（`AtomicLong`）发，**不碰 DB**；发完再领下一段。
- `next_value` 在 DB 里单调递增（`BIGINT`，永不回绕）；只有**展示**成 4 位时取模循环。
- 子单不消耗序列：直接在主单号后加 `-1/-2/…`（订单内 1-based 序号）。

## 为什么这样，不那样

### 为什么偏离 ADR-033 的随机段 —— 这是取舍的**反转**，且是知情的

ADR-033 当时为了**防枚举**（竞品估单量、爬邻号）和**防多实例碰撞**，用 `SecureRandom` 随机段
替掉了序列号。订单号这次反过来：用户要「好记、好报、结尾是数字」，而随机段 `A7K3M9QF2X`
正是难记难报的那一截。

代价说清楚：**序列号天然可枚举** —— 看到 `O261010140050` 就知道那小时约第 50 单，
也能猜邻号。这是用户在要「可读」时接受的代价，且**明确是短期方案**，将来重设计（号段换雪花/
业务无关 ID + 单独的「对外展示短号」等）。本 ADR 只把订单号这一类拎出来偏离，**其他业务码
（商品、会员、券、门店…）仍走 ADR-033 的随机段**，不受影响。

### 为什么号段，不是「每 JVM AtomicInteger」

ADR-033 列的旧序列毛病里有一条是「每 JVM 一个 AtomicInteger，多实例同秒撞 seq」。
号段**天然多实例安全**：每个实例领各自的段（DB 的 `+= 10` 是原子的，段不重叠）。
生产现在单实例，但将来上多实例**不用改**，纯内存计数器那条路到多实例就废了。
顺带：重启后内存段作废（最多浪费 9 个号），DB 游标已前进，领新段自然接上，**不会重号**；
且 10 笔才一次 DB 往返（用户明确要的「不每笔查库」）。

### 为什么到小时（yyMMddHH），不只到天

唯一性靠「时刻 + 展示序列」。到天的话同一天所有号共享 6 位日期段，展示序列循环一轮（9999）
就会与当天早先的号撞；到小时把碰撞窗口缩到「同一小时内 > 9999 单」，对任何真实单量都够。

## 边界与风险（务必知情）

| 风险 | 说明 | 兜底 |
|---|---|---|
| 同一小时 > 9999 单 | 展示序列回绕，与同小时早先号撞 | `uk_order_no` 唯一约束拦下；撞了跳过该号续发，不让下单失败 |
| 可枚举 | 序列号可被猜邻号、估单量 | 知情取舍，短期方案 |
| 号段浪费 | 重启/领段切换浪费 ≤ 9 个序列值 | 无害（展示循环，不影响唯一） |
| 多实例（将来） | 号段已支持，无需改 | — |

## 范围

- 改：订单主单号、子单号的生成（`OrderServiceImpl` 两处）。
- 新增：`sys_sequence` 表、`OrderNoGenerator`（号段逻辑）。`BizKey` 不动。
- **存量订单号不迁移**，新旧并存（都是字符串，查询/展示无影响）。
