# ADR-036 物流渠道更新留痕与订单收敛

> 2026-10-15 · 状态：实施中 · 关联：[TDD-订单物流刷新与渠道更新记录](../TDD-订单物流刷新与渠道更新记录.md)

## 决策

微信与快递100的查询、订阅推送均先写物流域当前运单，再由同一份不可变发货快照收敛交易订单。手动刷新在响应前同步调用收敛器；异步出站消息由消费者调用同一收敛器。快照携带来源渠道，订单状态流水据此标记“微信”或“快递100”。

物流域新增追加表 `lgs_update_log` 保存渠道尝试与更新结果，不存手机号和原始回调。B 端仅能读取已授权订单的当前运单记录。微信手动刷新缓存以配置项临时设为 0；普通页面读取继续节流，快递100按服务商频率限流。

## 原因与后果

微信查询可能只有状态，没有签收时间；把 `DELIVERED` 直接当作交易完成会让复用旧运单的订单误结算。当前发货代际、运单号、签收节点时间与最早轨迹时间仍由交易域统一核验。渠道来源需要能覆盖“状态未变化”和“查询无结果”，因此仅扩展物流节点表或交易状态流水都不足以完整留痕。

这增加一张审计表、一条 B 端读取端点和快递100主动查询成本；查询保留 30 分钟/48 次频率限制。上线前的历史查询无法可靠补全来源，不做推测性回填。
