# ADR-036 积分改为平台出资预存池

状态：**待确认**（2026-10-14 起草）
取代：[ADR-006 积分方案](./ADR-006-积分方案.md) 的成本模型；[积分域-完整方案](../design/积分域-完整方案.md) 的「商家发分费 1:1」
展开：[积分资金方案-平台预存池](../design/积分资金方案-平台预存池.md) · [TDD-积分域重整](../TDD-积分域重整.md)

---

## 背景

积分的成本模型已经改过两次：ADR-006 定「成本在商家，结算时扣」；积分域-完整方案改为「商家发分即付费用金进池」。
2026-10-14 对现状代码的 review 发现，第二个模型在实现里有三条路径收不到费用金、却照样让积分可花
（线下抵扣、售后积分退款、售后期内退款的费用金），而它的根因相同：**发分时钱并没有到账**，
费用金只是建结算单时记的一笔账面应收。

同日运营给出的诉求：运营自己创建积分（对标币种、兑换比例）、建资金池、超了就停发、定期补充、
按平台 / 门店 / 用户统计、能暂停；核心场景是购物返积分，**不能超发**。

## 决策

1. **出资方是平台。** 购物返分的钱由平台出（来源记为佣金收入），商家不再承担任何积分成本，也不再自开积分。
2. **先存钱、再发分。** 每个积分种类一个资金池，分「未分配 / 已承诺 / 待追回」三格；
   发分时从未分配挪到已承诺，未分配不够就**整单不发**。待生效的分也有钱对应。
3. **积分种类是主数据**：属于一个区域、绑定该区域币种；兑换比例生效后锁定，改比例 = 新建种类并迁移余额。
4. **所有积分写入只经一张借贷平衡的凭证过账**，`biz_ref` 唯一，条件更新失败即整张回滚。
5. **转正挂结算终局**（直连分账回执 / 归集结算确认），不再是支付后固定天数。
6. **线下单不返分、不抵扣**；售后「积分退款」形式下线。
7. **池子本期是平台账户内的专项**，靠每日外部对账校验「账户余额 ≥ 未分配 + 已承诺」；独立专户留作将来。
8. **到期积分的钱转平台收入。**

## 为什么不可逆

- 资金归属从商家变为平台：已发出的积分、已对商家收过的费用金、商家后台的「积分支出」都要按新口径处理，
  回到旧模型需要再向商家收一次钱。
- 新表族替换 `pts_user_account` / `pts_user_ledger` / `stl_points_pool`，存量要迁移。
- 对外承诺（用户看到的兑换比例、商家不再承担成本）一旦发布不宜反复。

## 后果

| 好的 | 代价 |
|---|---|
| 「不超发」在写入时成立，不靠事后核对 | 平台承担全部积分成本，靠池子上限控制 |
| 商家零推广阻力 | 商家侧积分开关、行业强制、小微判定整套退役 |
| 运营可控：种类、池子、停发、暂停、统计 | 新增 14 张表、7 个任务、6 个运营页 |
| 多区域多币种从模型上隔离 | 第二个区域开通时类目规则要加种类维度 |
| 直连补差与积分占用两阶段咬合，不再付两次 | 结算域多三个钩子调用 |

## 不在本决策内

营销积分（签到等）、商家会员积分、独立资金专户 —— 模型里预留了凭证类型与场景码，另行决策。
