# ADR-036 积分改为平台出资预存池

状态：**待确认**（2026-10-14 起草）
取代：[ADR-006 积分方案](./ADR-006-积分方案.md) 的成本模型；[积分域-完整方案](../design/积分域-完整方案.md) 的「商家发分费 1:1」
展开：[积分资金方案-平台预存池](../design/积分资金方案-平台预存池.md) · [TDD-积分域重整](../TDD-积分域重整.md)

---

## 背景

积分的成本模型已经改过两次：ADR-006 定「成本在商家，结算时扣」；积分域-完整方案改为「商家发分即付费用金进池」。
2026-10-14 对现状代码的 review 发现，第二个模型有三条路径收不到费用金、却照样让积分可花
（线下抵扣、售后积分退款、售后期内退款的费用金），根因相同：**发分时钱并没有到账**。

同日运营给出的诉求：运营创建积分（对标币种、兑换比例）、建平台积分专户、超了就停发、定期补充；
积分在平台、门店、C 端之间流转；B 端与平台约定用积分抵现金、收到的积分平台兑付；
支付时直接结算（默认）或商家收积分统一结算；按平台 / 门店 / 用户统计；能暂停；核心场景购物返积分，**不能超发**。

## 决策

1. **出资方是平台**，购物返分的钱来源记为佣金收入；商家不承担积分成本。
2. **先存钱、再发分**：平台积分专户分 U 未分配 / C 已承诺 / D 待付商家 / R 待追回四格；发放户余额对应 U，扣不动即**整单不发**。
3. **积分是平台发行的币**，在平台发放户、C 端户、门店户、平台接收户之间流转，积分守恒；补充资金时接收户回收的分优先流转回发放户。
4. **受理协议**：商家签了才能收积分；平台**全额兑付**；结算方式 **随单结算（默认）** 或 **定期结算**，写在协议里；直连商家在打款通道接通前只能随单。
5. **积分种类是主数据**：属于一个区域、绑定该区域币种；兑换比例生效后锁定。
6. **所有积分写入只经一张凭证过账**：积分守恒、资金对应、真钱对外部三条在构造时校验；`biz_ref` 唯一；条件更新失败整张回滚。
7. **转正挂结算终局**，不再是支付后固定天数。
8. **线下单不返分、不抵扣**；售后「积分退款」形式下线。
9. **专户本期是平台账户内的专项**，靠每日外部对账校验「账户余额 ≥ U + C + D」。
10. **到期积分回接收户，对应的钱转平台收入。**

## 为什么不可逆

- 资金归属从商家变为平台；回到旧模型需要再向商家收一次钱。
- 受理协议一经商家签署即是对外承诺（全额兑付、结算方式）。
- 新表族替换 `pts_user_account` / `pts_user_ledger` / `stl_points_pool`，存量要迁移。

## 后果

| 好的 | 代价 |
|---|---|
| 不超发在写入时成立 | 平台承担全部积分成本，靠专户上限控制 |
| 积分去向任何时候说得清（守恒） | 多发放户、接收户、发行登记三个平台户 |
| 商家零成本、全额兑付；可选随单或定期 | 两条结算链路；定期结算要出单、确认、打款 |
| 随单付款两阶段，不再付两次 | 结算域多三个钩子调用 |
| 运营可控：种类、专户、停发、暂停、统计 | 新增 18 张表、8 个任务、7 个运营页 |

## 不在本决策内

营销积分（签到等）、商家会员积分、独立资金专户、直连商家的定期打款通道 —— 模型里已预留，另行决策。
