# ADR-032 · 物流独立为模块：先内嵌，按「随时能拆」切数据与依赖

**日期**：2026-10-09 　**状态**：提议 　**相关**：[TDD-物流模块](../TDD-物流模块.md) ·
[ADR-021 支付域独立为服务与独立库](ADR-021-支付域独立为服务与独立库.md)（四阶段，本文照它的形状）·
[ADR-025 服务间调用用 HTTP Interface](ADR-025-服务间调用用HTTP-Interface.md)

## 背景

物流代码散在五个模块里（`shop-base` 的三个 spi 包、`shop-channel/express`、`shop-core/fulfillment` 与 `trade`、`shop-app/paybridge`）。
更要紧的是**数据流向是反的**：商家发货只写 `ord_sub_order`，运单行由物流去扫订单表「读时补齐」，
补齐时还用订单状态覆盖运单状态 —— 已签收的单被打回运输中，每 30 分钟重查一次快递100，直到买家确认收货。

用户要求（2026-10-09）：物流作为独立模块，**现在集成在主服务里**，将来可以独立。

## 决定

1. **新建 `backend/logistics/`**：`logistics-domain` + `logistics-channel`；阶段 3 才建 `logistics-svc`。
   包 `ai.neargo.shop.logistics`，登记进 `ArchitectureTest.DOMAINS`。
2. **这次只走 ADR-021 的阶段 1**：同库、同 jar、同事务管理器。
3. **表前缀改为 `lgs_`**（`RENAME ful_shipment / ful_shipment_trace / ful_carrier`）。
   `ful_` 留给不搬的自提/分拣表 —— 前缀不分开，阶段 2「主库不再建 `lgs_*`」这条闸门写不出来。
4. **数据流向翻过来**：交易域发货时发事件（已有 `SubOrderShipped`），物流登记运单；
   物流**只在登记那一刻**经 `ShipmentSourcePort` 向交易域取一次快照，之后再不读交易域。**反向 Port 预算 = 1**。
5. **物流对外只有四样**：`LogisticsPort`（交易域读）、`LogisticsAdminPort`（运营端）、`LogisticsEvents`（揽收/派件/签收/异常）、`/callback/logistics/**`（服务商推送）。
   **C / B / 运营端的 HTTP 端点留在主应用**：物流不认识用户，属主与判权只能在主应用做（同支付域「领域模块不做 controller」）。
6. **回调放在物流模块内**，路径前缀 `/callback/logistics/` —— 拆出去那天 nginx 按前缀转发一行即可。
7. **多渠道按「能力」切**（订阅 / 推送 / 探测 / 展示 / 下单各一个 SPI），路由按「门店 → 承运商 → 默认」三级、每级一条链；
   承运商编码放映射表 `lgs_carrier_code`，回调路径带渠道名 `/callback/logistics/{channel}`。
   **加一家渠道不改表结构、不改调用方、不改作业** —— 圆通直连是第一家照这个形状接的，顺丰、京东等照抄。

## 为什么不是别的

- **现在就切库 / 上独立事务管理器**：支付域踩过 —— 跨域调用还没全部改成提交后执行时就分开事务，
  两边各提交各的，会造出孤儿数据。先把「延后」做实（本次跨域写全部经 outbox），隔离留给阶段 2。
- **事件里带全量发货数据（免掉反向 Port）**：`sys_outbox` 没有清理，收件人手机号会在那里永久留一份明文。
- **五层模块（api/domain/store/channel/svc）**：支付域文档规划了七个模块，实际落地三个。规划了没人用的层只是空壳。

## 后果

- 物流模块不依赖任何业务域代码，不读写 `ord_*` / `trd_*` / `pmt_*` 表；`LogisticsBoundaryTest` 看住，反向 Port 数只许 ≤ 1。
- 阶段 2（切库）的前置条件已经具备：没有跨域 JOIN、没有跨域事务。
- 阶段 3（切产物）时，主服务里 `LogisticsPort` 换成 `@HttpExchange` 远程实现，`ShipmentSourcePort` 变成主服务的 `/internal/**` 端点。
- 运费模板、快递代下单**这次不搬**（同步算价路径、与结算耦合），作为阶段 3 之前的待决。

## 不适用

- 微信发货信息上报、确认收货提醒、结算事件 —— 它们是微信支付的合规义务，留在交易域；物流只提供触发它们的事实。
- 自提、分拣、调度 —— 门店履约，不是物流。
