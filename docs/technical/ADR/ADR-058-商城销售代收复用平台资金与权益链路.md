# ADR 058 商城销售代收复用平台资金与权益链路

状态：已接受（用户 2026-11-13 确认按建议执行）；本地已实现，未部署。
关联：[TDD-商城销售代收与套餐双端闭环](../TDD-商城销售代收与套餐双端闭环.md)。

## 背景

用户恢复“销售收钱、运营确认到账”，要求先从运营确认套餐，再在 App 验证完整闭环，且运营可以购买。现有线下订单、平台资金核款、履约和权益恢复已经建立，但收款方式只识别银行转账。

## 决定

- 将销售代收作为独立的 OFFLINE/SALES_COLLECTION 方式，冻结于原报价、原订单与原付款尝试；银行转账仍有独立语义。
- 真实钱款只写平台支付账；运营确认真实销售实收后，沿既有付款结果交付权益。运营、App 不直接改订阅伪装购买。
- 销售凭据资金身份为租户、销售员工、方式与收款凭据号，数据库唯一裁决；不含订单/金额/币种，不能改字段重复入款。
- 复用同一订单、同一支付域与既有跨事务恢复，销售代收不再建独立订单、独立商城或新的通用 Outbox。

## 取舍和影响

需扩展银行专用条款、资金校验、DTO、运营与 Flutter 展示及原生资金唯一约束。历史银行条款和唯一键保持原含义；迁移只增不改。独立销售账会增加同步和重复交付风险；伪装银行字段会损坏资金证据，因此均不采用。

本决策已实现并创建增量迁移，通过本地验证；尚未部署、发布商品或记录真实实收。销售缴款、佣金和线上通道不随此决策新增。
