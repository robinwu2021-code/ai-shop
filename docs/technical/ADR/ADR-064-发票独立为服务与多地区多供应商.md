# ADR-064 发票独立为服务，支持多地区、多供应商

> 状态：**提案，待评审**（2026-11-22）。演进自 [ADR-063](./ADR-063-发票独立成模块与税制SPI.md)；
> 参照 [ADR-021](./ADR-021-支付域独立为服务与独立库.md)（支付独立服务与独立库，分阶段）与 [ADR-044](./ADR-044-支付接入层模块pay-portal.md)（接入层独立模块）。
> 设计见 [TDD-发票服务-总体设计](../TDD-发票服务-总体设计.md)。

## 一、决策

1. **发票服务与支付同形**：独立目录 `backend/invoice/`，四个模块 `invoice-channel`（供应商层）/ `invoice-domain`（领域与应用）/
   `invoice-portal`（接入层 controller 与鉴权）/ `invoice-svc`（独立形态进程，只暴露 `/internal` 与 `/callback`）。
2. **双形态部署**：`shop.invoice.deployment=embedded`（默认，在主应用内）| `standalone`（`invoice-svc` + 独立库 `ai_shop_invoice`）。
   调用方只依赖 `spi.invoice.InvoicePort`，切形态只换 bean。
3. **地区是数据 + 税制插件**：`ivc_region` 一行对应一个 `InvoiceRegime` 实现；首期 `TW_EGUI`。
4. **供应商是数据 + 能力适配**：`ivc_provider` / `ivc_provider_region` / `ivc_provider_product`；适配按动作实现能力接口
   （开立 / 作废 / 折让 / 查询 / 领号段 / 核验），由 `ProviderInvoker` 统一调用与留痕。
5. **营业人 × 供应商账户 × 门店绑定**取代主体级一条配置；开立时冻结账户，作废、折让、重传、查单只认原账户。
6. **编号方式是策略**：`LOCAL_RANGE`（Turnkey）/ `PROVIDER_RANGE`（鲸跃）/ `PROVIDER_ONLINE`（绿界）/ `LOCAL_SEQUENCE`（预留）；
   编号差异只能出现在 `NumberingStrategy` 实现里。
7. **状态只有一个写入点**：`InvoiceOutcomeService#apply`（同步回包、上传任务、查单、回执、对账）。

## 二、理由与替代方案

| 方案 | 结论 |
|---|---|
| A. 维持 ADR-063 的模块形态，账号加在主体配置上 | ❌ 一个主体只能一个供应商一个账号；门店切换供应商时历史票的作废与折让找不到原账户 |
| B. 独立仓库、独立 Maven 父工程 | ❌ 要复制 `shop-base` spi、`secret` 模块与 pre-push 闸门；独立发布的收益 `invoice-svc` 已拿到 |
| C. 按供应商在开立流程里写分支 | ❌ 鲸跃与绿界的根本差异是「号从哪来」，按供应商分支会让每加一家都改开立事务 |
| D. 与支付同形的独立服务 + 地区 / 供应商 / 编号三个正交维度 | ✅ 加地区加一个税制实现，加供应商加一个适配包，加编号方式加一个策略，主流程不动 |

## 三、约束

- 号段取号与开立同事务（ADR-063 不变）；在线配号的 `PENDING / UNKNOWN` 票所在来源单不得换账户重开。
- 凭据（鲸跃 posno/posid、绿界 HashKey/HashIV）与 QR 金钥只进 `secret` 模块，业务表只存引用；适配类不持密钥。
- 跨库只存业务键 + 快照列，不跨库 JOIN（ADR-021 §3.3）。
- 鲸跃只放行台湾出口：任何形态下连鲸跃的进程都必须部署在台湾出口机房。

## 四、后果

- 已实现的 V1–V5 需一次 V6+ 迁移（`ivc_regime_profile` → 营业人 / 账户 / 绑定），两个版本内可回退。
- B 端发票设置页改为营业人 + 账户 + 门店绑定；运营端新增供应商与账户管理。
- 新增 7 条架构守卫（TDD §8）。
