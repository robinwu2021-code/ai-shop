# ADR-001 商家端的形态与拆分时机

状态：**待确认** · 创建 2026-08-05
关联需求：[C端功能清单](../../requirements/C端功能清单.md) · 关联方案：[TDD-c-app](../TDD-c-app.md)

---

## 1. 背景

平台定位从「单运营方自营」扩展为**邻里购物平台**：个体户与正规商家可入驻，需要「入驻申请 + 商品管理 + 订单处理」的商家端。
问题：商家端做独立小程序/App，还是集成进现有 C 端？成本如何？

---

## 2. 决策

**分两期，形态不同：**

| 阶段 | 商家端形态 | 理由 |
|------|-----------|------|
| **一期**（平台方是唯一入驻方） | **不做独立小程序**。轻操作（订单、核销、上下架、库存）进**现有 C 端小程序**的商家专区；重管理（商品批量维护、财务对账、结算）进 **PC Web（ops-web）** | 只有一个商家（平台自己），独立端没有收益，只有成本。团长经营台已经是「C 端内嵌角色专区」的模式，商家专区复用同一套壳 |
| **二期**（开放第三方入驻） | **拆独立小程序**（uni-app 同仓多端产物，共享 `ports/` `strategies/` `design/`，只有 `pages/` 不同）。App 不做 | 见 §3 拆分理由 |

**App 端商家端不做** —— 商家高频操作在小程序里够用；除非后续需要蓝牙小票打印、常驻推送保活，再评估。

---

## 3. 二期为什么要拆（拆分理由不是技术，是这四条）

1. **发版节奏冲突**。商家端改动频率远高于 C 端，混在一起会让每次商家端小改都要拖着 C 端一起过审。
2. **包体挤占**。微信小程序**主包 2MB、总包 20MB** 是硬限制。商家端的表格、批量操作、图表会显著吃掉 C 端的预算。
3. **权限与数据边界**。商家端能看到订单明细、客户手机号、经营数据。同一份代码包里混放消费者与商家逻辑，越权风险与审计成本都更高。
4. **能力诉求不同**。扫码枪、批量导入、打印这些商家能力，塞进 C 端是纯负担。

---

## 4. 成本（问题里问的重点）

### 4.1 直接成本 —— 很小

| 项 | 成本 |
|----|------|
| 小程序注册 | 免费 |
| **企业主体认证** | **300 元/年/个小程序**（要用微信支付等能力就必须认证） |
| 多一个小程序 | 多一个 appid + 一套独立的发版/审核流程 |

**多一个小程序的直接费用就是每年 300 元**，相对人力成本可以忽略。

### 4.2 真实成本 —— 在维护与合规，不在钱

- **维护**：uni-app 一套仓库可以出两个小程序（不同 appid、不同 `pages.json` 入口），`ports/` `strategies/` `design/` `api/` 全部共享，增量主要是页面。**增量约 30–40%，不是 100%。**
- **⚠️ 类目资质（这条比费用重要得多）**：
  - **自营**（平台自己卖）：营业执照 + 对应行业资质即可。
  - **平台型**（第三方入驻）：微信小程序需选「电商平台」类目，**要求《增值电信业务经营许可证》（EDI/ICP）**。
  这是一期先自营、二期再开放入驻的**额外理由** —— EDI 办理周期以月计，必须提前启动。
- **⚠️ 资金合规**：多商家结算要么走微信支付**服务商/分账**模式（商家需在微信支付侧完成分账接收方报备），要么平台先收后付（**涉及二清风险，不合规**）。这条必须在开放入驻前定死。

---

## 5. 被否决的方案

| 方案 | 否决原因 |
|------|---------|
| 一期就拆独立商家小程序 | 只有一个商家，独立端零收益；还要提前扛 EDI 资质与分账合规 |
| 商家端永远内嵌在 C 端 | 撑到几十个商家后必然触发包体与发版冲突，届时拆分成本更高 |
| 商家端做独立 App | 商家不会为低频管理装 App；小程序即开即用更契合 |
| 商家端只做 PC Web | 个体户没有 PC；核销、接单必须在手机上完成 |

---

## 6. 一期落地清单

- C 端「我的」增加**商家入驻**入口（申请表单 + 审核状态），与团长入驻并列
- C 端增加**商家专区**（订单 / 核销 / 商品上下架 / 库存），与团长经营台同级
- `ops-web` 承担商品批量维护、审核、结算
- **数据模型现在就按多商家建**（`merchantNo` 贯穿商品/订单/评价/结算），一期只是所有数据都挂在平台自己这个商家下 —— 这样二期开放入驻是配置变更，不是重构
