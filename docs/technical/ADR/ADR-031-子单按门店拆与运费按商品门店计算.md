# ADR-031 子单按门店拆，运费按「商品 → 门店 → 模板」实时计算

状态：**已决策（2026-10-09，用户确认）**
关联：[ADR-030 商品归属改为门店 Offer](ADR-030-商品归属改为门店Offer与品牌库.md)（前置：商品带 `store_no`）·
[TDD-下单按门店拆单与运费模板](../TDD-下单按门店拆单与运费模板.md) ·
[TDD-快递100商家寄件](../TDD-快递100商家寄件.md) §8（本 ADR 取代其 AC16「门店模板，否则默认」）

---

## 1. 背景

下单链路以**经营主体**为单位：按 `entity_no` 分组 → 每个主体落**一家**店 → 用这家店的快递模板算一笔运费 → 一个主体一张子单。

2026-10-09 线上：同一主体「虹选」下四家店各卖各的。买家在鲜果门户买过柿子，再从首页买只在粮油上架的盐 ——
端上按主体记着「鲜果店」，整个主体被落到鲜果店 → 预览 70076 已下架 → 端上退回本地估算，运费显示成写死的 6 元。

根因不在那一处记忆，而在**分组单位**：一个主体一单只能落一家店，那么「柿子在鲜果、盐在粮油」放进同一单，
总有一件被落到不卖它的店。修记忆只是让它更少发生。

用户口径（原话）：「商品和主体、和商户都没有关系，这和商品本身，以及商品所属的门店相关」。

## 2. 决策

1. **商品属于且只属于一家门店**（ADR-030 的 `prd_goods.store_no`）。一行商品的门店**由商品决定**，
   端上不再传、后端也不再「挑一家」。
2. **子单按门店拆**：一单里每家门店一张子单。`ord_sub_order` 本就有 `store_no` 与 `entity_no` 两列，**表结构不变**。
3. **钱的边界不动**：结算、分账、进件仍按 `entity_no`（ADR-011）。结算本就是「每张子单一张账单」，
   一主体多子单天然成立。
4. **运费模板逐行解析**：商品指定的模板 ＞ 门店快递通道的模板 ＞ 平台默认模板。
   商品只能从**平台模板**里选（模板由运营维护，商家不能自建）。
5. **同一门店内多模板合并（淘宝式）**：
   - 同模板的商品合在一起按首重 + 续重算；
   - 不同模板之间，**首费最高**的那个模板计首重，其余模板的全部重量**只按各自续重**计；
   - 满额包邮按模板组各自判（该模板组商品额 ≥ 门槛 → 这一组 0 元，且不参与「首费最高」的竞争）；
   - 任一模板对收货地区「不配送」→ 这家店这一单不能下（整店拒）；
   - 地区加收取参与计费的模板组里**最高的那一笔**，每个包裹只加一次。
   只有一个模板时与现行公式**逐字相同**。
6. **活动与券按门店组计算**：门店就是买家眼里的「店」。主体级满减、商家券按门店组的商品额判门槛、分摊；
   一个主体的多张子单各自成立，不再把主体折成一组。
7. **按主体的东西仍按主体**：经营额度 / 单笔上限（`requireOrderAllowed`）按主体**汇总**判；
   活动赠积分（`bonusPoints(orderNo, entityNo)`）一个主体只发一次。
8. **实时计算、不缓存**：模板、通道配置、商品模板每次预览与下单都现读。

## 3. 弃选

| 弃 | 理由 |
|---|---|
| 修端上「按主体记门店」就够 | 只能降低频率；同主体两店的货放进一单仍必然错一件 |
| 子单仍按主体、运费按门店拆 | 一张子单两个发货门店：发货、核销、轨迹、结算的 `store_no` 都只能填一个 |
| 多模板时各自算完相加 | 买家要为同一个包裹付多次首费 |
| 多模板时取最高的一个模板整单计 | 轻货挂了贵模板会被重算，重货挂便宜模板会被少算 |
| 商品挂「商品 × 门店」模板 | 商品已经只属于一家门店，两者等价，多一层只多一处可以不一致的地方 |
| 商家自建模板 | 模板价取自快递100 由运营生成（TDD-快递100商家寄件 §8 AC17），商家自建会脱离真实成本 |

## 4. 代价

- `OrderServiceImpl` 里约 15 处按 `merchantNo` 键的映射改为按门店键（`subOrderNoOf`、运费、地区排除、自提、周期票、确认、锁库存）。
- 营销端口 `CampaignPort` / `CouponPort` 的分摊单位从主体改为门店组。
- 契约：预览 / 能力 / 下单的 `activityChoices`、`addressChoices` 改按门店键（旧的按主体键仍收，应用到该主体的每家店）；
  `storeChoices` 作废（门店由商品决定）。
- C 端购物车与结算页按门店分段，段头显示门店名。
- 报表：主体级「订单数」口径从「一单算一」变为「一张子单算一」—— 只有多门店主体受影响（线上 1 个）。
