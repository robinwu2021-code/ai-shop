# ADR-048 美业来源观察水位与本域分配仲裁

日期: 2026-10-24。状态: Task58 设计已技术核对，实施中；未验收。

## 背景

功能矩阵 BTY-H01/H03/I04 要求明确选择项目、加项本人确认和逐来源账单。商品、普通订单、消费者确认、支付和退款事实由共用所有者维护。现有 CheckoutPort.source 是可信观察，不提供共享原子消费许可；美业已有来源行 guard 能序列化本域分配，但 allocated_qty<=source_qty 的约束不能记录退款后剩余量低于历史已分配量的阻断事实。仅保留旧 guard 会允许旧版本再次占量。

## 决策

追加美业 V8 单表 bty_source_observation，记录唯一 canonical 子订单及 checkout 操作身份、观察 epoch、最高来源 revision/hash、上次完整非金额来源行及当前 UNKNOWN/READY/BLOCKED。不建立美业订单或资金账。平台 V539 对 order/subOrder 的永久唯一和 sourceOperationNo 校验保证同一版本域；不能比较不同操作的 revision。

所有来源调用先短事务领取 epoch 并置 UNKNOWN，提交后锁外调用共用 owner，再短事务核验并应用。最高来源版本不可回退。同版本异摘要必须阻断。旧 epoch 不能授权 READY 或绑定；若其可信完整结果含更高版本，仍须提升最高水位并阻断。可信旧 UNKNOWN 也不能被较晚返回的旧事实抹掉，须使在途 ticket 失效并要求新查询。外域或畸形结果不得污染水位。

绑定按 observation→排序行 guard→工单→排序任务→submission 锁序执行。当前 epoch、READY、来源 pair 和冻结范围均匹配后，原子校验 allocated+delta 同时不超过历史 orderedQuantity 与当前 refundableQuantity，再同事务插入历史绑定、切任务版本和推进意图。退款后不释放或重写历史分配。绑定是本域经观察的分配，不能串行化观察后发生的远端退款，更不是开工/核销权；canStart=false，BM05 关闭。

原提交意图在外调前持久化原操作、摘要和身份。B 只准备报价、查询，C 继续走真实当前本人确认/建单/支付；不保存 C token。其他当前员工可查询原号，不能冒用原 B 或消费者重新提交。缺原证明时保持待原提交人处理，不换号。

逐来源账单使用同一次可信 owner 快照，去重实际成功回执得到 gross，以 owner net received 推已退，以 owner outstanding 展示未结；UNKNOWN 金额为 null。币种分桶，无法完全归属于本工单的来源只展示 WHOLE_SOURCE 明细，汇总保持不完整，不按任务数量推钱。账单 GET 仅更新观察投影，不绑定或收款。

## 取舍与验证边界

并发或失败的观察可能使来源暂时 UNKNOWN，降低可用性，保留历史事实优先。新 V8 只创建表，旧美业 V1–V7 和平台 V539/V540 冻结；执行前根独立核对生成文件的字节/hash。设计候选 4582 字节，SHA256 c5b54d574624a5265366cf4bf7897ec949d107bd302f171539c461a89a9d8343。

真实原生并发、旧高版本/UNKNOWN迟回、退款低于已分配、原号恢复、本人确认、账单不完整和最小消融均为待执行验收，不把设计当测试通过。58 实现内核，59 开放协议，60 整 BM04 实际构件部署及独立审查。
