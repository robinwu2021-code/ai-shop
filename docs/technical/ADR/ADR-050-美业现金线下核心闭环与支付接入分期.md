# ADR-050 美业现金线下核心闭环与支付接入分期

日期：2026-10-25。状态：用户确认阶段方向；精确接口/状态/数据库待Task63设计审查和实施，尚未实现。

## 背景

用户要求先完成美业核心逻辑，使用现金及线下方式，暂不接支付链条。Task62-S0共用操作人业务人员事实已验收；Task61原设计将Core/Pay保护作为开工前置，现需调整近期交付顺序。现有OfflineReceiptPort是正式Pay实收链路；旧商家confirmOfflinePay拒绝SERVICE_EXECUTION且触发markPaid副作用，均不能不经分析地用作“无支付链条”的开工开关。

## 决策

当前先做商品/共用订单→人工线下业务准入→真实资源占用→任务作业/参与→完工关闭/订单履约→具体任务日历。线上支付、Pay份额保护/自动退款、储值/次数权益及复杂收银后置；原全范围目标保留。默认沿用先收后服务，前台人工确认现金/线下已收，不新增未获授权的赊账/后付规则。

人工确认表达真实受权经办人对现金/线下已收的声明和业务准入，保留方式、时刻、原操作与版本/撤销审计；不是stl_payment或银行/通道核验。Core可基于该权威声明推进合法人工收款状态，必要时标明MANUAL来源，不能仅由服务完工推导已付；精确状态复用由Task63审计决定，不强制新造未付状态机。商品/价格/订单/来源和数量权威归共用所有者，人员/容量归共用人员资源；美业不复制金融/订单账。

人工模式须由服务器绑定到适当来源，不能把在线/已付/资产来源改标签以跳过既有退款约束。真实买家与临客归属、未付关单、取消/售后/履约与开工数量竞争必须在无Pay模式下获得真实合同；不能伪造顾客会话、guestNo充userNo或把UNKNOWN改成READY。Task63须审计这些现有模型限制，提出精确可实施切片后才编码。

人员权限、技能任职、资源真实占用、幂等/原号未知恢复、审计日志/outbox及历史完成量不可省略。旧SERVICE_EXECUTION通用完工拦截继续保留；专用服务履约与人工准入分别定义。已存在的正式线下/线上收款代码及历史证据不删除或改写。

## 取舍与验证

缩短近期交付链，优先验证美业业务闭环；代价是人工声明不具备银行核验/正式支付对账或自动资金逆向能力。界面、报表和接口必须区分人工登记、业务执行与正式资金事实，后续接入不得重复累计或覆盖原历史。

设计/代码/必要隔离MySQL9.7.2与HTTP测试/审查/编译先完成；正式部署仍按用户原要求统一后置。方案/表/接口存在不等于可营业或已部署。实施细节及AC→测试见主TDD§0.3/§2.41及后续Task63设计；现阶段不创建新迁移或修改业务源码。
