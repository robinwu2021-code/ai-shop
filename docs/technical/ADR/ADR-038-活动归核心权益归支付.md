# ADR-038 活动归核心服务权益归支付服务

状态：用户已明确模块边界，具体实施设计待评审 · 2026-10-18

## 决策依据

用户明确“权益类在支付服务，活动类在核心服务”。既有统一活动promotion以及券模板/实例都在core，不能仅将储值迁pay而继续宣称完整符合该边界。

## 决策

核心持有活动规则、版本、参与/营销预算；pay持有券和兑换券、付费次卡/月卡、金额储值的模板/实例/余额余次/发放与使用账。core商品售价和订单仍引用pay已发布权益定义，不把活动参与预算或商品库存搬进pay。

统一UI入口与服务所有权分别处理，shop-app可承载HTTP但只作门面与可信编排。模块间使用SPI、本域Outbox/Inbox与幂等分阶段协议，不跨数据源SQL或共享事务。

## 取舍与后果

pay成为权益承诺的权威方，活动下架不改变历史权益；代价是现有pmt/mkt券模板、实例和使用记录需要迁移及兼容适配。必须建立唯一owner registry和明确批次水位，既有URL可保留但不能双写。增量迁移不能修改已应用Flyway或删除历史证据。

本决策取代ADR-037中pay拥有活动规则的提案，也取代此前赠送兑换券属于core账务的归属描述；不表示首次上线日期、月卡退费条款或模板能力已获批准。

## JB-010身份边界补充（2026-10-18）

统一会员凭证归core.member，补充C本人签发及B扫码识别，不能由pay另建储值核销码。采用256位随机不透明凭证和持久SHA-256摘要，码60秒、顾客引用120秒；不使用登录token/静态用户号，也不要求扫码商家理解消费者身份数据。引用绑定tenant/entity/store/B actor/user，扫码不授予财务授权；源业务的消费者本人确认仍归core.trade（JB-011）。

本次沿既有核心数据源增加V426身份表，代价是凭证查询需要数据库，以及后续JB-051定期清理过期识别事实。相较内存临时映射，重启及多实例下不会丢失既有引用；相较有状态签名密钥轮换，随机原文不入库，伪造值不能匹配摘要。不改变活动、权益或资金owner。此为已授权统一会员码要求的实现细化，非资金托管或线上退款变更。

## JB-011本人授权与源决策补充（2026-10-18）

消费者身份识别与消费授权分离。core只把可信订单/pay报价冻结为PENDING意图；消费者通过C09以登录态确认后，core再持久写入授权引用。PENDING不是授权，不允许pay扣减。确认时锁定主单、子单和订单行，重验修订、选择摘要、报价引用及订单快照摘要；同本人幂等键仅回放原授权。报价意图由core内部服务接收，不向公网开放任意金额/用户/资产快照入口。

核销/发放的终态源决策由core业务事务与业务变化同事务写入`ord_ent_source_decision`，pay通过SourceDecisionPort读取；超时/缺失均不是取消。取消记录不占成功来源键，成功settledKey不含修订号，因此允许旧修订取消后新修订成功，同时阻止同一源跨修订重复成功。该一致性需要未来每个源owner调用同一core事务服务；本地代码门默认关闭，真实pay quote/远程调用仍由后续JB-020/JB-041接入。
