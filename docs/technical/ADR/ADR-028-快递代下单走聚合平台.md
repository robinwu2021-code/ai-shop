# ADR-028 快递代下单走聚合平台（快递100 商家寄件）

状态：已采纳
日期：2026-09-28
取代：[平台端功能清单](../../requirements/平台端功能清单.md) P-5.2「不接承运商 API」这一句（ADR-005 §5 的一期口径）

## 背景

一期口径是「不接承运商 API，只存运单号、展示、校验」。当时的前提是商家各自有快递渠道。
孵化期实际情况：商家单量小，签不到网点协议价，散寄一件跨省 10–15 元起；平台也没有量去谈统一价。
调研见 [低成本快递方案](https://claude.ai/artifact/4NvufMNHeWACEQkDGKiBdB)。

## 决定

先接**快递100 商家寄件（上门取件 · 线上支付）**，平台开一个企业账号，所有商家共用：

- 小单量也能拿到它的批量折扣价（官方口径：起步阶段的中小商家与大批量同价），不签网点、不谈量；
- 接口免费，平台预充值，按实际运费实时扣，次月出账单；
- 一套接口覆盖通达系、京东、德邦，以及快运（重货）。

运费由商家承担：取件后记为商家欠款（`DebtService#incur`，按来源单号幂等）。

## 放弃的方案

| 方案 | 为什么不选 |
|---|---|
| 微信官方快递接口 | 接口免费，但不签网点时只能走顺丰 / 德邦现付，价格是公开价；等商家自己签了网点再接，作为第二条通道 |
| 商家各自签网点 | 孵化期单量不够，谈不下来 |
| 易达、云洋等二级渠道 | 价格可能更低，但资料少、可能断供 |

## 后果

- 平台要垫一笔预充值（孵化期几百元量级），商家欠款的回收本期靠运营线下，接放款抵扣是后续工作。
- 公网多一个回调口 `/callback/express/kuaidi100`，靠快递100 的签名自证。
- 通道做成可替换的 `ExpressPickupPort`：以后加微信快递接口或别的聚合平台，不动订单与发货逻辑。
