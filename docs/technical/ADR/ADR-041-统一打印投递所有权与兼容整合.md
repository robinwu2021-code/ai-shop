# ADR-041 · 统一打印投递所有权与兼容整合

状态：方向已确认，实施中。日期：2026-10-25。

## 背景

统一分支已通过V567/V579和`core/printing`提供公共设备、模板、路由、任务、尝试及撤销epoch，餐饮PrintPort/内部HTTP和KDS工作流已有调用。待合入独立打印模块的V551同时创建4张同名但异构的表，并具有另一套领取和回执实现。文本冲突解决不代表数据或执行协议可兼容。

用户明确选择“适配现有统一打印域”，不选择“隔离表名保留两套实现”。

## 决策

保留现有统一PrintService、五张规范表和既有PrintPort合同。将新增模板规划、请求批次、冻结附件、模拟、PDF、通知、agent等功能挂到同一个投递所有者；新旧入口争用同一个设备执行门控、attempt和证据归并规则。附属记录不能形成第二个在线可领取任务库。

已发布迁移冻结。未部署的独立分支候选迁移从统一应用默认执行序列撤出，原文归档；新增兼容迁移承接附属能力。升级不改变历史身份、快照、UNKNOWN或有效原lease。

## 不采用的方案

- 直接三方合并实体/DDL：四张表概念不同，会发生重复建表或静默映射错误。
- 给新任务表换前缀再并行运行：两套设备状态/领取器不能保证同机串行和未知结果防重打。
- 让旧PrintPort无条件转发新引擎：必须重新证明全部旧数据、撤销epoch、跨进程协议和餐饮调用；目前风险及迁移面更大。
- 删除旧实现或迁移、放宽守卫：破坏历史兼容或掩盖结构错误。

## 影响

本次合入需要实质兼容开发，不是仅处理Git冲突。纯编译/布局/PDF组件可复用；新Facade、dispatch、receipt、agent、reprint、查询与监控需改为统一owner调用。旧文本模板与新富文档明确版本化，不重新渲染历史任务。详细任务和验收见[TDD](../TDD-统一打印域兼容整合.md)。
