## 独立审查和修复

一次只读整体审查发现三项 Important，无 Critical：

1. 部分主体先生成账单时，发行方全局水位会跳过其他主体旧记录。新增用例复现失败，改为所有尚未领取且早于账期截止的过账记录均可结转；冻结水位仅用于本次来源快照。明细保留原发生/过账时间及结转标记。
2. 反向账单修改原消费应付时，金额方向相反。新增用例复现 850 而非 950，修复为原始清分保持原方向，账单及明细按账单方向转换。
3. 原生成命令重试未重新校验主体权限。新增用例复现失权后返回旧账单，修复为恢复原结果后仍按当前主体权限过滤，包括事务内并发恢复分支。

三项用例先失败、修复后通过。未派发第二轮审查，无延后 Minor。

## 实施裁定与限制

- 本次为用户明确要求的当前部分后端发布，覆盖此前“完整阶段编码后统一测试”的顺序要求；Core 金融变更协调器、集中收款证明/跨主体入账、B 端汇总结算页面及对应 UI 联调尚未完成。若误当作完整 P6，业务无法完成跨主体全流程，因此任务表与能力接口均明确标识未交付。
- 未结转旧清分全部进入下一次可生成账期，避免按主体分批处理造成遗漏；成本是首张账单可能包含更早未结算项，明细必须标记结转而不能冒充本期业务。
- 构建能力 COORDINATION_IMPLEMENTATION_PROTOCOL=0，固定返回 P6_FINANCIAL_COORDINATION_NOT_INSTALLED；配置开关不能提前开放跨主体。
- 公开首期只登记加密凭据编号，不支持照片附件，非空附件引用明确拒绝；照片需后续私有证据能力。
- 历史实收100赠30原单继续 DEFERRED，不重投、不补账、不取消、不改状态；P3 正式切换及资金开通不执行。线上资金开关保持关闭，不新增真实资金测试。
- B/C 页面、App 包与小程序版本不变；微信模板和真机限制不因后端部署消失。
