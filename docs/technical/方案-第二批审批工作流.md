## 0. 和第一批的不同

第一批的接法照用（送审 → OpsKit 审批 → 执行节点 `apply` → 未通过 `onClosed`；执行人记为 `OPSKIT`；可以本人审批）。第二批多出三类情况：

| 情况 | 涉及 | 处理 |
|---|---|---|
| **商户侧审批**：审批人是商户自己的店主 / 店长 / 财务，不是平台运营 | T19–T23（E2、F7、A19、H1、H3、H4、H5） | 要 OpsKit 的**商户空间**（契约 C11 建空间、C12 自省带门店 / 管理空间）。OpsKit 侧**还没做**（契约 §8 列在「S3 之前」，联调清单未勾）。见 **Q9** |
| **今天是「当场生效」、没有待审状态** | T16（G3、G8、F11）、A16、A13 | 要新增「待复核」：提交时冻结要做的事（拟定结果，同 Q7），审批通过再执行。见 **Q11** |
| **near-pay 回调身份没有数据权限** | T13 的 B3、T14 的 A9 | 业务里调 `scopes.effective(actor)`，`OPSKIT` 没有任何授权会被拒。见 **Q10** |

## 3. 逐项要点

### T13 · 渠道账户核验 B1、渠道资格激活 B3（near-pay）

- 两项都已在旧审批中心（`CHANNEL_ACCOUNT_VERIFY`、`CHANNEL_QUALIFICATION`），照第一批包一层：`RoutedApprovalSubject` + 一次性凭据，送审入口仍是 `/approvals`。
- B1 生效 `ChannelAccountService.verify`（ChannelAccountService:341），「登记人 ≠ 核验人」（:352）对 `OPSKIT` 天然满足。
- B3 生效 `QualificationService.activate`（:125–136）；数据库约束 `activated_by <> maker_ref`（V57:40）对 `OPSKIT` 满足。**阻塞**：`authorize` 调 `scopes.effective(actor)`（:71–72）与 `requireDeviceScope`（:97）；申请内容读 `actors.current()`（:120–121）。见 Q10。

### T14 · 蓝新已建店商户修改 A9（near-pay）

- 旧审批中心 `NEWEBPAY_MERCHANT_MODIFY`（敏感两节点），只在网关为 mock / sandbox / production-http 时存在。
- 生效 `approve`（:116–119）只置 APPROVED，发往蓝新仍是后续一步（:127）。**阻塞**同 Q10：`access()` → `requireMerchant`（:56、:117）。

### T15 · 接入应用启用 C1、开放 API 接入申请 C3（near-pay）

- C1：旧审批中心 `OPEN_APP_ENABLE`；生效要按状态分「启用 / 恢复」（OpenAppEnableSubject:27–29）。「登记人不得启用」（OpenAppService:128）对 `OPSKIT` 满足。
- C3：独立流程，`approve` 以申请人身份建应用（AppApplicationService:122–133），「提交人 ≠ 审核人」（:125）对 `OPSKIT` 满足。代码不在第一批分支上，见 Q13。

### T16 · 出款回执 G3、对账差异关闭 G8、人工确认到账 F11（near-pay）

- 三项今天都是**当场生效**（OpsFundController:304–326；OpsReconDiffController:144–166；OpsOrderController:292–310），没有待审状态。
- 接法（Q11）：提交时写待复核记录（冻结回执号 / 原因 / 金额 / 到账时间等），送审；通过后调原服务方法（`markPaid`/`markFailed`、`decide`、`manualSettle`，都按操作人字符串执行、不依赖登录会话）。
- 控制器里的范围校验（`payoutInScope`、`inScope`、认领人校验）挪到提交时。

### T17 · 自营供应商出款账户 A18（ai-shop）

- 提交 `PayoutAccountServiceImpl.submit`（:42），生效 / 驳回同一个 `audit`（:128）。
- 回调线程要包 `executeWithoutScope`（:133 的查询有意留在数据权限内）；审计日志今天写在控制器里，要挪进执行节点。
- 「改账号 → 复核」：账号与上一个 ACTIVE 账户不同即加复核步骤。

### T18 · 平台活动报名 E1（ai-shop）

- 提交 `enroll`（PlatformActivityServiceImpl:323），生效 `review(pass, reason, operatorNo)`（:212），操作人显式传入，不依赖会话。
- 超预算由条件更新判（:244–255），抛 `ENROLLMENT_OVER_BUDGET` → 生效失败，运营调预算后重试或放弃。

### T24 · 店招 / 公告 A12（ai-shop）

- 机审命中时 `submitForAudit`（MerchantStoreServiceImpl:175、:294）建 `mch_store_audit`，送审挂在这里。
- 生效 `decideStoreAudit`（MerchantGovernServiceImpl:939）已经不限数据权限。原运营审核队列在审批启用后只读。

### T26 · 商户认领渠道账户 B5（near-pay）

- 商户提交 `submit`（BizChannelAccountClaimController:40），运营 `resolve`（ChannelAccountClaimService:135–166）。
- 通过需要目标账户与账户版本（:146），按 Q13 先在认领单上选定，再送审。
