## 1. 管理需求（查看 · 审核 · 处置）

### D 测试渠道（台湾，正式实例上的沙箱渠道）

- **查看**：哪些渠道账户是测试账户（标「沙箱」）；试运行资格的有效期，**按到期时间判断是否可用**，不能只看「生效中」；哪些收款入口含测试产品（真实顾客也能看到「信用卡（測試）」）。
- **审核**：试运行资格生效要走「渠道资质」两节点审批（现有审核待办已支持）。当前实例允许同一人提交并复核，是否收紧由产品决定。
- **处置**：
  - 资格续期：一键带出账户版本、可选产品与开通证据，填证据号与有效期即可建草稿，再提交审批。
  - 测试结束后撤下入口里的测试产品（现有收款入口编辑已支持）。
  - 开通验收时生成测试收款链接（固定 1 元，最长 30 分钟）。
- **不放运营端**：测试渠道账户「从服务器环境变量登记」。它读服务器 ENV 里的沙箱密钥，属于平台运维一次性动作；需要三项管理权限，误操作会登记出一堆待核验账户。建议保留在运维脚本，运营端只看结果。

### B2 PayBy SGS 测试单（阿联酋）

- **查看**：生成的测试单号、收银台链接、到期时间；后续支付结果在支付订单里看（来源 `PAYBY_ACCEPTANCE`）。
- **审核**：生产私钥启用的两节点审批已在凭证管理与审核待办里。
- **处置**：在 PayBy 测试入口生成测试单（固定 1 AED，同一请求号复用同一单），交给验收人付款。

### B1 PayBy POS 执行配置与验收（阿联酋，功能关闭）

- **查看**：终端的 POS 执行配置历史（草稿 / 已核验 / 已发布 / 停用 / 已取代）、两种执行模式的就绪检查与阻塞原因、绑定状态（凭据只显示是否已关联，不显示引用值）、审计记录；验收批次的身份快照、D01–D20 用例结果、阻塞项、当前用户能否签核、证据清单。
- **审核（核心）**：
  - 配置核验：另一人提交审核证据，制单人不能自审。
  - 验收签核：签核人不能是批次创建人或任何用例的报告人；有阻塞项不能签。
- **处置**：发布（默认模式就绪后）、停用（只停新支付，历史可恢复）；验收用例补录证据。
- **说明**：配置草稿要填设备、商户、凭据引用等大量技术字段，属于制单环节。运营端提供表单是为了让「制单—核验—发布」在同一处可追溯。真正的价值在核验、签核和发布这三个把关点。

### C 蓝新 SoftPOS 设备绑定（台湾，产品关闭）

- **查看**：终端下的绑定（包名、签名指纹、App / SDK 版本、MID / TID、激活批次、有效期、状态）。
- **审核**：设备资格的审批走现有「渠道资质」审批；绑定本身没有审批。
- **处置**：登记绑定（换机时先撤旧再登新）、**撤销绑定（风险处置，撤销后旧设备立即不能收款）**。
- **暂不做**：「SoftPOS 待核实交易」列表。near-pay 运营端还没有对应接口（BE08 未完成），等后端补。

### A 易特付跨境虚拟账户（接口未加载）

- **查看**：账户的令牌状态（缺失 / 已过期 / 已配置，含版本与到期时间）、进件状态；按虚拟账户号查开户结果与收款信息（账号仅生效后显示）；按流水号查到账证据；对账运行结果（流水条数、余额快照、未关闭差异数）；对账差异列表（类别、期望与实际金额、关联流水与到账、处理人）。
- **审核**：一期文档没有写明哪一步必须两人办理，只要求渠道账户管理权限加经营主体范围。**待产品确认：到账认领、差异关闭是否需要复核。**
- **处置**：
  - 财务：认领无法自动归属的到账（必须有归属证据）、把渠道流水和到账逐笔绑定、关闭差异。
  - 运营：发起对账、补查到账与关联、代开虚拟账户、代报贸易单、发起资金关联。
- **不放运营端**：令牌写入（明文令牌，归凭证管理统一处理或运维写入）。
- **缺口**：near-pay 没有「虚拟账户列表」「到账列表」接口，运营端只能按单号查，无法总览。要做成可管理的页面，需要 near-pay 先补列表接口。

## 4. 建议的顺序（待确认）

1. **先做 D + B2**（线上在用、开关已开）：资质续期、测试链接、PayBy 测试单。
2. **再做 B1 + C 的查看与把关**（功能关闭，但页面就位后开关一开就能用）：POS 配置历史、核验、发布、验收批次与签核；SoftPOS 绑定的登记与撤销。
3. **A 易特付暂缓**：接口没加载、账户为 0、产品方案未定稿，而且缺列表接口，运营端无法做成可管理的页面。建议等 near-pay 补「虚拟账户列表」「到账列表」并确定复核口径后再做。
