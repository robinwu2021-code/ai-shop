# 服务端本地业务文件统一管理

状态为待实施。范围包括服务端持久化和临时落盘的业务文件。沿用[现有本地存储与多云设计](TDD-本地存储根路径与多云切换.md)、[文件位置清单](reference/文件与图片存储位置.md)和[图片存储与清理设计](design/TDD-图片存储与门店空间清理.md)。

全项目按[数据库优化、混合存储与发票打印开发计划](TDD-数据库优化、混合存储与发票打印开发计划.md)执行。数据库先验收，本篇作为存储实施依据。

## 0. 目标和验收

| 验收项 | 可验证结果 |
| --- | --- |
| 统一入口 | 上传、生成、读写授权、盘点、删除和迁移可按业务归属追查。已有图片和下载链接可以回读。 |
| 统一根目录 | 启用本地存储的同一环境只配置一个持久业务文件根。API、OPS、文件生成与回收进程从同一持久卷访问文件。 |
| 归属及权限 | 从文件编号或业务单号能查到对象键、用途、归属、大小、状态、哈希和期限。私有文件按资源及主体、门店范围授权。 |
| 生命周期 | 文件完整落盘后发布，失败写入可恢复，到期及无引用文件满足策略后回收，删除留有记录。 |
| 发票接入 | 企业证明联、手机条码交易明细沿用同一机制生成、归档、授权下载和清理。设备出纸、PDF 就绪和邮件交付分别记录。 |

## 1. 现状和范围

- 已有 `SHOP_STORAGE_ROOT`，通常媒体落在 `<root>/uploads`，打印 PDF 落在 `<root>/print-private`。旧媒体和打印目录配置可覆盖默认值。台湾 v2 打印卷已知为宿主机 `/data0/app/ai-shop-v2/print-private/`、容器 `/data/print-private/`。切换前须确认各类文件在真实运行环境中的配置和挂载。
- 图片和既有上传使用 `MediaUploadService`、`MediaStore` 和 `sys_media_asset`。CSV 报表通过 `MediaReportArtifactStore` 复用媒体存储。打印 PDF 使用 `PrintArtifactStorePort`、`prn_export_task` 和独立的私有签名入口。
- 存储范围包含门店封面和商品图、主体及门店附件、资质和付款凭证、售后材料、导入原件与错误报告、报表、打印、发票 PDF，以及已启用的渠道文件交换和业务临时文件。
- 程序包、运维配置、密钥、日志和数据库备份沿用运维目录及权限。支付进件等已有数据库密文的材料保留既有 Vault 模型，可在管理视图显示引用和状态。Android 文件缓存继续由端侧管理。

| --- | --- | --- |

```text
├── documents/            # 新增通用私有文档，按所属业务和用途分支
├── exchange/             # 已启用的文件交换渠道，按渠道及收件、发件和回执分区
└── tmp/                  # 上传暂存、导入展开、渲染中间文件
```

本机发票输出改为 `/Users/robin/work/ume/invoice-qa/storage/print-private/`。脱敏验收材料继续放在 `/Users/robin/work/ume/invoice-qa/evidence/<run-id>/`。服务端备份和开发者验收副本分别归对应生命周期。

现有对象键逐字保留。新增文件例如 `documents/<tenantNo>/<entityNo>/<storeNo>/<purpose>/<yyyyMM>/<fileNo>.<ext>`，主体级文件使用明确的主体作用域。目录仅使用服务端生成的编号和用途。业务表保存文件编号或既有稳定引用，物理路径由根目录加上命名空间与对象键解析。

本地适配器共用路径解析。拒绝绝对路径、回退路径及符号链接逃逸。临时文件在目标所在文件系统完成写入与校验，发布时原子改名。生产本地卷缺失或不可写时应报告具体故障，避免业务文件落入容器可写层。

## 3. 统一入口、数据归属和 API

由一个业务文件服务编排登记、落盘、授权读取、盘点、回收。媒体与打印端口保留作兼容适配。业务传入用途、来源、归属和保留规则，组件按部署配置使用本地磁盘或现有 COS。

| 操作 | 实施方式 |
| --- | --- |
| 上传 | 商家 `POST /biz/upload/image`、买家上传和各专用附件接口内部统一接入。用途由服务端决定可见性、格式和大小规则。 |
| 生成 | 发票、打印、报表及导入结果提交来源编号、用途、格式和内容。按业务操作或冻结版本防重，并保留失败恢复记录。 |
| 公开读取 | 保留 `/uploads/**` 下已授权的门店及商品等公开用途，包括现有旧链接。应用按用途和发布状态决定能否公开读取。 |
| 私有读取 | 沿用 `/media/**`、私有打印下载及业务流式读取。校验授权后发放单文件短期许可。发票邮件继续经收件人验证码兑换下载。 |
| 盘点与查询 | 扩展运营端现有存储治理页及 `/ops/media/*`，按环境、用途、归属、来源、大小、状态和有效期查询。 |
| 回收 | 业务释放引用后，由统一清理流程判断是否可删。治理页支持预览、执行与结果查询。 |

`sys_media_asset`、`prn_export_task` 和报表导出任务作为各自权威记录，统一查询以来源类型加记录编号定位。只有现有表缺少登记能力的新私有文档类别才补登记表。必需字段包括文件编号、用途、提供方、对象键、租户、主体、可空门店、业务来源类型及编号、MIME、大小、SHA-256、状态、有效期、创建及清理时间。业务引用仍归原业务域。

写入前登记，校验成功后发布。磁盘已有文件但登记仍待完成时，对账任务核对大小和摘要后修复。缺文件或摘要不一致进入差异清单。重复请求按幂等键恢复，重复回收安全可重试。应用日志和 HTTP 响应只返回文件编号和必要业务状态。

## 4. 权限、留存和运维

- 公共用途使用服务端白名单。证照、凭证、售后原件、报表、发票和打印文件均走私有访问。Nginx 转发应用路由，完整存储根没有静态公开映射。后台列表和日志隐藏密钥、完整签名、原始磁盘路径及敏感内容。
- 商户文件按租户、主体和门店范围查看。运营预览、回收和迁移分别使用相应权限。授权绑定对象及有效期。隔离跨租户访问、越权对象、失效授权及路径逃逸。
- 门店和商品等长期图片按业务引用管理；既有媒体回收规则继续适用。私有附件及交换文件按其业务保留策略处理。发票及打印 PDF 首期维持七天留存。临时目录有独立短期策略，任务执行期间持有租约。
- 回收分预览、执行和结果，记录操作人、时间、对象编号、业务引用和处理结果。统一任务接管台湾 v2 日常清理前按命名空间确认执行者，避免与现有宿主机任务重复回收。
- 运营页显示分类用量、对象数和可回收数。监控磁盘空间、挂载可用性、写入失败、清理滞后、缺失引用和磁盘孤儿。备份和恢复同时核对数据库记录、对象清单及摘要。

## 5. 迁移、上线和回滚

1. 盘点生产与本机的提供方、旧目录覆盖项、宿主机路径、挂载、对象数量和实际写盘点。包括计划任务、进口导出工具及文件交换对端。缺少归属或没有登记的对象单列。
2. 先在本机接入统一入口及根目录。验证门店图、商品图、用户上传、私有附件、CSV、打印 PDF 及两类发票档案。保留既有 HTTP、对象键和提供方。
3. 按命名空间预复制到新根，切换窗口内暂停受影响写入并补齐增量。核对数量、字节、哈希、权限及业务抽样。缺文件或同键不同内容的对象进入差异清单。
4. 同步切换 API、OPS、worker、下载授权和清理任务的挂载及配置。文件交换另行确认对端轮询目录、回执和重传。验证原链接回读和新对象写入。
5. 保留旧根快照和原配置直至回滚窗口结束。需回滚时暂停写入，补回切换后增加的对象并对账，再恢复旧挂载。完成恢复演练和引用核对后再安排旧盘回收。

验收包括原图链接、私有与跨店权限、同卷多服务回读、MIME、幂等、失败恢复、签名到期、私有下载、按类型清理及同批对象恢复。多云迁移单独核对公开出口和签名策略。
