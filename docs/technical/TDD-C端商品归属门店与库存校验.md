## 问题：门店化只改了「店内」，没改「跨店目录」

门店化那一批把 C 端的**列表与门户**换成了门店口径，但商品流（首页 / 分类 / 搜索 / 收藏）
是**跨店目录**（那一版明确写了「不给 `/mp/goods` 加 `storeNo`」），于是它整条没被复查：

| 环节 | 现状 | 症状 |
|---|---|---|
| 落款行 | `goods.merchant.name` = **主体名** | 线上四家店（虹选鲜果 / 鲜果·福田 / 粮油 / 粮油·深圳测试）在商品流里都显示「虹选科技有限公司」 |
| 池 → 列表 | `GoodsServiceImpl:107` `.map(getGoodsNo).distinct()` | 池行本来带 `store_no`（口径是「∃ 门店：这家店**在架卖它** ∧ 这家店可达」），门店维度在这一行丢掉 |
| 列表 → 详情 | 首页 / 分类 / 搜索 / 收藏都只带 `goodsNo` | 只有门店门户带 `&storeNo=`，其余四个入口没有门店上下文 |
| 下单落店 | 只判「这家店可达 ∧ 营业」 | **没有「在架」也没有「有货」** |
| 加购 | `StockPort.sellable(skuNo)`，分店库存时「取最能卖的那家」 | 注释直言「加购时不知道哪家店履约」 |

### 两把尺之间的缝（已在线上）

```
看得见（池，门店化第 3 步）：这家店在架卖它 ∧ 这家店可达
单落到哪家店（OrderServiceImpl）：这家店可达 ∧ 这家店营业      ← 少了「在架」
```

线上实测（2026-09-30，生产库）：

- 多门店主体 **1** 个（虹选科技有限公司），名下 **4** 家店
- **20013 对（社区 × 商品）只因为非默认店摆着才可见**

也就是说：商品因为「虹选粮油」摆着才进了买家的列表，而下单按「默认店服务得了就用默认店」
落到「虹选鲜果」—— 那家店根本没有这件货。页面一切正常、闸门全绿。

## 设计原则：显示哪家店，就由哪家店履约

**不新增「多家店都有货时显示哪家」这个产品决策** —— 让商品流、详情、加购、下单
共用同一个落店解析器。于是「显示的那家」按定义等于「会履约的那家」，
显示与履约不可能不一致，也不用再写一条对账规则去守它。

底座已经齐了，缺的只是把门店上下文接过去：

- `prd_store_goods`（店级在架）与 `prd_store_stock`（店级库存）**逐字同一套覆盖层语义**：
  一条店级行都没有 → 走主体级（单店商家行为不变）；有了任意一条 → 没行的店视为未上架 / 零库存
- `StockPort.SkuQty(skuNo, qty, storeNo)` 与 `StockPortImpl` 已经按这套语义读店级库存
- `OrderServiceImpl` 已有落店解析（门户选择 → 默认店 → 服务不了才挑别家）

## §0 对账一 · 需求 → 设计

| AC | 需求 | 落点 |
|---|---|---|
| AC1 | 商品流每一行显示**门店名**，不是主体名 | `GoodsVO` 带 `store{storeNo,storeName}`；`biz-goods-card` 落款改读它 |
| AC2 | 显示的那家店 = 会履约的那家店 | 目录与下单共用落店解析器（抽到 spi，两边同一个出口） |
| AC3 | 列表 → 详情 → 加购 → 下单 一路带着门店 | 四个入口的 `openGoods` 带 `storeNo`；详情把它写进加购与下单 |
| AC4 | 落店要判**在架** | 解析器加一条：这家店在架卖这件货 |
| AC5 | 落店要判**有货** | 同上，再加一条可售量 > 0 |
| AC6 | 加购按**该店**库存校验 | `sellable(skuNo, storeNo)`；不再「取最能卖的那家」 |
| AC7 | 显示的库存 / 售罄按**该店**算 | `GoodsVO.SkuVO.stock` 按门店取（覆盖层语义） |
| AC8 | 单店商家行为**逐字不变** | 没有店级行时全部回退主体级 —— 每条 AC 都要有一条单店的反向用例 |

## §1 模块设计

### 口径（2026-09-30 用户拍板）

- **落店仍一单一店**（按商家）。候选店必须对该商家这一单的**每一件**都「在架 ∧ 有货」；
  一家都选不出 → **当场拒，不退回默认店**。少卖可恢复，把单发给没货的店不可恢复。
- **一起做一次发完**：不留「显示还是主体名但已经按门店履约」的过渡态。

### 底座已经有的（不重建）

| 已有 | 在哪 |
|---|---|
| 覆盖层语义（无店级行 → 主体级；有了任意一行 → 没行的店视为未上架/零库存） | `PrdStoreGoods` / `PrdStoreStock` 的类注释，两处逐字一致 |
| 店级库存的锁定/释放/回补 | `StockPort.SkuQty(skuNo, qty, storeNo)` + `StockPortImpl` |
| **店级在架已接进带门店的快照** | `GoodsQueryPortImpl.storeOffSale(...)` |
| 落店解析（门户选择 → 默认店 → 服务不了才挑别家） | `OrderServiceImpl`（本篇给它加两条判据） |
| 池行带 `store_no`，口径已是「在架 ∧ 可达」 | `prd_community_pool`（V241） |

### 四处接线

| # | 动作 | 文件 | AC |
|---|---|---|---|
| A | 带门店的快照里 `available` 按门店算（现在取主体级 `sku.stock − locked`） | `GoodsQueryPortImpl` | AC5/AC7 |
| B | 落店解析加「在架 ∧ 有货」候选筛选；选不出 → 拒 | `OrderServiceImpl` + 一个批量查询出口 | AC4/AC5 |
| C | `sellable(skuNo, storeNo)`；加购按该店判，不再「取最能卖的那家」 | `StockPort` / `StockPortImpl` / `CartServiceImpl` | AC6 |
| D | 目录不再 `distinct()` 掉门店：每件货挑一行池行（与落店同一优先级），VO 带 `store{storeNo,storeName}`，`SkuVO.stock` 按该店 | `GoodsServiceImpl` + `GoodsVO` + 契约 | AC1/AC2/AC7 |
| E | 四个入口（首页/分类/搜索/收藏）`openGoods` 带 `storeNo`；详情把它带进加购与下单 | `c-app` 五个页面 + `biz-goods-card` 落款 | AC1/AC3 |

**AC8（单店商家逐字不变）不是单独一处改动，而是每一处都要有一条「没有店级行」的反向用例** ——
覆盖层的回退分支恰恰是今天所有商家走的那一条，改坏了是全站级事故。
