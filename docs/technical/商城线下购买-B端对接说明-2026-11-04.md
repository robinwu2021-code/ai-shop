# 商城线下购买 · B 端对接说明

2026-11-04。给 `ai-shop-bapp`（Flutter）接手 Task 6 用。接口契约以 [商城 HTTP](../api/commerce-mall-http.md) 末节「线下银行转账购买」和 [OpenAPI](../api/commerce-mall-openapi.json)（`task8-v1`）为准，本文只讲页面流程和状态怎么读。

## 前提

- 后端已接线并有测试，但**还没有在真实开发环境联调**（Task 7）。台湾三家线上通道仍不可用，前端不要显示可点的线上付款按钮。
- 只有服务端返回 `readiness.available=true` 且付款选项里有 `OFFLINE / BANK_TRANSFER` 时，才显示「银行转账」。
- 金额一律是 `{currency, minor}`，`minor` 是整数字符串，`TWD 69900` 表示 NT$699.00。不要在客户端算总价或折算。

## 购买流程

1. **选购与报价**：`POST /biz/stores/{storeNo}/mall/offline/quotes`。展示 `payable`、抵扣明细与报价有效期（15 分钟）。
2. **下单**：沿用 `POST /biz/stores/{storeNo}/mall/orders`（`quoteNo` + 客户端生成的 `idempotencyKey`）。重复点击用同一个 key，后端返回同一张单。
3. **发出收款指引**：`POST …/offline/orders/{orderNo}/instructions`，请求体 `{}`。返回收款账户信息与 `paymentDueAt`（付款截止，下单时冻结，不会续期）。之后可 `GET` 同一路径回读。0 元订单走内部结算，`instructions` 为空，不要让用户去转账。
4. **上传转账凭证**：
   1. `POST …/evidence`（`{}`）拿到 `assetKey`；
   2. `POST …/evidence/content?assetKey=…`，请求体为图片字节，`Content-Type: image/jpeg` 或 `image/png`，≤10MB；
   3. 同一个 key 只能传一次；要换图就重新预留一个 key。
5. **提交付款申报**：`POST …/claims`，带 `claimNo`（客户端生成，重试用同一个）、申报金额、转账时间、银行流水号、凭证 key 列表（1–10 个）。
6. **等待核款**：`GET …/claims` 看申报状态；付款与权益看订单详情 `GET /biz/stores/{storeNo}/mall/orders/{orderNo}`。

## 状态怎么读

| 看什么 | 字段 | 含义 |
| --- | --- | --- |
| 申报 | `claims[].status` | SUBMITTED 待审核 · REVIEWING 运营核对中 · CONFIRMED 已核到款 · MISMATCHED 到账金额与订单不符 · DECLINED 被拒 |
| 付款 | 订单详情 `paymentStatus` | 只有这里变成已付款才算到账 |
| 权益 | 订单详情 `fulfillmentStatus` + 门店权益接口 | 交付完成后刷新权益 |

- **申报 ≠ 到账**。CONFIRMED 也要以订单 `paymentStatus` 为准再提示「已开通」。
- **DECLINED**：提示原因，允许用新的 `claimNo` 重新申报，订单不会被取消。
- **MISMATCHED**：提示联系平台；这笔钱由运营人工处置（退回或另行处理），不会自动开通。
- 超过 `paymentDueAt` 仍未到账，订单可能被运营对账作废；作废后再转账的钱会被退回，不会开通。

## 错误与重试

- 错误信封 `code = 10000 + HTTP 状态`，`msg` 是机器原因码。常见：`OFFLINE_INSTRUCTIONS_NOT_ISSUED`（先调发出指引）、`EVIDENCE_ALREADY_STORED`（换新 key）、`EVIDENCE_FORBIDDEN`、`IDEMPOTENCY_CONFLICT`（同一个号带了不同内容）、`STORE_UNAVAILABLE`、`CHECK_UNAVAILABLE`（稍后重试）。
- 网络超时一律按「结果未知」处理：用同一个 `idempotencyKey` / `claimNo` 重试，或回读订单与申报列表，不要换号重提。
- 切换门店后清掉当前订单、指引与凭证缓存；所有路径都带门店号，后端会按当前门店校验。

## 权限

接口要求当前门店成员有采购职责（与既有商城购买相同）。没有采购职责时只能浏览商品，不显示购买入口。
