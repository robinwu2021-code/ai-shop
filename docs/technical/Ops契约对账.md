2026-08-11 补：**系统配置页的三块主数据也接了真后端** —— 行业（`/ops/industries/**`）、
授权码字典（`/ops/auth-codes/**`）、经营范围开关（`/ops/service-scopes/**`），

ops-web 的开关是 `NEXT_PUBLIC_USE_MOCK !== "0"` —— **默认走 mock**。
所以 19 个页面全绿，而后端根本没有这些接口。

> **发布口径（必须写进发布清单）**：在契约补齐之前，ops-web **只能当 demo**。
> 它不是"接口还没调通"，是**大部分接口不存在** —— 把 `NEXT_PUBLIC_USE_MOCK=0` 一开，
> 页面会成片报 404，而不是个别功能缺失。

## 二、比路径不一致更麻烦的：**模型不一致**

入驻审核这一段，两边不是同一个模型：

| | ops-web | 后端 | 谁对 |
|---|---|---|---|
| 申请是什么 | **商家记录的一个状态**（`Merchant.status = SUBMITTED/REVIEWING/APPROVED`） | **独立的申请单** `mch_entity_apply`，通过后才创建 `mch_entity` | **后端** |
| 审核动作 | `POST /ops/merchants/{merchantNo}/status` | `POST /ops/merchant/apply/{applyNo}/audit` | 后端 |
| 驳回后 | 库里留一个 REJECTED 的商家 | 只有申请单是 REJECTED，**没有商家** | 后端 |

**为什么后端是对的**：驳回的申请如果在 `mch_entity` 里留一行，那就是个「僵尸商家」——
它会出现在按主体聚合的每一处（结算、积分、报表），而它从来没有开过张。
定稿口径也是这一条：*审核通过才创建主体*。

> 所以这一段不是「把路径改一改」，是 **ops-web 的审核视图要换数据模型**：
> 待审列表读申请单，审核动作打在 `applyNo` 上，通过之后才在商家档案里看到它。

## 四、命名口径（避免下一轮又对不上）

| 规矩 | 例 | 为什么 |
|---|---|---|
| **资源段用单数** | `/ops/merchant/apply`，不是 `/ops/merchants/...` | 与 ADR-007 及 C/B 两端生成器里的断言一致（`/(\w+s)/:` 会被生成器拒绝） |
| **申请与主体是两个资源** | `/ops/merchant/apply/{applyNo}` vs `/ops/merchant/{entityNo}` | §二的模型冲突就是混用这两个的结果 |
| 动作用子路径而不是 PATCH body | `/{applyNo}/audit`、`/{applyNo}/accept` | 审计留痕按动作记，动作是路径的一部分才好授权（`@PreAuthorize` 按端点） |

## 五、排期建议

| 序 | 范围 | 理由 |
|---|---|---|
| ~~1~~ ✅ 已完成 | **入驻审核链路接真**：ops-web 审核视图换成申请单模型（`ApplyTab`），打通检索/受理/通过/驳回 + **通过时补服务范围**。后端新增 `GET /ops/merchant/apply/search`，`audit` 增 `serviceScope`/`communityNos` 入参 | 它是唯一一条「不接真就没人能填服务范围」的链路 |
| 2 | 商家档案（列表/详情/认证标/封禁/归档） | 审核通过之后运营才需要它 |
| 3 | 进件看板（运营侧推进 + 拒因回填） | 后端推进链路本轮已建好，缺运营视图 |
| 4 | iam 路径统一 + 行业开关接真 | 后端已有，纯对接 |
| 5 | 其余 14 个模块 | 按业务优先级另排；**每接一个就把它从 mock 摘掉**，别让 mock 与真实现长期并存 |

> 并存期的规矩：`IS_MOCK` 已经暴露给页面，**走 mock 的页面要在界面上显示出来**，
> 否则运营会拿 mock 数据去做真实决策 —— 那比页面报错糟得多。

## 六、本轮补上的对账能力

`backend/scripts/api-align.py` 此前**不扫 ops-web 的前端调用**（平台端一直显示「前端 0 条」）——
于是「ops-web 调了什么」这件事在报告里根本不存在，而它默认走 mock，页面全绿。

现在纳进来了，同时修了两处让报告失真的归一化：

| 问题 | 现象 | 修法 |
|---|---|---|
| 不认 JS 模板字面量 | `` `/ops/x/${no}/y` `` 原样进比对，90 条假差异 | `${...}` → `{id}` |
| 路径参数名参与比对 | 契约 `{auditNo}` vs 前端本地变量 `{no}` 被当成两条 | **参数名一律折叠** —— 名字不是契约的一部分，路径形状才是 |
| PUT 被折成 POST | 契约 PUT / 前端 PUT 被判成「契约里没有」 | 动词按原样保留 |

修完之后平台端的报告从「90 条假差异」变成 **0 阻塞 + 177 条真实待补**，
这 177 条就是后端的工作清单。
