## 零、怎么用这份文档

这是**交付跟踪表**，不是一次性快照。

| | 约定 |
|---|---|
| 数字怎么来 | `npm run gen:delivery` 从代码里重算，写进下面的自动区块 |
| 什么时候跑 | **每次合并涉及端点的改动之后**；至少每周一次 |
| 能改哪里 | 自动区块（`AUTO:BEGIN…AUTO:END`）之外的都可以手改；区块内改了会被覆盖 |
| 数字对不上时 | 先信生成器 —— 它和 `npm run check:api` 同一套折叠口径 |

> **为什么坚持生成**：手写的进度表第二周就会过期，
> 而过期的跟踪表比没有跟踪表更糟 —— 它让人以为自己知道进度。

配套：[交付计划与验收清单](../requirements/交付计划-商家侧.md)（每一项的范围、验收标准、测试方式）。

### 2.3 本轮修掉的一个静默缺陷：`/biz/order` 一直查不出单

商家用的是**消费者令牌**，会话的数据域维度是 `SELF`；而 `ord_sub_order` 上 SELF 锚定的是 `user_no`（买家）。
于是 SQL 被追加 `user_no = <商家自己的 userNo>` —— 商家在订单页只看得到**他自己买过的单**，
卖出去的一单都看不到，而且不报错，只是"今天没有订单"。

修法与商品服务一致：归属判断由 `BizContext` 的 `merchantNo` 显式做掉，查询显式豁免数据域。
