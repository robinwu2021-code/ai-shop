# 商家打印浏览器验收结果

真实 HTTP、组件测试、合同夹具和实体出纸分别记账。

## 真实隔离 H2 后端

Chrome 从 PRINT-BROWSER-ORDER 发现 SUB_ORDER 来源，点击模拟后由软件 worker 推进至 PASSED，读取预期、实际和事件明细；点击导出后推进至 READY，下载并打开一页 PDF。商品冻结内容和实付88.00正确，包含模拟警示。

真实 COURIER 账号通过正式店员创建、角色授权和 OTP 登录产生，直达打印中心、设备和模板页均拒绝。另一真实商家读目标订单得到空来源、零统计；读取他人的模拟、PDF、下载授权，以及携带他人的事实提交模拟均拒绝，见 [HTTP结果](merchant-real-http.json)。

首次真实链路的 [模拟样票](isolated-order-simulation.pdf) 随本记录留存；最终 H5 另行生成并打开 PDF，布局内容一致。两者均为模拟副本。

## 浏览器合同夹具

在独立 loopback 合同夹具中实际完成：旧设备编号收编（初始暂停）后启用、80mm模板创建/版本/预览/发布、路由创建与发布、订单事实请求、模拟详情、PDF打开、UNKNOWN无自动重试入口、异常知悉、无权限直达拒绝。见 [脱敏请求](merchant-contract-requests.jsonl)。

最终失败夹具设置 FIXTURE_FAIL_COMMANDS=1。模拟提交失败后保持原页签和错误提示；等待16秒，后台列表及summary轮询确实发生，错误提示仍在。此项证明浏览器反馈保留，不能作为真实渠道失败恢复证据。
