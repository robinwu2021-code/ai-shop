# 三行业优惠规则：组合与多券

> 状态：设计提案，未实现 · 2026-10-22 · 档位2。根据最新讨论，单条规则独立定义、按单组合校验；多张折扣券分别约束使用数量、作用范围、同项重叠与叠加顺序。本篇作为三行业新模板的优惠组合口径；[原54条详细规则](./TDD-统一试算引擎-三行业规则与规则引擎.md)中的商品/资金/身份边界继续有效。存量零售不自动迁移。

## L1 共同定义

- 折扣券：按原权威规则打折的券；金额优惠券：现金券、金额抵扣券。商品兑换/次数抵扣券先按原权益规则落实具体项目及数量，不能一律当作现金金额券。
- 活动：本单实际接纳的门店促销，不是门店开着活动开关就禁止所有订单用券。
- 储值：支付工具，不是营销折扣；卡附带会员优惠需单独参与冲突判断。
- 人工抹零/减免与实际现金找零分开。禁止券后人工抹零不代表不退还现金多收部分。

## §0 所有新行业模板共同规则

| 编号 | 简单规则 | 配置性质 |
|---|---|---|
| B01 | 本单参加活动，就不能使用任何券 | 强制互斥，门店不能放宽 |
| B02 | 使用任意折扣券，就不能使用储值；反之亦然 | 强制互斥 |
| B03 | 折扣券可以和金额优惠券同时使用，但每张券/原提供方都必须允许该组合 | 组合开关可收紧，真实能力不可越过 |
| B04 | 折扣券默认最多1张；支持能力验收后门店可增加 | 可配置，受全单券数总上限约束 |
| B05 | 金额优惠券默认最多1张；门店可配置多张现金券/抵扣券及分类型上限 | 可配置，原提供方须支持 |
| B06 | 多张折扣券默认分商品/项目使用，同一计价项最多1张 | 可配置重叠模式，默认不连续叠折 |
| B07 | 使用活动、券、储值或积分后，不再额外人工打折 | 强制互斥 |
| B08 | 使用任何券后，禁止人工抹零 | 强制互斥 |
| B09 | 活动或金额券可与储值组合，但原资金和优惠权威必须支持；储值与折扣券仍互斥 | 可收紧，能力不足拒绝 |
| B10 | 积分在本次储值分配后计算；抹零在最后，均不能超过获准剩余金额 | 固定阶段，资格/额度由原权威确定 |
| B11 | 人工操作必须选择原因分类，验证人员权限、额度和必要审批 | 可配原因及受控额度，不可取消授权 |
| B12 | 不参与活动的商品保留应收；原未付/未知资金范围、币种和行分摊均须守恒 | 不可放宽；商品资格可在受控范围配置 |

“允许组合”不会覆盖其他禁止：例如折扣券＋金额券＋储值，虽然折扣券＋金额券合法，整体仍因折扣券＋储值而拒绝。所有相关规则都必须通过后才生成执行计划。

## §1 多张折扣券的统一规则

### 1.1 三种作用模式

| 模式 | 同一计价项 | 核销规则 |
|---|---|---|
| DISJOINT 分项使用，推荐默认 | 最多1张折扣券，不同券可作用于不同项 | 仅核销实际有合法分摊的券 |
| BEST_ONE 同项择优 | 每项最多1张，在合法候选中择优 | 未采用的候选券不核销 |
| STACK 同项叠加，默认关闭 | 可按配置多张，但需提供方支持 | 按冻结顺序逐张计算、保存分摊及实际核销 |

EXPLICIT表示明确要求使用的券，不能静默丢弃。若用户将多张券作为候选供系统择优，需标明CANDIDATE_POOL/AUTO_BEST，不能把“明确核销两张”偷偷解释为“择优核销一张”。

数量至少分成：每单券总数、每单折扣券数、每单各金额券类数量、每项折扣券数。一张券作用多个合法商品只算使用1张；不能按分摊行数重复计数。即使券作用范围不重叠，仍受全单总张数和单资产使用次数限制。

主菜/套餐父项及计价叶子组件不能同时重复作为券基数。重叠依据实际可计价源项及数量份额判断，不能只按菜品名称、分类或SKU判断。

### 1.2 店铺覆盖例子

```json
{
  "couponMode": "MULTI",
  "couponLimits": {"total": 3, "percent": 3, "cash": 0, "deduction": 0},
  "discountCouponPolicy": {
    "maxUsedPerOrder": 3,
    "overlapMode": "DISJOINT",
    "maxUsedPerItem": 1,
    "stackingEnabled": false
  }
}
```

表示最多用3张折扣券分商品使用，不代表同一商品可以打3次折。若仍保留couponMode=SINGLE或total=1，发布时直接报配置冲突。

### 1.3 计算示例

主菜100元用八折券，饮品50元用九折券：`100×80%＋50×90%=125元`。

同一100元商品：BEST_ONE模式可采用八折、应付80元；STACK模式在所有权限/原提供方均允许且无其他限制时，可按八折再九折得72元。带门槛、封顶、部分适用及分摊舍入的真实券须逐张依原权威计算，不能只把折扣率相乘再一次舍入。

同时存在金额券与折扣券时，新模板按先金额抵扣再折扣，金额抵扣先落实到源项，再对各项剩余适用基数应用折扣。不能对整单先扣一次金额，再对各项重复扣相同金额。

## §2 餐饮优惠规则

| 规则 | 默认处理 | 门店可调整项 |
|---|---|---|
| 活动和券 | 参加活动不再用券；订单不能用不可优惠菜品凑门槛 | 可选已发布活动及排除范围，不可放宽互斥 |
| 折扣券数量 | 默认1张 | 真实多券合同支持后可设2/3张等 |
| 多折扣券范围 | 主菜、饮品、小料等分项使用，同项最多1张 | 可选DISJOINT/BEST_ONE；STACK单独验收后开放 |
| 金额券 | 默认1张，允许与折扣券组成合法用券方案 | 可配现金券/抵扣券分类型与总上限 |
| 小料及套餐 | 明确各组件资格；套餐父价/组件价不得重复优惠 | 可配置受控组件排除与已发布套餐模式 |
| 储值 | 将来能力具备后可与活动或金额券组合，不能与任何折扣券组合 | 默认关闭，真实餐饮来源及混合支付验收后开启 |
| 积分与抹零 | 积分末段；有券禁止人工抹零 | 可关闭积分/抹零及配获准额度 |
| 人工折扣 | 没有其他活动/券/资产优惠时才可用，有原因和审批 | 服务补偿、出品问题、获准议价等分类 |
| 后付与AA | 原批次价格/优惠冻结，次数和份额不因分桌、并桌重置 | 只启用核心已支持的范围结账模式 |

## §3 零售优惠规则

| 规则 | 默认处理 | 门店可调整项 |
|---|---|---|
| 活动和券 | 新模板参加活动不再用券 | 可选活动及范围；存量活动＋券留在原兼容档案 |
| 折扣券数量 | 默认1张 | 原核销能力支持后调整总数及折扣券数 |
| 多折扣券范围 | 按SKU/源行/数量份额分项，不能对同一份商品重复打折 | 可选DISJOINT/BEST_ONE，叠折默认关 |
| 金额券 | 默认1张，可与折扣券组成合法方案 | 多现金券/抵扣券需原提供方合同及上限 |
| 会员价、特价品 | 采用原价格权威及优惠标记，不能重复减同一会员优惠 | 选择原权威支持的价格/叠加策略 |
| 运费与多门店 | 运费不默认进入商品门槛；商家券不抵别店，原资方分别记账 | 可选已支持运费优惠；不可跨主体任意通兑 |
| 储值与支付方式 | 储值不与折扣券组合；线下平台券限制继续有效 | 开启储值/组合必须有真实能力 |
| 积分与人工操作 | 积分末段；券后禁人工打折/抹零 | 商品瑕疵、价格纠错、客服补偿等原因及额度 |
| 售后 | 原价格、券/活动分摊和资金路径退款 | 不以配置改变历史订单经济事实 |

## §4 美业/服务优惠规则

| 规则 | 默认处理 | 门店可调整项 |
|---|---|---|
| 活动和券 | 新模板参加活动不再用券 | 可选已发布服务活动与资格范围 |
| 折扣券数量 | 默认1张 | 能力具备后可增加，不能把次数卡算折扣券张数 |
| 多折扣券范围 | 护理、剪发、美甲等按合法服务项目分项使用，同项最多1张 | DISJOINT/BEST_ONE；同项叠折默认关 |
| 金额券 | 默认1张，可与折扣券组成合法组合 | 现金券/抵扣券数量与范围须原权威支持 |
| 次数/疗程权益 | 被权益覆盖的项目不再收全额现金，不再对覆盖部分重复优惠 | 未开通权益能力不得配置为可核销 |
| 储值 | 不能与折扣券组合；首期储值核销要求全额适用余额覆盖 | 余额不足不能自动补记现金；混合需新合同验收 |
| 积分 | 仅原服务源/积分能力支持时使用，储值全额覆盖后无剩余不继续抵 | 可关闭，不能靠配置虚构积分接线 |
| 人工操作 | 服务补偿、价格纠错、获准议价等；券后禁止人工打折/抹零 | 原因及受控审批额度 |
| 来源与确认 | 同服务不能现金单、储值单重复结清；会员识别不等于扣款授权 | 不能关闭真实消费者确认或绕过UNKNOWN |

## §5 默认模板、配置与执行

三行业新模板默认最多2张券：最多1张折扣券＋1张金额券；同项折扣券最多1张，同项叠折关闭。允许组合仍需原提供方支持；门店可收紧为单券。门店个性化允许多券时必须同时调整总数与分类型上限；选择多个候选券不等于使用多张券。美容默认SINGLE_KIND不阻止在COUPON这个种类内部选择合法多张券，但仍受默认组合及全单/分类上限约束。

```text
逐条定义规则
→ 行业默认模板＋门店覆盖
→ 编译：数量、范围、互斥、顺序、能力
→ 针对本单逐条校验所有相关规则
→ 生成唯一合法执行计划
→ 先抵扣、后折扣或储值、再积分、最后获准抹零
→ 计算与分摊
→ 正式确认重验原规则/资产/范围
```

每次输出使用的券、每张券的实际作用项/分摊、未使用候选及原因、冲突项、配置版本和quote指纹。禁止规则不能被组合许可或高优先级覆盖。未知能力/不支持的叠加不能以0折扣或默认成功处理。
