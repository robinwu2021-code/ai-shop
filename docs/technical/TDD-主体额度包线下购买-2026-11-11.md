# 主体额度包线下购买 TDD

需求、边界、线上目录核对及剩余项见 [交付清单](../handoff/offline-plan-purchase-2026-11-11/README.md)。用户确认两套套餐均需支持线下付款，真实账户后补。独立Flutter仓库已接入本轮新接口；本仓旧Vue商户端不是调用方。

- 主体容量定义沿用V150/V221，不与门店行业套餐合并。报价保存时冻结容量和周期，购买单再冻结报价版本及平台收款版本。
- 一主体一笔未处置订单，requestNo在买家范围幂等；原键不同参数拒绝。付款指引仅在原付款意图持久发出后可读。
- 私有证据绑定订单/真实门店/上传人/用途，并保留媒体引用。商家申报与资金核款分离。
- ACCEPTED动作冻结运营身份、实际款项信息和受理时间；资金IO在业务事务外，只有可信MATCHED可应用容量。明确拒绝终结REJECTED并允许纠正，未知保持ACCEPTED。
- 兑现时锁主体归属、主体订阅及订单；原owner/market/套餐基线变更、删除或归属冻结转REVIEW_REQUIRED。应用和动作终结同事务，重试不延长第二次，保留override/trial_used。新试用准确记录TRIAL来源。
- 复用原资金账本和恢复任务；主体单先分流，只有对应资金记录和持久商业结果才能acknowledge，不误交商城门店履约。
- 取消仅为商家申请，运营必须持银行核查凭证对账形成关闭栅栏；明确拒绝的对账保留动作记录。
- UNMATCHED/REVIEW_REQUIRED保留占用；二阶段复用共享OfflineCashRefundPort，以原实收全剩余款申请退款，REFUND_PROOF核验，真实退款完成后再经原作废对账栅栏解除占用。正常已交付匹配款仍走原权益退款；不允许人工改库绕过。

验证：EntityPlanPurchasePolicyTest / EntityPlanPurchaseMysqlTest / EntityPlanOfflineLedgerMysqlTest；OPS精确请求及私有字节契约；App未知结果、原键恢复、身份选店隔离及不误报开通测试。仅MySQL9进行数据库联调。初轮未修改166；用户后续已授权二阶段修复验收后直接部署166，发布证据见交接二阶段记录。

## 1. 二阶段边界

本金事实仍为stl_payment；V13退款/动作表仅存恢复命令和协调状态，不执行银行转账。REFUNDED只表示资金退清；解除主体占用仍需银行对账关闭，不能覆盖后续订单占用、订阅或override。原退款/动作键参数不可改，未知恢复原命令，明确拒绝后新动作纠正。

## 2. 二阶段实现清单

- commerce API/core/persistence：CashReceipt与OfflineCashRefundPort、退款命令/动作持久化、V13迁移、买家安全查询及运营申请/核验/恢复。
- pay与shop-app适配：原款匹配、剩余可退额/待退款占用、可信完成事实；恢复任务交接；保留真实资金账本。
- shop-merchant：退款授权服务/双端控制器、REFUND_PROOF用途、退清后的关闭流程、运营代购上下文与创建者身份；V650和schema同步。
- OPS/独立Flutter：原款与退款进度、私有凭证、原动作恢复、代购入口；外部消费登记与OpenAPI同步。
