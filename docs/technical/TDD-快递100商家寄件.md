## §0 对账一 · 需求 → 设计

孵化期单量小，商家自己签不到网点协议价。平台开一个快递100 企业账号（预充值），所有商家共用它的批量价：
商家在订单页「叫快递」，平台代下单，快递员上门取件，取件后运单号自动回填、自动报微信发货，运费记到商家欠款上。

| AC | 需求 | 落点 |
|---|---|---|
| AC1 | 叫快递前看到各家报价，按价从低到高 | `GET /biz/order/{sub}/express/quotes?weightKg=`；`ExpressPickupPort#quote`（快递100 `method=price`，各家并发查） |
| AC2 | 选一家、填重量，平台代下单；同一子单同时只能有一张未结束的取件单；订单须是快递单且待发货；门店寄件信息不全要说清缺什么 | `POST /biz/order/{sub}/express`；`ExpressPickupServiceImpl#create`；表 `ord_express_pickup` |
| AC3 | 回调要验签；重复推送幂等；推送顺序乱了也不回退状态 | `POST /callback/express/kuaidi100`；`ExpressPickupPort#verifyCallback`（`MD5(param + salt)` 大写） |
| AC4 | 已取件 → 子单自动发货（写运单号与快递公司，`PAID → FULFILLING`），并走现有的微信发货上报；商家已经手动发过货的不覆盖 | `ExpressPickupServiceImpl#onCallback` → `MerchantOrderService#ship`（同一条发货链路，上报自动跟着走） |
| AC5 | 运费记到商家欠款：取件后按快递100 折后运费记一笔；改重后运费变高，补记差额；幂等 | `MerchantDebtPort#incur`（新 SPI，薄转发 `DebtService#incur`），来源类型 `EXPRESS`、来源号 `取件单号#累计运费` |
| AC6 | 取件前可以取消；取消或下单失败后可以重新叫 | `POST /biz/order/{sub}/express/cancel`；快递100 `method=cancel` |
| AC7 | 通道没开（没配凭据）时，接口直说「快递通道未开通」，不假装下单成功 | 桩 `StubExpressPickupGateway#enabled()=false`；错误码 70070 |
| AC8 | 商家 App：快递单待发货时，订单详情出现「叫快递」卡（重量、报价、下单）；下单后显示状态、快递员、运费、取消 | `b-app/src/pages/order/index.vue` |

**孤立项**：无。

**本期不做**（写明，免得被当成遗漏）：
- **顺丰**：微信发货上报对顺丰要求收件人手机号（`receiver_contact`），现有上报没接。可选快递里先不放顺丰。
- **欠款自动从放款里扣**：`DebtService#offset` 至今没有触发者（类注释已写明）。本期运费只记账，商家端「欠款」页可见；怎么收回由运营线下处理，接放款抵扣是另一件事。
- 预约上门时段、保价、面单打印：用快递100 默认（快递员带面单上门）。

## §1 现状与影响面

- 发货：`MerchantOrderServiceImpl#ship` 写运单号 + 状态迁移 + 留痕 + `notifyShipping`（入微信上报台账）。本次**复用它**，不另写一条发货路径。
- 运营端运单列表（`LogisticsServiceImpl`）是从子单的运单号**懒补**出来的：取件回填了运单号，它自动出现，不用改。
- 快递公司码：库里存的是微信 `delivery_id`（`ExpressCompanies`）。快递100 用自己的码，映射只在快递100 网关里一处。
- 行为变化面：只新增入口。原来「商家手填运单号」完全不动，两条路并存。

## §2 方案

### 契约变更

**端点**（权限一律 `biz:ship`，与发货同一个）：

| 端点 | 请求 | 返回 |
|---|---|---|
| `GET /biz/order/{subOrderNo}/express/quotes` | `weightKg`（0.1–30） | `[{carrier, carrierName, priceMinor, listPriceMinor}]` 按价升序；查不到价的那家不出现 |
| `POST /biz/order/{subOrderNo}/express` | `{carrier, weightKg}` | `ExpressPickupVO` |
| `GET /biz/order/{subOrderNo}/express` | — | 最近一张取件单 `ExpressPickupVO`，没有为 `null` |
| `POST /biz/order/{subOrderNo}/express/cancel` | — | `ExpressPickupVO` |
| `POST /callback/express/kuaidi100` | 表单 `taskId / sign / param` | `{"result":true,"returnCode":"200","message":"成功"}` |

`ExpressPickupVO`：`pickupNo, carrier, carrierName, status, trackingNo, weightG, chargedWeightG, freightMinor, courierName, courierMobile, failReason, createdAt`（重量单位克、金额单位分，与全站金额口径一致）。
`status`：`CREATED`（已下单）/ `ACCEPTED`（已接单）/ `PICKED`（已取件）/ `DONE`（已签收）/ `CANCELLED` / `FAILED`。

**库表** `ord_express_pickup`（V351）：`pickup_no`（唯一）、`sub_order_no`、`order_no`、`entity_no`（数据域锚点）、`store_no`、`provider`、`carrier`（微信码）、`task_id`（唯一）、`provider_order_id`、`tracking_no`、`status`、`provider_status`、`weight_g`、`charged_weight_g`、`freight_minor`、`list_price_minor`、`freight_booked_minor`（已记欠款的累计额）、`courier_name`、`courier_mobile`、`fail_reason` + 公共列。

**错误码**：70070 快递通道未开通 / 70071 这一单已有进行中的取件单 / 70072 门店寄件信息不全（缺地址或店主手机号）/ 70073 快递公司拒单（带原因）/ 70074 已取件，不能取消。

**配置**：`shop.express.kuaidi100.stub`（默认 `true`）、`key`、`secret`、`salt`、`callback-url`；凭据来自环境变量 `KUAIDI100_KEY / KUAIDI100_SECRET / KUAIDI100_SALT`，不进代码库。

**部署**：nginx 加 `location ^~ /callback/`（与 `/pay/callback/` 同形）。`SecurityConfig` 已放行 `/callback/**`。

## §6 开通步骤（需要人做）

1. 用公司主体注册快递100 企业账号，开通「商家寄件 · 上门取件（线上支付）」，预充值一小笔运费；
2. 在后台拿到授权 key / secret；自己定一个回调签名盐 salt；
3. 服务器环境变量：`SHOP_EXPRESS_KUAIDI100_STUB=false`、`KUAIDI100_KEY`、`KUAIDI100_SECRET`、`KUAIDI100_SALT`；
4. 服务器 nginx 应用本仓库 `deploy/tencent/nginx/www.hxmall.top.conf` 新增的 `/callback/` 段；
5. 发 B 端新包。

## 偏差说明

- `ExpressPickupVO` 的重量用克（`weightG`）而不是设计稿的公斤：避免小数在前后端来回转，金额同理用分。
- 查价接口的 GET 参数补了一个请求类型 `ExpressQuotesQuery`（B 端契约生成器要求每个带参数的方法都有入参类型）。
- 进行中的取件单存在时，手填运单号的发货卡隐藏：两条路同时开着，商家会一边等快递员、一边自己又叫一个。要换方式先取消。
- 回调不开外层事务（原设计未写）：`ship()` 自带事务，抛错会把外层标成只能回滚；三步各自幂等，靠通道重推补齐。

### §7.4 偏差说明

- 测试环境不再用环境变量 `KUAIDI100_HOST` 切：改为运营端开关 + 按取件单落库。原因是开关要能随时拨、且拨了之后已下的单取消要回原环境；环境变量做不到后者。凭据脚本的 `--test` 参数随之删除。
- 寄件人口径抽成 `StoreSenderResolver` 一处（设计里没写）：发货设置页的「不填时用」与快递单上实际印的必须是同一份。
- 订单详情读发货设置要 `biz:store`，店员 / 配送员 / 客服没有：按 `can()` 裁掉、失败不挡发货，登记进 `biz-page-perm` 的豁免。
