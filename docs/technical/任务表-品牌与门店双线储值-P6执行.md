## 代码结构与接口边界

- shared SPI：StoredValueReports 定义可信 ReportScope、Period、Summary、StoreAttribution、ActivitySummary；StoredValueSettlements 定义 FinancialScope、Bill、Item、Event、Payment 与命令；StoredValueMembership 定义金融组织变更的冻结事实及确认。
- Merchant：StoredValueFinancialAuthorityService 复用管理空间和 ENTITY/BRAND/STORE 授权，分别构造报表和主体财务权限；BrandFinancialChangeService 保存原变更、完整冻结事实和 Core 生效围栏。
- Pay：StoredValueSummaryService 读取账务和来源批次；StoredValueSettlementService 负责生成与状态机；StoredValueSettlementPaymentService 负责登记/确认/撤销；StoredValueSettlementEvidenceCipher 负责带作用域 AAD 的凭据加密；StoredValueFinancialMembershipService 只同步金融准入；StoredValueCrossEntityReadiness 汇总真实就绪条件。
- App/BFF：StoredValueFinanceAppService 及 remote/embedded 实现、Pay 内部端点、BizStoredValueReportController、BizStoredValueSettlementController、金融组织变更协调器。先在锁外核验组织和权限，再进入 Pay 本地事务。
- B 端：stored-value-summary、stored-value-settlement、stored-value-settlement-detail 页面；按品牌/本店范围复用组件，财务动作由底部弹框承载。C 端不新增购买、退款或本金/赠金拆分。

候选 V575：sv_settlement_bill、sv_settlement_bill_item、sv_settlement_payment、sv_settlement_event、sv_activity_daily_summary。候选 V576：Core 金融品牌变更持久日志及 Pay 准入确认增量。未发布编号最终需再次核对远端；不编辑 V570–V574 或其他已执行迁移。

账单按 tenant/issuer/payer/payee/currency/period 唯一；item 对 tenant/clearing_no 唯一。账单、付款和事件使用统一编码生成器新增规则 VSB/VSP/VSE，预留号段在资金事务外。原账务、清分和付款事件不可覆盖。

## 实施裁定

1. 结算账期以清分过账 created_at 为界，业务 occurred_at 保留为原发生时间。生成时锁发行方并冻结已提交清分水位；晚入账旧业务进入其实际过账账期，避免冻结账单漏掉后来提交的旧发生时间事实。报表明确 asOf、水位及时间口径。
2. 争议及调整只追加事实；已结清纠错进入后续账期。未结清调整不能使应付低于已登记/已确认金额，不改原消费、账户余额或清分来源。
3. 首期付款 UI 仅登记当前待付金额，后端仍正确处理多次部分登记及确认，暂不增加独立的任意部分付款交互。证据加密未配置时显示明确不可登记原因，不存明文或使用默认密钥。
4. 金融组织变更不自动搬移任何旧储值。停旧准入与新绑定确认通过可恢复原单完成；存在预占、已收款未知等未完成承诺时拒绝组织切换。最后可用门店不得在仍有品牌余额时退出。
5. 跨主体能力须同时满足 P3 实际结构/恢复回执、结算结构和授权、组织准入一致性及显式开关。当前历史实收100赠30原单仍 DEFERRED，故兼容发布不等于实际开通。
6. 无真实微信模板、无 ADB 真机继续准确标记；不重复已完成的真实一分钱测试，不自动补账或创建真实结算付款。
