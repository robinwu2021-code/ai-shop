# TDD · 运营端内容审核与榜单问答（P-15.2）

素材页新增两个 tab：种草内容审核、榜单与问答。第三个 phase 2 批次。

## 一、批量通过必须绕开风险内容

这一域唯一真正危险的操作是**批量通过** —— 一次点击放行一屏内容。
所以规则不是"提醒一下"，而是三层同向：

1. **界面层**：命中风险词的行**根本不给勾选框**，全选也选不上它们；
2. **mock 层**：批次里含命中项时**拒绝整批**，而不是"跳过它们"——
   静默跳过会让人以为全过了，下次就更敢一次勾一屏；
3. **筛选器**：单给一个「只看命中风险词」，让这批内容有专门的处理入口。

样本里的两条风险内容对应两类真实成因：极限词与医疗暗示（`最低价 / 包治百病`）、
站外导流（`微信 / 内部价`）。没有这两条样本，上面的规则测不出来。

## 二、已通过的内容不能"改回待审"

```
PENDING → PASSED → OFFLINE
        ↘ REJECTED
```

`PASSED → PENDING` 这条边**不存在**：内容已经露出过、被人看过、可能已被引用，
把它退回待审等于假装没发生过。要撤只能走下架，而下架同样要写原因。

## 三、榜单：算出来的与人指定的是两回事

`MANUAL` 与 `SALES/RATING/NEW` 的校验路径完全不同：

| | 算出来的榜 | 人工榜 |
| --- | --- | --- |
| `manualSkus` | **传了直接抛错**（传了就是理解错了，不静默清空） | 必填，且 ≤ `size`、不重复、必须在售 |
| 上线前提 | 无 | 非空（空的人工榜上线就是首页开天窗） |

界面与之同向：**人工选品区只在选了「人工榜」时才出现**，切回算出来的榜时把已选清空 ——
常驻然后保存时报错，是在骗人先填一遍。选品下拉只列在售商品，
因为下架商品进了榜，用户点进去是空页。

## 四、问答：已回答的不能直接改答案

要改先隐藏再重新回答，让改动这件事本身留下痕迹。隐藏也要写原因 ——
否则用户来问"我的问题为什么不见了"时没人说得清。

## 五、顺带改了一处组件

`Column.header` 从 `string` 放宽到 `React.ReactNode`。
表头里放全选复选框是正当需求，不放宽的话调用方会在 `cell` 里手拼一列假表头。
注释里同时写清了边界：放控件的列不要再设 `sortKey`，点表头排序会与点控件抢同一个点击。

## 七、已知取舍

- `riskHits` 在 mock 里是预先标好的。接后端后它应由**风控词库实时匹配**产生，
  且词库本身要能配 —— 那属于 P-14 风控域，不在这一批。
- 榜位顺序目前等于勾选顺序，没有做拖拽排序。人工榜通常只有几个位置，
  收益不抵复杂度；真要排序时应与「首页楼层」那套排序复用同一个件。
