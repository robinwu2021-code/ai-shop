## 1. 需求摘要

矩阵 §八 M1-4「营销与评价」的平台侧。C 端要的是「领券中心 / 卡包 / 发表评价」，B 端要的是「商家回复」，
平台侧必须先有**券与活动的供给**和**评价的治理**，否则前两端没有东西可展示、没有规则可依。

| 矩阵条目 | 本批范围 |
|---|---|
| P-7.1 优惠券 | 券模板、发放与预算、核销效果 |
| P-7.2 活动 | 限时/秒杀场次、满减阶梯、买赠、新人礼包（统一为「活动」一张表，用 `type` 区分） |
| P-7.3 内容位 | 首页楼层与 Banner、投放范围、定时上下线 |
| P-13.1 评价治理 | 评价审核（含图片）、恶意差评申诉裁决、评分算法参数、刷评识别 |

**不在本批**：P-7.4 会员（矩阵标 P1 二期）；C 端领券/写评价（另端）；B 端商家回复（另端）。

## 2. 方案设计

### 2.1 页面结构

| 页面 | tab | 覆盖 |
|---|---|---|
| `/marketing` | 券模板 · 发放记录 · 活动 · 内容位 | P-7.1 / P-7.2 / P-7.3 |
| `/reviews` | 评价审核 · 申诉裁决 · 评分参数 | P-13.1 |

**刷评识别（P-13.1.5）不单独成页**：它是评价行上的**风险标**（同设备/同 IP/文案雷同/短时集中），
做成筛选项 + 行内徽标才有用 —— 单独一页会变成"看得见但没法处置"的孤岛。

**四类活动合成一张表**（限时/秒杀/满减/买赠/新人礼包）：它们的字段结构一致（时间段 + 范围 + 力度），
差异只在 `type` 与力度字段的解释。拆五张表会让"同一时段有哪些活动在跑"这个最常问的问题查不出来。

### 2.2 数据模型

**marketing.ts**
- `Coupon` 券模板：`type`(满减/折扣/新人/定向)、面额与门槛、有效期、**预算 `budget` / 已发 `issued` / 已核销 `redeemed`**、状态机 `DRAFT → ACTIVE ⇄ PAUSED → ENDED`
- `CouponIssue` 发放记录：谁发的、发给谁（人群/定向）、发了多少、成本（P-7.1.2 留痕）
- `Campaign` 活动：`type`(FLASH/SECKILL/FULL_REDUCE/GIFT/NEWCOMER)、起止时间、状态、参与商品数
- `ContentSlot` 内容位：位置(首页楼层/Banner/频道)、排序、投放范围（社区/语言）、定时上下线

**review.ts**
- `Review` 评价：评分(1–5)、内容、图片数、三维分（商品/履约/服务）、`riskFlags` 刷评信号、状态机 `PENDING → PASSED/REJECTED`
- `ReviewAppeal` 商家申诉：关联评价、理由、举证、裁决状态
- `ScoreConfig` 评分算法参数：三维权重（**和必须为 100**）、新商家保护期天数、时效衰减半衰期

### 2.3 关键业务规则（mock 层强制，不只是 UI 提示）

1. **预算不能改到小于已发放金额** —— 否则账面上"已超支"，财务对不上（P-7.1.3）
2. **发券超预算直接拒绝**，不是"先发了再说"
3. **停用/结束的券不能再发放**
4. **活动结束时间必须晚于开始**；同一位置的**秒杀场次不可重叠**（P-7.2.1 场次的意义就在不重叠）
5. **内容位下线时间必须晚于上线时间**
6. **评价驳回必须带原因**（与门店审核同一条规矩）
7. **评分三维权重之和必须为 100**；保护期 ≥0、衰减半衰期 ≥1 天
8. **申诉裁决必须二选一并留痕**，不允许"已读不处理"

### 2.4 权限

复用既有权限码，**不新增模块**：
`marketing:coupon:read/issue`、`marketing:campaign:update`、`marketing:slot:update`、`review:review:read/audit`、`review:score:update`。

⚠️ 发券（`marketing:coupon:issue`）是**花钱**的动作：CS 也持有它（矩阵 §2.3 客服可发补偿券），
所以预算校验必须在服务端而不是靠"只有活动运营能点"。

## 4. 风险

1. **发券预算是钱**：mock 阶段的"预算"只是数字，接后端时必须与 P-12 资金域对齐口径（谁出这笔钱：平台预算 vs 商家预算，矩阵 P-7 注「预算归属需区分」）。本批只做平台预算，商家券（B-11.8）标 P1 不做。
2. **评分算法参数会改变历史评分的呈现**（时效衰减是实时计算的），改参数前要能预览影响 —— 本批只做参数配置与校验，**预览留到有真实数据后再做**，先在页面上写明这一点。
3. 秒杀场次重叠校验只在**同一位置**内做；跨位置的重叠是合法的（首页与频道页可以同时跑）。
