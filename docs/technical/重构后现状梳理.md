## 一、6 个 Maven 模块（原本 13 个）

| 模块 | 主代码 | 职责 | 依赖 |
|---|---|---|---|
| **shop-base** | 54 | 基础设施 + 跨域契约（原 `shop-common` + `shop-spi` 合并） | 无 |
| **shop-core** | 158 | 七个业务域合并：community · fulfillment · marketing · message · platform · product · trade | base |
| **shop-merchant** | 29 | 商家域：主体 / 门店 / 员工 / 进件 | base |
| **shop-settle** | 18 | 结算与积分 | base |
| **shop-channel** | 9 | 支付通道实现（微信/支付宝/stub） | base |
| **shop-app** | 31 | 组装层：23 个 Controller + 配置 | 全部 |

### 依赖形状

```
        shop-app（Controller / 配置）
       ╱    │      │        ╲
  core   merchant  settle   channel
       ╲    │      │        ╱
            shop-base
```

**四个业务模块彼此不依赖** —— 跨域一律走 `ai.neargo.shop.spi` 的 Port 或 Event。
这条由 ArchUnit 第 1 条规则守着。

## 二、模块名变了，但**包名没变**

这是理解现状的关键，也是最容易看错的一处：

| | 变了吗 | 现在是什么 |
|---|---|---|
| Maven 模块名 | ✅ 变了 | `shop-svc-user` → `shop-merchant`；`shop-common`+`shop-spi` → `shop-base` |
| Java 包名 | ❌ **没变** | 仍是 `ai.neargo.shop.merchant` · `ai.neargo.shop.spi` · `ai.neargo.shop.common` |
| HTTP 路径 | ❌ 没变 | 端上零感知 |
| 表名 | ❌ 没变 | —— |

**所以**：12 条 ArchUnit 规则判的是**包**不是模块 —— 它们在合并后依然有效，一条没改就全过。
`shop-spi` 这个模块虽然没了，但 `ai.neargo.shop.spi` 这个包还在，
「Port 只能定义在 spi 包」这条规则照样成立。

> ⚠️ 但规则的**描述文字**还写着旧模块名（「shop-spi 的 Port」「svc 模块之间」），
> 这会让下一个人去找一个不存在的模块。见 §四。

## 四、重构带来的口径过期（要修的）

### 4.1 ArchUnit 规则描述（12 条里有 4 条提到已不存在的模块）

| 现在写的 | 应该写 |
|---|---|
| 「svc 模块之间不得互相依赖」 | 「**业务域之间**不得互相依赖」 |
| 「只走 shop-spi 的 Port/Event」 | 「只走 **`spi` 包**的 Port/Event」 |
| 「Port 接口只能定义在 shop-spi」 | 「Port 接口只能定义在 **`spi` 包**」 |
| 「接口在 shop-spi **另一个 Maven 模块**里」 | 已经是同一个模块（shop-base）了 |

**为什么值得改**：规则说明是给下一个人看的。
写着一个不存在的模块名，他会先花时间确认「是不是我 checkout 错了」。

### 4.2 文档里约 100 处旧模块名

| 旧名 | 出现次数 | 处置 |
|---|---|---|
| `shop-spi` | 18 | 描述**现状**的改成 `spi 包`；**历史记录**（交接文档、开发计划）保留并标注 |
| `shop-svc-user` | 15 | → `shop-merchant`（商家域）或 `shop-core`（消费者域） |
| `shop-svc-fulfillment/product/platform/trade/marketing/message` | 43 | → `shop-core` |
| `shop-svc-settle` | 9 | → `shop-settle` |
| `shop-common` | 8 | → `shop-base` |

> **不做无差别替换**：`docs/交接-*.md`、`docs/technical/*-开发计划.*` 记的是当时的决策过程，
> 把里面的模块名改掉会让历史记录变成一份看起来当时就长这样的假记录。
> 这类只在开头加一句「模块已于 2026-08 合并，对照表见本文」。
