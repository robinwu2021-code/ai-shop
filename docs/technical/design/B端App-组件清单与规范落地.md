# B 端 App · 组件清单与规范落地

> 状态：**现状盘点 · 2026-08-26** · 数字全部取自当天的代码扫描与守卫实跑，不是估计。
> 与 [B端UI规范-画原型的十二条](./B端UI规范-画原型的十二条.md) 的分工：
> 那份面向**画原型的人**（「该画成什么样」），本份面向**写页面的人**
> （「手上有哪些件、现在实际长成什么样」）。

## 一、一句话

B 端 52 个页面共用 **20 个组件 + 32 个公共类**，
但页面自己还另写了 **5 965 行 scoped CSS、1 119 条选择器** ——
**平均每页 114 行样式、21 条选择器**。组件库覆盖的是「壳与积木」，
「一页长什么样」基本仍由各页自己决定。

三道设计守卫（`typography` / `design-tokens` / `skin-vars`）**现在是红的，
而且它们不在 `pre-push` 的六道闸里**。也就是说：规范写下来了，
测试也写下来了，但**没有任何一处会拦住下一次跑偏**。

## 四、六处要处理的

### 4.1 三道设计守卫是红的，而且没有闸门在跑它们

`pre-push` 有六道闸（界面清单 / ops 契约 / 两侧孤儿页 / Controller 粒度 / 生成物 / 后端编译），
**没有一道跑 `vitest`**。所以下面这些自 2026-08-26 起就红着，谁都不会被挡：

| 守卫 | 红的断言 | 数量 |
|---|---|---:|
| `typography.test.ts` | 字号不在字阶 | ~~27~~ → **21** |
| | ~~非价格用了 700~~ | ~~8~~ → **0 ✅ 这条已绿** |
| | 圆角不在五档 | 14（B 端 13） |
| `design-tokens.test.ts` | style 块里写死了颜色 | 3 个文件 |
| | `color: var(--sh-primary)` 当文字色（应走 `--sh-primary-text`） | ~~13~~ → **11 个文件** |
| | 用了没定义过的 `--sh-*` | 1 处 |
| `skin-vars.test.ts` | ~~引用了皮肤里不存在的变量~~ | ~~1 处~~ → **0 ✅ 这道守卫整体绿了**（见 §4.2） |

**恒红的闸门等于没有闸门**，而且它会盖住下一个真问题
（下面 4.2 就是被盖住的那个）。

> **2026-08-26 收窄了一轮**：「非价格用了 700」从 8 条降到 **0，这条断言现在是绿的**。
> 其中 **4 条是守卫自己认漏**（`income`/`points` 的 `.amt`、`order` 的 `.due`
> 都是 `money(...)` 渲染的金额，而豁免名单只认 `amount` 全称）——
> **一条报四个假的断言等于没有断言**，真正那一处（`sh-sheet` 的标题用了 700）
> 就淹在里面。名单补了 `amt` / `due`，`income` 的 `.strong` 改叫 `.amt-sm`
> （它也是钱，名字得说清），`sh-sheet` 的标题改成字阶的 34rpx/600。
> 放宽是逐条核过的：现在被豁免的 7 个选择器全部渲染 `money(...)`，没有藏住任何一处。

### 4.2 `customers` 页四个筛选格没有底色 ✅ 已修（2026-08-26）

> **收编 `sh-stat` 时顺带修掉的**：这四个格子现在由组件渲染，底色走 `--sh-surface`。
> `skin-vars` 那道守卫**从红转绿**。
> 下面是当时的记录，留着 —— 它说明的是「CSS 变量拼错为什么查不出来」，那一课没过期。

`b-app/src/pages/customers/index.vue:320`：

```css
.quad__i { background: var(--sh-card); }   /* --sh-card 不存在，正确名字是 --sh-surface */
```

在 `localhost:5174` 的运行实例里取值：

| 表达式 | 计算结果 |
|---|---|
| `var(--sh-card)` | `rgba(0, 0, 0, 0)` ← **透明** |
| `var(--sh-surface)` | `rgb(255, 255, 255)` |

后果：会员页顶部那四个「分层数字即入口」的格子，**没被选中时是透明的**，
直接压在页面底 `#ECEDEF` 上 —— 看不出它们是四个可点的格子，
只有点中的那一个（`--sh-primary-tint`）才显出边界。
**CSS 变量拼错不报错、不降级，整条声明静默失效**，这正是 `skin-vars` 那道守卫要拦的东西。

### 4.3 「不用描边」这条，代码没在遵守 —— 要判的是哪边改

67 处 `border`、4 处 `box-shadow`，其中绝大多数是 `2rpx solid var(--sh-line)` 的分隔线，
分布在 26 个文件里。**这不是「几个人偷懒」的量级，是这条规矩在 B 端没被接受**：

- B 端是作业台，密集列表里没有分隔线确实难扫
- `sh-tabbar` **自己就带** `border-top` + `box-shadow`（组件里写着理由：
  白 tabbar 压浅灰页面，不加分界会像列表溢出到菜单里）

所以要么规范承认「hairline 分隔线是允许的第 13 条」并给出统一形态，
要么代码整改。**现在这样——规范说不用、组件带头用、页面各写各的——最糟**。

### 4.5 三处自建弹层没走 `sh-sheet`

`goods-list`（`.sheet`）、`my-specs`、`order`（`.dlg` + `.mask`）各自实现了一遍。
代价已经看得见：`order` 的遮罩写死 `rgba(0, 0, 0, 0.45)` 而不是 `var(--sh-scrim)`，
`.dlg` 的圆角是 28rpx（越档），`.sheet__t` / `.dlg__title` 都是 32rpx（越档）。
`biz-pickup-sheet` 同理。

顺带：**`sh-sheet` 自己的 `.sheet__title` 也是 32rpx**，也越档 ——
组件库带头破的那一档，页面照抄不奇怪。

### 4.6 图标：有库，但没有尺寸档，也没盖住常用的那几个

- 图标库 `packages/shared/src/design/icons.ts` 共 **18 个**
- B 端实际用了 7 个，`chevronRight` 一个占 **18/26**
- `sh-icon` 的 `:size` 在 B 端取过 **8 个值**（16/18/20/22/24/28/34/36rpx），默认值是 44 ——
  **圆角有五档、字号有八档、间距有五档，图标尺寸一档都没有**
- ~~模板里还留着 9 处 `✕`~~ → **收编 `sh-icon-btn` 后剩 6 处**（2026-08-26）：
  行尾删除 3 处、弹层关闭 2 处已换成真图标。剩下的是输入框清空 ×3、
  chip 内嵌 ×1、图片角标 ×1、详情图 ops ×1 —— **尺寸受宿主约束，是另一套几何**。
  另有 **10 处 `✓`**，库里没有 `check` 图标 —— 那一个要先补图标
- **同一个动作连字符都不是同一个**：`store-scope` 用的是 `×`（U+00D7，乘号），
  其余用 `✕`（U+2715）。换成图标之后这类问题不会再有

### 4.7 `wot-design-uni` 是依赖、有 easycom 映射、**零使用**

`package.json` 里装着，`pages.json` 里映射着 `^wd-(.*)`，
全 B 端没有一处 `<wd-*>`。要么用起来，要么摘掉 —— 留着的成本是
「下一个人以为可以用它」，然后 B 端就有了两套观感。
