# C 端 App 测试方案（模拟器 e2e + 跨端闭环）

状态：待执行（2026-08-15）
关联：[B端App测试方案](./B端App测试方案.md) · [B端App测试执行记录](./B端App测试执行记录.md)

覆盖面：**27 个页面 / 53 个端点**，按模块编号（C1–C11），共 **58 条用例**。
其中 **C5「三条履约闭环」是这份方案的重点** —— 它是 B 端测试留下的另一半：
B 端验的是「接了单怎么处理」，这里验的是「单从哪来、处理完用户看到什么」。

## 0. 判据与不重复

与 B 端同一套判据：**在 vitest / MockMvc 里测得出来的，这里不测**（订单状态机、
分账金额、券叠加规则等已有场景测试覆盖）。这里只测**装到设备上、连真后端、
一个真人从头买到收货**才会暴露的：跨端的状态同步、下单到收货的完整链、
真实数据下的金额、以及 C 端特有的「游客能逛、下单才登录」这条边界。

**C 端与 B 端最大的不同**：C 端**没有 RBAC**，只有属主鉴权（「这单是不是你的」）。
所以这里不测权限矩阵，而要重点测**属主边界**：查别人的订单、评价别人买的商品，
应当查不到而不是报错。

## C1 · 注册与登录（6 条）

C 端是**登录即建户**，与 B 端同一套 OTP，但落的是消费者账号。

| # | 场景 | 怎样算过 |
| --- | --- | --- |
| C1.1 | 全新号登录 | 建出 `usr_account` 行；进首页（不是入驻页 —— 那是 B 端的） |
| C1.2 | 老号登录 | 复用同一个 `user_no`，历史订单还在 |
| C1.3 | 验证码错 | 提示可读（**F1 修后应是「验证码不对或已过期」，不是 Invalid request**）—— 与 B 端同一条链，顺带回归 |
| C1.4 | 游客逛（不登录） | 首页、商品详情、门店主页都能看；**加购物车 / 下单时才要求登录** |
| C1.5 | 登出 | 服务端会话作废，再打需登录的接口返回 401 |
| C1.6 | 401 统一处理 | 令牌过期后任意请求 401 → 跳登录（不是白屏，这是 `unauthorized-handling` 守卫的运行时验证） |

## C5 · 三条履约闭环（重点 · 每条都是 C→B→C 一整圈）

**这是整份方案的核心**。每条都是：C 端下单付款 → **B 端接单处理** → C 端看到最终态。
判据是**每一步在两端各看一眼，状态一致**。

### C5-A · 快递闭环

| 步 | 端 | 判据 |
| --- | --- | --- |
| 1 | C 下快递单 + 付款 | 子单 `WAIT_FULFILL`；C 端订单页「待发货」 |
| 2 | **B 端接单发货**（填运单号） | `FULFILLING`；B 端订单卡转「已发货」 |
| 3 | C 端看订单 | 「已发货」+ **运单号可见** |
| 4 | C 端确认收货 | `COMPLETED`；可评价入口出现 |

### C5-B · 自提闭环（这个平台的主力）

| 步 | 端 | 判据 |
| --- | --- | --- |
| 1 | C 下自提单 + 付款 | `WAIT_FULFILL`；C 端有**自提码** |
| 2 | **B 端备货 → 标记到货** | `FULFILLING` + 核销码；C 端「可取货」 |
| 3 | **B 端核销自提码** | `COMPLETED`；C 端订单完成 |
| 4 | 反向：C 端出示的码 = B 端核销的码 | 两端同一个码 |

### C5-C · 自送闭环

| 步 | 端 | 判据 |
| --- | --- | --- |
| 1 | C 下自送单 + 付款 | `WAIT_FULFILL`；**B 端能看到完整收货地址**（自送单的地址曾经看不到，已修） |
| 2 | **B 端标记已送达** | `COMPLETED`；C 端「已送达」 |

## C6 · 售后（5 条 · C 端发起 → B 端处理，又一条闭环）

| # | 场景 | 怎样算过 |
| --- | --- | --- |
| C6.1 | 申请退款（仅退款） | 落 `ord_after_sale`；小额自动通过或进商家处理 |
| C6.2 | 申请退货退款 → **B 端同意** | C 端「等你寄回」；填退货运单号 |
| C6.3 | B 端确认收货 → 退款到账 | `REFUNDED` + **分账回退**（B 端 M7 验过后端，这里验 C 端可见） |
| C6.4 | **B 端驳回 → C 端上升平台** | C 端能发起 `escalate`，转 `ARBITRATING`（B 端 e2e 造的驳回单可复用） |
| C6.5 | 归集模式商家 | 售后直接进平台仲裁，C 端提示「平台处理中」（与 B 端 M7.5 对照） |
