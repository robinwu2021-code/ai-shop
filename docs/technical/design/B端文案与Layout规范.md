## 一、定位与适用范围

B 端是商家日常作业工具。界面优先展示对象、状态、数量、金额和下一步操作；说明只在影响当前判断时出现。

本规范补齐现有共享 UI 的 B 端使用约束，不另建组件库，也不覆盖生成版规范的真源。画布、字号、圆角、主题和层级仍以 `packages/shared/src/design/tokens.ts`、`packages/ui/src/styles/base.css`、组件源码为准；`ui-lib.json` 与生成版规范按原有生成链维护。

### 本次取舍

| 做法 | 取舍 |
|---|---|
| 只修字句与重复 key | 改动小，但不能解决页面各自定义表单尺寸、弹层和按钮层级的问题 |
| **沿用现有组件，统一文案语义与页面组装规则（建议）** | 维护现有三语、主题、RTL 和多端能力；先补规则，后分批迁移 |
| 重建 B 端设计体系 | 影响共享 UI 和 C 端，成本与本次目标不匹配 |

本次采用第二种做法；用户已于2026-10-26授权实施。当前清单按工作区源码统计，包含审查前已有的未提交变动。

## 二、文案标准

### 2.1 同一概念只有一个名称

| 概念 | 标准写法 | 区分边界 |
|---|---|---|
| 经营主体 / 门店 / 店铺 | 沿用对应领域名称 | 主体是证照/结算归属，门店是经营范围，店铺是顾客看到的门面；不能一律写“店” |
| 商品 / 规格 / 库存 | 商品、规格、可售库存、实物库存 | 规格不是商品；可售数与实物数不能都缩成“库存”而丢失口径 |
| 保存 / 提交 / 发布 | 保存草稿、提交审核、发布 | 仅保存才可用通用“保存”；影响线上需明确“发布” |
| 取消 / 作废 / 撤销 | 关闭当前操作用“取消”；业务单据按原状态机写“作废/撤销” | 关闭弹层不等于取消业务任务 |
| 移除 / 删除 / 停用 | 从关联中去掉、删除对象、保留对象但停止使用 | 不因中文暂时相同就合并这些动作 |
| 完成 / 已完成 | 动作用“完成”，状态用“已完成” | “券已核销”“打印完成”“付款完成”等业务状态保留对象语义 |

### 2.2 每类文字承担一件事

| 位置 | 写法 | 建议长度与目的 |
|---|---|---|
| 页标题 | 对象或任务，如“库存同步记录” | 中文通常 2–8 字；不写功能介绍，不重复到正文首行 |
| 分区标题 | 内容名称，如“收款账户” | 通常 2–8 字；同一层级不加副标题解释 |
| 按钮 | 动词，歧义时加对象，如“确认退款” | 通常 2–6 字；“保存并预览”等真实复合动作允许更长 |
| 字段标签 | 名词与必要单位，如“实收金额（元）” | 不写整句问题；不得只靠 placeholder 充当标签 |
| placeholder | 输入格式或示例 | 不重复“请输入”加字段名；必填与校验要求不只放在占位文字里 |
| 字段帮助 | 当前字段最容易填错的一点 | 通常一行；超过两行优先折叠，不隐藏必需条件 |
| 状态 | 状态名与必要数值 | “处理中”“待核实”；内部枚举、错误码不能直接作为主状态 |
| 空态 | “暂无 + 对象”，可操作时给一个入口 | 不归因网络，不把未加载/失败当无数据 |
| 错误 | 出了什么问题 + 怎么继续 | 可定位到字段就贴字段；请求失败提供重试；不显示堆栈 |
| 成功反馈 | 已完成的结果，如“已保存” | 不重复弹框与 toast；不能把“已受理”写成“已完成” |
| 危险确认 | 对象 + 后果 + 明确动作 | 不只写“确定吗”；保留不可恢复、金额、范围等决策信息 |

长度是中文编辑目标，不是截断规则；英文、阿语按完整意义翻译，数字、金额、姓名、编号不得为满足字数而丢失。

### 2.3 解释性文字的删减顺序

1. **删除界面自述**：“记录本店库存同步操作及处理结果。”重复页标题，无需常驻。
2. **删除操作解说**：“一件货一行，点开看……”由行布局与跳转箭头表达。
3. **缩短当前条件**：将“这家店的库存以进销存为准，这一页只是展示……”改为“库存由进销存管理”，保留“进货/盘点”入口。
4. **把规则放到相关控件旁**：例如长期有效的证照，日期字段旁写“长期有效可留空”，不在页头再解释一遍。
5. **低频原理移入帮助**：统计口径、人群动态计算、跨店规则等放“统计口径/规则说明”，首次使用或切换模式时按需展示。
6. **风险说明在决策处保留**：退款、重复出纸、发布覆盖、实物与可售库存差异、隔离库存、过账不可修改等信息不能被统一折叠掉。

一屏默认只有一处常驻页级提醒，多个问题合并成明确的待处理入口；字段错误可多处同时显示。此限制不适用于必须逐项核对的风险、必填信息与业务证据。

### 2.4 格式

- 中文句子使用中文标点；短标题、标签、按钮、状态不加句号。说明文字按完整句子处理。
- 数量与单位必须来自完整词条及参数；不用 `t('申请') + n + '件'` 拼句，避免英文、阿语语序错误。
- 金额、日期、时区、单位继续使用现有 `money`、日期和单位格式工具，不在词条中固定货币或拼接货币符号。
- 商品名、门店名、地址、备注等用户内容不塞进静态 i18n 词库；业务实体的多语内容与界面词条分开处理。
- 不将“可能”“一般”“平台后端”“占位值”“表单待接入”等内部实现说明当作常驻产品文案。未接入能力应明确可用状态，并由产品确认入口的隐藏或禁用方式。

## 三、i18n 共用规则

### 3.1 唯一 key 的判定

**同样的动作、同样的对象边界、同样的占位符和显示语境，使用同一 key。** 中文相同是审查线索，不是批量替换依据。三语中的任一语言意义不同，先确认语义，再选标准译文。

| 范围 | key 归属 | 例子 |
|---|---|---|
| 无业务对象的通用操作 | 现有 `common.*` | `common.save / cancel / confirm / done / remove / delete / submit / search / retry` |
| 通用反馈与访问状态 | 现有 `common.*` | `common.saved / loading / loadFailed / noPermTitle / sessionExpired` |
| 页面对象、业务后果、独有校验 | 对应领域命名空间 | `goods.publishStale`、`stockCheck.cutoffHint` |
| 后端状态与枚举 | 领域状态映射 | 保留原枚举 key，不用通用操作文案替代状态 |
| 共享组件默认文字 | B 端词库提供共享 key | 组件不得内置中文，也不强制 C/B 两端共用同一个词库文件 |

需要新增的通用 key（如后续确认统一“清除”）必须先查现有词库，三语同步新增。不能先在中文里新建再依赖 fallback。

### 3.2 本轮已实施的优先映射

| 当前 keys | 建议目标 | 条件 |
|---|---|---|
| `mySpecs.save`、`goods.save`、`activityEdit.save`、`couponEdit.save`、`memberDetail.saveTags` | `common.save` | 通用保存；调用位置仍应明确保存对象，发布动作不改为保存 |
| `mySpecs.saved`、`notifySetting.saved`、`shipSetting.saved` | `common.saved` | 均为完成保存后的反馈 |
| `qual.submit`、`invoice.submit`、`payoutAccount.submit` | `common.submit` | 若按钮需要说明审核/开通后果，优先保留具体业务动作 |
| `mySpecs.cancel`、`activityEdit.cancel`、`couponEdit.cancel`、`audience.cancel`、`batchTag.cancel` | `common.cancel` | 关闭/放弃当前输入；需要放弃改动确认的行为继续保留 |
| `rechargeActivity.remove`、`mySpecs.remove` | `common.remove` | 从当前集合移除一项 |
| `home.inv.all`、`order.tabAll`、`message.tab.all`、`stock.tabAll`、`stockCross.tabAll`、`reachTasks.tab.ALL` | `common.all` | 不带对象的筛选标签；“全部账期”需要具体对象时不纳入 |
| `goods.restrictedDone` | `common.done` | 完成当前选择，而非业务状态变为完成 |
| `audience.ok` | `common.confirm` | 先统一英文与阿语当前不同的译法 |

同义静态调用已迁移；历史审查中的重复词条按语义区分并迁移；[全量清单](./reviews/b-app-ui/inventory.md)展示当前词库。例如 `printCenter.action.CANCEL` 为实际取消打印任务，`couponIssues.done` 为状态，不能只因显示“取消/完成”就并入关闭弹层的 key。

### 3.3 迁移与验收

1. 列出旧 key、目标 key、三语译文、调用点、动态引用和上下文，先确认动作含义。
2. 目标 key 在三语存在且占位符一致后，再替换页面与组件引用；状态映射及动态 key 清单单独核对。
3. 只有证明无静态引用、动态引用、共享 UI 默认值或枚举映射后才能删除旧 key。**静态未命中不等于没用。**
4. 同一批修改三语并执行词条一致性、key 存在性检查；中文、英文、阿语分别查看按钮、表单与弹层。
5. 当前共享引擎把词条编译为消息函数，继续使用 `{name}` 命名插值。不引入当前引擎未支持的 `@:` 链接词条去“复用”文字。

## 四、组件使用规范

当前组件、页面调用关系、props、内部依赖及原生控件均记录在 [inventory.md](./reviews/b-app-ui/inventory.md) 与其 JSON 明细中。本轮增加的 `biz-rule-help` 只组合已有文字入口与 `sh-sheet`，用于按需查看规则。

| 类别 | 现有件 | 使用规则与防止的问题 |
|---|---|---|
| 页面壳 | `sh-scaffold` | 每页唯一根壳，统一标题、权限、失败、安全区、主题与 RTL；不再造第二个页面容器 |
| 应用常驻层 | `sh-tabbar`、`sh-prompt`、`sh-confirm`、`sh-pick`、`app-overlay` | 由外壳组织；不能因页面直接用量为 0 就删除 |
| 内容状态 | `sh-empty`、`sh-trace` | 空/加载/失败分开，轨迹使用一致结构；不能拿空态表达请求失败 |
| 导航与信息 | `sh-tabs`、`sh-section`、`sh-kv`、`sh-stat`、`sh-go` | 分别承担筛选、区块标题、键值行、统计、入口；标题不能充当说明段落 |
| 操作 | `sh-actionbar`、`sh-savebar`、`sh-fab`、`sh-add`、`sh-icon-btn` | 按实际任务选一种主操作入口，统一占位和点按区域；不逐页实现 fixed 底栏 |
| 输入与选择 | `sh-check`、`sh-switch`、`sh-stepper`、`sh-option`、`sh-uploader` | 控件保留禁用、忙碌、校验状态；原生 input/textarea/picker 配合公共 field 类使用 |
| 视觉与评价 | `sh-icon`、`sh-cover`、`sh-rating` | 图标、封面与评分使用已定义尺寸和语义；不以 emoji 代替操作图标 |
| 浮层与偏好 | `sh-sheet`、`sh-dialog`、`sh-theme-sheet` | 内容/选择用 sheet，明确决策用 dialog；外壳负责滚动、关闭、层级与安全区 |
| 业务选择 | `biz-audience-picker`、`biz-batch-tag-sheet`、`biz-item-picker`、`biz-supplier-picker`、`biz-category-sheet` | 业务件只封装对应数据与交互，尽量复用共享浮层和输入；不复制蒙层 |
| 门店与范围 | `biz-store-tag`、`biz-switch-curtain`、`biz-region-picker`、`biz-scope-text`、`biz-pickup-sheet`、`biz-time-range` | 当前门店明确且一致；切店语义不因页面而变，地图/范围例外留在业务层 |
| 积分账单 | `StorePointStatements` | 财务账单的明细、修订、确认与异议保持业务语义；不当作普通列表组件 |
| 按需说明 | `biz-rule-help` | 页内保留规则入口，长说明放入共享 sheet；必要风险仍直接显示在决策位置 |

页面局部 class 只表达业务排版。组件的尺寸、颜色、圆角、禁用态由组件或全局原语负责；页面不得用 `.field__input`、`.sh-btn` 等同名选择器重新制定规格。`flex:1` 等调用点布局确有必要时，挂页面语义 class，说明作用域。

不要求所有布局变成 Vue 组件：`sh-card`、`sh-block`、`sh-cells`、`sh-row` 等公共类也是规范原语。先复用；出现多个同语义结构时再决定抽公共组件，避免用一个拥有大量开关的组件承载所有页面。

## 五、Layout 规范

### 5.1 层级与职责

```text
sh-scaffold：标题、主题/RTL、页面边距、安全区、权限/加载/失败
  ├─ 当前门店/状态提示：有必要时出现，不重复标题
  ├─ sh-tabs / 搜索：只影响本页内容
  ├─ sh-card / sh-block / sh-cells：按内容语义选择一层容器
  │    ├─ sh-section：分区标题与局部动作
  │    └─ sh-row / sh-kv / field：信息或输入，不再套同类白卡
  └─ sh-actionbar / sh-savebar：主操作与相应占位
浮层：sh-sheet / sh-dialog，业务组件只提供内容
```

页面壳管外边距，卡片管内边距，子项管项间距，操作条管自身占位。每一层只承担一份留白，防止卡中卡、双重左右缩进和重复底部空白。

### 5.2 尺寸与密度

| 项目 | B 端规则 | 真源/边界 |
|---|---|---|
| 页面横向留白 | `--sh-pad-page: 24rpx` | `b-app/src/App.vue`；不逐页覆盖 |
| 卡片内边距 | `--sh-pad-card: 24rpx` | 与页边距对齐；通铺容器不再重复加卡片留白 |
| 空态留白 | `--sh-pad-empty: 48rpx` | 不用空态填满屏幕 |
| 筛选与内容间距 | `--sh-gap-tabs: 16rpx` | 优先语义变量 |
| 分区间距 | `--sh-gap-block`，当前默认 20rpx | 页面不另造相近数值 |
| 字段纵向间距 | `.field` 当前 20rpx | 首项不需要外空隙时由明确的表单结构控制；不复制定义 |
| 输入框 | 公共 `.field__input`：高 88rpx、左右 24rpx、圆角 24rpx | 不能缩成 76rpx；特殊内嵌输入需独立语义与可用性验收 |
| 正文/次要字 | 正文 28rpx；B 端 `.sh-muted` 取 `--sh-fs-sub: 24rpx` | 字阶工具类另按规范·字体；不要误以为变量会改写所有 `txt-sub` |
| 圆角 | 16 / 24 / 32 / 44rpx，胶囊 9999px | 不按页面新增近似档 |
| 间距网格 | 通常使用 4rpx 倍数，优先现有语义变量和工具类 | 现有 `2rpx` 微调、分隔线、图标光学对齐单独审查，不机械取整 |
| 点按目标 | 至少 88rpx 的目标区域或等效 `sh-hit` 扩展 | 缩小视觉不能同时缩小可点区域 |
| 宽屏 | >600px 沿用外壳的 375px 版心与内部滚动 | 与 `pages.json` rpx 规则一起维护；不添加独立桌面断点 |

当前工具类的 `sm/md` 不可按变量名猜值：例如 `.sh-mt-sm` 为 16rpx，`.sh-mt-md` 为 28rpx；以 CSS 为准。屏幕上相邻标签与数字用 `sh-row`，折行标签用 `sh-wrap`；不要把 4rpx 网格误写成只允许五个间距值。

### 5.3 页面模板

| 类型 | 固定内容顺序 | 主操作位置 |
|---|---|---|
| 工作台 | 当前门店 → 待处理 → 核心统计 → 业务入口 | 任务入口就近；不在顶部加整页使用说明 |
| 列表页 | 标题/门店 → 搜索/筛选 → 计数（需要时）→ 列表/空/失败 | 单一新建入口；列表每行显示主对象、主状态、关键值与少量动作 |
| 编辑页 | 标题 → 分区标题 → 标签/控件 → 当前错误/必要帮助 | 单一保存/提交条；原有页若为行内表单可就近操作，不重复底栏 |
| 详情页 | 对象与状态 → 关键金额/数量 → 分区键值 → 明细/轨迹 | 底部显示当前状态可执行的主要动作 |
| 设置页 | 当前范围 → `sh-cells` 分组设置 → 必要状态 | 自动保存与显式保存不混用；有未保存改动时用 savebar |
| 财务/库存报表 | 门店/周期 → 关键指标 → 明细 → 口径入口 | 不用长解释挤占首屏；金额/数量列对齐 |
| 弹层 | 标题 → 选择/输入内容 → 校验/必要风险 → 确定操作 | 不重复完整页面导航；长内容在壳内滚动 |

### 5.4 行、文字与动作

- 同字号左右排用 `sh-row sh-row--between`；字号不同时增加 baseline；右值会换行时用 top 形态。
- 主对象一侧使用 `sh-fill`/`min-width:0`，状态、金额和操作保留空间。长商品名可以省略并可进入详情；关键金额不可只显示省略号。
- 只读键值对用 `sh-kv`：资料使用默认定宽键列，账目使用 `between`。连续录入字段使用 `field → field__label + field__input` 的上下结构；不要将连续输入框直接塞进无间距的键值行。英文标签允许换行，不用更小字号挤进中文宽度。
- 字段组间距由B端 `.field` 的20rpx负责；标签到控件12rpx，说明使用 `sh-hint` 的8rpx上距，照片区单独一组，主次操作间距16rpx、操作区上距24rpx。不要仅凭“无横向溢出”验收，须检查输入底色不相接、标签与所属控件的距离、按钮和照片区的分组。
- 一块内容只强调一个主操作；其他操作使用已存在的次级按钮/文本入口；危险动作有明确后果和二次确认。
- 使用逻辑方向的 `padding-inline`、`margin-inline`、`text-align:start/end`；编号与金额在 RTL 下单独核对，不把整个页面强制 LTR。

### 5.5 加载与浮层

- 页面级状态顺序沿用外壳：无权限 → 加载失败 → 首次加载 → 内容。列表为空只在首轮请求完成后确认；刷新不应抹掉已有内容。
- `sh-empty` 的 `bare` 用于卡内，防止空态再套卡。刷新错误与无内容分开，重试入口必须可用。
- `sh-actionbar`、`sh-savebar` 已负责占位。Tab 页正确传入 `tabbar`；多行操作核对 `pad`，不能假设默认高度适用于所有翻译长度。
- 蒙层与面板优先复用 `sh-sheet/sh-dialog`；层级使用现有 `--sh-z-*`。切店幕布、透明点击拦截层等特例先说明职责，不能把所有 fixed 都判为违规。
- 不在本轮要求重排共享 UI 的 z-index。若新增浮层出现遮挡，单独验证导航、底栏、sheet、dialog 的实际叠放关系，再调整真源。

### 5.6 组件组合的强制约束

同一处间距只有一个所有者。外壳负责区块之间，卡片负责内容到边缘，组合容器负责子项之间，组件负责自身内部。不能用“没有横向溢出”替代组件对齐与留白验收。

| 组件/积木 | 摆放与间距约束 | 禁止事项 |
|---|---|---|
| `sh-scaffold`、`sh-tabbar` | 顶层区块沿用外壳间距；底部菜单由外壳挂载 | 页面另写同类 fixed 底栏、重复安全区/外边距 |
| `sh-card`、`sh-block`、`sh-cells` | 同一语义内容选择一层容器；卡片内多组控件用 `sh-stack`，设置清单使用 `sh-cells` | 把卡片内边距当成子项间距，连续控件裸贴 |
| `sh-section`、`sh-card__head` | 标题和局部动作在同一行；卡头负责与下方内容的分隔 | 在 `sh-stack` 内再叠加卡头外边距，标题与内容同一行粘连 |
| `field`、`field__label/input/area` | 连续录入按字段分组，标签到控件12rpx；普通流字段上距20rpx | 连续全尺寸输入塞进无间距的 `sh-kv`；仅靠 placeholder 代替必要标签 |
| `sh-stack` | 显式纵向布局，gap=20rpx；直接子项的 `field/sh-hint` 外边距归零；原生按钮清除自动外边距并撑满 | 直接子项另加正/负纵向 margin；叠加父 gap 与子 margin |
| `sh-actions`、`sh-btn` | 横向等宽操作组，gap=16rpx；按钮以200rpx基准宽度自动换行；长标签允许换行 | 多个按钮裸堆；继承原生按钮 auto margin 变成窄药丸；固定高度截字 |
| `sh-row`、`sh-wrap` | 单行图文/复合输入用 row，gap=16rpx；可折行标签用 wrap，gap=12rpx | 只写 gap 不启用 flex/grid；把多组纵向表单当横排 |
| `sh-kv` | 只读资料/账目使用原有定宽或between；已有单值日期选择可保留行内布局与点击目标 | 包含 input/textarea 的全尺寸编辑字段；未验证就把紧凑只读行改成表单 |
| `sh-tabs` | 作为区块直接放置；长标签及窄屏验证换行/滚动 | 页面为 tab 内部另加重复横向内边距 |
| `sh-stat` | 等列指标作为一组；标题在指标组外；单位和值保留可读空间 | 把多指标拼成长说明，指标和动作混成同一行 |
| `sh-check`、`sh-switch`、`sh-stepper`、`sh-rating` | 标量控件在独立行，与标签留gap；控制大小由组件决定；只有一处点击状态更新职责 | 文字字符冒充控件；点击行和控件各切换一次；压缩控件给长标签让路 |
| `sh-option` | 选择卡片的内排版由组件负责；父级使用stack或wrap组织多个选项，说明归入选项内容区 | 在选项里嵌套竞争的点击按钮，父级与选项重复加外边距 |
| `sh-uploader`、`sh-cover` | 单独图片区/字段组；使用组件真实props；证照与商品图按内容选择比例 | 传失效别名后依赖默认尺寸；图片区紧贴说明或动作 |
| `sh-icon`、`sh-icon-btn` | 图标与文字通过row对齐；图标按钮保留命中区域；方向图标沿用RTL处理 | emoji/字符替代UI图标，负margin挤进文字，页面重画命中规格 |
| `sh-go`、`sh-add` | 一行入口/添加动作，放在其归属分区；多个操作需要明确动作组 | 把入口当区块标题，重复主操作 |
| `sh-actionbar`、`sh-savebar`、`sh-fab` | 浮层负责位置及占位；多按钮显式使用动作组；多行内容核对pad与最后一行可滚达 | 默认actionbar直接塞两枚纵向按钮、上下相接；漏占位 |
| `sh-sheet`、`sh-dialog` | 弹层负责壳、滚动及安全区；正文按字段/stack排版；dialog动作槽沿用组件间距 | 把外层浮层节点当普通stack子项计间距；动作槽再叠一层无意义间距 |
| `sh-confirm`、`sh-prompt`、`sh-pick`、`sh-theme-sheet`、`app-overlay` | 由外壳/既有入口挂载，沿用组件内部排版 | 页面复制覆盖层、层级、边距与动作布局 |
| `sh-empty`、`sh-trace` | 空态只占所属区域，卡内空态用bare；轨迹正文在可伸缩列中换行 | 同时显示空/失败/正常内容；卡内再套大留白空态 |
| `biz-audience-picker`、`biz-batch-tag-sheet`、`biz-category-sheet`、`biz-item-picker`、`biz-pickup-sheet`、`biz-region-picker`、`biz-supplier-picker`、`biz-rule-help` | 沿用统一sheet壳；列表、搜索与动作独立分组；隐藏时不占文档流 | 给弹层宿主补页面margin、改写基础面板内边距 |
| `biz-scope-text`、`biz-store-tag`、`biz-time-range` | 范围标签/门店/时间段放在对应内容之前；由父级区块留白 | 为相同范围重复占行，长标签挤压操作 |
| `biz-switch-curtain` | 全屏切店业务遮罩保持现有基础定位 | 当普通内容块塞进stack，改变切店期间覆盖范围 |
| `StorePointStatements` | 账单行使用纵向组，争议输入单独field，确认/异议使用动作组 | 修订明细、输入、两按钮连成同一块；改变账单确认逻辑 |

组合示例：卡片加 `sh-stack`，内部字段直接放 `field`，两枚按钮放一个 `sh-actions`。普通流继续使用既有 `.field` 间距；紧凑的搜索+按钮/金额+单位保留 `sh-row`。不要为了统一外观改变只读数据、权限或业务动作。

自动检查由 `npm run check:ui -w ai-shop-b-app` 执行，并已接入B端 `npm test`：

- 拦截已知组件的未知props（class/style/id、aria/data和事件指令除外）。
- 拦截sh-kv中的文本编辑控件、相邻控件组无间距声明、组合容器与子项同时拥有纵向间距。
- 解析真实Vue/CSS结构；检查条件分支、透明template、dialog动作槽、逻辑边距及选择器优先级。注释中的类名不算定义；没有flex/grid的gap不算布局。
- 卡片标题分隔等需要上下文的情况列为人工复核候选，不用宽泛例外让整页免检。

每批验收须用中文在320/375/430px实际测量：控件矩形不相交、独立控件之间间距大于0、同组按钮对齐且宽度合理、长标签不压按钮、无横向溢出、最后内容与按钮可滚达。静态声明检查不模拟所有媒体查询、原生控件或软键盘；真机仍需单独验收。页面和组件清单见 [源码清单](./reviews/b-app-ui/inventory.md)。

## 六、后续页面迁移验收
