## 一、六条挡路的（[开发计划 §四](./进销存-开发计划.md)）

| # | 决策 | **定为** | 影响 |
|---|---|---|---|
| A | 预售额度归属 | **留平台**（`presale_quota` / `sold_count` 不进进销存） | 它是销售策略不是货；`available` 只有一个口径 |
| B | `prd_sku.stock` 只读缓存 | **保留** ＋ 对差看板**长期留着**当防漂守卫 | 可售判定不跨库 |
| C | 存量搬运 | **低峰跑 ＋ 双写对差期，不设回退** | 回退比对差更危险 |
| D | 权限码 `product:stock:read` | **新增** | 只读页挂写码 = 只有能改的人才看得到账 |
| E | B 端九屏入口 | ~~底部 tab 换成「库存」~~ → **撤回**（2026-09-02）：实际落地为**工作台一张进销存卡**（四个数 + 三个随状态变的快捷），底部 tab 未动 | 撤回理由：卡同时给出四个数，tab 只给一个入口；且不必挤掉「商品」 |
| F | Open API | **解禁**：只做接口，不做 ERP | 与「不做大商家能力」的边界写在交互契约里 |

## 二、领域与数据（[领域模型](./TDD-进销存领域模型.md) · [对象详解](./进销存-领域对象详解.md) · [表结构](./进销存-数据库表结构.md)）

| 决策 | 定为 |
|---|---|
| `on_hand` 允许为负 | **绝不允许** |
| 部分收货（到货 100 收 98） | 一期**不做**，字段已留位 |
| 盘点时冻结该库位出库 | **不冻结**，靠 `book_qty` 快照 |
| `reason_code` 冗余到流水 | **采纳**（快照，不是真源） |
| 批次 / 效期 / 序列号 | 一期**只留位**（`track_batch` / `batch_no` / `expire_at`） |
| 物理库 | **先同实例 ＋ 守卫**，D4 再拆物理实例 |
| `Owner` : `entity_no` | **1:1** |
| 成本口径 | **最新进价 / 手工价**二选一，不做移动加权 |
| 独立交付形态是否自带 UI | **不带**，按 SDK/API 交付（D5 范围） |
| 仓占不占门店额度 | **占** —— 否则 `CHAIN` 档白送仓 |
| `rpt_` 前缀 | **登记**为新域前缀（平台侧，不在 inv 库） |

## 三、接口与代码（[API 四层对齐](./进销存-API与四层对齐.md) · [代码结构](./进销存-代码结构与现状对齐.md)）

| 决策 | 定为 |
|---|---|
| B 端路径 | `/biz/inventory/**`（不用缩写 `inv`） |
| `GET /documents` | **四张头表 union**，一个端点 |
| 单件「改数」便捷端点 | **给** —— 三次往返换一次点击不值 |
| 报表在 D3 前直接聚合流水 | **可接受**；`inv_daily_snapshot` 是量上来之后的事 |
| DTO 组织 | **按用途聚合**（`InventoryVOs` 等），与 `FinanceVOs` 一致 |
| Controller 拆法 | **按资源拆，不按屏拆**（余额/单据/盘点/调拨/库位/报表六类） |
| 模块名 | `shop-inventory`（对齐今天的 `shop-settle` / `shop-merchant`） |
| `cost_price` 写权 | 移到进销存，平台侧**无写入口** |
| 写权守卫红了怎么办 | **拦提交**，不只报告 |

## 四、交互与前端（[交互契约](./进销存-与其他模块的交互契约.md) · [三端落点](./进销存-三端落点与功能矩阵.md)）

| 决策 | 定为 |
|---|---|
| 缺件上报是否自动建盘点单 | **只给入口，不自动建** —— 自动生成盘亏 = 系统替商家判责 |
| 投影延迟 | **同步投影 ＋ 失败降级异步**，常态下建完就能入库 |
| `commit` 失败的补偿窗口 | **24 小时**，超时进运营异常单 |
| 单位字典维护落点 | **并入 `/system` 现有字典页**，不新增 tab |
| 张姐这类商家是否隐藏单据中心 | **不隐藏**，但入口排序靠后 |
| 安全库存默认值 | **全 0**（不预警）—— 猜错的预警比没有预警更烦 |
| 对差看板 | **长期保留**（与 B 同一条） |
| 运营端菜单落点 | ~~挂 `/products` 的「库存与预售」组，不新建 L1；`sort` 取 41–43~~ → **已作废**（`V261` 落库）：实际是**独立顶级模块 `/inventory`**，四个 tab，`sort=45`，权限码 `inventory:*` |

### 底部 tab 换哪一个（决策 E 的下半段）—— ⚠️ 已随 E 一并撤回，下文保留记录当时的权衡

现有五个：工作台 · 订单 · 商品 · 我的 ＋ 一个。**「库存」替换掉「商品」的位置**，
商品移入库存页的二级入口 —— 判据是**打开频次**：商家一天开几十次库存（备货、改数、看缺货），
而商品是建完就不常动的主数据。

> ⚠️ 这一条影响现有页面的可达性，**落地时要同时补商品的新入口**，
> 并逐屏 `grep navigateTo` 验（需求 B-0）。
