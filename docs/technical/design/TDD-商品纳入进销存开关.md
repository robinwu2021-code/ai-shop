# TDD · 商品纳入进销存开关

> 状态：**方案待确认** · 2026-09-21

## 1 现状

| 事实 | 证据 |
|---|---|
| **每个 SKU 一建就进进销存**，没有任何判断 | `InventoryItemProjectionConsumer` 消费 `SKU_UPSERTED` → `acl.upsertItem`，只看 entityNo/skuNo 在不在 |
| 服务类商品（家政保洁）也建了物料 | 同上，不看类目模板 |
| 线上是双写：**商城库存是真相源**，进销存跟着记 | 生产 `SHOP_INVENTORY_STOCK_AUTHORITY=DUAL`；`DualWriteStockPort` 平台先扣，再经 outbox 由 `InventoryMirrorConsumer` 补记 |
| 两本账在界面上已经分开说 | B 端「改库存」弹层：「进销存记着 0……这里改的是商城显示的数，两本账各记各的」 |
| 物料已有停用态 | `inv_item.status` ACTIVE / ARCHIVED，归档不删流水；另有 `source_on_sale`（V5）、`retired_at`（V7） |
| 权威切换是**全局**的 | `stock-authority` 一个环境变量管全平台：PLATFORM / DUAL / INVENTORY |

**所以问题是**：服务、代销、按次卖的东西都被当成货在记，店主在进货/盘点/挑货里看到一堆
「家政保洁 · 2 小时」这种永远不会有进货单的物料；而他没有任何地方能说「这一类不用管库存」。

## 2 概念

**纳入进销存**（`库存管理`）：这件商品的 SKU 在进销存里**有物料、参与进货 / 盘点 / 调拨 / 出库、
下单时同步扣进销存**。不纳入的商品**只用商城库存**（「改库存」改的那个数），进销存里看不到它。

两级设置，**单品优先于品类**：

| 层级 | 取值 | 谁设 | 存哪 |
|---|---|---|---|
| 单品 | 跟随品类（默认）/ 纳入 / 不纳入 | 商家，编辑商品页 | `prd_goods.inv_mode`：`INHERIT` / `ON` / `OFF` |
| 品类 | 纳入 / 不纳入 | 商家，进销存设置页 | 新表 `prd_entity_category_inv`（稀疏，没行 = 用平台默认） |
| 平台默认 | 按类目模板 | 代码常量 | `STANDARD` / `FRESH` → 纳入；`SERVICE` / `VOUCHER` / `VIRTUAL` → 不纳入 |

生效值 = 单品 `ON`/`OFF` ? 单品 : (本主体给这个品类设过 ? 那个值 : 平台默认)。

**品类设置挂在主体上，不挂门店**：商品与进销存物料都属于主体（`inv_item.owner_id` = entityNo），
同一件货在 A 店纳入、B 店不纳入的话，这件物料的账就说不清了。
**单品设置挂在商品上，不挂 SKU**：同一件商品的「5 斤装」管库存、「10 斤装」不管，没有这种真实需求，
做到 SKU 级只会多一个没人用的开关。

## 3 设计

### 3.1 后端（商品域决定，进销存域照做）

**判断只在商品域做一次**，进销存那边不认识类目模板、也不该认识。

| 位置 | 改动 |
|---|---|
| `prd_goods` | 加 `inv_mode VARCHAR(8) NOT NULL DEFAULT 'INHERIT'`（迁移 + 实体字段，别漏补实体） |
| 新表 `prd_entity_category_inv` | `(entity_no, category_no, managed TINYINT)`，唯一键两列；稀疏 |
| `InvManagedResolver`（商品域） | `isManaged(entityNo, goods)` 按上表三级取值；类目换了跟着换 |
| `ProductEvents.SkuUpserted` | 载荷加 `invManaged` —— 投影据此决定建物料还是归档 |
| 新事件 `GOODS_INV_MODE_CHANGED` | 开关一变就发（与 `InventoryOnSaleConsumer` 同理：改开关时 SKU 内容一个字没变，`SKU_UPSERTED` 根本不会发） |
| `InventoryItemProjectionConsumer` | `invManaged=false` → 不建；已有物料 → 归档（`status=ARCHIVED`） |
| `DualWriteStockPort` | **不纳入的 SKU 不入镜像队列** —— 平台照扣，进销存不记 |
| 端点 | `GET/PUT /biz/inventory/category-settings`（品类开关）；商品保存体加 `invMode` |

**切换的规则**（开 → 关 最要紧）：

| 动作 | 处理 |
|---|---|
| 不纳入 → 纳入 | 建物料（余额 0），提示店主「去做一次期初盘点」—— **不自动把商城库存抄过去**：抄过去就是没有单据的库存，对账时说不清来源 |
| 纳入 → 不纳入，有**在途单据或未完结预留**（未收货的采购、未完成的调拨、未释放的锁库） | **拒**，列出是哪几张单，先处理完再关 |
| 纳入 → 不纳入，**库存不为 0** | 二次确认后归档：余额与流水**只读保留**，不再出现在进货/盘点/挑货里，库存报表不再计入；重新纳入时原样恢复 |
| 纳入 → 不纳入，库存为 0 且无在途 | 直接归档 |
| 品类开关一次影响多件商品 | 逐件套上面的规则；有被拒的，**整批不动**并列出原因（半开半关比不动更难收拾） |

**`stock-authority=INVENTORY`（未来 G3 切换）前必须补的**：`InventoryStockPort` 现在是全局的，
切过去之后不纳入的 SKU 在进销存里没有余额，会被当成「0 库存」拒单。**要改成按 SKU 分流**：
纳入的扣进销存，不纳入的扣商城库存。本次方案只做 DUAL 下的部分，这一条写进切换手册的前置条件。

### 3.2 B 端

- **进销存设置 →「纳入进销存的品类」**：列本主体各门店经营类目的并集，每类一个开关，
  旁边写「影响 N 件商品」；服务类默认关、实物默认开
- **编辑商品 · 库存那一段**：一行「库存管理」：`跟随品类（纳入）` / `纳入进销存` / `不纳入`，
  括号里写当前品类的生效值，让他知道「跟随」跟的是什么
- **商品列表**：不纳入的商品标「不入库存」；「改库存」弹层对它不再提进销存那本账
- **进货 / 盘点 / 调拨 / 出库 / 挑货 / 库存清单**：只列纳入的（归档物料本来就不列，免改）
- 文案不出现「投影」「物料」这类内部词（B 端文案规矩）

### 3.3 C 端

不改。C 端只认商城库存。

### 3.4 报表

经营报表（销售额、订单）**全部商品都算**；库存报表（库存金额、周转、缺货、滞销）**只算纳入的**。
两张报表口径不同要在页面上写一句，否则店主会拿两个数相减。

## 4 存量怎么落

| 存量 | 处理 |
|---|---|
| 全部商品 | `inv_mode` 默认 `INHERIT` —— 行为由品类决定 |
| 实物 / 生鲜类的商品 | 平台默认纳入 → **与今天一样**，不动 |
| 服务类商品（家政等）已经建了物料 | 平台默认不纳入 → 迁移后跑一次回填：**余额为 0 且无在途的归档**；有余额或在途的不动，列一份清单给运营看 |

**回填前先量**：线上有多少件服务类物料、其中几件有余额。量出来再跑，不改数据的那一步先做。

## 5 不做什么

- 不做 SKU 级开关（见 §2）
- 不做门店级品类开关（见 §2）
- 不把商城库存自动抄进进销存（见 §3.1 开的那一行）
- 不动 `stock-authority` 的全局切换；INVENTORY 档的按 SKU 分流单独立项

## 6 验证

- **投影**：服务类商品保存后没有物料；把它单品设成「纳入」→ 出现物料；再设回「跟随」→ 归档
- **镜像**：DUAL 下给不纳入的商品下单 → 商城库存扣了、进销存一笔流水都没有；纳入的两边都记
- **拒关**：有未收货采购单的商品设「不纳入」→ 拒且列出单号；关掉之后库存清单里看不到它、流水仍能查
- **品类批量**：一类里有一件被拒 → 整类不动
- **消融**：去掉投影里的 `invManaged` 判断，第一条必须变红；去掉镜像里的判断，第二条必须变红
