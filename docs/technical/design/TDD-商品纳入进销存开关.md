## 0 一句话

**以门店为单位，一家店一本实存账（进销存门店库位），线上卖的数是从这本账里按规则分出来的额度；
线上下单与线下卖出都扣同一本实存。** 不需要做库存的商品不进这本账，只用商城库存。

## 1 现状

| 事实 | 证据 |
|---|---|
| 每个 SKU 一建就进进销存，服务类也不例外 | `InventoryItemProjectionConsumer` 消费 `SKU_UPSERTED` 无条件 `upsertItem` |
| 线上是双写：**商城库存为准**，进销存跟着记 | 生产 `SHOP_INVENTORY_STOCK_AUTHORITY=DUAL`；`DualWriteStockPort` 先扣平台，再经 outbox 由 `InventoryMirrorConsumer` 补记预留 / 出库 / 释放 |
| **只有商城 → 进销存一个方向** | 进货入库、盘点、调拨、报损只改进销存；「改库存」只改商城。B 端弹层原话「两本账各记各的」 |
| 商城库存按门店 | `prd_store_stock`（`store_no, sku_no` 唯一；`stock` 总量、`locked_stock` 已锁） |
| 进销存按库位，门店与库位能对上 | `inv_location.kind=STORE`，`external_ref = mch_store.store_no`；另有 `source_location_id`（这家店从哪个库位发货） |
| 余额 | `inv_stock_balance`：`on_hand` 实存（只有单据过账能改）、`reserved` 已预留 |
| **线下卖货无处可记** | 出库单 `purpose` 有 `SALE` / `TRANSFER_OUT` / `SCRAP` / `COUNT_LOSS` / `INTERNAL`，其中 `SALE` 必须挂线上订单的预留；没有「柜台卖出」 |
| 每日对差只读 | `InventoryReconJob`：逐条比两边，只报不改 |
| 物料可停用 | `inv_item.status` ACTIVE / ARCHIVED，归档不删流水 |

## 2 概念：一家店的三个数、两条路径

以**门店**为单位（门店 ↔ 它的门店库位 ↔ 它的商城库存，三者一一对应）：

| 数 | 是什么 | 谁改它 |
|---|---|---|
| **实存** | 这家店货架上真有多少（`inv_stock_balance.on_hand`） | 只有单据：进货入库、盘点、调拨、报损、**线下卖出**、线上订单出库 |
| **可用** | 实存 − 已被线上订单占住的 − 安全库存 | 算出来的，不存 |
| **线上可售** | 顾客在商城看到的「还剩几件」（`prd_store_stock.stock − locked_stock`） | 按「线上可售规则」从可用算出来，写回商城 |

**两条路径都扣同一本实存**：

- **线上**：顾客在商城下单 → 扣线上可售 → 进销存占用 → 出库时扣实存
- **线下**：店员在 B 端「线下卖出」→ 进销存出一张柜台卖出单 → 实存减少 → 线上可售跟着重算

**为什么不用「调拨」把货调给线上**：调拨表达货物真的换了地方（店 → 仓、A 店 → B 店）。
线上卖的和柜台卖的是同一个货架上的同一批货，硬拆成两个库位，盘点时货架上 100 件、账上却分成两处，对不上；
每次补线上还要开一张假调拨单。**线上可售是额度，不是库位。**
例外：店里真有一个独立的线上仓 / 前置仓、线上订单从那里发货 —— 那是真实库位，用现有调拨，见 §11。

## 3 决策一：哪些商品纳入进销存（主体级）

纳入 = 这件商品有实存账，参与进货 / 盘点 / 调拨 / 线下卖出，线上可售按规则从实存算；
不纳入 = 只有商城库存一个数，店主手动维护。

两级设置，**单品优先于品类，都没设用平台默认**：

| 层级 | 取值 | 在哪设 | 存哪 |
|---|---|---|---|
| 单品 | 跟随品类（默认）/ 纳入 / 不纳入 | 编辑商品 · 库存管理 | `prd_goods.inv_mode`：`INHERIT` / `ON` / `OFF` |
| 品类 | 纳入 / 不纳入 | 进销存设置 · 纳入进销存的品类 | 新表 `prd_entity_category_inv(entity_no, category_no, managed)`，稀疏 |
| 平台默认 | 按类目模板 | 代码常量 | `STANDARD` / `FRESH` 纳入；`SERVICE` / `VOUCHER` / `VIRTUAL` 不纳入 |

**挂在主体上而不是门店**：纳入决定的是「这件商品有没有物料」，物料属于主体（`inv_item.owner_id`），
同一件货在 A 店有账、B 店没账说不清。门店维度的差异放在 §4 的可售规则里表达。
**挂在商品上而不是 SKU**：同一件商品的规格有的管库存有的不管，没有真实需求。

切换规则：

| 动作 | 处理 |
|---|---|
| 不纳入 → 纳入 | 建物料（各门店实存 0）；进入「期初对齐」（§7），不自动把商城库存抄成实存 |
| 纳入 → 不纳入，有在途单据或线上占用未完结 | **拒**，列出单号 |
| 纳入 → 不纳入，实存不为 0 | 二次确认后停用物料：余额与流水只读保留、不再出现在进货 / 盘点 / 卖出里；重新纳入时原样恢复 |
| 纳入 → 不纳入，实存为 0 且无在途 | 直接停用 |
| 品类开关批量影响多件 | 逐件套上面的规则；有一件被拒，**整批不动**并列出原因 |

## 4 决策二：线上可售规则（门店级）

**线上卖多少，是每家店自己的经营决定**（柜台客流大的店要给到店顾客留货），所以规则挂**门店**。

| 规则 | 线上可售目标值 T | 适合 |
|---|---|---|
| 全部可售（**默认**） | T = 可用 | 线上为主，或线下都及时记了卖出 |
| 保留线下 N 件 | T = max(0, 可用 − N) | 柜台也在卖，要给到店顾客留货 |
| 按比例 P% | T = ⌊可用 × P%⌋ | 货少，线上线下都要照顾 |
| 封顶 M 件 | T = min(可用, M) | 促销控量、新品试卖 |
| 手动 | T = min(店主设定值, 可用) | 想完全自己控，但不会超过可用 |

一家店内的取值顺序：**单品 › 品类 › 门店默认 › 全部可售**。
存 `inv_sell_rule(store_no, scope_type[STORE/CATEGORY/GOODS], scope_ref, rule_type, param)`，稀疏。

## 5 两条路径的流程（纳入的商品，按门店）

### 5.1 线上

| 步骤 | 商城 | 进销存（本店库位） |
|---|---|---|
| 顾客下单 | 线上可售 −n（锁定） | 占用 +n（现有镜像） |
| 支付后出库 / 核销 | 锁定转扣减 | 占用 −n、实存 −n（现有镜像） |
| 取消 / 超时 | 释放 +n | 占用 −n（现有镜像） |
| 售后退货入库 | — | 实存 +n（退货入库单）→ 触发重算 |

### 5.2 线下（新增）

| 步骤 | 进销存（本店库位） | 商城 |
|---|---|---|
| 店员在 B 端「线下卖出」扫码 / 选货、填数量、确认 | 出库单 `purpose=OFFLINE_SALE` 过账：实存 −n | 触发重算：线上可售超过目标就压下来 |
| 线下退货 | 入库单 `purpose=OFFLINE_RETURN`：实存 +n | 触发重算 |

- 出库单**仍不带售价**（沿用进销存「不存第二个销售真源」的约定）；线下收入不在本方案，报表只算线下**件数**，见 §9
- `OFFLINE_SALE` 不挂预留：它不是线上订单，没有占用可对

### 5.3 不纳入的商品

只有商城库存一个数。线上照常扣；**线下卖出也在同一个入口记**，但直接扣商城库存（没有实存账可扣）。
「改库存」直接改这个数。

### 5.4 补货：补的是实物，终点永远是门店库位

| 货从哪来 | 单据 | 路径 |
|---|---|---|
| 供应商 | 采购单 | 供应商 → 门店库位入库 |
| 自家仓 | 调拨单 | 仓 → 门店库位 |
| 另一家门店 | 调拨单 | A 店 → B 店 |

**线上不单独补货**：实存涨了，§6 的写回按本店规则把线上可售补上。
想给线上多放货，改的是线上可售规则或额度（§4、§8），不是开调拨单。
例外只有独立线上仓 / 前置仓（§11），那时补货才是调拨到那个仓。

### 5.5 线上销售在进销存里怎么显示

- 线上订单出库后，本店库存明细里有一条「销售出库」，关联订单号（**今天已经如此**，镜像的 commit 落 `SALE` 出库）；未出库的计入「已预留」
- 显示**数量与结转成本**，不显示售价与收款（进销存不存售价，见 §5.2）
- 第三期起「销售出库」按渠道分：线上（`SALE`，挂订单号，可点进订单）/ 线下（`OFFLINE_SALE`）；库存明细与库存报表可按渠道筛
- 不纳入进销存的商品不出现在这里，它们的销售只在订单与经营报表

## 6 同步：进销存 → 商城（写回）

以「门店 × SKU」为单位，**把线上可售对齐到按规则算出的目标值**。

### 6.1 触发

- 本店库位上任何单据过账：进货入库、盘点、调拨入 / 出、报损、领用、线下卖出 / 退货、售后退货入库、线上订单出库
- 规则变化：本店默认 / 品类 / 单品规则、安全库存改了 → 受影响的 SKU 各算一次
- 每晚兜底：每店每个纳入 SKU 按同一逻辑算一遍，补漏掉的事件，顺带出对差日报

### 6.2 步骤

1. **单号已处理 → 跳过**（自然键 = 单据号；规则变化用「规则版本号」作键）
2. **等同步追平**：这家店这个 SKU 还有未同步到进销存的线上订单动作（下单 / 取消 / 出库镜像）→ 稍后重试（秒级退避）
3. **算可用**：U = max(0, 实存 − 占用 − 安全库存)
4. **算目标**：T = 规则(U)，取值顺序 单品 › 品类 › 本店默认 › 全部可售
5. **写回**（带 `prd_store_stock.version` 的条件更新）：
   - 非手动规则：线上可售 = T
   - 手动规则：线上可售 > U 时压到 U，**否则不动**（店主设多少就是多少，不自动抬）
   - 更新影响 0 行（这一刻有订单改了这一行）→ 回到第 2 步，最多三次，仍失败交给退避重投
6. **记同步明细**：来源单号、门店、SKU、前后值、规则 → 店主能看到「线上为什么从 18 变成 23」；标记单号已处理

### 6.3 算例（福田店 · 香梨 5 斤装，安全库存 0）

| 场景 | 实存 | 占用 | U | 规则 | T | 线上可售 |
|---|---|---|---|---|---|---|
| 进货 +10 | 20→30 | 2 | 28 | 全部可售 | 28 | 18 → 28 |
| 同上，保留线下 5 | 30 | 2 | 28 | 保留 5 | 23 | 18 → 23 |
| 柜台卖出 8 | 30→22 | 2 | 20 | 全部可售 | 20 | 28 → 20 |
| 盘亏 3 | 22→19 | 2 | 17 | 全部可售 | 17 | 20 → 17 |
| 手动设 10，再进货 +10 | 19→29 | 2 | 27 | 手动 10 | — | 10 → 10 |
| 手动 10，柜台卖出 20 | 29→9 | 2 | 7 | 手动 10 | — | 10 → 7 |

### 6.4 为什么这样设计

- **最初写的是「涨按增量、降按封顶」，已放弃**：它挡不住镜像延迟 —— 线上订单商城先扣、几秒后才同步到进销存，
  这几秒里算出的 U 多一件，按封顶写回仍会多放出一件。**真正防超卖的是第 2 步（等追平）+ 第 5 步（版本号）**；
  有了这两道，直接对齐到目标值更简单，还能顺手纠正偶发偏差
- **只改线上可售，不改实存**：实存永远只由单据改
- **商城 → 进销存**保持现状（下单 / 取消 / 出库的镜像），不新增
- 失败走 outbox 退避重投；对差日报只报不改

## 7 期初对齐（打开同步前必须做一次）

两本账今天各记各的，已经有差。**打开写回前**，按门店逐件列出「实存 / 商城库存 / 差额」：

- 店主逐行确认以哪个为准，或整店「以商城库存为准」一键确认
- 确认后生成一张**期初对齐单**（盘点单的一种）调实存，之后才开始按 §6 写回
- 没对齐的门店不开写回 —— 带着旧差额开，第一天就不对

同一页也是「不纳入 → 纳入」时的入口。

## 8 「改库存」的新语义

| 商品 | 「改库存」改的是 | 说明 |
|---|---|---|
| 纳入 | **线上可售额度** | 等于把本品在本店的规则临时切成「手动」；不开单据，不改实存；不能超过可用。实物数量变了走盘点 / 报损 / 线下卖出 |
| 不纳入 | 商城库存（唯一的数） | 与今天一样 |

弹层里写清楚改的是哪个数：纳入的写「线上可卖（本店实存 20，可用 18）」。

## 9 报表

| 报表 | 口径 |
|---|---|
| 经营报表（销售额、订单） | 线上订单，全部商品；线下卖出**只计件数**，不计金额（出库单不带价） |
| 库存报表（实存、库存金额、周转、缺货、滞销） | 只算纳入的；按门店 |

两张报表口径不同，页面上写一句，免得店主拿两个数相减。

## 10 B 端界面（都在「当前门店」下）

| 位置 | 内容 |
|---|---|
| 进销存设置 · 纳入进销存的品类 | 主体级；各门店经营类目的并集，每类一个开关，旁边「影响 N 件商品」 |
| 进销存设置 · 线上可售规则 | **本店**默认规则 + 按品类覆盖 |
| 编辑商品 · 库存 | 「库存管理」：跟随品类（当前：纳入）/ 纳入 / 不纳入；纳入时再一行「本店线上可售」：跟随规则 / 全部 / 保留 N / 比例 / 封顶 / 手动 |
| 商品列表 | 纳入的显示「线上可卖 12 · 实存 20」；不纳入的标「不入库存」 |
| **线下卖出**（新） | 工作台入口；扫码或搜货 → 数量 → 确认；列当天已记的卖出，可撤销（生成退货入库） |
| 期初对齐（新） | 按门店的差额清单 + 一键以商城为准 |
| 进货 / 盘点 / 调拨 / 出库 / 挑货 | 只列纳入的（停用物料本来就不列） |

## 11 边界

| 情形 | 处理 |
|---|---|
| 门店从仓发货（`source_location_id` 指向仓） | 这家店的可用取**发货库位**的；该仓只给一家店发货时照常 |
| **多店共用一个仓** | 本方案不支持：一件货的可用被几家店共享，按店写回说不清加给谁。等切到「以进销存为准」按池预留时解决。今天数据里没有这种门店 |
| 独立线上仓 / 前置仓 | 是真实库位：线上订单从它发货，用现有调拨从门店补货；门店柜台用门店库位 |
| 称重品 | 实存与可售都按基本单位（`base_uom`）；本方案不改单位逻辑 |
| 门店停用 | 不写回、不对差 |

| 类型 | 内容 |
|---|---|

| 消费方 | 投影据 `invManaged` 建 / 停用物料；`DualWriteStockPort` 不纳入的不入镜像；新增写回消费者按 §6 |

## 13 分期

| 期 | 内容 | 上线后店主能感到的变化 |
|---|---|---|
| **一** | 纳入开关（§3）：投影与镜像按开关过滤；存量服务类回填停用 | 进货 / 盘点里不再有「家政保洁 2 小时」 |
| **二** | 线上可售规则（§4）+ 写回（§6）+ 期初对齐（§7）+ 「改库存」新语义（§8） | 进货入库后线上自动能卖，不用再手改 |
| **三** | 线下卖出（§5.2）+ 报表口径（§9） | 柜台卖出记得上，线上不会把柜台卖掉的货再卖一遍 |
| 以后 | 切到「以进销存为准」：线上下单直接按额度在进销存预留；**按商品分流**（不纳入的仍扣商城） | 商城库存变只读，写回退役 |

第二期必须在第三期之前：没有写回，线下卖出只减实存、线上不跟着降，会超卖。

## 14 存量

| 存量 | 处理 |
|---|---|
| 全部商品 | `inv_mode=INHERIT` |
| 实物 / 生鲜 | 平台默认纳入，与今天一样 |
| 服务类已建物料 | 迁移后回填：实存 0 且无在途的停用；有实存或在途的不动，清单给运营。**先量再跑** |
| 各门店线上可售规则 | 默认「全部可售」，不建行 |
| 两本账的差额 | 第二期上线时由各店走期初对齐，不在迁移里自动改 |

## 15 验证

| 场景 | 断言 | 消融 |
|---|---|---|
| 服务类商品保存 | 没有物料；单品设「纳入」出现物料；设回「跟随」停用 | 去掉投影判断 → 第一条红 |
| DUAL 下不纳入的下单 | 商城扣、进销存零流水 | 去掉镜像过滤 → 红 |
| 进货入库 +10、规则全部可售 | 线上可售对齐到新可用 | 去掉写回 → 红 |
| 规则保留线下 5、可用 20 | 线上可售 15；入库 +10 后 25 | — |
| 线下卖出 8、线上可售原本 = 可用 | 线上可售 −8 | 去掉写回 → 红，且能构造出超卖 |
| 写回与线上下单并发（含镜像未追平） | 最终线上可售 ≤ 真实可用，从不超卖 | 去掉「等追平」或版本号条件 → 能构造出多放一件 |
| 有在途采购单时设「不纳入」 | 拒并列出单号 | — |
| 品类批量有一件被拒 | 整类不动 | — |
| 同一单据重投两次 | 只写回一次 | 去掉自然键 → 红 |

## 16 不做什么

- 不用调拨表达「给线上分货」（§2）
- 不支持多店共用一个仓的写回（§11）
- 线下卖出不记售价与收款；线下收银是另一件事
- 不做 SKU 级纳入开关、不做门店级纳入开关（§3）
- 不自动把商城库存抄成实存，也不自动把实存抄成商城库存 —— 都走期初对齐由店主确认
- 不动 `stock-authority` 全局开关

## 17 建议取值（本稿按此写成，确认即定）

1. 纳入开关挂主体、按商品设；平台默认服务 / 券 / 虚拟不纳入
2. 关掉时实存不为 0：二次确认后停用，余额只读保留
3. 存量服务类物料按 §14 回填
4. 线上可售规则挂门店，默认「全部可售」
5. 写回：等同步追平 + 版本号条件更新，对齐到规则目标值；手动规则只降不升
6. 线下卖出新增 `OFFLINE_SALE`，只记件数不记金额
7. 多店共用一个仓、独立线上仓：本期不做
8. 分期顺序：一 → 二 → 三
