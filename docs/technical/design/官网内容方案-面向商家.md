## 〇、这次改的是什么

现在线上的首页（`site/`，七屏）**说话的对象是消费者**：
「楼下的好东西，都在虹选」「先看看附近有什么」「下载 App」，
七屏里只有第 6 屏 `MerchantCta` 对商家说话。

新定位：**hxmall.top 是招商站，唯一的成功指标是商家点了「申请开店」。**
消费者叙事不删掉，但降级成一屏——它在这里的作用不是拉新用户，
而是回答商家的那句「你们有客吗」。

**转化落点是现成的**：`https://www.hxmall.top/b/`（B 端 H5 已在线，见部署 README §location 表）。
不需要等 App 上架——这一点决定了首屏 CTA 可以是「申请开店」而不是「留下联系方式」。

## 一、受众与他们各自要的答案

招商站最容易犯的错是只写给第一类人。四类人问的不是同一件事：

| # | 谁 | 第一个问题 | 页面上必须回答 |
|---|---|---|---|
| 1 | 楼下夫妻店店主（个人 / 个体户） | 要执照吗？要钱吗？麻烦吗？ | 个人主体免资质 · 无年费 · 填一张表 |
| 2 | 有 2–5 家店的小连锁 | 几家店能一起管吗？店员能不能只看自己店？ | 多门店 · 六角色逐店授权 · 跨店对比 |
| 3 | 想要自己品牌小程序的商家 | 顾客是你的还是我的？能不能挂我自己的牌子？ | 自有小程序（§三 线 C） |
| 4 | 便利店 / 驿站（自提点承接方） | 我不卖货，能不能只赚服务费？ | 承接自提点：按件服务费 |

> 第 3 类是这次新增的一条产品线，现在站上**一个字都没有**。
> 第 4 类现在也没有——而它是最容易转化的一类：不用上架、不用备货。

## 三、骨架：三条上线方式

这是全站的主结构，也是用户这次提出的三件事。**一屏讲清三条路，其余屏是这三条的展开。**

| 线 | 一句话 | 商家得到什么 | 事实依据 |
|---|---|---|---|
| **A · 入驻虹选** | 开在虹选的小程序和 App 里 | 平台的邻里流量 + 现成的下单/履约/售后链路 | B-1 入驻 · C 端已上线 |
| **B · 多门店** | 一个账号管几家店 | 门店独立收款、独立库存、员工逐店授权、跨店对比 | B-14（`mStoreList` 等 10 条） |
| **C · 自有小程序** | 挂你自己的招牌 | 独立品牌小程序，与虹选后台同一套货、同一套单 | **⚠️ 按年 SaaS 开通的商品，代码里尚无多租户开通链路**，见 §七 |

A 与 B 是「已经在跑的东西」，C 是「要另外开通的东西」。
**页面上这两类必须在语气上分开**：A/B 用陈述句（「支持」「已经」），
C 用开通句（「开通后你会有……」）——把还没有开通链路的东西写成现成功能，是招商站最贵的一种失信。

> **C 已定为按年 SaaS 开通**（2026-08-20），不是一次性定制开发。这带来两个内容后果：
> ① 页面要写清**边界**：哪些是「同一套」（商品、订单、结算、员工权限），
> 哪些是「你独有」（招牌、入口、顾客名单、首页装修）——SaaS 卖的就是这条线，划不清就会被当成定制来提需求；
> ② 要写**续费口径**：到期不续会怎样（小程序还在不在、货和单还能不能查）。
> 这条不写，第一年到期时就是纠纷。**当前代码里没有开通/续费/到期的任何实现**，
> 所以页面只说「开通」，不说「立即开通」——CTA 是联系，不是自助下单。

### 「虹选自营」在页面上怎么说

已定（2026-08-20）：**自营与商家入驻并存** —— 平台自己有一个自营选品店，同时开放入驻。
于是官网**现在就可以全力招商**，首屏说「开在虹选里」成立，不需要延后放出 CTA。

对商家要说的是它的**因果**而不是它的存在：

> 自营的品是我们自己在卖，所以选品、履约、客诉这条链路我们天天在走。
> 你入驻后用的是同一套系统，不是一套我们自己不用的东西。

⚠️ **同时有一条硬约束**（[小程序上线指南](./小程序上线指南.md) §一 / §六）：
若小程序按「自营」类目提审，**小程序界面内不能出现第三方商家入驻入口**，
否则驳回。官网是站外网页，讲入驻不受此限——
**但「从小程序跳到官网入驻页」这条路要等类目定了才能开。**

## 四、首页九屏（逐屏内容）

一屏一件事，顺序按商家的疑问顺序排：能开吗 → 怎么开 → 开了干什么 → 我有几家店 → 钱怎么算 → 有客吗 → 还有什么问题 → 开店。

### 屏 1 · 首屏

- 标题：**开一家店，从今天下午开始。**
- 副文：填一张表就开张。个人主体免执照，无年费、无押金，**自带客流不抽佣**。
- CTA：**[申请开店]** → `/b/` ｜ [先看商家端能做什么] → `#workbench`
- 底注：三条上线方式一行锚点（入驻虹选 / 多门店 / 自有小程序）
- 图：B 端 App 工作台真机图（4:5）— **未产出前保留虚线槽位**，不放示意图

> 「今天下午」这个说法有据：入驻表单提交后走平台审核（A5），
> 审核是人工的，**不能承诺当天通过**。所以文案说的是「开始」不是「开张」。
> 一字之差，落到客服那里就是一天的解释成本。

### 屏 2 · 三种上线方式（新增，全站骨架）

三张卡，对应 §三 的 A / B / C。每张卡：一句话 + 三条要点 + 一个锚点链接。
C 卡右上角标 **「按年开通」** 角标，与 A/B 视觉上区分。

### 屏 3 · 开店三步（诚实版）

| 步 | 标题 | 正文 |
|---|---|---|
| 01 | 填一张表 | 手机号登录即注册。行业先选，它决定你能选哪种主体：个人免执照，个体户 / 企业传营业执照（B-1.3 / B-1.8） |
| 02 | 等审核 | 平台人工审核。**驳回会写清楚差什么**，补完在原页重提，不用重填（B-1.4 / B-1.5） |
| 03 | 上架开卖 | 商品过审后是下架态，**什么时候开卖你自己点**（C6 验收点） |

**这一屏必须再加一句**（来自 B1 验收点「能开店 ≠ 能收钱」）：

> 开店和收款是两段。开完店就能上架、能接单；**收款要另外走一次进件**，
> 没过之前工作台会一直提示你还差什么，不会让你以为已经好了。

把这句写在官网上是反直觉的，但它挡掉的是最贵的一类投诉：
「我都开店了怎么收不到钱」。系统里这段状态本来就做得很清楚（`missing` 逐条列缺什么），
**页面上说出来，等于把产品的诚实变成卖点。**

### 屏 4 · 一部手机管完（`#workbench`）

工作台六个待办 → 每个待办展开一句，全部对应已实现能力：

| 待办 | 一句话 | 依据 |
|---|---|---|
| 待发货 / 待自送 | 填单号发货，或自己送到点一下 | B-5.4 / B-5.5 |
| 待核销 | 输码或扫码，连扫多单一次提交；**一张废码不影响另外几单** | B-6.4 / B-6.4b |
| 待分拣 | 按商品分货、按人装袋，两种视图 | B-6.2 |
| 待售后 | 仅退款直接退；退货退款**确认收货后才退** | B-7.3 |
| 待回评 | 商品 / 履约 / 服务三个分分开看；三星及以下可申诉 | B-9.3 / B-9.4 |

配一句总结：**数字即入口，点数字直接到该做的那件事。**

### 屏 5 · 多门店与员工（墨底，节奏对比屏）

- 一个商户多家店，**每家店的钱各走各的**（B-14.4 门店级收款）
- 六个预置角色（老板 / 店长 / 店员 / 理货 / 配送 / 客服），也可以自己建角色
- **角色挂「人 × 门店」**：同一个人在 A 店是店长、B 店是店员
- 改权限有审计日志，谁在什么时候改的查得到（B-14.7）
- 跨店总览：各店今日单量、销售额、待办并排看（B-14.9）
- 边界要写：**第一家店免费，第 2 家起要额度**（B-11.12.2 / C1 验收点）

> 原「商家的颜色」皮肤演示屏（`SkinShowcase`，全站唯一客户端组件）**保留**，
> 但从「品牌叙事」改成「商家权益」：一句 lede 就够——
> **「你的店用你的颜色，不是所有店长一个样。」** 演示机本身不动。
> 它是本站唯一一处「产品能力现场可验证」的地方，对商家的说服力比对消费者更大。

### 屏 6 · 钱怎么算

招商站最该说清、最容易含糊的一屏。四行：

| 项 | 值 | 说明 |
|---|---|---|
| 自带客流佣金 | **0%** | 老客扫你的店铺码进来的单，平台不抽 |
| 平台客流佣金 | **2%** | 从虹选首页 / 附近发现你的单 |
| 自提点履约服务费 | **¥0.30 / 件** | 供货方付、承接方收；两头都是你时账面抵消，但分别列示 |
| 结算周期 | **7 天** | 应结 = 毛收入 − 退款 − 佣金 − 履约服务费 |

**工程约束（重要）**：这四个数**不许手打进 tsx**。
它们的唯一事实源是 `packages/shared/src/utils/constants`，
页面按 `SkinShowcase` 读 `tokens.ts` 的同一路子 `import` 过来——
改费率跑 `npm run gen:rules`，官网跟着变；手抄一次就会有一处忘了改
（[规则表](../../requirements/需求矩阵-三端.md#七之二交易规则常量唯一事实源)的原话）。

必须同时写上的一句：**费率以你下单时的快照为准，之后调整不影响历史订单**（B-12.4b）。
不写这句，商家会以为调价能追溯。

⚠️ **这一屏不能出现**：到账时间、提现、T+N。理由见 §七。

### 屏 7 · 自有小程序（`/mini-program/` 的首页摘要）

**按年开通**（已定 2026-08-20）。四条：

- **你独有的**：招牌、小程序入口、顾客名单、首页装修
- **和虹选同一套的**：商品、订单、履约、售后、结算、员工与权限 —— 一套货一套单，不用两边各录一遍
- **上架我们陪着走**：注册 / 认证 / 类目 / 提审这一串（[小程序上线指南](./小程序上线指南.md) 就是我们自己走过的清单）。
  **你自己卖自己的货属于「自营」类目，不需要 EDI 许可证** —— 这是自有小程序相对平台型最实在的一条：
  门槛差着一个数量级（同上 §一）
- CTA：**[聊聊开通]** → 联系方式（§八-4 待定）

**不写价格、不写「立即开通」**：多租户开通链路代码里还不存在，CTA 只能是联系。
页面必须出现一句续费口径（到期后小程序与历史订单怎么处理），口径本身待定 —— 见 §八-6。

### 屏 8 · 你的顾客从哪来（原 C 端内容压缩）

原来的三屏（附近的店 / 怎么买 / 邻里集市）压成一屏，且**改成对商家说**：

- 三档服务半径（同小区 / 步行圈 / 同城）→ 说成「**你自己决定卖给多远的人**」（B-3.4 覆盖社区）
- 顾客侧路径「挑 → 下单 → 楼下自提」→ 说成「**没有跨仓、没有三天沉默，客诉少一大半**」
- 底部一行：顾客入口 → `/download/`

### 屏 9 · 常见问题（FAQ · 结构化数据 `FAQPage`）

八问，全部照 §七 的红线作答：

1. 要营业执照吗？——个人主体不用；个体户 / 企业要传。
2. 要交年费或押金吗？——不要。
3. 多久能开张？——审核是人工的，通过后即可上架；收款要另走一次进件。
4. 抽多少佣金？——见屏 6，自带客流 0%。
5. 我有三家店怎么办？——第一家免费，之后按额度；每店钱各走各的。
6. 店员会看到我的账吗？——不会，钱的去向只有老板能碰。
7. 我不卖货，只想做自提点行吗？——可以，按件收服务费。
8. 能做我自己的小程序吗？——可以，按年开通；货和单与虹选后台同一套，招牌和顾客是你自己的。

## 七、红线：页面上不许出现的话

每一条都对应一个代码事实。招商站写下的每句话，最后都会有人拿着来对账。

| 不许写 | 为什么 | 依据 |
|---|---|---|
| 到账时间 / 提现 / T+N | **一期只记账，线下结算**；且支付本身还是桩 | B-12.5 · B 端清单 §七 |
| 「入驻即可微信收款」 | 收付通进件依赖平台资质，经营模式未定，进件可能长期停在未激活 | E3 · [ADR-012] |
| 「拍执照自动识别」 | OCR 未接 | B 端清单 §七 |
| 「分拣单可打印」 | ⬜ 未做 | B-6.7 |
| 「已覆盖 X 个社区 / X 家门店」 | 现在是占位 `——`。真上线前放假数字，是招商站最快的一种翻车 | 现有 `hero.tsx` |
| 自有小程序的**年费金额**、「立即开通」 | 形态已定（按年 SaaS），但价格未定，且多租户开通链路代码里不存在 | §八-2 已定 · §八-6 待定 |
| 折扣 / N 件优惠 | 模型里只有券 / 满减 / 限时特价 / 买赠四类 | B-10.2 |
| 「随时提现到微信」 | 同第一行 | — |

> 反过来，有两句**必须写**，它们是产品真实的分段，藏着比说出来贵：
> ①「开店 ≠ 能收钱，进件另走一次」②「费率按下单时快照，调整不追溯」。

## 八、决策清单

### 已定（2026-08-20）

| # | 事项 | 结论 |
|---|---|---|
