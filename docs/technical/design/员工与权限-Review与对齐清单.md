## 一、①「新增员工」：这是本轮最硬的缺口

### 1.1 后端**没有创建端点**

```
GET  /ops/staffs                  列表
POST /ops/staffs/{staffNo}/enabled  停用启用
POST /ops/staffs/{staffNo}/role     改角色
POST /ops/staffs/{staffNo}/scope    改数据域
```

四条全是**改存量**。库里的员工从哪来？`DevSeeder` ——
也就是说**生产环境无法加人**，只能改已经存在的那几个。

这与「有能力没有消费方」相反，是**连能力都没有**，
而三个改存量的接口做得很完整，容易让人以为这块齐了。

### 1.2 多角色：数据模型早就支持，API 把它压成了单值

| 层 | 支持多角色吗 |
|---|---|
| `sys_role_member` | ✅ 唯一键 `(end_code, subject_no, role_code, scope_no)` —— **role_code 在键里就是为多角色留的** |
| `sys_ops_staff.roles` | ✅ JSON 数组列 |
| `Perms.of(List<String> roles)` | ✅ 取并集 |
| `RolePermResolver.of(roles)` | ✅ 收 List |
| **`POST /ops/staffs/{no}/role`** | ❌ **收单个 `role`，且 `staff.setRoles("[\"" + role + "\"]")` 直接覆盖** |
| ops-web `Staff.role` | ❌ 单值 `Role` |
| ops-web 员工表 | ❌ 行内 `<select>` 单选 |

> **能力在最底下两层，被最上面三层压掉了。**
> 这与 B 端那次一模一样：`mch_store_role` 的唯一键 V18 就放宽成支持多角色了，
> 而写接口一直是单值 —— 那次也是先改接口再改 UI。

### 1.3 一个必须先答的问题

**新建员工时的初始密码怎么给？**这决定 API 形状：

- (a) 接口收明文密码 → 运营在界面上输入，**明文经过前端与日志**
- (b) 接口只收账号信息，后端生成随机初始密码并**一次性返回**，要求首登改密
- (c) 不设密码，走 OTP / 企业身份源

**我建议 (b)**，且首登强制改密。(a) 的问题不是加密与否，是
「谁都能在浏览器 devtools 里看到刚给同事设的密码」；而 (c) 需要先有身份源。

> ⚠️ 这条我不会替你定 —— 它牵涉账号安全策略，不是实现细节。

## 二、②「角色可编辑」：差一个改名

本轮（阶段 C）已经做完的：建自定义角色、勾功能点（多选，树是「功能 → 功能点」两层）、删角色、
预置角色渲染但只读。

**差的**：角色建好之后名字改不了。后端没有 `renameRole`，界面上也没有入口。
角色码不该能改（它是授权的键，改了等于换一个角色），**但展示名应该能改** ——
「退款复核」写错成「退款附核」，现在只能删了重建，而删的前提是没人在用。

## 三、③ 功能清单 ↔ 菜单：已经对齐，但没人守着

实测：

```
nav.ts 菜单叶子 href      67
库里 MENU 功能点 href     67
两边差集                  0   ← 双向都空
```

功能点总数 102 = **68 个 MENU** + **34 个 ACTION**，ACTION 分两类：

| 分组 | 数量 | 是什么 |
|---|--:|---|
| 页面内操作 | 10 | 按钮级授权（「编辑自提点」这种），**本来就没有菜单落点** |
| **无界面入口** | 24 | 保证金、进项发票、行业开关…**后端有能力、ops-web 没有页面** |

前者是设计，后者是缺口 —— 而它们现在混在同一个 `ACTION` 类型里，
只能靠 `group_name` 区分。**清单上要能一眼看出「这 24 个是没做界面」。**

### 为什么现在没有守卫

对应关系是 `gen-perm-seed.mjs` **生成**出来的（`nav.ts × perm-map.ts × Perms.java`），
生成那一刻是对的。但之后：

- 改 `nav.ts` 加一个菜单项 → 不重跑生成器 + 不出迁移，库里就没有这个功能点
  → **那个菜单项对所有非超管不可见，而没有任何东西报错**
- 反过来删一个菜单项 → 库里留下孤儿功能点，配角色时还能勾到，勾了没用

> 这正是「生成物要重新生成」那条教训的形状：守卫读的是产物，改源码不生成等于没改。

## 四、④ 交互一致性：角色页是左右排列

| 页面 | 形态 |
|---|---|
| 12 个页面 | 表格 + 抽屉 ✅ |
| **`/iam?tab=roles`** | **表格 + 右侧 24rem 常驻卡片** ❌ |
| `/products` | 同样是左右排列 ❌（不在本轮范围，登记） |

而且 `/iam?tab=staffs` 的**编辑动作被劈成两处**：

- 改角色 → 表格里的**行内下拉**，选完立即提交
- 改数据域 → **抽屉**

行内下拉的具体害处：**它没有「确认」这一步**。
选错一格，权限当场就变了，而这一列改的是「这个人能干什么」。
数据域那个动作反而有抽屉、有保存按钮 —— 两个同等重要的操作，一个能反悔一个不能。

> 统一成表格 + 抽屉之后，员工的三件事（角色、数据域、启停）在同一个抽屉里改、
> 一次保存 —— 这也顺带解决了多角色：多选控件在行内下拉里放不下。

## 五、对齐清单

### 5.1 数据库

| 表 | 改动 |
|---|---|
| `sys_ops_staff` | 无（`roles` 已是 JSON 数组；密码列已有） |
| `sys_role_member` | 无（唯一键已支持多角色） |
| `sys_role` | 无（改名只改 `name` 列） |
| `sys_function_point` | 加一列 `has_ui`（或复用 `group_name='无界面入口'`）—— 见 §5.5 Q3 |

**几乎不动库** —— 多角色的库结构两轮之前就铺好了。

### 5.2 API

| 端点 | 状态 | 说明 |
|---|---|---|
| `POST /ops/staffs` | **新增** | 建员工：username / realName / roles[] / scope；返回一次性初始密码 |
| `POST /ops/staffs/{no}/roles` | **新增** | 改多角色（复数）。旧的 `/role` 保留一段时间并转调，避免并发会话的前端 404 |
| `POST /ops/perm/roles/{code}/rename` | **新增** | 改角色展示名。预置角色拒绝（与改功能点同一条闸） |
| `POST /ops/staffs/{no}/role` | 保留→弃用 | 单角色版。**不立刻删**：另一个会话的前端可能还在调 |

### 5.3 对象

| 类型 | 改动 |
|---|---|
| `StaffVO.roles` | 后端已经是 `List<String>` ✅ |
| ops-web `Staff.role: Role` | → `roles: string[]`。**改动面最大的一处** —— 员工表的角色列、筛选、数据域判断（`SCOPED_ROLES.includes(s.role)`）都读它 |
| `RoleDef` | 无（本轮刚换过形） |

> `SCOPED_ROLES.includes(s.role)` 变成多角色之后语义要重定义：
> **持有任一受限角色就要配数据域**，还是**全部角色都受限才配**？
> 我建议前者 —— 数据域是「你能碰谁的数据」，只要有一个身份受限，就该受限。

### 5.4 Controller / Service / Mapper

| 层 | 改动 |
|---|---|
| `OpsStaffController` | 3 个端点（建员工 / 改多角色 / 改角色名） |
| `OpsServiceImpl` | `createStaff`、`setStaffRoles(List)`；`syncRoleMember` 改成**按集合增删**而不是覆盖 |
| `PermConfigServiceImpl` | `renameRole` |
| Mapper | 无 |

**四条闸要保留/新增**：
1. 不能改自己的角色（已有）
2. 不能停用自己（已有）
3. 角色码必须真实存在（已有，改多角色时**逐个校验**）
4. **新增：不能给自己加角色** —— 否则有 `iam:staff:update` 的人可以给自己加超管

> 第 4 条现在不存在，因为单角色版禁止改自己。改成多角色时**不要漏掉它**。

### 5.5 ops-web

| # | 事项 |
|---|---|
| W1 | 员工页改成**表格 + 抽屉**：角色（多选）、数据域、启停在一个抽屉里，一次保存 |
| W2 | 角色页从左右排列改成**表格 + 抽屉**（权限树进抽屉） |
| W3 | 新增员工入口（抽屉），初始密码**一次性展示 + 复制**，关掉就看不到了 |
| W4 | 角色改名入口 |
| W5 | `Staff.role` → `roles`，连带筛选与数据域判断 |

### 5.6 守卫（③ 的落点）

| # | 守卫 | 防什么 |
|---|---|---|
| G1 | `nav.ts` 叶子 href 集合 == 库里 MENU 功能点 href 集合 | 改菜单不重跑种子 → 新菜单项对所有人不可见，且不报错 |
| G2 | 「无界面入口」的 ACTION 点数量只降不升（棘轮） | 后端补了能力却又不做界面，会一直堆积 |
| G3 | 多角色端到端：给一个人两个角色，他的 perms == 两个角色的并集 | 覆盖式写入回潮 |
