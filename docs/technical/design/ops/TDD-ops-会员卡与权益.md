# TDD · 运营端会员卡与权益（P-7.4）

营销页新增「会员卡与权益」tab。第二个 phase 2 批次。

## 一、卖出去的是承诺，不是配置

这一域只有一句话，其余规则都是它的推论：

> 只要有人持卡，这张卡的**权益与月费就锁死**。要调整就新建一张卡、把旧卡停售，
> 让在售的那张始终与用户当初买的一致。

`holderCount` 因此不是统计数字，而是"这张卡还能不能改"的唯一依据。
界面上把它做成**显性的锁**：有持卡人时月费与全部权益控件直接禁用，顶部一条警告写清
「已有 1200 人持卡……请新建一张卡并把这张停售」—— 而不是让人改到一半才被服务端拒。

拦的是权益与价格，不是一切改动：改名字仍然允许（有专门一条用例锁住这个边界）。

同理，**有持卡人的卡归档不了**：权益还要继续兑现，归档会让它从所有列表里消失。

## 二、其余规则

| 规则 | 不这么做会怎样 |
| --- | --- |
| 至少一项权益 | 没有权益的会员卡就是纯收费 |
| 权益类型不重复 | 同类两条时命中哪条取决于顺序，那是隐性行为 |
| 折扣不低于 5 折 | 月费远补不回被打穿的毛利 |
| 积分倍率 ≥ 1 倍 | 低于 1 倍是"办了会员反而更亏" |
| **月赠券必须绑已启用的券** | 绑草稿券，用户开卡当天就领不到 |
| 停售是终态 | 已售出的权益要继续兑现，重新开卖得新建一张 |

赠券下拉只列 `ACTIVE` 的券模板，选不出草稿券 —— 与规则同向，而不是等保存时报错。

## 三、一个双语的坑：折扣

中文说「95 折」，英文说的是**折掉多少**：`5% off`。同一个 `9500`，两种语言里是两个数。
第一版按中文口径统一算，英文渲染出了 `9.50% off` 这种谁也看不懂的东西。

修法不是在组件里判语言（那会把 locale 逻辑漏进业务代码），而是**两个参数都传给文案表**，
各自的模板挑自己要的那个：

```ts
fill(c.bvDiscount, { zhe: b.value / 1000, off: (10000 - b.value) / 100 })
// zh: "{zhe} 折"   → 9.5 折
// en: "{off}% off" → 5% off
```

`fill()` 忽略模板里没用到的参数，所以这个模式不需要额外机制。

## 五、已知取舍

- `holderCount` 在 mock 里是样本值。接后端后它必须由会员订阅表实时统计 ——
  落成冗余字段一旦漂移，这把锁就形同虚设。
- 没有做「会员权益的实际核销流水」。那属于 C 端用券链路，平台侧这一页只管发行与配置。
