## 一、引用计数不是装饰

这一页改的东西**同时作用在一批店铺页上**，所以每一行都摆着「多少家店在用」。
`usedByCount` 是只读的引用计数，存在的唯一理由是拦住"停用一个正在被 12 家店用着的模板"。

| 规则 | 不这么做会怎样 |
| --- | --- |
| **正在被店铺使用的模板停不掉** | 那些店铺页会瞬间失去模板 |
| 默认模板停不掉 | 新店开出来就用它 |
| **必选板块（店招）不能停用** | 店铺页没有头部，等于一张裸列表 |
| 启用板块不少于 2 个 | 只剩店招的店铺页不是"极简模板"，是配置漏了 |
| 板块 key 不能重复 | 哪条生效取决于顺序，那是隐性行为 |

界面上三处与规则呼应：停不掉的模板不给「停用」按钮；必选板块的复选框直接禁用；
抽屉底部实时显示"已启用 N 个板块，至少 2 个"，而不是等保存时才报。

## 二、板块与排布分开

`layout`（商品区排布：双列网格 / 单列大图 / 主推位优先）与 `sections`（板块开关）
是两个正交的维度。合成一个"模板样式"枚举会立刻产生组合爆炸，
而运营真正想表达的往往只是"这类店不要优惠券区"。

## 四、已知取舍

- 模板的板块**顺序**目前固定，只做开关。顺序可调意味着要做拖拽排序，
  而在只有 6 个板块、且 C 端首屏顺序有强约定的情况下，收益不抵复杂度。
- `usedByCount` 在 mock 里是写死的样本值。接后端后它应由店铺表实时统计，
  不能落成一个会漂移的冗余字段。
