业务写入继续使用既有申请单、审核建店、支付来源及 NearPay 正常运营入口与幂等键；不新增直接改库入口，不改变事务或渠道资格规则。具体单据号和结果在验收证据登记。

店主解析发现原实现要求 EMAIL.verified_at 非空，与已导入种子账号及当前邮件不可用的验收条件冲突。用户已明确选择：允许使用已注册且正常的账号，保留邮箱未验证状态。调整共享 UserProvisionPort.registeredUserByEmail：规范化邮箱，限定 MAIN 的未删除 EMAIL 身份，并确认同租户未删除 usr_account.status=NORMAL；不再把邮箱验证作为代客/自营归属的前置条件。OTP、密码登录及验证时间写入规则不变。

未找到正常店主时返回专用 OWNER_ACCOUNT_UNAVAILABLE / 10425 及三语提示，避免“数据不存在”掩盖失败对象。台湾联系方式仍只记录，不发短信。
