## 一、业界调研

### 1.1 看了什么

| 站点 | 定位 | 与我们的关系 |
|---|---|---|
| 有赞 youzan.com | 面向品牌与连锁的企业级 SaaS | **不可照抄** |
| 微盟 weimob.com | 同上，规模更大 | **不可照抄** |
| 微店 weidian.com | 面向个人与小商家的开店工具 | **最接近** |

### 1.2 有赞 / 微盟的首页结构

两家高度一致：

```
使命口号 → AI 产品矩阵 → 行业解决方案 → 客户案例 → 数据背书 → 服务网络 → 资质认证
```

- 主标题是使命而非产品定义：微盟「让增长持续发生」。
- 大量数字背书：有赞「帮助 55 万个品牌」，微盟「1600+ 服务商、99.9% 可用性」。
- 案例是主板块，微盟列 16 个品牌 logo。
- CTA 双轨：「注册并免费试用」+「与产品专家交流 / 售前咨询热线」。
- 行业方案切得很细：微盟列十大行业。

### 1.3 微店的首页结构

```
开店方案（4 类）→ 行业方案（8 类）→ 核心能力 → 生态与服务市场 → 帮助中心
```

- 首屏直接给动作与耗时：**「一分钟免费开店，一键分享商城」**。
- CTA 统一「免费开店」，次级「立即咨询」。
- 费用不在首页展开，只提「注册享新人礼包」。

### 1.4 三条可借鉴的

1. **首页不讲操作细节。** 三家没有一家在首页写「怎么核销」「怎么发货」。功能清单一律收在二级或帮助中心。**我们现在的做法与业界一致**，上一轮把首页操作细节删掉是对的。
2. **用行业 / 场景做分流。** 三家都有行业方案入口。我们的六类店铺页承担同样的职责。
3. **CTA 双轨。** 自助入口 + 人工咨询并列。我们现在是「免费开店 / 联系招商」，一致。

### 1.5 两条明确不学的

**不学数字背书与客户案例。** 有赞的 55 万品牌、微盟的 16 个 logo 是它们首页的信任支柱。
我们**一个真实案例都没有，也没有覆盖数字**——照抄这个板块只能靠编，那是最快毁掉信任的方式。

> **这是我们首页最弱的一环，且短期补不上。**
> 替代方案：用**可核对的规则**代替案例来建立信任——费率怎么算、到期怎么降级、
> 店长看不看得到结算、自提点看不看得到金额。规则是可验证的，案例是要被相信的。
> 对一个还没有品牌的新平台，前者更实际。

**不学使命型主标题。** 「让增长持续发生」这类口号建立在品牌认知之上。
访客不知道虹选是什么的时候，一句使命只会让他继续不知道。主标题先给产品定义。

## 二、项目目的与定位

**全部来自仓库真源，不是新写的。**

### 2.1 平台定位

> 服务小商家，让创业容易；流量起来后再引入大商家。
> —— `ADR-004 增长模型` §1

### 2.2 商家侧一句话

> 让小店把自己的老客搬到线上并留住：填一张表就开张，一部手机管完接单、分拣、核销、结算。
> 不是给大商家用的后台——自带客流佣金 0%，平台不靠抽小店的佣金赚钱。
> —— `docs/requirements/B端功能清单.md` §〇

### 2.3 顾客侧一句话

> 邻里复购：楼下的菜摊、粮油店把自己的老客带进来，老客用它复购；
> 平台负责把「下单 → 到自提点 → 取货」这条链路做顺，**不负责给商家拉新**。
> —— `docs/requirements/C端功能清单.md` §〇

### 2.4 增长模型

`ADR-004` 的三条决策直接决定官网能说什么：

| 决策 | 对官网的约束 |
|---|---|
| 删除「团长」角色 | 官网不出现团长、不出现拉人头收益 |
| 团购发起人零报酬 | 邻里团购只能讲便利，不能讲赚钱 |
| 商家自带客流为核心资产 | 「店铺码进店 0%」是定位的直接表达，不是促销 |

### 2.5 由此推出的官网主张

三条，全部可核对：

1. **平台不靠抽小店佣金赚钱** —— 证据：自带客流 0%，平台带来的新客才计 2%。
2. **开店成本前置为零** —— 证据：无入驻费、年费、押金；免费版 1 家门店长期免费。
3. **老客是商家的资产，不是平台的** —— 证据：店铺码归属、自有品牌入口顾客名单归商家。

> **「不负责给商家拉新」这一条要小心。** 它是产品事实，但直接写在官网上会削弱吸引力。
> 官网的正确写法是讲平台入口**确实会带来新客**（计 2%），同时不承诺获客量。
> **不承诺获客效果**，与「不写覆盖数字」是同一条红线。

## 四、站点地图与结构

### 4.1 结论：结构不变，仍是 15 页

调研之后没有发现需要新增或删除的页面。业界的差异集中在**内容分量**（案例、数据、AI 产品矩阵），
不在**页面骨架**。我们缺的是内容，不是结构。

```
第 0 层  /                        首页 —— 定义 + 支持范围 + 能力 + 收入 + 异议
         │
第 1 层  ├─ /scenarios/           支持哪些店
         ├─ /how-it-works/        怎么开店
         ├─ /pricing/             收费与套餐
         └─ /mini-program/        自有品牌小程序
         │
第 2 层  ├─ /scenarios/{fresh,convenience,service,pickup-point,chain,own-brand}/
         └─ /capabilities/        功能总览（挂在收费页下）

旁路     /download/               顾客端下载
         /privacy/ /terms/        法务占位
```

### 4.2 首页结构（已按本轮方向改完）

| # | 节 | 承担 |
|---|---|---|
| 1 | 标题区 | 产品定义 + 一句事实（从上架到对账，一个账号完成）+ 三个标签 |
| 2 | 支持的店铺类型 | 行业清单，供认领 |
| 3 | 经营能力 | 四类模式、六种交付、多人协作、多门店 |
| 4 | 收入与拓展 | 佣金两档、代收服务费、自有入口 |
| 5 | 常见问题 | 身份、费用、续费 |
| 6 | 开始开店 | 收口 |

**首页不设案例板块、不设数据背书板块**，理由见 §1.5。信任由第 4、5 节的可核对规则承担。

### 4.3 一处结构建议

**顶栏「顾客入口」改为直接跳 `/c/`**，不落在 `/download/`。
商家点进去看到的是「怎么买东西」，这是转化线上的断点。`/download/` 保留，只从页脚进。
