# 种子数据清单（14 个 n_ 库）

> 状态：只读盘点，待生成种子数据。

> 2026-11-26 整理。只是清单，还没有生成任何写入语句，也没有往任何库里写数据。
> 行数是当天在 61 正式库上只读统计的精确值；“列对比”是 61 上新表与原表的列逐个比出来的。

## 口径

种子数据 = 系统能跑起来之前必须先有、且不是商家或顾客在使用中产生的数据：权限码、角色、字典、平台商品与套餐、支付产品定义、模板、规则。
376 张表里筛出 55 张，其余 321 张是业务数据、日志或运行状态，不需要种子。

分四类：

| 类 | 含义 | 表数 |
|---|---|---|
| A | 原表有数据，新表的列与原表对得上，可以按原样搬 | 20 |
| B | 原表有数据，但要先转换（多张并一张、一段内容拆成多行、列改了含义） | 9 |
| C | 原表在正式库是空的，种子要另外定来源（迁移脚本里的初始值，或由运营录入） | 22 |
| D | 不该用种子灌：由程序启动时自己登记，或属于环境密钥 | 4 |

## 还没定、需要拍板的

4. C 类哪些这一轮就不灌。

## 已知局限

- 列对比只比了列名，没有比类型和长度；状态列新表统一成了 varchar(10)，原值超长的会写不进去，要在生成写入语句时再验。
- B 类的转换规则是按表说明推的，没有对着代码核过。
- 没有检查各表之间的引用是否自洽（例如角色功能点引用的功能点是否都在）。
