# 多行业统一业务架构能力与现状矩阵

> 状态：能力证据附录，待评审 · 创建：2026-10-20 · 阅读顺序：[共用能力整理](./多行业共用能力整理.md) → [零售核心边界](./零售基础数据与核心能力边界.md) → [完整架构](../TDD-多行业统一业务架构-零售餐饮美业.md)。
> 证据范围：本地文档、源码和构建声明；没有检查生产实例，也未在本轮执行业务测试。旧文档“已实现”与测试文件存在均不等于实际门店已可用。

## 一、判定方式

**已有**表示已定位到相关实现；**部分**表示当前仅覆盖能力的一部分；**设计**表示当前依据主要是方案/DDL，不能直接调用；**待核**表示还需具体实现或装配证据。各行的“共用归属”是本提案的逻辑所有者，不自动对应新模块或新物理表。

零售、餐饮、美业列给出能力用法，不表示默认全部启用；无即时使用需要的能力可关闭。证据代号在第六节列出，具体已确认范围仍看对应业务真源的最新修订。

本册保留首轮C/O/P编号方便追溯，分组不是核心边界。复合行如人员账号/认证、会员基础关系/标签、标准收款/复杂收银，在零售边界册按职责拆为M/K/S/E/I；不能因某行列为“商业能力”就将全部内容纳入零售核心。现行业务要求的能力也不因归为扩展而被关闭。

## 四、行业保留能力

| 编号 | 行业特定能力 | 共用依赖 | 仍由行业承担的规则 |
|---|---|---|---|
| R01 | 零售备货、拣配、交接流程 | 订单、库存、任务、人员、履约 | 拣货区/波次、称重复核、缺货处理与交接守卫 |
| R02 | 生鲜截单/预售/社区履约 | 商品、营销、库存、履约、日历 | 保留当前各域所有权；不可为“零售包”复制拼团/集单或配送体系 |
| R03 | 零售退货处置 | 售后、库存、质量事实 | 实收数量、是否可再售、换货交接；退款成功不自动证明货已回来 |
| F01 | 菜品与餐牌展示规则 | 商品、陈列目录、销售日历 | 菜系、菜序、餐牌场景、口味规则；不复制售价 |
| F02 | 桌区、座位、就餐台账 | 资源、人员、客户引用 | 人数、拼桌/并桌/转台、清台，不能因清台抹掉欠款 |
| F03 | 点单批次、同桌协作和加菜 | 来源行、报价、幂等 | 同桌草稿版本、做法快照、核心行数量映射 |
| F04 | 厨房、出品和上菜 | 作业任务、工位路由、打印、库存 | 等叫/催菜、制作/上菜数量、撤菜与损耗；工位路由不等于时间资源 |
| F05 | 退菜及专项业态 | 售后、库存、审批、收银 | 已做未做、报损、自助餐/宴席等专项，不由通用状态机代替 |
| B01 | 预约业务单 | 共用资源、客户、项目引用 | 项目顺序、指定人员、到店宽限、爽约业务事实 |
| B02 | 服务工单与换人加项 | 来源、作业任务、人员、资源 | 服务开始/完工、参与区间、加项确认、部分完成 |
| B03 | 客史与护理资料 | 会员、媒体、受控授权 | 过敏/护理记录、照片及可见范围，不默认打印或群发 |
| B04 | 业绩与提成 | 来源分摊、服务产出、人员参与、退款事实 | 提成基数/规则版本、多人分配、冲回及已发放调整 |
| B05 | 疗程服务编排 | 销售、权益发行、预约、消费来源 | 每次服务计划、使用记录、后续提醒；余额/余次仍归Pay |

这些行业对象的存在不要求新建一整套行业基础设施。行业可共享目录、资源和人员合同，也可使用不同界面和不同业务单据。

## 七、实施前需要闭合的关系

共用目录与当前餐牌配置必须明确单一所有权及迁移映射；资源预约和现场占用必须使用同一仲裁者；员工账号与技能/资源关系不能双向随意编辑；现金订单与服务消费来源不能对同一次服务重复生效；Pay、库存和业务事实必须按原来源恢复，而非重建。

统一能力注册应记录实现方、契约版本、前置能力、开通范围、运行健康、权限、操作入口及关闭后的历史收尾策略。矩阵中的目标行不直接生成可用菜单；只有实际合同与验收证据齐备才开放经营。
