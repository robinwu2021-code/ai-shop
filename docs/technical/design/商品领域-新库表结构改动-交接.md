### 3.2 为什么现在不急

v2 的配置里商品、交易的句柄都还没绑定 `n_trade`（只有发票绑到平台服务库），代码仍在原来的主库上，没有任何代码读写 .61 的 `n_trade`。

### 3.3 什么时候必须做、怎么做

**在下面任一件事之前**：商品或交易的句柄绑到 `n_trade`；在演练库上验证搬迁脚本；正式切换。商品代码现在连上这个库会因缺列、缺约束直接报错。

**做法（推荐）**：按最新 `05-n_trade.sql` 整库重建，再按搬迁规则重新同步数据。不建议原地改 —— 差异太大（光默认值就 224 条 `MODIFY COLUMN`、表集合也不同），改完切换前还得再对齐一次。原地改的语句只保留门店目录那一段，见改动清单 §1.2，用前先 `SHOW CREATE TABLE` 对一遍。

**重建前**：先与交易迁移会话（store-trade-db）确认 `05-n_trade.sql` 已是交易侧的最终版；交易还要改表的话，改完再重建，免得建两次。生成器核对：

```bash
python3 scripts/gen-retail-ddl.py /Users/workingowl/work/ai-shop-slim/docs/technical/design/schema/ddl --check
```

**搬数据**：照改动清单 §3 的取值约定（`prd_spec_usage` 的范围与空串、草稿新状态、目录一版一行、门店级与主体级行用空串、无默认值表的 `tenant_no = 'MAIN'` 等）与 TDD §2.5 的逐表搬法。
