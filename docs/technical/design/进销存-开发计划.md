## 一、这份计划的读法

**六个阶段，五道闸门。** 闸门不是里程碑，是**不过就不许往下走**的判据 ——
库存是这个系统里错了最贵的数据，而它错了通常没有任何报错。

**每个阶段自己可发布**：停在任何一个阶段末尾，系统都是完整可用的，
只是功能少一些。这是排这个顺序的唯一理由。

---

## 二、六个阶段

| 阶段 | 目标 | 停在这里能用吗 | 量级 |
|---|---|---|---|
| **S0** | 建模块、独立库、把守卫先立起来 | 能（**零行为变化**） | 小 |
| **D1** | 流水 + 盘点 + 退货回补 + 对差看板 | 能：商家看得到「谁改的」 | 中 |
| **D2** | 真相源切到进销存，预留协议接管扣减 | 能：库存的账从此只有一份 | 中 |
| **D3** | 进货 / 报损 / 调拨 / 仓 / 报表 / 导出 | 能：对外可以说「带进销存」 | 大 |
| **D4** | 独立进程 + Open API | 能：外部系统接得上 | 中 |
| **D5** | 独立交付形态 | —— | 中 |

> **对外可宣称的时点是 D3 做完**（进 · 销 · 存 · 盘 四件齐），不必等 D4/D5。

## 三、逐阶段任务

### S0 · 地基（不依赖任何待拍板项，可立刻开工）

| # | 任务 | 判据 |
|---|---|---|
| S0-a | 建 `shop-inventory` 模块 + pom（只依赖 `shop-base`） | `mvn -o -pl shop-inventory -am clean install` 通过 |
| S0-b | `InventoryDataSourceConfig`：独立 `DataSource` / `SqlSessionFactory` / Flyway（`db/inventory`） | 空 schema 能建出 17 张表 + 8 行 `inv_uom` |
| S0-c | 17 个实体 + `InventoryMappers` | 见 S0-e |
| S0-d | **搬家**：`StockPortImpl` / `PrdStoreStock` / `PrdStockLock` | 抽出行段 `diff` **0 行差异**，原类 diff 全删除零新增 |
| S0-e | **扩两个 DDL 守卫**（`ddl-parsable` / `entity-alignment`）到 `db/inventory` | **故意漏补一列 → 守卫变红且点名**；撤掉再变绿 |
| S0-f | **新增写权守卫**：`shop-inventory` 以外不得写 `inv_*` | 能红、点名到类与行、**拦提交** |

> **S0 必须在 D1 之前**：D1 的流水与盘点是新代码，写进 `shop-core` 再搬出来是两倍工作量，
> 而且那时它已经有调用方了。

**闸门 G1**：守卫能红且点名 —— 恒绿的守卫等于没有守卫。

### D1 · 证据（本期真正的交付物）

| # | 任务 | 判据 | 依赖 |
|---|---|---|---|
| D1-a | `StockPostingService` + `LedgerMapper` | 过账重放不写两行（唯一键） | S0 |
| D1-b | **回放守卫**：`prev.balance_after + delta == balance_after` | **撤掉写入必须变红且点名到 SKU** | D1-a |
| D1-c | `StockCountService`（含单件「改数」） | 盘点 / 负库存 / 幂等 三条场景测试 | D1-a |
| D1-d | **`restore` 退货回补** | `RETURN_REFUND` 回补、`REFUND_ONLY` **不**回补、重复触发不加两遍 | D1-a |
| D1-e | **搬运任务**：存量库存 → 默认库位 + `INIT` 流水 | 幂等可重跑 · 只读平台库 · **结束打对差报告** | 拍板 C |
| D1-f | `BizStockController`（s01 s02 s03）+ B 端三屏落地 | **每屏 `grep navigateTo` 有出口**（B-0） | 拍板 E |
| D1-g | `OpsInventoryController.recon` + 对差跑批 | 对差数能对上手工抽查 | D1-e |

**闸门 G2**：D1-b / D1-d 的守卫与场景测试**撤掉修复必须变红**。
只跑绿一次不算 —— 这个仓库栽过「恒红的守卫等于噪声掩体」。

### D2 · 真相源切换（唯一一次不可回退）

| # | 任务 | 判据 | 依赖 |
|---|---|---|---|
| D2-a | `ReservationService`：`reserve/commit/release` | 并发测试不超卖；`commit` 产出 `SALE` 出库单 | D1 |
| D2-b | `StockPort` 旧签名转发到新方法 | **交易域 0 行改动** | D2-a |
| D2-c | 平台 `prd_sku.stock` 降为只读缓存（或退役，见拍板 B） | 写权守卫不再红在 `MerchantGoodsServiceImpl` | 拍板 A B |
| D2-d | `prd_store_stock` / `prd_stock_lock` 退役 | **两条路径合一**：`hasStoreStock` 判断消失 | D2-c |
| D2-e | 商品/商家档案投影 + 补偿任务 | 建品后能立刻入库（拍板 ⑤） | —— |

**闸门 G3**：**对差连续 N 天为零**才准切。
直接切等于「切换那天开始超卖」，而无从回溯是从哪一刻起的。

### D3 · 补上「进」与「账」

| # | 任务 | 判据 |
|---|---|---|
| D3-a | `InboundService` + 进货单（s04） | 过账后 `cost_price` 更新为最新进价 |
| D3-b | `OutboundService` + 报损（s06）、单据中心（s05） | `POST outbounds` **拒绝 `purpose=SALE`** |
| D3-c | `TransferService` + 仓与调拨（s07 s09） | **发出到收到之间 `Σ on_hand` 不变** |
| D3-d | 报表（s08）+ 榜单 + 毛利估算 | 五数等式**在界面上对得上**；毛利标「估算」 |
| D3-e | CSV 导出 | UTF-8 带 BOM；**portal 层写审计** |
| D3-f | 运营端台账 + 健康度两个 tab | 需 `product:stock:read`（拍板 D） |
| D3-g | 档位能力位 `inv_purchase` / `inv_warehouse` | `FREE` 能看流水与盘点、`PRO` 才能建进货单 |

**闸门 G4**：进销存月报的五数等式在界面上对得上，且与流水逐行可核。

### D4 / D5 · 独立

| # | 任务 | 判据 |
|---|---|---|
| D4-a | 冷路径挂 `worker` / 新 `@Profile("openapi")` | 报表跑批与导出不再与下单同进程 |
| D4-b | `inv_open_credential` + Open API 四接口 | 幂等走自然键；游标按 `id` |
| D4-c | 物理库拆到独立实例 | 跨库 join 守卫仍绿 |
| D5 | `acl` 不部署、`Item.source=OWN` | **能在一台空机器上装起来跑通一遍进销存** |

**闸门 G5**：D5 的那一条判据本身就是闸门 —— 装不起来就不叫可独立交付。

## 六、并行与切分

这个目录常有多个会话同时在改（ADR-015）。按能不能并行分三类：

| 类 | 内容 | 说明 |
|---|---|---|
| **能并行** | S0-c 实体、D3 的各 Service、B 端各屏 | 各自的文件不重叠 |
| **要排队** | 平台侧迁移（权限码、功能点） | **迁移号会撞**；`inv` 自己的 Flyway 是独立历史，不受影响 |
| **只能一个人做** | D1-e 搬运、D2-c 真相源切换 | 不可回退，且要盯对差 |

三条纪律（都是这个仓库栽过的）：
提交前 `git diff HEAD -- <file>` 自己读一遍 · 不 `git add <目录>` ·
不 stash / checkout 别人的文件。

## 七、风险与兜底

| 风险 | 兜底 |
|---|---|
| **搬运不可回退** | 双写对差期（G3）；对差不为零就不切 |
| 守卫恒红变成噪声掩体 | 每条守卫立起来时**先验一次红**，再验绿 |
| 页面没有入口（栽过三次） | B-0 验收项，每屏 `grep navigateTo` |
| 平台侧迁移号撞车 | 排队做；`inv` 独立历史已避开一半 |
| 共享工作树里 HEAD 编不过 | 如实说，不硬凑；worktree 也救不了 |
| 熔断默认放行 → 超卖 | 代码注释写死**方向是拒绝**；并发测试覆盖 |
| 投影延迟让建品后入不了库 | 同步投影 + 失败降级异步（拍板 ⑤） |
