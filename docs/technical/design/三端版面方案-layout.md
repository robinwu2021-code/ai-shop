# 三端版面方案（layout）

> 这一份回答的是**「一屏东西怎么摆」**，与[UI 标准库清单](./UI标准库清单.md)（一件东西长什么样）
> 是两回事。此前只有后者 —— 于是「按钮该多大」有唯一答案，而「贴底那条摆哪儿」
> 每个页面各答一次，答了 12 次。

## 一、页面骨架只有一层：`sh-scaffold`

三端所有页面都套在它里面。它管四件事，**只管这四件**：

| props | 管什么 |
|---|---|
| `titleKey` | 导航栏标题。`pages.json` 里的是静态的，切语言不会变 |
| `padded` | 内容区要不要横向留白 |
| `tab` | 传了就渲染自定义底部菜单，值是当前高亮项 |
| `denied` | 无权访问：整页换成一句说明，**不渲染 slot** |

`denied` 那条值得单说：受限页面的失败形状高度一致 —— 接口被拒 → catch 成空数据 →
画出一个正常的空态。实测过的样子是店员打开结算页看到「还没有可结算的订单」，
**他会以为店里没生意，而不是「这页不该我看」**。把「不给看」渲染成「没有」，
比报错更糟：它不像故障，像事实。

**骨架之外的版面节奏（分区间距、滚动、吸顶）不在它管辖内** —— 那是下面几节的事。

## 二、贴底条：三种形态，各有各的意思

这是版面里唯一被画了很多遍的东西。**三种形态不是三种皮肤，是三句不同的话**：

| 组件 | 位置 | 它说的是 | 调用点 |
|---|---|---|---|
| `sh-savebar` | 通栏贴底（left/right/bottom 全 0） | 「你有未保存的改动」 | B 端 2 |
| `sh-actionbar` | 悬浮内缩（两侧 28rpx、离底 28rpx） | 「这一页的主动作」 | C 端 12 |
| `sh-fab` | 右下角角标，避让 tabBar | 「再来一个」 | B 端 1 |

**为什么 savebar 要压住整条底边**：未保存是一个未完成的状态，它应该显眼到躲不开。
而 actionbar 露出四边，是要让人看得见它下面还有内容 —— 那一页没有未完成的状态，
只有一个建议你现在做的动作。

`sh-actionbar` 的两个药丸档是**量出来的不是设计出来的**：

- `pill="plain"` 一排东西等距（`goods` 的分享 / 购物车 / 加入）
- `pill="lead"` 左边一段文字、右边一个按钮，左内边距 40rpx —— 药丸是全圆角，
  文字贴着圆边会像被切掉一块（`cart` 与 `order-confirm` 两处**逐字节相同**）

### 占位块必须和条在同一个组件里

`sh-actionbar` 除了条还渲染一个流内占位块。这是它存在的主要理由：

收编前 **11 页各写一份占位块**，名字四种（`spacer` / `fab__spacer` /
`checkoutbar__spacer` / `actionbar__spacer`），高度**六种**（140 / 160×2 / 180×4 /
200 / 220×2）—— 全是手估的，因为条是 `fixed`，CSS 量不到它的真实高度。

**条高与占位高是必须相等的两个数。不相等不会报错，只是最后一行看不见** ——
而看不见的东西没有人会去报。散在 11 个地方靠人对，是迟早会错的安排。

> 它仍然不能自动对齐（`fixed` 元素的高度 CSS 取不到），所以 `pad` 是一个明写的数。
> **明写一个可能过期的数，好过假装它会自己对上。**

## 三、安全区：只有组件碰它

`env(safe-area-inset-bottom)` 此前在页面里出现 **15 处**（C 端 13 / B 端 2），
每一处都是「这一页自己记得要避开 Home Indicator」。现在剩 **2 处**，
其余都落在 `sh-actionbar` / `sh-savebar` / `sh-fab` / `sh-sheet` 里面。

**判据**：页面里出现 `safe-area-inset` 就说明有一个该收编而没收编的贴底件。

## 四、还没有方案的两件（如实记着）

**① 页面内边距**：`--sh-pad-page` 只有 3 处引用，而页面根上写死 `padding` 有
222 处。也就是说「一页四周留多少白」这件事**在变量里定义过、在代码里没人用**。
横向留白靠 `sh-scaffold` 的 `padded`，纵向节奏则完全散着 ——
`.sh-mt-md` / `.sh-mb-md` 那一族是这一轮才落的，只有 2 个调用点。

**② 吸顶**：`position: sticky` 全仓 **0 处**。筛选条、分组头这些「滚上去要留在顶上」
的东西，现在要么不留、要么整段重画。这不是欠账，是**这套界面还没决定要不要这个能力** ——
写在这儿是为了下次有人需要时，知道它是空白而不是被否决过。

## 五、运营端不在这一份里

`ops-web` 是 React/Next，用不了 `sh-*`，版面走它自己那套（Tailwind + 一套
`secondary-nav`）。它的 23 个页面**不在**上面的任何统计里。
不管它是有意的，但要说出来 —— 一份不声明范围的清单，最危险的不是漏，
是它把「没查过」呈现成「查过了没问题」。
