## M1 会员与顾客档案

统计粒度是旧会员与证据门店。一人跨两店有两条匹配结果，主体人数按租户、主体、旧会员号去重，品牌人数按租户、范围、顾客号去重。首次门店、旧门店行、新档案与来源记录分别保留。单有来源明细、缺少可验证身份或经营归属的记录列入缺失。品牌绑定准备中、已失效的品牌、身份或档案冲突进入歧义清单。

| 夹具 | SQL 结果 | 处置 |
|---|---|---|
| MC，品牌 BR 下的 A、B 店 | 两条 UNIQUE，共用已核实关系 SM。A 为 1 单 100 分，B 为 2 单 200 分；两个档案均为 REGULAR，旧行与新行均为 MATCH。主体合计 3 单 300 分。 | 经营指标按店展示。A 有备注，B 有顾问，MC 主体已退订。各店资料保留在相应档案。 |
| MS，单店主体 ES 的独立门店 C | 一条 UNIQUE，首次门店可核实，暂无范围映射与门店经营档案。主体 1 单 100 分，旧关系 BLOCKED。 | 单店回落使用主体指标。未核实的新关系和历史黑名单均需保留原读路径。 |
| MM，缺少门店；MX，X 店的品牌绑定为 PREPARING | 一条 MISSING、一条 AMBIGUOUS；总计 5 条证据行，4 名旧会员。 | MM 补查原来源单据；MX 待绑定产生最终事实再判定。禁止按同一主体或电话推定经营范围。 |

`UNIQUE` 只表示身份与门店证据可以唯一匹配。核销前后等增量可能改变订单指标，`MATCH` 应在迁移基准点核对；基准点之后的差异须按期间权威订单重放。退出旧映射前应逐行处理缺失和歧义，检查经核实的 `mbr_scope_legacy_link`、单店回落、主体去重人数与门店指标，并按受权门店账号验证私有备注、顾问、退订、黑名单。夹具已核对存储范围，真实账号权限和消息投递仍须业务验收。

一行代表租户、来源系统、原模板号，包含该来源下的全部实例。冲突可能同时命中两个来源，同一族也可能具有多项风险。夹具共 7 个来源根、6 个券号，全部仍由 Core 写。每行均列出实例数、批次数、占用/迁移状态、使用和返券证据，可按原券号继续查询实例、批次、版本与门店明细。

|---|---|---|
| PMT / STORE | 1 批、1 张未使用券，STORE2 仅包含门店 A，实测发行敞口 100 分 | RUN_STORE_PREFLIGHT，冻结后另核对发行版的有效门店明细与资格。 |

本组夹具按来源根统计，限定门店 1、多版本 1、有核销 1、有冲回 1、冲突 2、发行证据不全 1。已核销与已冲回来自同一族。另有结果集登记无法找到模板的实例、无法找到原持券人的核销、迁移后旧协议操作及对应售后。模板写入方由 Core 源决定、批次、计划哈希、Pay 导入回执及归属登记核对；实例的使用路由还需逐张匹配持有人、源实例、目标号及归属。如仅有归档映射，保留历史查询。

C2 的隔离交易测试 `LegacyCouponMigratedIssuanceFlowTest.merchantCanCreateClaimAndContinueIssuingAnUnusedFamilyAfterCutover` 从 Core 发券、冻结快照、提交归属到 Pay 导入、续发和报价。三组分别选全店、单版限定门店、多发行版。多版样本先发门店 A 面额 100 的券，再改成全店面额 200 并在切换前发出新版。切换后旧券仍只向 A 的订单分组折抵 100，其他店拒绝；已发新版和 Pay 新发券在其他店都按 200 使用。已有同源领取及发放重放继续返回原回执。全店与指定门店两种券均通过实际建单、扣次、整退、重复售后及并发重放；剩余次数恢复为 1，反向权益账和原售后冲回各 1 笔。这些写操作只发生在测试数据库。

C1 的只读 SQL 只给下一步预检建议。C2 的授权单位是完整券族；历史订单使用/冲回、未决占用、实例与批次版本不一致、缺有效范围或规则、编号冲突仍交原流程。多版另需每张券面额／折扣封顶与原版可核对，累计逐张敞口与 `pmt_coupon.issued_exposure_minor` 对平。当前批次支持单次、有效、未核销的 CENTER／TARGETED 商家订单券。

限定门店和多版本的候选判定另检查三个字段。`incomplete_versions` 统计缺失的原版本，以及缺少正向范围明细、快照和范围类型不符、或缺少受支持的单次订单券规则的版本。`invalid_unused_instances` 统计已删、已用、过期、有效期异常或商家不符的实例。`observed_issued_exposure_minor` 按实例发行版面额或折扣封顶求和；多版本时与源账 `issued_exposure_minor` 对比。快照与批次缺失列为 HOLD，范围、实例或敞口证据不符列为 CHECK_VERSION_EVIDENCE。有真实核销的券单列 CHECK_ORIGINAL_HISTORY，不能进入这两个未使用券批次。

在同一隔离库先用空规则快照验证，STORE 和 MULTI 均进入 CHECK_VERSION_EVIDENCE。补入完整的人工历史版本及有效期后，两族的 `incomplete_versions` 和 `invalid_unused_instances` 均为 0；STORE 进入单版本门店候选，MULTI 进入多版本候选。上述七个来源根中，3 个进入预检、3 个保留、1 个核对原使用历史。有效期以运行时刻判断，夹具过期后应转为人工核验。

SQL 候选对应 `UNUSED_STORE_COUPONS`、`UNUSED_VERSIONED_COUPONS` 两个迁移批次；同时存在多版本和门店限制时选多版本批次。当前模板完整快照与当前发布版逐字段一致、别名、市场与商家有效性、预算和每人限领、冻结水位及单一写入方由原冻结评估和迁移计划最终核验。日常只读预检中的发行版本差异、待核对门店证明仍应带入冻结证据复核。

C2 上线前逐批核对以下证据。

1. **每个发行版本的门店与规则。** 从实例和批次追到不可变规则及 `ENT_TEMPLATE` 范围行，逐版本核对是否只包含明确门店，或只有一条 ALL / *。出现排除规则或其他范围类型时转人工核验。无版本的旧行只能在有独立发行证据时补证。旧端当前可验证限定门店，已有 `CouponStoreScopeTest` 报告 3 项通过。冻结清单为限定门店及多版本候选携带原版本规则与范围。归一化按版本构建 Pay 规则；STORE 仅计入原商家和指定门店的订单分组。多版本券还须按各实例原面额或折扣上限重算累计发行敞口并与源账一致。范围不全、没有原版、批次和实例发行版不符的券族保留在 Core。
2. **源与目标写入。** 按完整券族运行受控预检、排空和冻结，核对决定、计划及回执哈希。逐实例验证归属唯一、门店 A 可用而其他门店拒绝、旧券按发行版计价后，才能切换该族。无源证据、编号冲突、冻结未决保留现有栅栏。
3. **原核销及售后决定。** 迁入前用原 `pmt_apply.apply_no` 对 `ent_migration_usage.source_usage_no`；迁入后旧协议用原实例和操作号对 `ent_usage`。按原订单取消或售后号对 `ent_use_reversal`；历史返券还需核对 `pmt_migration_return` 和 `ent_migration_return` 单笔回执。重复同一决定须返回原结果。已有 `LegacyCouponHistoricalMigrationFlowTest` 报告 2 项通过，覆盖历史使用与整退；只读盘点没有执行迁移切换。
