# 任务库：表字段

状态：字段草案。创建：2026-11-26。上一层：[表说明](../库/14-任务库.md)。
保留的表沿用现有的列；合并和新建的表的字段按并入的旧表推出，没有对着代码核过。
每张表都有的公共列（`id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`、`deleted`）不重复列出。
“来源”一栏：原有 = 原表就有的列；并入自 = 从被并入的旧表带过来；新增 = 这次设计新加的。

## 1 定时任务

### job_definition

任务定义：任务定义

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `job_name` | varchar(64) | 任务名，唯一 | 原有 |
| `display_name` | varchar(64) | 任务展示名 | 原有 |
| `description` | varchar(255) | 任务说明 | 原有 |
| `handler_name` | varchar(64) | 执行处理器名 | 原有 |
| `target` | varchar(16) | 执行目标：LOCAL 本进程 / HTTP 调用微服务 | 原有 |
| `params` | text | 任务参数 JSON | 原有 |
| `cron` | varchar(64) | 执行周期 cron 表达式 | 原有 |
| `enabled` | tinyint | 是否启用：1 启用 / 0 停用 | 原有 |
| `timeout_sec` | int | 单次运行超时秒数 | 原有 |
| `lock_at_most_sec` | int | 单次运行最长占用时长（秒），超过视为卡死可被重跑 | 原有 |
| `manual_trigger` | tinyint | 是否允许运营手动触发：1 允许 | 原有 |
| `log_every_run` | tinyint | 是否每次运行都写运行记录：1 是 / 0 只记失败与有产出的 | 原有 |
| `source` | varchar(8) | 定义来源：CODE 代码声明 / OPS 运营录入 | 原有 |
| `missing` | tinyint | 代码里已找不到该任务：1 是，只标记不删 | 原有 |
| `owner_module` | varchar(32) | 负责模块 | 原有 |
| `trigger_requested_at` | datetime | 运营请求手动触发的时间，worker 读到后执行 | 原有 |
| `last_triggered_at` | datetime | 最近一次手动触发被执行的时间 | 原有 |

唯一键与索引：任务名唯一；按处理器名查。

留意：运营写，worker 只读。

### job_run

任务现状：任务现状

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `job_name` | varchar(64) | 任务名，每任务一行 | 原有 |
| `last_run_at` | datetime | 最近一次开始运行时间 | 原有 |
| `last_status` | varchar(16) | 最近一次结果：OK 成功 / FAILED 失败 / TIMEOUT 超时 / SKIPPED 跳过 | 原有 |
| `duration_ms` | bigint | 最近一次耗时（毫秒） | 原有 |
| `detail` | varchar(500) | 最近一次做了什么，如「投出 12 条」「关单 3 单」 | 原有 |
| `error` | varchar(500) | 最近一次失败原因 | 原有 |
| `consecutive_failures` | int | 连续失败次数 | 原有 |
| `run_count` | bigint | 累计运行轮数 | 原有 |
| `next_run_at` | datetime | 下次计划运行时间 | 原有 |
| `running` | tinyint | 是否正在运行：1 是 | 原有 |
| `current_run_id` | varchar(40) | 正在运行的那次运行号，指向 job_log.run_id | 原有 |
| `running_instance` | varchar(255) | 正在运行它的实例标识（主机名） | 并入自 shedlock |
| `running_since` | datetime(3) | 本次开始占用的时间 | 并入自 shedlock |
| `running_until` | datetime(3) | 本次占用最长到何时，到点后其他实例可接手 | 并入自 shedlock |

唯一键与索引：任务名唯一。

留意：worker 写，运营只读。shedlock 的锁并入后由任务库自己判定“是否正在跑”，不再另设锁表；sys_job_run 与原表同义已合并。

### job_log

运行记录：每次运行一行

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `run_id` | varchar(40) | 运行号，唯一 | 原有 |
| `job_name` | varchar(64) | 任务名 | 原有 |
| `tenant_no` | varchar(32) | 租户编号；平台级任务为空 | 并入自 cim_sync_run |
| `run_type` | varchar(32) | 运行类别：SCHEDULED 定时任务 / CATALOG_SYNC 渠道商品同步 / AVAILABILITY_PUBLISH 渠道可售发布 / CATALOG_SNAPSHOT 目录快照 / MEDIA_PURGE 图片回收 | 并入自 cim_sync_run |
| `trigger_type` | varchar(16) | 触发方式：SCHEDULE 定时 / MANUAL 人工 / EVENT 事件触发 / RECOVERY 补偿 | 原有 |
| `scope_type` | varchar(16) | 处理范围类型：STORE 门店 / CONNECTION 渠道连接 / ENTITY 主体；全平台为空 | 并入自 cim_sync_run |
| `entity_no` | varchar(32) | 处理范围所属商家主体编号 | 并入自 cim_sync_run |
| `scope_no` | varchar(32) | 处理范围编号，如门店号、渠道连接号 | 并入自 cim_sync_run |
| `source_ref` | varchar(128) | 触发来源引用，如触发的事件号 | 并入自 cim_sync_run |
| `biz_date` | date | 处理的业务日期 | 原有 |
| `operator_no` | varchar(64) | 人工触发的操作人 | 并入自 sys_media_purge_batch |
| `operator_name` | varchar(64) | 人工触发的操作人姓名快照 | 并入自 sys_media_purge_batch |
| `started_at` | datetime | 开始时间 | 原有 |
| `finished_at` | datetime | 结束时间 | 原有 |
| `duration_ms` | bigint | 耗时（毫秒） | 原有 |
| `status` | varchar(16) | 结果：QUEUED 排队 / RUNNING 运行中 / OK 成功 / PARTIAL 部分成功 / FAILED 失败 | 原有 |
| `total_count` | int | 本次应处理条数 | 并入自 sys_media_purge_batch |
| `success_count` | int | 成功条数 | 并入自 sys_media_purge_batch |
| `failed_count` | int | 失败条数 | 并入自 sys_media_purge_batch |
| `total_bytes` | bigint | 处理的数据量（字节），如回收的图片总大小 | 并入自 sys_media_purge_batch |
| `result_ref` | varchar(256) | 产出引用，如快照文件、外部发布证据 | 并入自 cim_catalog_snapshot |
| `detail` | varchar(500) | 这一轮做了什么 | 原有 |
| `error_code` | varchar(64) | 失败错误码 | 并入自 cim_sync_run |
| `error` | varchar(500) | 失败原因 | 原有 |
| `next_recovery_at` | datetime(3) | 失败后计划补偿时间 | 并入自 cim_sync_run |
| `worker_instance` | varchar(64) | 执行实例标识 | 原有 |
| `http_status` | int | 调用微服务时对方返回的 HTTP 状态 | 原有 |

唯一键与索引：运行号唯一；任务名 + 开始时间查历史；主体 + 范围 + 运行类别查最近一次同步。

留意：cim_sync_run_item（每个对象的同步结果）是一对多且各有结果，备注说结果记在资源映射上，不压进本表；cim_catalog_snapshot 的 payload_json 与 cim_availability_publication 的发布内容体量大，这里只存 result_ref 引用，原文应落文件存储。

### job_cursor

任务游标：任务游标
（新建）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户编号 | 并入自 prn_reconcile_cursor |
| `job_name` | varchar(64) | 所属任务名，指向 job_definition.job_name | 并入自 pts_cursor |
| `scope_type` | varchar(16) | 游标范围类型：GLOBAL 全局 / STORE 门店 / SOURCE 来源 / QUEUE 队列 | 新增 |
| `scope_no` | varchar(128) | 游标范围编号，如门店号、来源类型、队列名；GLOBAL 为空 | 并入自 payment_collection_scope |
| `entity_no` | varchar(64) | 范围所属商家主体编号 | 并入自 prn_reconcile_cursor |
| `store_no` | varchar(64) | 范围所属门店编号 | 并入自 prn_reconcile_cursor |
| `watermark_seq` | bigint | 按序号推进时已处理到的序号 | 并入自 pts_cursor |
| `watermark_at` | datetime(3) | 按时间推进时已处理到的时间点 | 并入自 prn_reconcile_cursor |
| `watermark_no` | varchar(200) | 按业务号推进时已处理到的最后一个编号，如子订单号 | 并入自 ord_points_work_cursor |
| `overlap_seconds` | int | 每次回看的重叠秒数，防止漏掉迟到的数据 | 并入自 prn_reconcile_cursor |
| `last_full_scan_at` | datetime(3) | 最近一次全量扫描时间 | 并入自 prn_reconcile_cursor |
| `last_success_at` | datetime(3) | 最近一次成功推进时间 | 并入自 prn_reconcile_cursor |
| `last_error_code` | varchar(64) | 最近一次推进失败的错误码 | 并入自 prn_reconcile_cursor |
| `status` | varchar(16) | 游标状态：ACTIVE 正常推进 / PAUSED 暂停 / FAILED 失败待处理 | 并入自 pts_cursor |

唯一键与索引：租户 + 任务名 + 范围类型 + 范围编号唯一；按门店查各任务进度。

留意：并入的旧表里 ord_points_command（命令请求与结果）、ord_points_refund_retry（售后单改号重试）不是游标，是幂等记录或待办单，按“技术件不写”未设字段；若退款改号重试是业务待办，应归订单或积分库。prn_reconcile_cursor 的租约列属于锁，不保留。
