# 平台服务库：表字段

状态：字段草案。创建：2026-11-26。上一层：[表说明](../库/12-平台服务库.md)。
保留的表沿用现有的列；合并和新建的表的字段按并入的旧表推出，没有对着代码核过。
每张表都有的公共列（`id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`、`deleted`）不重复列出。
“来源”一栏：原有 = 原表就有的列；并入自 = 从被并入的旧表带过来；新增 = 这次设计新加的。

## 1 通知与常见问题

### notify_channel

触达渠道：短信、邮件、微信订阅消息、App 推送、站内信各接了哪家服务商，优先级与启停；凭据只存引用

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `channel_no` | varchar(48) | 渠道编号，业务主键 | 原有 |
| `channel_type` | varchar(16) | 触达类型：SMS 短信 / MAIL 邮件 / WXSUB 微信订阅消息 / PUSH App 推送 / INAPP 站内信 | 原有 |
| `provider` | varchar(16) | 服务商：ALI 阿里云 / SMTP 邮件服务器 / WECHAT 微信 / GETUI 个推 / FCM 谷歌推送 / APNS 苹果推送 / INTERNAL 平台自有 | 原有 |
| `scope` | varchar(16) | 接入范围：PLATFORM 平台统一接入 / MERCHANT 商家自带通道 / TEST 测试接入 | 原有 |
| `owner_no` | varchar(64) | 接入范围为商家时的商家号；平台与测试接入为空串 | 原有 |
| `enabled` | tinyint | 启停开关，运营可即时停用：1 启用 / 0 停用 | 原有 |
| `priority` | int | 同类型同服务商多个实例时的选用优先级，数值小者先用 | 原有 |
| `cred_ref` | varchar(64) | 平台与测试接入的凭据引用（环境变量前缀），不存明文 | 原有 |
| `sec_key_id` | varchar(64) | 商家自带通道的凭据在密钥库里的密钥编号，替代原来落在本表的凭据密文 | 新增 |
| `config_json` | varchar(1024) | 非敏感接入参数，如短信签名、模板号、推送主题，可在界面回显 | 原有 |

唯一键与索引：渠道编号唯一；渠道类型 + 接入范围 + 商家号 + 启用 + 优先级 索引，用于选通道。

留意：原表 secret_cipher 存商家凭据密文，按“密钥不落业务表”改为 sec_key_id 引用密钥库；cred_ref 与 sec_key_id 是两种来源的凭据引用，后续可考虑统一成一个。

### notify_template

通知模板：每个模板、每种语言一行，带服务商侧的模板号

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `template_no` | varchar(64) | 平台内部模板号，同一模板的各语言共用 | 原有 |
| `name` | varchar(128) | 模板名称，运营识别用 | 原有 |
| `channel` | varchar(16) | 适用渠道：SUBSCRIBE 微信订阅消息 / PUSH App 推送 / INBOX 站内信 | 原有 |
| `lang` | varchar(16) | 语言：zh-CN 简体中文 / en 英文 / ar 阿拉伯文等，缺失时按回落链取 | 原有 |
| `content` | varchar(1024) | 模板正文，含 {占位符} | 原有 |
| `provider_template_id` | varchar(64) | 服务商侧的模板编号（如微信订阅消息模板 ID），站内信为空 | 原有 |
| `enabled` | tinyint | 是否启用：停用后引用它的推送立即发不出去 | 原有 |

唯一键与索引：模板号 + 语言唯一。

### notify_scene_channel

场景与渠道的开关：某个场景（如订单已付款）对某类接收人走哪些渠道、推送级别。平台级

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `scene_code` | varchar(48) | 场景码，与业务事件码同一套，如 ORDER_ARRIVED 订单已到达 | 原有 |
| `audience` | varchar(16) | 接收人类别：C_USER 消费者 / B_STAFF 商家员工 / OPS_STAFF 运营人员 | 原有 |
| `channel` | varchar(16) | 触达渠道：INAPP 站内信 / WXSUB 微信订阅 / PUSH App 推送 / SMS 短信 | 原有 |
| `enabled` | tinyint | 平台级开关：1 开 / 0 关；站内信恒为开且界面锁定 | 原有 |
| `push_level` | varchar(8) | 推送级别：NORMAL 普通 / RING 响铃提醒，仅 App 推送有意义 | 原有 |

唯一键与索引：场景码 + 接收人类别 + 渠道唯一。

### notify_store_setting

门店通知开关：门店自己对每个场景、每个渠道的开关。和平台开关串联，平台关了门店开也不发
（原 `mch_notify_pref`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `store_no` | varchar(64) | 门店号，开关按门店而不是按主体，一个主体下各店各管各的 | 原有 |
| `scene` | varchar(48) | 场景码，如 SUB_ORDER_PAID 子订单已付款，与平台场景同一套 | 原有 |
| `channel` | varchar(16) | 渠道：WXSUB 微信订阅 / WEBHOOK 企微群 / SMS 短信 / MAIL 邮件 / PUSH App 推送；站内信不在此表 | 原有 |
| `enabled` | tinyint | 门店自己的开关：1 开 / 0 关；与平台开关串联，平台关了这里开也不发；缺行视为开 | 原有 |

唯一键与索引：门店号 + 场景码 + 渠道唯一。

### notify_store_recipient

门店通知的接收地址：额外的短信号码、邮箱、企微群地址，一个地址一行
（原 `mch_notify_recipient`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `store_no` | varchar(64) | 门店号 | 原有 |
| `sms_phones` | varchar(255) | 额外的短信接收号码，逗号分隔，最多 2 个；店主登录手机号恒发，不在此处 | 原有 |
| `email` | varchar(128) | 邮件接收地址，空表示不发邮件 | 原有 |
| `wecom_webhook` | varchar(512) | 企业微信群机器人的 Webhook 地址（当前明文存放） | 原有 |

唯一键与索引：门店号唯一（原表一个门店一行）。

留意：desc 说“一个地址一行”，但原表是一个门店一行、短信号逗号拼接；若按地址一行，应改为 store_no + addr_type(SMS/MAIL/WEBHOOK) + address 的结构。企微 Webhook 地址含访问密钥，按“凭据不落业务表”宜改存密钥库编号。

### notify_message

一条通知：发给谁、标题正文、点开去哪、是否已读、关联的业务单。排队叫号、套餐到期提醒、储值变动、发到买方邮箱的发票，都是一条通知

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `message_no` | varchar(64) | 通知单号，业务主键 | 原有 |
| `receiver_type` | varchar(16) | 接收人类型：USER 消费者 / STAFF 商家员工 / OPS 运营人员 / GUEST 无账号的联系人（如排队登记的手机号、发票收票邮箱） | 原有 |
| `receiver_no` | varchar(64) | 接收人编号；无账号联系人时为联系方式引用 | 原有 |
| `msg_type` | varchar(16) | 通知类型：SYSTEM 系统消息 / ORDER 订单 / QUEUE_CALL 排队叫号 / EXPIRY 套餐到期提醒 / STORED_VALUE 储值变动 / INVOICE 发票送达 / MARKETING 营销 | 原有 |
| `scene_code` | varchar(48) | 触发场景码，与场景渠道开关同一套，用于查平台与门店开关 | 并入自 notify_stored_value_task |
| `template_no` | varchar(64) | 所用通知模板号；自由文本的系统消息为空 | 原有 |
| `title` | varchar(128) | 标题 | 原有 |
| `body` | varchar(512) | 正文（已套模板后的文字） | 原有 |
| `values_json` | json | 模板占位符的取值，各渠道按自己的模板重新渲染时用 | 并入自 notify_stored_value_task |
| `link` | varchar(255) | 点开后跳转的完整页面路径（带参数） | 原有 |
| `is_read` | tinyint | 站内是否已读：1 已读 / 0 未读 | 原有 |
| `biz_type` | varchar(32) | 关联业务单类型：ORDER 订单 / QUEUE_TICKET 排队号 / ENTITLEMENT 套餐权益 / STORED_VALUE 储值流水 / INVOICE 发票 | 原有 |
| `biz_no` | varchar(64) | 关联业务单号，如订单号、排队号、权益编码、储值流水号、发票号 | 原有 |
| `entity_no` | varchar(64) | 所属经营主体号 | 原有 |
| `store_no` | varchar(64) | 所属门店号 | 原有 |
| `dedup_key` | varchar(128) | 业务去重键：同一业务单同一场景同一接收人只生成一条通知，如到期提醒按“权益 + 到期阈值档” | 原有 |
| `due_at` | bigint | 计划送达时刻（毫秒），如到期提醒的应发时刻；空表示立即 | 并入自 commerce_expiry_notice |
| `expires_at` | bigint | 通知失效时刻（毫秒），过期未送达不再发送，如套餐已到期、发票下载链接到期 | 并入自 commerce_expiry_notice |
| `at` | bigint | 通知生成时刻（毫秒） | 原有 |

唯一键与索引：通知单号唯一；去重键唯一；接收人类型 + 接收人 + 已读 + 时刻 索引（站内信列表）；业务类型 + 业务单号 索引。

留意：到期提醒的阈值档、权益版本等仅为生成判断用，不再单列，由 dedup_key 与 values_json 承载；各渠道的发送状态、重试与服务商回执都在 notify_delivery。

### notify_delivery

发送记录：一条通知在每个渠道的一次发送，各有成功或失败、错误信息、服务商回执号、重试次数；重发是又一行。验证码短信这类没有站内消息的发送也记在这里
（原 `sys_notify_log`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 新增 |
| `notify_no` | varchar(32) | 发送记录号，业务主键 | 原有 |
| `message_no` | varchar(64) | 所属通知单号；验证码短信、初始密码邮件等没有站内通知的发送为空 | 新增 |
| `resend_of_no` | varchar(32) | 重发时指向被重发的那条发送记录号；首次发送为空 | 并入自 ivc_invoice_delivery |
| `channel` | varchar(16) | 渠道：SMS 短信 / MAIL 邮件 / WXSUB 微信订阅 / PUSH App 推送 / WEBHOOK 企微群 | 原有 |
| `provider` | varchar(16) | 服务商：ALI / SMTP / WECHAT / GETUI / FCM / APNS；历史行可能为空 | 原有 |
| `biz_type` | varchar(32) | 发送用途：OTP 验证码 / OPS_INIT_PASSWORD 运营初始密码 / OPS_RESET_PASSWORD 运营重置密码 / NOTICE 业务通知 / INVOICE 发票送达 / TEST 测试 | 原有 |
| `store_no` | varchar(64) | 所属门店号，门店维度的发送统计与排查用 | 并入自 commerce_expiry_notice |
| `recipient_type` | varchar(32) | 收件人类型：USER 消费者 / STAFF 商家员工 / OPS 运营人员 / ADDRESS 仅有联系地址 | 并入自 commerce_expiry_notice |
| `recipient_no` | varchar(64) | 收件人编号（用户号、员工号）；仅有地址时为空 | 并入自 commerce_expiry_notice |
| `target` | varchar(64) | 收件地址的掩码（手机号、邮箱、openid），明文不落库 | 原有 |
| `recipient_secret_ref` | bigint | 收件地址明文在密钥库中的引用，需要重发到同一地址时取用 | 并入自 ivc_invoice_delivery |
| `template_no` | varchar(64) | 平台通知模板号；自由文本发送为空 | 原有 |
| `template_code` | varchar(64) | 服务商侧模板：短信为服务商模板号，邮件为主题 | 原有 |
| `content` | text | 实际提交给服务商的发送正文；历史或不可得时为空 | 原有 |
| `status` | varchar(16) | 发送状态：PENDING 待发 / SENT 已发出 / DELIVERED 已送达 / OPENED 已打开 / FAILED 失败 / SKIPPED 因开关关闭或额度不足跳过 | 原有 |
| `error` | varchar(512) | 失败时服务商返回的错误码与消息 | 原有 |
| `provider_msg_id` | varchar(128) | 服务商回执号（如阿里云 BizId、邮件 Message-ID），对账用 | 原有 |
| `attempts` | int | 已尝试次数 | 并入自 commerce_expiry_notice |
| `next_attempt_at` | bigint | 下次重试时刻（毫秒），不再重试为空 | 并入自 commerce_expiry_notice |
| `sent_at` | bigint | 发出时刻（毫秒） | 并入自 commerce_expiry_notice |
| `opened_at` | bigint | 收件人打开时刻（毫秒），如发票邮件中的下载链接被点开 | 并入自 ivc_invoice_delivery |
| `access_token_hash` | char(64) | 邮件内下载链接令牌的摘要，用于校验买方打开链接，不存明文 | 并入自 ivc_invoice_delivery |
| `link_expires_at` | bigint | 下载链接失效时刻（毫秒） | 并入自 ivc_invoice_delivery |
| `operator_no` | varchar(32) | 触发人；自动发送（如验证码）为空 | 原有 |
| `client_ip` | varchar(64) | 触发来源 IP，排查滥用用 | 原有 |

唯一键与索引：发送记录号唯一；通知单号 索引；渠道 + 状态 + 下次重试时刻 索引；下载链接令牌摘要唯一（有值时）。

留意：原表无 tenant_no，按平台多租户补上。发票送达的申请号、导出号等由所属通知的 biz_type/biz_no 承载，不在发送记录上重复。

### notify_push_task

批量推送任务：向一群人发一次，记人群、内容、定时时刻、预估与实发条数。只用于批量；发给一个人的通知不走它

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `task_no` | varchar(48) | 推送任务号 | 原有 |
| `name` | varchar(128) | 任务名称，运营自己识别用 | 原有 |
| `audience_type` | varchar(32) | 目标人群：ALL_APP_USER 全部 App 用户等 | 原有 |
| `channel` | varchar(16) | 下发渠道，一期仅 PUSH App 推送 | 原有 |
| `title` | varchar(128) | 推送标题 | 原有 |
| `body` | varchar(512) | 推送正文 | 原有 |
| `link` | varchar(256) | 点开后的落地页路径，如 /pages/activity/xxx | 原有 |
| `scheduled_at` | datetime | 定时下发时刻；空表示尽快发 | 原有 |
| `status` | varchar(16) | 任务状态：QUEUED 排队中 / RUNNING 发送中 / DONE 已完成 / CANCELLED 已取消 | 原有 |
| `estimated_count` | int | 创建时预估触达人数 | 原有 |
| `sent_count` | int | 实际发出条数 | 原有 |
| `finished_at` | datetime | 完成时刻 | 原有 |

唯一键与索引：任务号唯一；状态 + 定时时刻 索引。

## 2 打印

### prn_printer

打印机：门店里的一台物理打印机，云打印或本地连接、纸宽、能力、健康状态；现在也带投递状态——当前在打哪个任务、谁持有投递权、租约到何时。云打印的凭据在密钥库，这里只存引用；本地连接的代理是一台门店设备（平台基础库的 `mch_store_device`），这里只存设备号

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `entity_no` | varchar(64) | 所属经营主体号 | 原有 |
| `store_no` | varchar(64) | 所在门店号 | 原有 |
| `printer_no` | varchar(32) | 打印机编号，业务主键 | 原有 |
| `name` | varchar(64) | 打印机名称，如“后厨 80 打印机” | 原有 |
| `physical_key` | varchar(128) | 服务端规范化后的物理身份（厂商 + 序列号等），不能用连接地址代替，同一台机器只登记一次 | 原有 |
| `connection_type` | varchar(16) | 连接方式：CLOUD 云打印 / LOCAL 经门店设备本地连接 | 原有 |
