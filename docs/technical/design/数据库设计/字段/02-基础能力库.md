# 基础能力库：表字段

状态：字段草案。创建：2026-11-26。上一层：[表说明](../库/02-基础能力库.md)。
保留的表沿用现有的列；合并和新建的表的字段按并入的旧表推出，没有对着代码核过。
每张表都有的公共列（`id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`、`deleted`）不重复列出。
“来源”一栏：原有 = 原表就有的列；并入自 = 从被并入的旧表带过来；新增 = 这次设计新加的。

## 1 权限（运营端）

### sys_role

运营端角色：运营端角色

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `role_code` | varchar(32) | 角色编码，同一端内唯一 | 原有 |
| `name` | varchar(32) | 角色展示名 | 原有 |
| `end_code` | varchar(8) | 所属端：OPS 运营端 / BIZ 商家端 / MP 小程序端 | 原有 |
| `builtin` | tinyint | 是否平台预置角色：1 预置不可删 / 0 自定义 | 原有 |
| `wildcard` | tinyint | 是否通配角色（超管）：1 拥有全部权限码，判权时直接放行 / 0 按授予的功能点判 | 原有 |
| `entity_no` | varchar(64) | 自定义该角色的商家主体编号；空 = 平台角色 | 原有 |
| `sort` | int | 列表展示顺序 | 原有 |
| `tenant_no` | varchar(32) | 租户编号 | 原有 |

唯一键与索引：租户 + 端 + 主体 + 角色编码唯一。

留意：本库只装运营端角色；B 端角色在平台基础库另有一套。

### sys_role_point

角色功能点：角色有哪些功能点

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `role_code` | varchar(32) | 角色编码，指向 sys_role.role_code | 原有 |
| `point_code` | varchar(64) | 功能点编码，指向 sys_function_point.point_code；后端未实现的点也照样建关联 | 原有 |
| `end_code` | varchar(8) | 所属端：OPS / BIZ / MP | 原有 |
| `entity_no` | varchar(64) | 自定义角色所属的商家主体编号；平台角色为空 | 原有 |
| `tenant_no` | varchar(32) | 租户编号 | 原有 |

唯一键与索引：租户 + 端 + 角色 + 功能点唯一；按功能点反查哪些角色拥有它。

### sys_grant

授权：谁在什么范围拥有什么角色或权限，带有效期
（原 `sys_role_member`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `end_code` | varchar(8) | 所属端：OPS / BIZ / MP | 原有 |
| `subject_no` | varchar(64) | 被授权人编号：运营 staff_no / 商家 mch_account_no / 用户 user_no | 原有 |
| `grant_type` | varchar(16) | 授予的是什么：ROLE 角色 / POINT 单个功能点 | 新增 |
| `role_code` | varchar(32) | 授予的角色编码；grant_type=ROLE 时有值 | 原有 |
| `point_code` | varchar(64) | 直接授予的功能点编码；grant_type=POINT 时有值 | 新增 |
| `scope_no` | varchar(64) | 授权作用范围：B 端为门店编号，运营端为空表示全局 | 原有 |
| `valid_from` | datetime | 授权生效时间；空 = 立即生效 | 新增 |
| `valid_to` | datetime | 授权到期时间；空 = 长期有效 | 新增 |
| `status` | varchar(16) | 授权状态：ACTIVE 有效 / REVOKED 已撤销 | 新增 |
| `granted_by` | varchar(64) | 授权操作人编号 | 原有 |
| `granted_at` | bigint | 授权时间（毫秒时间戳） | 原有 |
| `revoked_by` | varchar(64) | 撤销操作人编号 | 新增 |
| `revoked_at` | datetime | 撤销时间 | 新增 |
| `tenant_no` | varchar(32) | 租户编号 | 原有 |

唯一键与索引：租户 + 端 + 被授权人 + 授予对象（角色或功能点）+ 作用范围唯一，一人可多行即多角色；按角色反查成员。

留意：原表 sys_role_member 只表达人员 × 角色；desc 要求能直接授予权限并带有效期，故加 grant_type、point_code 与有效期。

## 2 开放应用

## 3 统一事件

| 字段 | 类型 | 说明 | 来源 |

| `source_system` | varchar(32) | 发出或接收事件的系统：ORDER / PAY / INVENTORY / POINTS / LOGISTICS / CIM 等 | 原有 |

| `store_no` | varchar(64) | 事件所属门店编号 | 并入自 cim_inbound_event |

| `schema_version` | int | 事件载荷结构版本 | 原有 |
| `payload` | text | 事件载荷 JSON，自带消费方所需全部字段，不含码和凭据 | 原有 |
| `payload_hash` | varchar(64) | 载荷摘要，同号异载荷时拒收 | 原有 |

| `received_at` | datetime | 收到外部事件的时间（INBOUND 时有值） | 并入自 lgs_push_event |
| `status` | varchar(16) | 发出状态：PENDING 待发 / SENT 已发 / FAILED 失败待重试 / DEAD 放弃 | 原有 |
| `retry_count` | int | 已重试次数 | 原有 |
| `next_retry_at` | datetime | 下次重试时间 | 原有 |
| `last_error` | varchar(512) | 最近一次失败原因 | 原有 |
| `sent_at` | datetime | 发出成功时间 | 原有 |

唯一键与索引：事件号唯一；来源系统 + 外部事件号唯一（收入的外部回调去重）；按状态 + 下次重试时间扫描待发事件；事件流键 + 流内序号唯一。

留意：各库原有的 outbox/inbox（支付、积分、库存、商务、渠道、物流回调、积分来源事实）都收进这一张，用 direction 区分收发；每个接收方的进度在 sys_outbox_delivery，消费去重在 sys_event_consumed。cim_operation 是对外操作工单而不是事件，其授权回调状态等若仍需要，应归渠道对接库自己的表，不在此处承载。
