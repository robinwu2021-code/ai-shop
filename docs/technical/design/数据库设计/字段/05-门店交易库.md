# 门店交易库：表字段

状态：字段草案。创建：2026-11-26。上一层：[表说明](../库/05-门店交易库.md)。
保留的表沿用现有的列；合并和新建的表的字段按并入的旧表推出，没有对着代码核过。
每张表都有的公共列（`id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`、`deleted`）不重复列出。
“来源”一栏：原有 = 原表就有的列；并入自 = 从被并入的旧表带过来；新增 = 这次设计新加的。

## 1 分类

### prd_category

平台类目：全平台统一的商品分类树，决定规格模板、资质要求、可用支付方式

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `category_no` | varchar(64) | 类目编号，全平台唯一 | 原有 |
| `parent_no` | varchar(64) | 上级类目编号；一级类目为空 | 原有 |
| `level` | int | 类目层级：1 一级 / 2 二级 / 3 三级 | 原有 |
| `name` | varchar(64) | 类目中文名 | 原有 |
| `name_en` | varchar(64) | 类目英文名；缺失时按回落规则展示中文名 | 原有 |
| `icon` | varchar(512) | 类目图标地址 | 原有 |
| `sort` | int | 同级类目内的展示顺序，小的在前 | 原有 |
| `template` | varchar(16) | 录入模板，决定商家建品时看到哪些字段：STANDARD 标准品 / FRESH 生鲜 / SERVICE 服务 / VIRTUAL 虚拟 / VOUCHER 券 | 原有 |
| `attr_template` | text | 该类目的商品属性模板（JSON） | 原有 |
| `qualification_required` | varchar(512) | 经营该类目需要的资质清单（JSON） | 原有 |
| `required_code` | varchar(32) | 经营该类目所需的经营类目编码，对应主体的经营类目；空表示无门槛 | 原有 |
| `disallowed_pay_modes` | varchar(64) | 该类目禁止的支付方式（JSON 数组，取值 ONLINE 线上 / OFFLINE 线下）；空表示全部放行 | 并入自 prd_category_pay_mode |
| `status` | varchar(16) | 类目状态：ACTIVE 启用 / DISABLED 停用 | 原有 |

唯一键与索引：类目编号唯一；上级类目编号 + 排序 建索引，用于取子类目。

留意：原类目 × 支付方式表是「没有行即放行，有 allowed=0 才禁止」，取值只有两种，故压成一个禁止清单列，语义不变。

### prd_store_category

门店展示分类：门店自己定义的分组、名称和排序
（原 `fnb_menu_category`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `tenant_no` | varchar(32) | 租户号 | 原有 |
| `entity_no` | varchar(32) | 所属经营主体 | 原有 |

| `category_no` | varchar(32) | 门店展示分类编号 | 原有 |
| `catalog_no` | varchar(32) | 所属门店目录（原 menu_no）；空表示门店通用分类，不挂具体目录 | 原有 |
| `platform_category_no` | varchar(64) | 对应的平台类目编号；纯自定义分组可为空 | 并入自 mch_store_category |
| `name` | varchar(64) | 分类展示名；挂平台类目且为空时用平台类目名 | 原有 |
| `sort_no` | int | 在门店页或菜单里的顺序，商家拖动修改 | 原有 |

唯一键与索引：分类编号唯一；门店 + 目录 + 排序 建索引。

留意：零售货架、餐饮菜单、美业项目分类共用此表。原「主体 × 平台类目 记不记库存」改挂在门店分类上，粒度从主体变为门店分类，迁移时需按平台类目展开到各店。
