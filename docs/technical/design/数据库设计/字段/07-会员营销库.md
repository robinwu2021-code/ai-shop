# 会员营销库：表字段

状态：字段草案。创建：2026-11-26。上一层：[表说明](../库/07-会员营销库.md)。
储值账本字段已对照现行迁移与入账代码。门店经营指标、活动范围、活动额度预留和权益等级的本次落地字段见 V704 至 V707；共用模型中卡券与储值专用的扩展字段仍为目标设计。
每张表都有的公共列（`id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`、`deleted`）不重复列出。
“来源”一栏：原有 = 原表就有的列；并入自 = 从被并入的旧表带过来；新增 = 这次设计新加的。

## 1 会员

### mbr_member

会员：顾客在某个商家或范围下的会员身份，含当前等级

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `member_no` | varchar(64) | 会员号，会员关系的业务唯一编号 | 原有 |
| `entity_no` | varchar(64) | 所属商家主体号；同一人在同一主体下各门店算一个会员 | 原有 |
| `scope_type` | varchar(16) | 运营身份范围：ENTITY 主体、BRAND 品牌、STORE 独立门店 | 并入自 mbr_scope_member |
| `scope_no` | varchar(64) | 范围对象编号：主体号、品牌号或门店号，与 scope_type 对应 | 并入自 mbr_scope_member |
| `person_no` | varchar(64) | 平台人档号（平台基础库）；不存 user_no 与手机号，需要时从人档取 | 原有 |
| `status` | varchar(16) | 会员状态：LEAD 线索（不可触达、不进受众）/ ACTIVE 正常 / BLOCKED 被商家拉黑 | 原有 |
| `source` | varchar(16) | 首次来源：ORDER 下单 / SHARE 分享 / SCAN 扫码 / MANUAL 手工录入 / FAVORITE 收藏 / SEARCH 搜索；逐次明细在 mbr_member_source | 原有 |
| `first_store_no` | varchar(64) | 首次进来的门店号，冗余自来源明细，列表不回表 | 原有 |
| `first_order_at` | bigint | 首单时间（毫秒） | 原有 |
| `last_order_at` | bigint | 最近一单时间（毫秒） | 原有 |
| `order_count` | int | 累计下单数 | 原有 |
| `total_spent_minor` | bigint | 累计消费金额（最小货币单位） | 原有 |
| `d90_order_count` | int | 近 90 天单数，每日重算，分层与筛选直接读 | 原有 |
| `d90_spent_minor` | bigint | 近 90 天消费金额（最小货币单位），每日重算 | 原有 |
| `level` | varchar(16) | 该身份的经营分层：NEW 新客、REGULAR 常客、LOYAL 忠诚、SLEEPING 沉睡 | 原有 |
| `grade_code` | varchar(32) | 会员等级编码，按 mbr_level_rule 计算得出的当前等级 | 新增 |
| `level_rule_version_no` | varchar(64) | 定出当前等级所用的等级规则版本号 | 新增 |

| `last_recharge_at` | datetime(3) | 最近一次实际储值时间，B 端储值会员列表默认按它排序 | 并入自 sv_user_store_index |
| `last_consume_at` | datetime(3) | 最近一次储值或卡券实际核销时间 | 并入自 sv_user_store_index |
| `reach_opt_out` | tinyint | 买家是否关掉了这家店的消息；商家看得到状态，看不到原因 | 原有 |
| `remark` | varchar(255) | 商家备注，如「三单元张阿姨」 | 原有 |
| `shared_profile` | json | 品牌范围下允许各门店共享的会员资料 | 并入自 mbr_scope_member |
| `joined_at` | bigint | 入会时间（毫秒） | 原有 |
| `claimed_at` | bigint | 线索被本人认领的时间（毫秒） | 原有 |
| `tenant_no` | varchar(32) | 租户号 | 原有 |

唯一键与索引：会员号唯一；租户 + 范围类型 + 范围编号 + 人档号唯一（同一人在同一范围下只有一个会员身份）；主体 + 分层、主体 + 最近下单时间索引，用于分层筛选与列表。

留意：范围身份按租户、范围和人档唯一。多店主体的门店消费与门店分层在 mbr_store_profile，按原会员号可追溯；按来源重算沿用原主体和门店口径。
