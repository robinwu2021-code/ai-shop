# 数据库设计

状态：设计稿（纸面目标）。创建：2026-11-26。
这是 ai-shop 库表清理、抽象、分库之后的目标设计：**14 个库、412 张表**。
本版按逐表评审更新库边界和目标清单。会员、活动和卡券的 v2 实现与目标表差异见[三类业务对齐](库/07-会员营销库.md#会员活动和卡券对齐)。门店消费统计随门店档案保存，会员身份按经营范围计数。会员营销库的说明、字段及机器索引按本次范围合并更新；其他库的下层资料仍以原设计为基线。

首批商家券按原核销号关联取消和退款的逐笔冲回，占用释放和历史券处理见[会员营销库](库/07-会员营销库.md#首批商家自发券的实施范围)。

## 贯穿各库的约定

- **一个业务对象只有一个归属库。** 其他库只存它的编号和必要的快照。
- **物理分库之间通过业务编号协作。** 跨库协作走接口或公共事件，要有重试、对账与补偿。
- **业务写入保留原子约束。** 应用识别重试，业务库保证同一业务效果只发生一次。事件投递与发号可复用公共能力，凭证冻结、事件首写及消费去重保留所需的本域事务边界。
- **字典、事件、轻量审批、审计各用一个统一的模型。** 都在基础能力库。
- **重的审核与工单不在这些库里。** 由独立的审核与工单服务承担，业务表只存单号。
- **一对多的明细保留为表。** 不压成主表里的一段内容。
- **规则与定义类的表每行一版。** 带版本号、状态、生效起止；已发生的业务记下用的是哪一版。
- **每张表都有的公共列不在字段文档里重复列。** `id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`（乐观锁）、`deleted`。
- **金额用最小货币单位的整数加币种。**
