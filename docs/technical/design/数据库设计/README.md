# 数据库设计

状态：设计稿（纸面目标）。创建：2026-11-26。
这是 ai-shop 库表清理、抽象、分库之后的目标设计：**14 个库、376 张表**。
库里的表和代码都还没有动；表的合并与归属按列结构和业务含义定，没有对着代码验证；字段是草案。

## 贯穿各库的约定

- **一个业务对象只有一个归属库。** 其他库只存它的编号和必要的快照。
- **库之间不联表、不共事务。** 跨库协作走接口或公共事件，要有重试、对账与补偿。
- **库里只存业务数据。** 事件收发、发号是公共能力，在基础能力库；防重由应用层做，不建表。
- **字典、事件、轻量审批、审计各用一个统一的模型。** 都在基础能力库。
- **重的审核与工单不在这些库里。** 由独立的审核与工单服务承担，业务表只存单号。
- **一对多的明细保留为表。** 不压成主表里的一段内容。
- **规则与定义类的表每行一版。** 带版本号、状态、生效起止；已发生的业务记下用的是哪一版。
- **每张表都有的公共列不在字段文档里重复列。** `id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`version`（乐观锁）、`deleted`。
- **金额用最小货币单位的整数加币种。**
