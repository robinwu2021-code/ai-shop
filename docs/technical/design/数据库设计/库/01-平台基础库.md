# 平台基础库 `n_platform`：表说明

状态：设计稿。创建：2026-11-26。上一层：[清单](../01-清单.md)。下一层：[表字段](../字段/01-平台基础库.md)。

## 这个库是什么

**谁在平台上、能登录、能做什么。**

| 项 | 说明 |
|---|---|
| 库名 | `n_platform` |
| 表前缀 | `mch_` 商户：主体、门店、品牌、人员、B 端账号与授权、门店设置；`usr_` C 端用户与访客；`ops_` 运营端账号；`auth_` 跨端的一次性票据；`agr_` 协议与同意 |
| 管什么 | 商户集团、主体、资质；门店、门店设备（唯一的设备登记）；门店的履约方式与服务范围；品牌及其门店；B 端账号与收银员 PIN；业务人员及其任职与岗位；B 端的角色、权限码与授权；门店开通的端；C 端用户与运营端账号；三端各自的会话与登录日志、顾客临时会话、一次性票据；协议版本与同意记录；门店级的设置；受信任装置；员工打卡；总部对门店的下发及各店的套用状态 |
| 不管什么 | 通知、打印、发票、风控（平台服务库）；运营端的角色与授权、密钥、审计（基础能力库）；资源与预约占用（门店交易库）；收款与结算（支付相关三个库）；会员身份（会员营销库）；入驻、开店、变更的申请、审核与通过后的执行编排（独立的审核与工单服务）；行业、主体类型等字典（基础能力库的通用字典）；可以卖哪些端（平台商城库） |
| 谁在用 | 三端都用，每一次请求都要读它验令牌；其他库只存主体号、门店号、用户号来引用这里的对象。 |
| 和其他库的关系 | 账号、B 端授权、门店在同一个库：判“这个人能不能管这家店”不跨库，入驻时建主体、门店、老板账号和授权是同一个事务。原来的账号认证库已并入本库（用户 2026-11-26 确认）。 |
| 现状 | 新建，从 shop 库拆出。 |
