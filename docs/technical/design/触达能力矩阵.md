## 2.5 模板体系：两类模板，别混为一谈

「模板」在这套系统里指两种性质完全不同的东西，混谈会导致把通道的硬约束
当成我们的功能没做，或者反过来把本该可配的东西写死在代码里。

| | **通道方模板**（短信 · 微信订阅） | **平台业务模板**（邮件 · 推送 · 站内信） |
|---|---|---|
| 谁定义 | 通道方（阿里云 / 微信 mp 后台） | **我们自己** |
| 谁审核 | 通道方**报备制**，审核通过才能用 | 无人审核 |
| 正文能否改 | ❌ 只能填参数 | ✅ 我们说了算 |
| 改一次的成本 | 重新报备（天级） | 改数据（秒级）—— **前提是它在数据里** |
| 平台侧存什么 | 模板号 + 正文副本（**仅供展示与预览**） | **正文本身就是权威** |
| 不一致的后果 | 预览与实际不符（人工保持一致） | 无（只有一份） |

### 2.5.1 邮件业务模板：✅ 已模板化（2026-08-14）

| 业务 | 模板 | 状态 |
|---|---|---|
| 运营账号开通（含初始密码） | `TPL_MAIL_OPS_INIT_PWD` | ✅ V142 种子 + 走 `MailTemplatePort` |
| 运营密码重置（含重置码） | `TPL_MAIL_OPS_RESET_PWD` | ✅ 同上 |
| 通道联通测试 | `TPL_MAIL_TEST` | ✅ V141 种子 |

改造前三封的正文都是 Java 字符串拼接（改一句话要发版）。现在正文在
`msg_template` 里，**运营端各通道页可见**，邮件的那份改了下一封就变。

**行为上的三条约定**（都有测试守着）：

1. **模板缺失或被停用 → 回落内置文案，照常发**。账号类邮件发不出去的后果是
   「新同事永远登不进来」，比「文案没跟上最新一版」严重得多 ——
   页面上也照这个口径写明，否则运营会以为停用开关能关掉它们。
2. **占位没取到值 → 整封回落内置文案**，不发一封写着 `{password}` 的邮件：
   收件人此刻正等着这个密码登录，一封读不懂的邮件比一封旧文案的邮件糟得多。
3. **正文仍不进日志与发送记录**（`NotifyLogWriter` 本就只记掩码收件人与模板号）——
   模板化没有破坏这条。

⚠️ 两处**含密**：初始密码与重置码在正文里。模板化时这两个占位必须
在发送记录与日志里保持不可见（现有 `NotifyLogWriter` 已经不记正文，
模板化不能把这条破坏掉）。

### 2.5.2 目标形态

沿用已经在跑的那套（`msg_template` + V141 六条种子 + 抽屉展示预览），
把邮件的三封纳入，并补齐真实业务邮件：

| templateNo | 用途 | 占位 | 状态 |
|---|---|---|---|
| `TPL_MAIL_TEST` | 通道联通测试 | `subject` `body` | ✅ |
| `TPL_MAIL_OPS_INIT_PWD` | 运营账号开通 | `realName` `username` `password` | ✅ |
| `TPL_MAIL_OPS_RESET_PWD` | 运营密码重置 | `realName` `token` `ttlMinutes` | ✅ |

**候选（业务上该有、目前一封都没发）**：入驻审核通过/驳回、结算单生成、
提现审批结果、商家违规处置通知。这几封要不要发是产品决策，不是技术缺口 ——
列在这里是为了让「邮件只有三封」这件事被看见。

### 2.5.3 模板化要连带解决的三件事

1. **多语言**：⬜ **未做，是本轮唯一没解决的一条**（G2c）。正文仍写死中文，
   而平台是三语 —— `msg_template` 没有语言维度，要加 `lang` 列还是按 `templateNo`
   分语言需要先拍板。本轮**刻意保持中文一种**：那与改造前的行为逐字一致，
   不会因为模板化而让谁收到不同的东西。
2. **占位缺失的行为**：✅ 已解决 —— 整封回落内置文案（§2.5.1 第 2 条）。
3. **纯文本 vs HTML**：✅ 维持纯文本。`MailPort.send` 仍只收一个 body。
   纯文本进垃圾箱的概率更低，而这几封都是要人立刻看到的。

## 6. 三条刻意的「不做」（免得反复讨论）

1. **站内信不进 `sys_notify_log`** —— 它自己就是一张可查的表（`msg_message`，三端在读），
   抄一份等于同一件事存两处，两处必然对不上。发送记录页有一句说明指向各端收件箱。
2. **发送记录不给删除、不做保留期清理** —— 那张表是只追加的事实流水，
   「能删的审计等于没有审计」。表会长，但它是运维流水，量级远小于订单。
3. **不做记录导出 CSV** —— 会把掩码收件人与失败原文整表带出运营的电脑，
   而这张表存在的前提就是明文不落地。要对账去通道后台，那边有明文也有权限。

#### 7.2.1 G5 立项时要保留的三条规则

**壳已经摘掉了**（2026-08-14）：`ops-web` 此前在调 `/ops/push-tasks` 三条端点，
而后端一条都没有 —— mock 下一切正常，**接真后端时站内信页当场 404**。
一个报错的页面比没有这个页面更糟：它让人以为功能坏了，而不是没做。

摘除时把 mock 里仅有的三条业务规则搬到这里。它们此前**只存在于 mock**，
是当时想清楚过的产品意图，不该跟着空壳一起消失：

1. **预估触达为 0 不让发**。选了个空人群等于白发一次，而且那条发送记录
   会污染后面的效果分析 —— 分母里多一次「发了但没人收到」。
2. **关联模板已停用不让发**。停用即刻生效是模板的既有语义；
   允许绕过它发送，等于「停用」这个开关对群发无效。
3. **已发送的任务不可撤销**，已发送也不可重复发。撤销只对未发出的有意义 ——
   对已经进了别人手机的推送，「撤销」这个词本身就是骗人的。

## 8. 上线检查单（真凭据到位后按此走）

```
□ 短信   SHOP_SMS_STUB=false  + ALI_SMS_AK/SK/SIGN/TPL_OTP
□ 邮件   SHOP_MAIL_STUB=false + MAIL_USERNAME/PASSWORD/FROM
□ 微信   SHOP_WX_STUB=false   + WX_APPID/SECRET + 两个模板号
         ⚠️ 模板号必须与端上 VITE_WX_TPL_* 同值，否则额度对不上、一条发不出
□ 推送   SHOP_PUSH_STUB=false + GETUI_APP_ID/APP_KEY/MASTER_SECRET
         ⚠️ 免费档：在线不限量，厂商离线有日配额
□ 每条通道在运营端「模拟发送」走一遍，确认「最近发送」里是 SENT
□ 通道总览四行凭据全绿
```

**缺配置时通道启动即失败，不静默退回桩** —— 静默退回的表现是「已发送」日志照常出现，
而用户一条都收不到，要等投诉才发现。
