## 屏 2 · 核心价值：更容易 / 更赚钱

> **开店更容易，
> 经营更赚钱。**

社区门店上线的两个真实障碍：一是开不起来 —— 资质、系统、人力都要先投入；
二是开起来不赚钱 —— 流量要买、佣金要抽、复购留不住。虹选对这两件事分别给出答案。

| 更容易 · 把上线的前置成本降到零 | |
|---|---|
| 零门槛开店 | 个人主体免营业执照，无年费、无押金、无签约保证金。 |
| 三步完成入驻 | 提交申请、平台审核、上架经营。驳回会写明缺什么，补齐后在原页重新提交。 |
| 一部手机完成日常 | 接单、发货、核销、售后、对账在同一个工作台上，六项待办即入口。 |
| 开箱即用的分工 | 六个预置角色覆盖常见岗位，店员用自己的账号登录，不必共用老板密码。 |

| 更赚钱 · 把复购的钱留在你自己的店里 | |
|---|---|
| 老客复购零佣金 | 扫店铺码进店的订单记为自带客流，平台佣金 **0%**（← import）。 |
| 新客获取成本明确 | 平台首页与附近发现产生的订单按 **2%**（← import）计费，费率按下单时快照。 |
| 四类营销工具提升复购 | 店铺券、满减、限时特价、买赠，叠加规则由下单算价统一计算。 |
| 承接自提点是额外收入 | 代邻居收货、通知、核销，按件计 **¥0.30**（← import）。 |

> **这一屏是整站的主线**，写文案时的检验标准：一条价值主张如果既不落在「更容易」
> 也不落在「更赚钱」上，它多半是在描述功能而不是价值 —— 放到屏 4 去。
> 「高效」「赋能」「一站式」这类词一个不用：商家分不清它们和竞品的同款说法有什么区别。

## 屏 3 · 三种上线方式 `#paths`

> **三种上线方式，
> 按门店规模选择。**

### 卡 A · 入驻虹选

在虹选的小程序与 App 内开设门店，共享平台的社区客流。

- 平台自营业务运行在同一套系统上，不是一套只提供给商家的旁支
- 下单、拆单、履约、售后、结算全链路已就绪，无需自行搭建
- 老客扫店铺码进店的订单记为自带客流，平台不收佣金

`查看入驻流程 →` `#how-to-open`

### 卡 B · 多门店

一个账号统一管理多家门店，账目与库存彼此隔离。

- 每家门店独立收款、独立库存、独立订单
- 店员按门店授权，仅可见其所属门店的数据
- 跨店总览与对比：各店经营指标并排呈现

`查看权限模型 →` `#stores`

### 卡 C · 自有小程序 ｜ 角标：按年开通

使用你自己的品牌与小程序入口，后台仍是同一套系统。

- 名称、图标、入口与顾客名单归你所有
- 商品、订单、结算与虹选后台同源，无需双份录入
- 自营类目上架，**无需 ICP 经营许可证（EDI）**

`查看包含范围 →` `/mini-program/`

> 依据：卡 A/B 全部对应已实现能力（B-1、B-14）；**卡 C 是要加购的商品，不是现成功能**，
> 所以它用「开通」而不是「支持」，且带角标区分。类目门槛见《小程序上线指南》§一。

## 屏 4 · 开店三步 `#how-to-open`

> **提交申请 → 平台审核 → 上架经营。
> 没有第四步。**

**01 提交申请**
手机号登录即完成注册。先选行业 —— 行业决定可选的经营主体：个人主体免营业执照，个体工商户与企业需上传执照。

**02 平台审核**
由平台人工审核。**驳回会写明缺失项**，补齐后在原页重新提交，无需重新填写全部资料。

**03 上架经营**
商品通过审核后处于下架状态，**何时开售由你决定** —— 平台不代为上架。

---

**需要预先知道：开店与收款是两段流程。**

门店审核通过即可上架与接单；**收款需另行提交进件申请**。进件完成前，工作台会持续列出尚缺的事项，
不会让你误以为已经就绪。

> 依据：B-1.3 / B-1.8 行业驱动主体 · B-1.4 / B-1.5 驳回带原因且留在原页 ·
> C6 验收点「过审后是 OFF_SALE 不是自动上架」· B1 验收点「能开店 ≠ 能收钱」，`missing` 逐条列缺什么
> **末段是有意写上去的**：系统里这两段状态本来就分得很清楚，说出来挡掉的是最贵的一类投诉。

## 屏 6 · 多门店与员工 `#stores`（墨底屏）

> **多门店的难点不在开店，
> 在于账目与权限的隔离。**

- **账目按门店隔离** —— 门店级收款绑定，各店款项不并入同一账户
- **数据按门店隔离** —— 角色绑定在「人 × 门店」上：同一个人可在 A 店任店长、在 B 店任店员
- **六个预置角色**：老板 / 店长 / 店员 / 理货员 / 配送员 / 客服，并支持复制修改为自定义角色
- **结算权限仅归老板** —— 店长可上架、调价、处理售后，但不可查看结算与门店收款配置
- **授权变更留痕** —— 谁在何时修改了谁的权限，均可追溯
- **跨店总览与对比** —— 各店当日单量、销售额、待办并排呈现，并可按销售额、订单数、复购率、评分、缺货数对比

门店额度按档位给：**免费版 1 家、专业版 3 家、旗舰版 10 家**。第一家永远免费。

## 屏 7 · 交易费率 `#pricing`

> **先说清怎么算，
> 再看算出多少。**

下表为每笔交易的计费方式，与所选订阅档位无关 —— 三档适用同一套费率。

| | |
|---|---|
| **自带客流佣金** | **0%** ← import · 老客扫描店铺码进店产生的订单，平台不收佣金 |
| **平台客流佣金** | **2%** ← import · 顾客经由虹选首页与附近发现进店产生的订单 |
| **自提点履约服务费** | **¥0.30 / 件** ← import · 由供货方支付、承接自提点的一方收取 |
| **结算周期** | **7 天** ← import · 按自然周生成结算单 |

**应结 = 毛收入 − 退款 − 佣金 − 履约服务费**

费率**以订单生成时的快照为准**，后续调整不影响历史订单。

> 依据：[交易规则常量表](../../requirements/需求矩阵-三端.md#七之二交易规则常量唯一事实源)（由 `npm run gen:rules` 从代码生成）·
> 结算公式与实测见 B-12 · 「快照为准」出自 B-12.4b
>
> ⚠️ **这一屏不许出现**：到账时间、提现、T+N。一期只记账、线下结算（B-12.5），支付本身还是桩。

## 屏 10 · 顾客从哪来 `#customers`

> **服务范围决定曝光范围，
> 由你自己划定。**

社区过滤是邻里电商的第一约束，而非排序偏好：顾客只会看到能够服务到自己的门店。
你申请覆盖哪些社区，商品就卖到哪些社区。

| | |
|---|---|
| **01 同小区** | 顾客下楼即可取货，或由你自行配送，通常十余分钟送达 |
| **02 步行圈** | 覆盖周边街区，支持到店自提与当日送达 |
| **03 同城** | 超出步行范围的订单走同城配送，商品页明确标注所属档位 |

顾客侧的路径是「浏览 → 下单 → 就近取货」：不涉及跨仓调拨，也没有「已揽收」之后的长时间静默 ——
由此减少的客诉，原本都要由你承接。一笔订单包含多家门店的商品时自动拆单，各自履约，你只处理自己那部分。

顾客入口 → `/download/`

## 屏 11 · 常见问题（同时输出 `FAQPage` 结构化数据）

**开店需要营业执照吗？**
个人主体不需要，收款走微信零钱。个体工商户与企业需上传营业执照。可选的主体类型由你所选的行业决定，申请表单中会直接标明。

**需要缴纳年费或押金吗？**
不需要。开店不收取任何费用，平台按成交计费，其中自带客流部分为 0%（← import）。软件本身分三档订阅，免费版长期免费。

**从申请到可以经营需要多久？**
申请表单通常十余分钟即可填写完毕，审核由平台人工处理。审核通过后即可上架。**收款需另行提交进件申请**，与开店是两段独立流程。

**平台佣金如何计费？**
老客扫描店铺码进店产生的订单为 0%；经由虹选首页与附近发现进店的订单为 2%（← import）。费率以订单生成时的快照为准，后续调整不追溯历史订单。

**我有多家门店，如何管理？**
一个账号即可统一管理。门店额度按档位提供：免费版 1 家、专业版 3 家、旗舰版 10 家，第一家门店永久免费。各门店独立收款、独立库存，店员按门店授权。

**订阅到期不续费，门店会被关闭吗？**
不会。到期后先进入 7 天宽限期，能力全部保留；宽限期结束后为降级而非关店 —— 超出免费额度的门店转为只读，不再接收新订单，但历史订单可查、未完成的订单照常核销。补缴后配置原样恢复。付费档位可先免费试用 14 天。

**店员能看到经营账目吗？**
不能。结算与门店收款配置仅老板可访问；店长可上架、调价、处理售后，但不可查看结算。权限变更均有审计记录。

**不销售商品，只承接社区自提点可以吗？**
可以。代邻居收货、通知与核销，按件计服务费 ¥0.30（← import）。承接方可见的字段裁剪至履约必需 —— 取货码、品名、数量与昵称，不含金额与完整手机号。

**可以使用自己品牌的小程序吗？**
可以，按年加购。小程序名称、图标、入口与顾客名单归你所有，商品与订单数据与虹选后台同源。

## 段 4 · 试用与到期（墨底）

> **到期不是关店，
> 是降级。**

先免费试用 14 天（一个主体一次，到期不自动扣费）。之后就算你不续，店照常开、单照常接 ——
收回去的只是超出免费额度的那部分能力。

| | |
|---|---|
| 升档立即生效 | 他现在就要开第四家店，不该等到下个周期。 |
| 降档 / 退订到期时生效 | 已付的周期不退，但也不会立刻收走你买过的东西。 |
| 到期先进 7 天宽限期，能力全保留 | 扣款失败、老板出差、忘了续 —— 这些都与经营无关，不该当天就影响生意。 |
| 宽限期结束是降级，不是关店 | 超出额度的门店转为只读：不接新单，但历史订单可查、**未完成的单照常核销**。 |
| 哪几家店变只读，规则写死 | 保默认店，其余按建店时间倒序。不让系统猜，也不在那一刻逼你做选择。 |
| 补缴后原样恢复 | 门店与授权配置全部保留。数据也不删 —— 降级改的是「能看多久」，不是「存不存」。 |

降级前会提醒三次：到期前 7 天、前 1 天，以及降级当天 —— 并且写明是哪几家店转成了只读。

> 依据：方案 §4.4.3 / §4.4.5 · 「未完成的单照常核销」是这套设计里最重要的一句：
> 欠费当天还有几十个待取货订单，冻住它们受损的是买家和取货点，而他们与这笔欠费无关。

## 段 5 · 加购：自有小程序

与档位**正交** —— 你用哪一档都可以加，按年开通。

## 段 6 · 常见问题

**免费版有什么限制？**
一家门店、没有子账号、没有跨店总览与对比。除此之外的单店经营是全套的。

**三档的交易费率一样吗？**
一样。费率不做成档位差异 —— 按档位分费率，等于换个名字重新抽佣。

**试用要绑卡吗？14 天之后会自动扣费吗？**
不用绑卡，到期也不自动扣费。一个主体只能试用一次。试用结束如果没有订阅，超出免费额度的门店会转为只读 —— 开通前的二次确认里会把这句写明。

**换档位什么时候生效？**
升档立即生效。降档或退订在当前周期到期时生效。

**我有十几家店，档位不够用怎么办？**
联系我们。谈下来的连锁客户不走自助付费，平台可以单独授予档位并覆盖额度。

**自有小程序算在哪一档里？**
不算在档位里，它是单独按年开通的一项。

> **先开一家店，不花钱。**
> 开到第二家再谈档位 —— 那时候你已经知道这套东西值不值。
