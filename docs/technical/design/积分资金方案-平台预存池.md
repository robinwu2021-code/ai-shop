# 积分资金方案 平台预存与退款备付

状态：草稿 v3，待评审 · 更新：2026-10-14

平台先备款再发分，以独立退款备付金支撑付款后的返分。积分在发放户、用户户、门店户和接收户流转；R是待追回款，不是可兑付资金。

需求：[PRD积分模块](../../requirements/PRD-积分模块.md) · 技术与开发计划：[TDD积分域重整](../TDD-积分域重整.md) · 决策：[ADR-036](../ADR/ADR-036-积分改为平台出资预存池.md)。本稿替代同路径v2的C+R备付、全接收户回流及内存事件口径，旧实现不据此认定已经改造。

## 一 定位与选择

平台承担购物返分成本，商家签约后全额兑付；平台承担回款延迟风险。选择独立B备付、R应收分开核算，额外占用预算。临时从U垫付会在预算耗尽时卡退款，等追回才转可用会改变用户照退承诺。

本期专项仍在平台账户内，非独立银行账户；积分业务模块拥有pts账务，集成pay-domain并复用pay事务；通道转账由pay资金能力执行。实际资金/专项划拨必须有可信证据。

## 二 积分与资金结构

| 积分户 | 格 | 说明 |
|---|---|---|
| 发放户ISSUE | AVAILABLE | 对应U，有钱才可发 |
| USER | PENDING/AVAILABLE/HELD | 占用来源在订单/退款/到期准备头寸分开 |
| STORE | PENDING/AVAILABLE | 定期门店待确认/待结算 |
| RECEIVE | REFUND_RESERVED/RECIRCULATABLE | 仍可退款的分不可回流；责任解除后方可自由回流 |
| MINT发行登记 | 累计负数 | 使积分总和为0，真实备款支持才可新增发行 |

| 钱 | 说明 |
|---|---|
| U | 未分配，等于发放户折现金额 |
| C | 用户/门店积分的实际备付，等于两类户的全部积分价值 |
| D | 已兑付但未完成资金支出/抵销的应付 |
| B | 退款备付；其中被预留额度不得提取/复用 |
| R | 已垫付返分后仍应追回的钱，单独应收台账，不参与现金总额 |

```text
积分户总和（含发行登记） = 0
U = m(ISSUE)
C = m(USER所有格 + STORE所有格)
B >= 有效退款预留总额
实际专项资金 = U + C + D + B
```

每日外部对账按币种聚合全部专项和其他占用，确保实际可支配余额覆盖；不能用同一余额重复覆盖多种类。每凭证Δ(U+C+D+B)等于可信现金/专项划拨变动；R变动另核凭证及应收明细。

完整图解见[积分流转与类图图册](./积分模块-流转与类图.md)，包含备款、随单/定期、退款、返分收回、到期、调账和异常恢复。

## 三 流转与凭证

| 动作 | 积分 | 钱 / 额度 | 防住什么 |
|---|---|---|---|
| 补U | 自由接收户先回流，不足才发行到ISSUE | U增加已核验备款 | 预算超发 |
| 补B | 不发行 | B增加已核验备款 | 风险款被当发放额 |
| U转B | ISSUE→RECEIVE自由 | U−/B+，外部0 | 改钱不改分破坏守恒 |
| 发放 | ISSUE→USER.P | U→C | 无资金发分 |
| 占用 | USER.A→H | B预留上限增加，B余额不重复扣 | 已兑付退款无钱支撑 |
| 取消 | USER.H→A | 释放B预留 | 无单占用 |
| 随单兑付 | USER.H→RECEIVE预留 | C→D | 商家少收的部分漏付 |
| 定期收分/确认 | H→STORE.P；终局P→A | 不动备付 | 门店尚不具备兑付条件 |
| 定期账单确认 | STORE.A→RECEIVE预留 | C→D | 未确认账单直接付钱 |
| 明确付款成功 | 不动分 | D减实际现金/专项划拨 | 未付款先记出账 |
| 付款前退款 | STORE或RECEIVE预留→USER.A | 若在D则D→C；释放B额度 | 已退分仍补差 |
| 付款后退款，回款到 | RECEIVE预留→USER.A | 真实回款补C；释放B额度 | 返分无实款 |
| 付款后退款，回款未到 | RECEIVE预留→USER.A | B→C，消耗预留并开R | 应收冒充现金 |
| 迟到追回 | 不动用户余额 | 真实资金入B，R减少 | 追回再次补C或返分 |
| 账单抵销 | 不动分 | 成功时D−offset/B+offset/R−offset，外部0 | 抵销假记外部现金 |
| 返分实际收回 | USER.P/A（经准备H）→ISSUE | C→U | 用户负余额 |
| 现金补收到账 | 可回流自由积分/发行登记→ISSUE | 实际补收q进U | 别的退款预留被拿走 |
| 责任解除 | RECEIVE预留→自由 | 释放剩余B额度 | 补U提前消耗可退积分 |
| 到期准备/完成 | A→到期H；明确划拨后H→RECEIVE自由 | 准备不减C，划拨明确成功后C出专项 | 到期与收入划拨不同步 |

新增发行允许TOPUP及核验现金补收；两者必须带等额新备款。B补充不发行。积分尚未上线，首次初始化只按已核验真实备款建立最新账本，不导入旧测试积分。

## 四 最小金额核算

例子为价值100最小单位的积分，比例1:1，仅验证账务，不设生产参数。

1. 发放预算U100、退款备付B100，发行100分到ISSUE。发放后U0/C100/B100，USER100。
2. 核销100，USER→RECEIVE预留100，C0/D100/B100，B预留100。
3. 付商家100，D0/B100；补U100不会用预留分，因此新发行100，原预留仍在。
4. 原单退款追回失败：RECEIVE预留−100/USER+100，B0/C100、R100，用户返分有实款。
5. 实际追回100：B100/R0，不再增加USER/C。

账期抵销例：gross100、offset30、cash70。明确成功的组合凭证为D−100/B+30/外部−70，R−30；已结算价值100。失败/未知时R不提前减少。零现金抵销也须结果凭证，不能等不存在的银行回执。

## 五 退款与发行边界

prepare冻结本次退款计划/权益占用，现金结果明确后confirm，不让用户先花掉尚未完成退款的返分。cashOffset不超过本次业务现金退款，路径不能把补收送回平台时为0，不足平台承担。现金补收单独记真实结果；未到账不补U、不发行，迟到到账按证据只处理一次。

返分逐行收回，抵扣分按累计商品退款比例退；运费不进入积分比例。全额商品退补齐取整，业务退款额和净现金退款额分列，不因现金扣减让订单永远达不到全退。

订单事务不能回滚pay已提交占用。订单与pay分别持久事件；pay内结算与积分通过域内Hook，在必要处同事务提交。资金意图先提交、通道再执行、结果再确认；未知不能“失败重发”。具体准备、付款、责任解除、对账契约见TDD。

## 六 取舍与开放条件

额外B预算及积分退款预留降低可自由发放/回流的额度，换取已承诺退款可履行。新hold前预留最大退款价值，余额不足就不再承诺；旧承诺继续履行。退款责任解除事实由订单域给出，不能只看分账终局。

种类比例、返分、首笔U/B、闲置期限、账期、协议文本、生产存量见PRD待确认表。新业务开闸前必须完成退款、事件、对账及能力校验。当前是设计草稿，资金回路的数学核验不代替通道、目标数据库和生产存量验证。
