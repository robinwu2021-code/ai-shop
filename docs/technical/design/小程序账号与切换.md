## 3. 切换要同时动的三处

**少动一处都不会报错，但一定用不了。**

| # | 位置 | 不改的后果 |
|---|---|---|
| 1 | `c-app/src/manifest.json` 的 `mp-weixin.appid` | 产物被传进**另一个小程序**：appid 与密钥对得上就传，传完一切正常，只是你在这个号的版本管理里找不到它 |
| 2 | 服务器 `/opt/ai-shop/shop-app.env` 的 `WX_APPID` + `WX_SECRET` | 包能打开、能逛，**谁也登不进** —— `code2Session` 报 `40029 invalid code`，而这条错在端上只表现为「转一下圈回到登录页」 |
| 3 | 新号后台：IP 白名单 `106.55.27.246` · 服务器域名 `https://www.hxmall.top` · 用户隐私保护指引 | 白名单缺 → 上传报 `invalid ip`；域名缺 → **真机所有请求被拒**（开发者工具关掉 urlCheck 后完全看不出来） |

`release-mp.sh` 从 manifest 读 AppID 传给服务器，所以第 1 处是**唯一的真源**；
服务器端缺 `MP_APPID` 直接报错，不会默默用上一次的。

### ⚠️ 切号 = 现有微信身份全部作废

`openid` **按 AppID 隔离**。换号之后，同一个人再进来就是一个**全新账号** ——
旧账号的订单、卡券、积分他都再也看不到，且**没有自动合并**。

2026-09-03 那次切换时生产库里只有 1 个 openid，代价接近于零。
**用户涨起来之后再切，代价就是全体用户的历史。**

想避免，唯一的路是提前把两个小程序绑到同一个**微信开放平台**账号下拿 `unionid`
（登录时按 unionid 优先认人）—— 但绑定只对**新登录**生效，已有账号不会追溯合并。
线上目前一条 unionid 都没有。

### ⚠️ 开发者工具登的微信号必须是这个小程序的成员

不是成员时，工具照样能打开项目、照样打印正确的 AppID，
但 `wx.login` 发出的 code 微信**不认**，后端一律 `40029 invalid code`。
2026-09-03 排查这条花了半小时：凭证对、appid 对、code 新鲜、几秒内兑换 —— 全对，就是不给过。
**换管理员的微信重新扫码即可。**

## 4. 切换步骤

```bash
# ① 改 AppID（唯一真源）
sed -i '' 's/"appid": "wx[a-z0-9]*"/"appid": "<目标 AppID>"/' c-app/src/manifest.json

# ② 后端凭证：从备份里恢复，或按目标号重新填
#    切回旧号可直接用 /opt/ai-shop/shop-app.env.bak-appid-1788395396 里的两行
#    改完 systemctl restart ai-shop，并在 /var/log/ai-shop/app.log 里确认那行
#    「[wxauth] code2Session 已启用 appid=…」是目标 AppID

# ③ 目标号后台确认：IP 白名单 / 服务器域名 / 隐私指引

# ④ 发版
cd c-app && npm run release:mp -- <版本> "<备注>"
```

**验收不看「传成功了」，看这两条**：

- 后端日志里 `code2Session 已启用 appid=` 是目标 AppID
- 模拟器跑一遍 `node tests/e2e/mp-silent-login.mjs` —— 它会去生产库数账号，
  能区分「认出了人」和「又建了一个」

## 5. 交易类接口：现在要不要接

| 接口 | 触发条件 | 现在 |
|---|---|---|
| **发货信息录入**（小程序发货信息管理服务） | 绑定**微信支付**后强制，支付完要在时限内回传发货信息 | ⏳ 未开微信支付，**暂不触发**；支付一上线就是硬要求，且有罚则，不能上线后补 |
| 自定义交易组件 / 微信小店 | 想进搜索直达、视频号带货那类流量入口 | 可选。四个「商家自营」类目走**自有商品 + 微信支付**即可，不必为合规去接 |

⚠️ 上面两行是按当前理解写的，**接之前要照微信最新文档核一遍** ——
这类平台规则改得比代码快，本仓库尚无任何相关对接代码。
