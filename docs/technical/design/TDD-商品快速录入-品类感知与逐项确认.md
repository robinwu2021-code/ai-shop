### 我上一轮 B1 的一处错（要改）

B1 的 `gramsOf()` 把所有重量**取最大值**填进 SKU 的「标称重量」，注释写的是「寄走的是 4.5 斤的箱子，不是 140g 的果子」。

**这个推理只对了一半。** 标称重量有两个用途：生鲜按重计价、**快递运费估算**（编辑页那行「买家快递运费约 ¥14.00」就是拿它算的）。运费该按**毛重**（带箱）算，而 4.5 斤是**净重**。我把净重填了进去 —— 运费因此会**估低**，而且这是一个「看起来合理」的错，界面上没有任何提示。

你第 3 点把「净重」「毛重」分开说，正好戳到这里。改法见 §2.4：**标称重量只从毛重取；只有净重时不自动填**，在确认区提示一句。

## §2 方案

### 2.1 点击识别 → 前置确认区重新成立

上一轮 §2 放弃「先确认再填入」、改成「自动填 + 事后撤销」，**唯一的理由**是：边输边识别下，每打几个字就弹一次确认，两种交互不可能共存。

现在改成点击触发，**这个理由消失了**。所以：

```
粘贴 → 点「识别文字」→ 结果进确认区（不写表单）→ 逐项勾选 / 改落点 → 点「填入（N）」→ 写表单
```

上一轮的撤销（`mergeUndo` + 快照）**保留**，作为填入之后的第二道保险。原型 s06 当初画的就是这张确认区，那时因为自动识别被搁置了，现在回到它。

### 2.2 两阶段：先认东西，再抽属性

同一个「140g」，落点取决于它是什么：

| 商品 | 「140g」应该落到 |
|---|---|
| 苹果 | 单果重量 |
| 手机壳 | 重量 |
| 洗衣液「2kg」 | 净含量 |

所以 prompt 必须先知道品类：

| 阶段 | 何时跑 | 输入 | 输出 |
|---|---|---|---|
| **① 认品类** | **只在还没选类目时** | 文字 | 1–3 个类目候选 + 置信度 |
| **② 按品类抽** | 每次 | 文字 + **该品类的属性清单** | 实体列表，每个实体的落点只能是清单里的属性 |

属性清单由后端按 `categoryNo` 从 `prd_category_spec` 现查（维度号、名称、值类型、单位、一句含义说明），**拼进 prompt**。清单外认出来的东西进「未归类」，由人指定落点 —— 不让模型自由发明属性名。

**① 的结果不直接改类目。** 认错品类会让后面所有落点一起错，所以确认区顶上写一行「识别为：水果 › 苹果　不对？」，点开可换。已选类目时 ① 不跑，省一次调用。

### 2.3 实体：一个识别出来的东西就是一行

```
Entity {
  raw        "140g+"              原文片段（确认区要显示）
  span       [4, 9]               在原文里的位置（以后可高亮）
  value      140   unit "g"   qualifier "+"
  role       UNIT_WEIGHT          见 §2.4
  target     { kind: PARAM, dimNo: "SD_UNIT_WEIGHT", label: "单果重量" }
  confidence 0.9   source llm|rule
}
```

确认区一实体一行：**勾选框 · 字段名 · 值 · 原文片段 · 落到哪儿（可改）**。落点下拉只列本品类能落的属性。

### 2.4 重量的四个角色（AC6）

| 角色 | 原文例子 | 落到 | 说明 |
|---|---|---|---|
| **单果重** | 单果140g+、单个约 200 克 | 参数「单果重量」 | **新维度**，绑水果类目（P3 迁移） |
| **净重** | 净重 4.5 斤、净含量 500ml | 参数「净含量」`SD_NET_CONTENT` | 已有维度 |
| **毛重** | 毛重 5 斤、带箱 5 斤 | SKU「标称重量」 | **运费只认它**。不新建维度 —— 毛重随规格档变（4.5 斤装毛重 5 斤、9 斤装毛重 10 斤），它是 SKU 级的，不是商品级参数 |
| **规格档** | 4.5斤装 / 9斤装 | 规格「重量」`SD_WEIGHT` → 生成 SKU | 一句话里出现**多档**时才是规格；只有一档时它就是净重 |

**规格档 vs 净重**这一条最容易错：「净重 4.5 斤装 10 元」里的 4.5 斤，在只卖一种份量时是净重（参数），在同时卖 4.5 斤装与 9 斤装时是规格档（生成两个 SKU）。模型按「一句话里有几档」判，确认区落点可改。

### 2.5 图片与文字分开（AC5）

**卡内两档，不拆成两张卡** —— 上一轮你定过「页面骨架不要大动」，两档切换（`sh-seg`）留在原来那张「快速录入」卡里，卡序不变。

| | 文字 | 图片 |
|---|---|---|
| 输入 | 多行文字框 | 相册 / 拍照 / 压缩包 |
| 按钮 | 识别文字 | 识别图片 |
| 结果 | 各自一个确认区 | 各自一个确认区 |
| **互不触发** | 识别文字不跑图片识别 | 识别图片不往文字框里写东西 |

压缩包里带的 txt：**不再自动灌进文字框**。改成在图片档的结果里给一行「压缩包里有一段文字，导入到文字识别？」，点了才切到文字档并填进去 —— 还是不自动识别，等你点。

### 2.6 prompt 要改的（落到《识别-prompt方案.md》）

| 改什么 | 现在 | 改成 |
|---|---|---|
| 品类 | 静态，无参数 | `textPrompt(category)`：注入品类名 + 属性清单（维度号 / 名称 / 单位 / 含义） |
| 输出 | 扁平 `params[{name,value}]` | `entities[]`，每项带 `role` 与 `target.dimNo`，`dimNo` 只能取自清单 |
| 量词 | 「140g+」整串 | 拆成 value / unit / qualifier，「+」「约」「左右」留在 qualifier |
| 重量 | 只区分单果重与净重 | 四个角色（§2.4），并给出判「规格档 vs 净重」的规则 |
| 价格 | 规则为准 | **不变** —— 真金白银不交给概率 |
| 新增 | — | ① 认品类的 prompt（候选 + 置信度，不直接改类目） |

## §3 契约影响

- **`parse-text` 出参只加不删。** 后端刚发版，**旧 APK（0.5.28）还在商家手里**，它读的是 `weights` / `params`。新增 `entities[]` 与 `categoryGuess`，旧字段保留至少一个版本。删字段会让旧包的快速录入直接失效，而且不报错。
- 新迁移：`SD_UNIT_WEIGHT 单果重量`（QUANT，g，PROP），绑水果类目。**毛重不建维度**（§2.4）。
- 品类属性清单：复用现有的按类目取维度（`propDims` / `prd_category_spec`），不新开端点 —— 只是由后端拼进 prompt。

### 第 2 条对设计的影响（P3）

§2.4 那张「重量四个角色」的表是**我按水果硬写的**，第 2 条把它推翻成数据驱动：

- **标准核心参数挂在品类上**，不写死在代码或 prompt 里。水果的核心参数含单果重量、净重、毛重；
  洗衣液是净含量；手机壳是重量 —— 各品类各一套，由运营维护。
- **LLM 的任务是映射，不是发明**：prompt 注入该品类的核心参数清单（维度号 / 名称 / 单位 / 含义），
  模型只能把输入落到清单里的维度号上；清单外的进「未归类」由人指定。
- **毛重因此成为水果的一个核心参数**（商品级），而不是我原先提的「只放 SKU 标称重量、不建维度」。
  SKU 的标称重量（运费用）可以按规格档从它带出默认值，但真源是参数。
- §2.4 的表降级为「水果这一类的核心参数示例」，不再是全局规则。

P3 要补的数据：`prd_category_spec` 上标出哪些绑定是**核心参数**（区别于可选参数），
并给每个核心参数一句**给模型看的含义说明** —— 「单果重量：一颗果子的重量，不是整箱」。
没有这句说明，模型分不清单果重与净重，这正是现在的问题。

### P1 的范围（不受第 2 条影响）

P1 不碰模型、不碰参数体系，只改端上交互：点击识别 · 一实体一枚 · 卡内图文两档 ·
**停止从未分角色的重量猜标称重量**（B1 那个错）。P1 下 rule 层回来的 `weights` 没有角色，
所以正确做法是**不猜** —— 角色要等 P3 的品类核心参数来定。

## §9 P3 参数映射：实现与上线（2026-10-07，`9bb26f0d4`）

用户：「文字识别出来的数值要对应到商品参数」。

### 在生产上查到的

识别后的草稿里有两条 `{dimNo:"单果重量"}` `{dimNo:"净重"}` —— **维度号是模型自己起的中文名**，
`code` 为 null。值写进了参数，但不是这个商品的那个参数：不参与筛选、与标准的「净含量」是两个键。

逐层排查（每一步都是在生产上实测的，不是推的）：

| 层 | 结论 |
|---|---|
| 模型 | **好的**。直接打生产 `parse-text`，回来的是「单果重量 = 140g+」「净重 = 4.5斤」，分得很对 |
| 后端 | 拿模型的自由叫法**直接当维度号**转发，中间没有任何一步对到品类上 |
| 数据 | 水果类目（CAT120/121/122）**一个重量参数都没绑** —— 没有单果重量、没有毛重、连已有的净含量都没绑到水果 |
| 端上 | 没问题。`applyParamPicks` 本来就按维度号落，之前是拿到了一个不存在的维度号 |

> 起初怀疑模型没调用（日志里一行识别相关的都没有）。查下去是：**成功路径本来就不打日志**，
> 只有失败才打 WARN。开关、地址都配好了。判据最后是直接打一次接口看原始返回。

### 改了什么

- **V378**：新维度单果重量、毛重（TEXT，不入池，保留「+」「约」）；三个重量参数绑到三个水果类目
- **prompt 带清单**：有类目时把品类的标准参数清单拼进去，模型只能从清单里选维度号
- **`ParamMapping` 核对**：①模型给的维度号在清单里 ②名称相同 ③重量别名（安全网）④对不上就留作自由参数。
  ②③的目标也必须在本品类清单里；模型编的清单外维度号不信
- 清单取不到就退回自由抽取，不让识别 403

## §11 参数随值调整（2026-10-07 用户：4.5 斤可能是单果重量，也可能是净含量）

同一个值，落到哪个参数要看**说了什么、有几个、是什么商品**。判据按先后：

| 判据 | 例子 | 结果 |
|---|---|---|
| ① 原文有说明词 | 单果 140g / 净重 4.5斤 / 毛重 5斤 | 规则直接定，不给备选 |
| ② 同类有几个值，看相对大小 | 「140g 4.5斤」都没说明词 | 小的单果、大的净含量，给备选 |
| ③ 只有一个值，看品类合不合理 | 柿子 4.5斤 / 西瓜 4.5斤 | 模型判（一颗柿子不会 2250g），给备选 |

③ 不建「品类常见重量范围」的数据 —— 这正是模型擅长的常识判断；要做的是在品类参数清单里给每个参数**一句含义**
（「单果重量：一颗的重量，不是整箱」），让它知道在比什么。

**界面**（原型 s11–s13）：判不准的行在参数格下多一小行「或 单果重量」，点了就换；
同类两项**互换**（4.5斤 换到单果重量，原来占着的 140g 自动换到净含量），顶上一行可撤回。
量过：这种行 47px（普通行 30px），参数格 64px 不截断。

**契约**：参数草稿加 `alternatives`（备选维度号，同样核对必须在本品类清单里）。
