## 怎么读

「类别」由**最近的那个开标签**判定：`sh-btn`→按钮、`field__label`→字段名、
`sh-empty`→空态、`sh-hint`→说明、`placeholder`→输入框占位。
顺序是模板里的出现顺序，也就是**商家从上往下看到的顺序**。

## 一、横向先看：四处对不齐

逐屏看只看得见每一屏，横着比才看得见系统。下面四条都是比出来的。

### 1.1 「过账」有三种说法 ⚠️

| 屏 | 主按钮 | |
|---|---|---|
| 进货 | **过账入库** | 动宾 |
| 报损 | **过账出库** | 动宾 |
| 盘点 | **提交并过账** | 两个动词并列 |
| 调拨 | **确认发出** / **确认收货** | 换了个动词 |

同一件事（把草稿变成生效）在四屏上三种说法。**调拨那两个是对的** ——
它确实不是「过账」而是两段式交接；错的是盘点那个「提交并过账」，
它和进货报损做的是同一件事，却比人家多两个字。

### 1.2 空态在中文里少了一句，而英文里有 ❗已发生

三屏的「尚未添加货品」是三个独立词条（`purchase.noLines` /
`stockOut.noLines` / `transfer.noLines`）。中文三处一样，**而英文和阿语不一样**：

```
en  purchase.noLines   No items yet. Recording yesterday's delivery today?
                       Just set the date to yesterday.
en  stockOut.noLines   No items yet.
```

进货页那句「昨天的货今天记？把日期改成昨天就行」是条好提示 ——
**只有英文和阿语用户看得到**。三个词条一句话，改一处不会带上另两处。

### 1.3 「可用 {n}」两种语序 ❗已发生

```
en  stockOut.availableN   Available {n}
en  transfer.availableN   Available {n}
en  transfer.qtyHint      {n} available      ← 同一页里就不一致
```

### 1.4 进货有草稿，报损没有

进货能「存草稿」，报损只能直接过账。这可能是对的（报损通常当场就确定），
但它是**没有被写下来的决定** —— 清单里摆出来，好过下次有人当缺陷去补。

## 三、这份清单没有覆盖的

- **弹层里的文案**：`prompt()` / `confirm()` 的标题与提示是在 `.ts` 里传的，
  不在模板上，提取器扫不到。作废那两句（草稿 / 已过账分开写）就属于这一类。
- **枚举标签**：`stock.reason.*`、`stockDocs.status.*` 这些是按后端值取的，
  模板里写的是 `` `stock.reason.${r.reasonCode}` `` —— 带变量，抓不到。
  它们有自己的守卫：`i18n-backend-enum-keys`（后端枚举每个值都要有三语词条）。
- **运营端与 C 端**：进销存在那两端各有落点，不在本文范围。
