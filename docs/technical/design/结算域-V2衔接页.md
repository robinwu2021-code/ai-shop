# 结算域 · V2 衔接页

状态：页 · 2026-08-28 · 第二梯队 #8。结算域自身不动（两条链路照旧），本页只说清**它怎么消费 V2 的新事实**。

| V2 新事实 | 结算侧消费方式 |
|---|---|
| `ord_payment` 收款流水 | **MIXED 不再是黑盒**：结算单/对账可下钻到逐笔（现金/微信/储值各多少）。对账轴新增「通道日汇总 = Σ payment(SUCCESS−REVERSED)」 |
| 资产通道（TIMES_CARD/STORED_VALUE） | **不入分账**（通道表三开关全 0 已表达）；也**不是现金流** —— 日结现金口径要按通道表 `supports_payout` 类开关过滤 |
| 卖卡单 vs 耗卡单 | **收入在卖卡单**（正常进结算）；耗卡单实收 0，结算按 `asset_deduct_minor` 记「预收核销」维度，不再计收入（A1 预收款口径） |
| `asset_deduct_minor` | 子单金额分解新增项：`payAmount = goods+freight − discountP − discountM − points − asset ± weigh`。结算快照公式同步（不变量 O5） |
| 计量调整（weigh 语义扩） | 既有称重差价链路原样；TIME/DISTANCE 到位后同列同链 |
| FEE / GIFT 行 | FEE 行计收入正常结算；GIFT 行金额恒 0 自然不入 |
| 线下/先吃后付 | 终态口径不变（OFFLINE_SETTLED 一支，早有 TDD）；settle 批次号（pay_trade_no=CHECK/…）供结算侧追台账 |
| Modifier 金额 | 已并入行 amount，结算无感知；**退款倒扣含 modifier**（订单域保证） |

**一条新增校验（建议进对账 Job）**：对每张 PAID 单，
`Σ ord_payment(SUCCESS, 定向该单或按批次分摊) ≥ payAmount − asset_deduct` —— 收款与订单两本账日切互核。
**不做的**：结算不回读商品/行业表；不为行业加任何列（快照自足，既有原则）。
