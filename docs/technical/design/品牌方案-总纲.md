## 四、体系结构

一个母题、一套字形、四档字符、三级容器 —— 改任何一条，改的是整个体系。

| 维度 | 规则 |
|---|---|
| 母题 Motif | **一道扁弧** = 虹。竖半径 ÷ 横半径 = 0.65（原为正半圆），固定在字符正上方。**H 档没有弧线** |
| 字形 Letterform | H 与 X **同源自绘**：笔画等宽、直角切口，X 按 H 的参数反推。中文用思源黑体 Bold，不重绘 |
| 字符层级 | H（单字符）→ HX（双字符）→ 虹（中文单字）→ 虹选（中文双字）→ 横向字标。场合越小，层级越低 |
| 容器 Container | 透明 → 圆章 → 圆角方章（0.275 × 边长）→ 镂空。**字形与弧线参数不随容器变化** |
| 分隔符 | `·` 表并列，`｜` 表分组。域名全小写 |
| 颜色 | 主色 / 墨 / 反白 / 主色描边，四种。**不用渐变，不用灰** |

### 色

| Token | 值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--hx-red` | `#E1251B` | 主色：标识、主按钮、C/B 端图标底 | 压白字 **4.69** ✓ AA |
| `--hx-red-deep` | `#B31710` | 浅底上的红**文字**、hover | 白底 **6.89** · 面板 **6.37** ✓ |
| `--hx-red-bright` | `#FF5A4D` | 深色模式主色、母品牌弧线 | 压墨 **5.77** · 压深板岩 **4.65** ✓ |
| `--hx-ink` | `#17181A` | 墨：正文、深底、单色稿、母品牌底 | 白底 **17.77** |
| `--hx-plate-merchant` | `#242B33` | 深板岩（B 端底色备选，当前未启用） | 亮红弧 4.65 |

**三条不可互换**（防的是「看起来差不多、实际过不了无障碍」）：

1. 灰底上的红字用 `#B31710` —— 主色压面板只有 **4.33**，差 0.17 不到 AA，而面板里的红字最多（金额、状态、链接）
2. 深色模式主色用 `#FF5A4D` —— 主色压深底只有 **3.72**，主按钮会糊进背景
3. `#FF5A4D` 上的字用**墨**不用白 —— 白字压它只有 **3.08**

印刷参考：主色 C0 M91 Y92 K0。正式打样前以实际纸张为准。

## 五、几何参数

全部按「边长 S」的比例定义，与尺寸无关。共用参数：圆角 0.275、笔画宽 0.267 × 字高、弧描边 0.05、字弧间距 0.04、H 宽高比 0.80、安全区 0.25。

### 分档（`build.py` 的 `TIERS`）

| 档 | 字高 / 边长 | 弧线宽 / 边长 | 用在哪 |
|---|---|---|---|
| `H` | **0.64** | **无弧线** | 头像、favicon、通知栏（16px 要能辨） |
| `HX` | **0.30** | **0.44** | App 图标、站点主标 |
| `CN1` 虹 | 0.46 | 0.40 | 小程序中文版、包装 |
| `CN2` 虹选 | 0.38 | 甲 0.38 / 乙 0.70 × 字组宽 | 双字方章，两字紧排（字距 0.02）。**两版并存到定案为止** |
| 横向字标 | — | 1.00 × 字高 | 只压「虹」，加「好物」后**不变宽** |

**分档不是可选项。** 规范 §02 对各档本来就给了不同的值，v1.0 的实现只有一档，H 被塞进 HX 的度量里 —— 章内的 H 只有规范的四成大，还被一道比它还宽的弧压着。

### 两个母题级参数

| 参数 | 值 | 说明 |
|---|---|---|
| `arc_flat` | **0.65** | 竖半径 ÷ 横半径。1.00 = 正半圆。横向占位不变，纵向省 31%。压到 0.50 时弧内净空不足两个描边宽，小尺寸下读成一条直线，「虹」的字义就没了 |
| `bar` | **0.38** | H 横画中心高度 ÷ 字高（从顶算起）。**这不是新造型** —— hxmall 原始素材的 H 路径量出来就是 0.380（横画 10.97→22.47，中心 16.72 ÷ 字高 44），v1.0 的 `_h_at()` 把它写死在正中 0.50 才是走样 |

`bar` 对**单独 H 与 HX 里的 H 取同一个值** —— 两处 H 长得不一样就是两套字形。

**落地时 `arc_flat` 影响两处，漏一处很难查**：`arc_path()` 的 `A r r` → `A rx ry`，以及 `arc_h` 从 `r + aw/2` 改成 `ry + aw/2`（后者管纵向占位，漏了整组的垂直居中就偏）。

### 一个跑不掉的取舍

X 是两条角到角的对角线，**交点永远在正中**，提不上去。H 的横提到 0.38 之后，H 的横与 X 的交点不在同一条水平线上。规范 §02 写的是「X 按 H 的参数反推：同笔画宽、同字高、同切口角度」，**没说交点位置**，所以保持角到角不算违反规范。

## 六、各端落点

| 端 | 配色 | 主用档 | 小尺寸降级 |
|---|---|---|---|
| C 端 · 虹选好物 | 红底 + 白 HX + 白弧 | HX | 32px 以下换 H 圆章（无弧） |
| B 端 · 虹选商家 | **待定**（现状红底） | HX | 同上 |
| 运营端 · ops-web | 沿用 B 端 | HX | 同上 |
| 官网 · hxmall.top | 白底 + 红方章 | HX + 横向字标 | 同上 |
| 母品牌 · hxtech.top | 墨底 + 亮红弧 | HX + 虹选科技字标 | — |

**最小尺寸**：方章 28px · H 圆章 16px · 字标字高 20px。

制版硬约束：

- iOS 1024 **不得带 alpha 通道**，带了 App Store 直接拒（当前产物已是 RGB 无 alpha）
- 图标源**不烘焙圆角** —— iOS 与 Android 各自套遮罩，预切会二次圆角
- Android 自适应前景内容缩到安全圆 72，否则圆形遮罩削角
- 通知栏图标**去弧线、仅 H**，白色剪影（系统会重新着色，带颜色的图标会被压成白块）
- 启动页**不引 `core-splashscreen`** —— 本仓库没有该依赖，继承 `Theme.SplashScreen` 会直接编译不过；改用平台属性 `android:windowSplashScreenBackground` / `...AnimatedIcon`（API 31+ 自带），31 以下退回 `drawable/splash.xml`

## 七、交付物清单

完整缩略图与路径见 [brand/index.html](../../../brand/index.html) —— 那里有一节 **各端方案**，
逐端给出配色、用哪一档、以及可点开的实物缩略图。这里只给分组与落点：

### 按端分发 `brand/dist/<端>/`

各端**从固定路径取**，不用满仓库找。每个目录带一份 README，说明里面是什么、有哪些坑。

| 目录 | 文件 | 谁用 |
|---|---|---|
| `c-app/` | 10 | C 端 App 与 H5 |
| `b-app/` | 10 | B 端 App 与 H5 |
| `mini-program/` | 4 | 微信小程序（两端 + 中文版） |
| `ops-web/` | 4 | 运营端 |
| `site-hxmall/` | 8 | **子业务官网 hxmall.top** · 白底 + 红方章 |
| `site-hxtech/` | 12 | **母品牌官网 hxtech.top** · 墨底 + 亮红弧 |
| `print/` | 11 + `cards/` | 印刷物料、名片 |
| `trademark/` | 12 | 商标申报 |

**它是生成的镜像，不是第二处真源** —— `build_dist()` 每次重跑先清空再写，往里手放文件下次会被删掉。
小程序、印刷、母品牌官网三组只有 dist 一个家：仓库里没有对应的工程目录。

**两个官网各一套，母品牌不复用子业务的红方章** —— 否则合同抬头与商城 App 长得一样，
对公场合分不出是哪一个主体。

### 名片：模板 + 数据表

改 `brand/print/people.csv` 的一行，重跑 `python3 brand/gen-print.py`，每人四个文件
（正/反 × 正式稿 + 预览稿 + 300dpi 校对图）。

**为什么不发一个可编辑的 AI 文件**：改名的人会顺手把字号、间距、logo 位置也一起动了 ——
十个人十张名片，版式各不相同，而这种漂移没人会去比对。把「会变的」（姓名/职务/联系方式，在 CSV 里）
和「不许变的」（尺寸/出血/安全区/字号/标识位置，在生成器里）分开，版式就必然一致。

规格：90×54mm，出血 3mm（画布 96×60），安全区裁切线内 5mm。
`-preview.svg` 带裁切线与安全区，**不要交印厂**。

### 分组清单

| 组 | 数量 | 落点 |
|---|---|---|
| 标识矢量 | 12 | `brand/logo/*.svg` |
| 字标与域名 | 5 | `brand/logo/wordmark-*.svg`、`domain-*.svg` |
| App 图标位图 | 6 | `brand/ios/`、`android-shell/app/src/{consumer,merchant}/res/`、`brand/store/play-*.png` |

## 八、商标与法务

按「图形」「中文文字」「组合」三类分别申报，避免单一注册被局限：

| 申报单元 | 类型 | 用途 |
|---|---|---|
| HX 方章 | 图形 + 文字 | App / 小程序图标、官网、海外物料 |
| 虹选 | 中文文字 | 国内渠道、包装、单据、门店 |
| 虹选 · 好物 | 中文文字 | 对外全称、印刷物、开屏 |
| H 圆章 | 图形 | 头像、favicon、封口贴 |
| 虹选科技 / HX TECH | 组合 | 母品牌署名、合同、资质 |

申报稿要求：纯黑实心、白底、无渐变无阴影无描边；Slogan 与英文副行不进申报稿；文字转轮廓；提交 JPG 边长 ≥ 400px（当前产物是 PNG 带 alpha，**另存 JPG 再提交，改扩展名会被退回**）；建议至少 35 类（零售批发）与 9 类（App 软件）。

**法律署名**：官网页脚、隐私政策、用户协议、App 关于页、开发者名称、发票合同，必须出现 **深圳市虹选科技有限公司** 全称，不能用品牌名代替。联名写作 `虹选科技｜HX MALL`。

命名规则见 [视觉设计方案-全项目.md](./视觉设计方案-全项目.md) §4.3（`虹选 · 好物` / `虹选｜好物` / `虹选` / 连写 `虹选好物` 各自的适用场合）。

## 十、取舍记录

| 冲突 | 让了谁 | 为什么 |
|---|---|---|
| 「已落地的橙」vs「成体系的红」 | 让红 | 重跑一次生成器的成本，远小于长期维护两套品牌 |
| 「微信生态一致性」vs「品牌一致性」 | 让品牌 | 该理由在小程序里成立，在 App / H5 里不成立；`fresh` 皮肤保留，用户可切回 |
| 「主色红」vs「危险色红」 | 让危险色的**表现形式** | 主色不改，危险操作改用描边按钮 + 图标 + 文案；颜色不做唯一信息载体（WCAG 1.4.1） |
| 运营端主色 | 让品牌红 | `--destructive` 是 `#D92D20`，与品牌红肉眼同色；密集表格里主按钮与删除同色会出事故。品牌红退到标识位 |
| 弧的辨识度 vs 占位 | 让占位，止于 0.65 | 再扁到 0.50，弧内净空不足两个描边宽，小尺寸下读成直线 |
| H 横画对齐 X 交点 | 让对齐 | X 角到角，交点几何上就在正中；为迁就它把 H 的横放回正中，等于丢掉这套字形唯一的造型动作 |
| 「弧只压虹」vs「弧罩整词」 | 暂让前者 | 后者更好看，但弧会从字义符号退化成装饰雨棚，且要改规范文本 |

### 上游素材未入库 —— 这是个真风险

## 十一、明确不做的事

- **不改包名** `ai.neargo.shop.*` —— 改包名 = 老用户视为全新 App，数据全丢、评分清零

- **不把品牌红塞进运营端 `--primary`**（§十）
- **不手改任何生成物** —— `brand/` 下的产物、`packages/ui/src/styles/base.css`、`docs/**/*.html`
- **不用渐变做主色** —— 渐变无法算对比度、无法当按钮底、单色印刷（发票 / 合同 / 刻章）直接死掉
