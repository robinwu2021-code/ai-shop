# 官网信息架构 · 层级与每段的中心思想

配套文案：[官网文案-全量.md](官网文案-全量.md)｜逐页：[官网文案/](官网文案/README.md)

本文回答两件事：**站点分几层、每层放什么**，以及**每一页的每一段到底在说哪一件事**。
段落的中心思想只许有一句 —— 一段说两件事，读者一件都记不住。

---

## 一、结构：三层 + 两条旁路

```
第 0 层  /                        首页 —— 三个问题各给一个够用的答案
         │
第 1 层  ├─ /scenarios/           支持哪些店      ← 商家的第一个问题
         ├─ /how-it-works/        怎么开店        ← 已经动心，想知道要做什么
         ├─ /pricing/             收费与套餐      ← 在比价
         └─ /mini-program/        自有品牌小程序  ← 加购项（支线，不是主干）
         │
第 2 层  ├─ /scenarios/fresh/          生鲜果蔬
         ├─ /scenarios/convenience/    便利 · 日用 · 烘焙
         ├─ /scenarios/service/        到店与上门服务
         ├─ /scenarios/pickup-point/   社区自提点
         ├─ /scenarios/chain/          多门店与连锁
         ├─ /scenarios/own-brand/      自有品牌
         └─ /capabilities/             功能总览（挂在收费页下，不进顶栏）

旁路 A   /download/                顾客端下载 —— 受众是消费者，不在商家转化线上
旁路 B   /privacy/ /terms/         隐私政策 · 用户协议 —— 占位，随各自版本发布
```

**分层依据不是功能模块，是商家的决策顺序：**

| 层 | 商家此刻在问 | 页面给什么 |
|---|---|---|
| 0 | 这网站跟我有关系吗 | 三个问题的摘要 + 分流 |
| 1 | 支持我吗 / 要做什么 / 多少钱 | 一个问题一页，答完 |
| 2 | 我这类店具体怎么用 | 场景化的作业流 |

**第 2 层不许承担第 1 层的活。** 类型页只讲「我会怎么用」，价格、流程各回各页 ——
每个类型页末尾只放两个出口（免费开店、看价格），放第三个的代价是读者停下来做选择。

**顶栏五项**：支持哪些店 · 怎么开店 · 收费与套餐 · 自有小程序 · 顾客入口　＋　［免费开店］

「支持哪些店」排第一，它回答第一个问题。「功能总览」不进顶栏 —— 进了顶栏，宣传站就变成说明书。

## 二、每页的定位

| 页面 | 受众 | 这页回答 | 转化目标 |
|---|---|---|---|
| `/` | 所有来访商家 | 支持我吗 · 好用吗 · 多少钱 | **免费开店** |
| `/scenarios/` | 不确定自己算哪类 | 我这种店支持吗 | 点进对应类型 |
| `/scenarios/*` | 明确业态的店主 | 我会怎么用它 | **免费开店** |
| `/how-it-works/` | 已经动心 | 从现在到收第一笔钱要干什么 | 免费开店 |
| `/pricing/` | 在比价 | 一共几笔 · 不续费会怎样 | 免费开店 / 联系报价 |
| `/capabilities/` | 要逐条核对的少数人 | 到底包含哪些功能 | 回到收费页 |
| `/mini-program/` | 已有品牌 | 独有什么 · 共用什么 · 怎么开通 | 咨询开通 |
| `/download/` | 消费者 | 在哪下载 | 下载对应那一端 |

## 三、逐页 · 每段的中心思想

### 3.1 首页 `/`

**整页一句话**：三个问题各给一个够用的答案，然后把人送去对应的深页。

| 段落 | 中心思想 |
|---|---|
| 标题 | 身份不是门槛，成本也不是 |
| 你最先要确认的三件事 | 三个零各给一条能核对的证据，不是口号 |
| 这些店都能开 | 覆盖面够宽，你多半在里面 |
| 每天就这六件事 | 日常操作不复杂，一部手机够用 |
| 不止一家店，不止一笔收入 | 开起来之后还有增量，不是开完就到头 |
| 收款、送达与结算 | 钱怎么进、货怎么出、账怎么算，一张表交代完 |
| 常见问题 | 拆掉四个最常见的顾虑：身份、费用、时长、续费 |
| 收尾 | 复述门槛与成本，收口到「免费开店」 |

### 3.2 支持哪些店 `/scenarios/`

**整页一句话**：先换掉他的分类方式，再让他认领自己那一类。

| 段落 | 中心思想 |
|---|---|
| 标题 | 不按行业分，按交付方式分 —— 这是理解全站的前提 |
| 六类店铺 | 六个入口，认领自己那一类 |
| 需要资质的品类 | 有证门槛既是限制，也是对合规同行的保护 |
| 收尾 | 不在六类里的别走，用交付方式兜住长尾 |

### 3.3 生鲜果蔬 `/scenarios/fresh/`

**整页一句话**：用预售把损耗这件事解决掉。

| 段落 | 中心思想 |
|---|---|
| 标题 | 卖多少进多少 —— 预售制直接对上生鲜最大的成本 |
| 你会这样用 | 一天的作业流：截单 → 下架 → 分拣 → 通知 → 核销 |
| 另外两项 | 少录入、多一笔代收收入 |
| 常见问题 | 截单权限、顾客逾期、送货范围 |
| 收尾 | 门槛低，现在就能填 |

### 3.4 便利 · 日用 · 烘焙 `/scenarios/convenience/`

**整页一句话**：老客是你的资产，平台不从中抽成。

| 段落 | 中心思想 |
|---|---|
| 标题 | 回头客再来不抽成 |
| 你会这样用 | 把老客沉淀下来的具体手段：码、活动、团购、配送、名单 |
| 特色 | 强调这是**费率**不是活动，并给出可量化的看板 |
| 常见问题 | 码怎么拿、活动怎么发、几个活动怎么算 |
| 收尾 | 行动是「印码」，不是抽象的「注册」 |

### 3.5 到店与上门服务 `/scenarios/service/`

**整页一句话**：先收款，把服务业最大的风险前置解决。

| 段落 | 中心思想 |
|---|---|
| 标题 | 钱先到手，再安排人 |
| 你会这样用 | 服务履约与实物不同的六个点 |
| 另外两项 | 约定留痕、差评有救济 |
| 常见问题 | 顾客爽约、地址隐私、做完要退 |
| 收尾 | 收口到免费开店 |

### 3.6 社区自提点 `/scenarios/pickup-point/`

**整页一句话**：不卖货也有一份收入，而且顺带带来到店的人。

| 段落 | 中心思想 |
|---|---|
| 标题 | 不卖货也能挣钱 |
| 你会这样用 | 代收作业台的五个动作 |
| 特色 | 你只看得到该看的字段；服务费单独记账 |
| 常见问题 | 纯代收可不可以、接单量、顾客不来取 |
| 收尾 | 行动是「勾选自提点意愿」 |

### 3.7 多门店与连锁 `/scenarios/chain/`

**整页一句话**：第二家店开起来之后，钱、货、人必须分得开。

| 段落 | 中心思想 |
|---|---|
| 标题 | 三个隔离：账、货、权限 |
| 你会这样用 | 钱货人三分开，加上切换与并排比 |
| 权限与账号 | 老板和店长的边界划在结算上 |
| 门店额度 | 档位差的是额度，不是功能 |
| 常见问题 | 共用商品、订单串店、超额 |
| 收尾 | 收口到免费开店 |

### 3.8 自有品牌 `/scenarios/own-brand/`

**整页一句话**：判断你这样的店该不该做独立入口。（**注意与 3.12 的分工，见 §五**）

| 段落 | 中心思想 |
|---|---|
| 标题 | 招牌是你的，客也是你的 |
| 你会这样用 | 两个入口并行：平台带新客，自己沉淀老客 |
| 特色 | 省下的最大一块是资质时间 |
| 常见问题 | 与入驻的关系、计价方式、可定制范围 |
| 收尾 | 可以先入驻跑起来，客群稳了再加入口 |

### 3.9 怎么开店 `/how-it-works/`

**整页一句话**：把「要做什么」框成三步，并且拆开开店与收款这两件事。

| 段落 | 中心思想 |
|---|---|
| 标题 | 材料就一张身份证，动作都在手机上 |
| 三步 | 申请 → 审核 → 上架，把不确定性框在中间那一步 |
| 收款要单独申请一次 | **防误解**：能上架不等于能收到钱 |
| 要准备的材料 | 按身份对号入座，选完行业不允许的直接变灰 |
| 常见问题 | 审核时长（不承诺）、没单怎么办、能不能先试 |
| 收尾 | 第一步现在就能做 |

### 3.10 收费与套餐 `/pricing/`

**整页一句话**：一共两笔，且停付不会让你关店。

| 段落 | 中心思想 |
|---|---|
| 标题 | 没有前置成本 |
| 一共两笔 | 交易 + 软件，两张表说完，不留第三笔 |
| 档位差的是额度，不是功能 | 消除「免费版是残废版」的顾虑 |
| 到期是降级，不是关店 | **比价者最大的隐性顾虑**，必须单列一节 |
| 加购：自有小程序 | 独立计价，与档位无关 |
| 常见问题 | 免费版限制、试用绑卡、超额、为什么不标价 |
| 收尾 | 收口到免费开店 |

### 3.11 功能总览 `/capabilities/`

**整页一句话**：给要逐条核对的人一份可核对的清单，并把未上线的集中标出来。

| 段落 | 中心思想 |
|---|---|
| 标题 | 声明这是附录，不需要的人请回去看类型页 |
| 端与形态 | 在哪用、缺哪一个 |
| 十四个功能域 | 范围声明 + 免费版包含到什么程度 |
| 店铺配色 | 这是真实可选项，不是官网画的示意 |
| 还没上线的 | **把角标集中一处**，防止转述时丢失 |
| 收尾 | 送回收费页 |

### 3.12 自有品牌小程序 `/mini-program/`

**整页一句话**：这个加购项包含什么、归属怎么划、怎么开通。

| 段落 | 中心思想 |
|---|---|
| 标题 | 前台是你的，后台是我们的 |
| 哪些归你，哪些共用 | 归属边界一次划清，避免事后争议 |
| 上架我们陪着走 | 类目决定要不要办 EDI —— 这是省时间的关键一步 |
| 常见问题 | 与入驻关系、顾客归属、计价、可定制范围 |
| 收尾 | 先入驻也行，数据不用搬 |

### 3.13 下载 `/download/`

**整页一句话**：别下错那个 App。

| 段落 | 中心思想 |
|---|---|
| 标题 | 两个 App 名字相近，这页最大的失败模式就是下错 |
| 顾客端 | 消费者入口 |
| 商家端 | 商家入口 + 解释安卓包在微信里为什么被拦 |
| 顾客那侧是这样买的 | 让商家看一眼顾客侧体验 |
| 收尾 | 把误入这页的商家拉回开店 |

## 四、页与页之间怎么走

```
首页 ──「这些店都能开」──→ 类型页 ──→ 免费开店
  │                            │
  │                            └──→ 收费与套餐 ──→ 功能总览（想核对细节的少数人）
  │
  ├──→ 怎么开店（还在犹豫流程的）
  └──→ 自有小程序（已经有品牌的）
```

**主 CTA 全站统一四个字：免费开店。** 同一个动作写成「立即入驻」「马上开店」「申请入驻」，
商家会以为它们通向不同的地方。

## 五、这轮梳理发现的三个结构问题

### 1. `/scenarios/own-brand/` 与 `/mini-program/` 严重重叠

`own-brand` 的 3 条 FAQ **全部**在 `mini-program` 里重复（与入驻冲突吗、多少钱、能改样式吗），
其中两条一字不差。「上架流程」和「EDI 类目」两段也各写了一遍。
读者点完一页再点另一页，会觉得被绕回了原地。

**建议的分工**（不合并，因为一个在类型层、一个在产品层）：

| | `/scenarios/own-brand/` | `/mini-program/` |
|---|---|---|
| 回答 | 我这样的店**该不该**做独立入口 | 这东西**包含什么、怎么开通** |
| 留 | 受众判断：客群多稳算稳、老客占比多少划算 | 归属表、上架流程、EDI、计价 |
| 删 | EDI 段、计价 FAQ、样式 FAQ | 「与入驻不冲突」重复陈述保留一处即可 |

### 2. 首页「店铺配色」放错了地方

它在「不止一家店，不止一笔收入」那一节里，是四张卡中唯一与「增量收入 / 多门店」无关的一张。
**建议移到 `/capabilities/`** —— 那里本来就有配色小节。移走后该节只剩三张卡，主题反而更聚焦。

> 首页目前 8 节，已经顶到上限。**要加新内容必须先删一节**，不能直接追加。

### 3. 顶栏「顾客入口」把商家引向了消费者页

`/download/` 的受众是消费者，出现在商家转化线的顶栏上是个断点 ——
商家点进去看到的是「怎么买东西」。

**建议**：顶栏那一项直接跳 C 端入口（`/c/`），不落在官网页面上；
`/download/` 保留，但只从页脚进。

## 六、暂不做

| 页 | 为什么 |
|---|---|
| 关于我们 / 团队 | 商家不因为这个入驻。等有融资或资质背书再说 |
| 客户案例 | **一个真实案例都还没有。** 编造案例是最快毁掉信任的方式 |
| 博客 / 帮助中心 | 帮助中心属于已入驻商家，应该在商家端里，不在宣传站 |
| 数据大屏 / 覆盖地图 | 覆盖数字未到位，在有真实数字之前一个都不放 |
