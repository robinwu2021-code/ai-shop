# TDD-多位置单生效（美团式地址切换）

状态：**草稿（待确认）** · 2026-09-03
关联：[TDD-定位能力受限下的位置模型](./TDD-定位能力受限下的位置模型.md) · [TDD-定位与未开通区域](./TDD-定位与未开通区域.md)

---

## 1. 一句话

用户可以存多个位置（家 / 公司 / …），但**任一时刻只有一个生效**；
生效的那一个决定他看到哪些商家与商品。顶栏显示它，点开可切换、可新增。

---

## 2. 现状：底子比预期好

`usr_address` 已经有这些列：

```
address_id  user_no  name  phone
province city district detail  region
lat_e6  lng_e6        ← 有坐标
tag                   ← 「家」「公司」
is_default            ← 已有「默认」的概念
```

**不需要新建表。** 「多位置」在数据上已经成立，缺的是：

1. 「**当前生效**」是一个比 `is_default` 更短命的概念（默认是长期偏好，
   生效是这一次逛的上下文）—— 需要一个独立的、可随时切换的选择
2. 端上没有「切换位置」这件事：地址页现在只服务于下单填收货人
3. 商品池仍挂在 `communityNo` 上，与地址无关

---

## 3. 分两步走，第一步不动主轴

### 第一步：地址 → 归属社区（UI 就是最终形态，后端不动）

```
用户选中一个地址（家 / 公司 / 刚定位到的）
        │
        ▼
  用它的坐标查 nearbyCommunities(lat,lng)   ← 这个接口已经有了
        │
        ▼
  取覆盖它的那个社区 → 沿用现有的 communityNo 链路
```

**为什么这样切**：界面从第一天起就是美团式的（顶栏地址、点开切换、可新增），
而后端的商品池仍按 `communityNo` 走 —— 现有的商家可见性、佣金归属、
配送范围判定**一行不用改**。

这一步能独立上线，且**用户看到的就是最终形态**。

### 第二步：坐标直接决定可见性（动主轴，另开方案）

去掉「地址 → 社区」这一跳，后端按坐标 + 商家配送范围实时算。
好处是办公楼、任意门牌这类**不属于任何已开通小区**的位置也能用。
代价是商家可见性、佣金归属两条线都要重做，**不在本方案内**。

> 第一步做完，第二步是**替换中间那一跳**，端上一行不用改 —— 这是分两步的全部理由。

---

## 4. 设计

### 4.1 「当前生效」存在哪

**端上本地 + 服务端各存一份**，以服务端为准：

- 本地：切换要立刻生效，不能等一次网络往返
- 服务端：换设备、重装小程序之后还是同一个上下文

⚠️ **不要复用 `is_default`。** 「默认」是「下单时预填哪个收货人」，
「生效」是「现在按哪儿看货」——两者会不一样：
给父母下单时切到父母家看货，但默认收货地址仍是自己家。
合成一个字段的后果是**改了一个、另一个跟着变**，而用户不会预期这件事。

### 4.2 新增位置的三条路

| 路 | 用什么 | 状态 |
|---|---|---|
| 推荐附近的小区/写字楼 | `getFuzzyLocation` 定位到区 → 列该区已开通的点 | 待接口获批 |
| 地图上指一个 | `chooseLocation`（米级） | **已开通，已在用** |
| 从微信地址簿导入 | `chooseAddress` | **已开通，已在用** |
| 搜索 | 现有的社区搜索框 | 已有 |

三条都已经有落点，**不需要为这个功能去申请新接口**。

### 4.3 顶栏

首页顶栏那一行从「选择自提点」改成「当前位置」：
显示 `tag`（家/公司）或地址简称，点开是位置列表。

未选任何位置时显示「选择位置」—— **不弹窗、不跳转**，
理由见 [定位能力受限下的位置模型 §3.1](./TDD-定位能力受限下的位置模型.md)。

---

## 5. 要防住的三件事

**一、切换位置后购物车怎么办。** 不同位置对应不同商家，车里的东西可能
在新位置买不到。**不能静默清空**（那是用户的东西），也不能装作没事
（结算时才报错更糟）。方案：保留，但在车里把不可售的行标出来并禁选。

**二、「生效位置」与「收货地址」是两个概念，界面要分得开。**
下单页选的是收货人地址，顶栏选的是浏览上下文。它们常常是同一条记录，
但不是同一件事 —— 合并会在「给父母下单」这个场景上出错。

**三、位置为空时不能空转。** 新用户没有任何位置，首页要照常有东西看
（平台推荐 + 全局在售），而不是一片空白等他去选。

- [ ] `GET/PUT /mp/user/active-address`
- [ ] 端上 `location` store：生效位置 + 切换 + 由坐标解析社区
- [ ] 首页顶栏改成位置切换入口
- [ ] 位置列表页（列表 + 新增三条路 + 切换）
- [ ] 购物车不可售标记（§5-一）
- [ ] 守卫：生效位置 ≠ 默认收货地址（防止两者被合成一个字段）
