# 界面规范 · 运营端 · 列表与抽屉

> 状态：**规范 · 长期有效** · 创建 2026-11-16
> 范围：运营端（`ops-web`，PC Web）里「一张表 + 行内动作 + 右侧抽屉」这一类页面 —— 运营端绝大多数功能都是这个形状。
> 关系：token、字阶、组件清单与闸门数字见 [规范-运营端](规范-运营端.md)（生成物）；组件分层与来由见 [`ops-web/components/README.md`](../../../ops-web/components/README.md)。本文只管**页面怎么拼**，不重复那两份。

## 一句话

**表格负责「找到那一行」，抽屉负责「对那一行做一件事」。** 看详情、编辑、新增、审核都在右侧抽屉里完成，列表上下文不丢；动作按钮一律在抽屉底栏，保存成功后关抽屉、刷列表、给 toast。

## 1. 页面骨架

```
TabHeader                 页头（单 tab 也走它，传 desc）
  ReadOnlyNotice          无写权限时
  HelpNote / Notice       这一屏的前提或风险（常驻说明用 HelpNote，默认收起）
  Toolbar                 左：搜索 TextFilter + 筛选 FilterSelect（都挂 toChip）
                          右：导出 / 【新增】主按钮
  PagedTable              分页列表；不分页的配置表用 DataTable（自己接 error/onRetry）
    └ 最后一列「操作」     行内动作 → 打开抽屉
  Drawer / FormDrawer     详情 · 编辑 · 新增 · 专项动作
  ConfirmDialog           归档 / 删除 / 停用等一句话就能确认的动作
```

| 要素 | 规则 |
|---|---|
| 新增入口 | **只有一个**：`Toolbar` 右侧的主按钮，文案「新增{实体}」。没有新增权限时不渲染（不是置灰） |
| 列表 | 分页一律 `PagedTable`；空态文案 ≥20 字、说清为什么空和下一步（已有闸门） |
| 抽屉 | 页面级状态，放在表格之后渲染；**同一时刻最多一个抽屉**，不叠抽屉 |
| 文案 | 页面正文走同目录的 `copy.ts` + `useCopy`，不在 JSX 里写死 |
| 说明文字 | **只留标题、placeholder、风险 / 错误提示（`Notice tone="warning\|danger"`、校验错误、`ReadOnlyNotice`、确认弹窗）与空态文案**。不写页头描述、`HelpNote`、分段 `desc`、字段 `help`、灰字说明；资金类风险提示算「风险提示」保留。删掉的文案连同 `copy.ts` 里的词条一起删 |

## 2. 操作列

| 规则 | 说明 |
|---|---|
| 位置 | 表格**最后一列**，表头「操作」 |
| 行内按钮 ≤ 2 个 | `Button size="sm" variant="ghost"`。第一个固定是**主查看入口**（「详情」），第二个是最常用的写动作（通常「编辑」）。其余动作进 `RowActions`（「更多」菜单） |
| 危险动作 | 归档 / 删除 / 停用 / 驳回**不放行内**，进 `RowActions` 并标 `danger`（自动沉底、分隔线隔开），点了走 `ConfirmDialog` |
| 权限 | 无权限的动作**不渲染**；只有「当前状态不允许」时才 `disabled` 并给 `hint` 说明原因。整列动作都没有时 `RowActions` 自己不渲染 |
| 状态相关 | 动作随行状态变（已归档显示「恢复」而不是「归档」），由 `cell` 里判断，不要出一个点了才报错的按钮 |
| 不做整行点击 | 行上已有复选框、复制编号、链接等交互，整行可点会误触；打开详情只走操作列（或主键列的链接） |

```tsx
{
  header: c.colActions,
  cell: (r) => (
    <div className="flex items-center gap-2">
      <Button size="sm" variant="ghost" onClick={() => setDrawer({ mode: "view", id: r.no })}>{c.view}</Button>
      {canEdit && <Button size="sm" variant="ghost" onClick={() => setDrawer({ mode: "edit", id: r.no })}>{c.edit}</Button>}
      <RowActions actions={[
        canEdit && r.status !== "ARCHIVED" && { label: c.archive, danger: true, onSelect: () => archive(r) },
      ]} />
    </div>
  ),
}
```

## 3. 抽屉的四种用途

| 用途 | 标题 | 正文 | 底栏 |
|---|---|---|---|
| **详情** view | 「{实体}详情」，`desc` 放编号 / 名称 | 只读：`DrawerSection` + `FieldGrid` + `Field`；明细行用 `DataTable` | 有权限时放写动作（「编辑」及状态动作）；纯只读则**不传 footer** |
| **编辑** edit | 「编辑{实体}」，`desc` 放编号 | 表单；业务主键只读（`readOnlyOnEdit`） | 「取消」+「保存」 |
| **新增** create | 「新增{实体}」 | 同编辑，初值取页内常量 `EMPTY` | 「取消」+「保存」 |
| **专项动作** | 动词起头：「审核入驻申请」「调整库存」 | 上段只读上下文，下段要填的输入，**两段必须分开** | 「取消」+ 动作按钮（如「驳回」「通过」） |

- **详情 → 编辑在同一个抽屉里切换**：详情底栏点「编辑」，`mode` 变成 `edit`，宽度不变；保存成功回到详情（从列表直接进编辑的，保存成功直接关闭）。不要先关详情再开编辑抽屉，更不要叠两层。
- **抽屉里某一块自带表单**（如商家详情的「支付服务」页签）：表单原地展开，按钮用 `DrawerFooter` 放进外层底栏；纯字段表单直接 `FormDrawer inDrawer`。不要为它再弹一层抽屉。
- **一件事一个抽屉**：「改资料」和「挑商品」「设价格」是不同的事，各用一个 `mode`，不要塞进同一张表单里分 tab（参考 `app/products/topics-tab.tsx` 的 `picking` 与 `form` 分开）。

### 状态写法（新页面）

用一个可辨识联合表示「哪个抽屉、哪一行」，不再一个抽屉一个 `useState`：

```tsx
type DrawerState =
  | { mode: "view"; id: string }
  | { mode: "edit"; id: string }
  | { mode: "create" }
  | { mode: "audit"; id: string };

const [drawer, setDrawer] = useState<DrawerState | null>(null);
const close = () => setDrawer(null);
```

- `open={!!drawer}`、`onOpenChange={(o) => !o && close()}`；正文用 `{drawer && …}` 包住，关闭即卸载，换行打开不会残留上一条的输入。
- 存量页面里的 `current`（选中查看的行）、`form`（编辑表单）、`editing` 三种命名照旧可用，**改到这个文件时再收**，不为改名单独动。

## 4. 抽屉的结构与尺寸

```
┌ 标题 / desc ─────────────── ✕ ┐  头部（Drawer 自带）
│ DrawerSection first  基本信息  │
│   FieldGrid › Field × n        │  只读：两列
│ DrawerSection  要填的          │
│   输入控件（单列）              │
│ …（正文独立滚动）               │
├────────────────────────────────┤
│              [危险] [取消] [主] │  footer：右对齐，主动作在最右
└────────────────────────────────┘
```

**宽度**（`width` 只取下面这几档，不要再造新值）：

| 档 | 值 | 用在 |
|---|---|---|
| 默认 | 不传（440px） | 单列表单、≤ 8 个字段的简单详情 |
| 标准 | `w-[560px]` | 带 `FieldGrid` 两列详情、分段表单（存量 `w-[520px]` 视同此档，改到时再收） |
| 宽 | `w-[720px]` | 抽屉里要嵌一张明细表（订单商品、流水、操作记录） |
| 超宽 | `w-[900px]` | 左右对照 / 多列编辑器，**需在 TDD 写明理由** |

窄屏不用管：`Drawer` 自带 `max-w-full`，375px 下自动铺满。

**正文**：

- 第一段 `DrawerSection first`，其后每段自带分隔线。**只读的和要填的不在同一段。**
- 只读字段用 `Field`（标签在上、值在下）；两列用 `FieldGrid`，里面的 `Field` 传 `className="mb-3"`。长文本、地址、备注占整行。
- 金额 `money()`、时间 `fmtTime()`、状态 `StatusBadge`，与列表同一种写法 —— 同一个值在表格和抽屉里长得不一样，运营会以为是两回事。
- 加载中给 `Skeleton`，加载失败给 `ErrorState` + 重试，**不要渲染一个空表单让人以为数据是空的**。

**底栏**：

- **所有动作按钮放 `footer`，不放正文底部。** 正文会滚动，按钮跟着滚出视野；footer 是固定的。
- 顺序：危险动作（`variant="destructive"`）→「取消」（`variant="outline"`）→ 主动作（默认 variant）。主动作永远在最右；当危险动作本身就是这个抽屉的主动作（如「驳回」抽屉）时，它放最右。
- 保存按钮**只在提交中禁用**，不因校验未通过而禁用（理由见 `form-drawer.tsx`：灰按钮不告诉人为什么）。点击后暴露全部错误、不提交。

## 5. 表单：`FormDrawer` 还是手拼

| 情况 | 用 |
|---|---|
| 纯字段表单，控件都在 text / number / select / switch / password / textarea / date / multiselect 之内 | **`FormDrawer`**（字段定义 `FieldDef[]`，校验、分区、联动、必填星号、a11y 都现成） |
| 要嵌表格、选择器、图片上传、子表单，或详情与编辑共用一个抽屉 | `Drawer` + `DrawerSection` + 控件 + `footer`，校验走 `lib/form-validate` 的 `validateAll`，不要另写一套 |

- 表单状态用函数式更新：`setForm((p) => p && { ...p, title: v })`（已有闸门）。
- 编辑的初值来自**详情接口**，不是列表行 —— 列表通常是摘要，拿它回填会把没返回的字段保存成空。
- 输入校验以服务端为准，前端只做必填、长度、格式这类即时提示，不重复业务规则。

## 6. 数据与提交

```tsx
const detail = useQuery({
  queryKey: ["topic", drawer && "id" in drawer ? drawer.id : null],
  queryFn: () => api.getTopic((drawer as { id: string }).id),
  enabled: !!drawer && "id" in drawer,
});

const save = useMutation({
  mutationFn: (f: Form) => (f.no ? api.updateTopic(f) : api.createTopic(f)),
  onSuccess: () => {
    qc.invalidateQueries({ queryKey: ["topics"] });   // 列表
    qc.invalidateQueries({ queryKey: ["topic"] });    // 详情
    close();                                          // 或回到 view
    notify.success(c.saved);
  },
});
```

| 规则 | 说明 |
|---|---|
| 详情按需取 | 抽屉打开才请求（`enabled`），queryKey 带主键 |
| 成功 | 刷新**列表与详情**两个 query → 关闭（或回到详情）→ `notify.success` |
| 失败 | **抽屉保持打开、表单内容保留**。错误 toast 由 `components/providers.tsx` 的 `MutationCache.onError` 统一弹，页面不再自己 `catch` 弹一遍 |
| 防重 | 保存按钮 `loading={save.isPending}`（`Button` 自带，提交中即禁用） |
| 不在前端先改行 | 不做乐观更新；运营端的列表是对账用的，显示的必须是服务端的结果 |

## 7. 关闭

- ✕、Esc、点遮罩、「取消」**是同一件事**，都走 `close()`。
- 表单有未保存修改时，关闭前用 `useConfirm` 问一次「放弃未保存的修改？」。
  ⚠️ 这条目前**还没有公共实现**，各页都没做；新写的复杂表单（字段 ≥ 6 或有子表）按这条做，等第二处出现时提到 `Drawer` 里。
- 抽屉里发起了资金类命令且结果未定（退款、实收调整）时，用 `useFinancialLock`（`components/offline/financial-lock.tsx`）挡关闭与离开页面。

## 8. 什么时候不用抽屉

| 情况 | 用 | 依据 |
|---|---|---|
| 一句话就能确认的动作（归档、删除、启停） | `ConfirmDialog`（不可逆的加 `requireText`） | 没有要填的东西，不值得滑出一整屏 |
| 行内顺手改一个值（排序号、开关） | `Popover` / 表格内 `Switch` | 「顺手改一下」，不遮列表 |
| 纯配置页（没有列表） | `ConfigCard` | 页面本身就是表单 |
| 新增需要多组双栏、内容明显比抽屉宽 | 居中弹框（先例：`app/merchants/on-behalf-tab.tsx` 代办入驻） | **例外**，需在该功能的 TDD 写明为什么抽屉放不下 |
| 一个对象有多个子页面、要能分享链接 | 独立详情路由 | 抽屉不进 URL，刷新就没了 |

## 9. 评审清单

提交含列表 + 抽屉的页面前过一遍：

- [ ] 新增入口只有 Toolbar 右侧一个，无权限不渲染
- [ ] 操作列行内 ≤ 2 个，危险动作在 `RowActions` 且走确认
- [ ] 抽屉标题按「{实体}详情 / 编辑{实体} / 新增{实体} / 动词+对象」
- [ ] 宽度只用 默认 / 560 / 720 / 900 四档
- [ ] 只读与可填分段；两列只读用 `FieldGrid`
- [ ] 所有按钮在 `footer`，主动作最右，只在提交中禁用
- [ ] 编辑初值来自详情接口；成功刷新列表 + 详情并关闭；失败保留输入
- [ ] 详情加载中 / 失败有 `Skeleton` / `ErrorState`
- [ ] 正文文案在 `copy.ts`；金额、时间、状态与列表同一写法
- [ ] 改了页面标题或菜单 → 重跑 `python3 scripts/gen-ui-catalog.py`

数字是当天 grep 出来的，用来判断收口工作量，不是闸门。

| 项 | 现状 | 处理 |
|---|---|---|
| 动作按钮在 `footer` | 71 个含抽屉的文件里，33 个全部走 footer，30 个完全不用 footer（保存按钮放在正文底部），8 个混用 | 改到哪个页面收哪个；新页面必须 footer |
| 行内动作 ≤ 2 | `RowActions` 只有 1 个页面在用；例如 `app/products/topics-tab.tsx` 行内 3 个按钮（含「归档」） | 同上 |
| 抽屉宽度 | 出现 10 种值：520（19 处）、560（15）、640、680、760、860、900、1100 等 | 新页面按四档；存量不批量改 |
| 状态命名 | `current` 24 / `form` 14 / `editing` 11，一个抽屉一个 state | 新页面用 `DrawerState` 联合 |
| 未保存提醒 | 0 处实现 | 见 §7 |
| 门店 / 商户两组页面 | 2026-11-16 已按本规范收口（含套餐抽屉改成详情→授予/额度三态、支付服务表单不再叠抽屉、`ArchiveActions` 归档进「更多」并常显「查看」） | 其余业务域照此推进 |
