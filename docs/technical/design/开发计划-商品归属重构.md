## 0. 总原则

1. **每期可独立发布**，期内再拆到「一次提交能验完」的粒度。
2. **先补数据再改约束**（V387 回填 → 才置 NOT NULL）。
3. **双读期**：P2 加列不改读路径，P3 一次切完并把旧投影代码**删干净**，
   不留两套判定 —— 留两套的症状是「看得见、下单说没货」，且不报错。
4. 每个任务按 TDD §5 指名测试方法，**跑过并做一次消融**（撤实现→变红）才算完。
5. **共享工作区**：多会话同目录。提交前 `git diff HEAD -- <file>` 自读，只提交自己认得的行；
   迁移号实现时现 `ls` 取（本文写的是计划值）。

逐组保留哪条要人确认（看谁带 `origin_code`、谁被经营范围引用）；

若需要可用运营端围栏设置单独调。
