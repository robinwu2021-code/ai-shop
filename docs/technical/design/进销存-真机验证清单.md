## 为什么需要人来点

三轮改动的验证到目前为止只到这里：mock 上的交互实跑、线上产物 grep 到新文案、
后端路由确认在跑着的 jar 里。**登录之后的真实界面没有人走过一遍。**

mock 的数据是构造的，回边落到哪一条数据上、落错了会不会看出来，只有真数据能回答。

## 五条，每条一分钟

判据写成「应当看到什么」，不是「点一下看看」——
看不出对错的检查等于没检查。

### ① 单据 → 那件货（新）

工作台 → 库存 → **按单查**（这一屏原来叫「单据」）

- 顶上应有一句：「按单看变动。想知道某一件货怎么变的，去库存点开那件货」
- 点任意一张**入库单或出库单**（不是盘点/调拨，那两类会跳走）
- 应当**就地展开**「这张单动了这些货」，列出该单动过的每一件货与增减数
- 点其中一行 → 应当到那件货的**库存明细**，页内第一行就是这件货的名字

> 会出错的地方：展开后是空的。若该单是**草稿**（还没过账），空是对的，
> 应显示「还没过账，暂无流水」；若是**已过账**的单还空，那是缺陷。

### ② 那件货 → 那张单（新）

接着上一步，停在库存明细

- 「变动明细」这一块现在叫 **按货查**，下面一行小字「点一行看那张单」
- 每一行的单号应当是**链接色**（不是灰色）
- 点任意一行 → 应当回到按单查，顶上显示 **「只看 XXX」**，右侧一个「看全部」
- 点「看全部」应当回到完整列表

> 会出错的地方：点了没反应，或列表没有被那个单号筛住。

### ③ 报表 → 那件货（新）

库存 → 报表

- 动销榜、滞销榜的每一行右侧应有一个 **›**
- 点任意一行 → 应当到那件货的库存明细

### ④ 「盘这一件」（改名）

库存 → 点开任意一件货 → 拉到页尾

- 按钮应当是 **「盘这一件」**（原来叫「调整数量」）
- 上方小字应当是：「盘这一件会生成一张盘点单，并按下面的原因记一行流水」
- 点它，弹窗标题应为「盘这一件」，提示里应出现「**确定后生成一张盘点单**」
- **可以取消**，不必真盘 —— 这一条验的是文案，不是功能

### ⑤ 挑货能挑到「还没进过货」的货（本轮最实的一条）

库存 → 进货 → 添加货品

- 弹层顶上应有一个**搜索框**（有边框、可点进去打字，不是一行灰字）
- 输入两个字应当立即筛选
- 选中一件后再打开弹层，顶上应显示「已选 N 件」，选过的那一行**压暗**
- **关键**：随便挑一件商品，先在「商品」里新建一个 SKU（或用一件从没进过货的），
  它应当**出现在这个弹层里、数量显示 0**

> 这一条对应的缺陷是：此前挑货读的是余额，而余额行按需建 ——
> 一件刚建的货没有余额行，于是**在弹层里根本不存在，商家没法给它记第一笔进货**。
> 修复上线于 `44f35735`。挑不到就是没修好。
