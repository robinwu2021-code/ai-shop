## 一、完整入口（从代码取，不凭印象）

进销存**只有一个门**：工作台上那张「进销存」卡。它不进上面的待办九宫格 ——
九宫格里每一格是「有几单等着你」，而进销存不是待办，是一个域。

```
工作台
└─ 进销存卡（v-if: 有 biz:stock）
   ├─ 标题行「全部 ›」 ────────────┐
   ├─ 三个数：在售 / 缺货 / 滞销 ──┤ 三个都点到 → 库存
   └─ 三个快捷：进货 · 盘点 · 单据 ─┘（各自直达，跳过枢纽）

库存（枢纽）
├─ 七格入口（按权限过滤）
│    进货 · 盘点 · 报损 · 单据 · 调拨      ← biz:stock
│    报表                                 ← biz:customer
│    库位                                 ← biz:store:admin
├─ 筛选：要处理 N / 全部 / 有预留
└─ 列表每行 → 库存明细
```

**七格不是并列的七件事**，这是本文第二节要解决的问题。

### 1.1 页面与它的写动作

| 页面 | 路由 | 权限 | 写动作（`api.m*`） |
|---|---|---|---|
| 库存 | `stock` | `biz:stock` | 无（纯看） |
| 库存明细 | `stock-detail` | `biz:stock` | `mStockAdjust` |
| 单据 | `stock-docs` | `biz:stock` | `mInboundVoid` `mOutboundVoid` |
| 进货 | `purchase-edit` | `biz:stock` | `mInboundCreate` `mInboundPost` |
| 盘点 | `stock-check` | `biz:stock` | `mCountOpen` `mCountFill` `mCountPost` |
| 报损 | `stock-out` | `biz:stock` | `mOutboundCreate` `mOutboundPost` |
| 调拨 | `transfer` | `biz:stock` | `mTransferCreate` `mTransferShip` `mTransferReceive` |
| 报表 | `stock-report` | `biz:customer` | 无 |
| 库位 | `locations` | `biz:store:admin` | `mWarehouseCreate` `mLocationSetSource` |

**两处权限不同于其余五处，是有意的**：报表看的是经营数据（与「谁能看客户」同一档），
库位是门店级配置（与「谁能改店铺」同一档）。理货员天天改库存，但不该看毛利、不该建仓。

## 二、功能：七格其实是四件事

商家拿这套东西做四件事。**七格按「功能」排，人得先知道自己要用哪个功能才找得到入口** ——
而他脑子里想的是「今天要做什么」。

| 他要做的事 | 落在哪几格 | 频率 |
|---|---|---|
| **看** —— 现在有多少、哪件断了、哪件压着 | 库存 · 库存明细 | 每天多次 |
| **记** —— 进了货、坏了、挪了、点了一遍 | 进货 · 报损 · 调拨 · 盘点 | 每天 1–3 次 |
| **查** —— 这批货怎么来的、这笔怎么少的、这个月怎么样 | 单据 · 明细里的流水 · 报表 | 每周／每月 |
| **配** —— 有几个仓、发货从哪出 | 库位 | 一次性 |

四件事的**频率差两个数量级**，而现在七格是等大的、并排的、同色的。

| 能力 | 端点 | 界面 | 状态 |
|---|---|---|---|

## 三、流程：八条，按发生频率排

流程图用状态名写，状态名取自 `InvEnums`，不另造词。

### 3.1 建品 → 上账 → 第一次进货

```
商品页新建 SKU
  └→ SKU_UPSERTED 事件 → outbox → 投影 → inv_item（物料建好，余额行还没有）
       └→ 进货页挑货：**读物料不读余额**，所以这件 0 库存的新货挑得到
            └→ 过账 → 余额行按需建出来 → 库存列表里出现
```

> **这条边 2026-08-28 之前是断的两处**：SKU 建了不上账；上了账因为读余额而挑不到。
> 两处的症状都是「那件货在库存里根本不存在，且不报错」。

### 3.2 进货

```
进货页 → 挑货（可搜） → 填数量与进价
  ├─ 存草稿  → DRAFT   不动库存
  └─ 过账入库 → POSTED  加库存 + 一行流水 + 按本次进价更新成本
```

### 3.3 盘点（整批）

```
盘点页勾一批货 → 开单
  → COUNTING：**锁住开单那一刻的账面数**（盘点期间照常卖，不影响差异）
  → 逐件录实数（差异 = 实数 − 锁定账面）
  → 过账 POSTED：差异不为 0 的落 COUNT_GAIN / COUNT_LOSS 流水
```

### 3.4 盘一件（便捷）

```
库存明细 →「盘这一件」→ 填实数 + 选差异原因
  → 底下走的就是 3.3 的开单/录数/过账，只是一步完成
```

> 按钮此前叫「调整数量」，商家以为是直接改个数 ——
> 而它会开一张盘点单、出现在单据列表里。**名字照实说**，代价是多四个字。

### 3.5 报损

```
报损页 → 挑货（只列可用 > 0）→ 填数量 + 原因（BROKEN/EXPIRED/GIFT/OTHER）
  → 过账 POSTED：扣库存 + 一行流水
```

> 原因是**枚举不是自由文本**：自由文本汇总不出「这个月报损了多少」，
> 而那正是月底商家唯一想知道的数。

### 3.6 调拨（两段式）

```
调拨页：从 A 仓 → B 仓，挑货填数
  → DRAFT
  → 确认发出 SHIPPED：**A 扣了，B 还没加** —— 差额在「在途」
  → 到货确认 RECEIVED：B 加上
```

> 两段式不是麻烦，是**在途那段本来就存在**。一段式会让「货在路上」这个事实无处安放。

### 3.7 销售自动出库（无界面）

```
买家下单付款 → 平台扣库存（真相源）
  └→ 同一个事务写 sys_outbox
       └→ OutboxDispatcher（5 秒一轮）→ 进销存跟记一笔 OUT/SALE
```

> `stock-authority=DUAL`，2026-08-28 22:54 起生效。
> **这条链在生产上一次都没跑过** —— 线上 0 订单，不是因为坏。

### 3.8 录错了怎么办

```
单据页 → 展开那张单（先看它动了哪几件货）→ 作废
  ├─ DRAFT  → VOIDED，本来就没动库存
  └─ POSTED → VOIDED + **一行反向流水**，库存回到这张单之前
       └→ 重新录一张对的
```

> **单据不可修改**。改单据等于改历史，而历史正是这些表存在的理由。
> 所以 `PUT inbounds/{no}` 有端点而**故意没有入口**。

## 四、这套流程里，界面还欠的三件

不是功能缺口，是**排布**问题 —— 第三节每条流程都跑得通，但商家要自己找到起点。

1. **七格等大等色**，而「看」每天几十次、「配」一辈子一次。
2. **工作台那三个快捷是写死的**（进货 / 盘点 / 单据），不随他实际在做什么变。
3. **没有「在途」的位置**。调拨 SHIPPED 的货既不在 A 也不在 B，
   而库存页三个数（在售 / 缺货 / 滞销）里没有它 —— 只有翻单据才看得到。

这三件是下一节 UI 原型要回答的问题。
