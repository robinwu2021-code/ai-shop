## 0 目标与边界

| 情况 | 怎么认 | 本文管什么 |
|---|---|---|
| 单店 | 主体只有一家店 | 已完成第一期（库存落本店行），本文不再展开 |
| 多店 | 多家店，都不在连锁里 | 保持现状（同主体跟卖） |
| **连锁** | 门店有生效中的品牌绑定；**品牌 = 连锁** | 本文主体 |

不做：区域 / 片区等第二种组、跨连锁共享、连锁级库存池、门店级独立进件（ADR-011）。

## 1 概念模型（一页）

```
商户集团 mch_group ──授权的根──┬── 经营主体 mch_entity（收钱、结算、开票）── 门店
                               └── 连锁 = 品牌 mch_brand
                                     ├── 总部 = legal_entity_no（一个主体）
                                     ├── 成员门店（有时效绑定；门店主体 = 总部 → 直营，否则加盟）
                                     └── 以连锁名义的发行方：储值 / 券 / 活动 /（积分）
```

- **运营归连锁，钱归主体**；连锁只经「结算指定」与「清分事实」碰钱。
- 命名：业务「连锁」；领域层 GROUP(kind = CHAIN)；存储、接口、权限码里的 `BRAND` / `brand` 冻结，经 `ScopeCodes` 一处翻译。

## 2 业务规则

### 2.1 组织与授权

| 规则 | 说明 |
|---|---|
| 连锁属于集团 | `mch_brand.management_no`；不属于某个主体 |
| 总部唯一来源 | `mch_brand.legal_entity_no`；绑定一次，更换走变更（审核） |
| 主体属于集团 | `mch_entity.management_no`（定稿已有列），取代「所有人账号推出」 |
| 门店入退连锁 | 门店须在同一集团内（加盟店先把门店授权进集团）；走审核工单服务（定稿已并入），带影响检查：储值在途、券预占、会员 |
| 直营 / 加盟 | 不记字段，按门店主体是否等于总部主体推出 |
| 总部权限 | 集团授权（`mch_grant`）里对连锁的能力码，如 `brand.manage`、新增 `chain.goods.release`、`settlement.designate` |

### 2.2 商品与价格（详见商品与库存方案 §5）

- 总部商品 = 总部主体名下、`store_no` 为空串的商品，只作模子，不上架、不卖、没库存。
- 总部下发（`mch_hq_release`，类型 GOODS / PRICE / CATALOG）到连锁成员门店；门店自动或手动套用。
- 套用 = 在门店名下建或更新一件本店商品，记来源（总部商品 + 版本）；下发字段（标题、图、类目、规格）门店不能改。
- 价格：下发价写入本店商品默认价；门店能否改价由总部按商品设定，默认不能。取价：目录价 → 门店价 → 默认价。
- 门店退出连锁：已套用的商品变成普通本店商品，来源保留作历史。

### 2.3 库存

- 永远按门店一行（单店第一期已落地）；连锁不共享库存，不复活主体库存池。
- 仓与调拨走库存库（进销存）；连锁门店可按门店切库存权威（`PLATFORM` / `INVENTORY`），对差连续为零才准切。
- 不做跨店借货；要共用一份货就建仓。

### 2.4 会员

- 连锁范围会员：`mbr_member.scope_type` = 连锁（存储 `BRAND`），成员门店共享。
- 门店退出连锁：会员关系不随门店走，历史消费留在原连锁范围。

### 2.5 发行方与权益

| 权益 | 发行方范围 | 结算主体 | 跨主体兑付 |
|---|---|---|---|
| 储值 | 门店 / 连锁 | 发行方版本冻结的结算主体（默认取结算指定） | 清分事实 → 跨主体账单（已有） |
| 券 | 门店（主体） / 连锁 / 平台 | 同上 | 券版本冻结成本承担：发行方全担 / 核销主体自担 / 按比例；不同主体时出清分事实（G4） |
| 活动 | 门店（主体） / 连锁 / 平台 | 连锁活动继承发行方，不再自选主体（G3 v2） | 现有成本规则分摊 |
| 积分 | 平台（现有）；连锁积分待定 | 平台；连锁积分则为结算主体 | 同储值清分 |

- 一个连锁只有一个发行方（按版本演进），储值、券共用它（G4 的「发行方泛化」）。
- 结算指定：连锁级默认一条有效版本；发行方新版本默认复制冻结它；更换不追溯已冻结版本。

### 2.6 结算与清分

- 订单、收款、分账照旧按门店所属主体（ADR-011）。
- 权益的负债与承担经发行方：跨主体兑付产生清分事实（工具维度：储值 / 券 / 积分），按发行方、期间、付款方、收款方、币种出账单。
- 报价分摊（`ord_price_quote_allocation`）记每笔优惠由谁出钱；清分从这里取数，券模块不另算。

### 2.7 报表

- 连锁范围的跨店报表：范围 = 连锁的成员门店（按绑定时效），不是主体。

## 4 代码改动方案

### 4.1 公共抽象（`shop-base` spi）

| 新增 | 作用 |
|---|---|
| `ScopeRef(type, no)`、`ScopeType { STORE, ENTITY, GROUP, PLATFORM }` | 范围统一表达 |
| `ScopeResolver`：`stores(scope, at)`、`scopesOf(storeNo, at)`、`lock(scope)` | 范围解析唯一入口（组织抽象 §1.2） |
| `ScopeCodes` | `BRAND` ↔ GROUP 的唯一翻译点；ArchUnit 规则：`"BRAND"` 字面量只许出现在它、迁移脚本与测试夹具（存量基线，只拦新增） |
| `StoreModePort.chainOf(storeNo)` | 门店所属连锁、总部主体；商品、库存、目录只调它 |
| `SettlementDesignationPort.current(subject)` | 结算主体唯一来源 |
| `HqReleasePort` | 商品领域接收下发、回报各店套用结果 |

### 4.2 商户域（`shop-merchant`）

| 改动 | 说明 |
|---|---|
| `GroupRepository` 包住 `mch_brand*` | 领域层用组语义，表名不改 |
| 主体建档写 `management_no`；回填任务（D1） | 取代 `ManagementScopeServiceImpl` 的所有人推出 |
| 结算指定服务（D3） | 端点挂在 `/biz/management/brands/{b}/settlement-designations`；主体方确认；停用守卫 |
| 总部下发服务（D2） | 建下发、选门店、撤回；按门店写 `mch_hq_release_store`；调商品域套用 |
| 入退连锁、储值开通改走审核工单服务 | 定稿已把 `mch_brand_change`、`mch_brand_financial_*` 并入审核工单；`BrandServiceImpl`、`BrandFinancialActivationServiceImpl` 改成「提交审核单 → 审核结果回调执行」 |
| `StoreModePort` 实现 | 读生效中的品牌绑定 |

### 4.3 商品域（`shop-core` product）

| 改动 | 说明 |
|---|---|
| 总部商品 | 建、改只总部有权（新能力码）；`store_no = ''`；列表与买家侧读路径排除 |
| 套用 | `HqReleasePort` 实现：按来源（D5）建或更新本店商品，复用现有保存与审核流程（下发内容按总部审核过的版本，门店套用免审，待定 §6 ⑦） |
| 字段锁 | 有来源的商品，门店保存时拒改下发字段；门店价按 D6 判 |
| 库存 | 不改（门店一行）；库存权威按门店切换，改 `shop.inventory.stock-authority` 的装配为按门店分派 |

### 4.4 营销与储值（`shop-core` promotion、`pay`）

| 改动 | 说明 |
|---|---|
| 发行方泛化 | `IssuerAuthorityService` 接受 PLATFORM；`instruments` 校验 |
| 连锁活动 | 创建时从发行方当前版本推出结算主体（只读）；`pmt_activity.issuer_no` |
| 连锁券（G4） | 券归属用 `ScopeRef`；核销时 `ScopeResolver` 判门店在不在范围；核销事实带发行方版本与承担方式；跨主体出清分事实 |
| 报价分摊 | 写 `bearer_entity_no`（D8）；清分从这里取 |
| 储值账户 | 统一到发行方（定稿 `ent_instance.issuer_no` 已是这个口径）；门店储值 = 范围为门店的发行方；V532 的按店隔离身份在迁移时映射过去 |
| 积分（若做） | 积分类型挂发行方（D13）；发放、抵扣、过期按发行方；跨主体按清分 |

### 4.5 报表与会员

- 跨店报表范围改用 `ScopeResolver.stores(连锁)`；能力位 `cross_store_stats` 不变。
- 会员范围判断改用 `ScopeRef`，去掉散落的 `"BRAND".equals(...)`。

### 4.6 守卫与测试

| 守卫 | 内容 |
|---|---|
| `BRAND` 字面量 | ArchUnit，存量基线只许减少 |
| 结算主体 | 约束测试：发行方版本、连锁活动、连锁券的结算主体都来自结算指定 |
| 下发字段锁 | 门店改下发字段被拒；改本店价按开关 |
| 跨主体清分 | 加盟门店核销连锁券 / 储值 → 产生一条清分事实，金额与承担方式一致 |
| 门店退出连锁 | 已套用商品照卖；连锁券在该店不能再核销，在其他店照常 |
