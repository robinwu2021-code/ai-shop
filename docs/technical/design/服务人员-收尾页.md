# 服务人员 · 收尾页

状态：页 · 2026-08-28 · 第二梯队 #10。档案/技能/排班已入基座（预约域规格 §2），本页收尾三件小事。

## 1. staff ↔ resource 同步（基座内）
`mch_resource(resource_type=STAFF, ref_no=staff_no)` 与 `mch_staff` 的一致性：
- 建技师 → **自动建同名 STAFF 资源**（Provision 钩子，幂等）；停用技师 → 资源置 SUSPENDED（未来时段随排班调整走 E2 流程）；
- 闸门：一致性校验 Job（有 staff 无资源 / 资源 ref 悬空 → 告警）。**不做双向编辑**：资源侧 STAFF 行只读。

## 2. RESOURCE 源 Modifier 选项同步（基座内）
`prd_modifier_group(source=RESOURCE:STAFF)` 的选项 = 该店在职技师×等级加价：
- 技师增/停/调级 → 事件驱动重算该店相关组的 `prd_modifier` 行（`ref_no=resource_no`，只读）；
- 等级加价表放**组配置**（按 level_code 定 delta），技师行由它展开 —— 商家改一处全店生效；
- 快照原则不变：已下单的 `ord_item_modifier` 不受重算影响。

## 3. 提成（美业包内，行业规则不上收）
基座给的事实：基数=行快照原价、归属=`ord_item_modifier.ref_no`、倒扣挂 `onRefunded`。
包内实现：`bty_commission_rule`（scope STORE/STAFF/GOODS/LEVEL，从具体到一般首中）+
`bty_commission_record(ACCRUED/REVERSED/PAID)`；发放动作留 B 端（`beauty:commission:settle`）。
**待 PRD 的三问**（沿既有清单）：换人后归属切换点、退款是否追已发放、指定技师加价是否计提成基数。
