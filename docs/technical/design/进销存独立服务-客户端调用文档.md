# 进销存独立服务 · `InventoryClient` 调用文档

> 适用：`inventory-client` 1.0.0-SNAPSHOT（提交 `862bf06d4` 起）。
> 接口语义以 [API 文档](进销存独立服务-API文档.md) 为准，设计见 [TDD](TDD-进销存独立服务与多业态.md) §2.23。
> 源码：`backend/inventory/inventory-client/src/main/java/ai/neargo/inventory/client/`
> - `InventoryClient`：门面；
> - `InventoryHostApi`：声明式接口，请求和响应的记录类型都定义在这里；
> - `InventoryReservationClient`：预留。

## 1. 一句话

一个 `InventoryClient` 对应一个库存服务地址和一把凭证。先选账本拿到 `Session`，再在 `Session` 上调用各类操作。

| 宿主 | 凭证 | 怎么拿 `Session` |
|---|---|---|
| 电商（ai-shop） | **系统凭证**（`SHOP`），一把管所有商家 | `client.owner(账本编号, 账本类型, 操作人)` |
| ShareHub 等单账本宿主 | **账本凭证**，绑定一本账 | `client.self(操作人)` |

## 2. 引入与创建

### 2.1 依赖

```xml
<dependency>
    <groupId>ai.neargo</groupId>
    <artifactId>inventory-client</artifactId>
    <version>${inventory.version}</version>
</dependency>
```

它依赖 `inventory-api`（错误码、`InventoryException`）和 `svc-client`（HTTP 代理与传输错误归类）。目前还没发布到 Nexus（评审 U13），仓库外的宿主暂时只能本地安装。

### 2.2 创建

```java
InventoryClient client = InventoryClient.create(
        () -> Optional.ofNullable(env.getProperty("shop.inventory.service.base-url")), // 每次调用时现取
        appKey, appSecret,                 // 凭证：Authorization: Bearer <appKey>:<appSecret>
        Duration.ofMillis(500),            // 连接超时
        Duration.ofMillis(2000),           // 读超时（同机 RTT 1~3 ms，2 秒没回就是服务出事了）
        5, Duration.ofSeconds(10),         // 熔断：连续 5 次传输失败后打开，10 秒后放一个试探
        "shop.inventory.service");         // 配置前缀：只用于报「哪个配置没填」
```

- **一个进程建一个，单例复用**。它线程安全，不持有会话状态。
- 地址每次调用时才去取：没配地址的报错发生在调用时，不会在启动时失败。
- 预留、宿主接口共用**同一个连接规格和同一个熔断器**。

ai-shop 的装配见 `InventoryReservationConfiguration`：配置了 `shop.inventory.service.base-url` 时才建它，`InventoryReservationClient` 这个 Bean 直接取自 `client.reservations()`。

### 2.3 测试 / 自定义传输

```java
InventoryClient client = InventoryClient.of(hostApiImpl,
        InventoryReservationClient.of(reservationApiImpl, new CircuitBreaker(5, Duration.ofSeconds(10), Clock.systemUTC())));
```

真实控制器上的写法（MockMvc 传输）见 `InventoryClientContractTest#client`。

## 3. 三条约定（先读）

### 3.1 账本

```java
InventoryClient.Session store = client.owner("S3001", "STORE", "STAFF:" + userNo);  // 系统凭证
InventoryClient.Session pb    = client.self("STAFF:E1");                           // 账本凭证
```

- `ownerRef`：账本在宿主里的编号，比如商家号、门店号、连锁号。
- `ownerType`：账本类型，比如 `ENTITY`、`STORE`、`CHAIN`、`PLATFORM`。**只在同一系统里同号有多本账时才需要**，否则可以传 `null`。同号多本却没给类型时，返回 `CONFLICT owner_type_required`。
- `actor`：操作人，写进审计，最长 64 个字符。约定写法：`STAFF:<工号>`、`AGENT:<商家号>`、`SYSTEM:<任务>`。
- `Session` 不可变，可以缓存，按「账本 + 操作人」复用即可。

### 3.2 命令键（幂等）

**所有写操作的第一个参数都是 `key`**，即调用方给的**稳定命令键**：

| 规则 | 说明 |
|---|---|
| 用业务单号拼动作 | 例如 `"issue-" + shipmentNo`、`"post-" + outboundNo`、`"rcv-" + inboundNo` |
| 不要用随机数 | 随机键让重发变成新命令，回包丢失时就会**重复记账** |
| 同键同参 | 返回第一次的结果，不重复执行 |
| 同键不同参 | 抛 `IDEMPOTENCY_CONFLICT`（409） |
| 作用域 | 按 `(系统, 账本, 键)` 唯一，不同账本可以用同一个键 |
| 保留期 | 至少 90 天（API 文档 §1.4），补偿窗口不要超过它 |
| 长度 | ≤ 64 个字符 |

结果不确定（超时、进程崩溃）时，二选一：

```java
// ① 用原键重发：已执行过的回放原结果
String no = pb.createOutbound("issue-" + shipmentNo, body);
// ② 只查不做
JsonNode cmd = pb.command("issue-" + shipmentNo);   // 查不到 = 没执行过（404）
```

### 3.3 错误

| 情况 | 抛出 | 处理 |
|---|---|---|
| 服务认得出的业务错误 | `InventoryException`，`error()` 是原码，`args()` 是原参数 | 在自己的边界翻成宿主错误码，例如商城把 `STOCK_SHORT` 翻成 `STOCK_SHORT_ITEMS` |
| 连不上、超时、5xx 无错误体、熔断打开中 | `InventoryException(UNAVAILABLE)`，`args()[0]` 为 `TIMEOUT` / `CONNECT` / `circuit_open` 等 | 当作「服务不可用」：下单路径拒单；后台任务稍后重试 |
| 服务回 5xx 但带错误码（如 `DEPENDENCY_UNAVAILABLE`） | 原码 | 算一次服务故障，计入熔断 |

客户端**不自动重试**，要不要重试由调用方决定，重试时用同一个命令键。常见错误码见 API 文档 §1.3。

### 3.4 标识

物料、库位都**直接给宿主编号**（`itemRef` = SKU 号或型号，`locationRef` = 门店号或仓号），不用维护「宿主编号 → 内部号」的对照表。请求里的 `itemId` / `locationId` 和 `itemRef` / `locationRef` 二选一，两个都给时以内部号为准。

## 4. 方法一览（`Session`）

记录类型都在 `InventoryHostApi` 里（下文省略前缀）。「宿主编号」列打勾表示可以不传内部号。

### 4.1 主数据

| 方法 | 作用 | 返回 |
|---|---|---|
| `upsertItem(key, itemRef, ItemSpec)` | 按宿主编号新增或更新物料。`ItemSpec(name, baseUom, trackingMode, gatePolicy, gateRefType, attributes)`，`trackingMode` 取 `QUANTITY`（缺省）或 `SERIAL` | 内部物料号 |
| `syncTarget(key, type, ref, TargetSync)` | 同步出库对象（商家、站点、人、门店……）。`TargetSync(name, parentRef, status, sourceVersion, linkedOwner, linkedLocationRef)` | 对象（`JsonNode`） |
| `targets(type, parentRef)` | 列出库对象 | `List<JsonNode>` |
| `warehouses(holderRef)` | 列仓库，可以按持有方过滤 | `List<Warehouse>` |
| `createWarehouse(key, WarehouseCreate)` | 建仓。`WarehouseCreate(name, externalRef, holderRef)`，**`externalRef` 填宿主仓号或门店号** | 内部库位号 |

`TargetSync` 要点：
- `sourceVersion`：宿主那条记录的单调版本号，旧版本到达时会被忽略。
- `status`：`ACTIVE` / `DISABLED`；停用不要删除。
- `parentRef`：站点要先同步上级商家。
- `linkedOwner` + `linkedLocationRef`：这个对象在本系统里也有账本（兄弟门店、加盟店）时才填。填了之后，发给它的出库就是一出一入。**每次同步都按整份状态处理，不填等于解除关联。**

### 4.2 入库

| 方法 | 作用 |
|---|---|
| `createInbound(key, InboundCreate)` | 建入库草稿，返回入库单号 |
| `postInbound(key, inboundNo)` | 过账（入在手） |
| `cancelInbound(key, inboundNo)` | 作废草稿 |
| `receive(key, inboundNo, Receive)` | **成对入库单**确认收货，返回 `Receipt(docNo, pairNo)` |
| `inbound(inboundNo)` | 详情（`JsonNode`） |

```java
InboundCreate(locationId, locationRef, purpose, sourceRef, basis, attachmentRefs, remark, List<InLine> lines)
InLine(itemId, itemRef, qty, gateRef, List<SerialIn> serials)       // 数量物料给 qty；SN 物料给 serials
SerialIn(serialNo, gateRef, parentSerialNo)                         // parentSerialNo：挂在哪个上级件下（柜内宝）
Receive(List<Received> lines); Received(itemId, itemRef, qty)       // 实收；没列出的物料算 0
```

- `purpose` 必须是档案登记过的入库用途，最长 32 个字符。
- 物料的放行策略为 `REF_REQUIRED` 时，过账前必须带放行凭证（`gateRef`）。
- 成对入库单不能 `postInbound` / `cancelInbound`（409 `paired_use_receive`），只能 `receive`。

### 4.3 出库

| 方法 | 作用 |
|---|---|
| `createOutbound(key, OutboundCreate)` | 建出库草稿，返回出库单号 |
| `appendOutbound(key, outboundNo, OutboundAppend)` | 草稿追加行或 SN（大批 SN 分批扫） |
| `postOutbound(key, outboundNo)` | 过账。交接方式为 `POOL` 时生成出库池记录；为 `RECEIPT` 时在对方账本生成待收单 |
| `cancelOutbound(key, outboundNo)` | 作废草稿（已过账的 `ISSUE` 不可作废） |
| `outbound(outboundNo)` | 详情 |

```java
OutboundCreate(locationId, locationRef, purpose, reasonCode, Map<String,String> targets, remark,
               List<OutLine> lines, List<String> serialNos)
OutLine(itemId, itemRef, qty, parentSerialNo)     // parentSerialNo：成套数量件随哪个上级件出
OutboundAppend(List<OutLine> lines, List<String> serialNos)
```

- `targets`：`{对象类型: 编号}`，必须满足档案里该用途的必填和选填对象，例如 ShareHub 的 `ISSUE` 要 `MERCHANT` + `PERSON`，`SITE` 可选。
- 扫一个上级件会带出它挂着的下级件（扫柜即带出柜内宝）。

### 4.4 账内调拨（同一本账换库位）

| 方法 | 作用 |
|---|---|
| `createTransfer(key, TransferCreate)` | 建调拨单，返回调拨单号 |
| `shipTransfer(key, transferNo)` | 发运：调出仓出、进在途 |
| `receiveTransfer(key, transferNo)` | 收货：在途出、进调入仓 |
| `cancelTransfer(key, transferNo)` | 作废（只限草稿） |
| `transfer(transferNo)` | 详情 |

```java
TransferCreate(fromLocationId, fromLocationRef, toLocationId, toLocationRef, List<QtyLine> lines,
               List<String> serialNos, remark)
QtyLine(itemId, itemRef, qty)
```

SN 随件走，放行凭证沿用原值，组装关系不拆。**跨账本不要用调拨**：发给关联了账本的出库对象（一出一入），见 §5.1。

### 4.5 成对单据、出库池

| 方法 | 作用 |
|---|---|
| `pairedTransfers(direction, status)` | `direction`：`OUT` 表示本账本发出的，`IN` 表示本账本收的；`status`：`SHIPPED` / `RECEIVED` / `null` |
| `dispatchPool(status, rootTargetRef, serialNo)` | 查出库池，`status` 例如 `List.of("AVAILABLE")` |
| `claim(key, dispatchIds, businessRef)` | 签收（领取）。批量操作全成或全败，返回 `Claim(claimNo, dispatchIds)` |
| `revoke(key, dispatchId, reason)` | 撤回待签收的记录，整套回仓；返回纠正入库单号 |

### 4.6 查询、事件、命令

| 方法 | 作用 | 返回 |
|---|---|---|
| `balances(itemRef, locationRef)` | 余额，两个参数都可以为 `null` | `List<Balance>`：`itemId/itemRef/locationId/locationRef/onHand/reserved/unavailable/available` |
| `serials(itemRef, locationRef)` | 在仓 SN | `List<Serial>`，含 `parentSerialNo`、`gateRef`、`holdReasons` |
| `inTransit()` | 「货在外面」 | `List<InTransit>`：`kind` 取 `POOL`（待签收）/ `PAIRED`（已发未收）/ `TRANSFER`（调拨在途） |
| `events(afterSeq, limit)` | 拉取本账本事件（至少一次，按序） | `{events:[{seq,type,resourceType,resourceId,…}], lastSeq, ackedSeq}` |
| `ackEvents(seq)` | 确认到某个序号 | — |
| `command(key)` | 按命令键查结果 | `JsonNode` |

### 4.7 客户端级

| 方法 | 作用 |
|---|---|
| `client.balancesAcross(List<OwnerKey>, Set<String> itemRefs)` | **系统凭证专用**：多账本批量余额，最多 50 本账、200 个物料。每本账单独判断，出错的那一项带 `error`（`NOT_FOUND` / `NOT_WRITER` / `owner_type_required`），不影响其他项 |
| `client.reservations()` | 预留客户端（电商下单），见 §5.1 |
| `client.breakerOpen()` | 熔断器是否打开中（用于健康检查和告警） |

## 5. 场景示例

### 5.1 电商（ai-shop）

```java
InventoryClient.Session hq   = client.owner("CH1001", "CHAIN", "STAFF:" + userNo);
InventoryClient.Session shop = client.owner("S3001",  "STORE", "STAFF:" + userNo);

// 门店要先作为出库对象同步给总部，并关联到它自己的账本
hq.syncTarget("target-S3001-v" + ver, "STORE", "S3001", new TargetSync("西湖店", null, "ACTIVE", ver,
        new OwnerRef("STORE", "S3001"), "S3001"));

// 总部给门店配货：一出一入（用途 STORE_OUT，交接方式 RECEIPT）
String out = hq.createOutbound("supply-" + supplyNo, new OutboundCreate(null, "HQ", "STORE_OUT", null,
        Map.of("STORE", "S3001"), null, List.of(new OutLine(null, "SKU-TEA", 4, null)), null));
hq.postOutbound("supply-" + supplyNo + "-post", out);

// 门店确认实收（物料用宿主编号，不需要知道自己账本里的内部号）
String pending = shop.pairedTransfers("IN", "SHIPPED").getFirst().get("to").get("docNo").asString();
shop.receive("rcv-" + pending, pending, new Receive(List.of(new Received(null, "SKU-TEA", 4))));

// 连锁看各店
client.balancesAcross(List.of(new OwnerKey("STORE", "S2001"), new OwnerKey("STORE", "S3001")), Set.of("SKU-TEA"));

// 下单预留（与上面共用连接和熔断）
client.reservations().reserve("S3001", "SYSTEM:order", new InventoryReservationApi.Reserve(orderNo,
        List.of(new InventoryReservationApi.Line(null, null, "SKU-TEA", "S3001", 1, null)), 900, null));
```

预留客户端的其他动作（`acceptUnpaid` / `allocatePaid` / `issue` / `cancel`，系统级的 `commitByRef` / `releaseByRef` / `issueByFulfillment` 等）见 `InventoryReservationClient`，语义见 API 文档 §6。

### 5.2 ShareHub（充电宝）

```java
InventoryClient.Session pb = client.self("STAFF:" + staffNo);

// 主数据：按需同步（ShareHub 侧变更后经 outbox 推送；建发货单前再兜底推一次）
pb.upsertItem("item-CAB", "CAB", new ItemSpec("柜", null, "SERIAL", "REF_REQUIRED", "QC", null));
pb.syncTarget("t-MERCHANT-AG001-v" + v, "MERCHANT", "AG001", new TargetSync("商家甲", null, "ACTIVE", v, null, null));

// 到仓入库（带质检单号作放行凭证；宝挂在柜下）
String in = pb.createInbound("in-" + qcNo, new InboundCreate(null, "WH-SZ", "PURCHASE", qcNo, null, null, null,
        List.of(new InLine(null, "CAB", null, null, List.of(new SerialIn("C1", qcNo, null))),
                new InLine(null, "PB",  null, null, List.of(new SerialIn("P1", qcNo, "C1"))))));
pb.postInbound("in-" + qcNo + "-post", in);

// 发货：扫柜即带出宝，进出库池待签收
String no = pb.createOutbound("issue-" + shipmentNo, new OutboundCreate(null, "WH-SZ", "ISSUE", null,
        Map.of("MERCHANT", "AG001", "SITE", "ST01", "PERSON", "E1001"), null, List.of(), List.of("C1")));
pb.postOutbound("issue-" + shipmentNo + "-post", no);

// 签收、撤回
String dispatchId = pb.dispatchPool(List.of("AVAILABLE"), null, "C1").getFirst().get("dispatchId").asString();
pb.claim("sign-" + signNo, List.of(dispatchId), signNo);

// 仓间调拨 / 坏件转次品仓
String trf = pb.createTransfer("trf-" + moveNo, new TransferCreate(null, "WH-SZ", null, "WH-BAD", List.of(), List.of("C2"), null));
pb.shipTransfer("trf-" + moveNo + "-ship", trf);
pb.receiveTransfer("trf-" + moveNo + "-receive", trf);

// 事件：每分钟拉一次，处理完确认
JsonNode page = pb.events(lastAcked, 100);
// … 投影 DispatchRedirected / DispatchRevoked / TransferReceived …
pb.ackEvents(page.get("lastSeq").asLong());
```

## 6. 恢复与对账（推荐写法）

**宿主写入**（ShareHub 对接方案 G1）的推荐顺序：

1. 本地事务里先落「命令」：命令键、请求体、状态 `PENDING`。
2. 事务提交后调用客户端，带这个命令键。
3. 成功：把命令标成 `DONE`，记下返回的单号。
4. 遇到 `UNAVAILABLE` 或超时：保持 `PENDING`，由补偿任务用**同一个键**重发，或调 `command(key)` 查结果。
5. 业务错误（4xx）：标成 `FAILED`，交给人处理；不要换新键重发。

**事件**：至少送达一次。按 `seq` 处理并去重，处理完再 `ackEvents`。游标过期时抛 `EVENTS_CURSOR_EXPIRED`（410），这时要全量对账，比如对比 `balances` 和 `serials`。

## 7. 常见问题

| 问题 | 回答 |
|---|---|
| `NOT_WRITER`（409） | 这本账的写入方还不是独立服务，比如商城过渡期还由内嵌在写。这时由宿主自己的内嵌路径处理 |
| `owner_type_required` | 同号有多本账（门店号与连锁号撞了），`owner(...)` 时给上类型 |
| `NOT_FOUND itemRef:xxx` | 物料还没同步，先 `upsertItem` |
| `BAD_REQUEST target.not_linked` | 发往门店的一出一入用途，对象没带 `linkedOwner`；重新 `syncTarget` 带上关联 |
| `CAPABILITY_DISABLED` | 账本档案没开这个能力包（如 `SERIAL`、`DISPATCH_POOL`、`RESERVATION`），找平台运维装档案 |
| 熔断打开（`UNAVAILABLE circuit_open`） | 连续传输失败后的保护，到时间后会自动放一个试探请求。下单路径直接拒单 |
| 要不要每次 `owner(...)` 新建 `Session` | 可以；它只是三个字符串的组合，开销可以忽略 |
| 怎么本地联调 | 本机服务 `http://127.0.0.1:8086`；系统凭证由运维接口 `POST /api/inventory/admin/v1/systems/{code}/credentials` 签发 |
