# 连锁 · 品牌 · 主体 · 发行方 梳理

> 2026-11-28 草案，待用户拍板（§6）。用户口径：一开始没有「连锁」概念，用**品牌**代替了，所以**现在的品牌就是连锁**；
> 连锁可以发积分、活动、储值等，是这些权益的**发行方**。
> 改名策略沿用 [组织抽象-技术方案与缺口](组织抽象-技术方案与缺口.md)：业务叫「连锁」，领域层叫「组 GROUP（kind = CHAIN）」，库表与接口里的 `BRAND` 编码冻结不改。
> 相关：[商品与库存-单店与连锁方案](商品与库存-单店与连锁方案.md)、[ADR-011 经营主体与门店边界](../adr/ADR-011-经营主体与门店边界.md)、
> [ADR-030](../adr/ADR-030-商品归属改为门店Offer与品牌库.md)、[ADR-门店储值账户隔离](../adr/ADR-门店储值账户隔离.md)、旧迁移 V544 / V548–V576 / V651–V652。

## 0 结论先行

```
商户集团（老板 / 总部的管理空间）  mch_group（旧 mch_management_space）
 ├── 经营主体 mch_entity（营业执照，收钱、结算、开票的那个法人）── 名下若干门店
 └── 连锁（= 品牌）mch_brand
       ├── 总部 = 连锁的签约主体 legal_entity_no（一个经营主体）
       └── 成员门店 mch_brand_store_binding（有时效；一店同时只属一个连锁）
             门店的主体 = 总部主体 → 直营；≠ 总部主体 → 加盟
```

| 概念 | 一句话 | 落表 | 管什么 | 不管什么 |
|---|---|---|---|---|
| 商户集团 | 一个老板名下的管理空间 | `mch_group` | 授权的根：给人授权管哪些主体、连锁、门店 | 钱 |
| 经营主体 | 营业执照 | `mch_entity` | 收款、结算、开票、分账（ADR-011） | 运营范围 |
| 门店 | 实际经营的地点 | `mch_store`（挂一个主体） | 商品、库存、订单、服务 | — |
| **连锁（品牌）** | 一组门店在运营上算一家 | `mch_brand` + 门店绑定 | 统一商品（下发）、统一营销、共享会员、统一权益 | 钱不在连锁上，经总部 / 结算指定落到主体 |
| **总部** | 代表连锁签约、出钱收钱的主体 | `mch_brand.legal_entity_no` | 连锁权益的默认结算主体；下发商品的发起方 | — |
| **发行方** | 某项预付性权益的负债归谁 | 按权益不同（§2） | 发了谁兑、出了钱谁扛、跨主体谁欠谁 | 运营范围（那是连锁） |

**原则**：运营归连锁，钱归主体；连锁只通过「发行方的结算主体」碰钱，任何地方都不从连锁直接推出主体（与组织抽象 §1.1 一致）。

## 1 现状

### 1.1 已有的表与代码

| 概念 | 旧库（代码在用） | 定稿 | 代码 |

| 商户集团 | `mch_management_space`、`mch_management_grant`（V544） | 改名 `mch_group`、`mch_grant` | 有（`shop-merchant/.../brand`） |
| 连锁 | `mch_brand`（V544；V573 加 `stored_value_status`；V651 加 `legal_entity_no`） | 同名 | 有 |
| 门店入退连锁 | `mch_brand_store_binding`、`mch_brand_change`（V544） | 绑定同名；变更单并入审核工单 | 有（`BrandServiceImpl`） |

| 品牌储值开通 | `mch_brand_financial_activation` / `_change`（V573、V576） | 并入审核工单 | 有 |

数据量（正式库清单）：集团 3 行、授权 93 行、连锁变更 2 行；品牌储值开通、品牌营销、跨主体清分都是 0 行。

### 1.2 各类权益现在由谁发行

| 权益 | 发行方能是谁 | 怎么记 | 钱怎么走 |
|---|---|---|---|
| 储值 | 门店 / 连锁（`sv_issuer.scope_type` = STORE / BRAND） | `sv_issuer` + 版本里的 `settlement_entity_no`、收款方式（集中 / 门店各收） | 结算主体收款兑付；跨主体核销记 `sv_clearing_entry`，出跨主体账单 |
| 营销活动 | 商家 / 平台 / 连锁（`pmt_activity.owner` = MERCHANT / PLATFORM，代码另写 BRAND） | 连锁活动的归属在 `pmt_brand_activity_owner`（定稿并入 `pmt_activity`） | 优惠是商家让利；连锁活动按 `pmt_brand_cost_rule` 在总部与门店主体间分摊 |
| 券 / 权益 | 主体；连锁券取总部主体 | `pmt_coupon.entity_no` + `funder`；连锁券源 `pmt_brand_coupon_source`（定稿并入 `ent_template` 的 `brand_no`） | 同活动，按成本规则分摊 |
| 积分 | **只有平台** | 积分类型按市场，没有商家归属；主体只有「开 / 强制开」开关 | 平台出资预存池（ADR-036，待确认） |
| 会员 | 主体 / 连锁 / 门店（定稿 `mbr_member.scope_type`） | — | — |

### 1.3 问题

1. **「总部」有三种写法**：`mch_brand.legal_entity_no`（已实现）、ADR-030 的 `hq_entity_no`（未实现）、`mch_hq_release.entity_no`（只在定稿）。
2. **结算主体没有单一来源**：储值发行方版本、连锁活动归属、成本规则、连锁券各记一个主体，互不校验。
3. **「发行方」含义不一**：储值是独立的发行方号；成本规则里是一个主体；积分里是平台账户桶；券和活动没有发行方，只有「主体 + 出资方」。
4. **范围取值各表不同**：BRAND / STORE、SPACE / BRAND_STORES / STORE、ENTITY / BRAND / STORE、MERCHANT / PLATFORM / BRAND……
5. **`management_no` 一词两义**：在集团表是「集团号」，在会员营销库几张表的注释里写成「品牌管理关系号」。
6. **两套储值账户身份并存**：V532 按门店隔离（ADR 写「连锁共用搁置」），V548 起又按发行方实现了连锁储值。
7. **连锁没有自己的积分**。
8. **主体与集团没有直接关联**：定稿加了列，代码与迁移都没有。
9. **定稿把连锁变更单、储值开通并入审核工单**，现行代码强依赖原表。

## 2 统一后的模型

### 2.1 连锁（= 品牌）

- 业务叫「连锁」；代码领域层叫 GROUP（kind = CHAIN）；库表、接口、权限码里的 `brand` 不改（组织抽象 §2）。
- 成员是**门店**，不是主体。门店的主体从门店推出，所以连锁天然可以跨主体（加盟）。
- **直营 / 加盟不加字段**：门店的主体等于总部主体就是直营，否则是加盟。
- 一家店同时只属一个连锁（现有唯一约束）。区域、片区以后作为别的 kind，不在本期。

### 2.2 总部

- **只有一个来源：`mch_brand.legal_entity_no`**。ADR-030 的 `hq_entity_no` 作废；`mch_hq_release` 改记连锁号，发起主体从连锁取，不再单独存（要改表，§5）。
- 总部是一个经营主体，所以总部自己也可以有门店（直营店）。

### 2.3 发行方

**发行方 = 「以谁的名义发、负债归谁」**，用同一组字段描述：

| 字段 | 含义 |
|---|---|
| 范围 | STORE（门店） / CHAIN（连锁，存储编码 `BRAND`） / PLATFORM（平台） |
| 范围编号 | 门店号 / 连锁号 / 空 |
| 结算主体 | 收钱、兑付、承担的那个主体；连锁默认 = 总部主体，可以另行指定（组织抽象 G3「结算指定」） |
| 成本分摊 | 跨主体兑付时，发行方与兑付门店主体各承担多少（现有 `pmt_brand_cost_rule` 的「总部比例 + 门店比例」） |

各权益对上这一组字段：

| 权益 | 发行方范围 | 结算主体 | 跨主体兑付 |
|---|---|---|---|
| 储值 | 门店 / 连锁（`sv_issuer` 已有） | 发行方版本里的结算主体 | 清分事实 + 跨主体账单（已有） |
| 营销活动 | 门店（主体） / 连锁 / 平台 | 连锁活动 = 结算指定的主体 | 成本规则分摊（已有） |
| 券 | 门店（主体） / 连锁 / 平台 | 同上 | 同上 |
| 积分 | 平台（现有）；**连锁积分待定（§6 ③）** | 平台；连锁积分则为结算主体 | 连锁积分跨主体使用时同储值清分 |

### 2.4 主体

- 主体只管钱：收款、结算、开票、分账（ADR-011 不变）。
- 主体属于集团：用定稿的 `mch_entity.management_no` 直接记，取代「所有人账号推出」；迁移时按现有推法回填。
- 门店换主体仍只限「占位主体认领」（ADR-055）。

### 2.5 门店在连锁里拿到什么

| 能力 | 来自 |
|---|---|
| 商品 | 总部下发、门店套用成本店商品（[商品与库存方案](商品与库存-单店与连锁方案.md) §5） |
| 价格 | 总部下发；门店能否改看总部设定 |
| 库存 | 门店自己的（不共享）；仓与调拨走库存库 |
| 会员 | 连锁范围的会员（`mbr_member.scope_type` = 连锁） |
| 储值、券、活动、积分 | 连锁作为发行方发的，在成员门店可用；跨主体按清分 / 成本规则结算 |
| 报表 | 连锁范围的跨店报表 |

## 3 与现有代码的对应

| 统一模型 | 现有代码 / 表 | 动作 |
|---|---|---|
| 连锁 | `mch_brand*`、`BrandService` | 不改名；领域层逐步收敛到 GROUP（组织抽象 §2） |
| 总部 | `mch_brand.legal_entity_no` | 作为唯一来源；`mch_hq_release` 改挂连锁 |
| 发行方（储值） | `sv_issuer`、`IssuerAuthorityService` | 保留 |
| 发行方（活动、券） | `pmt_activity.owner`、`ent_template.brand_no`、成本规则 | 补「发行方范围」统一取值；结算主体走结算指定 |
| 结算指定 | 散在四处 | 组织抽象 G3：收成一处 |
| 范围取值 | 各表各一套 | 领域层统一 `ScopeType { STORE, ENTITY, GROUP, PLATFORM }`，存储编码经 `ScopeCodes` 翻译 |
| 储值账户 | 门店隔离（V532）与发行方（V548）两套 | 统一到发行方：门店储值 = 范围为门店的发行方（§6 ②） |

## 6 要用户拍板的

1. **总部的唯一来源**：用 `mch_brand.legal_entity_no`（推荐，已实现），作废 ADR-030 的 `hq_entity_no`，`mch_hq_release` 改挂连锁？
2. **储值账户两套身份**：统一到「发行方」，门店储值就是范围为门店的发行方（推荐）；还是保留按门店隔离那套？
3. **连锁积分**：连锁要不要发自己的积分？要的话积分加发行方（连锁），跨主体使用按储值那样清分；不要就维持平台积分。
4. **直营 / 加盟**：不加字段，按「门店主体是否等于总部主体」推出（推荐）；还是在绑定上显式记？
5. **连锁变更单与储值开通**：定稿并入审核工单，代码要跟着改；还是保留原表？
