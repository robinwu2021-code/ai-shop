# TDD-定位能力受限下的位置模型

状态：**草稿（待确认）** · 2026-09-03
关联：[TDD-定位与未开通区域](./TDD-定位与未开通区域.md) · [小程序账号与切换](./小程序账号与切换.md)

---

## 1. 为什么要重排

不是产品想换，是**平台把设计空间划走了一块**。

2026-09-03 微信驳回 `wx.getLocation`，理由是开放范围不含
「获取定位以**匹配附近服务**」与「辅助填写**收货地址**」——
而那两句正是这一页在做的事。**驳的是规则不是措辞**，改写理由重提不解决。

于是「打开小程序 → 自动知道你在哪 → 给你附近的自提点」这条路，
在微信里**不成立**。现有设计整个挂在它上面。

---

## 2. 能力现状（决定一切的那张表）

| 能力 | 状态 | 给什么 | 要用户操作 |
|---|---|---|---|
| `wx.chooseAddress` | ✅ 已开通 | 姓名 / 手机 / 省市区 / 详细地址 · **无坐标** | 点一下，从微信地址簿选 |
| `wx.chooseLocation` | ✅ 已开通 | **精确坐标** + POI 名 + 地址 | 点一下，地图上确认 |
| `wx.openLocation` | ✅ 无需申请 | 唤起导航 | 点一下 |
| `wx.getLocation` | ⏳ 可重新申请 | 静默精确坐标 | 无 |
| `wx.getFuzzyLocation` | ⏳ 待申请 | 静默 **区级** 坐标 | 无 |

`getLocation` 值得再提一次：开放范围里写着
「**针对自营**，提供售卖商品线下发货、**线下收货服务**、线下商超导览、**导航服务**」——
我们四个类目都是商家自营，自提点取货就是线下收货服务，且端上真有导航。
但**它可能再次被驳，所以不能把设计押在它身上**。

---

## 3. 由此推出的三条原则

### 3.1 首屏不许依赖静默精确定位

它可能永远拿不到。首屏必须在**零位置信息**下也是有用的。

### 3.2 精确位置由用户一次点击给出，而这一下要放在有回报的地方

`chooseLocation` 要用户开地图、确认。让他做这一下的时机，
应该是他**正想要一个结果**的时候（「找离我最近的自提点」「填收货地址」），
而不是刚打开小程序、还不知道这里有什么的时候。

> 反例就是现在：新用户第一屏被推到「选择社区自提点」，
> 而他还不知道这个小程序卖什么。

### 3.3 位置有三档精度，界面要**说出**自己在哪一档

| 档 | 来源 | 能干什么 | **不能**干什么 |
|---|---|---|---|
| 无 | — | 按区域手选 | — |
| 区级 | `getFuzzyLocation` | 定位到「你在西湖区」，给该区的清单 | **排不出五公里内谁更近** |
| 精确 | `chooseLocation` / `getLocation` | 按距离排序、算配送范围、导航 | — |

代码里已经把这一档写进了类型（`LocationOutcome.fuzzy`）——
不标出来的话，下一个人会拿区级坐标去排序，**而那个排序看起来完全正常，只是结果是错的**。

## 4. 新的用户旅程

```
打开小程序
   │
   ├─ 有归属？ ──是──► 首页（照旧）
   │
   └─ 否 ──► **留在首页**，顶栏显示「选择取货点 ›」
              首页展示平台推荐 + 该区（若拿到区级定位）在售
                 │
                 └─ 他点「选择取货点」时才进选择页：
                      ① 📍 在地图上选择我的位置  → 精确 → 按距离排序   ← 已可用
                      ② 按区域选                → 无位置也能走完
```

**改动的核心是把「选自提点」从第一屏挪到「他自己要」的那一刻。**
现有实现已经有 `probeNearby()` 决定要不要推，方向是对的，
但推的前提（能静默定位）不再成立 —— 所以改成**不推**。

### 4.1 收货地址

```
新增地址
  ├─ 「微信地址」→ chooseAddress → 填掉姓名/手机/省市区/详细   ← 已可用
  └─ 「地图选点」→ chooseLocation → 补坐标（配送范围、骑手导航要用） ← 已可用
```
两者是**配合不是替代**：`chooseAddress` 不返回坐标。这条已写进端口注释。

## 5. 与「按地址筛选商品」的关系

用户提过：希望按**收货/居住地址**筛选门店与商品，而不是先选自提点。
在上面的模型里这是自然的下一步 —— 但它动的是主轴（现在商品池挂在
`communityNo` 上），**要单独一份方案**，且有三个决定必须先定：

1. 自提点还留不留（(a) 由地址自动推 / (b) 砍掉这条履约线）
2. 地址是单选还是多选（商品池跟哪一个？切地址就换池？）
3. 没填地址的新用户看到什么

本方案**不替这三条做决定**，只把位置能力这一层铺好 ——
它们在任何一种选择下都要用。

## 7. 一条操作纪律

**没获批的接口不许写进 `requiredPrivateInfos`。**
2026-09-03 把尚未申请的 `getFuzzyLocation` 写进去，整个小程序在启动阶段卡死 ——
不是报错，是**没有任何响应**：automator 连得上、`currentPage` 永远不返回，
重启工具、重开项目都一样，查了四轮才落到那一行。

声明与获批必须同时成立：获批不声明 → 真机上调不通（模拟器不拦）；
声明没获批 → 整个小程序起不来。**顺序只能是先批后加。**
