## 0. 先说这套测试**不测什么**

仓库里已经有 107 个后端场景测试和 41 条前端守卫。**它们覆盖过的东西这里一律不重复** ——
重复测的代价不是浪费时间，是**让人以为红了就是新问题**，而实际是同一条规则在两处各响一次。

| 已有覆盖 | 谁管 |
| --- | --- |
| 六角色 × 13 权限码的判权矩阵 | `BizPermsTest` / `BizEndpointPermTest` |
| 页面门禁 ⊇ 该页调用所需的码 | `biz-page-perm.test.ts` |
| 契约字段与后端 VO 逐字段对齐 | `biz-contract-fields.test.ts` |
| 角色种子（库 vs 代码） | `biz-role-seed.test.ts` |
| 401/403 的统一处理 | `unauthorized-handling.test.ts` |
| 订单状态机、售后状态流转、结算金额 | `M1UserFlowTest` / `M7SettleFlowTest` 等 |

**判据：这条如果在 vitest 或 MockMvc 里测得出来，就不该出现在下面。**
下面测的是「**装到设备上、连着真后端、由一个人从头点到尾**才会暴露」的那一类：
跨页面的状态同步、多步骤流程中断后的恢复、真实数据下的边界值、以及壳本身的行为。

## 1. 环境

| 件 | 值 |
| --- | --- |
| 模拟器 | AVD `hxmall_b`（Pixel 6 · Android 14 · arm64） |
| 包 | `ai.neargo.shop.b`（merchant flavor · debug） |
| 页面来源 | `http://localhost:5174`（dev server），**不是 assets 里的离线产物** |
| 后端 | 8083（`SHOP_OTP_FIXED=123456`） |
| 端口映射 | `adb reverse tcp:5174 tcp:5174` · `adb reverse tcp:8081 tcp:8083` |

> **debug 包为什么必须走 dev server**：`file://` 的 origin 是 `null`，后端 CORS 不认，
> **每个请求都被浏览器拦在发出之前**。表现不是报错，是各页渲染成空状态 ——
> 第一次装上去看到的那屏「还没有开店」就是这么来的（详见 `MainActivity.ENTRY_RES`）。
> 真机上的 uni-app 原生包不吃这一套（原生请求没有 CORS），这是**壳特有的**限制。

## 附 · 角色边界（穿插在上面各模块里跑，不单列）

只测「**界面上看不看得见**」——判权本身已有测试：

| 角色 | 应当 denied 的页 | 应当可用的页 |
| --- | --- | --- |
| CLERK | 结算、员工、营销、评价、客户 | 订单、商品列表、核销、分拣、配送 |
| CS | 商品、结算、员工、营销 | 评价、售后、订单 |
| PICKER | 订单详情、结算、员工 | 分拣、商品列表（改库存） |
| COURIER | 商品、结算、员工、核销 | 配送、订单 |

**denied 的表现必须是门禁态**，不是空白页、不是报错弹窗。越权请求直接打后端时，
70006 的消息里要带**缺的那个权限名**（今天刚改的）。

## 执行与记录

adb 驱动（`input tap/text`），`exec-out screencap` 取证，`logcat -s ShellConsole` 抓页面异常。
**判据用库里的数据或页面文本核对**，不靠肉眼看截图。

失败分三类记，**混在一起会让下一个人去改一段没有问题的代码**：

- **产品缺陷** → 记 issue，修；
- **壳的限制**（M3.10 / M6.4 / M13.5）→ 预期失败，不修，等原生包；
- **测试环境问题**（端口、CORS、数据）→ 修环境，不记缺陷。
