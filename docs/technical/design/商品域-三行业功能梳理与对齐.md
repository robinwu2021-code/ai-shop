## 0. 为什么要重做一次梳理

上一版的"分别梳理"里，餐饮和美业那两栏直接写着 `≈ R18`、`≈ R20` ——
**梳理阶段就已经在对照了**。那等于把需求裁剪成「能塞进零售现有模型的那部分」，
而这正是我自己在方案里写过要避免的事。

本册的规矩：**§一~§三 三份独立梳理，各用各的行话，一个跨行业对照都不出现。**
对齐只发生在 §四。

结果值得记一笔：**分开梳理多捞出 6 条上一版被对照裁掉的需求**（§四.4）。

| 资源类型与数量 | — | 包间 | B-09 / B-10 |

## 4.2 部分同构 → 合并但要带参数

| 概念 | 差异 | 处理 |
|---|---|---|
| 选配项 | 餐饮要"必选且不加价"（甜度），零售的加项都是可选且加价 | 一个模型带 `required` / `min_pick` / `max_pick` / 加价可为 0 |
| 组合商品 | 餐饮的可选套餐要"三选一"，美业疗程是"同一项目 ×10" | `bundle` 带"可选组"与"次数"两种形态 |
| 陈列分组 | 餐饮一道菜常属多个分类；零售通常一个 | 多对多，零售也用得上 |

## 4.3 不同构 → 不合并

| 需求 | 为什么 | 去向 |
|---|---|---|
| 上菜顺序 / 叫起（F-25） | 驱动**出品队列调度**；零售的发货优先级驱动**拣货波次**，下游完全不同 | 留门店选品的一列，**标注待观察** |
| 技师技能（B-11） | 是**员工能力**，不是商品属性 | `mch_staff_skill` |
| 派单规则（B-13） | 是**预约/排班规则** | 预约域 |
| 提前预约期 / 最晚可约（B-22 / B-23） | 是**预约规则** | 门店配置 |
| 次卡 / 储值可用范围（B-16 / B-17） | 是**会员资产**的适用范围，反向挂在卡上 | 会员域 |
| 疗程跨店通兑（B-28） | 是**门店覆盖 + 跨主体结算** | 单独议题 |
| 菜品成本卡 / 耗材成本 | 是**进销存** | `shop-inventory` |

## 4.4 分开梳理多捞出来的六条

这六条在上一版"带着对照做梳理"时被裁掉了，**都是三行业共有的真需求**：

| # | 需求 | 谁提出来的 | 为什么上一版漏了 |
|---|---|---|---|
| 1 | **会员价 / 首单价** | 三家都有（R-15 / F-19 / B-18） | 零售侧现状是 ❌，对照时没有可挂靠的行 |
| 2 | **每日定价**（时价菜 / 生鲜时价） | 餐饮 F-22、零售 R-16 | 被当成"餐饮特有" |
| 3 | **必选选配项**（奶茶不选甜度不让下单） | 餐饮 F-14 | 上一版的选配项模型只考虑了"加不加价" |
| 4 | **多资源同时占**（双人服务两个技师两张床） | 美业 B-10 | 上一版只有 `resource_type`，没有数量 |
| 5 | **连锁总部统一管控**（改价 / 停售下发） | 三家都有 | 被当成"组织能力"，但下发对象是商品 |
| 6 | **服务禁忌与注意事项**（过敏提醒） | 美业 B-06 | 被归进"详情富文本"，但它要在**服务前**弹出，不是详情页的一段 |

**这就是先分开梳理的价值**：带着对照梳理，只会捞到"现有模型装得下的需求"。

## 4.5 对齐后的模型增量

在[对齐清单](../reference/商品域-多行业对齐清单.md)已有的十二项之外，本轮再加五项：

| 概念 | 英文名 | 落点 | 说明 |
|---|---|---|---|
| 会员价 | Member Price | `prd_store_price` 加 `price_type` 维度 | 与渠道价同一张表、同一手法 |
| 每日定价 | Daily Price | `prd_store_price` + 生效日 | 时价菜与生鲜时价同一件事 |
| 选配项必选规则 | Modifier Constraint | `prd_modifier_group.required/min_pick/max_pick` | 已在模型里，本轮补 `required` 的语义说明 |
| 资源占用数量 | Required Resource Count | `prd_goods.resource_count` | 与 `resource_type` 成对，双人服务用 |
| 服务禁忌 | Service Caution | `prd_goods.caution` | **服务前弹出**，不是详情页的一段 |

第六条「连锁统一管控」**不进商品域** —— 它是"总部对门店的下发"，
对象可以是商品、价格、菜单，属于**组织与治理**，另立议题。
