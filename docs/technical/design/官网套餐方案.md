# 官网套餐方案

真源：`site/lib/plans.ts`（`PLANS` 三档 + `ENTITLEMENTS` 九行 + `LIFECYCLE` 六条）。
展示位：`/pricing/`「两部分费用」表、`/scenarios/chain/`「门店额度」表。

本文提出优化方案，**改动要落到 `plans.ts` 与 `sys_merchant_plan_def` 种子两处**，
只改官网 md 是不够的 —— 额度值由 token 从真源取。

## 二、四个问题

### 1. 自有品牌小程序没进档位表

商家在比价页看不到它，要点进另一页才知道有这回事。**比价页是他做决定的地方** ——
一个能明显拉开档位差距的东西不出现在这里，等于没有。

### 2. 免费版 0 子账号，跨度太大

夫妻店、父子店是社区门店的常态。现在的结构里，**老板想给老婆一个账号，就得从 1 家门店
直接跳到 3 家门店的档**——他只多要一个人，却被要求为两家用不上的门店付钱。

这是转化漏斗上最容易漏人的一处：**他不是不愿意付费，是没有一个匹配他的档。**

### 3. 旗舰版之上没有出口

超过 10 家门店只在 FAQ 里写了一句「联系我们，可单独授予档位」。
比价页上没有可点的位置，大连锁看到 10 家封顶会直接判定「这平台不做我们这种规模」。

### 4. 三项 `规划中` 混在表里

数据留存、对账导出、专属客服都还没上线。角标在页面上有，**但在销售转述时最容易掉**。

## 三、建议方案：四档 + 一行小程序

| | 免费版 | 专业版 | 旗舰版 | 定制版 |
|---|---|---|---|---|
| **适合** | 单店，老板本人打理 | 单店有帮手，或开到第二三家 | 多店多人，看数据做决策 | 连锁、区域代理 |
| **门店数** | 1 家 | 3 家 | 10 家 | 按需授权 |
| **子账号数** | **1 个** | 3 个 | 15 个 | 按需 |
| **跨店总览与对比** | — | ✓ | ✓ | ✓ |
| **自有品牌小程序** `对接中` | — | 可加购 | **含 1 个** | 含，可多个 |
| **数据留存** `规划中` | 90 天 | 1 年 | 3 年 | 按需 |
| **对账与客户导出** `规划中` | — | ✓ | ✓ | ✓ |
| **专属客服通道** `规划中` | — | — | ✓ | ✓ |
| **免费试用** | — | 14 天 | 14 天 | 面谈 |
| **单店经营全套** | ✓ | ✓ | ✓ | ✓ |
| **交易费率** | 同一套 | 同一套 | 同一套 | 同一套 |
| **价格** | 长期免费 | 联系报价 | 联系报价 | 联系报价 |

### 四处改动与理由

**① 免费版给 1 个子账号**（新增）

覆盖夫妻店。代价是免费版更好用了，但换来的是**免费用户能把店员拉进来** ——
店员用得顺手，老板开第二家店时不会考虑换平台。这一个账号是留存投入，不是让利。

> 需要改 `plans.ts` 的 `staffQuota: 0 → 1`，以及 `sys_merchant_plan_def` 种子。

**② 自有品牌小程序进表，作为一行**（新增）

三种取值：免费版无 / 专业版可加购 / 旗舰版含 1 个。

**旗舰版含 1 个是这套结构的关键**——它把「加购项」变成「升档理由」。
一个已经开到 10 家店的连锁，本来就该有自己的招牌；把小程序含进旗舰版，
升档的动机从「多几家店的额度」变成「拿到自己的品牌入口」，后者贵得多也值得多。

> **这是商务决策，需要你拍板**：小程序的成本（认证、域名、备案、代办人力）
> 是否愿意包进旗舰版年费里。

**③ 新增定制版**（新增）

不写具体额度，写「按需授权」，价格「联系报价」。
作用是给大连锁一个可点的位置，**而不是让他在 10 家封顶处掉头**。

后端已经支持——现在就是「单独给这个商户授档位并覆盖额度」的做法，
只是没有在官网上给它一个名字。

**④ 三项 `规划中` 单独成组**

在表格里下沉到最后三行，并在表下方加一句：
「标注规划中的三项尚未上线，不计入当前承诺。」

> 或者更干脆：**定价拍板时决定这三项算不算首批权益。算就先做，不算就从表里拿掉。**
> 靠一个角标兜着，是在赌销售不会漏说。

## 四、档位名要收口

| 位置 | 现在 |
|---|---|
| 官网 `plans.ts` | 免费版 / 专业版 / 旗舰版 |
| 库里 `sys_merchant_plan_def.name` | 孵化版 / 成长版 / 连锁版 |

两套叫法，商家在官网看到「专业版」，进商家端看到「成长版」。
**需要一条 UPDATE 迁移把库里改成官网的叫法**——反过来改官网不行，
「孵化版」「连锁版」是内部视角的词。

新增的定制版要一并进种子。

上一轮已经因为手抄导致过分叉。

## 六、需要拍板的三件事

| # | 决策 | 影响 |
|---|---|---|
| 1 | 免费版是否给 1 个子账号 | 改 `plans.ts` + 库种子；影响免费版的留存与升档动机 |
| 2 | 旗舰版是否含 1 个自有品牌小程序 | 决定「加购项」还是「升档理由」；影响旗舰版定价 |
| 3 | 三项 `规划中` 是否算首批权益 | 算则要先做，不算则从表里删 |

三档的**具体价格**仍未定，是所有事情的前置——见
[产品规划-下一阶段.md](产品规划-下一阶段.md) §B。
