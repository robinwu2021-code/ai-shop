# 商品与库存 · 单店、多店与连锁方案

> 2026-11-28 草案。用户口径：
> - 单店是默认情况，**先实现**；
> - 没有建连锁的多店**就是多店**；
> - 连锁看门店上的标记，连锁表在旧库与代码里已有；
> - **连锁商品由总部下发、门店套用**，这是连锁存在的意义。
>
> 依据：[ADR-030 商品归属改为门店 Offer](../adr/ADR-030-商品归属改为门店Offer与品牌库.md)、[ADR-011 经营主体与门店边界](../adr/ADR-011-经营主体与门店边界.md)、
> 旧迁移 `V544__brand_management_organization.sql`（连锁表）、定稿 `01-n_platform.sql`（集团、品牌、总部下发）、
> `05-n_trade.sql`（商品与门店目录）、`08-n_inventory.sql`（库存库）、[进销存需求](../../requirements/进销存-需求.md)。

## 0 结论先行

| | 单店（默认，先做） | 多店（没有建连锁） | 连锁门店 |
|---|---|---|---|
| 怎么认 | 主体只有一家店 | 主体有多家店，门店都没有连锁标记 | 门店有连锁标记：生效中的品牌绑定（§2） |
| 商品归谁 | 本店 | 建在哪家店就归哪家店 | 本店；内容来自总部下发，记着来源 |
| 商品从哪来 | 本店自建 | 本店自建；同主体的其他店可以跟着卖（设本店价与库存） | **总部下发，门店套用**；也可本店自建 |
| 价格 | `prd_sku.price` 一个价 | 默认价 + 各店门店价（`prd_store_sku.price`） | 总部随商品或单独下发价格；门店能否改看总部设定 |
| 库存 | 本店一行 `prd_store_sku` | 每家卖它的店各一行 | 每家店各一行；仓与调拨走库存库 |
| 主体库存池 `store_no=''` | 不用；旧数据并进本店行 | 待定（§6 ②） | 不用 |

三种情况的共同底座：**库存永远按门店记一行**（锁本店、扣本店），订单与结算按主体（ADR-011）。
单店是多店只有一家店的特例；连锁在门店之上多了「总部下发」与跨店查看。

## 1 现状

### 1.1 连锁表（旧库与代码已有）

| 旧表（V544，`shop-merchant` 的 `brand` 模块） | 定稿（平台库） | 作用 |
|---|---|---|
| `mch_management_space` 管理空间 | `mch_group` 商户集团 | 一个老板 / 总部名下的多个主体、品牌、门店；授权以它为根 |
| `mch_management_grant` | 并入授权 | 对空间、品牌、门店、主体分别授权 |
| `mch_brand` | `mch_brand` | 品牌，属于集团，不属于某个主体 |
| `mch_brand_store_binding` | `mch_brand_store_binding` | 门店属于哪个品牌、何时起止；一店同时只属一个品牌（**连锁标记**） |
| `mch_brand_change` | 品牌归属变更单 | 门店加入 / 退出品牌，带影响检查 |
| —（未实现） | `mch_hq_release`、`mch_hq_release_store` | **总部下发**：商品 / 价格 / 目录 / 设置 / 活动发给哪些店，各店待套用 → 已套用 / 拒绝 / 失败；自动或手动套用 |

品牌目前接的是储值、营销、品牌成本（`pmt_brand_*`、`mbr_brand_*`）；商品、库存、目录还没读它。

### 1.2 商品与库存

| 方面 | 现状 |
|---|---|
| 商品归属 | 新建商品一定有所属门店（请求的门店，没有就取默认店） |
| 多店跟卖 | 同主体的其他店给商品设店级库存（`prd_store_sku` 一行）就能卖，可设门店价 |
| 库存行 | 所属门店行（PR #59 起）、跟卖店的行、主体库存池（只来自旧数据）。`StockPortImpl` 按「有没有任一店级行」选路；现货不足时所属门店可回落预售额度 |
| 库存权威 | 全局开关 `shop.inventory.stock-authority`：`PLATFORM`（默认）/ `DUAL` / `INVENTORY` |
| 价格 | 默认价 `prd_sku.price` → 门店价 `prd_store_sku.price` → 目录价 `prd_catalog_item_sku.price` |
| 套餐 | `FREE` 3 家店、`PRO` 10 家、`CHAIN` 30 家（只管门店额度，不是连锁判据） |

## 2 判据

- **单店 / 多店**：看主体名下的门店数。
- **连锁门店**：看门店有没有生效中的品牌绑定（`mch_brand_store_binding.status = ACTIVE`）。所属品牌及其集团就是它的总部。
- 同一主体下可以既有连锁门店又有非连锁门店，各按各的规则。
- 判据只放一处：商品领域加端口 `StoreModePort`（商户域实现）：
  - `chainOf(storeNo)`：没有标记返回空；有则返回品牌号、集团号、发下发的总部主体；
  - `storeCount(entityNo)`：单店 / 多店。
  商品、库存、目录只调它（一处改动一处改）。
- 门店退出品牌：已套用的商品照卖，变成普通本店商品，不再接收下发。不搬数据。

## 3 单店（先做）

### 3.1 规则

| 对象 | 规则 | 落表 |
|---|---|---|
| 商品 | 属于本店 | `prd_goods.store_no` = 本店；`entity_no` 由门店推出（结算键） |
| 上下架 | 商品自己的 `on_sale`；有门店目录（餐饮菜单）时以目录为准 | `prd_goods.on_sale`；`prd_catalog_item` |
| 价格 | 只有默认价 | `prd_sku.price` / `origin_price`；不写门店价 |
| 库存 | 本店一行；`sellable_qty` 空 = 不记库存 | `prd_store_sku`（`store_no` = 本店） |
| 锁量 | 下单锁本店行，付款扣减，取消释放 | `prd_stock_lock.store_no` = 本店 |
| 预售 | 现货不足时用 SKU 的预售额度 | `prd_sku.presale_quota / sold_count / cutoff_at` |
| 不记库存的类目 | 门店分类开关 | `prd_store_category.inv_managed` |
| 进销存 | 可选；进货、盘点、报损在库存库记流水，结果写回本店行 | 现有回写 `syncSellable` |

### 3.2 要改的

| # | 改动 | 说明 |
|---|---|---|
| S1 | 判据端口 `StoreModePort` | §2；连锁部分先返回空，连锁期再接品牌绑定 |
| S2 | 建品只写本店行 | 现状已如此（PR #59）；补约束测试：建品后只有本店一行，没有库存池行 |
| S3 | 库存选路：所属门店行优先 | 本店有行 → 锁本店；现货不足 → 预售额度（在所属门店）。库存池只作旧数据过渡 |
| S4 | 读侧统一 | 买家详情、B 端列表、缺货统计都读门店行；缺货 = 该店 `sellable_qty - locked_qty ≤ 0` |
| S5 | 搬迁：单店主体的库存池并进本店行 | 只有一家店时两者是同一份货，行为不变。搬迁脚本与 `migrate-product-stock.sql` 同一规则 |
| S6 | 守卫 | 约束测试：单店主体的 `prd_store_sku` 不出现 `store_no=''` |

S1–S6 不动表结构，不改接口行为（S3、S4 只统一现有读写口径）。

## 4 多店（没有建连锁）

保持现在的能力，只把口径理顺：

- 商品建在哪家店归哪家店；同主体的其他店要卖，就在本店设门店价与库存（`prd_store_sku` 一行），即「跟卖」。
- 价格：本店门店价 → 默认价。库存：各店各一行，锁本店、扣本店；没有行 = 这家店不卖。
- 现货不足时只有所属门店能回落预售额度（现状，`presaleAt`）。
- 跨店查看：已有跨店总览与对比（`cross_store_stats` 能力位、`/biz/inventory/cross-store`）。
- 旧数据的主体库存池：旧系统「一份总量，各店都能卖」，处理方式待定（§6 ②）。

## 5 连锁（后做，先定规则）

### 5.1 商品：总部下发，门店套用

```
集团 mch_group ── 品牌 mch_brand ── 门店绑定 mch_brand_store_binding（标记）
        │
   总部 ── 总部商品（模子：标题、图、类目、规格、建议价；不上架、不卖、没有库存）
        │  下发 mch_hq_release（GOODS 商品 / PRICE 价格 / CATALOG 目录）
        ▼
   各连锁门店 mch_hq_release_store（待套用 → 已套用 / 拒绝 / 失败）
        │  套用 = 在门店名下建一件本店商品，或更新上次套用的那一件
        ▼
   门店商品 prd_goods（store_no = 本店，entity_no = 门店自己的主体）＋ 本店价与库存
```

| 规则 | 说明 |
|---|---|
| 总部商品放哪 | 总部主体名下、`store_no` 空的商品（定稿允许「空 = 不属于某家店」）；只作模子 |
| 下发 | 总部选一批商品（或价格、目录）发给品牌下选定门店；`apply_mode` 自动（到时自动套用）或手动（门店确认后套用） |
| 套用 | 门店名下建或更新本店商品；记来源（哪件总部商品、哪一版），下次下发据此更新同一件 |
| 门店能改什么 | 下发的字段（标题、图、类目、规格）门店不能改；本店上下架、本店库存、本店价（总部允许时）可以改 |
| 门店自建 | 连锁门店也能自建本店商品，与单店相同 |
| 加盟（门店主体 ≠ 总部主体） | 套用时商品建在**门店自己的主体**名下，订单、库存、结算都在加盟主体（ADR-011）。加盟与直营走同一套 |
| 撤回 | 总部撤回下发：未套用的店不再套用；已套用的商品不自动删，由总部再下发一次下架 |

### 5.2 价格

- 总部下发价格 = 套用时改写各店商品的 `prd_sku.price`。
- 门店能否改价：总部按商品设定，默认不能（§6 ③）。允许时门店价写 `prd_store_sku.price`。
- 取价顺序：目录价 → 门店价 → 本店商品默认价。已下单的价在报价与订单行快照里，不回改。

### 5.3 库存

| 场景 | 规则 |
|---|---|
| 各店独立（默认） | 每家店一行，锁本店、扣本店；总部商品没有库存 |
| 仓与调拨 | 进销存库存库：仓、门店都是库位，调拨两段式（发出 → 收到，在途单列）。门店行 `sellable_qty` 置空，可售量由 `prd_sellable_rule` 从库存库换算 |
| 库存权威 | 连锁可按门店切到库存库（§6 ④），对差连续为零才准切 |
| 跨店借货 | 默认不做；要共用一份货就建仓（§6 ⑤） |
| 跨店查看 | 总部看品牌下各店的库存与销售；范围 = 品牌绑定的门店，不是主体 |

### 5.4 连锁要改的（先列，不排期）

| # | 改动 | 动不动表 |
|---|---|---|
| C1 | `StoreModePort.chainOf` 接上品牌绑定 | 不动表 |
| C2 | 总部商品的建、改（只总部有权，新权限码，授权走集团授权） | 不动表 |
| C3 | 下发与套用：建或更新本店商品，记来源 | **要动表**：本店商品记「来自哪件总部商品、哪一版」，`prd_goods` 没有这一列（`std_no` 是平台标准品，不能复用）；下发内容的冻结快照放哪也要定 |
| C4 | 门店能否改价的设定 | 可能动表 |
| C5 | 库存权威按门店切换 | 可能动表或配置表 |
| C6 | 跨店查看范围改为品牌 | 不动表 |

动表各项先出改表清单，用户确认后再改。

## 6 待定

1. ~~连锁商品来源~~：已定，总部下发、门店套用。
2. **多店主体的旧库存池**：建总仓承接、各店从仓发货；或按商家指定拆到各店行；或多店继续保留库存池作「共用总量」。正式库只有 5 个 SKU，可按主体逐个定。

5. **跨店借货**：不做，用仓（推荐）；还是允许 A 店缺货从 B 店扣。
