# 商品与库存 · 单店与连锁方案

> 2026-11-28 草案，待用户拍板（§6）。用户口径：商品与库存分**单店**（默认，先实现）与**连锁**（另行统一处理）两种情况；
> **是不是连锁看门店上的标记**。
> 依据：[ADR-030 商品归属改为门店 Offer](../adr/ADR-030-商品归属改为门店Offer与品牌库.md)、[ADR-011 经营主体与门店边界](../adr/ADR-011-经营主体与门店边界.md)、
> 定稿 `01-n_platform.sql`（品牌、总部下发）、`05-n_trade.sql`（商品与门店目录 21 张）、`08-n_inventory.sql`（库存库）、
> [进销存需求](../../requirements/进销存-需求.md)、[商品领域迁移交接](商品领域迁移-交接.md)。

## 0 结论先行

| | 单店（默认） | 连锁门店 |
|---|---|---|
| 怎么认 | 门店没有连锁标记 | 门店有连锁标记（§2） |
| 商品归谁 | 本店：`prd_goods.store_no` = 本店 | 仍是本店的一件商品；内容来自总部下发，记着来源 |
| 商品从哪来 | 本店自建 | 总部下发后套用（自动或手动），也可以本店自建 |
| 价格 | `prd_sku.price` 一个价 | 总部随商品或单独下发价格；门店能不能改看总部设定 |
| 库存 | 本店一行 `prd_store_sku`；卖完一键改数 | 同单店：本店一行。仓与调拨走库存库 |
| 预售 | 额度挂 SKU，在本店用 | 同单店 |
| 主体库存池 `store_no=''` | 不用；旧数据并进本店行 | 不用；旧数据按 §4.4 处理 |

一句话：**每家店都只卖自己名下的商品、扣自己的库存**；连锁门店多了一条来源 ——「总部下发」，再加上跨店查看与仓调拨。
单店的规则因此就是连锁的底座，先做单店不会白做。

## 1 现状（2026-11-28 代码与定稿）

| 方面 | 现状 | 问题 |
|---|---|---|
| 连锁标记 | 定稿平台库有：`mch_group`（集团，主体之上）、`mch_brand`（品牌，属于集团）、`mch_brand_store_binding`（门店属于哪个品牌，一店同时只属一个品牌）、`mch_hq_release(_store)`（总部下发与各店套用）。商品与库存代码一处都没读它们 | 商品侧不知道哪家店是连锁 |
| 套餐 | `FREE` 3 家店、`PRO` 10 家、`CHAIN` 30 家；`END_CHAIN` 端权益管跨店管理与考勤工资 | 门店数、套餐都不等于「是不是连锁」 |
| 商品归属 | 新建商品一定有所属门店（`newGoods`：请求的门店，没有就取默认店）。定稿允许 `store_no` 空 =「主体下各店共用」，代码没有这条路 | — |
| 跨店卖同一件货 | 任何一家店都能给别店的商品设店级库存（`prd_store_sku` 一行），然后就能卖 | 没有总部 / 门店之分，也不看标记 |
| 库存 | 三种行并存：所属门店行（PR #59 起）、别店的店级行、主体库存池（只来自旧数据）。`StockPortImpl` 按「有没有任一店级行」选路；现货不足时所属门店可回落预售额度 | 同一件货在不同店、新旧商品之间口径不一 |
| 库存权威 | 全局开关 `shop.inventory.stock-authority`：`PLATFORM`（默认）/ `DUAL` / `INVENTORY` | 只能全平台一起切 |
| 价格 | `prd_sku.price` 默认价；`prd_store_sku.price` 门店价；`prd_catalog_item_sku.price` 目录价 | 单店用不到后两层 |

## 2 判据：门店上的连锁标记

- **按门店判**：门店有连锁标记就是连锁门店，否则是单店。同一主体下可以有连锁门店，也可以有独立门店，各按各的规则。
- 标记取什么（待定 §6 ①）：推荐用现有的品牌绑定 —— `mch_brand_store_binding` 里这家店有一条**生效中**的绑定，就是连锁门店，所属品牌（及其集团）就是它的总部。
- 判据只在一处：商品领域加端口 `ChainStorePort`（由商户域实现）：
  - `isChainStore(storeNo)`：有没有标记；
  - `headquarters(storeNo)`：总部是谁（品牌号、集团号、发下发的总部主体）。
  商品、库存、目录的分支都只调它（一处改动一处改）。
- 解除标记（门店退出品牌）：门店名下的商品照卖，变成普通本店商品，不再接收下发。不搬数据。

## 3 单店方案（先实现）

### 3.1 规则

| 对象 | 规则 | 落表 |
|---|---|---|
| 商品 | 必属一家店；建在哪家店就是哪家店的 | `prd_goods.store_no` 必填；`entity_no` 由门店推出（结算键） |
| 上下架 | 商品自己的 `on_sale`；有门店目录（餐饮菜单）时以目录为准 | `prd_goods.on_sale`；`prd_catalog_item` |
| 价格 | 只有默认价 | `prd_sku.price` / `origin_price`；不写 `prd_store_sku.price` |
| 库存 | 本店一行；`sellable_qty` 空 = 不记库存（不限量） | `prd_store_sku`（`store_no` = 本店）；`locked_qty` 管下单锁量 |
| 锁量 | 下单锁本店行，付款扣减，取消释放 | `prd_stock_lock.store_no` = 本店 |
| 预售 | 现货不足时用 SKU 的预售额度 | `prd_sku.presale_quota / sold_count / cutoff_at` |
| 不记库存的类目 | 门店分类开关 | `prd_store_category.inv_managed` |
| 进销存（进货、盘点、报损） | 可选；开了也只是给本店那一行记账 | 见 §3.4 |

### 3.2 要改的代码

| # | 改动 | 说明 |
|---|---|---|
| S1 | 判据端口 `ChainStorePort` | §2；先只实现「没有标记 = 单店」，标记来源定了再接 |
| S2 | 建品只写本店行 | 现状已如此（PR #59）。补约束测试：建品后 `prd_store_sku` 只有本店一行，没有库存池行 |
| S3 | 只有所属门店能设库存、门店价 | 现在任何店都能给别店的货设库存；改成别的店返回无权 |
| S4 | 库存选路简化 | 只锁本店行；现货不足 → 预售额度（就在本店）。库存池分支只留给旧数据过渡 |
| S5 | 读侧统一 | 买家详情、B 端列表、缺货统计都读本店行；缺货 = 本店 `sellable_qty - locked_qty ≤ 0` |
| S6 | 搬迁：库存池并进本店行 | 单店主体只有一家店时，「主体总量」与「本店库存」是同一份货，并过去行为不变。搬迁脚本与 `migrate-product-stock.sql` 两处同一规则 |
| S7 | 守卫 | 约束测试：单店的 `prd_store_sku` 不出现 `store_no=''`、不出现非所属门店的行 |

S1–S7 不动表结构；S3 改了接口行为，按开发规范属「动了契约」，要先补 TDD。

### 3.3 同一主体开了几家店、都没有连锁标记

- 按几家独立单店处理：每家店各建各的商品，同一件实物在两家店就是两件商品。
- 现有的跨店能力（给别店的货设库存）收掉（S3）。已经这样用了的存量数据：上线前查一遍，有就列给用户定（拆成各店各一件，或给这几家店打连锁标记）。

### 3.4 单店与库存库

- 库存权威用商品库里的简单库存（`PLATFORM`）。
- 开了进销存的单店：进货、盘点、报损在库存库记流水，结果写回本店那一行（现有回写口径 `syncSellable`）；下单锁量不切到库存库。

## 4 连锁方案（后做，先定规则）

### 4.1 商品：总部下发，门店套用

```
集团 mch_group ── 品牌 mch_brand ── 门店绑定 mch_brand_store_binding（标记）
        │
   总部主体 ── 总部商品（模子，不直接卖）
        │  下发 mch_hq_release（GOODS / PRICE / CATALOG）
        ▼
   各连锁门店 mch_hq_release_store（待套用 → 已套用 / 拒绝 / 失败）
        │  套用 = 在门店名下建或更新一件本店商品
        ▼
   门店商品 prd_goods（store_no = 本店，entity_no = 门店的主体）+ 本店库存
```

| 规则 | 说明 |
|---|---|
| 总部商品 | 总部主体名下、`store_no` 空的商品（定稿允许）；只作模子，不上架、不卖、没有库存 |
| 下发 | 总部选一批商品（或价格、目录）发给选定门店；`apply_mode` 自动（到时自动套用）或手动（门店确认） |
| 套用 | 在门店名下建一件本店商品，或更新上次套用的那一件；记住它来自哪件总部商品、哪一版 |
| 门店能改什么 | 总部下发的字段（标题、图、规格、类目）门店不能改；本店上下架、本店库存、（总部允许时）本店价可以改 |
| 门店自建 | 连锁门店也可以自建本店商品，与单店相同 |
| 跨法人（加盟） | 门店的主体可能不是总部主体：套用时商品建在**门店自己的主体**名下，钱照样按主体结算（ADR-011）。所以加盟不用另做一套 |

为什么下发而不是「各店共用一件商品」：
- 每家店仍然只有自己名下的商品，库存、价格、订单、结算全都沿用单店那一套，不出现「一件商品多家店」的口径；
- 加盟店是另一个法人，商品必须在它自己名下才能结算，共用做不到；
- 定稿已经有下发表，省掉新结构。

### 4.2 价格

取价顺序（高 → 低）：目录价 `prd_catalog_item_sku.price` → 门店价 `prd_store_sku.price` → 本店商品的 `prd_sku.price`。

- 总部下发价格 = 改写各店商品的 `prd_sku.price`（套用时写）。
- 门店能不能改价：总部按商品设定，默认不能。
- 已下单的价在报价与订单行快照里，不回改。

### 4.3 库存

| 场景 | 规则 |
|---|---|
| 各店独立（默认） | 与单店相同：本店一行，锁本店、扣本店 |
| 仓与调拨 | 进销存库存库：仓、门店都是库位（`inv_location`），调拨两段式（发出 → 收到，在途单列）。门店行的 `sellable_qty` 置空，可售量由可售量规则 `prd_sellable_rule` 从库存库换算 |
| 库存权威 | 按门店（或主体）切：连锁可切到库存库，对差连续为零才准切（现有 G3 闸门） |
| 跨店借货 | 默认不做：A 店没货不扣 B 店；要共用一份货就建仓，从仓发货 |
| 跨店查看 | 总部看各店库存、销售：已有跨店总览（`cross_store_stats` 能力位、`/biz/inventory/cross-store`），范围改成「同一总部下的连锁门店」 |

### 4.4 旧数据里的主体库存池

- 单店主体：并进本店行（S6）。
- 多店主体（旧系统「一份总量，各店都能卖」）：二选一（待定 §6 ③）—— 建一个总仓承接、各店从仓发货（推荐）；或按商家指定拆到各店行。正式库目前只有 5 个 SKU，搬迁前按主体列清单逐个定。

## 6 要用户拍板的

1. **连锁标记取什么**：门店有生效中的品牌绑定（推荐，定稿已有），还是另加一个门店字段？
2. **没有标记的多店主体**：按几家独立单店处理、收掉现有的跨店设库存（推荐），还是保留？
3. **多店主体的旧库存池**：建总仓承接（推荐），还是拆到各店？
4. **连锁商品的来源**：总部下发、门店套用成本店商品（推荐），还是各店共用一件总部商品？
5. **连锁门店能否改价**：总部按商品设定、默认不能（推荐），还是默认能改？
6. **库存权威**：连锁可切库存库、单店固定简单库存（推荐），还是全平台一个开关？跨店借货默认不做（推荐）。
