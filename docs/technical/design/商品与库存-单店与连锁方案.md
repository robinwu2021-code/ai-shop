## 0 结论先行

| | 单店（默认） | 连锁 |
|---|---|---|
| 谁是连锁 | 没有连锁权益的主体。开了几家店也是**几家各自独立的单店** | 主体有连锁权益（套餐 `CHAIN` / 端权益 `END_CHAIN`） |
| 商品归谁 | 门店：`prd_goods.store_no` 必填，就是这家店的货 | 总部商品（`store_no` 空，主体下各店共用）＋ 门店自建（`store_no` 填店） |
| 卖不卖 | 商品自己的上下架 | 各店在自己的目录里选总部商品上架 |
| 价格 | 只有一个价：`prd_sku.price` | 总部统一价 `prd_sku.price`，门店可改价 `prd_store_sku.price`，目录价最优先 |
| 库存 | 一行：`prd_store_sku`（本店行），简单库存，卖完一键改数 | 各店独立一行；仓与调拨走库存库，门店可售量由规则从库存库换算 |
| 预售 | 额度挂 SKU，就在本店用 | 额度挂 SKU，**只在指定门店**用（默认不开） |
| 主体库存池 `store_no=''` | **不用**。旧数据搬迁时并进本店行 | 不再新增；旧数据按 §4.4 处理 |

一句话：**单店 = 一家店、一份货、一个价、一行库存**；连锁 = 总部管商品，门店管卖不卖、价与库存，仓与调拨交库存库。

## 1 现状（2026-11-28 代码与定稿）

| 方面 | 现状 | 问题 |
|---|---|---|
| 「单店 / 连锁」判据 | 代码里没有。套餐 `FREE` 3 家店、`PRO` 10 家、`CHAIN` 30 家；`END_CHAIN` 只管跨店管理与考勤工资菜单 | 门店数不能当判据：`FREE` 也能开 3 家 |
| 商品归属 | 新建商品一定有所属门店（`newGoods` 取请求的门店，没有就取默认店）。定稿允许 `store_no` 空 =「各店共用」，代码没有这条路 | 共用商品没实现 |
| 跨店卖同一件货 | 已经能：别的店给它设店级库存（`prd_store_sku` 一行）就能卖。跨店测试就是这么测的 | 没有「总部 / 门店」区分，任何店都能给别店的货设库存 |
| 库存 | 三种行并存：所属门店行（PR #59 起新建商品）、其他店的店级行、主体库存池 `store_no=''`（只来自旧数据搬迁）。`StockPortImpl` 按「有没有任一店级行」选路，现货不足时所属门店可回落预售额度 | 同一件货在不同店、新旧商品之间口径不一致（缺货统计已出现过） |
| 库存权威 | 全局开关 `shop.inventory.stock-authority`：`PLATFORM`（默认，商品库里的简单库存）/ `DUAL` / `INVENTORY`（库存库） | 只能全平台一起切，不能「单店用简单库存、连锁用库存库」 |
| 价格 | `prd_sku.price` 默认价；`prd_store_sku.price` 门店价（无行回退默认价）；`prd_catalog_item_sku.price` 目录价 | 三层都在，单店用不到后两层 |
| 品牌（跨法人） | 平台库有 `mch_brand`、`mch_brand_store_binding`（一店同时只属一个品牌）；ADR-030 的品牌商品库没进定稿 | 加盟的商品共用没有落点 |

## 2 判据：怎么知道一个主体是单店还是连锁

- **按权益判，不按门店数判**：主体有 `END_CHAIN` 权益（或套餐 `CHAIN`）= 连锁；否则单店。
- 没有连锁权益却开了几家店（`FREE` / `PRO` 的多店）：**按几家单店处理**，每家店的商品、价格、库存互不相干。
- 判据只在一处：商品领域加一个端口 `ChainModePort.isChain(entityNo)`（由商户域实现，读权益），商品、库存、目录的分支都调它。不在各处散判（一处改动一处改）。
- 降级（连锁权益到期）：已有总部商品照卖、只读；不能再新建总部商品。不做数据搬动。

## 3 单店方案（先实现）

### 3.1 规则

| 对象 | 规则 | 落表 |
|---|---|---|
| 商品 | 必属一家店；建在哪家店就是哪家店的 | `prd_goods.store_no` 必填，`entity_no` 由门店推出（结算键） |
| 上下架 | 商品自己的 `on_sale`；有门店目录（餐饮菜单）时以目录为准 | `prd_goods.on_sale`；`prd_catalog_item` |
| 价格 | 只有默认价 | `prd_sku.price` / `origin_price`；**不写** `prd_store_sku.price` |
| 库存 | 本店一行；`sellable_qty` 空 = 不记库存（不限量） | `prd_store_sku`（`store_no` = 本店），`locked_qty` 管下单锁量 |
| 锁量 | 下单锁本店行，付款扣减，取消释放 | `prd_stock_lock.store_no` = 本店 |
| 预售 | 现货不足时用 SKU 的预售额度 | `prd_sku.presale_quota / sold_count / cutoff_at` |
| 不记库存的类目 | 门店分类开关 | `prd_store_category.inv_managed` |
| 进销存（进货、盘点、报损） | 可选。开了也只是给本店那一行记账；不开就是「卖完一键改数」 | 见 §3.4 |

### 3.2 要改的代码

| # | 改动 | 说明 |
|---|---|---|
| S1 | 判据端口 `ChainModePort` | §2；单店返回 false |
| S2 | 建品只写本店行 | 现状已经如此（PR #59）。补约束测试：单店主体建品后 `prd_store_sku` 只有本店一行，没有库存池行 |
| S3 | 单店禁止给别的店设库存 / 门店价 | 现在任何店都能给别店的货设库存。单店：设库存、设门店价只认商品所属门店，别的店返回无权 |
| S4 | 库存选路简化 | 单店：只锁本店行；现货不足 → 预售额度（就在本店）。`hasStoreStock` / 库存池分支只留给连锁与旧数据 |
| S5 | 读侧统一 | 买家详情、B 端列表、缺货统计都读本店行；缺货 = 本店 `sellable_qty - locked_qty ≤ 0` |
| S6 | 搬迁：单店主体的库存池并进本店行 | 只有一家店时，「主体总量」与「本店库存」是同一份货，并过去行为不变。改搬迁脚本与 `migrate-product-stock.sql` 两处同一规则 |
| S7 | 守卫 | 约束测试：单店主体的 `prd_store_sku` 不出现 `store_no=''`、不出现非所属门店的行 |

S1–S7 不动表结构，只动代码与搬迁脚本；动了接口行为（S3 的拒绝），按开发规范属「动了契约」，要先补 TDD。

### 3.3 单店的多家店（`FREE` / `PRO` 开了几家店）

- 每家店各建各的商品，同一件实物在两家店就是两件商品（两个 `goods_no`）。
- 想「一件商品多店卖、总部统一管」→ 就是连锁，开连锁权益。
- 现有的跨店能力（给别店的货设库存）在这类主体上要收掉（S3）。已经这样用了的存量数据：上线前查一遍，有就列给用户定（转成各店各一件，或给主体开连锁）。

### 3.4 单店与库存库

- 库存权威仍是商品库的简单库存（`PLATFORM`）。
- 开了进销存的单店：进货、盘点、报损在库存库记流水，结果写回本店那一行（现有回写口径 `syncSellable`）。不把单店的下单锁量切到库存库。
- 全局开关 `shop.inventory.stock-authority` 改成按主体：单店固定 `PLATFORM`；连锁见 §4.3。

## 4 连锁方案（后做，先定规则）

### 4.1 商品

| 来源 | `store_no` | 谁能建、谁能改 | 门店能改什么 |
|---|---|---|---|
| 总部商品 | 空（主体下各店共用） | 总部权限（新权限码，如 `biz:chain:goods`） | 不能改标题、图、规格；只能定本店卖不卖、本店价（若总部允许）、本店库存 |
| 门店自建 | 本店 | 门店 | 全部，同单店 |

- 门店「卖不卖」总部商品：在本店目录里有没有这条（`prd_catalog_item`，零售用门店级行 `catalog_version_no=''`，餐饮用目录版本）。不再用「给别店设库存」来表达。
- 总部新建商品默认**不**自动上架到各店；总部可以一键下发到选定门店（批量写目录条目）。
- 总部下架 / 平台强制下架：各店一起下（`platform_suspended` 同理）。

### 4.2 价格

取价顺序（高 → 低）：目录价 `prd_catalog_item_sku.price` → 门店价 `prd_store_sku.price` → 统一价 `prd_sku.price`。

- 门店能不能改价：总部按商品设开关（默认不能）。不能改时门店价行不写价。
- 价格变动只影响之后的报价；已下单的价在报价与订单行快照里，不回改。

### 4.3 库存

| 场景 | 规则 |
|---|---|
| 各店独立（默认） | 每家店一行 `prd_store_sku`，锁本店、扣本店；没有行 = 这家店没货 |
| 仓与调拨 | 进销存库存库：仓、门店都是库位（`inv_location`），调拨两段式（发出 → 收到，在途单列）。门店行的 `sellable_qty` 置空，可售量由可售量规则 `prd_sellable_rule`（全部 / 留几件 / 按比例 / 封顶）从库存库换算 |
| 库存权威 | 按主体：连锁主体可切 `INVENTORY`（下单锁库存库的预留），对差连续为零才准切（现有 G3 闸门） |
| 跨店借货 / 总量共享 | 默认不做：A 店没货不从 B 店扣。要「共用一份总量」就建一个仓，各店从仓发货（履约选源 `source_store_no`），不复活主体库存池 |
| 预售 | 额度挂 SKU；总部指定哪些门店可用预售（默认只有所属门店，总部商品默认全部不开） |

### 4.4 旧数据里的主体库存池（连锁主体）

旧系统「一份总量，各店都能卖」。连锁主体搬迁时二选一（待定 §6 ③）：

- A. 建一个「总仓」库位承接这份总量，各店从仓发货（推荐，与 §4.3 一致，但要开库存库）；
- B. 平均或按店指定拆到各店行（简单，但拆法要商家定）。

正式库目前只有 5 个 SKU，量很小；搬迁前按主体列清单逐个定也可以。

### 4.5 跨法人（加盟、品牌）

- 品牌与门店的归属已有：`mch_brand`、`mch_brand_store_binding`（平台库）。
- 跨法人共用商品：ADR-030 的「品牌商品库」没进定稿。建议先用**平台标准品**（`prd_standard_goods`）加品牌维度承接，或复制下发（每个加盟主体一份总部商品），不在本期做引用式。
- 钱永远按主体结算（ADR-011）：加盟店的订单、库存、价格都在加盟主体自己名下。

## 6 要用户拍板的

1. **判据**：按连锁权益判（推荐），还是按门店数判？
2. **非连锁的多店**：按几家单店处理、收掉现有的跨店设库存（推荐）；还是保留现有跨店能力？
3. **连锁旧库存池**：建总仓承接（推荐），还是拆到各店？
4. **连锁门店能否改价**：总部按商品开关、默认不能（推荐），还是门店默认能改？
5. **跨店借货**：不做，用仓发货（推荐），还是允许 A 店缺货从 B 店扣？
6. **库存权威**：连锁主体可切库存库、单店固定简单库存（推荐），还是全平台一个开关？
