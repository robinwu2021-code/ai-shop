## 一、这一份是什么

**标准库 = 令牌 + 积木 + 组件三层**，一共 10 档令牌、36 个公共积木、17 个组件。
清单与原型**是同一条命令跑出来的**，所以「规范怎么说」与「原型长什么样」不可能对不上。

三份 UI 文档的分工，别混：

| 文档 | 回答 | 谁看 |
|---|---|---|
| [B端UI规范-画原型的十二条](./B端UI规范-画原型的十二条.md) | **该画成什么样**（十二条铁律） | 画原型的人 |
| **本文 + [ui-lib.json](./ui-lib.json) + 原型页** | **手上有哪些件、每件长什么样、什么时候用** | 画原型的人 / 写页面的人 |
| [B端App-组件清单与规范落地](./B端App-组件清单与规范落地.md) | **现在实际长成什么样**（落地审计） | 要动手整改的人 |

## 二、为什么它是生成的，不是画的

十二条的 §四 记着一次真实返工：进销存九屏原型自造了一套样式
（6px/8px/22px 的圆角、到处 1px 描边、9.5px 的字），**十二条里踩了九条**。

根因不是画的人不认真 —— 是**原型与规范之间只有人力这一条联系**：
规范在 `base.css` 里，原型在另一个文件里，两者靠人一条条比对，而人会漏。

所以这一份原型里的每一个色块、每一个圆角、每一条声明，
都是从真源**读出来再渲染**的，中间没有「照着规范画」这一步：

| 真源 | 供给 |
|---|---|
| `packages/shared/src/design/tokens.ts` | 圆角五档 · 间距五档 · 九套皮肤 |
| `packages/shared/src/design/icons.ts` | 18 个图标（内联 SVG） |
| `packages/ui/src/styles/base.css` | 皮肤变量 · 全部积木的真实声明 |
| `b-app/src/App.vue` | B 端密度覆盖 · `.field` |
| `packages/ui/src/components/*.vue` · `b-app/src/components/**` | 组件 props / 行数 / scoped 样式 |
| `b-app`·`c-app` 的 `.vue` | 用量统计 |

**边界要说清楚**（不说清楚就等于在暗示「全都是生成的」）：

- **生成的**：所有数值、颜色、声明、props、用量，以及原型里的**全部样式**
- **手写的**：每条的「什么时候用 / 不要用在」，与组件样例的**结构**（`<div class="sh-card">…`）
  —— 意图与结构代码里读不出来。**样式一行都没写**：样例长什么样由真源的 CSS 决定

渲染口径：**375pt 画布，`1rpx = 0.5px`**。这与 `base.css` 里
「>600px 固定按 375 渲染」是同一个数，所以原型上量到的 px 就是桌面浏览器上的 px。

## 三、令牌

### 圆角五档 · 间距五档

| | sm | md | lg | xl | full |
|---|---|---|---|---|---|
| **圆角** | 16rpx = 8px | 24rpx = 12px | 32rpx = 16px | 44rpx = 22px | 9999px |
| **间距** | xs 8rpx = 4px | sm 16rpx = 8px | md 28rpx = 14px | lg 40rpx = 20px | xl 64rpx = 32px |

组件层**只许用这五个**。差 4rpx 的两个圆角没人分得出，只会让人各写各的。
`uno.config.ts` 与 `tokens.ts` 同源，规范测试比对两处。

### 字阶八档 · 字重三种

**700 只给价格，600 只给标题与按钮，其余一律 400。** 层级改由颜色与留白承担。

| 类名 | rpx | 375pt 下 | 字重 | 现在谁在用 |
|---|---|---|---|---|
| `.txt-mega` | **60** | **30px** | 700 | **0** ← 2026-08-26 新增，收款台那一档 |
| `.txt-hero` | 48 | 24px | 700 | **0** |
| `.txt-display` | 40 | 20px | 700 | **0** |
| `.txt-price` | 34 | 17px | 700 | **0** |
| `.txt-title` | 34 | 17px | 600 | **0** |
| `.txt-strong` | 30 | 15px | 600 | **0** |
| `.txt-body` | 28 | 14px | 400 | **0** |
| `.txt-sub` | 26 | 13px | 400 | **0** |
| `.txt-caption` | 24 | 12px | 400 | **0** |

八档九个类（`.txt-price` 与 `.txt-title` 同为 34rpx，靠字重分）。
最小 24rpx = 12px —— 再小中文笔画糊。字阶里**不含 letter-spacing**：
同一个类要同时承载中/英/阿三种文字，少一个轴就少三种试错。

> ⚠️ **八档全是 0**。实际在跑的是 `.sh-h1`（B18/C3）、`.sh-h2`（B78/C27）
> 与各页手写的 `font-size`。这是清单如实报出来的，不是笔误 ——
> 处置见[落地审计 §五 待决 1](./B端App-组件清单与规范落地.md)。

### 语义色（不随皮肤变）与常量

| | 值 | tint（同色 14%） |
|---|---|---|
| success | `#12b76a` | `rgba(18,183,106,.14)` |
| warning | `#f79009` | `rgba(247,144,9,.14)` |
| danger | `#f04438` | `rgba(240,68,56,.14)` |

`--sh-tabbar-h` 124rpx（底部菜单高，悬浮条靠它对齐）·
`--sh-app-max` 100%（>600px 时 375px）· `--sh-scrim` `rgba(10,12,16,.45)`（遮罩）。

### 皮肤

九套（`brand` 虹选红为 B 端默认），每套**按明暗分别取值** ——
主色压深底与压白字是两个不同的对比度问题，不能共用一个值。
每套 12 个 `--sh-*`：主色 3 档 + 前景 + 中性面 7 档。全部由对比度断言守着。

### 密度：同一套原语，两种松紧

| 变量 | C 端 | B 端 | 管什么 |
|---|---|---|---|
| `--sh-pad-card` | 32rpx | 24rpx | 卡片内边距 |
| `--sh-pad-page` | 28rpx | 24rpx | 页面左右/上边距 |
| `--sh-pad-empty` | 72rpx | 48rpx | 空态上下留白 |
| `--sh-gap-tabs` | 20rpx | 16rpx | 分栏与内容的距离 |
| `--sh-fs-sub` | 26rpx | 24rpx | 次要文字字号 |

C 端是顾客逛店（松一点显精致），B 端是店主一天扫几十次的**作业台**。
**靠五个变量分开，不复制样式** —— 改一次覆盖两端所有页面。

## 六、闸门

`gen-ui-lib.py` 已挂进 `scripts/check-generated-docs.mjs` 的生成器表，
`pre-push` 会在 **HEAD 的干净副本**上跑一遍，产物变了就拦下：

```bash
python3 scripts/gen-ui-lib.py          # 重新生成（清单 + 原型页）
python3 scripts/gen-ui-lib.py --check  # 只校验
node scripts/check-generated-docs.mjs --check   # 九个生成器一起校验
```

**它拦的是「改了 base.css 而清单没跟上」**，不是「代码违不违反规范」——
后者是 `typography` / `design-tokens` / `skin-vars` 三道守卫的事，
而那三道现在是红的且没挂闸门（见[落地审计 §4.1](./B端App-组件清单与规范落地.md)）。
两件事不要混：**这一道保证清单说真话，那三道保证代码照做**。

产物放哪：`ui-lib.json` 入库（它是清单本身，也是 `--check` 的判据）；
`ui-lib.page.html` 与界面清单同理进不了库（`docs/**/*.html` 被 gitignore）——
HTML 是发布用的一次性产物，随时能从真源重新渲染。

## 七、清单一跑出来就报了三件事

生成器在末尾会把「清单里有、代码里没人用」的直接打出来。首次跑出 10 条：

| 条目 | 两端引用 | 说明 |
|---|---|---|
| `.txt-*` 八个 | 0 / 0 | 整套字阶没人用（见 §三） |
| `.sh-btn--danger-solid` | 0 / 0 | 二次确认弹层还没有一处真的做出来 |
| `.field__hint` | 0 / 0 | 规则说明这一档定义了没人用 —— 页面里是各写各的灰字 |

另外两条不体现为 0，但清单摆在一起就看得见：

- `.sh-block` / `.sh-block__head` **B 端 0、C 端 12** —— 十二条第 10 条只在 C 端落了地
- `.field__label` / `.field__input` / `.field__area` **C 端全 0**，却定义在两端共用的
  `base.css` 里，而同族的 `.field` 定义在 `b-app/App.vue`。同一套表单件横跨两个文件、
  只有一端用 —— 要么整体挪进 B 端，要么整体留在共用层，现在这样两头不靠
