> ⚠️ **补上之后 ops 的行为会变**：`blocked` 从「因崩溃而不可达」变成「恒 true」——
> 所有需资质的类目授权都会被禁掉。**这是正确的**（没登记资质就不该授权），

**③ 补守卫 —— 这一步不能省，否则修完还会回来**

改完之后我去找「撤掉必须变红」的那条守卫，**发现它不存在**：

| 已有守卫 | 覆盖什么 | 为什么没抓到 |
|---|---|---|
| `biz-contract-fields` | 契约字段 ↔ 后端下发，**字段级** | 只覆盖 b-app / c-app，**运营端是盲区** |
| `ops-web/lib/api/contract.test.ts` | mock ↔ http 的**方法集合** | 不看返回体形状 |
| `type-alignment` | shared ↔ ops-web 的**枚举取值** | 不比字段 |
| TypeScript | ops-web 自己前后一致 | 对后端发什么一无所知 |

新增 `packages/shared/tests/ops-contract-fields.test.ts`：
**ops-web 声明为必填的数组字段，后端 VO 必须真的有**。

> 只查「必填数组」是刻意收窄：少一个 `string` 字段只是显示空白，
> 少一个必填 `T[]` 字段会让 `.length` / `.map` **直接抛异常**，整块不渲染 ——
> 而错误信息指向渲染代码，不指向契约。先守会崩的那一类。

**这条守卫第一版是假绿的**，两个解析缺陷各让它空转一次：

| 缺陷 | 后果 |

| `export interface Merchant extends Archivable {` 匹配不上 | 该类型一个字段都没比过 |
| 全限定壳 `ai.neargo.shop.common.PageData<...>` 剥不掉 | 端点被当成「解析不到」而静默跳过 |

两次都**报绿**。所以加了一条前置断言：「能配上足够多的端点，配不上说明解析退化了」。

**验收**：ops-web 切真接口（关 mock）打开商家授权页不崩；需资质类目显示为禁用且有提示。
**已做**：撤掉后端字段 + 把 ops-web 类型改回必填 → 守卫变红，恢复后转绿。

#### V23 的实证：`DEFAULT` 回填存量已经发生过一次

54 张 `business_mode = SELF_OPERATED` 的结算单，状态却是第三方轨道的 `PENDING`。


把 08-11 15:18 之前的历史单**全部回填成了自营**。

## 第三步 · 定资金前提（决策，不是开发）

**要定的一句话**：用户支付的钱，是**直接进商家二级商户户**（收付通直连），
还是**先进平台账户再结给商家**（平台代收）？

| | 收付通直连 | 平台代收 |
|---|---|---|
| 平台角色 | 撮合方 | **资金参与方** |
| 无照商户能否交易 | 可以（钱不过平台） | **不能**（无进项票，平台全额担税） |
| 需要什么资质 | 服务商 | 可能涉及支付/资金归集合规 |
| 契约里的痕迹 | — | `/ops/finance/withdrawals/{no}/decide`（平台审批提现）**已声明** |

**为什么必须先定**：第六步（商户类型改造）的能力矩阵、
[全链条清单](./商户类型-全链条清单.md) §三/§四整套结论，全部依赖这个前提。
定错方向的话，第六步做完要重做。

**产出**：一份 ADR（`docs/technical/ADR/ADR-0xx-资金归集模式.md`），
不是代码。**这一步不产出任何代码改动。**

```ts
// packages/shared/src/capability/index.ts
export function canPoints(ctx: {
  globalOn: boolean;
  communityOn: boolean;
  merchantOn: boolean;
  legalFormCanPoints: boolean;      // 替代硬编码的 subjectType === "MICRO"
  legalFormDenyReason: string;
+ /**
+  * 门店经营模式。**自营下没有补差问题** —— 钱本就在平台账户，
+  * 积分抵扣是平台自己让利，不涉及给商家额外付钱。
+  * 所以 channelSupportsSubsidy 只在第三方模式下参与判断。
+  */
+ businessMode: "SELF_OPERATED" | "THIRD_PARTY";
  channelSupportsSubsidy: boolean;
}): Verdict {
  if (!ctx.globalOn) return deny("积分功能未开放");
+ // 顺序要紧：自营下跳过通道补差闸，否则会错误拒绝
+ if (ctx.businessMode === "THIRD_PARTY" && !ctx.channelSupportsSubsidy)
+   return deny("当前支付方式不支持积分抵扣");
  if (!ctx.communityOn) return deny("本社区暂未开放积分");
  if (!ctx.legalFormCanPoints) return deny(ctx.legalFormDenyReason);
  if (!ctx.merchantOn) return deny("本店未开启积分");
  return allow();
}
```

**Java 侧改成同样五闸同样顺序**，并加守卫比对两份判据。
