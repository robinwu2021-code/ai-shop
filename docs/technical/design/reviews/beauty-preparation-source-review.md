## Important 1 — final HUMAN evidence IO has no subsequent current-SELF check

**Location:** `backend-plugins/shop-industry-beauty/beauty-core/src/main/java/ai/neargo/shop/beauty/service/impl/ServiceTaskStockPreparationCoordinator.java:208-217`, especially line 210.

`prepareAcceptedOriginal` calls `access.requireSame` at line 208, then performs `provider.queryOriginalEvidence` at line 210, then calls `apply` without another current-SELF check. `apply` protects local source/fence/companion epochs, but does not recheck the live personnel/membership link. The last call is explicitly a MACHINE evidence operation, so it does not independently check HUMAN permissions either.

**Trigger and consequence:** allow bootstrap/retain or saved-route query to succeed; during the final evidence call revoke the employee's current SELF/store membership/personnel link without changing the Beauty source fence; return otherwise valid original evidence and a valid retained receipt. The HUMAN response can still persist and return `STOCK_RETAINED` after revocation. The earlier SELF check and local source CAS do not cover this IO interval. This violates the explicit current-SELF-after-IO requirement even though `canStart` remains false.

**Minimal correction:** immediately after the final evidence call and before `apply`, call `access.requireSame(binding.scope(), current)` again. Preserve the existing propagation of FORBIDDEN/UNAUTHORIZED/TOKEN_EXPIRED; do not convert that denial to a pending success. Any final task authorization check must stay outside the Beauty transaction; local source/assignment invalidation must continue using the existing fence guards.

**Minimal fixture source:** make only the final `queryOriginalEvidence` callback revoke the current SELF result, after earlier checks and retain have passed. Assert FORBIDDEN, no final `rows.observe`, exact saved original and any accepted stock pins remain unchanged, and no second retain/prepare/key. The existing test at `ServiceTaskStockPreparationCoordinatorTest.java:406` stubs every `requireSame` to fail before retain, so it does not exercise this interval. Add a corresponding native-membership case to the existing native execution fixture when practical; runtime execution remains deferred.

**Checked external semantics:** `ServiceExecutionAccess.requireSame` actually re-queries the current personnel/membership owner; `ExecutionOriginalEvidence` is observational; `DelegatedIdentityContext.outside` merely enforces no transaction. Therefore the last evidence call does not implicitly supply the missing authorization check.

## Important 2 — aggregate RETAINED is accepted without binding its component proofs to this lookup/roster

**Location:** `backend-plugins/shop-industry-beauty/beauty-core/src/main/java/ai/neargo/shop/beauty/service/impl/ServiceTaskStockPreparationCoordinator.java:574-602`, especially lines 588-599. The standalone adapter's `RemoteServiceExecutionPreparationPort.java:163-177` also checks only outer aggregate coordinates/hash, so it does not close this gap.

The validator checks correct outer reference/retention/request/route coordinates, a non-null roster hash and a nonempty list whose wrapper statuses are RETAINED. It then validates whichever nested platform/inventory/not-applicable proof is present. It never checks that the nested component's original equals `lookup`, that wrapper kind/no/hash agrees with that nested proof, that nested receipt outcome agrees with the wrapper, or that the exact authority roster is present without missing/duplicate/substituted components. The inventory branch does not validate the nested receipt schema/hash/coordinates/outcome at all, only the proof. `ownerRosterHash` is checked for non-null only.

**Trigger and consequence:** return a correctly rehashed outer aggregate for lookup A containing an internally valid retained platform proof for lookup B; or return a DUAL aggregate containing only its valid PLATFORM component; or wrap a non-retained nested receipt with RETAINED. Each can pass the current validator and be persisted/projected as `STOCK_RETAINED`. HMAC request binding and self-consistent nested hashes do not establish these missing associations. This is an actual consumed Beauty trust boundary, not an assertion that the normal HOST implementation intentionally emits such a result.

**Minimal correction:** add/use one reusable exact V2 receipt validator without changing existing hash domains. Validate fixed schemas, all inner receipt hashes/outcomes/identities and the exact lookup parent; enforce exclusive payload per component, matching wrapper kind/no/hash, ordered unique authority roster (PLATFORM / INVENTORY / both), and derive/verify the roster hash from the same frozen descriptors and historical-not-applicable evidence used by HOST. Never derive new routing from current configuration or convert Inventory proof into platform rows. Apply it before either persistence or public readiness, including rereads and standalone responses.

**Minimal fixture sources:** start with actual retained V2 receipts from two native originals A/B, substitute B's self-valid proof into A's aggregate and recompute only the aggregate checksum; separately remove one DUAL component, duplicate a kind, alter wrapper identity, substitute a wrong-schema inventory receipt, and wrap a pending nested receipt as RETAINED. All must fail before Beauty observation CAS and must retain any previous valid receipt/sticky route/pins. Add one genuine full DUAL retained observation through the actual Beauty coordinator as the positive case; synthetic fixtures may supplement it but cannot prove native owner effects.

**Checked external contracts:** `PlatformExecutionStockRetentionComponent.ComponentReceipt.validate()` validates its own component parent, not the caller's lookup; `InventoryProof.validate()` likewise validates its own descriptor. `RouteOriginalV2.validate()` already demonstrates the required authority roster and parent-association rules, while `AggregateReceiptV2` itself has no validator/constructor invariant that supplies them. The call-site gap is therefore not covered elsewhere.
