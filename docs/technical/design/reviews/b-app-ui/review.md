## 二、已核实的问题

### R1 · P1：英文、阿语缺少实际使用中的删除按钮词条

- 证据：`b-app/src/pages/notify-settings/index.vue:213` 使用 `common.delete`；中文在 `zh-CN.ts:292` 定义，英文、阿语缺少该 key，却在 `mySpecs.delete` 留有 Delete/حذف。
- 影响：英文/阿语没有本语言对应文字。共享引擎配置中文 fallback，通常会回落为中文“删除”；不同运行端的最终呈现尚未实测，不能直接断言一定显示裸 key。
- 建议：先补齐 `common.delete` 的三语，再检查旧 `mySpecs.delete` 的动态引用；不要只删除多余词条。
- 复现：`npm run test -w @ai-shop/shared -- tests/i18n-parity.test.ts -t b-app`。结果为 **1 项失败、1 项通过、2 项跳过**；失败项首先报告英文缺 `common.delete`，静态盘点另确认阿语同缺。占位符检查通过。

### R2 · P2：公共类拼写/变体无定义，预期排版与操作层级不生效

| 位置 | 证据与后果 | 建议 |
|---|---|---|
| `after-sale/index.vue:323–324` | 使用 `sh-between`；公共样式只有 `sh-row--between`，两行不会因此获得两端对齐 | 使用现有规范类 |
| `marketing-assets/index.vue:154` | `sh-btn--ghost` 没有对应定义，继承基础按钮外观，无法表达预期次级动作 | 选已有的次级按钮变体，避免编辑/主动作同等突出 |
| `marketing-assets/index.vue:145`、`recharge-activity-edit/index.vue:98` | `sh-error` 没有定义，错误文字失去预期语义样式 | 使用现有 danger 文字或 notice 形态，并保证可读 |

核对范围为 base.css、B 端/共享 Vue 样式与共享 UnoCSS 配置；以上类没有自定义生成规则。报告 JSON 另保留静态未解析项，便于重跑时复查。

### R3 · P2：退货验收与库存同步路径绕过 i18n

| 路径 | 证据 | 建议 |
|---|---|---|
| 退货验收 | `after-sale/index.vue:144,321–333` 直接写确认内容、字段与质检结果 | 独有内容归 `afterSale.*`；“申请 {n} 件”用整句插值；保留隔离库存后果 |
| 商品编辑 | `goods-edit/index.vue:3048,3061,3067,3119` 四个“清除” | 查明是否同一清除语义后统一 key；不能误用“删除” |
| 期初对齐 | `stock-align/index.vue:56,101–111` 预览、结果、模式、计数、按钮中英阿无法切换 | 取消用 `common.cancel`，其余归 `stockAlign.*`，计数改完整插值 |
| 库存同步 | `stock-settings/index.vue:186` 入口及 `stock-sync-records/index.vue:33–55` 状态/结果/标题/空态直写 | 标题、状态映射、结果模板全部纳入词库，删除重复页介绍 |
| 核销数量 | `verify/index.vue:470` 直写单位“件” | 按数量/单位现有规则处理，不拼接中文单位 |

这类问题不会被“词库三语 key 一致”检查发现，因为文字根本没进入词库。建议后续增加只针对用户可见文案的棘轮，明确排除日志与测试数据，不能对所有中文字符串一刀切。

### R4 · P2：资质页重新定义公共输入框规格

`qualifications/index.vue:337–341` 将 `.field__input` 设为高 76rpx、横向 20rpx、圆角 16rpx；公共规格为 88/24/24rpx。字段视觉高度由 44px 降为 38px（375px 基准），与其他页面不一致，且需复核实际点按目标。

建议移除公共类尺寸覆盖。若确有紧凑输入场景，用独立语义规格和可用性验证处理；不能以“B 端更紧凑”为由逐页缩控件。登录字段间距 32rpx、店铺设置 24rpx、全局 20rpx 也应按表单语义统一，不能只改一页。

### R5 · P2：期初对齐结果将内部状态与错误码直接交给商家阅读

`stock-align/index.vue:107` 输出 `line.status` 与 `line.errorCode`；批次主标题与操作又使用直写中文。商家需要知道哪些项完成、哪些阻断、下一步处理什么，而不是先理解枚举名。

建议领域状态映射为三语；错误原因在可处理行显示，诊断码保留于次级详情/复制信息中。技术码仍可保留给定位使用，但不能作为唯一解释。

## 三、组件与布局的审查判断

### 3.1 已有基础应继续使用

- 96/96 页直接使用 `sh-scaffold`，页面壳无需重建。
- `sh-empty` 在 59 页出现 63 次；`sh-actionbar` 在 29 页出现 36 次；`sh-kv` 在 14 页出现 59 次。后续整理以这些既有原语为基础。
- `sh-confirm/sh-prompt/sh-pick/sh-tabbar/app-overlay` 是外壳间接依赖。页面直接用量为 0 不代表可删除。
- 全量组件表同时列出用途、源码、props 和依赖；原生 input/button/picker 等另列，避免只统计自定义组件而遗漏表单基础件。

### 3.2 需人工裁决的候选

| 候选 | 处置 |
|---|---|
| `goods-edit/index.vue:3972` 起自建分类蒙层与面板 | 优先核对是否能复用 `sh-sheet`；需验证选类、滚动、关闭与底栏叠层后再迁移 |
| `goods-edit` 中 `.std-search .field__input`、`.kv .field__input` | flex/清除 margin 可能是调用点合理排版；改为页面语义 class，不当作错误尺寸覆盖一律删除 |
| `biz-switch-curtain` 的 fixed | 切店幕布有独立职责，保留，不强改为普通弹层 |
| `stock/index.vue:607` 的透明 `.catch` | 关闭“更多”的点击层，不等同于弹层蒙层；按当前职责保留并验交互 |
| 共享库 actionbar/dialog/scaffold/tabbar 的 fixed | 基础能力，应排除于“页面自建底栏”违规统计之外 |
| 2rpx 标签 padding、-10rpx 拖动图标补偿等 | 个别是光学微调，先审查目的；分隔线不参与 4rpx 间距规则 |
| 库存同步页 10rpx 顶部间距 | 普通详情文本间距，建议使用现有 8/12rpx 档，避免新增近似值 |

## 五、建议实施顺序与边界

| 批次 | 工作 | 完成判据 |
|---|---|---|
| A：可用性 | 补 `common.delete`；修无效公共类；翻译退货验收/库存同步/期初对齐直写 | 对应三语/布局检查通过，不改变业务结果 |
