# 餐饮系统 · 功能清单与代码对齐

> 状态：评审结论（2026-10-26，分支 `codex/ai-shop-codex` @ `176766c60`）。本文是餐饮**功能清单的唯一入口**：
> 每项功能写清「文档怎么说 / 代码里有什么 / 谁测着 / 对不上的地方」。细节仍以各切片 TDD 为准，本文只做对照与索引。
>
> 依据：约 70 份餐饮文档（需求、TDD、设计、验收记录、`design/schema/food-*.json`）；插件 `backend-plugins/shop-industry-food`
> 五模块（728 个主代码文件、184 个测试类）；核心侧行业扩展点（`backend/shop-core` trade、`shop-app` internal、库存、报表）。
> 插件测试本次实跑：923 个执行、1 个失败（见 §4 C3），另有 55 个需一次性 MySQL 才跑的并发用例未跑。

## 0. 结论

1. **餐饮 = 零售核心 + 餐饮业务层**的结构在代码里是成立的：订单、报价、售后、履约、库存预留与出库、报表全部经核心端口完成，
   插件不复制价格、不复制库存；`food-web` 不依赖 `food-core`，`food-channel` 不依赖 web/core，模块边界与 README 一致。
2. **后端「非支付」部分基本做完**：菜品、餐牌、选项、配料、套餐、配方与耗用、桌区桌台、预约排队、共享购物车、报价下单、
   后厨工位 KDS、打印、退餐（不退款）、营业日与结转、报表 —— 都有服务实现、B 端端点和测试。
3. **没做的集中在三块**：
   - **收款侧**：店员收银（`BizSettlementController` 只有 GET）、现金钱箱交班、券/储值/积分、混合支付、订金、资金退款、挂账；
   - **终端界面**：b-app / c-app / ops-web 里没有任何餐饮页面；只有两个「在建」原型与在写的 POS 安卓方案；
   - **外部与离线**：Keeta 等第三方、断网营业、宴会、存酒、房账 —— V1 预建的 15 张表没有任何代码引用。
4. **文档与代码对不上的主要是「状态」**：多份文档仍写「未实现 / 未开始 / 未编译」，而代码早已交付；
   数字口径（迁移基线、表数、API 数）各说各的；机器真源 `food-system-design.json`、`food-code-plan.json` 停在 10-21 的提案口径。
5. **有几处需要尽快修的代码问题**（§4）：4 个定时任务在生产形态下根本不运行；交易恢复每 2 分钟改动未付款结算单的业务版本，
   顾客付款会 409；恢复任务处理不了店员下的单；一个核心内部端点没有令牌校验；插件不在 pre-push 闸门里，HEAD 上已有一个红测试。
