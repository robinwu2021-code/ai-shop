# 一 · 现状与需求

**现状**：能力级 F2 + 散点决策（流水唯一入口、余额归主体、耗卡=支付走 markPaid、
`asset_deduct_minor` 列、`TIMES_CARD/STORED_VALUE` 通道行、PERIOD 记账）—— **无正册、无表、无接口**。

**三行业需求**（各用各的话）：
美业——办卡/储值/疗程/耗卡/退卡/过期顺延/转卡；餐饮——储值营销（充 100 送 20）、储值结账；
零售——储值会员、礼品卡（记账）；健身（记账）——期限卡会籍、停卡冻结。

# 二 · 决策记录

| # | 决策 | 一行理由 |
|---|---|---|
| 1 | **两种载体一张流水**：账户（储值 VALUE）+ 卡（TIMES/PERIOD 实例），流水 `mbr_asset_txn` 是**余额与余次的唯一变更入口** | 绝不无流水 UPDATE；对不上账的起点就是第二个写入口 |
| 2 | 扣减一律**条件 UPDATE 判影响行数** | 与库存、时段、配额同一手法同一理由 |
| 3 | **耗用=支付**：`TIMES_CARD/STORED_VALUE` 是通道行，`markPaid` 不认识资产；金额链走 `asset_deduct_minor` | 结算/报表/售后/评价四条链路不用为资产写第二条路 |
| 4 | **卡定义=CARD 商品 + `prd_trait_redeemable`**；卖卡=普通订单，**发卡是履约**（onPaid 幂等发放） | 卖卡进收入、进结算、可退款 —— 全复用基座 |
| 5 | 储值**双池**（本金/赠金），扣减按比例（A3）；**退卡只退本金余额** | 预收款口径（A1）：赠金是营销费用不是负债 |
| 6 | 卡的适用范围挂**卡定义**上（全部/类目/商品白名单），校验在下单五步的第②步 | 「这张卡能核销哪些项目」是资产的属性，反向挂卡（既有裁决） |
| 7 | 退卡链路固定顺序：已耗按口径核销（A2）→ 售后受理 → **payment 冲正 → 资产回补流水 → 退款登记**（C5） | 顺序错任何一步都会多退或漏回补 |
| 8 | 余额/余次**永不冗余存别处**；行业与前端一律现查 | 工单不存余次（既有）；存一份就在退卡/过期/转让三处分叉 |
| 9 | 归主体、默认全店通用，能力开关可限（A4）；**跨主体通兑记账不做** | 跨主体=跨结算实体，成本在结算不在这里 |
| 10 | PERIOD（期限卡）**表结构与枚举本期就位，核销逻辑记账** | 改形状比加形态贵；健身入驻时只写核销分支 |
| 11 | 过期由 Job 扫描置态，处理方式门店三选（A5）；**过期后不可耗**由状态守卫保证 | 不靠人记得 |
| 12 | 冻结/解冻（停卡）本期只留状态位与留痕，规则记账 | 健身场景需求，形状先留 |

# 三 · 与其他域的接缝（全清单）

| 接缝 | 方向 | 内容 |
|---|---|---|
| 商品域 | 定义 | `prd_trait_redeemable`（卡定义）；充值面额=VALUE 卡商品 |
| 订单域 | 卖卡 | 下单支付 → `onPaid` → **幂等发卡**（同一订单只发一次） |
| 订单域 | 耗用 | 行业 `CoreMemberApi.deductAsset` → 流水 → `markPaid(TIMES_CARD/STORED_VALUE)` + `asset_deduct_minor` |
| 订单域 | 逆向 | C5 固定顺序；`onRefunded` → 提成倒扣（行业）与资产回补（本域）各自幂等 |
| 预约域 | 无直接接缝 | 爽约扣次是行业规则调 `deductAsset(NO_SHOW)` —— 一种 biz_type 而已 |
| 结算域 | 口径 | 资产通道不入分账（通道表三开关全 0）；**卖卡单进结算、耗卡单实收 0** |
| 行业包 | 入口 | 只经 `CoreMemberApi`（查/扣/回补），**不许自己算余额余次** |

# 四 · 不变量（M1–M8）

M1 余额恒等于流水之和（对账 Job 逐日校验，分叉即告警）｜ M2 扣减条件 UPDATE，不足即拒｜
M3 冲正幂等且仅一次（幂等键与原流水关联）｜ M4 双池按比例扣、退卡只退本金｜
M5 过期/冻结/已退状态**不可耗**（状态守卫）｜ M6 适用范围校验发生在下单，不在核销时补救｜
M7 发卡按订单幂等（`source_order_no` 唯一）｜ M8 卡耗次 `remain-=n` 条件更新，n≥1

# 五 · 测试与闸门

单元：M1–M8 正反；并发扣最后一次只成一个；比例扣的分池舍入（分位）；过期后耗用必拒。
场景：充 100 送 20 → 耗 30 → 退卡（验本金按比例）；卖疗程 → 耗 3 次 → 退卡按 A2 口径；
爽约扣次；**撤掉条件 UPDATE 用例必须变红**。
闸门：`-Pcore-only` 全绿（本域是基座）；对账 Job 的流水恒等式；ArchUnit 行业包禁 import `mbr_*` 实体。
