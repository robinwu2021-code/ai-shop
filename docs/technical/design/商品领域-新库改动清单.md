## 1 门店交易库 `n_trade`

### 1.1 .61 现状与建议

.61 上的 `n_trade` 是按拆库分支的基础建表语句建的（74 张表），与零售定稿（67 张）的表集合不同，也缺定稿里的规则（默认值、唯一约束、毫秒时间等）。逐列补的语句见[列默认值补回方案](门店交易库-列默认值补回方案.md) §2.3 做法 B（已生成、未执行）。

**建议（与补回方案的做法 A 一致）**：线上 `n_trade` 现在不动；交易迁移完成、切换之前，按最新的 `05-n_trade.sql` 重建，再重新同步数据。这样下面 §1.2 的改动随重建一起生效，不需要单独执行。

### 1.2 若要原地改（只在不重建时用）

门店目录：旧表一店一行，装不下按版本存的目录（定时生效要并存多版）；冻结内容不能用 json 类型（MySQL 会规范化，读回的文本与写入时不同，快照摘要对不上）。

```sql
-- 先确认没有违反新约束的行
SELECT tenant_no, entity_no, catalog_no, version_no, COUNT(*) FROM prd_store_catalog
GROUP BY tenant_no, entity_no, catalog_no, version_no HAVING COUNT(*) > 1;

ALTER TABLE prd_store_catalog
  DROP INDEX uk_prd_catalog_no,
  DROP INDEX uk_prd_catalog_scope,
  ADD UNIQUE KEY `uk_prd_store_catalog_tenant_no_entity_no_catalog_no_version_n` (`tenant_no`, `entity_no`, `catalog_no`, `version_no`),
  ADD UNIQUE KEY `uk_prd_store_catalog_tenant_no_catalog_vers` (`tenant_no`, `catalog_version_no`),
  MODIFY `frozen_content` mediumtext NULL COMMENT '冻结内容（结账对账用）：发布时的原文，快照摘要按它算';

-- 门店级上下架行的目录版本号存空串（不是 NULL，NULL 在唯一键里互不相等）
ALTER TABLE prd_catalog_item
  ADD UNIQUE KEY `uk_prd_catalog_item_tenant_no_store_no_goods_no_catalog_vers` (`tenant_no`, `store_no`, `goods_no`, `catalog_version_no`);
```

## 2 会员营销库 `n_member`

### 2.1 `mbr_favorite` 加商品收藏唯一约束

同一人对同一件商品只收藏一次；取消收藏是真删，所以不含 `deleted`；门店收藏的 `goods_no` 为空，不受约束。

```sql
-- 先确认没有重复
SELECT tenant_no, user_no, favorite_type, goods_no, COUNT(*) FROM mbr_favorite
WHERE goods_no IS NOT NULL GROUP BY tenant_no, user_no, favorite_type, goods_no HAVING COUNT(*) > 1;

ALTER TABLE mbr_favorite
  ADD UNIQUE KEY `uk_mbr_favorite_goods` (`tenant_no`, `user_no`, `favorite_type`, `goods_no`);
```

### 2.2 新建专题两张

列按字段定稿（`db-target-fields.json`），含将来并入内容位、榜单的列；公共列照零售库规则。

```sql
CREATE TABLE `prd_topic` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '主键，自增',
  `tenant_no` varchar(32) COLLATE utf8mb4_bin NOT NULL DEFAULT 'MAIN' COMMENT '租户号',
  `topic_no` varchar(64) COLLATE utf8mb4_bin NOT NULL COMMENT '专题 / 运营位编号',
  `topic_type` varchar(16) NOT NULL DEFAULT 'TOPIC' COMMENT '类型：TOPIC 主题专题 / RANKING 榜单 / HOME_FLOOR 首页楼层 / BANNER 轮播 / CHANNEL 频道',
  `rank_kind` varchar(16) DEFAULT NULL COMMENT 'RANKING：MANUAL 人工挑选 / 其余为按规则计算的榜单类型',
  `capacity` int DEFAULT NULL COMMENT 'RANKING：榜单容量，人工条目数不能超过它；空表示不限',
  `title` varchar(64) NOT NULL COMMENT '名称，C 端直接展示',
  `subtitle` varchar(128) DEFAULT NULL COMMENT '一句话说明，如「7 点前送到」',
  `cover` varchar(512) DEFAULT NULL COMMENT '封面图',
  `community_nos` text NULL COMMENT '投放社区编号 JSON 数组，空 = 全部社区',
  `sort` int NOT NULL DEFAULT 0 COMMENT '同类型内展示顺序，小的在前',
  `start_at` datetime(3) DEFAULT NULL COMMENT '上线时间，空 = 立即',
  `end_at` datetime(3) DEFAULT NULL COMMENT '下线时间，空 = 长期',
  `enabled` tinyint NOT NULL DEFAULT 1 COMMENT '开关；关掉立即下线，不等 end_at',
  `status` varchar(16) NOT NULL DEFAULT 'ACTIVE' COMMENT '状态：ACTIVE 使用中 / ARCHIVED 已归档（C 端历史链接仍指向它）',
  `deleted` tinyint NOT NULL DEFAULT 0 COMMENT '逻辑删除：0 = 正常，1 = 已删除',
  `version` bigint NOT NULL DEFAULT 0 COMMENT '乐观锁版本号，每次修改加 1',
  `created_at` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
  `created_by` varchar(64) DEFAULT NULL COMMENT '创建人',
  `updated_at` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间，每次修改自动更新',
  `updated_by` varchar(64) DEFAULT NULL COMMENT '更新人',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_prd_topic_no` (`topic_no`),
  KEY `idx_prd_topic_type_status_sort` (`topic_type`, `status`, `sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='专题与运营位：主题专题、榜单、首页楼层、轮播、频道';

CREATE TABLE `prd_topic_goods` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '主键，自增',
  `tenant_no` varchar(32) COLLATE utf8mb4_bin NOT NULL DEFAULT 'MAIN' COMMENT '租户号',
  `topic_no` varchar(64) COLLATE utf8mb4_bin NOT NULL COMMENT '专题 / 运营位编号',
  `goods_no` varchar(64) COLLATE utf8mb4_bin NOT NULL COMMENT '商品号',
  `sku_no` varchar(64) COLLATE utf8mb4_bin NOT NULL DEFAULT '' COMMENT '规格号，榜单按规格挑选时有值；按商品挑选时为空串（不用 NULL：唯一键里 NULL 互不相等）',
  `entity_no` varchar(64) COLLATE utf8mb4_bin NOT NULL COMMENT '商品所属主体',
  `sort` int NOT NULL DEFAULT 0 COMMENT '专题内排序，小的在前',
  `deleted` tinyint NOT NULL DEFAULT 0 COMMENT '逻辑删除：0 = 正常，1 = 已删除',
  `version` bigint NOT NULL DEFAULT 0 COMMENT '乐观锁版本号，每次修改加 1',
  `created_at` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
  `created_by` varchar(64) DEFAULT NULL COMMENT '创建人',
  `updated_at` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间，每次修改自动更新',
  `updated_by` varchar(64) DEFAULT NULL COMMENT '更新人',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_prd_topic_goods` (`topic_no`, `goods_no`, `sku_no`),
  KEY `idx_prd_topic_goods_goods_no` (`goods_no`)
```

## 3 不改表结构、但搬数据时要照办的约定

代码里新用到的取值与写法，搬迁脚本必须照此写入，否则代码读不到或唯一约束挡不住重复：

| 表 | 约定 | 来源 |
|---|---|---|
| `prd_spec_usage` | `scope_type`：`CATEGORY` / `MCH_CATEGORY` / `MERCHANT` / `CATEGORY_TYPE`；维度级行 `value_no = ''`；商家覆盖的 `scope_ref` = 商家号/类目号，停用为 `status = DISABLED`；品类推荐的 `scope_ref` = 品类，`*` = 不限 | 批次 2-d、2-e |
| `prd_goods_revision` | 草稿状态 `EDITING` / `SUBMITTED`，放弃为 `DISCARDED`；草稿基于的线上版本写 `base_goods_version` | 批次 2-f |
| `prd_store_catalog` | 一个版本一行，`stage = PUBLISHED`，`version_no` 从 1 自增，`frozen_content` 存发布原文 | 批次 2-g |
| `prd_catalog_item` | 门店级上下架行 `catalog_version_no = ''`，`enabled` 即原 `on_sale` | 批次 2-g |
| `prd_store_category` | 主体级库存开关行 `store_no = ''`、`catalog_no = ''`，`category_no` = `INV` + sha256(主体号\|平台类目号) 前 29 位 | 批次 2-g |
| `prd_store_sku` | 门店价与店级库存合一行；店级库存为空 = 这家店没有 | 批次 2-c |
| `prd_sku` | 定价策略、卡权益绑定写进本市场那一行；停用绑定 = `status = DISABLED` | 批次 2-b |
| `prd_category` | 禁止的付款方式写 `disallowed_pay_modes`（JSON 数组，空为 NULL） | 批次 2-a |
| `mbr_favorite` | 商品收藏 `favorite_type = GOODS`、`tenant_no = MAIN` | 第 3 批 |
| `prd_topic` / `prd_topic_goods` | 专题 `topic_type = TOPIC`；按商品挑选 `sku_no = ''` | 第 3 批 |
| 新表的 `tenant_no` | 没有默认值的表（`prd_catalog_item`、`prd_store_category`、`mbr_favorite`）一律写 `MAIN` | — |

逐表的搬法见 TDD §2.5。
