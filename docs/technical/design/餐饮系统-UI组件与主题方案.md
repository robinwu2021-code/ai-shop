# 餐饮系统 UI 组件与主题方案

> 状态：原型方案 · 待评审 · 2026-10-20。对应[需求矩阵](../../requirements/餐饮系统-需求矩阵.md)、[平板原型](../../../prototypes/food-cashier-tablet.html)。本轮没有新增或替换线上Vue组件、公共设计令牌或业务API。

## 一、定位与阅读顺序

餐饮采用独立的POS展示配方，满足平板长时间、多轮、高频操作。共享认证、业务状态、金额、可访问性和基础字阶；桌台、菜品、账单、收款重新组织成餐饮专用组件。原型仍由proto.css维护，所有新规则限制在pos-v2作用域，其他零售原型及服务员手机不受影响。

先在原型顶部选主题，再看四个作业页，最后看页尾组件展示。色系仅调整品牌、背景、导航与选中态，不能改变营业和收款状态含义。

## 二、五种主题

| 标识 | 名称 | 主色 | 适配示例 | 主按钮前景 |
|---|---|---|---|---|
| forest | 松绿（默认） | #216857 | 正餐、咖啡 | 白色 |
| indigo | 靛蓝 | #3855A5 | 连锁、快餐 | 白色 |
| amber | 暖橙 | #96521A | 烘焙、茶饮 | 白色 |
| wine | 绛红 | #93374C | 中餐、酒馆 | 白色 |
| graphite | 石墨 | #424E5E | 西餐、简餐 | 白色 |

“适配示例”只是视觉预设，不限制业态。用户随时切换，全部四页及组件展示同步更新；本地仅记住配色，不保存订单、付款和现金数据。危险红、成功绿、警告橙固定，状态同时用文字/图形表达，不只依赖颜色。

新增原型令牌：pos-brand、pos-tint、pos-ink、pos-rail、pos-rail-text、pos-bg、pos-surface、pos-sub、pos-radius。实际产品实施前映射到餐饮设计令牌模块并评审，不能在全局覆盖现有sh主题。字号沿12/14/17/20/24/30px的已有码阶；菜单卡/list具有独立布局规则，不缩小触控区增加密度。

## 三、餐饮专用组件候选

这些名称是未来组件候选，不表示Java或Vue组件已实现；原型CSS是真源的展示实现，未来仍需组件API评审。

| 候选组件 | 展示结构 | 输入/状态 | 事件/边界 |
|---|---|---|---|
| DiningPosShell | 门店/收银员、资源导航、设备连接 | store、operator、activeSection、connection | navigate；不能改变当前主体授权 |
| DiningThemePicker | 5色样板与选中标记 | theme、presets | change；只改外观 |
| DiningResourceRail | 桌区/餐牌分类常驻侧栏 | groups、active、counts | select；数量仅有效范围 |
| DiningTableTile | 状态色条、文字状态、桌号、席位、时长、金额 | table、occupancy、selected、settlementSummary | select；selected与用餐状态分别表示 |
| DiningMenuViewSwitch | 图文卡片/紧凑行 | mode | change；不重置购物车 |
| DiningMenuItem | 本地示意插画、名称、口味、价格、数量 | item、quantity、availability、view | add/remove/configure；价格由报价权威决定 |
| DiningQuantityStepper | 44px方角加减区 | value、min、max、step、unit | change；非法或不可售原因不能靠变灰掩盖 |
| DiningOrderDock | 待提交源行、中部滚动、底部金额和主按钮 | draftLines、submittedSummary、quote、submitState | submit；不把待提交计入正式应收 |
| DiningPaymentTool | 大尺寸工具卡、图标、选中勾 | tools、selected、capabilities | select；扫码/现金权限门控 |
| DiningCashPad | 现金输入、数字键、快捷金额、实收/找零 | dueMinor、receivedMinor、currency | input/confirm；找零整数单位计算，不能声明已收款 |
| DiningShiftSummary | 当班数字、钱箱核对与差异 | shift、cashEvidence、pendingHandover | requestHandover；不是门店日结 |
| DiningStatusLabel | 固定语义色＋状态文字 | state、label | 只展示，不作为写操作按钮 |

底层可复用按钮、图标、弹层、金额格式化和键值行能力；不要求每个专用组件复制一套基础件。餐饮使用12px组件圆角、8px局部控件圆角、深色资源侧栏与凭条式账单组织，替换手机B端胶囊式卡片堆叠。此配方是用户要求的餐饮展示差异，基础组件默认样式保持原样。

菜品插画为本地原创SVG，仅作构图占位，未来用商家真实图片；不是商品真实照片。无图/售罄/长菜名/套餐换菜等完整业务退化状态仍在后续详细设计补齐，不因原型能切换布局就宣称组件全部完成。

## 四、页面组合与交互

| 页面 | 主组合 | 本轮可操作范围 |
|---|---|---|
| 桌台开单 | 资源侧栏＋状态桌台网格＋已点凭条 | 状态筛选、A03进入示例 |
| 点餐收银 | 分类侧栏＋图文卡片/紧凑行＋待提交账单坞 | 分类与搜索求交、数量、切换展示、送厨及金额联动 |
| 结账收款 | 账单明细＋付款工具卡＋现金触控板 | 选择扫码/现金、按键输入、快捷金额、找零；无真实收款 |
| 交接班 | 指标＋核对明细＋交班操作区 | 盘差计算及提示；不执行签核日结 |

主题切换不重建页面，不能丢草稿、重置金额或误触发收款。图文/列表保持相同SKU与数量；分类切换不改变已选菜品。现金键盘最多两位小数，操作金额仍由现有moneyInput及整数最小单位校验。

## 五、验证与实施边界

本轮验证原型五套主题切换、选中态、重载记忆、图文/列表、搜索分类求交、数量与提交金额、现金找零/小数限制、交班盘差以及1024/1280横屏。固定语义色和白字主按钮需对比度检查。其他原型未挂pos-v2，不应读取新的主题变量。

未来实施才在组件库中落地餐饮展示配方，先评审props/events与令牌归属，再补缺图、空态、售罄、长名单、未知支付与离线状态。现有业务API、权限和日结资金守卫不因换肤而变化。


## 六、桌台开单页紧凑化修订

2026-10-20：桌台页单独使用floor-screen配方，其他三个作业页保留原结构。窄桌区栏、中央16桌网格、固定右侧详情组成工作台；缩小无意义留白，保留44px触控区与既有字阶。

| 项目 | 桌台页规则 |
|---|---|
| 顶部 | 68px导航，门店身份14px，辅助信息12px |
| 桌区栏 | 88px；1024视口下76px；桌区入口至少88px高 |
| 网格 | 4列、118px高卡片、8–10px间距；大厅16桌、包间4间 |
| 桌台信息 | 桌号24px（窄屏20px）/600，金额17px/700，状态与席位/时长12px |
| 颜色 | 白色桌卡、细语义色条、选中浅底与品牌轮廓；状态与选择分别表达 |
| 右侧详情 | 300px（窄屏264px），明细滚动；人数、开台、方式与服务员集中；主操作固定底部 |
| 筛选 | 桌区、状态、桌号搜索求交；数量按当前桌区统计；无结果有空态 |
| 选桌联动 | 更新人数、时长、账单及金额；空桌隐藏结账与转台，主操作变开台 |

原型除A03外只演示桌台汇总，完整点餐及收款流程仍以A03为例；不得将其他桌台汇总跳转为A03账单。当前示例非真实营业数据。验证覆盖16桌同屏、包间切换、无结果空态、五主题、主操作可见及加菜后桌卡金额同步。


## 七、白底黑按钮与点餐收银页修订

当前默认配方为mono：白色画布、黑色主按钮、浅灰辅助控件、细灰分隔；语义色只用于桌台和设备状态。旧五色系保留在折叠的外观设置中，不再优先占据页面；偏好使用新版本本地键，避免旧主题自动覆盖本轮默认。

点餐收银页独立采用与桌台一致的三栏框架：88px分类、三列12道菜、300px常驻账单；窄屏同步收紧。采用纯文字菜品卡，菜名14px/600、价格17px/700、口味/单位12px，44px数量加减；不使用菜品插画作为本轮核心作业页的装饰。原图文方案仅保留在旧资产与组件示例作比较，不代表线上菜品必须无图。

本轮增加主食、热菜、饮品等12道示例菜品，分类与拼音搜索求交；卡片/列表切换保留草稿；宫保鸡丁口味可选且数量变化不重置选择。清空本次只清未提交草稿，已点订单保持；送厨后同步桌台、已点和预结金额。所有数据为本地演示，不产生真实订单、收款或打印。


## 八、图片直接加购与购物车调整

当前点餐页保留12道菜的本地SVG示意图（非实拍），分类横向置于菜品区，取消左侧独立分类栏。整张菜品卡是一个可键盘/触控操作的button；点击一次加一份，卡内没有嵌套按钮或数量控件。购物车负责加减、减到零移除、直接移除及口味调整；重绘时保留口味和原有订单金额。

菜品区为主内容+常驻购物车两栏，商品图、菜名、价格是同一点击目标。分类和搜索求交，卡片/列表都保留图片与直接加购语义。图像全部本地加载，未来可替换为门店真实商品图片。

本地预览使用loopback HTTP地址，不依赖聊天客户端打开file路径；当前地址为http://127.0.0.1:8765/prototypes/food-cashier-tablet.html#s02。服务运行期间可访问，仅本机预览。验证覆盖图片点击一次加一份、购物车加减移除、金额重算、分类及搜索；不发生真实订单/支付写入。
