# 库存域 · V2 边界页

状态：页 · 2026-08-28 · 第二梯队 #9。一页钉住三条边界，防止 P1/P2 有人越线。

## 1. 库存（存量） vs 配额（流量） —— 永不互碰
| | 库存 stock | 每日配额 daily_quota |
|---|---|---|
| 语义 | 卖完要补货 | 每天回满 |
| 落点 | `prd_store_stock` / `prd_sku.stock` | `prd_store_listing.daily_quota/quota_used` |
| 沽清 | **不碰它** | 今日 quota 置 0，次日 Job 回满 |
| 扣减 | 下单锁定→支付转实扣（既有） | `tryConsumeQuota` 条件 UPDATE |
两者可同时生效：都过才可下单。**用库存表达沽清 = 第二天要有人记得改回来**（既有裁决，重申）。

## 2. 下单五步中的顺序（订单域决策 9，重申归属）
`resolve 价 → modifier 校验 → ③扣配额 → ④锁库存 → 落快照`；失败逆序回滚。
**先锁库存再扣配额 = 配额超卖时白白回滚库存** —— 顺序由 PlacementPipeline 固化，两域都不许绕。

## 3. 物理驻留与所辖
`prd_sku.stock/locked_stock` **物理暂驻商品表、逻辑归库存域**：商品域代码只读不写（规格书已注）；
写入口只有库存域的锁定/实扣/释放三动作。FEE 行、Modifier、Bundle 子项核销**都不碰库存**
（珍珠的库存是进销存 BOM 的事，不是目录的事 —— 既有裁决）。

## 4. 与进销存（shop-inventory）的边界
进销存是**独立数据源独立迁移史**（既有）：采购/入库/成本在那边；门店可售库存在这边。
两边经既有 invbridge 同步，V2 **不新增跨界写**。行业包对库存的全部合法动作 = `CoreListingApi`（配额）——
**没有 CoreStockApi**：行业连"设库存"都不该做（沽清已改走配额，早前设计里的 setStock 通道作废）。
