# B 端「经营范围」选择器 — 交互方案 v4

> 状态：**已落地 · 2026-08-24**（`b-app` 选择器已按本文改完，H5 mock 走查过）
> 关联：[无资质商家-邻居集市方案](./无资质商家-邻居集市方案.md) · ADR-013 §4.2（省市区要审、街道及以下自助）

面向 `b-app/src/components/biz/biz-region-picker.vue`（唯一入口，宿主页 `pages/store-scope/index.vue`）。
v4 相对 v3 的三处改动：**两个 Tab**、**搜索按层级排序且可下钻**、**地图结果直接添加、彻底删掉「提报」**。

## 0. 主张

店主心里只有一句话：**「我做哪儿」**。系统里这件事被拆成七种东西（省/市/区/街道/村/已开通小区/只有地图上有的小区），
但这七种的差异对店主没有意义。所以：**任何一个地点都是一行，点一下就加进来**；建档、逆地理定街道、父子合并这些由系统自己完成，不问用户。

## 1. 两个 Tab —— 找地方只有两种方式

| Tab | 什么时候用 | 内容 |
|---|---|---|
| **按区划**（默认） | 「我要整个 XX 区」「我不知道叫啥，一级级点下去」 | 从 `sys_region` 逐级下钻：省 › 市 › 区 › 街道 › 村/小区 |
| **搜索** | 「我知道名字」 | 一个输入框，跨所有层级匹配，结果按层级从大到小排 |

Tab 只切换**列表内容**，不切换交互：两个 Tab 里的行长得一样、点法一样、勾选框在同一个位置。
顶部已选摘要、底部「完成」在两个 Tab 上是同一条，不随切换动。

## 2. 数据模型：一行 = 一个地点

| 来源 | 层级 | 加入时系统做什么 | 生效 |
|---|---|---|---|
| `sys_region` 1–4 级 | 省 / 市 / 区 / 街道 | 直接记 `refCode` | 街道自助；省市区待审 |
| `sys_region` 第 5 级（官方村/居委会，62 万条） | 村 | `mApplyCommunity(kind=VILLAGE, originCode=村码)` 免审直开，拿 `communityNo` | 自助 |
| `community` 表（已开通聚落） | 小区 / 村 | 直接记 `communityNo` | 自助 |
| 高德 POI（搜索联想 / 地图选点） | 小区 | `mOpenCommunityFromMap` 直接开通（服务端逆地理定街道 + 三道闸查重） | 自助 |

四类来源共用同一个 `Row = { name, sub, hasChild, picked, covered }`，差异只落在副标题那行小字上。

## 3. Tab A「按区划」

- 面包屑一行（`全国 › 广东省 › 深圳市 › 龙华区`），任一段可点，点了回到那一级。
- 面包屑下固定一行 **「整个 XX」**：让「我就要这一整片」与「我进去挑几个」在同一屏并列，不用先决定走哪条路。
- 下面是本级列表，每行同一种样式。街道层的下一级是**村与小区混排**（官方村 + 已开通小区 + 该街道的地图 POI），不再往下钻区划。
- 列表末尾固定一行 **「在地图上选点添加」**。

## 4. Tab B「搜索」

- 输入 ≥2 字，debounce 300 ms，四路并行取数，合并成一个列表：
  1. `mRegionSearch(q)` — 跨级区划 + 已开通聚落，服务端返回完整 `path`；
  2. `mVillageDict(streetCode, q)` — 官方村名词典（当已停在某个街道时）；
  3. 地图 POI — 有当前层中心用 `searchPlacesNear(q, center, 5 km, city)`，否则 `searchPlaces(q, city)`；
  4. 已选清单本地匹配（让他看得见「这个我已经选过了」）。
- **排序恒定，从大到小**：省 › 市 › 区 › 街道 › 村/小区 › 地图上的地点。每段加一个浅色分组标题，不打乱、不按相关度重排——相关度排序会让「深圳市」跑到「深圳市某小区」后面，店主会以为搜不到市。
- 每条的副标题是**完整行政路径**（`广东省 / 深圳市 / 龙华区 / 福城街道`）。同名地点全国一大把，这是唯一分得清的东西。
- **点搜索结果里的区划 = 进入它的下一级**：自动切到 Tab A 并停在那一级，搜索词保留在框里（回 Tab B 结果还在）。搜索因此也是导航。
- **点村/小区 = 直接加入**，不需要先走到它所在的街道——街道是行政编码，店主不知道也不需要知道，系统能从坐标反查。
- **去重**：`normalizeName` 归一后，已开通 > 官方村 > 地图 POI，只留最左那条。已开通的绝不再出一条「去添加」。

## 4.5 层级到哪儿为止 —— 按数据说话（2026-08-24 实测线上库）

| 级别 | 行数 | 有坐标 |
|---|---|---|
| 省 / 市 / 区县 | 31 / 342 / 2978 | **0** |
| 街道 | 41 352 | **0** |
| 村·社区（第五级，也是最后一级） | 620 573 | 2 839（0.46%，补录覆盖到的城市） |
| 已开通聚落 `cmt_community` | 12 | 全部 |

三条由此定死：

1. **村之下库里什么都没有**。第五级就是终点，再往下的「小区」只存在于地图上——所以那一层是按坐标圈出来的，不是查出来的。
2. **有坐标才给 ›**。没坐标就圈不出小区，点进去必然是空的一屏；而农村的村委会≈村本身，勾了就是终点。深圳龙华福城街道下 13 个社区居委会全部有坐标，所以城区那条路是通的。
3. **同名街道全国有好几个**（「福城街道」在江西、深圳、云南各一个），这正是「深圳市龙华区福城街道」这种带上级写法要能搜的原因。

## 5. 地图：搜到即加，没有提报

- 地图来源出现在两个地方：搜索结果最后一组「地图上的地点」，以及两个 Tab 列表末尾常驻的「在地图上选点添加」。
- **点一下就 `mOpenCommunityFromMap` 建档并勾上，不弹表单、不等审核。** 高德给的名字、门牌、坐标齐全，服务端逆地理定街道（用 `adcode + 街道名`，不用高德 towncode——两套编码不同源，实测会静默挂错），重复由三道闸挡（官方村码 / 同街道归一名 / 坐标 150 m 内且名字相近），撞上返回既有那条。
- 「在地图上选点」的初始中心按「已标过的 › 当前所在层中心 › 设备定位」排。店主常在自己店里配另一个区的范围，开局落在脚下等于每次先拖几百公里。
- **`mApplyCommunity` 的提报表单（名称/门牌/坐标/等审核）整个删除。** 它是「地图拿不到坐标」时代的产物；现在地图两条路都带坐标，留着只会让人在「直接加」和「提报」之间选，而后者注定被驳回。官方村仍走 `mApplyCommunity`，但那是免审直开的服务端细节，界面上就是普通一行。

## 6. 五条一致性规则（两个 Tab、任何一级都成立）

- **R1 左右分工恒定**：行主体点击 = 有下级则下钻、无下级则勾选；右侧勾选框永远只做「加入/取消」；`›` 永远只做「换一屏」。两者之间有竖分隔——勾一个市影响几千个小区，和「换一屏」后果差着量级。
- **R2 加入即完成**：不弹表单、不跳页、不问街道。未开通的村/POI 由系统当场建档，店主不感知这一步。
- **R3 父子只留父**：加入一条区划时自动吸收其下已选项，并 toast「已合并 N 条到『福城街道』」——不说，店主会以为刚勾的小区被弄丢了。
- **R4 被覆盖的行不可勾**：显示「已被『深圳市』覆盖」，而不是一个灰掉的勾。判据是区划码前缀，与后端 `LIKE '前缀%'` 同一口径。
- **R5 影响面大的先问一句**：省/市/区加入前 `showModal` 确认，行上与已选清单里都标「待审核」；街道及以下自助生效，不问。

## 7. 反馈文案（toast，`store.picker.*`）

| 情形 | 文案 |
|---|---|
| 加入未开通的村/小区/地图地点 | 已加入 |
| 触发父子合并 | 已合并 {n} 条到「{s}」 |
| 点了被覆盖的行 | 已被「{s}」覆盖，无需重复选 |
| 省市区加入 | 已加入，等待运营审核 |
| 到 200 条上限 | 最多 {n} 条，先移除一些再加 |
| 建档失败 | 原样透出服务端消息（如「已开通，直接勾选即可」） |

## 8. 边界

- 上限 200 条；到顶时说清是哪条没进去，不静默丢弃。
- 每次打开面板重置临时态；切 Tab **不重置**已选、不重置面包屑——切回来要还在原地。
- 后端未配 `AMAP_WEB_KEY` 时 POI 联想为空，搜索的前三组照常工作，「在地图上选点」走原生 SDK 不受影响。

## 9. 落地情况（2026-08-24）

全部落在 `biz-region-picker.vue` 一个文件里（宿主页只去掉了 `@applied` 一条线）：

| 项 | 改动 |
|---|---|
| Tab 结构（§1） | `tab: "REGION" \| "SEARCH"`，`sections` 是模板唯一的列表源 —— 两个 Tab 共用同一段行渲染，样式不会各改各的 |
| 搜索（§4） | `mRegionSearch` + 地图 POI 两路并行；`groups` 按 `LEVEL_ORDER` 分组；`openFromSearch()` 用 `mRegionPath` 补齐面包屑后切回 Tab A |
| 地图入口（§5） | 两个 Tab 的滚动区末尾常驻（含「还没输字」「正在搜」两个瞬间）；`pickOnMapAndAdd()` → `mOpenCommunityFromMap` 直接建档并勾上 |
| 提报流程 | **已删**：`applyOpen / applyName / applyDetail / submitApply / applyGeo / useVillage / useEstate / pickPlace / pickPoi` 及三份 locale 里的 16 个 `store.apply*` 键 |
| 加过的行要看得见 | 新增 `hitAdded`（行 key → 新建的聚落号）：官方村与地图地点那几行加完立刻显示勾，再点一下＝取消 |

守卫：`vue-tsc` 干净；`packages/shared` 的 i18n 平价、字阶/圆角/皮肤对比度守卫在改动文件上通过（仓库里其余失败项属并行会话的未提交改动）。
