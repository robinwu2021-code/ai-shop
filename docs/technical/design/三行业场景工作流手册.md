# 三行业场景工作流手册

状态：**梳理 · 待确认** · 创建 2026-08-28
定位：[组合模型](./TDD-基础订单流与行业工作流-组合模型.md)的**场景级展开** —— 先细分场景，再给每个场景的完整工作流，
全部用统一记法书写，末节做跨行业同构校验。28 个场景，无一需要新的同步点或新的基础流状态（L6 复验）。

**记法**（贯穿全册）：

```
[A1]…[A5]  组合模型的五个同步点：A1 开单 place · A2 钱 markPaid/settle · A3 履约 verify/计量 · A4 逆向 · A5 事件
⟨…⟩        预约/资源域动作（占位 hold / 开放占用 occupy / 释放）
(状态)      订单状态；行业轨状态直接写名字（OPEN/SERVING…）
⊗          失败与逆向分支
×N         重复段
```

每个场景先给三参数：**轨道**（用了哪几条）｜**开单时机**（组合模型 W2）｜**收款**（W3）。

# 一 · 零售（8 个场景）

零售 = 基础订单流 + ∅，所以它的场景就是**基础流本体的全部形态** —— 这一节同时是另外两个行业的对照基线。

| # | 场景 | 轨道 | 开单 | 收款 |
|---|---|---|---|---|
| R1 | 网购·快递/自送 | 订单 | 即时 | 先付 |
| R2 | 网购·到店自提 | 订单 | 即时 | 先付 |
| R3 | 网购·邻里自提点 | 订单 | 即时 | 先付 |
| R4 | 社区拼团 | 订单(+团) | 即时 | 先付 |
| R5 | 收银台线下开单 | 订单 | 即时 | 当场付（可混合） |
| R6 | 称重生鲜·预售 | 订单 | 即时 | 先付+补差 |
| R7 | 预约自提时段 | 订单+资源 | 即时 | 先付 |
| R8 | 售后（逆向，跨场景共用） | 订单 | — | — |

**R1 网购·快递/自送**
```
跨店购物车 → [A1] place（一主单拆 N 子单，WAIT_PAY）→ 支付回调 [A2] markPaid(PAID)
→ 子单(WAIT_FULFILL) → 发货 → 配送/签收 [A3] → (COMPLETED) → 结算
⊗ 超时未付 → (CLOSED，库存/配额回补)
```

**R2 到店自提** —— R1 的履约变体：`[A2] 后出核销码 → 到店核销 [A3] → 完成`。
**R3 邻里自提点** —— R1 + 分拣：`[A2] 后按拣货分区(station)打分拣单 → 送达自提点 → 核销 [A3]`。

**R4 社区拼团**
```
开团/参团 → [A1] place(WAIT_PAY) → [A2] → 成团判定（人满/到时）
→ 成团：进入 R1/R2 履约 ｜ ⊗ 不成团：[A4] 自动整单退款
```
成团判定是**营销域**的编排 —— 它调用 A4，不新增同步点。

**R5 收银台线下开单**（基座功能，零售基线的补缺）
```
openTicket [A1] place(WAIT_OFFLINE_PAY) → 逐笔 ord_payment（现金+微信+储值）
→ 足额 [A2] settle → markPaid(MIXED) → 即时履约(FULFILLING→COMPLETED)
```

**R6 称重生鲜·预售**
```
截单前 [A1]+[A2]（按标称量出价，nominal 快照）→ 到货实称 [A3] applyMeteredAdjust(±差价落行)
→ 自提核销 [A3] → 完成    ⊗ 超允差 → 人工确认后再核销
```

**R7 预约自提时段**
```
选时段 ⟨hold 1 格（门店级 slot，旧径 tryBook）⟩ → [A1] place → [A2]
→ 到点核销 [A3]（appointment_at 由时段推出）   ⊗ 取消 → [A4] + ⟨release⟩
```

**R8 售后（逆向共用）**
```
申请 → 按商品 after_sale_policy 分流（实物常规/虚拟拒/服务按取消规则）
→ (APPLIED→REFUNDING→REFUNDED) ｜ 驳回→申诉→仲裁
规则：按行退款含 modifier 金额；GIFT 行不退钱；付款冲正先于退款存在性检查
```

# 二 · 餐饮（10 个场景）

| # | 场景 | 轨道 | 开单 | 收款 |
|---|---|---|---|---|
| F1 | 快餐先付·柜台/叫号 | 台账(轻)+订单 | 即时 | 先付 |
| F2 | 扫码点餐·先付 | 台账+订单 | 即时×N | 先付/轮 |
| F3 | 正餐后付·多轮加菜 | 台账+订单 | 即时×N | 结账统付 |
| F4 | 服务员代客点单 | 同 F2/F3 | 即时 | 同左 |
| F5 | 外卖 | 订单 | 即时 | 先付 |
| F6 | 自取 | 订单 | 即时 | 先付 |
| F7 | 包间预定→转开台 | 资源+台账+订单 | 到店后 | 后付 |
| F8 | 结账拆分（AA/按单/按人） | 台账+订单 | — | 变体 |
| F9 | 退菜/减菜（逆向） | 台账+订单 | — | — |
| F10 | 营业日运行（沽清/时段切换） | 商品售卖层 | — | — |

**F1 快餐先付**
```
点单（可无桌台）→ [A1] place(WAIT_PAY, DINE_IN) → [A2] 支付
→ [A5] onPaid → 入厨+出票(取餐号) → 制作(QUEUED→READY) → 叫号交付 [A3 划菜] → 完成
```

**F2 扫码点餐·先付**
```
扫桌码 ⟨开台：occupy(TABLE)⟩ → 台账 OPEN → { 一桌多人台账车点单
→ [A1] place(WAIT_PAY) → [A2] → [A5] 入厨 → 上菜划菜 }×N轮
→ 客走结台 CLOSED ⟨release⟩（先付制：结台无收款动作）
```

**F3 正餐后付·多轮加菜**（餐饮主流程）
```
⟨开台⟩ 台账 OPEN → { 点单 → [A1] place(WAIT_OFFLINE_PAY) → 入厨（不等支付）}×N轮
→ 发起结账 SETTLING（此后拒加菜）→ 应收=Σ订单(现算) → 逐笔 ord_payment
→ 足额 [A2] settle → 逐单 markPaid(MIXED) → [A5] onPaid → 结台 CLOSED ⟨release⟩ + 小票
⊗ 超时未结：按门店配置告警，台账未结不自动取消订单
```

**F4 代客点单** —— 与 F2/F3 同流，差异只在操作者与权限码（`food:order:place`），
外加两个代客专属动作：赠菜（GIFT 行，金额 0）、折扣（下单时优惠，不是事后改价）。

**F5 外卖** —— **无台账**，基础流全程：
```
外卖菜单(渠道过滤) → [A1] place(WAIT_PAY, MERCHANT_DELIVERY/EXPRESS) → [A2]
→ [A5] 入厨 → READY → 基座履约发货/配送 [A3] → 签收 → 完成（餐饮只贡献了"入厨"）
```
**F6 自取** —— F5 的履约变体：`READY → 叫号 → 核销 [A3]`。

**F7 包间预定 → 转开台**（两种占用模式接力）
```
选包间时段 ⟨hold bySpan(ROOM)⟩ → 预定记录（行业）→ 到店：⟨hold confirm→release⟩
→ ⟨occupy(ROOM) 开放占用⟩ 开台 → 进入 F3    ⊗ 爽约：hold TTL/Job 过期还量
```

**F8 结账拆分**（都是 F3 结账段的变体，**无一新机制**）
```
AA：对台账收 n 笔 ord_payment，凑够总额一次 settle
按单：payment.order_no 定向，各单各 settle
按人：下单时 placeSplitByPerson 分车 —— 拆单在下单时发生，不在结账时劈账
```

**F9 退菜/减菜**（唯一分叉判据：这笔钱收没收）
```
钱已收：制作行 VOIDED(原因必填) → [A4] refundLine（含加料金额）→ 打撤单条
钱未收：台账撤行 → [A4] cancel 整单 → 需保留的重下 [A1] → 打撤单条
```

**F10 营业日运行**
```
沽清 = listing.daily_quota 今日置 0 [商品售卖层] → 次日 Job 回满
时段菜单 = availability 规则到点自动切换（不是上下架）
```

# 三 · 服务业（美业为代表，10 个场景）

| # | 场景 | 轨道 | 开单 | 收款 |
|---|---|---|---|---|
| B1 | 线上预约·线上付 | 预约+工单+订单 | **预约时**（付钱=真意向） | 先付 |
| B2 | 线上预约·到店付 | 预约+工单+订单 | **到店时**（防幽灵单） | 后付 |
| B3 | 电话/前台代约 | 同 B2 | 到店时 | 后付 |
| B4 | 直客 walk-in | 工单+订单 | 开工单时 | 后付 |
| B5 | 卡客耗卡 | 工单+订单 | 开工单时 | **早付过** |
| B6 | 疗程分次 | 订单(卖卡)+B5×N | 各自 | 卖卡时 |
| B7 | 上门服务 | 预约+工单+订单 | 预约时 | 先付 |
| B8 | 双人/团体 | 同 B1 | 预约时 | 先付 |
| B9 | 改约/取消/爽约（逆向） | 预约+资源 | — | — |
| B10 | 办卡/充值 | 订单 | 即时 | 先付 |

**B1 线上预约·线上付**
```
选项目 → 选技师(技能∩排班∩余量) → 选时段 → ⟨hold bySpan(资源×时长+缓冲)⟩
→ [A1] place(WAIT_PAY) → [A2] → [A5] onPaid → 预约 CONFIRMED + ⟨hold confirm⟩
→ 到店 CHECKED_IN → 开工单 → 服务 SERVING → 完成 [A3] verify → (COMPLETED) → 结算·提成
```

**B2 线上预约·到店付** —— 订单延迟诞生：
```
⟨hold⟩ → 预约 CONFIRMED（无订单！）→ 到店 → 开工单 → [A1] place(WAIT_OFFLINE_PAY)
→ 服务 → 完成 → 收款 ord_payment → [A2] settle → 提成
```
**B3 电话/前台代约** —— B2 + 客人可无会员账号（guest 姓名电话，脱敏存储）。

**B4 直客 walk-in**
```
到店 → 看今日排程有空档 → ⟨短 hold 或直接占当前格⟩ → 开工单 → [A1] → 服务 → 收款 [A2]
```

**B5 卡客耗卡**（"早付过"）
```
到店识别会员 → 开工单 → [A1] place（原价快照=提成基数）→ 服务 → 完成
→ [A3] verify + deductAsset(基座资产流水扣次) + [A2] markPaid(TIMES_CARD, 实收0, assetDeduct)
→ 提成计提（基数=原价）+ 余次条打印
```

**B6 疗程分次** —— 两段式：
```
卖卡：B10 一张订单（钱在此确认）→ 之后每次到店 = B5 ×10（每次实收 0 的新订单）
收入不重复计；「订单 ≡ 一次消费」保持成立
```

**B7 上门** —— B1 + 路途缓冲进占位（`buffer_before/after` 折进 hold 跨度）+ 履约=APPOINTMENT（必须有地址）。

**B8 双人/团体** —— B1 的占位参数化：`⟨hold bySpan(M 资源) → N格×M 单元原子⟩`，工单一张多行、各归技师。

**B9 改约/取消/爽约（逆向）**
```
改约：⟨先 hold 新时段 → 成功才 release 旧⟩ → 订单不动（未付）/不动（已付）
取消：提前 ≥ 免责时长 → ⟨release⟩ + [A4] 退款(若已付)
     提前 < 免责时长 → 按门店规则扣定金/扣次
爽约：Job 到点未 CHECKED_IN → NO_SHOW → ⟨release⟩ → 按规则处置
```

**B10 办卡/充值**
```
选卡(CARD 商品) → [A1] place(WAIT_PAY) → [A2] → 会员资产入账(mbr_card/mbr_asset_txn)
→ 即时履约完成（虚拟交付）    ⊗ 退卡：[A4] + 已耗次数按门店口径核销 + 资产冲正
```

# 四 · 跨行业同构校验

## 4.1 同构组（同一机制的不同名字）

| 同构组 | 零售 | 餐饮 | 服务业 | 共用机制 |
|---|---|---|---|---|
| 混合收款结账 | R5 收银台 | F3 结账 | B2 收款 | `ord_payment` + settle |
| 到店核销 | R2 自提 | F6 自取叫号 | B5 核销 | verify [A3] |
| 按实结算 | R6 称重补差 | 海鲜按斤 | （KTV 按时·记账） | `applyMeteredAdjust` |
| 时段占位→开单 | R7 预约自提 | F7 包间预定 | B1 预约 | ⟨hold⟩→[A1] |
| 基础流全程直走 | R1 网购 | F5 外卖 | B10 办卡 | 行业几乎零参与 |
| 逆向分叉 | R8 售后策略 | F9 钱收没收 | B9 提前时长 | [A4] + 各自判据 |

## 4.2 同步点覆盖矩阵（28 场景 × A1–A5）

| | A1 开单 | A2 钱 | A3 履约 | A4 逆向 | A5 事件 | ⟨资源⟩ |
|---|---|---|---|---|---|---|
| 零售 R1–R8 | 7 | 7 | 7 | 3 | 隐式 | R7 |
| 餐饮 F1–F10 | 8 | 7 | 7 | 2 | 4 | F2/3/7 |
| 服务业 B1–B10 | 9 | 9 | 6 | 3 | 2 | 8 个 |

**结论：28 个场景全部由 A1–A5 + 资源域原语组合而成，无一需要新同步点、新订单状态、新基础流边。**
组合模型的 L6（新工作流不得要求基础流加状态/加边）在场景粒度上复验通过。

## 4.3 三个行业各自的"重心"

| 行业 | 场景重心 | 对基座的压力点 |
|---|---|---|
| 零售 | 履约形态多（4 种交付 + 称重 + 拼团） | 履约域与计量结算 |
| 餐饮 | **多轮开单 + 合并结账**（一个台账 N 张订单） | `ord_payment`/settle 与厨打事件 |
| 服务业 | **开单时机 + 占位生命周期**（hold 贯穿全程） | 预约/资源域与会员资产 |

—— 三个重心互不重叠，这就是"一条基础流吃三个行业"仍然成立的结构性原因：
**它们各自压的是基座的不同侧面，而不是同一处的三种改法。**
