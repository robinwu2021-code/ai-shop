# 库表：按业务域整理与冗余分析

状态：分析稿，待用户逐项确认后再立 ADR / TDD。
创建：2026-11-25。数据口径：正式库 `ai_shop_ume`（850 张）与 `ai_shop_ume_inv`（58 张）当日结构与行数。
业务域划分由用户给定：支付、库存、会员营销、平台商城、平台基础、零售、餐饮 / 美业。

冗余的四种判定（只从业务上判，不看“有没有人用”）：

| 记号 | 含义 | 处置 |
|---|---|---|
| **重** | 同一个业务对象建了两套或多套 | 定一套为准，其余并入 |
| **旧** | 旧一代模型或迁移过渡表，新一代已覆盖 | 迁完后退役 |
| **错域** | 业务上属于别的域 | 搬到所属域 |
| **技** | 不是业务对象，是每个域自造的技术件（事件收发、幂等、游标） | 用平台统一机制 |

## 7 餐饮、美业：建议与零售合并在同一个库

理由是业务上的：餐饮和美业不是独立的交易体系，而是在零售的“商品—订单—收款”之上加了一段**营业过程**（桌台、出品、预约、服务）。它们的订单依赖零售订单，分库会把一笔交易拆到两个库。

**餐饮 138 张**，按业务拆开看：

| 类别 | 表 | 处置 |
|---|---|---|
| 餐饮特有（约 60） | 桌台 `fnb_table*` 5、`fnb_seat`；菜单 `fnb_menu*` 10、`fnb_course`；出品 `fnb_kds_*` 4、`fnb_kitchen_*` 2、`fnb_station*` 2、`fnb_sku_station`；排队 `fnb_queue_*` 2；宴会 `fnb_banquet_*` 3；寄存 `fnb_bottle_*` 2、`fnb_custody_entry`；配方 `fnb_recipe*` 3；堂食服务 `fnb_service_*` 11、`fnb_guest_session`、`fnb_dining_*` 2；`fnb_store_policy` 等 | 保留 |
| 与零售商品重叠（约 12） | `fnb_dish(+option_group)`、`fnb_bundle*` 3、`fnb_option_group*` 2、`fnb_modifier*` 2、`fnb_menu_item_sku`、`fnb_sales_*` 2 | 套餐与选配是商品能力，零售的组合商品同样需要，**重** → 零售商品 |
| 与零售订单、结账重叠（约 22） | `fnb_check*` 7、`fnb_order_*` 4、`fnb_core_*` 2、`fnb_settlement(+item)`、`fnb_charge_intent`、`fnb_room_charge_intent`、`fnb_fee_*` 2、`fnb_return*` 3 | 账单是订单的营业视图，结账与退货应走零售订单，餐饮只留“账单与桌台、批次的关系” |
| 门店通用能力（约 16） | 班结 `fnb_cash_*` 4、`fnb_close_*` 4、`fnb_business_day`；离线下单 `fnb_offline_*` 6 | 零售收银同样要交班、日结、离线，**错域** → 零售 / 平台基础 |
| 与库存重叠（约 15） | `fnb_stock_*` 12、`fnb_production_consumption(+line)`、`fnb_return_stock_disposition` | → 库存 |
| 与预约重叠（约 6） | `fnb_reservation*` 3、`fnb_capacity_claim`、`fnb_service_slot`、`fnb_service_calendar` | 平台已有资源预约，**重** |
| 与渠道接入重叠（3） | `fnb_channel_*` 3 | 与零售渠道接入 **重** |
| 技术件（约 8） | `fnb_business_command`、`fnb_action_log`、`fnb_sync_batch`、`fnb_edge_lease`、`fnb_external_mapping`、`fnb_integration_exception`、`fnb_config_revision`、`fnb_kds_cursor` | **技** |

**美业 30 张**：预约编排 `bty_appointment*` 10 张（建立在平台资源预约之上）、服务定义 5 张、工单与服务任务 6 张、门店策略 2 张为美业特有；`bty_trade_binding`、`bty_source_*` 2、`bty_service_execution_stock_intent`、`bty_service_execution_fence`、`bty_action_log` 为对接与技术件。重叠少，约 6 张。

合并后的形态：零售、餐饮、美业同在“门店交易库”，共用商品、订单、结账、班结、离线、渠道接入；餐饮约保留 60 张、美业约 24 张行业特有表。
