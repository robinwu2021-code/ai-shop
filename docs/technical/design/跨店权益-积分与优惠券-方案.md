# 跨店权益：积分与优惠券 · 方案

> 状态：**设计待确认** · 上游 [增值服务与分享激励-需求](../requirements/多门店与分享激励-需求.md) · 相关 [ADR-006 积分方案](./ADR/ADR-006-积分方案.md) §2 · [ADR-002 分账](./ADR/ADR-002-结算走微信支付分账.md) · [增值服务方案](./增值服务-多门店与子账号-方案.md)
> 优先级：P0（多门店上线前必须定，否则第一个开第二家店的商家就会问）

---

## 一、一句话

**权益的边界是「经营主体」，不是账号，也不是门店** ——
同一个主体下的几家店，积分与券通用；不同主体之间不通用，哪怕它们由同一个账号管理。

---

## 二、为什么是这个方案

### 2.1 一句话背后的三条线

多门店/多商家上线后，「这张券能在哪儿用」出现了三种可能的边界：

| 边界 | 例子 | 选它会怎样 |
|---|---|---|
| **账号** | 老王管着 A、B 两个主体，A 发的券能在 B 用 | ❌ **钱算不清**：A、B 是两个营业执照、两个结算主体，B 收的钱要拿去抵 A 发的券 |
| **主体** ← 选定 | 张记粮油的券，三家分店都能用 | ✅ 同一个结算方、同一笔钱 |
| **门店** | 文三路店的券只能在文三路店用 | ❌ 顾客不理解 —— 他认的是「张记粮油」这块招牌 |

**关键区分：账号是管理入口，不是权益边界。**
一个账号能管两个主体，不代表这两个主体是一家人 ——
它们可能只是同一个人投资的两门生意，各自独立报税。

### 2.2 它顺带回答了 ADR-006 挂着的问题

[ADR-006 §2](./ADR/ADR-006-积分方案.md) 把「A 商家送的积分在 B 商家花掉，谁承担」
列为上线前必答题，给了三个方案，建议**先 B（商家专属）后 A（全平台通用 + 清算）**。

多门店让"商家专属"这个词第一次需要精确定义。本方案给出的定义是：

> **商家专属 = 主体专属**，而主体下的多门店**天然通用**。

这不需要任何清算：三家分店的钱最终结算到同一个主体账户，
在店 1 送出、店 3 用掉，对账上是同一个口袋左手倒右手。

**跨主体仍然不通用**，ADR-006 §2 的 A 方案（全平台通用 + 清算）不受影响，
将来要做时按原计划做——本方案没有提前消耗那个选项。

### 2.3 被否掉的做法

| 方案 | 为什么否掉 |
|---|---|
| **按账号通用** | 两个主体两本账，B 的钱抵 A 的券，结算对不上（2.1） |
| **按门店隔离** | 顾客认的是招牌不是门牌号。「我在你家另一个店买的积分怎么不能用」是一个无法解释的问题 |
| **门店级独立发券，主体级不管** | 三家店各发各的，顾客钱包里出现三张「张记粮油」的券，分不清哪张在哪用 |
| **积分按门店分账户** | 同一个主体的钱分成三个池子，而它们最终结算到同一个账户 —— 凭空造出对账工作 |

## 三、结构

```
   账号（user_no）  ← 管理入口，**不是权益边界**
        │
   ┌────┴────┐
   ▼         ▼
 主体A      主体B        ← 权益边界：积分账户、券、会员等级都挂这一级
   │         │              互不通用（不同营业执照、不同结算方）
 ┌─┴─┐     ┌─┴─┐
店1 店2    店3 店4        ← 门店：通用。发券/送积分时可**收窄**到指定门店
```

| 对象 | 挂哪级 | 现状 |
|---|---|---|
| 积分账户余额 | 主体 | `pts_*` 已按 `merchant_no`（ADR-006） |
| 积分开关 `points_enabled` | 主体 | 已是（多门店不拆——它是主体的成本结构） |
| 优惠券定义 `mkt_coupon.merchant_no` | 主体 | **已是主体级，多门店自动通用** |
| 券的门店限制 | 新增可选收窄 | ⬜ 见 4.2 |
| 会员等级/权益（将来） | 主体 | ⬜ |

**好消息**：`mkt_coupon.merchant_no` 的语义本来就是主体，
所以「同主体多门店通用」**不需要改任何东西**——它自动成立。
要新增的只有"限定某几家门店"这个**可选收窄**。

## 四、详细设计

### 4.1 积分

| 场景 | 行为 |
|---|---|
| 在店 1 消费得分 | 记到主体的积分账户；`store_no` 记在流水上（用于门店归因，不影响余额） |
| 在店 3 使用 | 可用。余额是主体级的 |
| 积分成本由谁承担 | 主体（结算时扣，ADR-006）。**门店之间不做内部分摊** |
| 门店只读/停用 | 该店**不能核销积分**（等同不接新单），但余额不受影响 |
| 主体被封禁 | 积分冻结，与今天一致 |

**门店之间不做内部分摊**是刻意的：店 1 送、店 3 兑，看起来"店 3 替店 1 买了单"，
但两家店的钱进的是同一个结算账户。做内部分摊等于**在一个口袋里造两个隔间**，
产生的对账工作没有任何外部意义。

> 如果将来商家要给每家店独立核算（加盟场景），那时它们本来就该是**两个主体**。

### 4.2 优惠券

`mkt_coupon.merchant_no` 已是主体级，新增一个**可选**的门店收窄：

| 新增列 | 说明 |
|---|---|
| `store_scope` | JSON 数组。**空 = 主体下全部门店通用**（默认） |

用得上它的场景就一个：**新店开业活动**。
「文三路新店开业，满 50 减 10，仅限该店」——这是真实需求，
而如果没有这个字段，商家只能靠券名写「仅限文三路店」然后在顾客用错时人工解释。

**默认必须是通用**，不是必填：绝大多数券没有门店区分，
把它做成必填等于让每个商家每次发券都要多做一次决策。

**校验落点**：下单时校验券的适用性已有一处（`CouponService`），
门店收窄加在同一处，**不新增一条校验路径**——两处校验券的地方迟早会不一致。

**错误提示要说清楚**：「本券仅限文三路店使用」，不是「券不可用」。
顾客拿着一张看起来能用的券被拒，而系统不说为什么，他会认为是平台的 bug。

### 4.3 跨主体：明确不通用，且要说清楚

同一账号下的 A、B 两个主体，积分与券**互不通用**。

**但必须在端上讲清楚**，否则商家（尤其是同一个老板）会认为是 bug：

| 位置 | 提示 |
|---|---|
| B 端发券页 | 「本券适用于**张记粮油**旗下门店」——用主体名，不用"本商家" |
| C 端券包 | 券卡片上标主体名 + 可用门店数（「张记粮油 · 3 家店可用」） |
| C 端积分页 | 按主体分组显示，**不合并成一个总数** |

C 端积分**不合并成总数**这一条尤其重要：
显示「共 1200 分」然后结账时只能用 300，是最糟的一种体验。

### 4.4 门店归因：余额不分，但要知道是哪家店产生的

积分流水与券的领取/核销记录都带 `store_no`：

| 用途 | 说明 |
|---|---|
| 跨店对比（增值包卖点） | 哪家店发的券核销率高、哪家店的积分兑换多 |
| 活动效果归因 | 新店开业券到底带来了多少人 |
| 争议排查 | 顾客说"我在你家用过"，能查到是哪家店 |

**记录粒度到门店，余额口径到主体** —— 这两件事不冲突，
前者是分析维度，后者是资金边界。

## 五、与增值包的关系

| Plan 档 | 权益能力 |
|---|---|
| FREE（单店） | 积分与券照常，**无门店收窄**（只有一家店，不需要） |
| PRO / CHAIN | 多门店通用 + **门店收窄**（新店开业活动） + 按店的效果对比 |

门店收窄与按店对比属于增值能力——它们只有在多门店时才有意义，
符合[增值服务方案 §2.3](./增值服务-多门店与子账号-方案.md) 的判据
（**增值包里的每一项都必须是单店商家用不上的**）。

## 六、取舍记录

| 冲突 | 让了谁 | 为什么 |
|---|---|---|
| 权益边界：账号 vs 主体 vs 门店 | **主体** | 账号是管理入口不是权益边界；门店边界顾客不理解 |
| 多门店间是否内部分摊积分成本 | **不分摊** | 钱进同一个结算账户，分摊是在一个口袋里造隔间 |
| 门店收窄：必填 vs 可选 | **可选，默认通用** | 绝大多数券没有门店区分，必填等于每次发券多一次决策 |
| C 端积分显示：合并总数 vs 按主体分组 | **分组** | 显示 1200 分却只能用 300 是最糟的体验 |
| 券校验：新增路径 vs 并入现有 | **并入** | 两处校验券的地方迟早不一致 |
| 跨主体通用 | **不通用** | 两本账、两个结算方；ADR-006 §2 的 A 方案留给将来 |

## 七、待确认

| # | 事项 | 建议 |
|---|---|---|
| Q1 | 门店收窄是否一期就做 | 做。新店开业活动是多门店商家的第一个诉求，而它只需要一个 JSON 列 |
| Q2 | 积分流水的门店归因是否一期就记 | 记。**补记历史是不可能的**——当时不记，将来做跨店对比就永远缺一段 |
| Q3 | 同一账号下多主体，C 端是否要提示"这是同一个老板的店" | **不提示**。主体之间的关联是商家的私事，且提示了反而会让顾客期待权益互通 |
| Q4 | 会员等级（将来）跟主体还是账号 | 主体，与积分同口径 |
| Q5 | 门店只读时已发出的券怎么办 | 券仍可在**该主体的其他门店**使用；只有全部门店都只读时才等同主体停业 |
