# TDD-B 端并入小程序

状态：**草稿（待确认）** · 2026-09-03 · **不是当前主线**，主线是接口能力申请
关联：[小程序账号与切换](./小程序账号与切换.md) · [TDD-微信发货信息录入](./TDD-微信发货信息录入.md)

---

## 1. 一句话

把 B 端（商家）作为**分包**并入现有的「虹选好店」小程序，而不是新开一个小程序。
**但它不替代 App** —— 小程序里的 B 端是「随时能看的轻量端」，接单提醒仍然靠 App。

---

## 2. 先摆事实（量过的，不是印象）

```
c-app 小程序产物      1.30 MB / 29 页
b-app                        68 页（c 端的 2.3 倍）
b-app 用到的原生独占能力      几乎为零 —— 全仓只有一处 plus.android，且那处是推送
小程序分包上限                主包 2 MB / 总 20 MB
```

**第三行推翻了一个先入之见**：以为 B 端深度绑在原生上，所以搬不动。
实际不是。2026-08-28 那条「店主用 App」的决定，针对的是
**不给 B 端 H5 申请高德 Web Key**（见 `b-app/.env.local.example`），
不是「B 端离不开原生」。搬迁的技术障碍比想的小。

---

## 3. 为什么合并，不新开

| | 合并进现有小程序 | 新开一个 |
|---|---|---|
| 上线成本 | 加一个分包 | **重走一遍全流程**：认证、备案域名、接口申请、隐私指引、上传密钥、IP 白名单 |
| 身份 | 两端共用一个 openid 命名空间 —— 店主本人既买又卖时不会分裂成两个人 | 同一个人在两个小程序下是两个 openid，**不可合并** |
| 体积 | 分包装得下（20 MB 上限，我们用了 1.3 MB） | — |

2026-09-03 这一天刚把 c-app 迁到新号，全流程走了一遍：认证、备案、密钥、白名单、
接口申请，加上路上三个只在真机暴露的缺陷。**新开一个就是把这一天再过一遍。**

---

## 4. 一个小程序换不掉 App 的地方：主动推送

这是唯一的硬缺口，而它恰好打在 B 端最关键的场景上。

| | App | 小程序 |
|---|---|---|
| 新订单叫店主 | 个推，**随时能推** | 订阅消息：**用户每点一次才换一条**，发完即止 |

订阅消息的配额靠用户点击攒，攒一次用一次 —— 做不到「有单子立刻响」。
**一个不能及时叫醒店主的商家端等于没有商家端**，所以：

- **进小程序**：查订单、看数据、改价格、上下架、核销 —— 店主在外面掏出微信就能办
- **留在 App**：接单提醒。装了 App 的店主拿推送，小程序是补充不是替代

## 5. 设计

### 5.1 分包切分

主包只放 C 端（现在 1.3 MB，离 2 MB 上限不宽裕）；B 端整体进分包 `biz/`。
分包是按需下载的：只逛不开店的用户永远不会下载那 68 页。

⚠️ **主包不许因为 B 端变大**。共享组件（`packages/ui`）已经在主包里，
B 端复用不额外占；但 B 端独有的组件必须留在分包内。
这条要有闸门盯着，否则会一点一点被侵蚀 —— 而超过 2 MB 时的报错是编译期的，
到那时已经不知道是哪一次提交挤破的。

### 5.2 两套令牌共存

后端 `SecurityConfig` 里 `/mp/**` 认 `ctk_`、`/biz/**` 认 `btk_`，
是两条独立的 filter chain。端上同时揣两个 token 可行，但**每一屏要明确用哪个身份**。

混了的症状是「以买家身份调商家接口」→ 401 → 页面空白。
这正是本仓库最常见的那种缺陷形状：不报错、不提示、只是什么都没有。

所以：**token 的选择由请求路径决定，不由「当前登录的是谁」决定**。
`http-client` 按 `/biz/` 前缀取 `btk_`、`/mp/` 取 `ctk_`，页面无需关心。

### 5.3 入口

C 端「我的」页放一个「商家入口」，只对已绑定商家身份的用户显示。
不做独立的启动路径 —— 那会让普通买家在首屏看到一个与他无关的东西。

---

## 6. 风险

1. **类目审核尺度**：B 端含提现与结算，可能触发比纯 C 端更严的审核。
   这个判断不了，得实际提交才知道 —— 所以**不要把它排在关键路径上**。
2. **两端同时上架**：合并后 B 端的问题会挡住 C 端发版（同一个小程序一次审核）。
   这是合并最实在的代价，比体积和令牌都更该先想清楚。

这三件落定、C 端跑顺之后再动 —— 那时加一个分包是纯技术活。

## 8. 不做什么

- 不新开小程序（理由见 §3）
- 不用小程序替代 B 端 App（理由见 §4）
- 不把 B 端做成「小程序优先」—— 它是补充
