# 平台商城全局订单与收退款统计

## 1 场景与边界
统一查看主体额度套餐、门店商城订单，已提交/审核中凭证从队列进入原办理详情。新入口不授予确认、退款、代购权限。本批不部署。

## 2 实施计划与契约
1. 两订单域内部只读查询，MAIN 和显式 ALL/MERCHANT 数据域在 SQL 分页前裁剪；历史订单不依赖门店有效状态。
2. GET /ops/platform-mall/orders、/claims 合并稳定游标（创建时间倒序、ENTITY/STORE、订单号倒序），每域一次有界查询；模型按原读权限交集选择。队列按订单粒度。
3. GET /ops/platform-mall/cash 按 [fromInclusive,toExclusive) 成功发生时间扫描平台收款账本，最大366天；单请求只读可重复读快照，500行批次。域内解析订单归属，不跨库联表。
4. 只认已验证 SUCCESS PAY/REFUND，不以订单金额/退款工作流统计。币种、模型和 NORMAL/UNMATCHED/CLOSED_ORDER 分组，最小单位为十进制字符串。退款沿用原收款分类。
5. 可见订单无效/冲突账本明确报冲突；ALL且有两域权限时无法归属亦报冲突。不可见事实不暴露诊断。依赖不可用不能回落零收入。
6. 新四菜单只读授权点默认仅 SUPER_ADMIN；原模型权限仍需满足。旧办理接口补显式数据域。
7. 本地来源 SQL、权限、游标、多币种资金、UI合约验证；未验证MySQL9实库要明确记录。

## 3 一致性与限制
汇总覆盖整个窗口，不是当前页。账本单请求一致，源归属独立读取；跨请求不是持久快照。关闭订单分类不能推断逾期到账。历史已删除门店可出现在索引，旧办理详情可能不可用。平台商城账本目前归 ai-shop 内嵌pay，独立near-pay不承载。
