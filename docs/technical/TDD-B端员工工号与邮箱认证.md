# B 端员工工号与邮箱认证

## 0. 验收条件

- 员工可通过配置的邮箱完成验证码认证，工号与账号密码解析到同一门店员工身份。
- 现有手机号、老板身份、门店多角色及权限数据库继续可用。
- 目标原生 POS 的账号、员工表单和角色目录按真实能力显示。

## 1. 契约

沿用员工、角色与统一登录接口。工号登录在统一身份验证中使用 EMPLOYEE_PASSWORD 和 companyCode。首版公司代碼直接使用主体编号。已配置邮箱通过现有验证码完成首次归属绑定。首版工号保留前导零，分配后固定。员工可先建档再逐店授权，提交首店角色时与账号建档同事务。

| 接口 | 变更 |
|---|---|
| `POST /biz/staff` | 新增 `loginEmail`、`employeeCode` 和首店 `storeNo`、`role`。旧手机号请求继续沿用原行为 |
| `GET /biz/staff` | 回传 `loginEmail`、`employeeCode`、`emailVerified` 并沿用门店角色清单 |
| `POST /biz/auth/identities` | `EMPLOYEE_PASSWORD` 用 `companyCode` 加 `principal` 工号和 `credential` 密码认证。票据仅可进入匹配的员工身份 |
| `POST /biz/auth/identities` | 已登记联系方式通过 `EMAIL_OTP` 或 `PHONE_OTP` 校验后，带 `newPassword` 可为工号设置密码。已配邮箱时走邮箱验证 |
| `POST /biz/auth/identities/enter` | 首次通过指定邮箱进入员工身份时存储已验证身份的关联。多人多主体在客户端选身份 |
| `POST /biz/staff/{mchAccountNo}/store` 与角色接口 | 复用既有授权、撤权与角色目录。草稿及退役权限的入口显示灰色 |

原生 Android 手机输入沿同一输入框识别台湾、中国大陆、阿联酋。显式国际码优先。本地号码完成后按常见格式确认，无法识别时提示补国际码。大陆按现有认证使用国内 11 位值，台湾和阿联酋按国际化号码提交。

## 2. 实施

1. 通过 V703 在现有 MchAccount 追加挂接字段和主体内唯一键，保持既有账户与角色行。
2. 扩展员工建档和统一登录。门店范围、角色和会话解析复用原服务。
3. Android 复用登录、员工表单及角色页。新功能保持灰态直至可用。
4. 定向验证迁移、认证、权限和 Oscar 目标门店。

## 5. 实施及验收证据

- MySQL 9 真实统一身份测试覆盖邮箱和工号的同一员工、公司边界及停用后票据失效。员工创建和首店角色原子性、重码保护和 OWNER 角色拒绝由 `MerchantRoleFlowTest` 验证。叠加线上预约基线后的定向构建通过 17 项。
- 原生 Android 认证及员工相关单测通过，模拟器分别显示台湾、中国大陆及阿联酋的自动识别结果。
- 首期员工以验证码自助激活。更换已绑定邮箱／工号及管理端邀请信重发保留灰态。现有员工的原手机号和角色不迁移。
