# nearshop 双域名渐进迁移

状态：已实施并验证。日期：2026-11-11。依据：用户要求新增 nearshop.umeshop.ai，支付 H5 之外逐步迁移，当前两个域名并行。

## 0 需求与验收

| 需求 | 落点 | 验证 |
|---|---|---|
| 新旧域名均能访问现有非 H5 入口 | 201 TLS 虚拟主机、166 独立虚拟主机 | HTTPS 证书、页面和静态资源逐项比对 |
| 支付 H5 保留原域名 | 原 twpay 配置与支付 URL 不改，新域名 H5 路径临时转回旧域名 | 原 H5 200、新域名 H5 307、回调原配置哈希不变 |
| 登录/API 在新域名可用且保留鉴权 | API/OPS 额外 CORS 来源追加新域名 | 两域 OPTIONS、匿名受保护接口、非法来源拒绝 |
| 后续逐步改默认入口 | 保留同名路径，不跨域强制跳转现有管理入口 | 迁移矩阵与回滚记录 |

## 1 方案与边界

采用新增独立虚拟主机、沿用路径的方式。直接把旧域名整体重定向不符合双入口并行；整体复制支付站点会把 H5 一并迁移，因此不采用。

第一批开放 `/ops-shop/`、`/shop-api/` 已公开路径、`/oms/`、受限 `/oms-api/` 以及应用签名验证的商城凭证路径。根路径临时跳转 `/ops-shop/`。新域名 H5 页面路径使用 307 返回 twpay；支付 URL、支付回调、Apple 域名验证和支付服务容器保持原配置。

独立库存当前是内部受控服务，没有已发布的独立 Web 入口，本批不直接把机器接口或管理接口暴露到公网；已有库存能力继续经商户 API。后续独立入口须按其正式认证方案接入。

201 复用已经覆盖新域名的通配证书。两个域名分别有浏览器存储和登录会话，新域名需要重新登录。不传递旧域名浏览器令牌，不修改原二维码和已冻结支付链接。

## 5 验证与回滚

使用真实 nginx 配置检查和无凭据 HTTP 验证；本批不改应用代码、数据库或业务状态，不重复运行业务全量测试。CORS 追加时不放开通配来源，保留原应用所有环境配置、上传挂载、资源限制和运行制品。

任一配置检查失败则不加载；新虚拟主机验证失败则撤下新增配置并平滑加载。容器重建失败按保存的原配置及实际运行 JAR 回退。支付服务与库存容器不重启。私有容器 inspect 备份不进入仓库。
