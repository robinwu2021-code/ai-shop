## §0 对账一 · 需求 → 设计

需求原文（用户，2026-10-08）：「通过快递 100 来查询物流信息」（此前调研结论：微信免费那条路要小程序微信支付有交易、且只能在小程序里展示；快递鸟免费版不含顺丰/中通/韵达）。

实证：线上 `SHOP_EXPRESS_TRACE_DEFAULT` 未配 → 默认 `stub`，**买家看到的物流轨迹一直是空的**；
已写好的真实 provider 只有圆通直连，线上也没圆通凭据。快递100 的 key 已在线上（寄件用）。

| AC | 一句话 | 落点 |
|---|---|---|
| AC1 | 在途运单由定时任务（每 30 分钟、每轮 ≤300 单）经快递100 实时查询刷新轨迹，买家/商家/运营看到真实轨迹 | `Kuaidi100TraceProvider` + 默认 provider 切 `kuaidi100` |
| AC2 | 顺丰、丰网等**必须带手机号**的承运商也查得到 | 轨迹端口加带手机号的重载；轮询从子单取收件人手机号 |
| AC3 | 快递100 的原始状态归一成统一五档（揽收/运输中/签收/异常/未知），节点按时间倒序 | provider 内映射 |
| AC4 | 缺授权码 / 接口报错 / 查无此单：这一单本轮空着，不编造推进、不抛、不拖垮别的单 | `available()` + 解析失败返回 empty |

**孤立项**：无。

## §1 现状

- 轮询：`LogisticsTracePollingJob`（`shop.job.enabled=true`，线上已开）→ `LogisticsServiceImpl#refreshInTransitTraces` →
  `LogisticsTracePort.trace(storeNo, carrier, waybillNo)` → `LogisticsTraceRouter` 按门店路由表挑 provider →
  节点按（时刻+文案）去重追加进 `ful_shipment_trace`，状态推进 `ful_shipment.status`。
- 承运商码是**微信 delivery_id**（`ExpressCompanies`），快递100 用另一套公司码，需要映射。
- 收件人手机号在 `ord_sub_order.receiver_phone`；`ful_shipment.receiver` 只有名字。

## §2 方案

### 契约变更
- 配置：`shop.express.kuaidi100.customer`（`KUAIDI100_CUSTOMER`，快递100 后台「授权信息」里的 customer）；
  上线时线上设 `SHOP_EXPRESS_TRACE_DEFAULT=kuaidi100`。
- SPI（内部，非对外契约）：`TraceProvider#trace(carrier, waybillNo, phone)`、`LogisticsTracePort#trace(storeNo, carrier, waybillNo, phone)`、
  `FulfillmentStatsPort#receiverPhonesOf(subOrderNos)` —— 均带默认实现，老调用方不动。
- 端点 / 库表 / 权限码 / i18n：无。

### 实现
| 动作 | 路径 | 说明 |
|---|---|---|
| 加 | `channel/express/trace/Kuaidi100TraceProvider.java` | `poll.kuaidi100.com/poll/query.do`，表单 `customer` + `sign=MD5(param+key+customer)` 大写 + `param`；`param={com,num,phone,resultv2:"1",show:"0",order:"desc"}` |
| 改 | `TraceProvider` / `LogisticsTracePort` / `LogisticsTraceRouter` | 带手机号的重载，默认退回老签名 |
| 改 | `FulfillmentStatsPort(+Impl)` | 批量取子单收件人手机号（系统作业，绕域） |
| 改 | `LogisticsServiceImpl#refreshInTransitTraces` | 取手机号、传下去 |
| 改 | `application.yml` | `customer` 配置项 |

### §3 决定
- **承运商映射只放核验过的 14 家**（与 `ExpressCompanies` 一一对应）：快递100 公司码以其官方编码表为准；
  不认的承运商 `covers=false`，路由打日志后这一单空着。
- **手机号传全号**：快递100 要求顺丰类必填收/寄件人手机号；不必须的承运商也传（它会忽略）。日志里不打手机号。
- **状态按快递100 主状态码映射**：1 揽收 → PICKED；0 在途 / 5 派件 / 7 转投 / 8·10·11·12 清关 → IN_TRANSIT；
  3 签收 → SIGNED；2 疑难 / 4 退签 / 6 退回 / 13 清关异常 / 14 拒签 → EXCEPTION；其余 → UNKNOWN（不动当前状态）。
- **计费与频率**：按单计费、同一单在计费周期内多次查询只扣一次；快递100 要求同一单查询间隔 ≥ 30 分钟 —— 轮询本来就是 30 分钟一轮，不另加缓存。
