## §1 现状与影响面

### 现状：16 行平铺，最贵的首屏给了最低频的三行

2026-10-09 在 b-app-mock（5175）实测，`pages/me/index` 共 **16 行**：

```
账户信息   用户名(未设置) · 登录账号(13800138000) · 登录密码(去设置)   ← 占首屏约 1/3
          收入 · 结算 · 员工 · 收款设置
          资质证照 · 证照与账户(2 张证照) · 套餐(孵化版·门店1/1) · 经营数据
          消息(2) · 外观与语言 · 商家帮助 · 版本(0.5.42)
          退出登录
```

这三行是全页**最低频**的：用户名一年改一次、登录账号**只读**、密码偶尔改。
而它们压着「收入 / 结算 / 员工 / 收款设置」这些每天要用的，首屏只剩 6 行功能。

### 这一页的既有定位（代码注释里，不要推翻）

`me/index.vue` 的注释写着：

> 「我的」是账号维度的东西 —— 密码、语言、套餐；门店是经营维度的，
> 两处都摆一个门就又回到「同一件事三个入口，人记不住走哪个」

所以**不是把账号信息赶出去**，而是把它从「平铺三行」收成「一行入口 + 二级页」——
定位不变，层级变了。同一段注释还写着「这里没有门店入口」，本次也不加。

### 可直接复用

- `sh-scaffold title-key="…"` 是二级页的标准外壳（`deposit/index.vue` 同形）。
- 两个 handler（`editDisplayName` / `editPassword`）连同 `hasPassword` 的加载**原样搬**，
  不重写。它们各自的注释记着为什么这么写（「设过是修改、没设过是设置，
  含糊成一个『密码』会让人不知道点进去会发生什么」），一并带走。

### 会被改到的

`pages/me/index.vue`（删三行、加一行入口、搬走两个 handler）、`pages.json`、
`shared/nav.ts`、三份 i18n、`ui-catalog.json`。

### 明确不受影响

端点（`mSetDisplayName` / `mHasPassword` / 改密码三个接口一个不动）、权限码、
「我的」其余 13 行、工作台、底部 tab。

## §2 方案

### 模块设计

| 动作 | 路径 | 说明 |
|---|---|---|

### 入口那一行显示什么

```
账号          <用户名 或 登录手机号>  ›
```

**带摘要不是装饰**：这一页原本就有「多店 / 多人时分不清此刻是哪个身份」的问题
（`me.account` 那一行的注释写着这是它存在的理由）。收进二级页之后，
如果入口只写「账号 ›」，那个问题就被重新制造出来了 ——
所以摘要里要能看出「我是谁」：有用户名显示用户名，没有就显示登录手机号。

### 明确不做

- **「资质证照」与「证照与账户」重名**：真问题，但它牵涉主体/资质两个域的叫法，
  且「账户」那半与出款链路有关（`mch_payout_account`）。单独处理，不搭车。
- **把「外观与语言」也收进去**：它是偏好不是身份，且入口已经自带摘要
  （「配色 · 明暗 · 语言」），收进去只会多一跳。
- **动其余 13 行的排布**：本轮只做用户要的那一件。
