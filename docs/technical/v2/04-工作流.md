## 1. 五个挂接点（不在这张表里的接触方式都是违规）

| # | 挂接点 | 方向 | 语义 |
|---|---|---|---|
| A1 | `place` | 工→基 同步 | 工作流唯一的开单入口（幂等键） |
| A2 | `markPaid / settle` | 工→基 | 钱的确认；混合先逐笔 `ord_payment` 再 settle |
| A3 | `verify / 计量回写` | 工→基 | 核销、发货、称重/计时差额 |
| A4 | `cancel / 售后` | 工→基 | 逆向（退行含 modifier 金额；GIFT 不退钱） |
| A5 | 事件（Created/Paid/Cancelled/Refunded/Fulfilled） | **基→工 异步，唯一回路** | outbox at-least-once，工作流自己保证幂等 |

## 2. 一条工作流必须声明的六件事

对象与状态机 ｜ **开单时机**（即时/延迟/资产早付 —— 判据：下单动作是否已代表真实交易意向）
｜ 付款时点组合 ｜ 同步点映射表 ｜ 超时与逆向策略 ｜ requiredCapabilities + 打印场景。

## 3. 基础工作流 Engagement（经营单据）

台账、工单、收银票的公共骨架：**聚合 1..N 张订单、占用若干资源、最终结清或作废**。

相位机（**final，子类不可改**）：`OPEN ↔ SETTLING → CLOSED | VOIDED`
骨架守卫：SETTLING 拒挂新单；close 需收款足额或全部订单已付；void 仅限无已付订单；
**单据不存金额，应收现算**。

**受限继承三规**：不能加相位/加边/改守卫；行业只能细分 OPEN 子态与特化终态；
钩子不许碰钱与订单状态（SPI 可见性保证）。

## 4. 三个行业工作流

| 子类 | 继承自 Engagement | 自有内容 | 子态映射 |
|---|---|---|---|
| `DiningCheck`（台账） | ✅ | 桌号、payMode、并台、**制作行（内容物，非相位）** | `MERGED`→终态特化 |
| `ServiceWorkOrder`（工单） | ✅ | 预约引用、技师行 | CREATED/SERVING/FINISHED→OPEN 子态 |
| `CashierTicket`（收银票） | ✅ 基座最小实现 | 无（超 30 行=抽象脏了） | 恒等 |
| `Appointment`（预约单） | **❌ 不继承** | 持 hold、可转工单 | 判据：不聚合订单、不结算 |

## 5. 六条组合定律与闸门

| 律 | 闸门 |
|---|---|
| L1 单向依赖 | ArchUnit：行业包禁 import 订单实体 |
| L2 金额/状态真源在基础流 | 行业表出现金额列即拒 |
| L3 同步点幂等 | 重放测试 |
| L4 多单各自独立 | 三轮加菜三单独立可退 |
| L5 工作流可缺席 | `-Pcore-only` 零售全绿 |
| L6 不得要求基础流加状态/边 | 状态机图完整性测试锁死；检验问题：**零售也需要吗** |
