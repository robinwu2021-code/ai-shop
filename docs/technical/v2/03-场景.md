# 03 · 场景

> 本层回答：**用户与商家实际怎么走**。每行业三个代表场景；28 场景全量见
> [场景手册](../design/三行业场景工作流手册.md)。

**记法**：`[A1..A5]`=同步点（开单/钱/履约/逆向/事件）· `⟨…⟩`=资源动作 · `⊗`=逆向分支

## 零售（= 基础订单流本体）

**R1 网购**
```
跨店购物车 → [A1] place（一主单拆 N 子单）→ [A2] 支付 → 发货/签收 [A3] → 完成 → 结算
⊗ 超时未付关单；售后按商品售后策略分流
```

**R5 收银台**（V2 补的零售缺口）
```
开单 [A1] (WAIT_OFFLINE_PAY) → 现金+微信逐笔 ord_payment → 足额 [A2] settle(MIXED) → 即时完成
```

**R6 称重生鲜**
```
截单前 [A1]+[A2]（标称量出价）→ 到货实称 [A3] 差价落行 → 核销 → 完成   ⊗ 超允差人工确认
```

## 餐饮

**F3 正餐后付·多轮加菜**（主流程）
```
⟨开台⟩ 台账 OPEN → { 点单 → [A1] place(WAIT_OFFLINE_PAY) → 入厨（不等支付）}×N轮
→ 结账 SETTLING（拒加菜）→ 逐笔收款 → 足额 [A2] settle → [A5] 结台 ⟨释桌⟩
⊗ 退菜：钱已收走售后 [A4]（含加料金额）；未收 cancel+重下。台账未结不自动取消
```

**F5 外卖**（无台账，基础流全程）
```
[A1] place(WAIT_PAY) → [A2] → [A5] 入厨 → READY → 基座配送 [A3] → 签收（餐饮只贡献"入厨"）
```

**F7 包间预定 → 转开台**（两种占用接力）
```
⟨hold 时段(ROOM)⟩ → 到店 ⟨confirm→release⟩ → ⟨occupy 开放占用⟩ 开台 → 进入 F3
```

## 服务业

**B2 线上预约·到店付**（订单延迟诞生）
```
⟨hold bySpan(资源×时长+缓冲)⟩ → 预约 CONFIRMED（无订单！防幽灵单）
→ 到店 → 开工单 → [A1] place → 服务 → 收款 [A2] settle → 提成
```

**B5 卡客耗卡**（"早付过"）
```
开工单 → [A1] place（原价快照=提成基数）→ 服务 → 完成
→ [A3] verify + 扣次(基座流水) + [A2] markPaid(TIMES_CARD, 实收0)
```

**B9 逆向**
```
改约：⟨先占新→再释旧⟩；取消：按提前时长免费/收费；爽约：Job 置 NO_SHOW → ⟨release⟩ → 按门店规则
```

## 跨行业同构（为什么一套能吃三个）

| 机制 | 零售 | 餐饮 | 服务业 |
|---|---|---|---|
| ord_payment+settle | 收银台 | 结账 | 收款 |
| verify 核销 | 自提 | 自取叫号 | 耗卡核销 |
| 计量补差 | 称重 | 海鲜按斤 | （KTV 按时·记账） |
| ⟨hold⟩→place | 预约自提 | 包间预定 | 线上预约 |

**28 个场景全部由 A1–A5 + 资源原语组合而成，无一需要新同步点或新订单状态。**
