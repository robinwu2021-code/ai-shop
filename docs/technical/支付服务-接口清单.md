**全篇通用约定**（各节不再重复）：

- 对外只出现**业务号**（`payOrderNo`、`payRefundNo`、`payMerchantNo`、`storeRef`…），数据库 `id` 不出站。
- 金额一律**最小货币单位整数** + 币种（`amountMinor` + `currency`），不传小数。
- 时间一律 ISO-8601 带时区偏移（UTC 存储）；签名头里的 `X-Timestamp` 是毫秒时间戳。
- 写接口接受 `Idempotency-Key`（开放 API 与 `outOrderNo` / `outRefundNo` 二选一）。
- 响应：开放 API 与收银台用 `{code, message, data, requestId}`；商家端、运营端沿用平台统一包装。
- 每次请求都有 `requestId`（入站带 `X-Request-Id` 则沿用，否则生成），出现在响应、日志、`pay_api_request_log` 里。

## 2 内部系统

### 2.1 内嵌 Port（今天的生产形态，A1）

| Port | 方法 | 调用方 | 说明 | 状态 |
|---|---|---|---|---|
| `spi.pay.PaymentPort` | `createPayment` · `queryPayment` · `closePayment` · `requestRefund` | 商城订单、餐饮结账 | 支付的唯一入口；退款必须带商家操作员（`onBehalfOf`） | ✅ I3 |
| `spi.pay.PaymentPort` | `startPayment` | 同上 | 选方式 → 选路由 → 冻结快照 | I5（I3 / I4 转来） |
| `spi.pay.PayMerchantQueryPort` | `routeOf` · `collectableRoutes` · `routeByPayMerchantId` · `capabilityOf` | 交易下单、退款、查单 | 收款路由唯一解析口，只按门店绑定 | ✅ I4 |
| `spi.pay.PayMerchantMirrorPort` · `PayMerchantReadSwitch` | — | 商户域 | 双写挂钩、读切开关（迁移期） | ✅ I4 · I5 退役 |
| `spi.settle.SettlePort` | 收款账本、结算 | 交易域 | 旧入口，收款方法标废弃，逐步转调 `PaymentPort` | ✅ 收敛中 |

**支付反过来依赖核心系统的 Port**（pay-svc 独立那天每一个都要变成 HTTP 客户端）：登记在 `backend/known-pay-reverse-deps.txt`，

### 3.2 webhook（我们 → 第三方，I5）

| 项 | 约定 |
|---|---|
| 事件 | `payment.succeeded` · `payment.closed` · `refund.succeeded` · `refund.failed` |
| 地址 | `pay_app.webhook_url`（**只允许 https**，登记时校验，禁止内网 / 回环地址） |
| 签名 | 头与请求签名同构：`X-App-Id` · `X-Timestamp` · `X-Nonce` · `X-Signature`（用该接入方密钥）；体含 `eventId`（`event_key`，接收方据此去重） |
| 重试 | 非 2xx 或超时（5s）→ 指数退避，≥ 24h 后 `GIVEN_UP`；运营端可手动重推；每次投递写 `pay_biz_notify_attempt` |
| 语义 | **至少一次**；接收方必须按 `eventId` 幂等，并以查单结果为准 |

| `POST /payments/{no}/card` · `/customer-code` · `/qr` · `GET /payments/{no}` · `POST /payments/{no}/cancel` | 刷卡、扫顾客码、屏显码、轮询、关前查单 |
| `POST /payments/{no}/void` · `POST /payments/{no}/refunds` | 撤销 / 退款（店长授权码 + 单终端日限额 + 复核规则） |
| `POST /batches` · `GET /batches/{bizDate}` | 日结 |

**卡数据红线**：终端 App 与服务端任何位置都不出现明文卡号 / 磁道 / PIN（只透传渠道读卡套件加密后的数据），否则整套系统进 PCI DSS 范围。
