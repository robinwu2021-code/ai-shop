- 新增经营主体、独立PM及资料修订本次已部署166：宿主V648、PAY V81/V82；具体制品及运行验证由本批发布记录标识。

状态分四层记录：**代码实现 → 验证范围 → 目标部署 → 真实业务验收**。下面20项是基础工作包，不是20个全部待开发功能，也不提供未经重新估量的人日/完成率。旧25项跨行业总台账继续保留；本清单通过“对应旧任务”引用，不另建重复业务真源。

| 批次 | 工作包 | 先交付什么 |

| A 真实联调入口 | BF01–BF05 | App可访问环境、固定版本、受控店主/员工/多店样本、真实登录切店与门店权限 |
| B 主体与支付主链 | BF06–BF12 | 管理空间及主体/PM关系；补新PM资料修订入口；按闭包发布，再验平台资料、独立PAY进件/N2与实际可收款 |
| C 通用完整性 | BF13–BF16、BF20 | 账号安全生命周期、套餐能力、资金只读、跨模块恢复及发布运维；有独立条件的可穿插推进 |
| D 库存合同准备 | BF17、BF18 | 补真实owner/档案、原单恢复/退货远程合同与N1归属协议；实现准备不代表writer已翻转 |

BF07与BF08是同一主链：先按既有创建合同补资料修订缺口，再统一复核待发布闭包；不为了“先发布创建页面”多做一次缺前置的发布。真实收款按指定渠道/门店受控验收，不能用创建成功、APPROVED或LINKED替代ready。

## 基础对象必须分清

| 对象/字段 | 含义与约束 |
|---|---|
| USR / MCH | 个人账号/员工身份；同ref不同类型不能混权，无店MCH仍是员工 |
| 门店storeNo与当前entityNo | 来自实际目录/上下文；切店是切请求上下文，不是设默认店 |
| 独立经营主体operatingEntityId | 新增账号侧经营资源，不能直接当法定证照、管理空间或PAY商户 |
| 法定资料/证照及legalSubjectId | 与经营实体关联但不等同；旧mch_entity领域不在本次重命名 |
| managementNo | 独立管理空间及资源授权，不从当前门店推定总部权限 |
| pay-service.merchantRef / memberships.merchantNo | 独立PAY平台商户，供X-Merchant-No及真实typed成员核验 |
| N2 claim.payMerchantNo | 认领关联的渠道账户编号；不能拿它覆盖前一行PAY平台商户作用域 |
| inventory owner/writer | 权威库存归属，必须冻结在原业务及回执里；历史恢复不跟随当前配置换owner |

这些区别要体现在API清单、App模型与验收断言中；不能只靠编号前缀或名称猜测对象。
