# 运营端营销四个列表：修完分页壳之后露出来的东西

> 2026-08-11 · 起因是修 `ops-pagination` 守卫报的 5 个端点，改完在浏览器里打开页面才看见。

## 一、先说已经修好的

这 5 个端点返回裸数组，而 ops-web 所有列表页按 `{records,total}` 渲染 ——
**接口 200、数据几十条、页面显示「暂无数据」，控制台一条错误都没有**。

`/ops/groups` `/ops/quotes` `/ops/coupons` `/ops/campaigns` `/ops/msg-templates`
全部包上 `PageData.ofAll`，守卫恢复绿。

值得记一笔的是：这条守卫是 `ac0ca6f`「十个列表端点返回裸数组」时立的，
**而它红着的这段时间里，又新增了 5 个端点重犯同一个错**。
守卫拦住了记录，没拦住行为 —— 因为没有人把它跑绿。
**长期红着的守卫等于没有守卫**，它只会训练人忽略它。

## 二、然后露出来的：页面能显示了，但显示的不是它要的东西

页面从「空」变成「有行」，于是错配第一次可见。

| 端点 | 分页壳 | 契约 | 性质 |
|---|---|---|---|
| `/ops/msg-templates` | ✅ | ✅ 字段全对 | 好的 |
| `/ops/quotes` | ✅ | ⚠️ 3 个字段名漂移 | 同一对象，改名即可 |
| `/ops/groups` | ✅ | ⚠️ 4 个字段名漂移 | 同一对象，改名即可 |
| `/ops/coupons` | ✅ | ❌ **不是同一个对象** | 要建后端能力 |
| `/ops/campaigns` | ✅ | ❌ **不是同一个对象** | 要产品先定 |

### 一个共同的根因：运营端接到了 C 端的 VO 上

`GroupBuyVO` 带 `joined` / `isOwner` / `neighborPickup`，`QuoteVO` 带 `chosen`，
`CouponVO` 带 `received` / `remain` —— **这些字段是给买家看的**
（「我参没参团」「我领没领券」）。运营端要的是治理视角：谁发的、发了多少、超没超预算。

一个 VO 同时服务两端，就得同时长出两套字段，而先写的那套会定下命名口径。
于是运营端要么将就，要么像现在这样对不上。

### coupons：字段几乎全不一致，且有 4 个后端根本没有

| ops-web 期望 | 后端返回 |
|---|---|
| `name` / `value` / `threshold` | `title` / `faceMinor` / `thresholdMinor` |
| `validFrom` / `validTo` | `startAt` / `endAt` |
| `budget` `issuedAmount` `issued` `redeemed` | **没有** |

实测页面上直接渲染出 `undefined / undefined`（已发/已核销那一列）。

**预算与发放统计是券治理的核心** —— ops-web 页面上那句提示写着
「预算是唯一挡住『发着发着超支』的地方」，而后端没有这个字段，
也就是说那道闸门现在**不存在**。这不是显示问题。

### campaigns：两个不同的领域对象被一根路径连着

ops-web 自己的类型注释已经写清楚了（`lib/types/marketing.ts`）：

> 这里的 `Campaign` 是**平台投放的营销场次**（带 `position`，秒杀场按位置分组做重叠校验），
> 由运营建，**后端还没有这个对象**

而后端 `/ops/campaigns` 返回的是**店铺级活动**（`entity_no NOT NULL`，商家自己建的
COUPON / FULL_CUT / FLASH / BUY_GIFT）。

实测表现：类型列一半中文一半原始枚举码 —— `FLASH` 恰好两套都有，
其余三个在 `PlatformSlotType` 里找不到映射，`StatusBadge` 就把码打给了用户。

**这一条我改分页壳之后变得更糟了**：之前页面是诚实的空，现在它显示 7 条店铺活动，
而页面标题与筛选器说的是平台场次。运营会以为这些是平台建的。

## 三、建议

按代价从低到高，前两条可以马上做，后两条要人先拍板：

1. **quotes / groups 字段名对齐**（低）——同一个对象，只是漂移。
   建议给运营端建独立 VO 而不是改 C 端 VO 的字段名：后者会牵动 c-app。

2. **campaigns 先止血**（低）——在后端对象建起来之前，
   这个 tab 该显式标成「未接通」，而不是显示另一个领域的数据。
   诚实的空比误导的有好。

3. **coupons 补治理字段**（中）——`budget` / `issuedAmount` / `issued` / `redeemed`
   需要数据模型支持（发放流水与预算校验）。在它到位之前，
   页面上「预算是唯一挡住超支的地方」那句话是不成立的，应当一并调整措辞。

4. **平台营销场次要不要建**（产品决定）——ops-web 已经把这块 UI 写完了，
   包括位置、场次重叠校验。要么建后端对象，要么把这个 tab 收掉。
   **一个写完了但接不上的页面，比没有这个页面更容易让人以为功能存在。**

## 四、这次的方法论收获

分页壳是形状，契约是内容。**形状不对时，内容错得再离谱也看不见** ——
页面一律显示「暂无数据」，而所有测试层都是绿的：
后端断言自己返回的形状，ops-web 的 mock 按自己的类型造数据，两边各自自洽。

这与 `docs/technical/B端权限端到端用例.md` 记的是同一件事：
**跨端的缺陷只在真的把两端接起来跑时才现形。**
