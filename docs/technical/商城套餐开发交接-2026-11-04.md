- 独立四模块：`backend/commerce/commerce-api`、`commerce-core`、`commerce-persistence`、`commerce-spring-boot-starter`。API 仅 JDK，内核不依赖宿主；宿主经公开契约适配。

- 同店数字变更共用唯一占用，重复请求与并发不重复生成订单、交付或增加权益。
- 同 code 权益累计；升级保留使用历史与独立未用时长，抵扣和退款保留原始价值来源。
- 业务端访问权益与功能 RBAC 分开；商城恢复入口不要求尚未购买或已过期业务端权限。

## 台湾与线下阶段的业务约束

平台作为收款商户；NewebPay、LINE Pay、JKOPay 均为待真实串接验收目标，不因配置存在而可收费。

商家付款声明不等于到账。运营依据实际收款账户、金额、币种、到账时间、唯一流水及证据核款。拒绝凭证不代表无款，不直接释放订单占用。发出收款指引后，关单须有运营核对及作废栅栏；作废后发现真实来款仍入账，进入异常退款，不补发权益或清除新单占用。

TWD 内部仍为 scale2：`69900` 表示 NT$699.00。新策略整元收付与分摊量子为 100，来源估值和余额保留分级精度。转换价值19950、新价69900时，本次抵扣19900、现金50000、余额保留50。历史订单按原冻结策略回放，不重新定价。

报价有效期保持15分钟，线下订单独立冻结付款截止时间。实际到账在期限前、运营审核在期限后且未作废的订单，须按实际到账事实处理。代客购买使用真实 OPERATOR，买家为可信门店及主体派生的 STORE 归属，不伪造 ACCOUNT 或 SYSTEM。

金额不符的真实款保留在同一资金账本的独立 `MALL_UNMATCHED` 场景，原应付意图不被改写；不自动补差、拆款或发权益。正常款与异常款共用稳定收款账户及银行流水唯一约束。
