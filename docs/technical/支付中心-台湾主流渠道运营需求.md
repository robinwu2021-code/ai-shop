# 支付中心 · 台湾主流渠道的基本运营需求

> 2026-11-21 · 用户：「先整理基本的需求……不要那么多，只针对台湾市场的几个主流进行管理即可。」
> 口径：运营端解决运营管理问题，按**查看、审核、处置**整理；只管台湾（TW / TWD）主流渠道。依据 near-pay docs《全渠道接入节点与剩余任务-2026-11-20》。

## 1. 范围：管哪几个渠道

| 渠道 | 产品 | 现状（near-pay 11-20） |
|---|---|---|
| 蓝新 NewebPay | 信用卡一次付清（MPG，H5 / API） | 正式在用：收款、查单、退款受理；退款「自动完成」还缺渠道的可信完成证明，暂由人工确认 |
| 蓝新 NewebPay | Apple Pay（钱包授权，需 H5 会话） | 设备、浏览器与钱包资格待逐项验证 |
| LINE Pay | Online（H5 / API） | 收、查、确认、退、查退已支持 |
| 街口 JKOPAY | OnlinePay（H5） | 收、查、通知、后台补查已支持；普通撤销未开放 |
| 街口 JKOPAY | POS（终端扫顾客码） | 已实现，待真实门店 POS 验收 |

**不在本期管理范围**：其它市场渠道（微信、支付宝、PayBy、易特付等）、蓝新 SoftPOS / TWQR / Google Pay / Samsung Pay、icash Pay。页面照常可以看到，但本期不为它们补功能、不做验收。

## 2. 运营要管的事（按业务环节）

| 环节 | 查看 | 审核 | 处置 |
|---|---|---|---|
| **商户与进件** | 商户档案、资料版本、蓝新进件进度 | 商户资料变更、进件提交（双人：申请人不能自审） | 退回补件、驳回 |
| **渠道账户** | 每个商户在蓝新 / LINE Pay / 街口的账户、核验状态、开通的产品 | 账户核验、恢复收款（走审批） | 暂停、只退不收、开 / 关产品、换凭证 |
| **门店收款** | 门店绑了哪个渠道账户、实际能用哪些支付方式、收款码 | 换绑（登记 → 审批 → 执行） | 调整支付方式、停用收款码 |
| **交易与退款** | 支付订单、异常交易、退款单、交易流水，按渠道筛 | 退款审核 | 蓝新卡退款人工确认完成、异常单补查 / 关单 |
| **对账与资金** | 对账差异、结算、出款 | — | 认领并关闭对账差异 |
| **监控** | 渠道成功率 / 耗时 / 回调失败告警、请求日志、审计 | 告警规则发布（另一人发布） | 认领、处置告警 |
| **凭证** | 三个渠道的商户密钥是否在有效期、即将到期 | 新版本启用（审批，启用人 ≠ 录入人） | 轮换、撤销 |

## 4. 本期建议只补三件事

1. **台湾主流渠道快捷筛选**：支付订单、异常交易、退款订单、渠道账户列表加「蓝新 / LINE Pay / 街口」快捷筛选，默认市场 TW。
2. **蓝新卡退款人工确认**：退款单里把「待渠道确认」的蓝新卡退款单独列出，运营核对蓝新后台后标记完成（near-pay 现有的退款人工确认能力；若没有对应接口，记为 near-pay 待补）。
3. **渠道健康概览**：在支付中心首页（审核待办旁）给三家渠道各一张卡：近 1 小时成功率、未处理告警数、即将到期的密钥数，点进去到对应页签。

## 5. 需要确认

1. 渠道清单对不对：蓝新（信用卡、Apple Pay）、LINE Pay、街口（线上、POS）？
2. 范围外的渠道，页面上是否要隐藏（比如渠道下拉只显示这几家）？还是照常显示？
3. 第 4 节三件事是否就是本期要做的全部？

## 6. 确认与实现（2026-11-21 用户：「确认，开始做」）

- 渠道清单按第 1 节；范围外渠道照常显示，只是本期不为它们补功能。
- **快捷筛选**：支付订单加「渠道」筛选（蓝新 / LINE Pay / 街口），走 near-pay 订单列表的 `payChannel` 参数。
  - 异常交易：near-pay 列表不支持按渠道筛（只按状态，最多 200 条在内存分页），前端只筛当前页会误导，**不做**，记为 near-pay 待补。
  - 渠道账户：在商户详情里按商户列出，每家只有几条，不加筛选。
- **蓝新卡退款**：shop 的退款列表没有渠道字段，near-pay 运营接口也**没有「人工确认退款完成」**。本期做到：
  - 筛「已发往渠道」时、以及这类退款的详情里，说明要到蓝新后台核对、可从订单补查。
  - 人工标记完成记为 near-pay 待补。
- **渠道健康卡片**：审核待办页头下三张卡。
  - 近 1 小时调用成功率：`/channel-calls` 按渠道 + 时间取总数与成功数。
  - 未处理告警：OPEN + CLAIMED，按渠道范围归类。
  - 30 天内到期的商户密钥：`/credentials` 按密钥类型 + `expiringWithinDays`。
  - 各项按查看权限显示；没有调用时显示「没有调用」，不当成 0%。
- **near-pay 待补**：退款人工确认完成接口；异常交易按渠道筛选。
- **测试**：`tw.test.ts` 4 条；ops-web 全量 160 个文件 1441 条通过；lint、界面规范检查通过。
