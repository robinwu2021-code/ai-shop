## 全局约束

- 复用原商品、订单、定价、税、独立库存和打印owner；不重建资金账。
- 在既有餐饮分支及隔离测试环境执行，Java21、离线Maven；不写生产数据、不提交测试订单。
- 用户要求仅针对相关范围验证，不重复全仓回归；一个修复只重测其受影响用例。
- 已存在测试不等于本轮运行通过；跳过不计成功，MockMvc不冒充整宿主真HTTP或门店验收。
- 本次不执行支付、退款、券储值积分实际扣减，不启用生产报表，不操作真实设备。

## 验收关注点

1. 身份、跨店及伪造参数必须在业务写入前拒绝。
2. 菜单发布、报价、下单必须沿相同冻结来源，复杂组件不可重复计价或扣库存。
3. 版本冲突、幂等重试及UNKNOWN恢复不得创建重复副作用。
4. 退餐、AA、打印及非资金交接不得被误判为付款或资金结清。
5. 厨房队列只接受当前支持的活动状态，终态筛选不得静默返回误导性空结果。

### 当前环境与范围

Java21、离线Maven，测试在本轮专用回环MySQL和MariaDB容器执行。业务、库存、报表使用分开的测试schema；报表另有migrator/writer/reader最小权限账号。集成宿主使用本地纯结构夹具，只导入DDL及迁移历史，没有导入业务行。临时凭据不入库。

本轮没有执行付款/退款、券储值积分资金扣减、生产迁移或生产报表启用，也没有发送真实设备/供应商指令。MockMvc、安全链、真实Service/数据库、typed与真loopback HTTP按证据分别标注。

### 仍需单独验收的边界

- 多数公共接口使用真实Controller、安全链和JSON绑定，业务owner为替身；Service/数据库用例分层验证，不能合并宣称同一请求已贯穿所有真实owner。
- 退餐审批、替换、耗用调整与冲销的状态替身不证明真实数据库CAS并发、库存跨进程或全事务；矩阵逐项保留边界。
- 实际付款、退款、券储值积分扣减、真实打印/播报设备、真实供应商、Keeta及离线写入未验收。
- 生产报表独立数据库、调度和导出仍未启用；本轮隔离环境验证不能代替生产启用验收。
