# 接口响应格式规范（三端统一）

> 真源是代码：包结构 `backend/shop-common/.../ApiResult.java`、错误码 `ErrorCode.java`、
> 客户端处理 `packages/shared/src/net/http-client.ts`。本文是它们的**人读版**，
> 与代码的同步由守卫测试锁住（`packages/shared/tests/spec-completeness.test.ts`）——
> 代码加了错误码而本文没更新，`npm test` 会红。

## 1. 响应包

所有接口（三端、增删改查、成功失败）返回**同一个信封**：

```json
{ "code": 0, "msg": "success", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 成功；非 0 见 §3 错误码分段。**判成败只看它**，不看 HTTP 状态码 |
| `msg` | string | 给人看的提示，已按 `Accept-Language` 本地化。**不用于程序判断** |
| `data` | any | 业务载荷。失败时为 `null`；无返回值的写操作成功时也是 `null` |

为什么不用 `{code, message, data}` + `{list, total}`（neargo 旧契约）：三端与全部 mock
已按本格式落地，改前端的成本远高于后端保留一个 20 行包装类（TDD-backend §12 S4 拍板）。

## 2. HTTP 状态码

**只有 401 用真状态码，其余一律 200 + 业务 code。**

| 场景 | HTTP | 包体 | 客户端行为 |
|---|---|---|---|
| 业务成功 | 200 | `code=0` | 取 `data` |
| 业务失败（库存不足、状态非法…） | 200 | `code=非0` | 按 code 分段处置，toast `msg` |
| 未登录 / token 失效 | **401** | `code=10401` | **清 token、跳登录**（`http-client.ts` 唯一看状态码的分支） |
| 传输失败（断网、超时） | — | 无包体 | `ApiError(-1)`，提示「网络异常」 |

后端发 4xx/5xx 的后果：前端走进 `fail` 分支，拿不到业务错误码，
用户看到「网络异常」而不是「库存不足」——所以业务失败**必须** 200。

## 3. 错误码分段

万位分域。段位不是装饰：客户端按段决定行为，改段等于改前端行为。

| 段 | 域 | 现有码 |
|---|---|---|
| `1xxxx` | 通用 | `10400` BAD_REQUEST · `10401` UNAUTHORIZED · `10403` FORBIDDEN · `10404` NOT_FOUND · `10409` CONFLICT · `10429` TOO_MANY_REQUESTS · `10500` INTERNAL_ERROR |
| `2xxxx` | 交易 | `20001` STOCK_NOT_ENOUGH · `20002` PRICE_CHANGED · `20003` OUT_OF_DELIVERY_RANGE · `20004` ORDER_STATE_ILLEGAL |
| `3xxxx` | 履约 | `30001` ALREADY_VERIFIED · `30002` NOT_THIS_PICKUP_POINT · `30003` ORDER_REFUNDED |
| `4xxxx` | 营销 | `40001` COUPON_SOLD_OUT · `40002` COUPON_NOT_APPLICABLE |
| `5xxxx` | 资金 | `50001` SPLIT_RECEIVER_NOT_READY · `50002` SPLIT_EXPIRED · `50003` WITHDRAW_STATE_ILLEGAL · `50004` WITHDRAW_OVER_BALANCE · `50005` WITHDRAW_BELOW_MIN · `50006` WITHDRAW_REVIEW_NOTE_REQUIRED · `50007` INVOICE_OVER_SETTLED · `50008` INVOICE_TAX_NO_REQUIRED · `50009` TAX_RATE_TOO_HIGH · `50010` WITHDRAW_MERCHANT_BANNED |
| `6xxxx` | 风控 | `60001` RISK_BLOCKED |
| `7xxxx` | 主体与准入 | `70001` INDUSTRY_SUBJECT_NOT_ALLOWED |

约定：

- 加码**只在对应段内递增**，不复用、不删除已发布的码（客户端可能已按它分支）
- `msg` 文案来自 `i18n/messages*.properties`，按 `Accept-Language` 渲染——后端不硬编码中文
- 客户端保留 `-1` 表示「没拿到合法包体」（断网 / 响应不符合契约），后端**永不**下发 -1

## 4. 分页

| 方向 | 形状 |
|---|---|
| 入参 | `page`（从 **1** 起，不传按 1）、`size`（不传按各接口默认，通常 10 或 20） |
| 出参 | `data = { "records": [...], "total": 满足条件总条数, "page": 当前页, "size": 每页条数 }` |

`total` 是**总条数不是总页数**；端上据此判断有没有下一页。不分页的列表接口 `data` 直接是数组。

## 5. 字段口径

| 类别 | 约定 | 例 |
|---|---|---|
| 命名 | camelCase | `merchantNo` |
| 业务单号 | `xxxNo`，字符串，非自增 ID | `orderNo` `goodsNo` |
| 时间 | `xxxAt`，**毫秒时间戳整数**（平台端历史接口暂为 ISO 字符串，向时间戳收敛） | `createdAt` |
| 金额 | `xxxMinor`，**最小货币单位整数**（分），禁止浮点 | `payableMinor` |
| 费率 | **万分比整数**（`platformRate/100.0` 才是百分数） | `2%` 存 `200` |
| 重量 | 克，整数 | `nominalGram` |
| 枚举 | 大写下划线常量 | `WAIT_PAY` |
| 布尔 | `is`/动词/形容词，不用 `flag` | `onSale` `verified` |
| 删除 | 契约禁止 `delete*`，软删除一律 `archive*`/`unarchive*` | `archivedAt` |

**字段名长度**：长名可接受，**当且仅当它携带口径**（单位、计费单元、方向）。
`serviceFeePerItemMinor` 的每一节都在防一次误读（服务费 · 按件 · 最小货币单位）；
缩短它省下的是字节，付出的是有人把费率当金额。反之，不携带口径的长名应当缩短。

## 6. 空值语义

| 情况 | 写法 |
|---|---|
| 可选字段无值 | **省略字段**（TS `?:`）。客户端不得区分「缺字段」与「值为 undefined」 |
| 明确的「无」且有业务含义 | `null`（如 `paidAt: null` = 还没付） |
| 空集合 | `[]`，**不是 null** —— 消费方不用判空两次 |
| 无返回值的写操作 | `data: null` |

## 7. 幂等

创建类写操作（下单等）请求体必带 `idempotencyKey`（端上生成）。
重复提交**返回同一笔结果**而不是报错——弱网下用户会连点。

## 8. 示例

成功（分页）：

```json
{ "code": 0, "msg": "success", "data": { "records": [{ "orderNo": "O20260806001" }], "total": 42, "page": 1, "size": 20 } }
```

业务失败：

```json
{ "code": 20001, "msg": "库存不足，仅剩 2 件", "data": null }
```

未登录（唯一的非 200）：HTTP 401 + `{ "code": 10401, "msg": "请先登录", "data": null }`
