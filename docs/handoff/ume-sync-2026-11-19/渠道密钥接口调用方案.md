## 一、API 变了吗——变了，两处

1. **新增了一次到可收款的端点**（near-pay `ac710c329`）。原来补密钥要逐户走：登记凭据 → 录入 → 核验 → `CREDENTIAL_ENABLE` 两人审批 → 启用 → 绑定 → 开产品 → `CHANNEL_ACCOUNT_VERIFY` 审批 → 核验 → 启用账户。现在一个端点做完全部、且**不经审批**：

   `POST /pay-ops/v2/channel-accounts/{payMerchantNo}/migration-credential`

2. **这个端点曾在迁移窗口内免认证**（near-pay `6ea6f1a40`）——**已于 2026-11-19 关闭**：该端点经 nginx `/oms-api/pay-ops/v2/` 对公网可达，现须带运营会话。以下为当时口径：窗口 = `near-pay.credential.migration.enabled=true` 且 `near-pay.credential.migration.anonymous=true`（166 当前两者都为 true）。窗口内：
   - 不需要运营会话 / 令牌，守卫层直接放行，以系统身份 `SYS-UME-MIGRATION-API` 执行；
   - 不校验数据范围（账户范围由来源证据 `file:ume/` 限定）；
   - 去掉了权限码 `pay:credential:migrate`（`@PreAuthorize` 已移除）。
   - 关掉 `enabled`（迁移完成）即同时恢复会话认证与审批。只有这一条 OPS 路径免认证，其它 `/pay-ops/v2` 不变（无令牌仍 401）。

其余已有接口（商户端 `GET /biz/merchant/payment`、运营端查询等）**没有变**。

## 二、调用方案

```
POST {PAY_BASE}/pay-ops/v2/channel-accounts/{payMerchantNo}/migration-credential
Content-Type: application/json
Authorization: Bearer <运营令牌>（必填，免认证已关闭）
```

- `payMerchantNo`：**渠道账户号**（`pay_merchant.pay_merchant_no`，如 `PM80D58ACC11C044CF`），不是主体支付商户号。
- 请求体（`MigrationCredential`）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `requestNo` | 是 | 幂等号 1..48，固定用 `ume-key-<账户号>`；重试从断点续做 |
| `secret` | LINE Pay 必填 | channel secret，16..512 |
| `hashKey` | 藍新必填 | 32 位可见 ASCII |
| `hashIv` | 藍新必填 | 16 位可见 ASCII |
| `reason` | 是 | 1..255，进审计 |

- 成功：`200`、`code=0`，`data.record.account.status == "ACTIVE"` 即可收款；产品 LINE Pay 开 `LINEPAY_ONLINE`，藍新开 `NEWEBPAY_CARD_ONETIME`、`NEWEBPAY_APPLEPAY_WEB`。
- 失败：业务错 `409 10409`（账户不符合迁移条件，如「非迁移来源账户」）、参数错 `400`；中途 `5xx/超时` 用同一 `requestNo` 原样重试。
