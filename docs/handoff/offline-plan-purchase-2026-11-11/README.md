## 已实现的主链路

|场景|门店商城|主体额度包|
|---|---|---|
|免费|沿用免费权益，不伪造收款|FREE继续免费，无付款单|
|开通、续费|沿用冻结报价/订单及数字权益履约|新增冻结报价、价格、容量、天数、收款版本；同档续费保留已付未用时长|
|升级/跨档|沿用商城已有升级估值规则|有效付费跨档及无到期协议包走运营协商，不自行发明折算/吞剩余权益|
|商家付款申报|私有凭证和申报，独立于资金事实|App报价→购买记录→冻结转账指引→私有凭证→申报；申报不改套餐|
|运营确认|使用订单冻结收款主体；无需手填内部编号|核对实际金额、时间、流水、平台凭证；使用平台资金底座落账，再按主体快照开通|
|拒绝/纠正|既有申报审核|拒绝后可新申报；银行明确拒绝的核款动作终结为REJECTED，可用新动作纠正|
|超时与未知结果|查询原动作，保留原始命令|原购买键/核款命令固定；已提交待恢复不改金额后复用键；付款窗口过后仍可补报/纠正凭证|
|异常/中断|既有资金/履约恢复|ACCEPTED→恢复原核款；款已收而主体/套餐/归属失效转REVIEW_REQUIRED，不覆盖新权益|
|取消|既有对账关闭|商家仅申请取消；运营上传银行核查凭证并对账后形成资金关闭栅栏，之后才CANCELLED；之后发现真实转账仍可申报，LATE进入人工处理不误开通|
|边界隔离|权益归下单门店|额度归原主体；保留override、trial_used，仅恢复plan_suspended店，不恢复商家自行停用店|

资金唯一事实仍为现有 `stl_payment`。新增主体购买表描述报价/订单/申报/动作/证据，不是第二套资金账本。付款和媒体IO均在业务事务外。到账恢复首先识别主体购买单，再交给商城，避免误把主体单当门店商城单。

App 还修正离线购买可用性：只有 `offlineReadiness.available=true` 才显示可购买，线上可支付和缺失状态均不能替代。

## 权限与接口

见 [主体额度包 API](../../api/entity-plan-offline-purchase.md)。商家仅老板 `biz:store:admin`，且选中真实门店；以USR/MCH类型对应的真实老板成员关系为权威，不读取旧owner字段推导身份。运营读沿用商家读权限及数据域；核款须同时有商家处置和线下核款权限；报价维护须system:param:update；关闭须线下作废权限。凭证私有，并绑定订单、原门店、上传人、用途；已登记媒体保留引用。

App入口：我的主体额度包→线下购买与购买记录。运营入口：商家→套餐额度→选中商家抽屉→线下购买与核款。门店商城入口保持独立。
