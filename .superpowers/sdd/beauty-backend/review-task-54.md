## Considered but declined as Task 54 defects

- **Expiry bypass on committed replay:** intentional required behavior, constrained by exact persisted request, original secret, complete claiming identity and fresh permission/active-user facts. New claims retain strict unexpired reference authorization.
- **Allowing authorized same-store staff other than the registering actor:** explicitly required handoff semantics. Registration-key replay remains actor-scoped; claim uses the new staff member's own strict cr1.
- **Unauthenticated legacy internal reference issuance producing nullable namespace:** the unchanged compatibility path may still produce legacy references, but the guest-specific reference gate rejects them. The brief requires strict guest consumption while preserving old reference behavior; no new guest authorization fallback results.
- **Returning REGISTERED/revision 1 from original register replay after claim:** this replays the original immutable response, while get/verify returns current state. It agrees with the explicit replay design and remote registration shape validation.
- **No foreign-owner RPC while holding guest root lock:** direct inspection confirms the calls are before the callback. Permission/user status can naturally change after a preflight snapshot; eliminating that race would require cross-owner locking or a new protocol beyond the authorized brief.
- **Frozen V537 comment labels request_hash as SHA256:** the live implementation uses HMAC as required and current design/report/API documentation state it. This historical schema comment is not grounds to mutate the frozen migration or reject the secure implementation.
- **Nullable namespace CHECK expressions are not a substitute for application authorization:** strict guest consumption explicitly compares both namespace values and fails nulls; application issuance and claim code populate them together. No reachable authorization bypass was found.
- **Generated metadata includes prior existing product/booking entries:** the additions reconcile generated reference inventories; the reviewed implementation does not introduce unrelated product/booking behavior.
- **Global guard failures:** the platform log names OpsPointsInspectionController fully-qualified PathVariable, the `store` top-level package registration, and the historical pay_ent_exception_action parser/schema mismatch. They match the controller's characterized Task54 baseline exclusions. The BM03 JobLockConfiguration omission remains required Task60 cleanup, not a Task54 regression.
- **Deployment gate and key rotation:** actual BM04 deployed-JAR acceptance belongs to Task60, and key rotation/retention is explicitly a subsequent operational concern. This review does not claim either has been completed.
