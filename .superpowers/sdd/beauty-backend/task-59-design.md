## 0. Outcome, boundaries and decisions

Expose only delivered guest/claim, arrival/challenge, walk-in, exception request, appointment OPEN, unassigned OPEN, work-order read, source submit/read/recovery, bill/trace and original-operation query/recovery. Reuse existing Service implementations; web depends on beauty-api, shop-base and shop-base-auth only. Both deployments produce the same public business contract. BM05 execution remains closed; `canStart=false` is preserved even for BOUND historical sources.

No new persistence table or migration. Current beauty V8 / ready 8 / 28 private tables remains unchanged. Shared identity, products, resources, ordinary orders and funds stay HOST-owned. Standalone SERVER has beauty private persistence and real reverse owner adapters. No C purchase/payment or B cash machine method is introduced. Consumer purchase continues at HOST `/mp/checkout/**`; cash continues at the existing HOST authenticated B route.

Decisions and cost:

1. **Chosen:** explicit typed service adapters plus bound replies over existing InternalHttp/HTTP1.1/machine token. Costs: five new Remote services, one reception wire interface, resource-sized SERVER controllers, one reverse checkout adapter and bounded shared response metadata. Benefits: no duplicated state machine; real owner authorization remains authoritative.
2. Bare-VO reuse alone is insufficient: Task52 booking responses have no full request echo. Keep untouched old booking wire compatible, but new BM04 and changed operation query/recovery use bound routes. Do not claim old methods already offer full echo.
3. A second login/token/nonce system or persisted delegation tickets is rejected. Source audit proves the current machine protocol uses only `X-Internal-Token`, not a nonce. HOST authenticates its current session before delegating namespace; SERVER rechecks live business authority. This provides no independent SERVER proof that the HOST session remains live after the HOST accepted an in-flight request.
4. 052/054 need a small core correction because their existing endpoint namespaces differ. §4 defines conservative equivalence, legacy compatibility and races. It does not redesign opening or resource recovery.
5. A small neutral optional error-header extension is proposed in §5.5 for exact safe error parity. It changes no old caller behavior and adds no auth mechanism. Root must explicitly include that surface in implementation release.

### 5.1 Neutral types and canonical binding

Recommended minimal neutral contract (shop-base; no beauty dependency):

- `ai.neargo.shop.spi.security.InternalRequestBinding(int protocolVersion, String endpoint, String action, DelegatedIdentity identity, String entityNo, String storeNo, String targetNo)`.
- `ai.neargo.shop.spi.security.InternalCall<T>(InternalRequestBinding binding,T request)`.
- `ai.neargo.shop.spi.security.InternalReply<T>(InternalRequestBinding binding,String requestDigest,T result)`.
- `ai.neargo.shop.svc.InternalBindings` computes/verifies requestDigest and validates complete schema; receives the actual configured internal token and ObjectMapper. Its constructor accepts absent/blank token without eager hashing or failure so default retail and disabled assembly remain valid; digest use requires configured token and fails closed. `String digest(InternalCall<?> call)` and `void require(InternalCall<?> call, InternalReply<?> reply)` are the exact operations; instance construction `(String token,ObjectMapper json)`. No secret is static/global or logged.
- `ai.neargo.shop.svc.InternalReplyDeserializer` is the contextual typed decoder attached to InternalReply only. Before mapping result to its known generic Java record type, recursively require each declared record component key to be present, including primitive0/false and nullable fields (nullable must be explicitly null). Lists/maps preserve element schemas; missing/unknown envelope keys fail. This prevents omitted primitive money/revision becoming default0. It is not a global retail Jackson setting. Ordinary non-bound old clients remain unchanged.

protocolVersion is integer1. Endpoint is fixed public BAPI identifier, `BM04-ARRIVAL-CHALLENGE`, `BM03-OPERATION-RECOVERY`, or the four fixed `CHECKOUT_*` endpoint identifiers. Action is the fixed §2/§3 action, not arbitrary user input. Both are checked against actual handler route. B has required entity/store; C binding.entityNo/storeNo=null and actorNo is current HOST consumer; actual store/ownership derives from appointment/work-order parent, never C supplied store. targetNo is exact business reference or null where the table says no target. All fields required in wire JSON (including explicit null); unknown keys fail. InternalCall request record must match the precise route type; no Object/Map payload.

Digest input is the entire validated **typed InternalCall**, including binding and all nested original payload fields, raw idempotency key, revisions, map entries, source selection, identity proofs and ordering. Canonical serialization: object keys sorted lexicographically by Java String ordering, arrays retain order, explicit null retained, strings JSON escaped/UTF8 without Unicode normalization, booleans literal, numeric values canonical decimal (`stripTrailingZeros().toPlainString()`, negative0→0); temporal DTO constructors normalize UTC before serialization. No DTO toString is used. A fixed golden byte fixture tests both sender and receiver.

`requestDigest = lowerHex(HMAC-SHA-256(UTF8(internalToken), UTF8("SHOP_BOUND_INTERNAL_V1\n") || canonicalJSON(call)))`.

This reuses the actual machine secret solely to bind a response; it is not an authentication replacement or a nonce/replay-protection claim. A plain unkeyed payload hash is rejected because low-entropy contact/request data could otherwise become a guessing oracle. The HMAC is transient request/reply metadata, never public, never persisted, never logged. All participating processes already require the same machine token. Token rotation can cause an in-flight binding failure/UNKNOWN and clients recover by original operation; no automatic new purchase.

Server recomputes digest from its own decoded typed call and validates endpoint/action/scope/identity/target before delegation. It never echoes a caller-supplied digest blindly. Client compares the complete safe binding plus constant-time digest before accepting nonnull result. This covers every field named in brief: entity/store/realm/kind/actor/op/key/revision/original payload, while secret values themselves are absent from replies. No caller-controlled action dispatch table executes a different handler.
