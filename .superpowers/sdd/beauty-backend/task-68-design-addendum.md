### 2.2 Canonical key and error contract

This lane still permits exactly one actual entity/store group. The resolver nevertheless operates on actual groups, not on the candidate list, so NONE is valid when no activity exists. Require nonnull map; keys/values use existing CheckoutPort reference rules: 1..64 chars, no leading/trailing whitespace, case-sensitive, no silent trim/case-fold. No combined `entity|store` public keys. Raw choices are retained in the frozen command and commandHash; normalized maps are TreeMap copies, not a rewrite of old command bytes.

Allowed key = one of the actual group's storeNo or entityNo. Store key takes precedence over entity fallback. If both target the same group, identical values are accepted and resolve once; different values return BAD_REQUEST, rather than silently discarding contradictory acceptance. A token that ambiguously denotes different group identities returns BAD_REQUEST. Unknown/foreign/store-not-in-this-order key returns ACTIVITY_CHOICE_UNAVAILABLE, including `foreignKey:NONE`. Scope validation precedes looking up activity IDs; no foreign activity details leak. There is no ID-based party or cashier fallback.

| Request for a valid group | Result before quote persistence |
|---|---|
| omitted key | `mode=AUTO`; reject any objectively otherwise-applicable unsupported discretionary offer, then choose maximum supported capped discount; equal amount uses ascending campaign id (the legacy owner index encounter order made deterministic for counter only). No eligible candidate yields zero. |
| `NONE` | `mode=NONE`, no selected rule, zero activity discount. Skips discretionary automatic offers in that group, including unsupported pmt/account offers. Still checks mandatory product price/gift effects. |
| supported legacy ID | `mode=EXPLICIT`, choose that exact eligible ID even when another supported offer is better. Skip competing discretionary offers, but still check mandatory price/gift effects. |
| existing same-scope pmt ID / nonempty-goods FULL_CUT / non-FULL_CUT ID | CHECKOUT_UNSUPPORTED_SELECTION, even if explicitly requested rule is currently inactive; unsupported kind cannot be made supported by explicit selection. |
| missing/deleted/foreign entity or foreign store ID | ACTIVITY_CHOICE_UNAVAILABLE, same outward result. |
| supported ID but paused/not-yet-live/expired/threshold not met/nonpositive cut | ACTIVITY_CHOICE_UNAVAILABLE. |
| malformed key/value, contradictory aliases | BAD_REQUEST. |
| coupon or other explicitly requested excluded mechanism | CHECKOUT_UNSUPPORTED_SELECTION. |
| selected discount makes due <= 0 | CHECKOUT_UNSUPPORTED_SELECTION; never choose a lesser offer or silently drop the selected offer to manufacture payable due. |

After an accepted quote, a changed owner result, expired selected rule, newly applicable forbidden effect or changed rule seal returns CHECKOUT_QUOTE_STALE. Dependency/parse/fence unavailability remains CHECKOUT_DEPENDENCY_UNAVAILABLE; authorization/shape failures keep their existing codes. No stale-quote exception is converted to a successful zero offer.

### 2.3 Supported legacy evaluation and conservative unsupported predicates

Query tenant MAIN, not deleted, exact entity, store null/blank or exact actual store; check RUNNING and legacy inclusive `startAt <= ownerNowMillis <= endAt`. Threshold null means zero, discount null/nonpositive means no eligible offer. Enumerate every matching FULL_CUT, cap discount at group goodsAmount, preserve qty=1/platform=0/enrollment=null. A null rule version is unavailable; real version 0 is valid. The new query orders by id ascending; ordinary `bestFullCut` and `pick` behavior are untouched.

Only SQL NULL/blank goodsNos and valid empty JSON array (including the existing singly wrapped H2 representation) mean supported whole-group scope. Counter parsing must distinguish malformed JSON from empty; the current CampaignJson helper collapses malformed input to empty and must not be used as proof. Malformed relevant rules fail dependency-unavailable, never become whole-store discounts. Canonical goods lists are sorted/deduplicated valid references.

For an omitted choice, a nonempty-goods FULL_CUT is unsupported only when active, same entity/store, positive discount, some actual purchased goods overlap, and group subtotal meets its threshold. Disjoint goods, inactive windows or whole-group subtotal below threshold prove irrelevance. Do not invent a scoped subtotal discount policy: existing owner ignores goodsNos, so an intersecting rule whose group subtotal meets threshold is conservatively potentially applicable even if the matching subtotal alone would not. An explicit such rule is unsupported. NONE or an explicit eligible whole-group FULL_CUT can opt out of this discretionary rule.

Promotion probe operates on its own actual heads/children with one captured owner time per evaluation. It does not invoke `memberPort`, cashier identity, `candidates(null,...)`, or quota reservation. First establish tenant/entity/store (or approved platform enrollment plus enrolled-goods intersection), active schedule and actual purchased goods. Only then inspect trigger and benefit. It must not reject merely because a RUNNING head exists.

* Legacy pmt (`draftSnapshot == null`): use PmtActivity.isActiveAt(now, Asia/Shanghai), exact group scope and head not deleted. Ordinary NONE/AMOUNT/QTY CUT uses existing cutTriggerHits semantics and positive capped cut. COMBO uses actual rule rows ordered by seq, actual GOODS intersection/subtotal, every AMOUNT/QTY condition, and CUT/PERCENT/POINTS benefit evaluation from comboHit; use the objective portion only. PRICE/GIFT use goods references plus active schedule; GROUP/CUTOFF or unknown nonempty effect shapes on intersecting goods are unsupported, not a guessed price. COUPON/other reward with an objectively satisfied trigger is unsupported under AUTO.
* Published pmt (`currentVersionNo != null` and nonnull draftSnapshot): read that exact PmtActivityVersion.ruleSnapshot / PublishedSnapshot; require active nonarchived head and definition schedule, including published end-exclusive and recurring local time semantics; apply its actual storeParticipationScope before trigger. ORDER/NONE/AMOUNT/QTY with positive CUT follows the objective calculation in UnifiedOrderActivityPricingServiceImpl.discount. Other scene/trigger/benefit forms: prove objective irrelevance where definition supplies sufficient facts; otherwise an active in-scope effect is unsupported. Missing/malformed referenced version is dependency-unavailable, not an empty candidate. Do not call `supportsDefinition == false` and interpret it as no effect.
* Platform legacy pmt: require APPROVED enrollment for this entity and enrolled goods intersection; evaluate amount/quantity from enrolled lines, schedule and trigger as platformHits does. A platform offer is always unsupported if otherwise applicable. Platform identity remains PLATFORM, not rewritten to the merchant.
* Audience and per-account/global quota/capacity are deliberately not used to prove ineligibility. Once objective time/scope/trigger/effect tests pass, an account-restricted or exhausted offer may still conservatively block AUTO. This is a published rollout restriction, not a claim that this guest qualifies; it avoids member and capacity reads under trade locks. Explicit NONE/supported selection gives an intentional opt-out. Thus mutable audience/participant/budget counters are not inputs to this predicate.
* For every mode, legacy FLASH with positive price and BUY_GIFT with positive buyN/giftM on an actual purchased goods reference are unsupported; the existing rule-level effect check need not wait for a gift to be awarded. Pmt PRICE/GIFT (including objectively applicable COMBO/published reward forms) are likewise checked independently of choices. Inactive, disjoint or foreign-scope effects do not win. Invalid relevant effect semantics fail closed.

Product `GoodsQueryPortImpl.snapshotForCounter` now returns the existing base/store SKU snapshot without consulting promotional prices. Both actual callers are OrderServiceImpl.split's two snapshot passes. Counter's group-aware campaign evaluation checks all price/reward effects before any quote is returned or order written. Remove the redundant counter gift probe from checkoutPricing in favor of this complete evaluation. Ordinary snapshot/snapshotFor and all ordinary/M1 gift/flash paths stay unchanged. This gives old recovery a real base-price path without adding a public bypass flag or a new pricing implementation.
