# 已经写进历史迁移的方言依赖 —— **只准变短，不准变长**。
#
# 2026-08-28 拍板「将来一定会切到 MySQL」时的存量。这里的每一条都**改不得**：
# 已应用的 Flyway 迁移动一个字符 checksum 就对不上，线上直接起不来。
# 所以这份基线不是「待办清单」，是**止血线** —— 新写的 SQL 不许再进来。
#
# 历史那部分怎么收尾（不是靠改这些文件）：
#   见 docs/technical/design/数据库可移植性-MariaDB到MySQL.md §3
#   —— 排序规则用一条新的 ALTER 迁移统一转换，趁库还只有 253MB。
#
# 格式：<文件路径><TAB><规则 id>。行号故意不带 —— 带了的话，
# 在文件里插一行注释就会让条目「变新」，那种闸门第二天就会被人绕过去。
#
# ── V288 那条（alter-column-if-exists）的理由，2026-09-02 ──────────────
# 闸门的建议是「去掉；迁移只跑一次，幂等靠 Flyway 的版本号」。
# **那句话在「迁移从没失败过」时才成立。**
#
# V288 在生产真的失败过一次：ALTER 已经成功、后面的 INSERT 撞了 JSON 列的
# CHECK 约束。Flyway 留下一条 failed 记录，而失败的迁移**清掉记录后会重跑** ——
# 那时 ALTER 会撞「Duplicate column name」，修完还要手工回退已成功的部分。
# IF NOT EXISTS 正是为此加的，且它当天就救了一次。
#
# 更硬的理由：V288 现在是 success=1，改它一个字符 checksum 就对不上，
# 线上直接起不来 —— 与这份文件顶部那句话是同一条。
#
