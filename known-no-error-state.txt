# 已知「拉数据但没有出错态」的页面 —— 失败与「这儿本来就没有」长得一模一样。
# 判据见 packages/shared/tests/ui-package.test.ts 的「拉数据的页面要区分出错与空」。
#
# 这份名单**只准变短**。补法：
#   1. 加一个 `failed` ref，`try/catch` 里置位（**别再写 `.catch(() => [])`**）
#   2. 空态改成 `<sh-empty :pending="!loaded" :failed="failed" @retry="load" ...>`
#      —— 三种态归它一个件管，文案走 `common.loadFailed` / `loadFailedTip` / `retry`
#   3. 有页面特有的说法就传 `failed-text`（`community` 的「没能加载附近的自提点」
#      比通用的「没能加载出来」有用）
#
# ⚠️ 机制不是「忘了处理」，是**处理成了另一件事**：全仓 `.catch(() => [])` 55 处、
# `.catch(() => null)` 41 处 —— 代码在主动把失败变成「空」。
# 于是网络不通时，「暂无收货地址」与「你确实还没填过地址」一模一样，
# 而前者该给「重试」、后者该给「去添加」，给反了比不给更糟。
