# 已知用了「复数资源名 + id」的端点。**清单只准变短。**
#
# ADR-007 定的是资源段用单数，而两端生成器把它做成了**硬失败**。
# 2026-08-28 数下来：c-app 3 条（都在 goods/address 豁免里）、b-app 18 条、
# **ops-web 98 条**（它的生成器压根没有这条规矩）。也就是说 126 个**线上活着的**
# 端点是复数，而规矩只活在两个生成器里 —— 其中 b-app 那个因此**一次都跑不起来**，
# `openapi-b.yaml` 从那天起就停在原地，且没有任何东西会报。
#
# 改成棘轮而不是删掉：**新写的仍然按 ADR-007 拒**，存量记在这儿。
# 要不要把 ADR-007 改成承认复数，是另一件事 —— 那要动 126 条线上路径或改约定本身，
# 不该由一个文档生成器顺手决定。
#
# 一行一个 `端点键<TAB>路径`。修好一条就删一行。
#
# 2026-08-30 新增 mSupplierUpdate / mSupplierActive：**进销存整个模块都是复数**
# （inbounds / outbounds / counts / locations / items / balances，本表已登记 13 条）。
# 单独把 suppliers 改成单数，它会成为模块里唯一那个 —— 而「同一件事在这儿长得
# 不一样」比「不合 ADR-007」更容易让人写错。要改就整模块一起改，不是一条一条改。
#
# 2026-09-17 新增 mCountVoid：与上面那条**同一个判断**，而且更直白 ——
# 它是 `counts/:no/void`，而本表里早就有一条一模一样形状的 `mInboundVoid`
# （`inbounds/:no/void`），同资源的另外三条（Detail / Fill / Post）也都在册。
# 单独把 void 这一条改成单数，counts 这个资源会自己和自己不一致。
#
# ⚠️ **不是它的作者加的**：开这个端点的会话（c4f51800）已经结束，而这道闸
