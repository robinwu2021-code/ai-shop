02 — H bar

已定：H 横画提到 0.38

旧版（虹橙 · G4）把横画提到 38%，build.py 里注释写着 「这是这版唯一的造型动作，也是它区别于随便一个 H 的地方」。换代到弧线 + HX 之后 这个动作丢了 —— 现在 _h_at() 把横画写死在正中。本节把它取回来，做成参数 bar（横画中心高度 ÷ 字高，从顶算起），并定在旧版的 0.38。 单独的 H 与 HX 里的那个 H 用同一个值 —— 规范 §02 的字形规则是「H、X 同源」， 两处 H 长得不一样就等于有两套字形。下面三版留作对照。

一个跑不掉的取舍：X 的交点永远在正中。 X 是两条角到角的对角线，交点位置是几何决定的，提不上去。H 的横一提， H 的横与 X 的交点就不在同一条水平线上 —— 上面每一格都是「单独 H + HX」并排， 就是为了让这条错位看得见。

要不要为此把 X 也改成上小下大的不对称形，是另一个决定； 规范 §02 现在写的是「X 按 H 的参数反推：同笔画宽、同字高、同切口角度」， 没说交点位置，所以保持角到角不算违反规范。

05 — How to adopt

落地顺序

顺序不能反：先让实现追上规范的分档，再落数值，再同步规范文本，最后重跑。 反过来做的话新字高只对 HX 生效，H 档还是又矮又带弧，产物「改了一半」很难查。

1. build.py：GEO 拆分档
   TIERS = {
       "H":  dict(glyph_h=0.64, arc_w=None),   # 无弧线，垂直居中
       "HX": dict(glyph_h=0.30, arc_w=0.44),
       "虹": dict(glyph_h=0.46, arc_w=0.40),
   }
   glyph_body() 按 letters 取档；H 档跳过弧线
   _h_at()：cy = (T+B)/2 → cy = T + (B-T) * 0.38  # 横画高度，见 §02
            旧版 legacy_H() 本来就是这么写的（BAR_RATIO=0.38），等于把那一行搬回新几何

2. arc_path()：A r r → A rx ry，ry = arc_flat × rx
   arc_h：r + aw/2 → ry + aw/2      # 管纵向占位，漏了整组居中就偏
   BASE 增加 arc_flat = 0.65、bar = 0.38

3. 补 §03 里缺的产出：启动页 4 项、小程序 3 项、通知图标 1 项、
   site/ favicon 一套、ico / webmanifest / 分享图 / OG、字标 SVG 入库

4. 同步 brand/spec.html §02 参数表与「母题」那一条
   「半圆弧，圆心角 180°」→ 扁圆弧 + arc_flat；它是真源，不同步就又出现两套值

5. python3 brand/build.py
本页仍未改任何产物。C 端 / B 端的底色区分（§02）是独立待定项 —— 定了它再一起重跑，避免图标连改两轮。规范全文见 brand/spec.html。
